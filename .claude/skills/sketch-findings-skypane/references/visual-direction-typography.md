# Visual Direction & Typography

## Design Decisions

**Winning variant, origin: Sketch 001, Variant B ("Full editorial").** The direction this sketch established still governs today: a warm serif on headings, cards with visible relief instead of flat bordered boxes, and a generally airier layout — but nearly every *specific value* below has since moved, in some cases more than once. Read the current value first on each line; the sketch's own draft value follows, marked SUPERSEDED.

- **Background:** the current three-level surface model uses `--color-canvas: #F7F4EF` for the page and `--color-secondary: #EEE8DE` for nav/sidebar surfaces (light mode) — not this sketch's own draft warm-tint pair, `#FBF9F6` for the page body / `#F3EEE7` for sidebar/header surfaces SUPERSEDED. Those draft values were themselves already a revision of 06.3's cool off-white (`--color-dominant: #FAFBFD` / `--color-secondary: #EEF1F7`) SUPERSEDED, but 06.6.2 (D-14) replaced the sketch's own two-level draft with the current three-level split (`--color-canvas` / `--color-dominant` / `--color-secondary`) before either of those values shipped as the sketch drafted them.
- **Cards:** the current contract is a hairline `--color-border` edge at rest, `box-shadow: none`, with `--shadow-card-hover` revealed only on `:hover`/`:focus-within` — not this sketch's own visible-shadow-at-rest / lift-on-hover / transparent-border treatment SUPERSEDED. 06.6.4 (D-03) reversed that specific trade across all eight card components (`.stat-tile`, `.page-section`, `.battery-trend-section`, `.runway-card`, `.history-card`, `.login-card`, `.airline-card`, `.theme-status`) — see `references/control-density.md` for the full contract and the **four** floating-overlay exceptions (`.lightbox`, `.dirty-bar`, `.mobile-nav`, and — Phase 22, X9 — `.tab-bar`) that keep a resting shadow. (This said "two" and named the first pair SUPERSEDED: `.mobile-nav` has carried an unconditional resting shadow since 06.6.1 and was simply never counted here; the tab bar makes four. Corrected in the same edit as `SKILL.md`'s own copy of this enumeration, so the two cannot disagree.)
- **Headings:** the warm-serif direction still holds, but the stack, the two heading-scale sizes, and the page-title weight have all since moved — not this sketch's own `Georgia, "Iowan Old Style", "Palatino Linotype", "Book Antiqua", serif` stack, unchanged size scale, and regular-weight page title SUPERSEDED (06.6.4.1.1 D-08/D-10, UIR-20/UIR-21). The current serif stack is `"Iowan Old Style", Charter, "Palatino Linotype", Georgia, "Book Antiqua", serif` — Georgia moved from first to fourth choice, so on a real Mac with either font installed the headings now render in Iowan Old Style or Charter, not Georgia. `--font-heading-size` is 22px (was 20px SUPERSEDED) and `--font-page-title-size` is 32px (was 30px SUPERSEDED, itself set by 06.6.2 D-15). `.page-title` additionally gained its own `font-weight: var(--weight-semibold)` and `-0.015em` tracking (was regular weight at `-0.01em` tracking, inherited from the shared serif rule, SUPERSEDED) — the top rung of a deliberate three-rung ladder, semibold/regular/semibold, with `.text-heading` staying regular in the middle and the nested-card-title tier below picking the semibold back up (see that entry below). The serif selector itself is unchanged: `h1, h2, h3, legend, .text-heading, .page-title, .site-title`. Body text, tables, and mono/data content stay on `--font-ui` — serif is headings-only, never dense/tabular content. `legend` was added to this selector after this sketch shipped (a bug fix, not a style change — see `SKILL.md`'s `<design_direction>` for why `<fieldset>`'s accessible-name element needed the same treatment as every other heading role).
  - **Label-voice legend exception (Phase 22, C1, 22-10-PLAN.md Task 1) — the serif boundary's second non-serif exception.** `.frame-colours__panel-legend` is a `<legend>` that wears the 12px uppercase **label voice**, so inheriting `--font-serif` from the selector above rendered a label in a heading's family: a real serif leak, which is what the audit's C1 row names. The fix is one declaration, `font-family: var(--font-ui)`, added to the **already-existing** `.frame-colours__panel-legend` rule — already later in source and already `(0,1,0)` against the shared selector's `(0,0,1)`, so **no new rule block was created**. This is the same later-higher-specificity mechanism `.page-section--nested > h2` uses, not a new one. **Bare `legend` STAYS in the shared serif selector and must not be removed from it** — its place there is the bug fix described above, and this exception is scoped to one named class, never to the element. A harness check pins both halves: the override on the class, and `legend` still present in the shared selector.
- **One "time value" role (Phase 22, C5, CFG-31) — four treatments replaced by one, with no new token.** The audit found the same kind of value wearing four different treatments across the app: a 14px grey label on Home, a 16px bold **mono** readout on Health ("Last checked in"), 14px mono in tables, and mono under the frame picture. `.time-value` replaces all four: `font-family: var(--font-ui)`, `font-variant-numeric: tabular-nums`, `--font-label-size` at regular weight, plus a single `.time-value--primary` modifier stepping up to `--font-body-size` + `--weight-semibold` where the time genuinely IS the primary value on its surface. The relative age stays a **sibling** at the file's existing 70% muted strength — never a second size and never folded into the value itself. **Monospace is now explicitly reserved for identifiers** — the callsign, the ICAO24 hex, the masked calendar URL — and a wall-clock time is not one, which is exactly the rule Health's 16px bold mono readout broke. `tabular-nums` is a `font-variant-numeric` declaration, so the digits hold their column as a clock ticks without any new machinery: **no new custom property, no new family, no new size**, and nothing added to the four-size scale. Raw ISO survives only behind a `.copy-btn`; every `title` tooltip carries a full Europe/Paris local timestamp instead (see `SKILL.md`'s Phase 18 entry, restated as exhaustive by this same phase).
- **`.site-title` (the wordmark)** is its own 24px serif semibold role with `-0.01em` tracking, still current since 06.6.1 (D-01) moved it off the retired Display role — a deliberate literal, not a token, because it is a brand role rather than a content-scale citizen (06.6.4.1.1 D-11 restated this explicitly when the type-ladder pass touched every other heading size around it).
- **Stat-tile captions — the serif Label-role exception is retired outright, not merely re-adjudicated (06.6.4.1.1 D-13/UIR-23).** The sketch's claimed 15px normal-case serif size no longer exists as a declaration SUPERSEDED, and now neither does the serif family itself SUPERSEDED. `.stat-tile__caption` no longer declares `font-family: var(--font-serif)` at all — it moved onto the new unified 12px uppercase sans-semibold label voice `SKILL.md`'s `<design_direction>` describes (the same declarations `.data-table th` / `.data-card__label` / `.filter-bar__count` / `.banner__pill` / `.airline-card__chip` now carry too). The weight round trip described below (quick task 260902-dng / 260902-iag) is now moot, not merely resolved: it was argued entirely within a four-role scale where this caption was a serif Label-role exception, and D-13 retired that whole premise. Kept below for the historical record, not because the question is still live. Weight round trip, quick task 260902-iag: quick task 260902-dng (Task 3) added `font-weight: var(--weight-semibold)` here SUPERSEDED, to match a nested card title that had just been demoted to 16px semibold (see the next bullet). Once that demotion was itself reverted, the promotion's only stated reason evaporated — a semibold 14px caption beside a regular 20px card title would have recreated the same weight-vs-size inversion in the opposite direction — so quick task 260902-iag (Task 2) reverted the promotion too. The rule declared no weight again after that, the same state this line described before 260902-dng, reached for a re-adjudicated reason rather than by omission — before D-13 retired the serif premise underneath the whole question.
- **Nested card title tier — a three-step round trip** (the `Battery trend` / `Unresolved prefixes` / `Resolution statistics` headings inside Health's own nested cards). This sketch never documented a distinct tier for these headings at all — see below. Read the three steps in order; the third is NOT a repeat of the first.
  1. **quick task 260901-uzi** (finding 4) demoted them to 16px sans semibold (the Emphasis role, `.stat-tile__value`'s own tier) to fix a real inverted-hierarchy defect — Health renders two structural levels (D-10's section headings and the cards nested inside them) and both were rendering at one identical 20px tier. This demotion was judged **in isolation**, against no larger ladder.
  2. **quick task 260902-iag** reverted it. The developer compared that demoted heading against Settings' own 20px "Runway" heading by screenshot, judged the Settings version correct, and it went back to plain 20px serif regular — each nested card's own border/`--color-dominant` surface/padding carrying the "this is one grouped unit" signal the font-size briefly carried instead.
  3. **06.6.4.1.1 (D-09)** re-applies the SAME 16px sans-semibold values a third time — `.page-section--nested > h2, .battery-trend-section > h2` now override the shared serif rule's family to `--font-ui` at Body size + semibold, `letter-spacing: normal` clearing the serif tracking, `margin-bottom: var(--space-md)` unchanged across all three states of this round trip. **What is genuinely different this time, so this does not read as a second attempt at step 1:** it is validated as the deliberate bottom rung of a full three-tier ladder — 32px semibold page title / 22px regular section heading / 16px semibold nested-card-title — composed and reviewed on a whole page (sketch 005 variant B), not judged against one isolated heading the way steps 1-2 were. The developer confirmed this framing in `06.6.4.1.1-CONTEXT.md` D-09 before the phase shipped it, and re-confirmed it live, in context, at the phase's own closing checkpoint (06.6.4.1.1-06 Task 2, item 7 — response: "oui"). Not adopted at any of the three points: the sketch's own `.wide-card__caption` card-title role, a 14px muted uppercase eyebrow label — a genuine fourth answer to this same hierarchy question that this app has never shipped, declined again at step 3 for the reason `references/control-density.md` and `SKILL.md` both give (it would create a second, competing label-like voice instead of reusing the existing Emphasis role).
- **Accent color:** the current terracotta accent is `#B13F16` (light) / `#FF8A5C` (dark) — not this sketch's own `#E8622C` (light) SUPERSEDED, darkened by 06.6.2 (D-14, UXA-04) to meet WCAG AA text contrast. The hue-separation reasoning this sketch established (keeping the accent distinct from `--color-status-warn`'s golden amber) still holds and is now executable — see `references/accessibility-contrast.md`.
- **Icons on stat tiles:** still current — accent-tinted (`color: var(--color-accent)`) via `.stat-tile__icon`, small inline SVG (20×20 by default), outline style, `stroke="currentColor"`. **Rule, made explicit by quick task 260902-j8w:** glyphs in this app are a tile/control affordance — stat tiles, nav links, the copy button, the filter bar, the refresh pill — and headings carry none. SUPERSEDED round trip: plan 06.6.1-04 (D-02) placed a glyph inside Health's `Battery trend` `<h2>`, the only glyph inside any `<h2>` anywhere on that page (Health renders five headings total), and quick task 260902-j8w removed it at the developer's explicit instruction ("supprime le logo de la batterie, car c'est inconsistant avec le reste") as inconsistent with the rest. This sketch's own evidence agrees and predates the glyph's placement: `sources/001-health-page-direction.html` defines an `#icon-battery` glyph in its `<defs>` but references it from nowhere — every `<use>` in all three of its variants sits inside a `.stat-tile__head`, and its own battery-trend section is a bare `<h2>Battery trend</h2>`. The heading placement 260902-j8w removed came from plan 06.6.1-04's own reading of D-02, not from anything this sketch showed, so the removal is a return to the validated direction rather than a departure from it.
- **Spacing:** the "generous throughout" direction landed, but not exactly where this sketch's own draft numbers placed it — see the token block below. `.page-content`'s base padding is `var(--space-xl) var(--space-lg) var(--space-2xl)`, with sides deliberately held at `lg` (24px) rather than promoted further, because a wider side gutter on a 375px phone viewport would leave too narrow a content column; the fuller `2xl`/`3xl` promotion this sketch anticipated instead lands on `.dashboard-main` at the `>=960px` breakpoint. This is a deliberate mobile-width floor the sketch's own draft numbers did not account for, not an inconsistency between the two rules.
- **Anomaly banner:** the redundant detail-text list this sketch proposed dropping was in fact re-added by 06.6.3 (UXA-06) as prose naming real failing categories — a genuine, still-open conflict between two validated decisions (06.6.1's sketch said drop it; 06.6.3 re-added it), not resolved by this file. Do not treat either direction as settled; it needs a developer decision, not a documentation correction. Separately, the banner's *container* treatment (background wash vs. hairline-plus-edge) did change — see `references/control-density.md`'s Banners section.
- **Battery trend section:** the card contract (full-width, out of the stat-tile dashboard grid, hairline-at-rest not shadow-at-rest, serif `<h2>` heading with no glyph) is still current — see the "Icons on stat tiles" bullet above for the glyph round trip. **What the card CONTAINS is superseded by Phase 24 — see the two entries below; the card treatment itself is untouched.** What the chart itself PLOTS changed, quick task 260902-l0b, at the developer's own explicit request (`ce qui m'intéresse, c'est globalement l'évolution sur plusieurs jours` — the evolution over many days, not just the latest few values): the chart's primary mode is now a 90-day daily-average series, one point per UTC calendar day, replacing the latest-20-raw-readings series it plotted before SUPERSEDED. The endpoint labels changed with it — two day-plus-month date labels ("31 Aug"/"2 Sep"), not the two `HH:MM` clock labels the raw-readings series used SUPERSEDED — still flowing through the same `<span>`-based axis mechanism quick task 260902-ep7 established, no SVG text node, no gutter estimate. Above a threshold (39 points) derived from a real Chrome instance's own `getBoundingClientRect()` measurement of the SVG canvas alone (226px at a 375px viewport, seeded with 90 days of realistic data — narrower than the 293px whole-grid figure `.battery-trend-section svg:not(.icon)`'s own comment in `companion/static/style.css` cites, once the auto-sized Y-axis label column and its gap are accounted for; see `_SPARKLINE_DENSE_POINT_THRESHOLD`'s own comment in `companion/pages/health_page.py` for the full before/after derivation) divided by the cosmetic dot's diameter, the per-point cosmetic dots stop being emitted and the hit-target radius shrinks — the same thin-line treatment preserved at 4.5x the point count, not a new visual language; every point stays reachable via its own (smaller) hit target and the unchanged roving-tabindex keyboard path. A device younger than two UTC calendar days of history falls back to exactly the raw-readings chart this section always showed, with its original clock-format endpoint labels — a data-availability degradation, not a reduced version of the daily-series feature. The latest computed reading (the readout, above the chart) is unchanged: still the latest raw reading, still humanised by `_battery_reading_parts()`, never sourced from the daily average — the developer's own second, additive request (`Et la dernière valeur calculée`).
  - **The chart's own contents, SUPERSEDED IN PLACE by Phase 24 (D8, CFG-41, 24-05).** The description above — and everything this file has ever said about this chart — describes **a bare trend line with no area beneath it, no distinguished last point and no reference level**, and that description is now history. Kept as history, because the reason for the change is a design decision rather than a defect fix: *a chart of a battery's charge that never says where "low" is makes the reader do the judging, and a chart whose newest reading looks exactly like its oldest makes them hunt for it.* Three things were added, all three derived from **the one already-filtered pair list** the line is drawn from, so none of them can drift from the readings: **(1) a filled area** under the line — `fill: currentColor` at `fill-opacity: 0.14`, closing at the **scale's own floor** (`sparkline_point_y(SPARKLINE_Y_MIN_MV)`, the level the "3000 mV" label names) and never at the canvas edge, which would add the vertical inset to every reading as a constant; **(2) the newest plotted point marked**, same element and same loop iteration as the cosmetic dot it replaces, one class and one radius different (5px against 3px) and never a second circle appended afterwards — `is_latest` feeds the mark *and* the roving `tabindex`, so the marked point and the Tab stop are the same point by construction; **(3) a drawn low-battery threshold**, a full-width `<rect>` in `var(--color-status-warn)` at the level `companion/battery.py`'s `LOW_BATTERY_DISPLAY_MV` names, **read from that module and never re-typed beside the chart that draws it**, and suppressed entirely — line *and* label — when the value falls outside the axis domain, because a clamped threshold pins to the axis edge where it reads as a threshold AT the chart floor. **Two clauses of CFG-41 were deliberately not built as worded and each carries its ground:** the area is flat and not a **gradient** (a `<linearGradient>` is only referenceable as `url(#id)` and this chart's own no-external-reference guarantee forbids that substring outright — see `references/data-density.md`'s drawing contract), and the threshold's label is a **legend in its own full-width grid row, not a third Y-axis tick** (`.sparkline__y` is `justify-content: space-between`, so a third label lands at 50% while the threshold sits at **59.25%** — a label naming a level it does not sit beside is a chart that lies, and pinning it to its real level needs an inline `style` attribute the drawing vocabulary refuses by name). The legend's swatch carries the **same token and the same 1px height** as the drawn rect, so the connection is made by colour rather than by proximity, and that equality is asserted in a real browser. What the chart PLOTS is unchanged: the 90-day Paris-day daily-average series and its raw-readings fallback are exactly as 260902-l0b left them.
  - **The battery ring gauge (new, Phase 24, D21, CFG-40) — one component at two sizes, and the "small variant" is structurally impossible.** The reading this app prints on two pages is now a picture on both: 72px inside the battery-trend card beside the existing readout, and 36px inside Home's Battery tile beside its two text lines. **One emitter, `draw.ring_gauge(fraction, size)`, called twice** — proven behaviourally rather than by grepping for the call: replace a class constant inside `companion/draw.py` and **both** pages change, at their two different sizes, in one observation. There is no `variant` parameter and the docstring says one must never be added; the geometry is ratios of the box side, so a second size is one drawing scaled rather than a second component (see `references/data-density.md` for the ratios and the two degenerate-fraction cases). **No CSS-only variant is available, and that is enforced by a mechanism rather than a rule:** `stroke-width` is emitted as a presentation **attribute**, which CSS of any specificity beats — so a `stroke-width` in `.drawing-ring-*` would flatten both sizes to one thickness and quietly hand the size parameter back to the stylesheet. Neither rule declares one, and both say so out loud. **The `aria-hidden` is justified, not assumed:** the ring carries no `<title>`, no label and no text node, and it introduces **no new user-visible string in either language** — every word beside it already existed. That justification is load-bearing in both directions and both halves are pinned: removing the printed `≈ NN%` would break it *and* remove the only exact value on the tile, so the ring is an **addition** to the verdict, the percentage and the millivolt detail, never a replacement for them. **On Home the ring sits BESIDE the text rather than above it, and that is a height decision rather than a taste one**: `.dashboard-grid` stretches every tile in a row to its tallest sibling, so a taller Battery tile does not merely grow itself, it pushes the whole row down. Measured after: the ring added **zero** height (Battery 111.59px box / 75.59px content, identical to its untouched Frame neighbour). With no drawable reading, **no ring is emitted at all** — an empty ring reads as 0%, which is a false statement about a device that has simply not checked in — and the no-reading page is byte-identically the page it was before.
  - **Health's third full-width card: Check-in regularity (new, Phase 24, D20, CFG-43, 24-07).** A plain `.page-section`, **not** the `.page-section--nested` modifier three checks pin the count and order of — following the Screen section's own existing precedent (the battery-trend card is itself a full-width card carrying its own class) rather than designing around a check. It renders 30 Paris days as a bounded grid of square cells with an HTML scale row beneath and a four-state key below that; the cells' geometry, its four states and the honesty rule about what it does not claim are in `references/data-density.md`. Health's `<h2>` count therefore moves **4 → 5**, retargeted in place in both fixtures, with that check's other half (no heading carries a glyph) untouched.

### Additions this file predates

These postdate this sketch entirely and are documented in full elsewhere — noted here only so this file's own reader knows they exist:

- The page-title role (`.page-title`, originally ~30px serif regular, distinct from the 20px `.text-heading` section-heading role) — 06.6.2 (D-15). 06.6.4.1.1 (D-10) later grew both sizes (32px/22px) and gave `.page-title` its own semibold weight — see `SKILL.md`'s `<design_direction>` Typography block and this file's own Headings bullet above.
- The retired SUPERSEDED Display type role (`--font-display-size`, 24px) — its two consumers (`.stat-tile__value`, `.runway-card__number`) moved to the Emphasis role (Body size + semibold) in 06.6.4 (D-09). See `references/control-density.md`.
- The heading-rhythm rule (`h1, h2, h3, .text-heading { margin: 0 0 var(--space-sm); }`) — stated in the same selector as the family so a heading role's spacing stays independent of whether it lands on a real `<h2>` or a `<p class="text-heading">`.
- The unified 12px uppercase sans-semibold label voice (06.6.4.1.1 D-13/UIR-23) — retired this sketch's own serif Label-role exception (`.stat-tile__caption`) outright. See this file's own "Stat-tile captions" bullet above and `SKILL.md`'s `<design_direction>` Typography block.
- **The sub-scale label tier gained one member in Phase 24 and NO new size** — `.drawing-axis-label` is 10px at line-height 1.2, which is exactly `.sparkline-axis-label`'s own pair, restated for the shared drawing vocabulary rather than chosen. That equality is deliberate and is stated in the rule's own comment: a drawing label at a different size would be a new type tier and needs an argument, not a value. The tier is enumerated in `SKILL.md`'s `<design_direction>` Typography block, now updated in place. **Phase 24 added no font size, no weight, no family and no custom property to this file's scale** — its one new custom property, `--drawing-canvas-height`, is a layout dimension on a drawing wrapper and is not a type token.

## CSS Patterns

The block below is a record of what shipped, not a proposal to add — every value that moved after this sketch is marked; treat this as historical documentation, and read `companion/static/style.css` directly for the live declarations.

```css
/* Serif headings — selector unchanged, but the page-title now overrides
 * weight/tracking (06.6.4.1.1 D-10, see below) */
h1, h2, h3, legend, .text-heading, .page-title, .site-title {
  font-family: var(--font-serif);
  font-weight: var(--weight-regular);
  letter-spacing: -0.01em;
}
.page-title {
  font-weight: var(--weight-semibold);  /* was regular (inherited above) SUPERSEDED, 06.6.4.1.1 D-10 */
  letter-spacing: -0.015em;             /* was -0.01em (inherited above) SUPERSEDED, 06.6.4.1.1 D-10 */
}

/* Card relief — SUPERSEDED (06.6.4 D-03 reversed this to hairline-at-rest, shadow-on-hover) */
.stat-tile { box-shadow: var(--shadow-card); border-color: transparent; }
.stat-tile:hover { box-shadow: var(--shadow-card-hover); transform: translateY(-1px); }

/* Tokens as they actually shipped, not as this sketch drafted them */
--font-serif: "Iowan Old Style", Charter, "Palatino Linotype", Georgia, "Book Antiqua", serif;  /* was Georgia-first SUPERSEDED, 06.6.4.1.1 D-08/UIR-20 */
--font-heading-size: 22px;     /* was 20px SUPERSEDED, 06.6.4.1.1 D-10 */
--font-page-title-size: 32px;  /* was 30px SUPERSEDED, 06.6.4.1.1 D-10 (itself set to 30px by 06.6.2 D-15) */
--color-accent: #B13F16;       /* light theme — was the sketch's own draft #E8622C SUPERSEDED, itself replacing 06.3's #3454D1 */
--color-accent-hover: #963610; /* was the sketch's own draft #D2521F SUPERSEDED */
--shadow-card: 0 1px 3px rgba(18, 21, 27, 0.06), 0 1px 2px rgba(18, 21, 27, 0.04);        /* value unchanged; usage on cards-at-rest is SUPERSEDED, now hover-only */
--shadow-card-hover: 0 4px 12px rgba(18, 21, 27, 0.08), 0 2px 4px rgba(18, 21, 27, 0.05); /* still current */
--radius-card: 10px;  /* still exists, but cards themselves now use --radius-control (8px) — --radius-card is reserved for floating overlays, see references/control-density.md */
```

## HTML Structures

No new HTML elements beyond what `companion/layout.py`'s `stat_tile()` and `page_shell()` emit — this was, and remains, a CSS-only visual layer over existing markup, plus the icon `<defs>` sprite block (`ICON_DEFS_HTML`) this sketch introduced, still current and now grown well past its original four icons (see `companion/layout.py`'s `ICON_IDS`).

## What to Avoid

- **Variant A ("Minimal warmth")** — still rejected. Too subtle; serif-only-on-h1 plus shadow-on-hover-only didn't read as a meaningfully different direction from 06.3.
- **Variant C ("Structured warmth")** — still rejected. The colored-left-border-per-status approach competed with the anomaly banner's own left-border for attention and made every card look like a warning/status indicator.
- Do not use serif for body text, table cells, or any monospace/data content — still a hard boundary (06.6.1-CONTEXT.md D-03).
- Do not pick an accent hue close to `--color-status-warn`'s amber — still a named constraint, now enforced mechanically (`references/accessibility-contrast.md`'s `MIN_SIGNAL_HUE_SEPARATION`), not only by eye.
- Do not restore a resting card shadow — 06.6.4 (D-03) is a deliberate reversal of this sketch's own original direction, not an oversight to "fix" back.
