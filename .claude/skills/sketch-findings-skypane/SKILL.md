## Project: skypane

SkyPane's companion web app (a stdlib-only Python HTTP service under `companion/`) has a hand-written, build-step-free, zero-external-reference stylesheet (`companion/static/style.css`) carrying its own full visual identity — colour, type, spacing, card treatment, control density, navigation — deliberately kept separate from the physical e-ink frame's own design system (the frame's vendored fonts and `PALETTE_RGB` values never cross into this file; style.css's own header comment states this boundary). This skill is that system's living reference: continuously updated as phases ship, not a snapshot of any single round of work.

**Current as of:** 2026-09-12, through Phase 21 (companion feedback round 3: Frame strip up front on Home and Display, a nav state reminder, Home rebuilt to three tiles plus a picture/recent-flights row, one "Frame colours" card replacing four theme chip grids, the Calendar card merged into one tile, a compact five-column Flights table with an expandable detail row, simple mode removed, the Health pause button removed, and the Airlines resolve-flow upload restored) — see the Folded-In Work list in `<metadata>` below for everything since. `.planning/ROADMAP.md` is the live record of each phase's plan-completion status — check it rather than trusting a status restated here. 06.6.4.1.1 is a closed INSERTED phase that revised the visual contract its parent/sibling Phase 06.6.4.1 itself shipped; the two are distinct phases, and 06.6.4.1.1's closure does not imply anything about 06.6.4.1's own status or vice versa.

**How this direction started.** The warm-serif / card-relief / hamburger-nav direction below traces back to Phase 06.6.1's sketch round, itself raised from real-device testing during Phase 06.5's 06.5-03 verification session — the shipped 06.3 UI had never actually been looked at on a real phone before that session, which surfaced both a real CSS bug (mobile nav-bar crush, fixed separately in commit `b90ed88`) and the design-feedback batch 06.6.1 addressed. The reference point for that direction was Goodreads: warm editorial feel, card-based browsing with visible relief, serif headings over a clean utility layout. Three phases and one debug session have since revised the *specifics* (accent hue, card relief mechanism, surface count, control density) while keeping that reference point intact — see `<design_direction>` below for what actually ships today, not what the sketch round proposed.
</context>

## Overall Direction

Every value below was read live from `companion/static/style.css` (and `companion/contrast_check.py`) at execution time. This section is a summary with a pointer to the reference file that carries the full detail — do not treat it as the whole contract.

**Colour.**
- Accent: light `#B13F16` / dark `#FF8A5C`. Light-mode accent was `#E8622C` SUPERSEDED — 06.6.2 (D-14, UXA-04) darkened it to meet WCAG AA text contrast; its hover state moved from `#D2521F` SUPERSEDED to `#963610` at the same time. Dark-mode accent is unchanged since 06.6.1.
- Three surfaces exist in both themes: `--color-canvas` (page background), `--color-dominant` (card/control surface), `--color-secondary` (elevated/nav surface) — replacing a pre-06.6.2 two-level model where `--color-dominant` did double duty as both the page background and the card surface SUPERSEDED. Light canvas is `#F7F4EF`, not the sketch round's own warm-tinted `#FBF9F6`/`#F3EEE7` pair SUPERSEDED (06.6.1's draft values, overtaken by 06.6.2's three-level split before they ever shipped as-drafted).
- Border (`--color-border`) is structural only — the sidebar/content divider, fieldset borders, table borders, the mobile-nav dropdown's edge, and (since 06.6.4 D-03) every card's resting hairline too. Never an interactive-state signal, never a substitute for accent or status colour.
- Status colours: ok `#16A34A`/`#4ADE80` and warn `#D97706`/`#FBBF24` are unchanged since 06.3; error is `#BE123C`/`#FB7185` — was `#DC2626`/`#F87171` SUPERSEDED, moved by the heading-color-consistency debug session (see `<metadata>` below and `references/accessibility-contrast.md`).
- Accent-reservation contract: the exhaustive list lives in `companion/static/style.css`'s own header comment (primary/`type="submit"` buttons, links, the focused-input outline, the active nav-pill indicator, the hamburger toggle's active state, a neutral stat tile's icon tint and top accent, the skip link's fill, the selected runway card's border/check-glyph/background-wash, the selected theme chip's border/check-glyph/background-wash (06.6.4.1.1-05, extended 06.6.4.1.1-06), native `accent-color` on radios/checkboxes, a `<summary>` disclosure marker, the neutral banner's left edge, and the favicon) — do not duplicate that list here; extend it there first if a new accent use is ever needed. quick task 260904-bbi re-keyed the two selected-card accent uses above to live `:has(input:checked)` state (inside `@supports selector(:has(*))`), not a new consumer — the quiet "saved but not live-checked" marker it added deliberately uses NO accent at all.
- Colour-separation contract: executable, not prose. `companion/contrast_check.py`'s `hue_separation()` / `perceptual_distance()` functions, gated by `MIN_SIGNAL_PERCEPTUAL_DISTANCE` (28.0) and `MIN_SIGNAL_HUE_SEPARATION` (24.0, accent-vs-error only), keep the accent measurably distinguishable from every status colour in both themes — see `references/accessibility-contrast.md` for the regression that made this necessary.

**Typography.**
- Four sizes: `--font-label-size` 14px, `--font-body-size` 16px, `--font-heading-size` 22px (was 20px SUPERSEDED, 06.6.4.1.1 D-10), `--font-page-title-size` 32px (was 30px SUPERSEDED, 06.6.4.1.1 D-10 — 06.6.2 D-15 had set it to 30px originally). Two weights: `--weight-regular` 400, `--weight-semibold` 600. Three families: `--font-ui` (system sans stack), `--font-mono`, `--font-serif` — now `"Iowan Old Style", Charter, "Palatino Linotype", Georgia, "Book Antiqua", serif` (06.6.4.1.1 D-08/UIR-20): the Georgia-first stack SUPERSEDED, so on a real Mac the headings now render in Iowan Old Style or Charter, not Georgia, wherever the OS has one installed.
- The page title (`.page-title`) now carries its own `font-weight: var(--weight-semibold)` and `letter-spacing: -0.015em` (06.6.4.1.1 D-10) — both override the shared serif rule's regular weight/`-0.01em` tracking. Section headings (`.text-heading`) stay regular weight at the new 22px. This, plus the nested-card-title tier below, is a deliberate three-rung ladder — semibold/regular/semibold — so all three read as distinct levels rather than one heading weight repeated at different sizes.
- `.site-title` (the "SkyPane" wordmark, sidebar + mobile header) is its own 24px serif semibold brand role with `-0.01em` tracking — a literal, not a resurrected `--font-display-size` (06.6.4.1.1 D-11); it is not a content-scale citizen and does not belong in the four-size scale above.
- Serif boundary, headings-only: `h1, h2, h3, legend, .text-heading, .page-title, .site-title` (and `.sidebar-title`, which is always co-classed with `.site-title` and needs no rule of its own). Body text, tables, form controls, nav links and monospace content stay on `--font-ui` — do not extend serif further. `legend` earned its place in this selector as a bug fix, not decoration: it is `<fieldset>`'s accessible group name and a genuine heading role, and being left out of the serif rule for one release let it render sans-semibold directly beside a serif-regular `<h2>` at the identical size.
  - **Serif Label-role exception, retired.** `.stat-tile__caption` is NO LONGER serif SUPERSEDED (06.6.4.1.1 D-13/UIR-23) — it moved onto the new unified label voice below. The serif set above is genuinely exhaustive again, with no named exception.
  - **New non-serif exception, the other direction.** `.page-section--nested > h2, .battery-trend-section > h2` (Health's "Battery trend" / "Unresolved prefixes" / "Resolution statistics" nested card titles) override the shared serif rule's family to `--font-ui` at the Emphasis role (Body size + semibold, see below) — this is the bottom rung of the page-title/section-heading/nested-card-title ladder (06.6.4.1.1 D-09). **`.theme-status--nested > h2` joined this same selector list (Phase 20, D-12, 20-UI-SPEC.md §C)** — a one-line, additive parity fix: `theme_fieldset()`/`runway_fieldset()`/`display_group()`/`quiet_hours_group()` wrap in `.theme-status`, not `.page-section`, so a group card placed under one of Display's three new supersections (see Navigation below) needed this extension to render its own `<h2>` at the identical 16px sans-semibold bottom rung, instead of the 22px serif tier its un-nested siblings on Device still use. No `.theme-status` wrapper was converted to `.page-section` — this selector only ever matches a `.theme-status` that also carries `--nested`.
- **Nested card title tier — a three-step round trip, read this in order.** (1) quick task 260901-uzi demoted this tier from 20px serif regular to 16px sans semibold in isolation, to fix a real inverted-hierarchy defect where Health's section headings and the cards nested inside them rendered at one identical 20px tier. (2) The developer compared that demotion against Settings' own 20px "Runway" heading by screenshot and judged the Settings version correct; quick task 260902-iag reverted it back to plain 20px serif regular. (3) **06.6.4.1.1 D-09 re-applies the same 16px sans-semibold demotion a third time** — but this is NOT a second attempt at step (1)'s isolated demotion: it lands as the deliberately-validated bottom rung of a full three-tier ladder (32px page title / 22px section heading / 16px nested-card-title), composed on a whole page and reviewed as a whole (sketch 005 variant B), not judged in isolation the way steps (1)-(2) were. The developer confirmed this specific framing in `06.6.4.1.1-CONTEXT.md` D-09, and re-confirmed it live, in context, at this phase's own closing checkpoint (06.6.4.1.1-06 Task 2, item 7 — approved, "oui"). Read `references/visual-direction-typography.md`'s own "Nested card title tier" entry for the full three-step history with each step's SUPERSEDED reasoning kept legible in place.
- **Stat-tile captions, the round trip is now moot.** The 260902-dng promotion (matching the nested card title's weight) / 260902-iag reversion adjudication described in `references/visual-direction-typography.md` no longer has a live premise: it was argued entirely within a four-role scale where `.stat-tile__caption` was a serif 14px Label-role exception. D-13 above retired that whole premise, so there is nothing left to weigh the caption's weight against a card-title tier for.
- **Label voice (new, D-13/UIR-23).** One voice, replacing what used to be several near-identical treatments: 12px, sans (`--font-ui`), `--weight-semibold`, uppercase, `0.06em` letter-spacing, the file's existing 70% `color-mix` muted strength. Covers `.stat-tile__caption`, `.data-table th`, `.data-card__label`, `.filter-bar__count`, `.banner__pill`, `.airline-card__chip`, and — **Phase 20, D-21, the seventh member** — `.status-row__label`: seven selectors, one shared declaration set (each written out separately, not consolidated into one rule, since they sit in different structural contexts). `.data-card__label` and `.data-table th` are additionally pinned string-equal by `test_status_pages.py` and must always move together. `.section-caption` (Settings' muted helper sentence under each group heading) is deliberately NOT part of this voice — it is a muted sentence-case description, not a label, and keeps its own `.text-label`-composed 14px treatment.
- Sub-scale exception tier, explicitly not a fifth content-type role — a hierarchy below the four-size scale: `.theme-form .theme-option` at 13px (colour-mixed, muted), `.cell-secondary` at 11-12px (13px in History dark mode, at 75% opacity — 06.6.4.1.1 D-16/UIR-25), `.sparkline-axis-label` at 10px, and buttons/`.filter-bar__field input` at 13px (14px below the `>=960px` breakpoint — see Controls and density below). Note the label-voice selectors above (`.data-table th` et al.) moved OUT of this tier and into the unified 12px label voice; they are no longer a "sub-scale exception," they are the label content type now.
- `--font-display-size` (24px) is retired SUPERSEDED — its two consumers, `.stat-tile__value` and `.runway-card__number`, moved to the Emphasis role (06.6.4 D-09): the existing Body size (16px) plus `--weight-semibold`, the same "existing size made bold" pattern `.data-table th` already used.

**Spacing.** Seven tokens: `--space-xs` 4px, `--space-sm` 8px, `--space-md` 16px, `--space-lg` 24px, `--space-xl` 32px, `--space-2xl` 48px, `--space-3xl` 64px. `.page-content`'s base padding is `var(--space-xl) var(--space-lg) var(--space-2xl)` — sides deliberately stay at `lg` (24px), not the airier `3xl` an earlier spec table named, because 64px of side padding on a 375px phone viewport would leave a 247px content column. The `2xl`/`3xl` promotion instead lands on `.dashboard-main` at the `>=960px` breakpoint (`2xl` top/bottom, `3xl` sides) — a deliberate mobile-width floor, not a disagreement between the two rules.
- **One sibling-card gap (06.6.4.1.1 D-14/UIR-24).** Every sibling-card gap in the app — in a grid or stacked — is now `--space-lg` (24px), the same value everywhere rather than a mix of gap sizes across contexts. A wider `--space-xl` (32px) grid gap used in at least one grid context SUPERSEDED.
- **Roomier card padding (06.6.4.1.1 D-15/UIR-24).** `.page-section`, `.theme-status` and `.battery-trend-section` now carry `--space-lg` (24px) padding at `>=960px`, dropping to `--space-md` (16px) below it. `.battery-trend-section` getting this treatment is one card beyond D-15's own literal wording — confirmed correct at this phase's closing checkpoint (item 12, "parfait").
- **`.section-intro` is mobile-first column (06.6.4.1.1 D-19/UIR-24).** The base rule is now a column stack (`gap: 2px`) so a heading-plus-caption pair (e.g. Health's "Screen — the physical frame...") never wraps onto a hanging "— ..." orphan line on a phone; a `@media (min-width: 960px)` override restores the original inline baseline row once there is room for it.

**Cards, borders, radii and shadows.** Current contract: a real `--color-border` hairline at rest, `box-shadow: none`, with `--shadow-card-hover` revealed only on `:hover`/`:focus-within` — 06.6.4 (D-03) reverses 06.6.1's shadow-at-rest treatment (`--shadow-card` visible at rest, transparent border) SUPERSEDED. Card set carrying this contract: `.stat-tile`, `.page-section`, `.battery-trend-section`, `.runway-card`, `.history-card`, `.login-card`, `.airline-card`, `.theme-status`, and (06.6.4.1.1-05) `.theme-chip`. Two floating-overlay exceptions keep a resting shadow instead: `.lightbox` and `.dirty-bar` — both are floating overlays, not page-flow cards, so their resting state should already read as elevated. Radius: this card set uses `--radius-control` (8px), not `--radius-card` — `--radius-card` (10px) is reserved for the floating/overlay elements only (`.mobile-nav`'s dropdown corners, `.dirty-bar`, `.preview-frame`, `.lightbox`). Getting this pairing backwards is the easiest mistake to make here.
- `.theme-chip` reuses `.runway-card`'s own hidden-radio + server-computed `--selected` modifier + always-present check-glyph mechanism verbatim (06.6.4.1.1-05) — a deliberate second consumer of one selectable-card idiom, not a second idiom invented from scratch.
- **Selected-state treatment, background wash added (06.6.4.1.1-06, developer checkpoint follow-up).** Both `.runway-card--selected` and `.theme-chip--selected` used to signal selection with ONLY a 2px accent border plus a small stroke-only check glyph — the developer's real-device checkpoint review reported this was too subtle to notice at a glance, site-wide ("l'élément sélectionné est très peu visible"), especially against `.theme-chip`'s photo-heavy preview band at 16-chip density. The fix ADDS (does not replace) a `color-mix(in srgb, var(--color-accent) 12%, transparent)` background wash — the same idiom `.theme-form .theme-option--active` and the nav-pill active-link rules already use, so the app now has exactly one "this is the current selection" visual language instead of two. On `.runway-card--selected` the wash covers the whole card (no separate body wrapper exists to scope it to). On `.theme-chip--selected` the wash is scoped to `.theme-chip__body` only — NOT the whole chip — so it never sits behind the rendered `.theme-chip__preview` band and tints the theme's own real colours. Border-only-selection-state SUPERSEDED as the site's general idiom; do not reintroduce a border-only selected-card treatment elsewhere without this same wash.
- **Selected-state treatment, re-keyed to live state (SUPERSEDED in part, quick task 260904-bbi).** The bullet above describes what 06.6.4.1.1-06 shipped, and its *mechanism* is now superseded: `--selected` was computed once, server-side, from the SAVED config, so the strong treatment kept following the saved value even after the user clicked a different card client-side — a real defect the developer found at a follow-up checkpoint, which 06.6.4.1.1-06's own wash addition made more visually insistent, not less. The strong border/wash/check-glyph treatment on both `.theme-chip` and `.runway-card` is now keyed to live `:has(input:checked)` state inside one `@supports selector(:has(*))` block; `--selected` is demoted to two honest jobs — the no-`:has()` fallback (painting the identical 06.6.4.1.1-06 treatment verbatim in non-supporting browsers) and, when it no longer matches the live choice, a quiet accent-free dashed 70%-muted ring plus an English "Current" `::after` tag. Full contract, including the specificity arithmetic behind the D-03a hover-guard transfer, lives in `references/control-density.md`.

**Status displays — the status-row primitive (Phase 20, D-21).** `layout.status_row(label, verdict, detail, state)` is the one new shared visual primitive this phase introduces, consumed by Home's status card (Frame/Battery/Flight data) and the Calendar card's own status line. Markup: a status dot (reusing `.dot`/`.dot--ok|warn|error` verbatim — no new colour, no new class) plus `.status-row__label` (the label-voice's seventh member, above), `.status-row__verdict` (semibold, the short state name — "Checking in normally", "Connected") and `.status-row__detail` (the same 70%-muted strength `.widget-detail` already uses, a supporting fact — a timestamp, a count). `label` is optional: passing an empty string omits the `<span>` entirely, which is how the Calendar card's own status row (no separate label column) differs from Home's three labelled rows. The rule this primitive enforces: **verdict and detail must always carry different information** — the verdict is the state name, the detail is evidence for it (when, how many, what value); collapsing them into one restated sentence is the exact "Has not checked in for a long time" duplicated-twice defect D-21 was written to close. `state` drives the dot colour through the existing `card_status_class()` whitelist, never a bare, unvalidated string interpolation.
- **Home hero (D-16..D-20).** `.home-hero` is a one-column grid on phones, two columns (`minmax(0, 1fr) minmax(320px, 400px)`) at `>=960px`, with `align-items: flex-start` so the status card never stretches to the picture's own height. Picture-first stacking on phones comes from source order alone (`.preview-frame` is the hero's first child in the markup) — no CSS `order` property is declared. `.preview-frame__image` shares its white-backing/hairline/radius declarations with the pre-existing `.now-showing__image` (one rule, two selectors — no new colour literal) and adds its own desktop-only `max-height: 60vh` cap, so the picture never dominates a tall desktop viewport the way an unconstrained image would.

**Controls and density.** Buttons are 30px tall at `>=960px` — was `min-height: 44px` SUPERSEDED, 06.6.4 (D-01)'s deliberate, developer-accepted WCAG 2.5.5 (Level AAA) trade-off — and grow to 36px/14px below `960px` (06.6.4.1.1 D-18/UIR-26), via a bare `button` selector at the same (0,0,1) specificity as the base rule, placed last in source order so it wins on position, not specificity; this does NOT reopen D-01, it extends it, and class-scoped controls (`.theme-form .theme-option`, `.copy-btn`, the nav-footer theme segments) deliberately keep their own geometry untouched by it. Primary buttons (`button[type="submit"]`) get an accent fill with a subtle inset highlight; quiet buttons (base `button`, `.logout-form button`, `.dirty-bar__cancel`) are near-invisible at rest (a `color-mix(in srgb, var(--color-text) 4.5%, transparent)` wash) and reveal on hover (7-7.5%), governed by source-order/specificity rules documented in `references/control-density.md`. Touch-target floor register (WCAG 2.5.8 / Level AA, 24px, is met everywhere): the 44px AAA floor was given up on exactly four selectors — buttons (30px/36px), desktop sidebar nav links (`.sidebar-link`, structurally desktop-only, hidden below the 960px breakpoint), theme-picker segments (28px), the filter input (32px); it was kept on native `input`/`select` (including `<input type="time">` and, as of 11-03-PLAN.md, `<input type="number">` — this codebase's first plain numeric input, the Settings page's Wake interval field), `.site-nav-toggle`, and `summary`; it was relocated (not removed, no accessibility trade-off) on `.copy-btn` (a `::before` pseudo-element synthesizes a real 44×44 hit area around a 22px visual box) and `.settings-checkbox` (a 44px `<label>` around a 16px native checkbox — a rename of its own original single-consumer `.led-checkbox` class, by 10-05-PLAN.md, once the Quiet hours group became a second consumer of the identical pattern alongside Diagnostic LED); and it was cleared by exempt-by-delegation on `input.visually-hidden`/`select.visually-hidden` — quick task 260902-l9w for the Runway-picker radios, and 06.6.4.1.1-05 for the theme-picker chip radios joining the same register, both delegating to a wrapping card label (`.runway-card`/`.theme-chip`) that exceeds 44px in both axes — see `references/control-density.md`. (The desktop sidebar's compacted height is stated once, directly, in the Navigation entry below, rather than repeated here.)

**Quiet hours group additions (10-05-PLAN.md).** `color-scheme` now exists in `style.css` for the first time — `light`/`dark` on the two `html[data-ui-theme]` override blocks and `light dark` on `:root`'s default (auto) case — added because the site's explicit `data-ui-theme` attribute (CFG-09) can disagree with the OS's own `prefers-color-scheme`, and without it a browser paints a native form control's chrome (the calendar-picker indicator on `<input type="time">`) using the OS scheme instead. `<input type="time">` is now in use on the Settings page (the Quiet hours group's Start/End fields) — the first of its kind in this codebase — and sits in the touch-target register's "kept" category: it inherits the global `input, select` rule's unmodified 44px floor exactly like `type="text"`, with no type-specific override needed.

The mobile dropdown link briefly lost its floor when D-05 reached it by mistake alongside the desktop sidebar link — it has no desktop compactness argument to trade against, being the phone's only nav — and regained its 44px floor via quick task 260902-qkm.

**Navigation.** Two renderings, chosen by the `>=960px` breakpoint: `.dashboard-sidebar` (vertical, hidden below it) and `.mobile-nav` (the header hamburger dropdown, hidden above it via `.site-header { display: none }`). The dropdown sits in normal document flow via `flex-basis: 100%` on `.site-header`'s wrapping flex row, not `position: absolute` SUPERSEDED — the absolute-positioned version shipped first, was found on real-device verification to only overlay (never push down) page content, and was replaced (06.6.1-06-SUMMARY.md). Both renderings share one active-state idiom: a 12%-accent tinted pill background plus accent text, `:not()`-scoped so hovering an inactive link can never erase the active tint. Current tab set is six, in two groups (Phase 18, companion audit / UX refactor): an unlabelled everyday group — Home, Display, Flights, Airlines — and an "Advanced" group — Health, Device — rendered by both nav renderers from one `NAV_GROUPS` tuple (`.nav-group`/`.nav-group__label`, a hairline-topped block with a 12px uppercase label voice). **Phase 21 (D-17) removed the Advanced-group visibility gate that used to sit in front of this tuple** — the group now renders unconditionally on every request, the same way it always did once simple mode's own hide-Advanced switch was deleted. Was four: Settings, Health, Airlines, History SUPERSEDED (Settings split into Display and Device per `companion/screens.py`, History renamed Flights; `/settings` and `/history` are now fixed 303 redirects, unlike the old `/config` path, which still 404s). Was five (Config, Health, Airlines, History, Preview) SUPERSEDED before that; Preview was retired by Phase 06.6.4.1 (D-22). Both renderings' footer region groups the theme picker with Sign out (06.6.2-05 D-17) — was grown to three segmented switches (Phase 20, D-02/D-29, 20-UI-SPEC.md §I), in order language / theme / simple mode / Sign out SUPERSEDED (Phase 21, D-17, CFG-23) — **the footer is two segmented switches again, in order language / theme / Sign out**: Phase 21 deleted the simple-mode switch (`layout._mode_form_html()`, the `POST /ui-mode` route, the mode cookie, and every `simple_mode`/`ctx.get("simple_mode")` gate across `prefs.py`/`app.py`/`home_page.py`/`config_page.py`/`airlines_page.py`) outright rather than superseding its markup in place, so there is no third segmented `<form>` left to describe — each of the two remaining `<form class="theme-form" method="post">`s still reuses the identical bordered-container-plus-borderless-segment idiom `.theme-form`/`.theme-option` established for the language switch, with its own `aria-label` (the translated group heading — "Language"/"Theme") so a screen reader announces two distinct control groups. A stale `sp_ui_mode` cookie left in an old browser is simply ignored — no code reads it any more.
- **New: the nav state reminder (Phase 21, D-03, CFG-19).** One line, `.nav-status`, sits under the brand and above the page list in both renderers (`sidebar_nav()`'s `<aside>`, `_mobile_nav_html()`'s dropdown panel — one shared `layout.nav_status_html(device_config)` body feeds both, so they can never disagree). It is a plain `<a href="/">` with an `aria-label` naming its destination — no `<form>`, no `<button>` — reading two dot-plus-word segments, "Screen {on/off} · Quiet hours {on/off}" (fully translated in French: "Écran allumé/éteint · Heures calmes activées/désactivées" — R-04 corrected the phase's own context doc, which had left the second word in English by drafting shorthand). The dots reuse `.dot--ok` for "on" and a new, fourth entry in the dot vocabulary, `.dot--off`, for "off" — a neutral/muted state, not a warning, so it reuses `.quick-action--off`'s own existing 30%-muted-text left-edge mix rather than `.dot--warn`/`--error`'s status colours. Text contrast (not the dot, which is merely supplementary) is the binding accessibility floor here, and it is full-strength `--color-text` on `--color-secondary` in both themes (>14:1 measured, see `references/accessibility-contrast.md`'s pattern for how this file gates that kind of claim). `page_shell()` takes this on as a new `device_config=None` keyword; `None` (login shell, 404, every pre-session page) renders no reminder at all — unchanged behaviour for every caller that predates this feature.

**Data and tables.** `.data-table th` is a quiet uppercase 11px label with a bottom hairline — was a filled `--color-secondary` block SUPERSEDED, 06.6.4 (D-07).
