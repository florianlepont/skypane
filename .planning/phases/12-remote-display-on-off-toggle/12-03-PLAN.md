<objective>
Pin the device's check-in cadence to 300 seconds while the display is off (D-01), and
compose that pin with the existing quiet-hours extension so the longest sleep wins
(D-05's sleep axis), by extending the `sleep_s` the vendored BYOS server hands back on
`GET /device/v1/display`.

Purpose: this is the half of the phase that decides how long the device sleeps, and it is
where the phase's single most subtle decision lives. D-05 splits precedence into two axes
that resolve differently — the toggle wins on *what the panel shows* (plan 12-04), but the
*longest value* wins on *how long the device sleeps*. A naive "off wins always" would pin
`sleep_s` to 300s inside a quiet-hours window, making the device wake more often with the
display off than quiet hours alone would have, inverting the point of both features.

Output: `DISPLAY_OFF_SLEEP_S`, `read_display_enabled()` and `display_off_sleep_s()` inside
`stub-server/byos_server.py`, the rewired `sleep_s` composition, the fourth `VENDOR.md`
local-modifications entry, and extended coverage in `stub-server/test_poll_cycle.py`
including the overlap case neither feature's own tests cover.
</objective>

before `quiet_hours_sleep_s()`. Return `DISPLAY_OFF_SLEEP_S` when
`read_display_enabled(state_dir)` is `False`, otherwise `base_sleep_s` unchanged.

pin cuts the wake count roughly fivefold, and against a long one (ceiling 3600s) it makes
switching the display back on *faster*, a predictable within-five-minutes instead of up to
an hour (D-02). Serving a shorter value than the configured interval is the intended
behaviour here, not an oversight for a later reader to "restore consistency" on.

**The rewiring.** Change the response's `sleep_s` expression so `display_off_sleep_s()`
wraps the `read_wake_interval_s()` call and `quiet_hours_sleep_s()` wraps that:

    quiet_hours_sleep_s(display_off_sleep_s(read_wake_interval_s(...), state_dir), state_dir)

**The nesting order is the correctness of this plan**, not a style choice. Composed this
way, the off-state pin becomes `quiet_hours_sleep_s()`'s base, and that function's
existing `max(base_sleep_s, remaining)` produces `max(300, quiet_hours_remaining)` — D-05's
sleep axis, for free, with no change to the Phase 10 function at all. Composed the other
way round, with `display_off_sleep_s()` outermost, an active quiet-hours window would be
overwritten by a flat 300s and the device would wake all night with the display off.
Extend the comment block above `sleep_s` with a Phase 12 paragraph in the style of the
Phase 10 and Phase 11 paragraphs already there, stating the resulting composition and why
the order cannot be swapped. Task 2 pins it with a negative control.

| Boundary | Description |

| `device_config.json` on disk -> `read_display_enabled()` | A hand-edited or corrupted file crosses the vendor boundary into the device's deep-sleep duration |
