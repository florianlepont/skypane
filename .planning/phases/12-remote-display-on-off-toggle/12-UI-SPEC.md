# Phase 12 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

This phase has **two distinct UI surfaces** with two different design systems — do not
cross-apply values between them, matching Phase 10's own precedent for the same split:

1. **Companion web app** (`companion/pages/config_page.py` + `companion/static/style.css`)
   — a sixth `.theme-status` group on the existing Settings page, holding a single
   on/off checkbox (D-08). Governed by the hand-rolled companion design system
   (`sketch-findings-skypane` skill). Covered by the standard template sections below.
   This is a small, conventional addition, structurally identical to `led_group()` — it
   should not invent anything new.
2. **E-ink panel screen** (`server/plane/render.py`) — a new dedicated "display off"
   render state on the 1200×1600, 6-color Spectra 6 panel. NOT a web surface — no CSS,
   no shadcn, a constrained 6-index palette (White, Black, Yellow, Red, Blue, Green —
   no intermediate tones outside dithering) and PIL/Pillow drawing primitives instead.
   Covered by its own dedicated section (`## Panel Screen Contract`) below, since the
   template's Design System/Color/Typography tables are web-shaped and do not fit it.
   This is the surface that needs real design thought — it is modelled directly on
   Phase 10's `_build_quiet_hours_canvas()`, with the one deliberate subtraction D-03
   specifies (no return-time promise).

### New copy this phase introduces (group-specific)

| Constant | Copy |
|----------|------|
| `DISPLAY_SECTION_HEADING` | "Display" |
| `DISPLAY_SECTION_CAPTION` | "Turns the physical panel off remotely, without touching the hardware. Takes effect within about 5 minutes, both switching off and back on." |
| Checkbox label | "Enable display" (mirrors the existing "Enable diagnostic LED" / "Enable quiet hours" phrasing exactly — unchecked means the panel goes dark) |

`DISPLAY_SECTION_CAPTION` states the ~5-minute latency directly in the caption, the same
place `QUIET_HOURS_SECTION_CAPTION` states its own "may now be hours away" caveat (D-02)
— this is the one config field on the page whose apply-timing (a fixed 300s check-in,
independent of `wake_interval_s` or quiet hours) is genuinely different from every other
field's "next scheduled poll" phrasing, so it earns its own honest sentence rather than
reusing the generic clause. **Do not write "instantly" or "immediately" anywhere in this
copy** — D-02 is explicit that the change is not instant, and the UI must not imply
otherwise.

## Interaction Contract (Companion Web App)

Specific to this phase's new group — not covered by the generic template tables above.

**Group placement and structure.** A sixth `.theme-status`-wrapped group, sibling to the
existing Theme/Runway/Diagnostic LED/Quiet hours/Wake interval groups, in the same
merged `<form action="/settings">`. No `<fieldset>`/`<legend>` — matches `led_group()`'s
established pattern exactly (a `<div class="theme-status">` with an `<h2
class="text-heading">` heading; a `<legend>` only has accessible-name semantics inside a
`<fieldset>`, which these sibling groups deliberately do not have).

**Field order (top to bottom), locked by this spec — a single checkbox, nothing else:**
1. `<h2 class="text-heading">Display</h2>`
2. `<p class="text-label section-caption">{DISPLAY_SECTION_CAPTION}</p>`
3. Enable checkbox (`<label class="settings-checkbox">`, the shared class introduced by
   quick task `260901-qif` and reused by both `led_group()` and `quiet_hours_group()`)

**Group order on the page:** Theme → Runway → Diagnostic LED → Quiet hours → Wake
interval → **Display** (new, last).

**Markup shape** (mirrors `led_group()`'s structure verbatim — same shape, new field
name and copy):
```html
<div class="theme-status" data-dirty-section="Display">
  <h2 class="text-heading">Display</h2>
  <p class="text-label section-caption">Turns the physical panel off remotely, without touching the hardware. Takes effect within about 5 minutes, both switching off and back on.</p>
  <label class="settings-checkbox">
    <input type="checkbox" name="display_enabled" value="on"{checked}> Enable display
  </label>
</div>
```

**No new CSS.** `.settings-checkbox` already exists (normalises the native checkbox to
16px while relocating the 44px touch-target floor onto the wrapping `<label>`) and
`.theme-status` already carries this phase's exact card/spacing treatment. This group
introduces zero new selectors, zero new declarations.

**No disabling logic, no dependent fields.** Unlike Quiet hours' Start/End inputs, this
group has nothing else to gate — it is exactly one checkbox with no sibling controls
whose enabled/disabled state depends on it. Keep it that simple; do not add helper
fields, a "reason" text box, or a schedule — the developer's own framing challenge
during discussion (*"pas possible de juste faire ON/OFF ?"*) is the phase's central
constraint, and the UI must not surface anything more than that.

**Applies-on-next-check-in copy: the caption is the only place this is stated.** Unlike
Quiet hours (which relies on the shared generic flash message plus its own caption), no
new flash-message variant is needed here either — reuse the existing shared
`FLASH_SAVED` flash ("Saved — will apply on the frame's next scheduled refresh.")
verbatim. The caption's own "within about 5 minutes" sentence is the more precise,
field-specific promise; the generic flash banner does not need to repeat it.

## Panel Screen Contract (E-Ink, `server/plane/render.py`)

This is the second UI surface. It is **not** a web page: 1200×1600px, a fixed 6-index
palette (`IDX_BLACK`, `IDX_WHITE`, `IDX_YELLOW`, `IDX_RED`, `IDX_BLUE`, `IDX_GREEN`),
drawn with PIL/Pillow primitives, with a `SAFE_BOX` margin contract `(64, 64, 1136,
1536)` every element must stay inside. The template's web-shaped Design
System/Color/Typography/Spacing tables above do not apply here — this section is the
complete, self-contained contract for this surface instead.

### Locked decisions (from `12-CONTEXT.md`)

- **D-03:** a dedicated, sober off screen — the same shape as Phase 10's
  `_build_quiet_hours_canvas()`, minus any return-time promise. Rejected: a blank field
  (indistinguishable from a dead device or an outage — erodes the meaning of the CFG-05
  source-fault icon) and a blank field with a discreet corner mark (invents a new
  composition needing its own on-glass validation for no decisive gain).
- **D-04:** copy is locked-English module constants, mirroring
  `QUIET_HOURS_HEADING_TEXT` / `QUIET_HOURS_BODY_TEMPLATE`. Must not promise a return
  time. Must not read as an error state.
- **D-05 (display axis only):** the display toggle wins on *what the panel shows* —
  this screen renders whenever the toggle is off, regardless of whether a quiet-hours
  window is also active. (The *sleep-duration* axis of D-05 — `max(300,
  quiet_hours_remaining)` — is a `poll_loop.py`/vendored-server concern, out of this
  visual contract's scope; noted here only so the executor does not confuse "which
  screen renders" with "how long the device sleeps," which D-05 explicitly keeps
  separate.)
- **D-07:** moving between two hold states (quiet-hours screen ↔ off screen) must not
  trigger an e-ink refresh — repainting an already-held screen costs energy and produces
  a visible flash for no informational gain. This is a rendering-dispatch/latch concern,
  not a pixel-composition concern, but it constrains when this canvas gets drawn: once
  per "entering the off state," never on every poll while already off.

### Visual structure — locked default: mirror `_build_quiet_hours_canvas()` exactly, minus the body's time reference

Structurally identical to Phase 10's quiet-hours screen (itself structurally identical
to `_build_empty_canvas()`), with different, honest copy and no template substitution
(there is no time value to interpolate — D-03 rejects any return-time promise, so the
body is a single fixed string constant, not a `%`-template like
`QUIET_HOURS_BODY_TEMPLATE`).

| Property | Value |
|----------|-------|
| Canvas background | Flat `IDX_WHITE` — always, regardless of the currently configured theme (`theme_id` is ignored for this screen, exactly like the empty state and the quiet-hours screen) |
| Ink color | `EMPTY_INK` (= `IDX_BLACK`) for all text and icons on this screen |
| Heading text | `DISPLAY_OFF_HEADING_TEXT = "DISPLAY OFF"` (all-caps, two words — matches `"QUIET HOURS"`'s own shape: short, all-caps, unambiguous, never mistaken for a flight state like `DEPARTING`/`ARRIVING`) |
| Heading font | `PT_SERIF_BOLD`, base size 72px (reuse `EMPTY_HEADING_FONT`'s size), shrunk via `fit_text_size()` down to a 48px floor (reuse `EMPTY_HEADING_MIN_SIZE`) against `safe_width` — identical mechanism to both `_build_empty_canvas()` and `_build_quiet_hours_canvas()`, even though `"DISPLAY OFF"` (11 characters, same length class as `"QUIET HOURS"`) is unlikely to need it in practice. Specify it defensively anyway, matching precedent |
| Body text | `DISPLAY_OFF_BODY_TEXT = "Switched off from the companion page. Turn it back on there anytime."` — a fixed constant, no template. States what happened (an intentional operator action, not a fault) and where to reverse it, without naming a time. Do **not** add a duration or "back at" clause here — the panel is passive and has no clock-driven end time to display; the ~5-minute apply-latency honesty belongs on the companion Settings caption (see above), not this screen, since nobody is looking at a dark panel waiting for a countdown |
| Body font | `PT_SERIF_REGULAR`, size 40px (reuse `EMPTY_BODY_FONT`), wrapped via `_wrap_text()` against `safe_width` — unlike the quiet-hours body (a short one-liner that fits in one line at this size), this body string is meaningfully longer and should be expected to wrap to 2 lines; verify against `safe_width` (1072px) rather than assuming single-line |
| Layout | Centered heading, then `SPACE_SM` (16px) gap, then centered body line(s) — vertically centered as a block in the full 1600px canvas height, using the identical `total_height` / `start_y` centering formula `_build_quiet_hours_canvas()` already uses |
| Safe-box assertion | Both the heading bbox and every body-line bbox MUST pass `_assert_in_safe_box()` before drawing, exactly like every other text element in `render.py` |
| Battery-low icon | Bottom-left, in `EMPTY_INK`, drawn via the existing `draw_battery_icon()` call, when `battery_low=True` — same precedent as `_build_empty_canvas()`/`_build_quiet_hours_canvas()` (a device-health fact independent of what's on screen; all three hold/empty states should stay consistent on this) |
| Source-fault badge | Bottom-center, in `EMPTY_INK`, drawn via the existing `draw_source_fault_badge()` call, when `source_fault=True` — same precedent |
| Palette legality | Flat White background + Black text/icons only — trivially satisfies `_assert_legal_palette()`'s "only legal indices, background dominant" contract, identical to the two screens this one is modelled on |

### Copywriting Contract (Panel Screen)

| Element | Copy |
|---------|------|
| Heading | `DISPLAY OFF` |
| Body | `Switched off from the companion page. Turn it back on there anytime.` |
| Language | English — locked (D-04), matching `QUIET_HOURS_HEADING_TEXT`/every other panel string (`DEPARTING`/`ARRIVING`, `ORY · RWY 3`, `QUIET HOURS`). Do not localize |
| Must NOT include | Any return-time promise (D-04) — no "Back at HH:MM", no "~5 minutes", no countdown. Any wording that reads as an error/fault state (D-04) — no "unavailable", "error", "offline", "disconnected"; this is an intentional, operator-initiated state, and CFG-05's own fault badge already owns the vocabulary for genuine faults. Reusing fault-adjacent words here would blur that distinction, which is exactly what D-03 rejected the blank-field option to avoid |
| Empty/error states | Not applicable to this screen — it has exactly one content shape, no empty/loading/error variant of its own (same as the quiet-hours screen) |
| Destructive confirmation | Not applicable — this is a passive display state, no user action happens on the panel itself |

### Open item this spec deliberately does NOT resolve — flag to planner/executor, on-glass verification required

**This phase now has three visually similar full-bleed White/Black centered-text hold
screens** (`_build_empty_canvas()`, `_build_quiet_hours_canvas()`, and this phase's new
off screen) — a real, cumulative legibility risk this spec's "mirror the precedent
exactly" default does not resolve on its own. D-03 deliberately chose this shared shape
over inventing a new composition, on the reasoning that consistency of *treatment*
across the project's hold states matters more than making each one visually distinct —
but that choice has never been checked side-by-side on real glass. Per this project's
own established discipline (05-CONTEXT.md for the battery icon, 03-CONTEXT.md for the
two-flight poster, 10-UI-SPEC.md for the quiet-hours screen itself), **do not assert
legibility or distinguishability from a rendered PNG preview** — Phase 9's on-glass
session found the preview mis-called text/background contrast even for saturated
Blue/Green/Red fills, so a White/Black preview should not be assumed accurate either,
purely on the strength of being the "safe" palette combination.

Before treating this screen as final, the blocking on-glass verification this phase's
ROADMAP entry already requires (`Closes with: a blocking on-glass verification, same
D-13 precedent as Phases 8, 9 and 10`) must specifically check, side by side on the real
panel:

1. **`DISPLAY OFF` reads as clearly distinct from `QUIET HOURS` and from the empty
   state's own heading** at a normal glance-from-across-the-room viewing distance — not
   just distinguishable on close inspection.
2. **The wrapped two-line body text** (`Switched off from the companion page. Turn it
   back on there anytime.`) renders legibly and doesn't crowd the safe-box margins at
   the 40px body size — this body string is longer than the quiet-hours screen's own
   `"Back at HH:MM"` and has not been visually confirmed at this size before.
3. **The screen does not read as an error/fault state** to a first-time viewer glancing
   at the frame without context — the specific ambiguity D-03 was written to avoid.

If the check finds the three hold screens too similar to distinguish at a glance, the
acceptable follow-up adjustments — in order of preference, least to most invasive,
mirroring 10-UI-SPEC.md's own escalation ladder — are: (1) nothing, if the differing
heading text alone proves sufficient in practice; (2) a slightly bolder/larger heading
treatment for this screen than the other two, still within White/Black; (3) only as a
last resort, a distinct flat fill color for this screen alone (still 6-palette-legal,
still passing `_assert_legal_palette()`). Do not skip the real-preview check and ship
option (2) or (3) speculatively — build option (1) first and test against it.
