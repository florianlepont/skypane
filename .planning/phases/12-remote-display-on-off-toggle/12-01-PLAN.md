  <action>
Extend the registry with the phase's one new field (D-08) and the one constant D-01 needs.

Add `DEFAULT_DISPLAY_ENABLED = True` immediately after `DEFAULT_QUIET_HOURS_END`, with a
comment recording D-09's reasoning: an explicit boolean following the
`DEFAULT_LED_ENABLED`/`DEFAULT_QUIET_HOURS_ENABLED` precedent, never an
absence-means-off convention, so nothing changes for an installation already in service
until someone opts in.

Add `DISPLAY_OFF_SLEEP_S = 300` directly below the `WAKE_INTERVAL_MAX_S` block. Its
comment must record three facts, because each one is a thing a later reader would
otherwise re-litigate: (a) per D-01 this is the fixed off-state check-in cadence, and it
deliberately replaces `wake_interval_s` rather than being derived from it — short
configured intervals get roughly a 5x wake reduction, long ones get a predictable
back-within-five-minutes switch-on; (b) the value falls inside the inclusive
`[WAKE_INTERVAL_MIN_S, WAKE_INTERVAL_MAX_S]` band, so unlike `quiet_hours_sleep_s()` this
mechanism needs none of the ceiling-exceeding latitude the comment above already
documents; (c) `stub-server/byos_server.py` independently redefines this value across the
vendor boundary (plan 12-03) and must be kept in step with it — cross-reference that file
by name, following exactly the same convention `WAKE_INTERVAL_MIN_S`/`MAX_S` already use.

Add `normalise_display_enabled(value)` immediately after `normalise_quiet_hours_enabled()`.
Body and contract are `normalise_led_enabled()`'s, against `DEFAULT_DISPLAY_ENABLED`:
return `value` unchanged only when `isinstance(value, bool)`, otherwise the default.
Never raises, deliberately no registry/membership test. Its docstring must state the
security-relevant consequence of the default's direction: because the default is `True`,
every degradation path — missing file, unreadable file, malformed JSON, non-dict
document, wrong-typed value — leaves the display ON. A corrupted config can never be the
reason a frame goes dark, which is the fail-open direction this field needs (a
fail-closed default would turn a disk-level fault into an apparently-dead device, exactly
the ambiguity D-03 rejected the blank-field option to avoid).

Extend `load_device_config()` with an eighth entry,
`"display_enabled": normalise_display_enabled(data.get("display_enabled"))`, and update
its docstring's key count and key list.

Extend `save_device_config()` with a `display_enabled=None` keyword parameter, its
`isinstance(..., bool)` guard placed alongside the existing `led_enabled` and
`quiet_hours_enabled` guards (before `current = load_device_config(state_dir)`, so a
rejection never touches the file), and its carry-forward entry in `new_config`. Update
the docstring's field enumeration.

Do not touch the theme or runway registries, `_HHMM_RE`, the quiet-hours arithmetic, or
`normalise_wake_interval_s()`.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| companion HTTP POST -> `save_device_config()` | An untrusted submitted checkbox value crosses into a persisted document (plan 12-05 is the writer) |
| `device_config.json` on disk -> `load_device_config()` | A hand-edited or corrupted file crosses into every reader, ultimately deciding whether the panel renders at all and how long the device sleeps |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-12-01-01 | Tampering | `server/device_config.py` write path (`save_device_config()`) | high | mitigate | The new `display_enabled` guard is an explicit `isinstance(..., bool)` check placed before `current = load_device_config(...)` and before the file is ever opened, so a rejection leaves any pre-existing file byte-identical (the T-06-01-01 all-or-nothing discipline `led_enabled`/`quiet_hours_enabled` already follow). Task 2 check 4 proves byte-identity across every rejection |
| T-12-01-02 | Denial of Service | The panel itself, via a corrupted on-disk config | high | mitigate | `normalise_display_enabled()` degrades every hostile shape to `True`, so a malformed or hand-edited `device_config.json` can never darken the frame.
