<objective>
Add the dedicated "DISPLAY OFF" panel render state (D-03) with its locked English copy
(D-04) to `server/plane/render.py`, plus the CLI flag that makes plan 12-06's on-glass
session possible.

Purpose: this is the second panel screen the project has deliberately carved out of its
own "no on-screen status text" rule, after Phase 10's quiet-hours screen and Phase 5's
low-battery icon. `12-UI-SPEC.md`'s Panel Screen Contract locks its structure, copy,
fonts, layout and palette, so this plan implements an approved contract rather than
making design choices. It is drawn exactly once, by `poll_loop.py` (plan 12-04), at the
poll that first enters a hold state.

Output: `DISPLAY_OFF_HEADING_TEXT`/`DISPLAY_OFF_BODY_TEXT`, `_build_display_off_canvas()`,
a `display_off` dispatch branch on `build_canvas()`/`render_panel()`, a
`--state display_off` CLI path, and extended coverage in `server/test_render.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `poll_loop.py` -> `build_canvas()` | A state string and indicator flags cross into the drawing pipeline; the state string decides which of three near-identical screens the operator sees |
| `build_canvas()` -> the physical panel | Anything drawn here reaches real Spectra 6 ink and stays there until the next refresh, which the device cannot request |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-02-01 | Spoofing | The off screen versus a genuine fault state | medium | mitigate | The copy is a fixed module constant containing none of the fault vocabulary `SOURCE_FAULT_TEXT` owns, so an intentional operator action can never be mistaken for the CFG-05 outage the badge signals. Pinned by Task 3 check 4's exact-equality assertion, and judged for real by plan 12-06's on-glass check 3 |
| T-12-02-02 | Information Disclosure | The panel surface | low | mitigate | This screen renders two fixed constants and no runtime data — no flight, no callsign, no config value, no time. There is nothing on it that could leak, by construction rather than by filtering |
