<objective>
Gate `server/poll_loop.py`'s render pipeline on the display toggle as well as the
quiet-hours window, and generalise the single-purpose quiet-hours latch into one
hold-state latch that spans both mechanisms so no e-ink refresh ever fires for a move
between two hold states (D-05 display axis, D-06, D-07).

Purpose: `poll_loop.py` is the only process that renders and writes `panel.bin`. Plan
12-03 decides how long the device sleeps; this plan decides what the device finds on the
panel when it wakes, and what it was left looking at when it went dark.

Output: a generalised `poll_state["hold_state"]` latch with a legacy-aware read, a single
shared hold branch entered by either mechanism and evaluated ahead of detection, a
generalised exit path, and extended coverage in `server/test_poll_loop.py`.
</objective>

<design_decision id="D-07-factoring">
**12-CONTEXT.md lists the D-07 hold-state generalisation under Claude's Discretion:
widen the existing latch, or add a sibling. This plan widens it, into one tri-valued key.
The reasoning is binding on the executor; do not substitute the sibling-boolean design.**

`poll_state["hold_state"]` takes exactly three values: `None` (not holding),
`"quiet_hours"`, or `"display_off"`.

Two independent booleans were rejected because they make "am I already holding?" a
compound test that every future hold mechanism has to remember to extend in every place it
appears — which is precisely the per-mechanism factoring D-07 forbids. With one key,
"entering a hold" is the single test `was_hold is None`, and it stays correct for a third
mechanism without touching a line. The single key also records *which* screen is currently
on the glass, which the two-boolean design throws away and which the log line and any
future exit logic genuinely want.

**Migration matters here — this runs on a live deployed device.** A `poll_state.json`
written by the Phase 10 code carries the legacy boolean and no `hold_state` key. If the
new code simply read `hold_state` and found it absent, an upgrade landing mid-window would
read "not holding", enter the hold branch as if fresh, and repaint the same quiet-hours
screen that is already on the glass — a needless full refresh, and exactly the class of
spurious repaint D-07 exists to prevent. So the read is legacy-aware, and the first write
retires the stale key rather than leaving it on disk to confuse a later reader.
</design_decision>
