<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> session-gated page GET | untrusted If-None-Match and X-Requested-With headers |
| DOM -> fetch headers | token read from the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-38 | Information disclosure (change oracle) | 304 vs 200 on page URLs | mitigate | the conditional branch runs only after `require_session()`; test asserts an unauthenticated freshness request gets 303 and the token function is not called |
| T-38-39 | Information disclosure | token contents | mitigate | the token is a truncated SHA-256 of inputs; no input value, path or timestamp is exposed; it is served only to authenticated users on no-store responses |
| T-38-40 | Tampering | header injection via a DOM-sourced token | mitigate | freshness.js sends only a value matching `^[0-9a-f]{16,64}$`; the server never echoes the request header, it sends its own token |
| T-38-41 | Repudiation (stale page shown as fresh) | token missing an input | mitigate | completeness test mutates each input; forced full refresh every 7 ticks; identical-cycle stability test prevents a token that never matches |
| T-38-42 | Information disclosure | caching of session pages | mitigate | 304 and 200 page responses keep `Cache-Control: no-store`; ETag is never paired with `public` |
</threat_model>
