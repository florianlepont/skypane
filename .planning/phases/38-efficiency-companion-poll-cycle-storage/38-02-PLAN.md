<objective>
Static files: validators, 304 on revalidation, bytes kept in memory, and compression at the edge
(EFF-01, D-1, ROADMAP criterion 2).

Purpose: a second page load costs 304s instead of ~280 KB of CSS/JS, and Caddy compresses what is
sent. D-1 (locked): CSS/JS use `Cache-Control: no-cache` with a strong ETag and Last-Modified, so
every load revalidates and no page runs new HTML against old JS after a deploy.
Output: `_serve_static` behind the existing delegates, Caddy `encode`, tests.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-04 | Information disclosure | 304 on static routes | accept | CSS/JS are already public pre-auth and identical for every client; a 304 reveals nothing a 200 does not |
| T-38-05 | Information disclosure | runway image 304 | mitigate | `_serve_runway_image` remains behind `require_session()` in do_GET, so the conditional path is only reached after auth; test asserts unauthenticated -> 303 |
| T-38-06 | Tampering / DoS | If-None-Match / If-Modified-Since parsing | mitigate | defensive parse; any exception -> no match (200), never 500; header bytes are never echoed; tests cover malformed input |
| T-38-07 | Information disclosure | shared caches | mitigate | only pre-auth assets are `public`; runway images stay `private`; `send_bytes` keeps its fail-closed default; HTML stays `no-store` |
| T-38-08 | Tampering | Caddy encode on the device block | mitigate | encode only in the companion block; test asserts the device block has no encode |
| T-38-09 | Information disclosure | BREACH-style compression oracle | accept | companion pages carry no CSRF token (Origin/Sec-Fetch-Site check), reflect little attacker input, and the session cookie is in the request, not the body |
