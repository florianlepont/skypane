one transaction per cycle (EFF-03), without changing any caller signature.

scope (wired in later plans: the poll cycle and the companion request). This plan changes no
caller, so behaviour outside a scope is identical.
Output: `connection_scope`, `write_batch`, schema-once in `connect`, tests.

  <name>Task 1: Thread-bound re-entrant connection_scope and scoped open_db</name>
  <files>server/history_db.py, server/test_history_db_scope.py</files>
  <read_first>
    - server/history_db.py (module docstring, connect, open_db, init_schema, writers)

    - deploy/tests/test_backup.py (direct connect users)
  </read_first>
  <behavior>
    - Two `open_db(tmp)` blocks inside one `connection_scope(tmp)` -> count_db().connections == 1 and both yield the same object; the connection is still open after the inner blocks and closed after the scope
    - A scope that never calls open_db opens no connection (0)
    - Nested `connection_scope(tmp)` inside another -> still one connection, closed only at the outermost exit
    - `open_db(other_dir)` inside `connection_scope(tmp)` -> a separate, normally closed connection (passthrough)
    - A second thread calling open_db(tmp) while the first thread holds a scope gets its own connection (scope is thread-bound; sqlite check_same_thread stays satisfied)
    - Scoped open failure (monkeypatch `sqlite3.connect` to raise sqlite3.OperationalError once): the first and the second open_db in the scope both raise sqlite3.OperationalError, and the patched connect was called exactly once
    - Scope exit with a pending transaction (an INSERT without commit) rolls it back; open_db outside a scope behaves as today (test_backup-style write + close keeps writer-committed rows)
  </behavior>
  <action>
Use a module-level `threading.local()` named `_SCOPE` (thread-bound by construction; avoids
relying on ContextVar inheritance rules across Python versions) holding `path`, `depth`, `conn`,
`error`. `connection_scope(state_dir)`: if a scope for the same `history_db_path(state_dir)` is
active on this thread, increment depth and yield; if a scope for a different path is active,
yield without taking over (the inner path is served unscoped); otherwise start a new scope with
`conn=None`. On the outermost exit: if a connection was opened, roll back if `conn.in_transaction`,
then close it; always reset the thread-local fields in `finally`. `open_db(state_dir, timeout)`:
when a scope for the same path is active, lazily call `connect()` on first use (storing any
`sqlite3.Error`/`OSError` in `error` and re-raising it; later calls re-raise the stored exception
without connecting again), yield the scoped connection, and do not close it; otherwise keep
today's connect/yield/close. Update the module docstring's concurrency paragraph in English
(one connection per scope; PRAGMAs; schema once) without history references.
  </action>

  <files>server/history_db.py, server/test_history_db_scope.py</files>
  <read_first>

  <behavior>
    - Three `connect(tmp)` calls in one process -> count_db().init_schema == 1; journal_mode is wal and busy_timeout 5000 on every connection
    - Deleting history.db (and its -wal/-shm) and connecting again at the same path -> init_schema runs again and the tables exist (covers inode reuse: the new file is empty)
    - Two different state dirs -> init_schema once each
    - `with write_batch(conn): record_runway_event(...); set_meta(...); record_device_health(...)` -> count_db().commits == 1 and all rows visible from a second connection afterwards
    - An exception raised inside write_batch -> rolled back (no row visible from a second connection), exception re-raised
    - Outside write_batch, `set_meta(conn, ...)` alone is visible from a second connection immediately (writer still commits)
    - `ingest_caddy_battery_log` inside write_batch commits once in total
  </behavior>
  <action>
Schema once: keep a module-level set `_SCHEMA_READY` guarded by a `threading.Lock`, keyed by
`(os.path.realpath(path), st.st_dev, st.st_ino)` from `os.stat` after `sqlite3.connect`. In
`connect()`: always set `row_factory` and `PRAGMA busy_timeout=5000`; run `PRAGMA journal_mode=WAL`
and `init_schema(conn)` only when the key is not in the set or `st.st_size == 0` (a brand-new or
recreated empty file, so a reused inode can never skip the schema), then add the key. Explain the
size check and the restore/recreate case in one comment. Do not add `PRAGMA user_version` or
`ALTER TABLE`. This is the "schema once per process (per database file identity)" rule from
CONTEXT.
Batch: make `connect()` pass `factory=_HistoryConnection`, a `sqlite3.Connection` subclass with a
`_batch_depth` int attribute (0 by default). Add `write_batch(conn)` context manager: increments
`_batch_depth` (via `getattr` default 0 so a plain sqlite3 connection also works), yields, and on
the outermost exit commits; on exception rolls back and re-raises. Add private `_commit(conn)`
that commits only when `getattr(conn, "_batch_depth", 0) == 0`, and replace the `conn.commit()`
in `record_runway_event`, `record_device_health`, `record_wake_epoch` and `set_meta` with it
(`init_schema` keeps its own commit). Writers therefore behave exactly as today outside a batch,
which keeps deploy/tests/test_backup.py and every seeding helper valid.
  </action>
