# Phase 47.1 Plan 06: Wake header, SPI timing, cost-neutrality review Summary

The frame now sends one `X-Wake-Stats` header on the display request, and times the SPI transfer with two timer reads. The firmware was NOT compiled for the target in this environment.

## What was done

- `api_client.c`: `wake_stats_header()` builds the value with `fp_wake_telemetry_format` from the current-wake values and `fp_wake_record_previous()` (validated inside the formatter; an invalid record means no `p_` keys; `require_sequential=false`, so gaps are sent and the server handles them by seq). A formatting error sends no header. It is called only in `fp_api_get_display`, after `telemetry_headers`. `clear_request_headers` deletes `X-Wake-Stats`. `fp_api_first_connect_ms()` returns the first-connect time saved in `fp_api_release()` before the counter is reset. `fp_api_set_wake_current()` hands the current wake's values over.
- `epd13in3e.c`: `#include "esp_timer.h"`, one static `s_spi_us`, two `esp_timer_get_time()` reads around the two `send_half` calls, accessor `epd_spi_ms()` (declared in `epd13in3e.h`). `panel.c` and `panel.h` are unchanged (the state machine includes `epd13in3e.h` directly, so no forwarding was needed).
- `state_machine.c`: before the display request, builds the current-wake struct and calls `fp_api_set_wake_current`; after the draw returns, assigns `spi_ms` and `tls_ms`. `state_machine.h` gets a `seq` member in `fp_poll_timing_t`, set in `app_main.c` right after the boot counter is read (plan 05's struct had no seq member; this is a one-line addition).
- `firmware/tests/check_panel_diff.sh`, run from `run_host_tests.sh`: diffs the panel files against the pinned pre-instrumentation commit `b404122` (no `main`/`origin/main` ref exists in this clone, so the plan's merge-base command could not be used; `PANEL_DIFF_BASE` overrides; needs full history, CI uses `fetch-depth: 0`). Fails on any removed line, fewer than two timer reads, or any added line other than a timer-read/`spi_us`/`spi_ms` line, the exact `esp_timer.h` include, or a bare brace or blank.
- `VENDOR.md`: rows updated for api_client.c/h, state_machine.c/h, app_main.c, epd13in3e.c/h, wifi.c/h; `wake_telemetry.*` and `wake_record.*` listed as new files of this project, plus the new check script.

## X-Wake-Stats leak argument (code argument, no host test)

`api_client.c` needs ESP-IDF, so it has no host test. The argument: every request on the shared handle calls `clear_request_headers(http)` first (setup at the start of `fp_api_setup`, display before `auth_header`, and before the image download), and that function now deletes `X-Wake-Stats`. The header is set in exactly one place, after the display request's own clear. The setup request never sets it. A header set on the display request is therefore deleted before the download or any later request.

## Cost-neutrality review (from `git diff b404122 HEAD -- firmware/main`)

Added in plans 05 and 06, checked for anything that costs time or energy:
- Flash writes: none. The previous-wake record is `RTC_DATA_ATTR` (RTC memory); no NVS call added (the only NVS access, the boot counter, existed before).
- Requests: none added. One extra header on the existing display request; request count, order, retries and TLS setup unchanged.
- Delays: none added. No `vTaskDelay`, `esp_rom_delay_us` or wait added or altered anywhere; panel delays and the 800 us row pacing are untouched (assertion above).
- Radio time: the header adds at most 192 bytes to a request (about 190 bytes on the wire, negligible against the TLS and image transfer). `fp_wifi_attempts()` only reads the existing retry counter.
- Log lines: no new `ESP_LOG` call; the existing diagnostic `wake timing` line gained fields (bt, att, rd, sp, tls, out), a longer snprintf on a line already logged.
- CPU: one `snprintf` of at most 192 bytes per wake, one record encode with a checksum at sleep entry, four-odd `esp_timer_get_time` reads.
- Panel: only the two timer reads, one static, one accessor; sleep logic and sequence byte-identical.
Conclusion: nothing beyond RTC stores, snprintf of at most 192 bytes, one header on an existing request and timer reads. Confirmed by review only; on-target cost is unmeasured.
