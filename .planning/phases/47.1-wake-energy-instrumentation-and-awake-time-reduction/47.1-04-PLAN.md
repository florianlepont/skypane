  <name>Task 1: Pure module and host test</name>
  <files>firmware/main/wake_telemetry.h, firmware/main/wake_telemetry.c, firmware/tests/test_wake_telemetry.c</files>
  <behavior>
    - Format with a valid record and current-wake values yields the exact golden string, at most FP_WAKE_STATS_MAX_LEN (192) bytes, keys in contract order, v=1 first
    - Format with an invalid record (wrong magic, wrong checksum, or p_seq not equal to seq minus one when the caller asks for the sequential check) omits every p_ key and still emits v, seq, bt, wf, att
    - Values above the contract bound are clamped to the bound (never wrapped, never emitted out of range); p_rd above 2 invalidates the record; an outcome token with a character outside lowercase, digit or hyphen, or longer than 16, is replaced by the token unknown
    - A zeroed record and an all-ones record validate as invalid; a record built by the encoder validates as valid and round-trips every field
    - Worst case: every field at its bound (seq and p_seq 4294967295, every ms key 3600000, att 16, p_rd 2, a 16-character p_out) formats to the golden worst-case string of 173 bytes, within the cap, with no truncation; values above their bounds clamp to that same string
    - Output buffer too small returns an error and never writes past the buffer
  </behavior>
  <action>
Create wake_telemetry.h and wake_telemetry.c with no ESP-IDF include (plain stdint, string, stdio snprintf only). The header declares fp_wake_record_t (magic, seq, awake_ms, request_ms, download_ms, draw_ms, spi_ms, tls_ms, redraw state 0 to 2, outcome token buffer, checksum), a function to build and checksum a record from measured values at sleep entry, a function to validate a record (magic and checksum), and fp_wake_telemetry_format(out, out_len, current-wake values, previous record pointer or NULL) returning the written length or a negative error. Declare the cap once as FP_WAKE_STATS_MAX_LEN (192) in wake_telemetry.h and use it for the caller's buffer size and the length check; it must equal WAKE_STATS_MAX_BYTES in server/wake_stats.py (plan 02). The checksum is a simple 32-bit sum or xor over the fields plus a nonzero magic, chosen so zeroed and all-ones memory fail. Per the contract: omit p_ keys when the record is NULL or invalid; clamp to bounds. Do not use dynamic allocation or floating point. Then create firmware/tests/test_wake_telemetry.c in the style of test_panel_guard.c covering the behavior block with golden strings. Add one cross-check test in the Python suite of plan 02's tests only if it needs no new file: instead, record the golden strings in the C test and run them through server/wake_stats.parse_wake_stats from the command line in the verify step below, so the C output and the server grammar are shown to agree (a mismatch here is the bug this plan exists to catch).
  </action>
