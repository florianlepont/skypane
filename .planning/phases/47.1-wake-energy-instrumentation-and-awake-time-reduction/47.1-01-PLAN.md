2. The contract, decided here (Claude's discretion area, one header, no second request, no new libraries): request header X-Wake-Stats on GET /device/v1/display, value a semicolon-separated key=value list starting with v=1. Keys, all optional except v: seq (the NVS boot counter of this wake), bt (ms from app start to Wi-Fi start), wf (ms Wi-Fi connect plus time sync), att (Wi-Fi attempts), and the previous-wake keys carried in RTC memory across deep sleep: p_seq, p_aw (total awake ms at sleep entry), p_rq (display request ms), p_dl (image download ms), p_dr (panel draw ms), p_sp (SPI transfer ms inside the draw, timer reads only), p_tls (first TLS connect ms), p_rd (0 no draw, 1 drawn, 2 deferred), p_out (outcome token, lowercase letters, digits and hyphen, 1 to 16 characters, ok or the failure step). Bounds: seq and p_seq 0 to 4294967295; every ms key 0 to 3600000; att 0 to 16; p_rd 0 to 2; whole value at most 160 bytes. Grammar rule: any violation (unknown key, duplicate key, out-of-range, bad token, unknown version, oversize) makes the whole header ignored and every wake column NULL; the battery reading and the other telemetry are still stored. A frame that does not send the header produces NULL columns and works as today.
3. Database route (the planner's choice, recorded): nullable columns added to device_health by a guarded ALTER TABLE ADD COLUMN driven by PRAGMA table_info inside init_schema (one row per wake stays one row; no join). Columns: wake_seq, boot_ms, wifi_ms, wifi_attempts, prev_seq, prev_awake_ms, prev_request_ms, prev_download_ms, prev_draw_ms, prev_spi_ms, prev_tls_ms, prev_redraw (integers) and prev_outcome (text). The read-only export falls back to its current five-column select when the columns do not exist yet so it never returns 503 before the migration runs (the migration runs in the 30 s poll oneshot after a deploy). Export keys are the five existing names followed by the thirteen column names above, always present, null when absent.
4. Rejected, with reasons from the research: a second request for telemetry (costs awake time), a second battery read at sleep entry (about 1 mV per wake, below ADC noise), several separate headers (each needs an allowlist and freeze entry), a new table (needs a join and a table-exists fallback).
5. The awake proxy: gap between wakes minus sleep_s is NOT a clean awake time (the research shows a hypothesis, labelled unproven, that the deep-sleep timer runs about 0.45 percent short; 47.1-RESEARCH.md Section 4).
