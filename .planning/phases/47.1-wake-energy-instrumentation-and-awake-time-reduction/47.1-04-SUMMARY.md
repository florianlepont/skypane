# Phase 47.1 Plan 04: Wake telemetry core Summary

A pure C module (no ESP-IDF include) formats the `X-Wake-Stats` value the server grammar accepts, clamps every number to the contract bound, and carries the previous wake's phase timings in a record sealed with a magic and checksum so cleared, corrupt or all-ones RTC memory is dropped and the `p_` keys are omitted instead of sent as zeros.

## Commits
- 76c64b0: module, host test, and the server-side cross-check test

## What was built
- `fp_wake_record_encode`, `fp_wake_record_valid`, `fp_wake_telemetry_format(out, out_len, cur, prev, require_sequential)`; returns length or a negative error, never writes past the buffer, empties the buffer on error.
- Invalid record (wrong magic, wrong checksum, `p_rd` above 2, NULL, or wrong sequence when asked) omits all `p_` keys; bad or over-long outcome tokens are sent as `unknown`; values above bounds clamp.
- `FP_WAKE_STATS_MAX_LEN` (192) is defined once in `wake_telemetry.h`. `server/test_wake_stats_firmware_agreement.py` compares it with `WAKE_STATS_MAX_BYTES`, compiles the real `wake_telemetry.c` with the host `cc`, and feeds typical, no-previous, clamped worst-case (173 bytes) and bad-token headers to `parse_wake_stats`; all accepted with expected values.
