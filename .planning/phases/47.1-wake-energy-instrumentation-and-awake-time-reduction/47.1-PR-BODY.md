## Wake-energy instrumentation: fleet path and freeze list (phase 47.1, plan 03)

The byos fleet (non-live device) path now parses the new `X-Wake-Stats` request header with the strict parser and stores the wake columns in that device's own history database. An absent or malformed header stores NULL columns only. The display response, `battery_state.json`, `device_report.json` and stdout are unchanged.

## Frames that do not send the header

A frame that sends no `X-Wake-Stats` gets a byte-identical display response and identical `battery_state` and `device_report` effects. The freeze suite and the wake-interval delivery suite pass unchanged apart from the amended list.

## Live device

On the live device the header is parsed by the access-log tailer in the poll oneshot, not by byos. That parser is covered by the server tests (`server/test_caddy_tail.py`), not by the byos freeze probe. The freeze probe measures the header on a fleet device, the only path on which byos writes history.
