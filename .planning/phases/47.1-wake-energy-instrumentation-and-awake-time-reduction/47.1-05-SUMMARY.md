# Phase 47.1 Plan 05: Wake record capture Summary

Every path that sleeps now stores a sealed previous-wake record in RTC memory inside `enter_deep_sleep`, built from timings the wake path already measured; nothing was added to the radio, flash or timing behaviour.

## Commits
- 5bcde3f: Wi-Fi attempt accessor, extended timing struct, `wake_record.{c,h}`
- 588f7fa: record built and stored in `enter_deep_sleep`, extended `fp_diag` line, OTA restart comment

## What was built
- `fp_wifi_attempts()` returns `s_retries + 1` capped at 4 (0 if no join was started). One new static flag is set just before `esp_wifi_connect()`; retry counts, timeouts and backoff are unchanged.
- `fp_poll_timing_t` gained `boot_ms` (elapsed at the connect call), `wifi_attempts`, `redraw` (0/1/2), `spi_ms` and `tls_ms` (both 0 until plan 06 fills them). `display_ms` is the record's request time.
- `wake_record.c` owns the single `RTC_DATA_ATTR fp_wake_record_t`; `fp_wake_record_store()` is called only from `enter_deep_sleep`, `fp_wake_record_previous()` is the reader (never NULL; callers validate).
- `app_main.c`: static boot counter (seq) and outcome token ("ok", or the failure step such as `wifi`, `config`, `deadline`, `nvs`). `redraw` is 1 on a successful blit, 2 on a guard deferral, and also set for the fault screen drawn/deferred in the failure exit. The `fp_diag` timing line gained `bt att rd sp tls out` (this wake's values, no `p_` prefix to avoid confusion with the previous-wake keys); the five frozen log-contract strings are unchanged.
- Comment at the OTA `esp_restart()` explaining that the restart bypasses `enter_deep_sleep`, so that wake's record is not written and RTC data is reinitialised. Control flow untouched.

## Deviations from Plan
**1. [No change needed] `CMakeLists.txt` not edited.** `main/CMakeLists.txt` uses `SRC_DIRS "."`, so `wake_record.c` is compiled by the directory glob (same as `wake_telemetry.c`).

**2. [Interpretation] Fault-screen wakes record `redraw` but not `draw_ms`.** The fault screen draw has no existing timer; adding one was avoided to keep the diff to existing measurements. `p_dr` is therefore 0 for a wake that drew only the fault screen.

**3. [Naming] The new `fp_diag` fields are `rd`, `sp`, `tls`, `out`, not `p_*`.** They describe the current wake in the log; the plan said "p_ values".
