Facts verified while planning (re-verify nothing; use as stated):
- The wake interval accepts 60..3600 s (`WAKE_INTERVAL_MIN_S`/`WAKE_INTERVAL_MAX_S` in server/device_policy.py), so 900 s is settable from the companion Device wake-interval setting (D-04).
- Precedence in server/wake.py `effective_wake_interval_s`: battery-critical parked cadence beats display-off cadence beats the configured wake interval. Therefore a display-off or quiet-hours state, or the BATTERY EMPTY park (`BATTERY_CRITICAL_MV = 3300`, hourly parked cadence), silently replaces the configured cadence for part of the run.
- Run one predates the BATTERY EMPTY park (added 2026-09-23). Run two will cross 3300 mV under park code that has never been exercised on glass. Gap-in-intervals and coverage figures after park onset are measured against the wrong cadence.
- Run one: 12.34 days, 3252 observed polls, mean poll-to-poll gap 328.0 s (about 28 s wake overhead over the 300 s setting), 0.923 mAh/cycle, 243.10 mAh/day, coverage 0.915 failed the pre-registered 0.95.
