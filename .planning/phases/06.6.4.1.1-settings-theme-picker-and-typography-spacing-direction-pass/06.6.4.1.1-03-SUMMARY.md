## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] My own new comment's literal selector text collided with an existing harness's naive media-block scan**
- **Found during:** Task 1 (running the full `test_status_pages.py` suite after adding the D-15 padding override)
- **Issue:** My first draft of the D-15 padding rule's comment (inside the `@media (min-width: 960px)` block) explained the chart-height safety argument by naming the selector literally: `` `.battery-trend-section svg:not(.icon)` ``. A pre-existing harness check scans every `@media` block's raw text for that exact literal string and, if found, additionally checks the whole block for any `height: <digit>` declaration (a `min-height: 100vh` elsewhere in the same media block matched). Because my comment happened to contain the literal selector text, the check false-flagged the media block as re-declaring the chart's height, even though no rule in the block actually does.
- **Fix:** Reworded the comment to describe the selector in prose ("the sparkline canvas's own selector (the section's `svg`, excluding the heading icon)") instead of quoting the literal string — the same fix pattern plan 02's own SUMMARY documented for an analogous collision.
- **Files modified:** companion/static/style.css
- **Verification:** `grep -n 'svg:not(.icon)' companion/static/style.css` shows the literal appearing only at its real rule declaration and two pre-existing, out-of-media-block comments; `test_status_pages.py` returns to a full pass.
- **Committed in:** ec4a5ac (part of Task 1 commit)
