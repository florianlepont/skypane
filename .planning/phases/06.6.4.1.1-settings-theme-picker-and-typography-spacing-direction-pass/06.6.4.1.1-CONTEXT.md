<decisions>
## Implementation Decisions

### Theme picker (UIR-01/02)

- **D-01:** Visual treatment is chip cards reusing the Runway-picker idiom exactly: native radio visually hidden inside the label (matching `.runway-card`'s existing hidden-input pattern), a swatch pair (departing/arriving colour, from `_palette_hex()` — already shipped for the single-theme read-only branch) plus the theme name, and an accent border on the selected chip. Not a `<select>`, not a minimal radio-sizing patch.
- **D-02:** Layout is a wrapping compact grid, chips ~160px wide (the audit's own figure), several per row depending on viewport — not one enlarged runway-card-sized tile per theme, and not a single narrow stacked column.
- **D-03:** Each chip additionally carries a **real rendered preview** of that theme, not just the two colour chips alone. This is new scope beyond the audit's own text — confirmed explicitly by the developer after a fidelity trade-off was surfaced.
- **D-04:** Preview fidelity is a genuine render through `server.plane.render`, not a CSS/SVG approximation. Higher implementation cost (new rendering + caching infrastructure) accepted deliberately over the cheaper CSS-mockup alternative.
- **D-05:** Generation is on-demand, cached to disk in the state dir — not a manually-run build script committing 16 static PNGs to the repo. First Settings page load after a cache miss pays the render cost once per theme; subsequent loads serve the cached file. (Downstream planning must design the cache key/invalidation — themes are static once shipped, so keying on theme id alone is likely sufficient; confirm during planning, not assumed here.)
- **D-06:** All 16 previews render the **same fixed fictional scene** (a fictional departing flight + a fictional arriving train — exact fixture values, e.g. callsign, are an implementation detail for planning) so themes are visually comparable against identical content. Never the real latest-known flight/train data — that would invalidate the cache on every poll cycle.
- **D-07:** The rendered preview occupies a thin band across the top third of the chip (e.g. ~160×60px, cropped from the real 1200×1600 render, not the full aspect ratio) — the theme name and the two colour chips sit below it. Chips stay compact even with 16 of them; a full-aspect-ratio embed was explicitly rejected as making the page too tall.
- **D-08 (UIR-02):** The Theme group gets the same `.theme-status`/`.page-section` card wrapper (rounded, hairline border) that Runway/LED/Poll already use — implied by adopting the chip-card treatment above, not a separate open question.

### Heading hierarchy (UIR-20, UIR-21, UIR-22)

- **D-09:** Nested card titles (e.g. "Battery trend" inside a `.page-section--nested` card) move to sans-semibold, 16px — the audit's own proposal, NOT the current 20px serif regular. **Note for planner:** this reverses quick task 260902-iag's own explicit reversal (iag moved this exact text FROM 16px-semibold BACK to plain serif, at the developer's direct request, after an isolated tweak felt wrong in context). This time it is being re-applied as part of a comprehensive, coherent hierarchy redesign (a real type ladder with page-title/section-heading/card-title tiers), not as an isolated demotion — the developer confirmed this explicitly aware of the prior reversal. Read `sketch-findings-skypane`'s "Nested card title tier" entry for the full round-trip before touching this.
- **D-10:** Page title (`h1`, `.page-title`) grows from 30px to 32px, gains weight 600 and `-0.015em` tracking. Section headings (`h2`, `.text-heading`) grow from 20px to 22px, stay weight 400. This is the full audit-proposed scale, not a weight-only change at the current sizes — confirmed explicitly after presenting "keep current sizes" as the lower-risk alternative.
- **D-11:** The wordmark (`.site-title`) grows to 24px serif weight 600, `-0.01em` tracking (the audit's proposal) — not a small-caps/tracked treatment, not left unchanged.
- **D-12 (UIR-20):** The serif stack reorders to `"Iowan Old Style", Charter, "Palatino Linotype", Georgia, "Book Antiqua", serif` (Iowan Old Style/Charter first, matching what Apple devices actually bundle) — adopted as proposed, near-mechanical, no further discussion needed.

### Label voice unification (UIR-23)

- **D-13:** The serif Label role (currently `.stat-tile__caption` at 14px serif) is retired entirely. Every label — stat-tile captions, table headers, filter counts, chips — converges on ONE voice: sans, 12px, weight 600, uppercase, `+0.06em` tracking. This is a full replacement, not a "new usages only" carve-out — confirmed explicitly.

### Spacing rhythm (UIR-24, UIR-25, UIR-26)

- **D-14 (UIR-25):** Sibling-card gaps unify to one value, 24px, in both grid and stacked contexts — the current 32px-in-grid / 24px-stacked distinction is treated as an inconsistency to remove, not a deliberate reading the developer wants kept.
- **D-15 (UIR-25):** Card padding (`.page-section`/`.theme-status`) increases to 20-24px at `>=960px`, stays 16px below that breakpoint — desktop gets more breathing room, mobile keeps its current density.
- **D-16 (UIR-25):** One-line full-width cards ("Device last checked in", "ADS-B pipeline last ran") get a `max-width` on their text content only — not a restructure into a two-up grid row. Lower-risk, doesn't touch page grid structure.
- **D-17 (UIR-25):** The flash banner (`Saved —`) moves to render after `page_header()` instead of before it, so the page title stops shifting position on save — the conventional slot.
- **D-18 (UIR-26):** History's secondary hex text moves from 12px/70% to 13px/75% (the audit's contrast-adjacent proposal), AND buttons grow to 14px/36px specifically below the 960px breakpoint (13px/30px is kept at `>=960px`, where it was a deliberate density trade-off per 06.6.4 D-01 — that decision is NOT reopened for desktop, only extended with a mobile-specific override).
- **D-19 (UIR-24, adopted directly — low ambiguity, not separately discussed):** Section-intro pairs (heading + muted caption on one baseline) switch from `align-items: baseline` row to `flex-direction: column` below 960px, so the caption stacks under the heading instead of wrapping into a hanging em-dash line. This is the audit's own concrete fix with no real alternative surfaced during discussion; flagged here for planner visibility rather than silently applied.

### Claude's Discretion

- Exact cache-key/invalidation scheme for the theme-render previews (D-05) — themes are static once shipped, so a simple theme-id-keyed cache file is the likely default, but confirm against how other cached/generated assets in this codebase are invalidated (e.g. the illustration-normalization cache) before committing to a scheme.
- The exact fictional flight/train fixture values for the preview scene (D-06) — callsign, route, timing. Any plausible, clearly-fictional values are fine as long as they're identical across all 16 renders.
- Precise CSS mechanics for the unified 12px label voice (D-13) migrating `.stat-tile__caption` off serif — this is a value change to an existing rule, not a new component; standard `sketch-findings-skypane` conventions (copy literals, don't extend selector lists the harness pins by exact string) apply.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `.runway-card` markup + CSS (`companion/pages/config_page.py`, `companion/static/style.css`) — hidden-radio-in-label, accent-bordered-when-selected chip mechanism, directly reusable for the theme picker's chip cards.
- `_palette_hex(index)` (`companion/pages/config_page.py:167`) — already resolves a palette index to a hex colour; both swatches and any preview-adjacent styling can read from it.
- `.theme-status` / `.page-section` card wrapper — already used by Runway/LED/Poll, direct reuse for D-08.

### Established Patterns
- Duplicated-not-imported cross-module constants (route prefixes, DOM literals) — if a new preview route is added (`/theme-preview/{id}.png` or similar), it should follow the existing `RUNWAY_IMAGE_ROUTE_PREFIX`/`ILLUSTRATION_ROUTE_PREFIX` precedent: membership-validated against `THEMES` keys before any path is built, never built from unvalidated request input (matches the project's own recorded threat-modeling discipline on similar routes, e.g. 06.4's runway-image route).
- `companion/illustration_normalize.py` — the closest existing "normalize/cache a derived image asset" pattern in this codebase; worth reading even though it processes uploaded illustrations rather than rendering from scratch, since its cache-directory-under-state_dir convention is the most likely template for D-05's theme-preview cache.

### Integration Points
- New/changed CSS lands in `companion/static/style.css`, following its established "new rule vs. edit existing rule" discipline — `companion/test_status_pages.py` and siblings pin several selectors by exact literal string (`css_source.index('<selector> {')`), so extending an existing selector's declaration list can silently break a passing harness check into a `ValueError`. New rules only where the audit calls for a still-independent selector.
- Any new theme-preview route needs session-gating like every other authenticated image route in `companion/app.py` (`/gallery/*`, `/runway-image/*`, `/illustration/*`) — this is an authenticated Settings-only affordance, not a public asset.
