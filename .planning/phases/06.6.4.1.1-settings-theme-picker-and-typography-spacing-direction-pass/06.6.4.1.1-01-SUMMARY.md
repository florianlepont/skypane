# Phase 06.6.4.1.1 Plan 01: Theme preview render + cache + route Summary

**Real `server.plane.render` panel renders, cropped/downscaled and disk-cached per theme, served at a new session-gated `/theme-preview/{id}.png` route for all 16 registered themes.**

## Performance

- **Duration:** ~30 min
- **Completed:** 2026-09-03T20:50:00Z
- **Tasks:** 2
- **Files modified:** 3 (1 created, 2 modified)

## Accomplishments
- `companion/theme_preview.py`: a fixed-scene (D-06), genuinely-rendered (D-04) theme preview module — `preview_png_bytes()` calls `render.build_canvas()`, converts P-mode to RGB before crop/resize (load-bearing ordering), crops to a measured 1200x450 band and downscales LANCZOS to 320x120.
- `preview_signature()`/`cache_path()`/`cached_preview_bytes()` implement D-05's on-demand-generation-cached-to-disk requirement with a signature keyed on the theme entry + `panel_format.PALETTE_RGB` + crop/size + a manual `THEME_PREVIEW_CACHE_VERSION`, so a future palette re-tune (already happened once, in 07-01) is a cache miss rather than a silently stale image.
- `GET /theme-preview/{id}.png` in `companion/app.py`: membership test against `device_config.THEMES` before any path is built, session-gated in `do_GET()`, degrading unknown ids/render failures/OSErrors all to the same 404 as `_serve_runway_image()`/`_serve_illustration_image()`.
- Verified all 16 themes render with pairwise-distinct mean RGB at the chosen crop/size, proving the crop box actually discriminates themes rather than landing on a region every theme paints identically.
- Manual cold-cache check (per the plan's `<verification>` section): deleted/absent `{state_dir}/theme_previews/`, hit the route, confirmed the directory and a `white-2f3abcafd6fa.png` file appeared.

## Decisions Made
- Realised D-06's "fictional departing flight + fictional arriving train" as a departing main flight + arriving previous flight (`THEME_PREVIEW_STATE="departing"`, `THEME_PREVIEW_PREVIOUS_STATE="arriving"`), since `render.py` composes only two flight-card slots and has no train renderer.
- Fixture values (`THEME_PREVIEW_FLIGHT`/`THEME_PREVIEW_ROUTE` = AFR1789 Air France ORY→JFK; `THEME_PREVIEW_PREVIOUS_FLIGHT`/`THEME_PREVIEW_PREVIOUS_ROUTE` = VLG1523 Vueling BCN→ORY) are this module's own constants, not imported from `render.py`'s private `_PREVIEW_ROUTE`/`_PREVIEW_PREVIOUS_ROUTE` manual-QA fixtures, which carry no stability contract and are free to change independently.
- `THEME_PREVIEW_ROUTE_PREFIX` is defined in `theme_preview.py` (the mechanism) rather than a page module (the emitter) — a deliberate, commented departure from the `RUNWAY_IMAGE_ROUTE_PREFIX`/`ILLUSTRATION_IMAGE_ROUTE_PREFIX` precedent, because plan 05's `config_page.py` markup will rebind this same constant a second time.
- Cache signature folds in `panel_format.PALETTE_RGB` alongside the theme entry, crop box, and output size — answering CONTEXT's explicit "confirm the cache scheme during planning" instruction by pointing at the project's own 07-01 real-glass palette re-tune as the concrete failure mode a theme-id-only key would miss.
