<objective>
Build the net-new backend half of the theme picker: a module that renders a real
`server.plane.render` panel per theme against one fixed fictional scene, crops it to a
thin landscape band, caches the PNG on disk under the state dir, and a session-gated,
membership-validated route that serves it.

Purpose: D-03/D-04 rejected a CSS/SVG approximation of the theme preview in favour of a
genuine render. That is new infrastructure — a new call pattern into `render.py` (no
prior caller renders a non-live "sample" scene), a new cache directory, and a new
authenticated image route. It lands on its own, ahead of any markup, so the UI plan
(05) only has to emit `<img src>` against a route that already works.

Output: `companion/theme_preview.py`, a `/theme-preview/{id}.png` route in
`companion/app.py`, and harness coverage in `companion/test_companion_app.py`.
</objective>

  Then the functions:

  `preview_png_bytes(theme_id)` — call
  `render.build_canvas(THEME_PREVIEW_FLIGHT, THEME_PREVIEW_STATE, route=…,
  previous_flight=…, previous_route=…, previous_state=…, theme_id=theme_id)`, then
  `.convert("RGB")` BEFORE any resize (resampling a "P"-mode image interpolates palette
  *indices*, producing colours that are not in the palette at all), then `.crop(
  THEME_PREVIEW_CROP_BOX)`, then `.resize(THEME_PREVIEW_SIZE, Image.LANCZOS)`, then save
  to an `io.BytesIO` as PNG and return the bytes. The convert-before-resize ordering is
  load-bearing — say so in the docstring, not just in the code.

  `preview_signature(theme_id)` — the cache key's discriminator, and the concrete answer
  to D-05's on-demand-generation-cached-to-disk requirement (explicitly not a build script
  committing 16 static PNGs to the repo). Return the first 12 hex
  characters of `hashlib.sha256()` over a stable repr of
  `device_config.THEMES[theme_id]`, `panel_format.PALETTE_RGB`, `THEME_PREVIEW_CROP_BOX`,
  `THEME_PREVIEW_SIZE` and `THEME_PREVIEW_CACHE_VERSION`, encoded UTF-8. Docstring must
  answer CONTEXT's explicit "confirm the cache scheme during planning" instruction:
  keying on the theme id alone would go stale silently if the panel ink is ever re-tuned
  again — which this project has already done once, on real glass, in 07-01 (see
  `panel_format.PALETTE_RGB`'s own comment block and `config_page._palette_hex()`'s
  docstring, which promises a re-tune "automatically updates every swatch"). Folding the
  palette and the theme entry into the filename makes a re-tune a cache MISS instead of a
  stale image, with no purge step for anyone to forget. Bumping
  `THEME_PREVIEW_CACHE_VERSION` is the manual escape hatch for a change this signature
  cannot see (a render-geometry change inside `render.py` itself).

  `cache_dir(state_dir)` — `os.path.join(state_dir, THEME_PREVIEW_CACHE_DIRNAME)`; return
  `None` for a falsy `state_dir`.

  `cache_path(state_dir, theme_id)` — return `None` when `state_dir` is falsy OR when
  `theme_id not in device_config.THEMES`. This membership guard is at the boundary itself,
  deliberately duplicating the route's own check rather than trusting it, exactly as
  `illustrations.override_path_for_key()` does (T-v26-01-01) — no path component is ever
  built from an id that is not a literal key of the registry. Otherwise join
  `cache_dir(state_dir)` and `"%s-%s.png" % (theme_id, preview_signature(theme_id))`.

  `cached_preview_bytes(state_dir, theme_id)` — return the cached bytes, rendering and
  writing them on a miss; return `None` for anything `cache_path()` refuses. Read the
  file if it exists; otherwise `os.makedirs(cache_dir, exist_ok=True)`, render, write to
  a temp file in the same directory named from the validated key plus `os.getpid()`, then
  `os.replace()` onto the final path — the same atomic-rename discipline
  `_handle_illustration_replace()` uses, so two concurrent ThreadingHTTPServer workers
  racing the same cold theme can never serve a half-written PNG. Let `OSError` propagate
  to the caller (the route handles it), matching
  `illustration_normalize.cached_normalized_png_bytes()`'s documented contract.

  Add the tests for this task in `companion/test_companion_app.py` (see the harness's own

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `GET /theme-preview/{id}.png` | Untrusted path segment crosses into code that builds a filesystem path |
| render engine → cached PNG on disk | Server-generated bytes land in a new directory under the state dir |
| panel data sources → preview image | The preview must NOT be a channel through which live flight/device data reaches an image |

| T-06.6.4.1.1-01 | Tampering | `Handler._serve_theme_preview_image()` | high | mitigate | Membership test against `device_config.THEMES` before any path is constructed (validate-then-join), mirroring `_serve_runway_image()`; `theme_preview.cache_path()` repeats the same guard at the boundary itself so the helper is safe even if a future caller forgets |
