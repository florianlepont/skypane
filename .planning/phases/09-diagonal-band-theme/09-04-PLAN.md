<expectation_note id="N-09-04-01">
**A forced render stays on the glass until the next real detection.** The poll loop holds the last panel through detection gaps by design (same behavior plan 08-06 documented). Every forcing step below ends the same way: restart the poll timer. If the session ends with that timer stopped, the frame sits on a synthetic test image indefinitely and looks like it is working. The timer's final state and a real post-restart poll cycle are both acceptance criteria.

**Each observation costs a full panel refresh**, roughly 31.5 seconds on this hardware (plan 08-06's measurement). Batch the forced renders in the order given below rather than tweaking and re-looking one change at a time.

**Confirm the deployed paths before forcing anything.** This plan writes the expected values (application root `/opt/skypane`, service user `skypane`, unit `skypane-poll.timer`/`skypane-poll.service`) from plan 08-06's own confirmed record — the operator should re-confirm them against the deploy directory and environment file on the host rather than trusting this document blindly, exactly as plan 08-06 itself required.
</expectation_note>

<in_session_correction_scope>
This session may apply bounded corrections directly, matching Phase 8's own precedent (plan 08-06). What counts as bounded here:

- A point-size adjustment on any of the band-specific text roles, respecting `fit_text_size()`-equivalent legibility (these roles do not currently shrink-to-fit; if the glass shows an overflow, the bounded fix is a size reduction, not adding a new fit mechanism mid-session — a genuine fit-mechanism gap is NOT bounded, see below).
- A geometry-constant nudge to `BAND_SHIFT_FRAC` or the dash width/gap constants, if real ink shows a collision the spike's screen-preview did not (mirrors plan 08-06's "geometry-constant nudge for bezel clearance or spacing" precedent).
- A palette RGB tweak is explicitly NOT bounded here — this phase introduces no new RGB triple, only combinations of the 6 already-calibrated Spectra 6 inks (Phase 7 already tuned all 6). If a band colour reads wrong on real ink, that is a genuine reopening, not a tuning pass.

What is **not** bounded, and requires an explicit, recorded developer instruction before it is touched:

- Excluding any of the 5 band colours from the shipped set, or changing which theme is default.
- Reinstating a text-backing-plate, outline, or shadow behind the band text (D-05/D-06 from Phase 8 rejected these project-wide; this phase inherits that decision).
- Changing the content ladder's tier definitions or the never-raw-callsign guarantee.
- Vendoring an italic font weight (the spike's own round-10 decision: PT Serif stays Regular project-wide, no italic).
- A materially different band geometry (a non-trapezoid shape, a different colour set) or a different card layout. Those need a new spike/phase.

Every correction applied in session must be re-rendered and re-confirmed on the glass before its step is considered closed, and the full test suite must pass again before the session ends.
</in_session_correction_scope>
