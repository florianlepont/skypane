<objective>
The developer's words, for the second time: *"Ok mais visuellement les titres sont
toujours incohérents !"*

27-06 investigated this in Phase 27 and concluded there was no defect. It reached that
conclusion by inventorying MARKUP — counting `text-heading` instances and classifying
them by which selector they sat under — and never once rendered Device and Display side
by side and read what the browser actually painted.

Rendered and measured, the delta is real and large: Device's **four** settings cards
(Diagnostic LED, Wake interval, Notifications — and Manual refresh, which arrives by a
different route and is the easy one to miss) render their titles at **22px / weight 400
/ serif** (the shared `.text-heading` default), while Display's nested cards render at
**16px / weight 600 / sans** (`.page-section--nested > h2, .battery-trend-section > h2,
.theme-status--nested > h2`). Two unrelated typographic registers for the same semantic
element, decided by nothing but which page you happen to be on.

**The cause is structural and PATTERNS.md located it exactly.** Device's render branch
flat-joins its cards — `groups_html = "".join(builders[g]() for g in groups if g in
builders)` — with no `_nested_wrapper_html()` call and no `section_intro_html()` heading
anywhere. Display's branch wraps each of its cards and introduces them under
supersections. The three Device card builders themselves (`led_group()`,
`wake_interval_group()`, `notifications_group()`) are correct and are NOT touched; only
the wrapping at the Device `render()` branch changes.

**And there is a FOURTH Device card that does not come through that branch at all.**
`poll_section_html` (Manual refresh / poll now) is built at `config_page.py:~5292-5297`
as a bare `<section class="page-section"><h2 class="text-heading">...` and appended at
`~5373`, outside the `builders` tuple entirely — `screens.py:~98` sets
`"has_manual_poll": True` and `screens.py:~91-92` documents in writing that this card is
"rendered directly by render()'s own has_manual_poll branch below, never through this
tuple." Wrap only the first three and this one stays at 22px/400/serif, which not only
leaves CFG-72 unmet for a card the developer can see, but breaks Task 2's own
cardinality-1 assertion. It is wrapped here too.

27-06 already conceded the point without acting on it. Its own inventory banner
(`test_config_page.py:~8353-8361`) calls the Poll heading unclassified and then writes
that its "ROLE — one heading, first thing inside its own box, naming exactly the one
card it belongs to — is otherwise identical to form A," and that it "carries no
[data-dirty-section] attribute only because it holds no persisted field for
dirty-tracking to watch." A card that is a card in every respect except a
dirty-tracking attribute is a card for CFG-72's purposes. That written concession is the
argument for wrapping it, and this plan cites it rather than inventing a new one.

**This plan edits no CSS.** The rule that produces 16px/600/sans already exists and
already lists BOTH `.page-section--nested > h2` and `.theme-status--nested > h2`. The
three builders-tuple cards wrap in `.theme-status` — the same base class Runway and
Quiet hours use — so they take `theme-status--nested`. The Poll card wraps in
`.page-section`, so it takes `page-section--nested`. Two modifiers, one rule, zero
declarations added. If a CSS edit still looks necessary, the modifier is wrong — re-read
the selector list before writing a declaration.

**And the proof is a rendered comparison, not a grep.** That is the whole lesson of
27-06 and it is this plan's central check.
</objective>
