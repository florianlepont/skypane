<objective>
The developer's words: *"Sur mobile le hamburger est perturbant car cela ressemble à
la navigation. Remplacer par un engrenage ?"*

This is the smallest item in the phase and the developer proposed the fix themselves.
`#site-nav-toggle` wears the universal "site navigation" glyph while opening a panel
that contains **zero page-navigation links** — real navigation moved to the bottom tab
bar in 22-14. The label (`"Account and preferences"`) has been accurate the whole time;
only the picture lied.

**This plan changes one argument and adds one symbol.** It does not touch the label, the
panel body, or any other icon consumer. Its only real hazard is the one PATTERNS.md
flagged: TWO checks hard-code the member count — `_icon_sprite_integrity()` AND
`_page_shell_emits_sprite_once_no_inline_styles()` — so adding a symbol without bumping
BOTH FAILS the suite rather than silently passing, which is the checks working correctly
and is why that file is in this plan's `files_modified`. 22-14 hit the same pair the last
time the sprite grew and edited both in place; the file's own header note at ~554-555
says so, and this task follows that convention.

**Why it is Wave 1 and parallel with 28-02:** its two files are disjoint from every
other plan in this phase's first wave. Nothing else writes `layout.py` or
`test_companion_app.py` in Wave 1.
