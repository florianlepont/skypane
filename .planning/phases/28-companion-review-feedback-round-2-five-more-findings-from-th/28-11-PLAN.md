<objective>
28-08 built the bar. 28-10 moved the existing browser coverage onto it. This plan adds the
three checks CFG-77 still owes — the clauses that had no executable coverage anywhere in
the phase.

**Section naming.** CFG-77 says the bar names the changed section(s) in document order.
Nothing proves it. A check that merely asserts the bar became visible would pass against a
bar that says "1 unsaved change" forever, which is the fallback branch, not the requirement.

**Cancel's side effects.** CFG-77 says Annuler restores every field and that the dial and
the theme preview stop showing the discarded value. `form.reset()` restores the fields
natively, but it fires no `change` or `input` events — so nothing downstream repaints on
its own, and the live preview would keep showing the discarded theme unless
`dirty-state.js` explicitly calls `window.SkyPaneLivePreview.refresh()`. That call has to
be proven by reading the resulting DOM, not by asserting the function was called.

CONTEXT.md separately claimed the quiet-hours dial repaints for free, because
`value-controls.js` already listens for `click` on `document` and the Cancel button's own
click bubbles into it. **That claim is wrong by specification, and 28-08 already refuted
it:** a `click` on a `<button type="reset">` dispatches and bubbles to COMPLETION before the
button's default action — the form reset — runs, so that listener repaints the dial from the
values the user just asked to discard. 28-08 therefore exposed `repaintAll` from
`value-controls.js` as a named entry point and calls it, together with
`window.SkyPaneLivePreview.refresh()`, from a single `setTimeout(fn, 0)` deferred tick inside
its `reset` handler — the first moment the restored values are actually readable. There is
nothing empirical left to settle. This plan asserts the RESULTING DOM STATE that mechanism
produces.

**The leave-guard's re-arm — BLOCKER 3, and the reason this plan exists as a separate
unit.** CFG-77's binding wording includes "does not disarm the leave-guard permanently...
kept exactly where CFG-63's own carve-out already put it." Nothing in the phase tests it.
28-10's retargeted guard check proves the guard arms on a typed edit, stays armed through a
commit, and disarms on Cancel — but it stops there. The clause that a NEW edit after a
Cancel re-arms the guard is the one T1 historically had to fix, it is the one a naive
implementation gets wrong (setting `suppressGuard = true` on Cancel and never clearing it),
and it currently has zero coverage. This plan adds it.

Purpose: give CFG-77's three unproven clauses executable contracts.
Output: three new relationship checks, each mutation-proven.
</objective>
