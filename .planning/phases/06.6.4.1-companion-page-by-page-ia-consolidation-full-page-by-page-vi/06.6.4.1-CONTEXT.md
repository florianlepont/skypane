# Phase 06.6.4.1: Companion page-by-page IA consolidation — Context

**Gathered:** 2026-09-01
**Status:** Ready for planning

<domain>
## Phase Boundary

A full page-by-page visual/content pass across all 5 companion pages, closing out the "regard neuf sur les 5 pages" request that also absorbed 06.6.3-08's dangling closing checkpoint. Every decision below was validated interactively this session as a standalone HTML sketch artifact (using real CSS tokens from `companion/static/style.css` and real content from `companion/pages/*.py`) before this phase was opened — nothing in `companion/` has been touched yet. This phase is the first real code change.

Net effect: Settings (renamed from Config) and Health get restructured; Airlines' old diagnostics content moves into Health and Airlines itself is reborn as a new illustration gallery (reusing already-shipped art, not adding a new capability from scratch); Preview disappears as a standalone page, absorbed into History. Nav stays at 4 items (Settings/Health/Airlines/History) — down from 5, but not down to 3, since Airlines survives repurposed rather than being removed.

<decisions>
## Implementation Decisions

### Settings (renamed from Config)
- **D-01:** Single-column stacked sections (Theme, Runway, LED) replace the current 2-column `.config-form` grid — this is the actual root-cause fix for the broken Runway section (`runway_fieldset()` in `companion/pages/config_page.py` emits 5 flat top-level elements with no wrapper div, unlike `theme_fieldset()`'s correct `<div class="theme-status">` wrap; the 2-column grid was never designed to hold an unwrapped fieldset).
- **D-02:** Each section gets a short descriptive sentence under its heading (validated: "ça manque d'une petite description de chaque paramètre").
- **D-03:** One page-level, sticky/fixed, full-width "unsaved changes" save bar (Discord-style) replaces the three current per-section dirty-bars. It names which section(s) contributed a change, with a single Save/Cancel pair for the whole page.
- **D-04:** Real bug fix bundled with D-03: `companion/static/dirty-state.js` currently only toggles `bar.hidden` and never hides the static no-JS fallback Save button, so today both show simultaneously. The unified bar replaces this entirely — once JS is confirmed running, the static fallback hides unconditionally (mirrors `nav-dropdown.js`'s existing `.js`-class-gated precedent).
- **D-05:** Backend route merge: the LED form's separate `/config-led` POST route folds into the same route/form as Theme+Runway's `/config`, submitting as one action. The original reason LED was kept separate — "a third fieldset would become a silent 2+1 orphan row" in the old 2-column grid — no longer applies once the page is single-column.
- **D-06:** No-JS graceful degradation is preserved: without JavaScript, the page still renders correctly and a real Save button still works, matching 06.6.3-08 checklist item 3's original intent, updated for the unified bar (bar never appears, but the underlying form submit still works).
- **D-26 (resolved post-research — genuine CONTEXT.md gap the researcher flagged):** The route itself renames too: `/config` → `/settings` (not just the nav label). The developer's explicit choice, against the researcher's own "keep `/config`, less blast radius" recommendation. Every internal reference to `CONFIG_ROUTE`/`/config` in `companion/app.py` and `companion/layout.py`'s nav renderer moves to `/settings`; `/config-led`'s retirement (D-05) means there is no second URL to reconcile. No redirect from the old `/config` path is required by any decision here — this is a fresh URL, not a deprecation of a URL anyone has bookmarked in a way this project needs to protect (unlike D-22's `/preview` → `/history` redirect, which exists specifically because Preview is a well-established page being removed, not renamed at inception).

### Health (absorbs the OLD Airlines page's diagnostics content)
- **D-07:** Anomaly banner uses short category-label pills (per UXA-06) instead of repeating the full-sentence detail list the Overview tiles already carry via colour/status (per 06.6.1-03's original intent) — this design satisfies both prior decisions' real intent rather than picking one over the other.
- **D-08:** Corroboration tile's 3 detailed explanation paragraphs are preserved (not deleted) but collapsed behind a native `<details>` "More details" disclosure, matching History's/Battery's existing disclosure precedent in this codebase.
- **D-09:** Battery trend section becomes a real interactive full-width SVG chart with labeled X/Y axes, a default always-visible "latest reading" value (no forced interaction needed to see a number), and working hover/click/keyboard reveal — plus a "View N readings" `<details>` table, same as before.
- **D-10:** Page restructures into two explicit, headed sections:
  - **"Screen"** — the physical frame's own status: the existing Device-freshness stat-tile, plus the Battery trend section (full width, unchanged position below the tiles).
  - **"Server & data"** — the ADS-B pipeline and route-resolution data: the existing Pipeline-freshness and Corroboration stat-tiles, PLUS a new third stat-tile, "Resolution rate" (the promoted headline, e.g. "52.6% resolved — last 30 days, 340 events"), all three in one `dashboard-grid` row.
- **D-11:** The old Airlines page's two sections — Unresolved-prefixes registry (with its filter bar) and Resolution-statistics breakdown table — move into "Server & data" as full-width cards, stacked vertically (NOT inside `dashboard-grid`/`.stat-tile`). This is the structural fix for two real bugs:
  - The "No resolution data yet" empty state used to read as a page-wide contradiction sitting above real Unresolved-prefixes data; scoped now under its own "Resolution statistics" sub-heading, the ambiguity disappears by construction.
  - The nested horizontal-scroll on the 5-column registry table was caused by forcing it into a narrow `.stat-tile` grid column (`.stat-tile`'s own CSS comment already documents this exact failure mode — the Battery-trend tile hit the same problem pre-06.6.1's D-02, which is why Battery trend already lives outside the grid). Full-width cards give the table real room; no CSS-only fix needed.
- **D-12:** The Unresolved-prefixes card keeps its filter bar and read-only note (D-16 from `airlines_page.py`: no button/form element, read-only by design) exactly as today — content and behavior unchanged, only its container changes from stat-tile to full-width card.

### Airlines (reborn as a visual illustration gallery — NOT the old diagnostics page)
- **D-13:** The `/airlines` route and nav slot are REUSED (not removed, not redirected) — same URL, entirely new page content. The old diagnostics content (Unresolved prefixes, Resolution statistics) has moved to Health per D-11/D-12; nothing on the new Airlines page duplicates it.
- **D-14:** The gallery shows one card per airline in `server/plane/illustrations.py`'s `_ILLUSTRATION_TARGETS` (27 distinct airlines today, via `target_airline_names()`), each showing:
  - The airline's real primary illustration PNG (already-shipped art in `server/assets/icons/illustrations/`, zero new asset pipeline).
  - The airline's name.
  - Chips for any fleet-type variants that airline has (e.g. Air Caraïbes: A330/A350/ATR72), derived from `_ILLUSTRATION_TARGETS`' shape entries.
- **D-15:** A new session-gated, membership-validated route serves the illustration PNGs — mirror `companion/app.py`'s existing `_serve_runway_image()`/`RUNWAY_IMAGE_ROUTE_PREFIX` pattern exactly: validate the requested key against a known-safe set FIRST (derived from `illustrations.target_filenames()`/`_ILLUSTRATION_TARGETS`, never the raw request), only then join a path — a request for an unknown key and a request for a real key with no file both 404 identically, leaking nothing about the filesystem.
- **D-16:** A lightweight filter bar (same visual pattern as History's) lets the user search by airline name across the 27 cards.
- **D-17 (Claude's discretion, not asked — kept in scope to match what was actually sketched and validated):** The gallery shows the full static curated list from `_ILLUSTRATION_TARGETS` regardless of whether that airline has ever actually been detected at this specific installation. Cross-referencing "seen at Orly" against real `history_db` data (e.g. a "seen" badge or a seen/unseen filter) is explicitly a DEFERRED idea, not built in this phase — see Deferred Ideas below.

### History (absorbs Preview entirely)
- **D-18:** Preview's "Live preview" content moves to a new "Now showing" section at the top of History: the live panel image (`.preview-frame`-style bounded, centered matte treatment) plus its "Captured {relative time}" caption and the mandatory not-colour-accurate caveat text, unchanged from `preview_page.py`'s existing `preview_section()`.
- **D-19:** Preview's render gallery (the grid of the last 12 renders) is preserved but demoted into a collapsed-by-default `<details>` "Recent renders (N)" disclosure directly under "Now showing" — not deleted, just no longer a full always-visible section, since per-row lookup (D-20) now covers most of that need.
- **D-20:** Every History row (both the desktop table's Timestamp cell and the mobile card's primary line) gains a small icon-button ("View panel near this time") that looks up and displays the gallery render whose filename-derived timestamp is nearest (before) that row's own timestamp — a render-time lookup against the existing `ctx["gallery_entries"]` list (`companion/app.py`'s `gallery_entries()`, already computed once per request), NOT a new stored relationship in the database. Shown in a small lightbox/overlay with the real matched timestamp labeled ("Panel near {ts}") plus a one-line note that this is the nearest render, not guaranteed to be that exact flight, since the panel refreshes on its own wake/poll cycle rather than once per detected flight. The real timestamp label is the only "distance" signal needed — no separate too-far threshold/fallback state is being added; showing the genuine nearest timestamp is self-documenting.
- **D-21:** History rows whose airline could not be resolved (`airline_label` falls back to `panel_render.ROUTE_FALLBACK_TEXT`, "Route unavailable") get a lightweight inline link to Health's new "Server & data" → Resolution-rate/Unresolved-prefixes section, instead of duplicating that registry table on this page too.
- **D-22:** `/preview.png` (the live-image byte-serving route) and `/gallery/{name}.png` (individual render byte-serving routes) are UNCHANGED — both are still needed as `<img src>` targets for History's new "Now showing" section and its Recent-renders disclosure. Only the `/preview` HTML *page* route becomes vestigial once Preview's page content moves into History; it should redirect to `/history` (302) rather than 404, so an old bookmark/link still lands somewhere useful.

### Cross-cutting / closing checkpoint
- **D-23:** This phase folds in and formally closes 06.6.3-08's own still-open Task 2 (blocking developer verification checkpoint) — left unresolved when the developer's "catastrophique" reaction to the shipped 06.6.2/06.6.3 UI redirected the session into 06.6.4's work instead. The closing checkpoint for THIS phase must cover the same ground 06.6.3-08's 20-item checklist covered, translated to the new page structure (Settings instead of Config's old layout; Health's new Screen/Server-and-data split; the new Airlines gallery instead of the old diagnostics Airlines; History's new Now-showing/per-row-lookup instead of standalone Preview) — not a literal item-for-item re-run of the old checklist against pages that no longer exist in that form.
- **D-24 (resolved via discussion this session):** 06.6.3-08's items 19 (a real assistive-technology pass — VoiceOver/NVDA/TalkBack) and 20 (a production authenticated walkthrough) were EACH ALREADY deferred once before this (originally from `06.6.1-UX-AUDIT.md`'s Wave 4, then again at 06.6.3-08). The developer's explicit choice this session: **do them for real this time, as part of 06.6.4.1's own closing checkpoint — no further deferral.**
- **D-25:** Full keyboard-only pass (06.6.3-08 item 18) is still required, updated for this phase's new controls: the unified Settings save bar's Save/Cancel, the Airlines gallery's filter input, and History's new per-row "View panel" lightbox button/close control, in addition to everything already covered.

### Claude's Discretion

- Exact wording for the unified Settings save bar's copy (which sections changed), the Airlines gallery's empty-filter-result copy, and the "View panel near this time" button's accessible label — follow this codebase's existing Copywriting Contract precedent (D-23-style "Copy {field}" pattern, `_FILTER_EMPTY_BODY_TEMPLATE` pattern) rather than being independently specified here.
- **`companion/pages/preview_page.py`'s fate once fully absorbed into History (D-18/D-19/D-22):** delete the file outright, not leave it orphaned. Matches this project's own stated convention (`CLAUDE.md`: "if you are certain that something is unused, you can delete it completely" — no backwards-compatibility shims). `companion/pages/__init__.py`'s page-module registry and any import of `preview_page` go with it; `companion/test_view_pages.py`'s Preview-specific test section is repurposed onto History's newly-absorbed content (Now-showing, Recent-renders disclosure), not left asserting against a deleted module.
- **Where the new per-airline fleet-variant grouping accessor lives in `server/plane/illustrations.py`:** add it as a new function alongside the existing `target_airline_names()`/`target_filenames()` accessors in that module (not in `companion/pages/airlines_page.py`) — it derives purely from `_ILLUSTRATION_TARGETS`, the same data source those existing accessors already read, so it belongs with them, matching this module's own established "one source of truth, several read-only accessor functions" shape.

- `layout.empty_state()`, `layout.status_dot()`, `layout.stat_tile()`, `layout.concise_timestamp_html()`, `layout.icon_html()` — existing `companion/layout.py` helpers this phase's new page code should call, not reimplement.

### Established Patterns
- Validate-then-join for any user-influenceable path/id before touching the filesystem (`_serve_runway_image()`'s `runway_id not in device_config.RUNWAY_IDS` check) — the pattern D-15's new illustration route must follow exactly.
- Native `<details>`/`<summary>` for any content that should stay present but not always visible (History's mobile "More details", Battery's "View N readings") — the pattern D-08 (Corroboration) and D-19 (Recent renders) both reuse.
- `_safe_query()` per-section database isolation (in both `health_page.py` and `airlines_page.py`) — a locked/missing/corrupt database degrades one section, never the whole page. The Resolution-rate/Unresolved-prefixes sections moving into Health (D-11) must keep this isolation, not merge it into Health's own broader `_read_health_inputs()` single-source-of-truth call in a way that would make one query's failure take down sections that used to fail independently.
- Single-escaping-choke-point discipline (`escape_html()` called exactly once per value, at the point of interpolation) — every new markup builder in this phase must follow this, matching every existing page module's own documented discipline.

### Integration Points
- `companion/app.py`'s route dispatch table (`do_GET`) — needs a new illustration-image route entry (D-15) and a redirect for the retired `/preview` page route (D-22); `/config-led`'s POST handler needs removing/merging into `/config`'s handler (D-05).
- `companion/layout.py`'s nav-link renderer (`_nav_links()`) — Airlines' nav label/slug stays, its route target's rendered content changes entirely.
