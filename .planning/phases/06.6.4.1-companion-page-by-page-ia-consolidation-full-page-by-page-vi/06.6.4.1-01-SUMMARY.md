# Phase 06.6.4.1 Plan 01: Shared stylesheet foundation Summary

**Landed every CSS rule waves 2-3's four page-module plans depend on in `companion/static/style.css`, plus the D-01 root-cause deletion of Settings' broken two-column grid — a single write site so the following page plans can run with zero file contention.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 3/3 completed
- **Files modified:** 1 (`companion/static/style.css`)

## Accomplishments

- Deleted the `>=960px .config-form` two-column grid rule group outright (D-01) — Settings' three sections now stack single-column at every viewport width via normal block flow, with a removal-rationale comment explaining this supersedes rather than re-tunes the layout.
- Added `.js [data-static-save-fallback] { display: none }` next to the existing `.js`-prefixed mobile-nav rules — hides the form's always-rendered bottom Save button once `nav-dropdown.js`'s unconditional `.js` class proves client-side script is running, so the unified dirty-bar is the sole visible save affordance and D-06's no-JS fallback still works (D-04).
- Added the Airlines illustration-gallery card system: `.illustration-grid` (200px auto-fill columns) plus `.airline-card` and its four BEM parts, carrying the 06.6.4 hairline-at-rest/shadow-on-hover card contract and a neutral 11px chip tier that adds zero new accent consumers (D-14).
- Added the History lightbox system: `.lightbox` (a styled native `<dialog>`, the phase's one deliberate exception to the hairline-at-rest contract since it's a floating modal, not a page-flow card) plus `.lightbox__image`/`.lightbox__caption`/`.lightbox__note`/`::backdrop` (D-20).
- Added `.sparkline-axis-label` (D-09) to the existing sparkline class family — 10px, `fill` not `color` since these are SVG `text` nodes, one step below `.data-table th`'s existing 11px sub-scale tier.
- Added `.banner__pill` (D-07) directly after the `.banner` severity modifiers — a neutral, flex-none pill declared byte-identical to `.airline-card__chip`, deliberately not severity-tinted since the banner's own edge/dot already carries that signal.

## Decisions Made
