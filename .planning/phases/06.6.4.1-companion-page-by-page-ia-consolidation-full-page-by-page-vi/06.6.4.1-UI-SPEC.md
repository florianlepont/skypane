# Phase 06.6.4.1 — UI Design Contract

> Visual and interaction contract for the companion app's page-by-page IA consolidation. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**How to read this document.** Every visual/interaction decision in this phase was already validated interactively by the developer as real HTML artifacts before this phase existed (see `06.6.4.1-CONTEXT.md`'s `<decisions>`/`<specifics>` sections — D-01 through D-26, all LOCKED). This UI-SPEC does not re-derive that direction. It translates those locked decisions into a formal, component-level contract grounded in the REAL, already-shipped tokens and markup in `companion/static/style.css` and `companion/layout.py` (both read in full this session), plus the REAL current markup in `companion/pages/config_page.py`, `health_page.py`, `airlines_page.py`, `history_page.py`, `preview_page.py` (all read in full this session). Every new component below reuses this codebase's existing visual vocabulary (hairline-at-rest/shadow-on-hover cards, quiet uppercase table headers, tinted-pill active states, native `<details>`/`<dialog>` over custom JS state) — **no new design tokens are introduced anywhere in this document.**

## Design System

| Property | Value |
|----------|-------|
| Tool | none — this is a hand-rolled stdlib Python HTTP service (`companion/app.py`, `http.server.ThreadingHTTPServer`) with server-rendered HTML string templates. There is no npm, no build step, no component library, no shadcn, and none should be introduced. |
| Preset | not applicable |

This phase's new components (below) follow the exact same pattern. |
| Icon library | none — a single inline SVG `<symbol>` sprite (`companion/layout.py`'s `ICON_DEFS_HTML`, referenced via `<use href="#icon-...">`), gated by a whitelist (`ICON_IDS`) rendered through `icon_html()`. This phase adds **zero new icon symbols** — every new component below reuses an existing glyph (see Component Reuse Contract). |
| Font | System serif (`Georgia, "Iowan Old Style", "Palatino Linotype", "Book Antiqua", serif`, `--font-serif`) — headings only (`h1`/`h2`/`h3`/`legend`/`.text-heading`/`.page-title`/`.site-title`/`.stat-tile__caption`). System mono (`ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`, `--font-mono`) — callsigns, hex codes, prefixes, timestamps, mV values. ## Typography

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Label | 14px | 400 (regular) | 1.4 | sans (`--font-ui`) |
| Body | 16px | 400 (regular) | 1.5 | sans (`--font-ui`) |
| Heading (section, `<h2>`) | 20px | 400 (regular) | 1.2 | **serif** (`--font-serif`) |
| Page-title (`<h1 class="page-title">`) | 30px | 400 (regular) | 1.2 | **serif** (`--font-serif`) |
| Emphasis (stat values, runway numbers) | 16px (Body size) | 600 (semibold) | 1.2 | sans |

There is no "Display" role — it was retired in Phase 06.6.4 (D-09), and its two consumers (`.stat-tile__value`, `.runway-card__number`) moved to the Emphasis role above. **Do not reintroduce a fifth size.** Every new text element this phase adds (section descriptions, banner pills, chip labels, lightbox caption, resolution-rate headline) must resolve to one of the five rows above — see Component Specs for the exact mapping per element.

Exactly 2 weights exist site-wide: 400 (regular) and 600 (semibold). This phase adds no new weight.

**Typography exceptions (pre-existing sub-scale, not new roles):** this codebase already has a documented, narrower-than-14px "sub-scale" tier reserved for quiet secondary/meta text, distinct from the five roles above and not counted against the "exactly 4 sizes" rule (which governs *content* typography roles, not this micro-label tier). Two real, already-shipped precedents, verified directly in `companion/static/style.css` this session:

| Precedent | Selector | Size | File:line | In-file justification |
|---|---|---|---|---|
| Table header labels | `.data-table th` | 11px | `companion/static/style.css:1265-1266` (comment at 1255-1264) | "06.6.4 (D-07): the header ... now reads as a quiet uppercase label ... " — an established quiet-label treatment, not a new type role. |
| Secondary table-cell data | `.cell-secondary` | 12px | `companion/static/style.css:1344,1346` (comment at 1331-1338) | "The 12px size on `.cell-secondary` is a legitimate secondary-data exception to the 4-size scale, scoped to this one class." — verbatim, in-file. |

This phase's two new sub-scale uses stay within that same established tier and are **scoped exceptions, not new type roles**:

| New use | Size | Where | Scoped to |
|---|---|---|---|
| Battery-trend chart axis labels | 10px | §5.3, `battery_sparkline_svg()`'s HTML `<span class="sparkline-axis-label">` axis labels (quick task 260902-ep7: moved out of the SVG's own `<text>` nodes — see §5.3's update) | The 4 min/max/oldest/newest axis-label glyphs beside/below the sparkline canvas only — same `color-mix(in srgb, var(--color-text) 70%, transparent)` muted strength `.data-table th` already uses at 1270, one step below `.cell-secondary`'s 12px because chart-axis micro-labels sit even further down the visual hierarchy than a table's secondary cell text. |
| Airline gallery chip labels | 11px | §7.1, `.airline-card__chip` | The airline fleet-variant chip pill text only — matches `.data-table th`'s existing 11px quiet-label precedent exactly (same size, same "small uppercase-adjacent meta label" role, not a table header but the same visual weight class). |

Neither 10px nor 11px is a fifth content-typography role: they are not used for headings, body copy, labels, or emphasis text anywhere in this phase, and no component in the five-role table above changes size. They are additions to the codebase's existing sub-scale-exception tier (`.data-table th` at 11px, `.cell-secondary` at 12px), which this phase extends by reusing the same reasoning at two new, narrowly scoped call sites — not by inventing a new type-scale entry.

## Component Specs — Settings (D-01 through D-06, D-26)

### §5.0 Page identity (D-26)

- **Route:** `/config` → **`/settings`** (D-26 explicitly overrides the researcher's own lower-blast-radius recommendation — this is locked, not discretionary). `/config-led` is retired (D-05, folded into `/settings`'s single POST).
- **Nav label:** "Config" → **"Settings"**. `NAV_TABS` entry becomes `("/settings", "Settings")`.
- **`_PAGE_TITLES["/config"]`** → `_PAGE_TITLES["/settings"] = "Settings"`.
- **`page_header()` title:** `"Settings"`.
- **No redirect from `/config`** — per D-26, this is a fresh URL at inception, not a deprecation of a bookmarked page (unlike `/preview`'s 302, §8.0).
- **Nav icon:** `NAV_ICON_IDS`'s `"config"` key renames to `"settings"` (the dict key must track the new slug, since `_nav_links()` derives `slug = route.lstrip("/")`). **The SVG symbol id itself (`icon-nav-config`) may stay unchanged** — it's a gear glyph, visually correct for "Settings" too; renaming the symbol id is optional cosmetic churn, not required by this spec.

### §5.1 Single-column layout + unified save bar (D-01, D-03, D-04, D-05, D-06)

**Layout:** `.config-form`'s `>=960px` 2-column grid (`style.css` L2021-2037) is deleted. Sections stack single-column at every width: Theme → Runway → **Save Settings** (bottom fallback button, see below) inside one `<form>`, then the Poll section, with the LED section now **merged into the same form** (no longer a separate `<section>`/`<form>` — D-05).

**Runway wrapper fix (D-01, root cause):** `runway_fieldset()` currently returns 5 flat top-level elements with no wrapper (`config_page.py` L243-247 — an `<h2>`, N cards, a `<p>`, no container). Wrap it exactly like `theme_fieldset()`'s existing `<div class="theme-status">` pattern (`config_page.py` L137-153): `<div class="theme-status">` around the `<h2>Runway</h2>`, the cards, and the helper `<p>`. **Reuse the `.theme-status` class name and CSS verbatim** — do not invent a new wrapper class; the two sections should share one wrapping idiom.

**Section descriptions (D-02):** one `<p class="text-body">` sentence directly under each section's heading, before its controls. Exact copy:

| Section | Description sentence |
|---|---|
| Theme | "The color palette used for departing and arriving flights on the physical frame." |
| Runway | "Which Orly runway the device watches for departures and arrivals." |
| Diagnostic LED | No new sentence needed — `LED_HELPER_TEXT` (`config_page.py` L39-43) already reads as a description and already renders under the `<legend>`; D-02 is already satisfied here. |

**Unified save bar (D-03):** reuse `.dirty-bar`/`.dirty-bar__save`/`.dirty-bar__cancel` **unmodified visually**. What changes is the copy inside `[data-dirty-count]` — instead of a raw field-diff count, it names which of the three sections (Theme/Runway/Diagnostic LED) changed:

| Sections dirty | `[data-dirty-count]` text |
|---|---|
| 1 | "{Section} changed" — e.g. "Theme changed" |
| 2 | "{A} and {B} changed" — e.g. "Theme and Runway changed" |
| 3 | "{A}, {B}, and {C} changed" — e.g. "Theme, Runway, and Diagnostic LED changed" |

The bar remains a single page-level instance (not per-section), sticky at `>=960px` (existing `.dirty-bar` sticky rule), non-sticky full-width in normal flow below that. One Save/Cancel pair, submitting the whole merged form.

**No-JS fallback fix (D-04) — reuses the existing `.js` class, zero new JS:** `nav-dropdown.js` already adds a `.js` class to `<html>` unconditionally as its first statement, present on every authenticated page including Settings. Give the form's own always-rendered bottom `<button type="submit">Save Settings</button>` a new attribute, `data-static-save-fallback`, and add exactly one new CSS rule:

```css
.js [data-static-save-fallback] { display: none; }
```

Without JS: `.js` is never added, the rule never applies, the bottom button is the only way to save (unchanged, D-06's graceful degradation). With JS running: the bottom button hides unconditionally the instant the page loads, regardless of dirty state — only the unified bar (which itself is `[hidden]` until dirty) can save. This is the precise fix for the real bug D-04 names: today `dirty-state.js` only ever toggles `bar.hidden`, so the old per-section bars and this same bottom button used to show simultaneously.

**LED merge (D-05):** `led_fieldset()`'s markup (checkbox + `LED_HELPER_TEXT`) moves inside the same `<form action="/settings">` as Theme/Runway, after Runway, before the bottom Save Settings button. `led_section()`'s own `<section class="page-section"><form>...` wrapper is deleted — the LED fieldset becomes a third fieldset-equivalent group inside the single form, matching Theme's/Runway's own heading pattern (an `<h2 class="text-heading">Diagnostic LED</h2>` replacing the `<legend>`, for visual consistency with Theme/Runway now that all three are siblings in one single-column stack — the `<legend>`-vs-`<h2>` distinction from the old 2-column grid layout no longer needs to exist once there's no `<fieldset>` wrapper reason left).

### §5.3 Battery trend chart (D-09)

Container (`.battery-trend-section`, heading, "View N readings" disclosure) is unchanged. Two real behavior/visual changes to `battery_sparkline_svg()`'s output:

1. **Default always-visible latest reading.** `_battery_readout_block()` currently seeds `#battery-readout` with a prompt (`BATTERY_READOUT_PLACEHOLDER`, "Tap or hover a point…"). Change the default text to the **latest point's own reading**, using the exact same label format `battery_sparkline_svg()` already builds per-point (`"%d mV — %s" % (value, ts)`). Hover/click/keyboard focus on any other point overwrites this text as it already does today (unchanged JS behavior in `battery-trend.js`); moving focus/pointer away should revert to the latest reading (not blank, not the old placeholder) — the "latest reading" is the resting state, not "no selection."
2. **Labeled X/Y axes.** A Y-axis pair (min/max mV values, e.g. "3850 mV" / "4200 mV") positioned above/below the plot area, and an X-axis pair (oldest/newest reading's short `HH:MM` clock time, matching `concise_timestamp_html()`'s own clock-format convention) positioned left/right below it. Typography: 10px, `--weight-regular`, `color-mix(in srgb, var(--color-text) 70%, transparent)` (this file's one existing muted-secondary strength — do not invent a new percentage).

   **quick task 260902-ep7 (BUG 4) update:** the "SVG viewBox grows from 300×60" sentence above is retired — the SVG no longer carries a viewBox at all. With no viewBox, 1 SVG user unit equals 1 CSS pixel and every plotted x-position is a percentage of the canvas's own real rendered width, so the chart's fill-the-card behavior is structural rather than a tuned viewBox size. The four axis labels move from SVG `<text>` nodes to HTML `<span class="sparkline-axis-label">` elements in a CSS grid outside the SVG (an `auto`-sized label column measures its own real rendered width, replacing the old `_AXIS_LEFT_GUTTER`/`_AXIS_BOTTOM_STRIP` Python estimates) — same 10px/`--weight-regular`/70%-muted typography as before, unchanged.

Content (reused verbatim from the old `_resolved_headline_html()`'s "figure" half, `airlines_page.py` L292-313):

```html
<p class="stat-tile__value">{pct}% resolved</p>
<p class="text-label">over the last {N} days, {M} events</p>
```

## Component Specs — History + Preview merge (D-18 through D-22)

### §8.0 `/preview` retirement

`/preview` (the HTML page route) becomes a fixed, hardcoded 302 redirect to `/history` — **never** a caller-supplied `next` value (that's `_validated_next_route()`'s unrelated mechanism; do not conflate the two). `/preview.png` and `/gallery/{name}.png` (byte-serving routes) are unchanged — still needed as `<img src>` targets from History now (D-22). `preview_page.py` is deleted outright once its content is absorbed (matches this project's own "delete what's unused" convention).

### §8.1 "Now showing" section (D-18)

At the very top of History's body, before the filter bar / flight table, reuse `preview_section()`'s existing markup **byte-identical** (`.preview-frame`-bounded, centered matte `<img>`, "Captured {relative}" caption via `concise_timestamp_html()`, the not-colour-accurate caveat) — wrapped in a `<section class="page-section">` with `<h2 class="text-heading">Now showing</h2>` (renamed from "Live preview").

**Explicitly out of scope for this section:** Preview's separate page-level `freshness_html`/stale-view-banner apparatus (the `/preview`-specific Refresh link + `data-stale-banner` pair) is **not** ported to History. D-18 says only the `preview_section()` content moves — its own "Captured {relative}" caption is already a sufficient staleness signal for this one section, and duplicating Health's whole-page freshness mechanism here would be new scope no decision asks for.

### §8.2 Recent renders disclosure (D-19)

Directly under "Now showing" (same `.page-section`, or an immediately-following sibling section — either is fine visually), a collapsed-by-default disclosure:

```html
<details class="readings-disclosure">
  <summary>Recent renders ({N shown})</summary>
  <!-- gallery_tiles() markup, unchanged: .gallery-grid / .gallery-tile,
       GALLERY_DISPLAY_LIMIT=12, existing empty-state copy unchanged -->
</details>
```

`{N shown}` is the actual count rendered (`min(len(gallery_entries), GALLERY_DISPLAY_LIMIT)`), matching the existing "View {N} readings" convention (count of what's shown, not the ceiling constant).

### §8.3 Per-row "View panel near this time" lookup (D-20, NEW component: lightbox)

**Trigger button** — one per History row, in the desktop table's Timestamp cell and the mobile card's primary line. Reuses `.copy-btn`'s exact 28×28-visual/44×44-hit-area shape:

```html
<button type="button" class="copy-btn" data-view-panel-src="/gallery/{matched-filename}.png"
        data-view-panel-caption="{matched full ISO timestamp}"
        aria-label="View panel near this time">
  {icon_html("icon-nav-preview")}
</button>
```

The matched filename/timestamp is computed **server-side**, at render time, per row — a linear scan over `ctx["gallery_entries"]` (already sorted name-descending = chronological-descending) for the nearest entry at-or-before that row's own timestamp, converted via `preview_page._gallery_name_to_iso()`'s existing regex helper (now relocated into `history_page.py`). **Not** a client-side lookup, not a new DB query/index (D-20 is explicit on this). If `ctx["gallery_entries"]` is empty, the button is omitted entirely for every row (never rendered disabled/broken).

**Shared lightbox** — one `<dialog>` per page (not one per row), opened/closed by a new small JS file (`companion/static/panel-lookup.js`, ES5-safe IIFE, matching every existing static JS file's convention):

```html
<dialog class="lightbox" id="panel-lookup-dialog">
  <img class="lightbox__image" src="" alt="">
  <p class="lightbox__caption text-label mono"></p>
  <p class="lightbox__note text-body"></p>
  <button type="button" data-view-panel-close>Close</button>
</dialog>
```

On trigger click: JS reads `data-view-panel-src`/`data-view-panel-caption` off the clicked button, sets the dialog's `<img src>`/caption text, calls `.showModal()`. The Close button (a plain, unstyled `<button>` — already gets the app's quiet-button treatment for free, no icon needed) calls `.close()`. Using the native `<dialog>` element (not a hand-rolled overlay `<div>`) is deliberate: it gives Escape-to-close, a native `::backdrop`, and focus-trap semantics for free, matching this codebase's stated preference for native browser primitives (`<details>`) over custom JS state wherever one exists — this satisfies D-25's keyboard-operability requirement structurally rather than through new focus-management code.

**Copy:**

| Element | Copy |
|---|---|
| Trigger `aria-label` | "View panel near this time" (verbatim, D-20) |
| Lightbox caption | "Panel near {full ISO timestamp}" |
| Lightbox note | "This is the nearest recorded render, not necessarily from this exact flight — the panel updates on its own wake/poll cycle." |
| Close button | "Close" |

**Dialog visual treatment (deliberate exception):** unlike every other card in this file, the lightbox `<dialog>` renders with `box-shadow: var(--shadow-card-hover)` **at rest** (not hairline-at-rest) — it is a floating modal overlay, not a page-flow card, so the "resting" state should already read as elevated. `background: var(--color-dominant); border: 1px solid var(--color-border); border-radius: var(--radius-card); padding: var(--space-lg); max-width: 480px;` (mobile: `width: calc(100% - var(--space-lg) * 2)`). `::backdrop { background: rgba(0, 0, 0, 0.5); }` — no token exists for a scrim; this raw value is consistent with the file's existing use of raw rgba() for shadow values.

## Interaction / Accessibility Notes

These are pointers for the closing-checkpoint plan (D-23/D-24/D-25), not a substitute for `06.6.4.1-VALIDATION.md`'s own manual-verification table:
