# Phase 06.6.4.1 — UI Design Contract

> Visual and interaction contract for the companion app's page-by-page IA consolidation. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**How to read this document.** Every visual/interaction decision in this phase was already validated interactively by the developer as real HTML artifacts before this phase existed (see `06.6.4.1-CONTEXT.md`'s `<decisions>`/`<specifics>` sections — D-01 through D-26, all LOCKED). This UI-SPEC does not re-derive that direction. It translates those locked decisions into a formal, component-level contract grounded in the REAL, already-shipped tokens and markup in `companion/static/style.css` and `companion/layout.py` (both read in full this session), plus the REAL current markup in `companion/pages/config_page.py`, `health_page.py`, `airlines_page.py`, `history_page.py`, `preview_page.py` (all read in full this session). Every new component below reuses this codebase's existing visual vocabulary (hairline-at-rest/shadow-on-hover cards, quiet uppercase table headers, tinted-pill active states, native `<details>`/`<dialog>` over custom JS state) — **no new design tokens are introduced anywhere in this document.**

| Token | Value | Usage |

| sm | 8px | Compact element spacing, card internal padding (stat-tile, page-section) |
| md | 16px | Default element spacing, table cell padding. SUPERSEDED as the sole card-padding value at `>=960px` — see the Exceptions paragraph below (06.6.4.1.1-03 D-15). |
| lg | 24px | Section padding, card margin-bottom. Also now the single sibling-card gap everywhere, grid or stacked (06.6.4.1.1-03 D-14/UIR-25), and the `>=960px` card-padding value (D-15/UIR-25) — see Exceptions below. |
| xl | 32px | Layout gaps. SUPERSEDED as `.dashboard-grid`'s own sibling-card gap — 06.6.4.1.1-03 (D-14, UIR-25) collapsed the 32px-in-grid gap onto the same `--space-lg` (24px) stacked-card value every other sibling-card relationship in the file already used (`companion/static/style.css:3227-3238`), so no card-adjacency gap in the app is 32px any more. |
| 2xl | 48px | Major section breaks, `.dashboard-main` vertical padding |
| 3xl | 64px | Page-level horizontal gutter (desktop) |

**Exceptions (all pre-existing, none new this phase):** control-height exceptions to the 8px rhythm are already established and this phase's new controls reuse them rather than adding new heights — buttons 30px, icon buttons 28px visual box (44×44 synthesized hit area via `::before`), nav links/filter inputs 32px, theme-picker segments 28px, chips/pills in this phase use the same reasoning at **20px height** (a new but consistent addition, justified below in Component Specs §5.2/§6.1 — treated as a control-height exception, not a spacing-token exception).

**Post-approval spacing pass, 06.6.4.1.1-03 (a real spacing pass, not new control-height exceptions):**
- **One sibling-card gap (D-14/UIR-25).** Every sibling-card gap in the app, grid or stacked, is now `--space-lg` (24px) — the `.dashboard-grid` 32px-in-grid gap named in the `xl` row above is SUPERSEDED (`style.css:3227-3238`).
- **Roomier card padding (D-15/UIR-25).** `.page-section`, `.theme-status` and `.battery-trend-section` now carry `--space-lg` (24px) padding at `>=960px`, dropping to `--space-md` (16px) below it (`style.css:4123-4164`) — this phase's `md` row above ("card internal padding") is SUPERSEDED as the sole value at desktop width. `.battery-trend-section` receiving this treatment is a stated extension one card beyond D-15's own literal wording, confirmed correct at 06.6.4.1.1's closing checkpoint.
- **One-line card text capped (D-16/UIR-25/UIR-14, NEW).** `.stat-tile__caption`/`.stat-tile__value` get `max-width: 60ch` at `>=960px` (`style.css:4166-4176`) — Health's single-tile "Device last checked in" row no longer stretches its text across the full ~1040px grid column. Text-measure only; the page grid is untouched.
- **`.section-intro` mobile-first column (D-19/UIR-24, NEW).** Base rule is now `flex-direction: column; gap: 2px` so a heading+muted-caption pair never wraps into a hanging "— …" orphan line on a phone; a `>=960px` override restores the original inline baseline row (`style.css:378-384`, `:4178-4189`).
- **Buttons grow to 36px/14px below 960px (D-18/UIR-26, NEW — extends, does not reopen, this phase's own 30px desktop decision).** A bare `button` selector at the same (0,0,1) specificity as the base rule, placed last in source order so it wins on position, not specificity (`style.css:4506-4534`). 30px/13px is unchanged and still correct at `>=960px`.

This is a literal 24px value, not a resurrected `--font-display-size` token (that token was retired in Phase 06.6.4 D-09, see below, and stays retired) — the wordmark is not a content-scale citizen and is not counted against the "exactly 4 sizes"/"exactly 5 roles" rules above. `.sidebar-title` needs no rule of its own; it is always co-classed with `.site-title`.

There is no "Display" role — it was retired in Phase 06.6.4 (D-09), and its two consumers (`.stat-tile__value`, `.runway-card__number`) moved to the Emphasis role above. **Do not reintroduce a fifth size.** Every new text element this phase adds (section descriptions, banner pills, chip labels, lightbox caption, resolution-rate headline) must resolve to one of the five rows above — see Component Specs for the exact mapping per element.

Exactly 2 weights exist site-wide: 400 (regular) and 600 (semibold) — **still true.** What is SUPERSEDED is the weight column above for the Heading/Page-title rows (Page-title gained its own 600/tracking treatment) and the addition of the `.site-title` role, which the five-role table above did not, and could not, cover — both landed in 06.6.4.1.1 (D-10, D-11), not in this phase.

|---|---|

```html
        aria-label="View panel near this time">
  {icon_html("icon-nav-preview")}
</button>
```

The matched filename/timestamp is computed **server-side**, at render time, per row — a linear scan over `ctx["gallery_entries"]` (already sorted name-descending = chronological-descending) for the nearest entry at-or-before that row's own timestamp, converted via `preview_page._gallery_name_to_iso()`'s existing regex helper (now relocated into `history_page.py`). **Not** a client-side lookup, not a new DB query/index (D-20 is explicit on this). If `ctx["gallery_entries"]` is empty, the button is omitted entirely for every row (never rendered disabled/broken).

**Shared lightbox** — one `<dialog>` per page (not one per row), opened/closed by a new small JS file (`companion/static/panel-lookup.js`, ES5-safe IIFE, matching every existing static JS file's convention):

```html
<dialog class="lightbox" id="panel-lookup-dialog">
  <img class="lightbox__image" src="" alt="">
  <p class="lightbox__caption text-label mono"></p>
  <p class="lightbox__note text-body"></p>
  <button type="button" data-view-panel-close>Close</button>
</dialog>
```

On trigger click: JS reads `data-view-panel-src`/`data-view-panel-caption` off the clicked button, sets the dialog's `<img src>`/caption text, calls `.showModal()`. The Close button (a plain, unstyled `<button>` — already gets the app's quiet-button treatment for free, no icon needed) calls `.close()`. Using the native `<dialog>` element (not a hand-rolled overlay `<div>`) is deliberate: it gives Escape-to-close, a native `::backdrop`, and focus-trap semantics for free, matching this codebase's stated preference for native browser primitives (`<details>`) over custom JS state wherever one exists — this satisfies D-25's keyboard-operability requirement structurally rather than through new focus-management code.
