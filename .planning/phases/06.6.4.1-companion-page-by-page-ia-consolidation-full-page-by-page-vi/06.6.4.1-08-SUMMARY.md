# Phase 06.6.4.1 Plan 08: Retire the Preview page — redirect, nav shrink, module deletion Summary

**Retired the standalone Preview HTML page (`/preview` now a fixed, un-steerable 303 to `/history`), shrunk site navigation from five tabs to four, and deleted `companion/pages/preview_page.py` outright now that every symbol it held lives in `history_page.py` — while leaving `/preview.png` and `/gallery/{name}.png` (History's own image dependencies) byte-identical (D-22).**

## Performance

- **Duration:** ~35 min
- **Tasks:** 3/3 completed
- **Files modified:** 5 modified, 1 deleted (`companion/app.py`, `companion/layout.py`, `companion/pages/__init__.py`, `companion/test_companion_app.py`, `companion/test_view_pages.py`; `companion/pages/preview_page.py` deleted)

## Accomplishments

- `companion/app.py`'s `do_GET` no longer renders a Preview page: `PREVIEW_PAGE_ROUTE` ("/preview") now branches straight to `self.require_session()` then `self.redirect("/history")` — a hardcoded literal, never a query parameter, form value, Referer header, or `_validated_next_route()`'s allowlisted login-next mechanism (documented inline as a deliberately different, non-reachable mechanism). The `preview_page` import is gone; the preview-image, gallery-prefix, runway-image, and illustration byte-serving blocks are untouched.
- `companion/layout.py::NAV_TABS` shrunk from five entries to four (settings/health/airlines/history); `NAV_ICON_IDS`' "preview" key is gone. `icon-nav-preview` (the eye glyph) stays in the `ICON_IDS` whitelist — its sole remaining consumer is `history_page.py`'s View-panel trigger button — with a comment at both the whitelist entry and the removed map key explaining why, so neither reads as an oversight later.
- `companion/pages/preview_page.py` deleted outright after a repo-wide `preview_page` import grep confirmed the only remaining references were the ones this plan removes. `companion/pages/__init__.py`'s gallery_entries context-key passage (and its module docstring's stale "five-tab" reference) now name `history_page` as the consumer, with the key's own rationale unchanged.
- `companion/test_companion_app.py` (105/105) and `companion/test_view_pages.py` (43/43) both retargeted: the redirect's fixed-target/query-string-immunity/session-gate behavior, the nav-count/tab-set assertions (including a new `len(NAV_TABS) == 4` check and an exactly-four-links-one-active-each check for both nav renderers), the eye-glyph survival, and (in test_view_pages.py) `preview_page.py`'s Preview-specific test section deleted with two robustness checks (`_gallery_name_to_iso()` degrade-safely fixtures, the malformed-filename caption fallback) and a new View-panel-icon check carried onto the History side.

## Decisions Made

- **Moved two nav-count-loop fixes from Task 2 into Task 1.** The plan's Task 2 action text describes retargeting "the tab-iteration tuple's preview pair" and implies the unauthenticated-redirect loop's `/preview` entry survives until Task 2. In practice, both break the instant Task 1's redirect lands (GET /preview stops returning 200/"Preview", and its unauthenticated redirect stops carrying a real page's `?next=` the moment NAV_TABS shrinks — but even before that, the authenticated 200/heading assertion breaks immediately). Fixed both in Task 1's own commit so `server/.venv/bin/python3 companion/test_companion_app.py` stays green after every individual task commit, mirroring plan 07's own documented precedent for the same situation.
- **Split Task 2's View-panel-icon acceptance criterion across two files/tasks.** "The eye glyph id is still a member of the icon whitelist and `layout.icon_html()` returns non-empty markup for it" (layout-level, no fixture needed) landed in Task 2's `test_companion_app.py` as planned. "A rendered History page still contains at least one View-panel trigger carrying a non-empty icon (for a fixture with gallery entries)" needs a full `history_page.render()` call with a matched gallery entry — that fixture machinery lives in `test_view_pages.py`, not `test_companion_app.py`'s HTTP-subprocess harness — so it landed in Task 3 instead, which already touches that file.
- **Corrected a stale "five-tab" reference in `companion/pages/__init__.py`'s module docstring**, beyond the plan's explicitly named gallery_entries passage, since it's in a file this task was already editing and the plan's own D-22 change makes the claim inaccurate the moment it lands (Rule 1 — cheap, in-scope doc-correctness fix).
