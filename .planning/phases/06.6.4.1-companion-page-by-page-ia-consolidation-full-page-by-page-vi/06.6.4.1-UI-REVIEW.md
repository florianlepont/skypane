## Executive assessment

The companion is in far better shape than the 2026-08-30 audit found: the shell (sidebar, hamburger dropdown with 44 px links, footer grouping, skip link, `aria-current`, focus rings, native `<dialog>` lightbox, filter bars, dirty-state save bar) is consistent and works on a real 375 px viewport with no page-level overflow on Settings, Airlines and History. Both themes are complete — no token is missing from any of the four blocks, and the light/dark override wins over the OS setting.

What still makes the site look unfinished is concentrated in five places, all of them visible on first open:

1. **Settings › Theme** — the first thing on the first page after login is a column of sixteen 44 px-wide radio circles with the label tucked under each one, inside a square `<fieldset>` that matches none of the three cards below it. This is the multi-theme branch of `theme_fieldset()` running for the first time since Phase 8 widened the registry; it was never styled.
2. **History table** — at a 1440 px laptop only Timestamp/Callsign/Type/Route fit; State, Corroboration and Runway are behind an unsignposted inner scroll, largely because unresolved rows say "Route unavailable" twice and glue a link onto it.
3. **Health on a phone** — the "2 errors" banner spills past the right edge of the screen (the page grows to 421 px on a 375 px viewport), and the migrated tables either get cut off (Unresolved prefixes) or wrap one word per line (Resolution statistics).
4. **Airlines cards** — every card reserves a 263 px-tall image box for a 900×263 illustration, so the plane floats in the middle third of a mostly empty card; 27 such cards make the mobile page 9,700 px long and ~4 MB.
5. **History › Now showing** — the 600 px nearest-neighbour preview is upscaled to ~956 px, so the dithered panel reads as static; the same render opened in the lightbox (full-size gallery PNG) looks clean.

Four of the five are small CSS/markup fixes (one selector each for the banner and the airline image); the theme picker is the one that needs a real design pass (it is also the place SEED-002's per-theme scoping will land, so it is worth doing once, properly).

Shareable report with annotated screenshots (French, same findings, same IDs): https://claude.ai/code/artifact/ea107413-5994-4662-80cb-35ccabd6dc79 — this file stays the source of truth.

## Top 3 Priority Fixes

1. **Theme picker (UIR-01 + UIR-02)** — the very first control an operator sees is visibly broken and gives no colour preview for a *colour* setting — Opt the theme radios out of the global 44 px `input, select` rule exactly like `.led-checkbox` already does, lay the 16 options out as a wrapping row of compact selectable chips/cards that show the departing/arriving swatches (`_palette_hex()` + `.theme-swatch__chip` already exist on the read-only branch), and wrap the group in the same `.theme-status` card + `<h2>` idiom Runway and Diagnostic LED use.
2. **History table content (UIR-04, UIR-05, UIR-06)** — 3 of 7 columns invisible at 1440 px, duplicated "Route unavailable", glued link, dead copy buttons on hex-only rows — Use an airline-specific fallback ("Airline unknown"), separate the link (or turn it into a small "?" affordance), shorten "Single-source (uncorroborated)" to "Single-source", promote the hex to the primary slot when the callsign is empty and skip its copy button, and add a scroll-edge shadow (`mask-image`/`background-attachment` trick) on `.data-table-wrap` so an overflowing table announces itself.
3. **Mobile Health (UIR-03, UIR-10, UIR-11)** — a phone user sees a banner hanging off-screen and two unreadable tables on the page whose whole job is "is everything fine?" — `flex-wrap: wrap` on `.banner` (+ `white-space: nowrap` on the "N errors:" label), and below 960 px render the two migrated tables as stacked rows (the `history-card` pattern) or move First/Last seen and Description behind a disclosure.

One-line CSS wins to ship alongside: `height: auto` on `.airline-card__image` (UIR-07), a space before the em dash in `_battery_trend_section_html()` (UIR-12), `white-space: nowrap` on the Source column (UIR-13).

## Detailed Findings

### Pillar 1: Copywriting (2/4)

**UIR-05 — "Route unavailable" doubles up and stands in for the airline.** `format_event_row()` ([history_page.py:498-507](companion/pages/history_page.py:498)) uses `panel_render.ROUTE_FALLBACK_TEXT` ("Route unavailable") as the fallback for a missing **airline**, and again for a missing route. On every unresolved row the desktop table therefore reads `B77L · Route unavailable View unresolved prefixes | Route unavailable` — the same phrase twice in adjacent cells, the first one describing the wrong noun. `_type_airline_cell()` ([history_page.py:623-637](companion/pages/history_page.py:623)) then appends the `<a>` directly after the secondary span with no space or margin, so it renders as "Route unavailableView unresolved prefixes" (screenshot `history-table-left`). The mobile card repeats the pair ("Route unavailable  Departing"). Fix: an airline-specific fallback ("Airline unknown" or a muted "—"), `margin-left: var(--space-xs)` on the link (or an icon-only "?" with the existing `.copy-btn` shape), and keep the Route column as the only place that says "Route unavailable".

**UIR-15 — Button casing.** Title Case: "Sign In" (login), "Trigger Poll Now", "Save Settings" (no-JS fallback, [config_page.py:655](companion/pages/config_page.py:655)). Sentence case: "Save settings" (dirty bar), "Sign out", "Clear", "Close", "More details", "View 20 readings". The 06.6.4.1 spec names "Save settings" as the primary CTA, so sentence case is the intended register; the three Title Case labels predate it. Fix: "Sign in", "Trigger poll now", "Save settings".

**UIR-12 — Glued em dash.** `_battery_trend_section_html()` ([health_page.py:1571-1580](companion/pages/health_page.py:1571)) emits `<h2>Battery trend<span class="text-label section-caption">— Last 3 months, daily average</span></h2>` with no whitespace between the heading text and the span; the two other section intros ("Screen — the physical frame…") get their space from the `.section-intro` flex `gap`. Fix: leading space in the span, or `margin-left: var(--space-xs)` on `h2 > .section-caption`.

Good: every empty/error state in the spec's Copywriting Contract is present verbatim (login error `role="alert"`, "Saved — will apply on the frame's next scheduled refresh." `role="status"`, "No matching flights", "No matching airlines", "Health history is temporarily unavailable…"); the anomaly banner's visually-hidden summary reads naturally.

### Pillar 2: Visuals (2/4)

**UIR-01 — Theme picker (BLOCKER).** Screenshot `settings-radios-desktop` / `settings-radios-mobile`. The multi-theme branch of `theme_fieldset()` ([config_page.py:224-246](companion/pages/config_page.py:224)) emits `<label><input type="radio" name="theme"> Label</label>` × 16. Three global rules then shape it: `input, select { min-height: 44px; min-width: 44px; padding: …; background: …; border: …; border-radius: … }` ([style.css:1208-1222](companion/static/style.css:1208)) turns each native radio into a 44×44 circle with a visible ring (`accent-color` makes the checked one a large filled disc); `label { display: block; margin-bottom: 8px }` ([style.css:1195-1199](companion/static/style.css:1195)) puts every option on its own 53 px row; and because the text follows the 44 px inline-block, the label sits at the bottom-right of the circle instead of beside its centre. Measured: radios 44×44, rows 53 px, 16 rows ≈ 850 px of the first screen. The read-only single-theme branch showed two colour chips per theme (`_palette_hex()`, `.theme-swatch__chip`); the 16-option branch shows names only, so "Yellow Light" vs "Band Blue Light" gives the operator nothing to look at. This is the same class of defect quick task 260901-qif fixed for the LED checkbox (`.led-checkbox`), not yet applied to radios. Fix (design + code): a wrapping row of compact selectable chips — swatch pair + name, ~160 px wide, `.runway-card`-style selected border — with the radio visually hidden inside the label as the Runway cards already do; or at minimum a `.theme-option-radio` normalisation (`width/height: 16px; min-*: 0; padding: 0; margin: 0 8px 0 0`) and `display: flex; align-items: center` on the label.

**UIR-02 — Two container idioms on one page.** The Theme group is a `<fieldset><legend>` (radius 0, transparent background, legend cutting through the border — [style.css:1175-1193](companion/static/style.css:1175)); Runway, Diagnostic LED and Poll are `.theme-status` / `.page-section` cards (white surface, 8 px radius, hairline). Measured: fieldset `border-radius: 0px`, `background: transparent`; `.theme-status` `8px`, `#FFFFFF`. The spec (§5.1) asks for the `.theme-status` wrapper on every group. Fix: emit the multi-theme branch inside `<div class="theme-status" data-dirty-section="Theme"><h2 class="text-heading">Theme</h2>…` like the other branch and Runway.

**UIR-07 — Letterboxed illustrations.** Screenshot `airlines-cards-desktop` / `airlines-card-mobile`. `.airline-card__image { width: 100%; aspect-ratio: 900 / 263; object-fit: contain }` ([style.css:2911-2918](companion/static/style.css:2911)) never gets to apply its ratio: the `<img width="900" height="263">` attributes ([airlines_page.py:121-129](companion/pages/airlines_page.py:121)) map to presentational `width/height`, and `aspect-ratio` only applies when one dimension is `auto`. Measured: rendered 224×263 at desktop, 325×263 on mobile — a 3.4:1 image in a 0.85:1 box — so every card is 317 px tall with the aircraft in the middle third and ~170 px of empty surface. Fix: `height: auto;` in that rule (keep the attributes — the browser still reserves the box via `aspect-ratio`, which is what `loading="lazy"` needs).

**UIR-09 — Preview reads as noise.** Screenshot `history-preview-dark`. `/preview.png` is produced at `PREVIEW_THUMB_WIDTH = 600` with nearest-neighbour scaling (a deliberate mobile-payload choice from 06-09); History's `.preview-frame` is 1,006 px wide, so `.preview-image { max-width: 100% }` stretches the 600×800 thumbnail to 956×1275 — the Floyd–Steinberg dither turns into visible static, while the same render in the lightbox (full-size `/gallery/…png`) is crisp. Fix: serve the preview at the panel's native 1200 px (or point the img at the newest gallery file with the 600 px version as `srcset` for phones), and cap the frame (`max-height: 60vh; object-fit: contain`) so "Now showing" stops being 1,325 px tall on a page named History.

**UIR-16 — 404 page.** `_not_found_page()` ([app.py:562-569](companion/app.py:562)) renders a 20 px `.text-heading` "Page not found." and a link — every other page opens with the 30 px serif `page_header()`; the shell also drops the Health nav dot because `health_alert` is not passed. Fix: `layout.page_header("Page not found", purpose="…")` and thread `health_severity` through (or accept the omission and document it).

Good: the runway cards, the segmented theme control, the dirty-state bar (fixed, `width: fit-content`, "Theme changed · Save settings · Cancel"), the mobile dropdown (281 px panel, 44 px/16 px links, footer with theme + Sign out) and the lightbox all match the sketch-validated direction and look finished.

### Pillar 3: Color (4/4)

- The four token blocks (`:root`, `@media (prefers-color-scheme: dark)`, `html[data-ui-theme="light"]`, `html[data-ui-theme="dark"]`) declare the same 13 tokens each — nothing is defined in only one theme, and the CFG-09 override was verified to beat a dark OS (sidebar inactive links compute to `rgb(23,25,31)` in light, `rgb(241,243,246)` in dark).
- Contrast (computed from the shipped hex values): 70 %-mixed muted text 6.2:1 on the light canvas / 6.5:1 on cards, 8.7:1 / 8.3:1 in dark; accent `#B13F16` 5.3:1 on canvas, 4.8:1 on the sidebar surface; white-on-accent 5.9:1; dark accent 8.3:1. Status ok/warn (`#16A34A`/`#D97706`) sit at 3.2–3.3:1 on white, which is fine for the dots/top borders they are used on (non-text, ≥ 3:1) and every dot carries a text label.
- Accent stays on the reserved list (primary buttons, links, active pill, focus ring, runway selection, summary markers, the neutral banner edge, favicon); the new pills/chips/lightbox use neutral mixes as the spec rules.
- One observation, not a defect: in dark mode the Health "Device last checked in" tile's rose top border and the sidebar's rose dot are the only saturated elements above the fold, which reads correctly as "attention".

### Pillar 4: Typography (3/4)

- Sizes in use match the five roles (14/16/20/30 + 16-semibold Emphasis) plus the documented sub-scale (13 px buttons/segments, 12 px `.cell-secondary`/filter count, 11 px `th`/pills/chips, 10 px axis labels). No stray size was found in computed styles on any page.
- UIR-12 (glued dash, above) is the one typographic defect visible on every Health load.
- UIR-13: the desktop Resolution-statistics table gives Description 811 px and Source 118 px, so "Fresh lookup" and "Airline only" wrap onto two lines while every other cell is single-line — `white-space: nowrap` on the first column (or `th:first-child { width: 1% }`) fixes it. The mobile counterpart is UIR-10 (Spacing).
- Mono is used consistently for timestamps, callsigns, hex, mV; `tabular-nums` is not declared anywhere — the mobile readings table and the History timestamps would align better with `font-variant-numeric: tabular-nums` on `.mono`.

### Pillar 5: Spacing (2/4)

**UIR-03 — Anomaly banner overflow on phones (BLOCKER).** Screenshot `health-banner-mobile`. `.banner { display: flex; align-items: center; gap: 8px }` ([style.css:978-988](companion/static/style.css:978)) has no `flex-wrap`, and `.banner__pill { flex: none }` ([style.css:1057-1069](companion/static/style.css:1057)) refuses to shrink, so at 375 px the "2 errors:" label wraps to two lines and the second pill ends at x = 421 — past the banner (351) and past the viewport. `document.documentElement.scrollWidth` is 421 on a 375 px viewport: the whole page gains a horizontal scroll and mobile Safari/Chrome zoom out to fit. Fix: `flex-wrap: wrap` on `.banner`, `white-space: nowrap` on the leading label span, `min-width: 0` on pills (they can wrap onto a second row).

**UIR-10 — Resolution statistics on mobile.** Screenshot `health-tables-mobile`. `.data-table--prose { min-width: 0 }` ([style.css:1688-1690](companion/static/style.css:1688)) releases the table, but with `table-layout: auto` the three columns come out 88 / 129 / 76 px — Description gets a third of the width and wraps one or two words per line ("A / live / adsdb / lookup / …"); the first row measures 171 px tall and the four-row table ~600 px. Fix: below 960 px, render Source as a heading and Description beneath it (a `<dl>`, like `history-card__details`), or `th:first-child, td:first-child { white-space: nowrap }` + `td.desc { min-width: 55% }`.

**UIR-11 — Unresolved prefixes on mobile.** Same screenshot: the 5-column table is clipped mid-cell ("06:10 UTC (5d") with Last seen and Example callsign off-screen; `.data-table-wrap { overflow-x: auto }` makes it scrollable but nothing signals it. Fix: the History `.history-cards` pattern for this table on phones (Prefix · count as the primary line, the rest in the card), plus a scroll-edge shadow on every `.data-table-wrap`.

**UIR-04 — History at 1440 px.** Screenshot `history-table-left` / `history-table-right`. `.data-table { min-width: max-content }` ([style.css:1654-1657](companion/static/style.css:1654)) is correct for short values, but History's Type column is 434 px (the doubled "Route unavailable" + link, UIR-05) and Corroboration 253 px ("Single-source (uncorroborated)"), so the table is 1,472 px in a 1,040 px column: State, Corroboration and Runway only appear after scrolling inside the wrap, and the wrap has no shadow/mask hint (`box-shadow: none`, `mask-image: none`). Fix: the content changes in UIR-05/06, "Single-source" as the visible label (keep the long form in a `title`), and a scroll-edge shadow; then verify the unscrolled fit at 1280 px, which `06.6.1-UI-SPEC.md` explicitly deferred.

**UIR-14 — Empty tile.** The three "Server & data" tiles stretch to 238 px (`align-items: stretch`), so the one-line "ADS-B pipeline last ran" tile is mostly empty; cosmetic, but it is the first thing under the section heading. Consider `align-items: start`, or give the pipeline tile a second line (last detection time, already in `meta.last_detection`).

Good: the 8 px scale holds everywhere measured (card padding 16, grid gap 32, section gap 48/64 at ≥ 960); the mobile pages Settings/Airlines/History have zero elements wider than the viewport.

### Pillar 6: Experience Design (3/4)

**UIR-06 — Hex-only rows.** Screenshot `history-rows-dark` / `history-cards-mobile`. `_callsign_hex_cell()` ([history_page.py:594-611](companion/pages/history_page.py:594)) always emits the callsign copy button and, when a hex exists, the separator — so a row whose callsign is empty (4 of the 50 rows in the production snapshot) renders `[copy ""] · 34560d [copy]`: a leading dot that reads as truncated data (the exact case `_merged_cell()`'s own docstring guards against for the *secondary* value), a "Copy callsign" button that copies an empty string, and on mobile a card whose primary line is blank. Fix: promote the hex to the primary slot with a muted "no callsign" secondary, and emit the copy button only for a non-empty value.

**UIR-17 — Row clutter.** Every desktop row carries three icon-only buttons (eye, copy, copy); across 50 rows that is 150 identical glyphs competing with the data. They are accessible (labels, 44 px hit areas) — the question is density: showing the copy buttons on row hover/focus-within (desktop only; mobile keeps them in the disclosure) would keep the affordance and remove the noise.

**UIR-18 — Auto-refresh feedback.** `freshness.js` reveals the "Updating…" pill 80 ms before `location.reload()`; in practice it never paints. The reload approach is documented and the interaction guards work (open disclosures, focused inputs, chart focus), but the operator has no persistent cue that the page is live. A small "Live · refreshed 12 s ago" text next to the title (server-rendered `data-loaded-at` is already there) would communicate the behaviour without new mechanics.

**UIR-19 — Flash in the URL.** `POST /settings` redirects to `/settings?flash=saved`; a reload or a bookmark re-shows "Saved —". `history.replaceState(null, "", location.pathname)` after the banner renders (or a one-shot cookie) keeps the PRG pattern without the replay.

**UIR-08 — Airlines page weight.** 27 normalized 900×263 PNGs at ~140–170 KB each (744 KB for the first five requests alone); cards never render wider than 325 px. `loading="lazy"` limits the initial cost, but scrolling the whole gallery on a phone still pulls ~4 MB. Fix: normalise to 450 px (halves the pixels, roughly quarters the bytes) or emit a `srcset`, and keep the mtime-keyed cache.

Good: login error and lockout copy announce via `role="alert"`; cooldown countdown and "Polling…" pending state exist; the dirty bar names the changed sections; `<dialog>` gives Escape/backdrop/focus trap; filter empty states and live counts work (verified "0 of 50 shown" + empty block); keyboard focus lands on visible 2 px accent outlines; the hamburger toggles `aria-expanded` and Escape returns focus.

## What is *not* a defect (checked and cleared)

- Sidebar/segment/sign-out colours in light mode are correct (an earlier in-app-browser probe read dark-mode values because the hidden pane freezes CSS transitions — re-verified with Playwright).
- Battery readout vs Device tile relative ages agree ("22h ago" both).
- Airlines images load in ~3 ms each once the per-process normalisation cache is warm (26 ms cold per file); the blank cards seen in a hidden background tab were tab throttling, not a server stall.
- No console errors on any page; no page-level horizontal overflow on Settings/Airlines/History at 375 px.
