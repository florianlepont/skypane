# Phase 06.6.4.1 Plan 05: History absorbs Preview's live panel + gallery, gains per-row lookup and unresolved-airline link Summary

**Moved Preview's entire live-panel/gallery content into History as a Now-showing section plus a collapsed Recent-renders disclosure, added a server-side nearest-render lookup with per-row "View panel near this time" triggers and a shared native `<dialog>` lightbox, and gave unresolved-airline rows a link to Health's Server & data anchor instead of a duplicated prefix registry.**

## Performance

- **Duration:** ~55 min
- **Tasks:** 3/3 completed
- **Files modified:** 2 (`companion/pages/history_page.py`, `companion/test_view_pages.py`)

## Accomplishments

- Copied `COLOUR_CAVEAT`, the no-panel/no-renders constants, `GALLERY_DISPLAY_LIMIT`, the preview/gallery route literals, panel pixel dimensions, the gallery filename-time regex, `_gallery_name_to_iso()`, `preview_section()`, and `gallery_tiles()` from `preview_page.py` into `history_page.py` byte-for-byte (D-18/D-19). `render()` now prepends a `Now showing` `.page-section` (the live panel image or an honest no-panel sentence, plus the caveat, always) and a collapsed-by-default `Recent renders (N)` `<details>` disclosure whose count reflects the real number of tiles shown. Preview's page-level freshness apparatus (`data-loaded-at` Refresh link + hidden `data-stale-banner`) was deliberately not ported.
- Added `nearest_gallery_entry(entries, row_ts)` (D-20): a linear scan over the already-in-memory `ctx["gallery_entries"]` list returning the `(filename, iso)` pair of the latest entry at or before `row_ts` — comparing timezone-aware `datetime` values, never raw strings, so a filename's local UTC offset can never mis-rank against a UTC-suffixed history timestamp. No database query, no new index, no stored relationship.
- Added `_view_panel_button_html()`/`_lightbox_html()` plus the D-20 copy/DOM-contract constants (`VIEW_PANEL_LABEL`, `LIGHTBOX_DIALOG_ID`, `LIGHTBOX_CAPTION_TEMPLATE`, `LIGHTBOX_NOTE`, the three `data-view-panel-*` attribute names) — duplicated against `companion/static/panel-lookup.js`'s own literals per this codebase's established must-equal discipline, pinned by a new three-file DOM-contract test guard. `render()` computes each row's match exactly once and shares the resulting trigger markup between the desktop Timestamp cell and the mobile primary line, so the two representations can never disagree; the single shared `<dialog>` is emitted only when at least one row actually carries a trigger.
- Added `UNRESOLVED_LINK_HREF`/`UNRESOLVED_LINK_TEXT` and the dedicated `_type_airline_cell()`/`_unresolved_link_html()` builders (D-21): a row whose `airline_label` equals `panel_render.ROUTE_FALLBACK_TEXT` gets an inline link to `/health#server-data` appended to both the desktop Type+Airline cell and the mobile Aircraft detail row — keyed on the airline label only, never the Route column (which still calls the shared, unmodified `_merged_cell()`). No prefix table or registry data duplicated onto History.

## Decisions Made

- **View-panel caption attribute carries the full "Panel near {iso}" string, not the bare ISO.** `companion/static/panel-lookup.js` copies `data-view-panel-caption`'s value verbatim into the lightbox caption (`caption.textContent = captionText`, zero client-side templating). The plan's Task 2 action-block parenthetical read ambiguously as either "the literal value is the escaped ISO" or "the value is derived from the escaped ISO." Resolved in favor of applying `LIGHTBOX_CAPTION_TEMPLATE` (the constant the plan explicitly instructs adding) so the shipped lightbox actually reads "Panel near {timestamp}" per UI-SPEC §8.3's approved copy table, and so the constant has a real call site rather than being defined-but-unused — consistent with every other `_TEMPLATE`-suffixed constant already in this module (`RECENT_RENDERS_SUMMARY_TEMPLATE`, `GALLERY_HEADING`, `_FILTER_EMPTY_BODY_TEMPLATE`) always being applied via `%`.
- Kept the Now-showing section and its Recent-renders disclosure inside one shared `.page-section` (the plan's own "same section or an immediately-following sibling — either is fine visually" option) rather than two sibling sections, since it needed no extra markup and matches the visual grouping "Now showing" implies.
- `_view_panel_button_html()`/`_type_airline_cell()` compute their match/link condition from data already threaded through `render()`'s single per-row pass (`row["view_panel_html"]`, the `airline_label == ROUTE_FALLBACK_TEXT` comparison) rather than re-querying or re-deriving inside `_history_table_html()`/`_history_cards_html()`, preserving the existing "one formatted-rows pass, both representations read it" architecture this module already used for `data-filter-text`/`data-filter-group`.
