# Phase 06.6.4.1 Plan 04: Health page restructure + Airlines diagnostics migration Summary

**Health now owns every server-and-data diagnostic signal in a two-section (Screen / Server & data) layout, with a pill-based anomaly banner, a collapsed Corroboration disclosure, an axis-labeled battery chart that shows a real reading by default, and the migrated Unresolved-prefixes/Resolution-statistics cards rendering in independently-failing full-width sections instead of a 240px-floored grid tile.**

## Performance

- **Duration:** ~45 min
- **Started:** 2026-09-01T13:00:00Z (approx)
- **Completed:** 2026-09-01T13:47:15Z
- **Tasks:** 3
- **Files modified:** 2 (`companion/pages/health_page.py`, `companion/test_status_pages.py`)

## Accomplishments

- Anomaly banner now emits one `banner__pill` per failing category (via new `_anomaly_category_labels()`/`_anomaly_banner_html()`) while keeping a visually-hidden accessible tail carrying the original sentence, so every pre-existing `ANOMALY_BANNER_TEXT` presence check keeps passing unmodified.
- Corroboration's three status rows dropped their inline explanation clauses; the three explanations now live in a `_corroboration_details_html()` disclosure (`<dl>` of `<dt>`/`<dd>` pairs), closed by default, reusing the existing `readings-disclosure` idiom verbatim.
- `battery_sparkline_svg()` grew its viewBox (reserved left gutter + bottom strip) to emit four `aria-hidden` axis-label text nodes (Y min/max mV, X oldest/newest clock time), and `_battery_readout_block()` now seeds its resting text with the latest reading's own label instead of a static prompt — retiring `BATTERY_READOUT_PLACEHOLDER`.
- Health's body restructured into two id-anchored sections: `#screen` (standalone Device-freshness tile + the battery-trend section) and `#server-data` (a three-tile grid — Pipeline, Corroboration, new Resolution-rate — followed by the two migrated full-width cards).
- `unresolved_rows()`, `coverage_status()`, `resolution_stats()`, and all their supporting builders (`_registry_row_html()`, `_registry_table_html()`, `_registry_section()`, `_registry_filter_bar_html()`, `_stats_table_html()`) migrated verbatim from `companion/pages/airlines_page.py`; a new `_resolution_rate_tile_html()` reuses the old promoted headline's figure. `airlines_page.py` itself is deliberately untouched — for exactly one wave both pages render this content (plan 06 removes it from Airlines next).
- The registry read (`poll_loop.load_poll_state()`) and the stats read (`_safe_query()`) stay independent calls in `render()`, never folded into `_read_health_inputs()`'s five-key dict — verified by a new isolation check with two inverse fixtures (corrupted db / malformed poll-state file).

## Decisions Made

- Kept `ANOMALY_BANNER_TEXT` as a `visually-hidden` accessible tail inside the new pill-based banner rather than removing it, preserving every existing substring/count check and giving screen readers one coherent sentence.
- Reused `health_page.py`'s own `HEALTH_UNAVAILABLE_TEXT`/`_unavailable_block()` for the migrated Resolution-rate tile's unavailable branch instead of duplicating Airlines' byte-identical `STATS_UNAVAILABLE_TEXT` constant a second time in the same module.
- Retired `_anomaly_banner_text()` and `BATTERY_READOUT_PLACEHOLDER` as dead code once their only call sites were replaced (neither was referenced anywhere else, including tests).
- Confirmed via direct read of `companion/static/battery-trend.js` that it has no blur/pointer-leave listener at all — the resting readout text simply persists after an interaction rather than reverting to "latest" automatically. D-09's "shows a real reading before any interaction" is satisfied by seeding alone; the JS file is out of this plan's `files_modified` scope and was not touched.
