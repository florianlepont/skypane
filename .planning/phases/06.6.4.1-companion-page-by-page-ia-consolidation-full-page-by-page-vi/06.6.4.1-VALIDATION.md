# Phase 06.6.4.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Custom stdlib `check(name, fn)` harness (not pytest/unittest) — each `companion/test_*.py` is directly executable and self-verifies against its own `EXPECTED_CHECK_COUNT` constant |
| **Config file** | none — `pyproject.toml`'s `[tool.coverage.*]` sections configure coverage measurement only (`fail_under = 83`), not test discovery |
| **Quick run command** | `server/.venv/bin/python3 companion/test_<touched_file>.py` (whichever single file was touched) |
| **Full suite command** | `scripts/run-all-tests.sh` |
| **Estimated runtime** | ~60 seconds (full suite, this project's own established precedent) |

---

## Sampling Rate

- **After every task commit:** Run the single touched harness directly.
- **After every plan wave:** Run `scripts/run-all-tests.sh`
- **Before `/gsd-verify-work`:** Full suite must be green (single accepted exception: `server/test_poll_loop.py`'s pre-existing, unrelated macOS-local Pillow/FreeType `panel.bin` digest mismatch — confirmed unrelated whenever zero `server/` files are touched, which is true for this entire phase; D-14/D-15's illustration route reads `server/plane/illustrations.py` and `server/assets/` but does not modify either).
- **Max feedback latency:** ~60s
