## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem→page (gallery listing) | Render filenames come from `companion/app.py`'s own directory-listing helper and are interpolated into image URLs and caption text. |
| database→page (runway events) | History rows are read from SQLite and rendered as cells and card lines. |
| server→browser DOM | Trigger attribute values are read by `panel-lookup.js` and assigned to DOM properties. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06.6.4.1-06 | Tampering (XSS) | `_view_panel_button_html()` and `_lightbox_html()` | medium | mitigate | Both the matched filename and the matched ISO timestamp are computed server-side from `ctx["gallery_entries"]` — a list `companion/app.py`'s own listing helper produced — and each is escaped exactly once at the point of interpolation into its attribute. The lightbox note is a static server-rendered constant, never written by the script. No client-supplied value ever reaches either. |
| T-06.6.4.1-16 | Tampering | trigger source attribute value | medium | mitigate | The URL is built by joining the existing gallery route prefix with a filename taken from the already-listed entry set — the page never joins a filesystem path and never accepts a filename from the request. | T-06.6.4.1-17 | Denial of Service | per-row nearest-render lookup | low | accept | A linear scan over an already-in-memory list capped by the router's own listing limit, run once per row for at most the page's row limit — bounded, allocation-free, and strictly cheaper than the database read the page already performs. No new query, no new index. |
| T-06.6.4.1-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install occurs in this plan; see `06.6.4.1-RESEARCH.md`'s Package Legitimacy Audit (not applicable). |
