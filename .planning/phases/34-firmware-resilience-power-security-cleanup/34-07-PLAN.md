Create `wake_guard.h/.c` (SkyPane-original SPDX). Header comment: two mechanisms with two purposes — the task watchdog (≤60 s, Kconfig maximum) detects a hang and panics so the next boot backs off; the wake budget (CONFIG_SKYPANE_WAKE_BUDGET_S) bounds a wake that is still making progress, and on expiry the main task records a failure and deep-sleeps through the normal exit. The timer callback never sleeps the chip itself: it only sets a flag, so the power-down order (radio, panel guard, LED) stays in one place.

API:
- `typedef void (*fp_wake_expired_fn)(void);` — must not return.
- `void fp_wake_guard_start(fp_wake_expired_fn on_expired);` — records `esp_timer_get_time()` as the start, creates and starts a one-shot esp_timer for CONFIG_SKYPANE_WAKE_BUDGET_S seconds whose callback sets a `volatile bool` (use `_Atomic bool` or `volatile` with a comment) and does nothing else, and subscribes the calling task with `esp_task_wdt_add(NULL)`. Timer or subscription failure is logged with ESP_LOGE and degrades (the checkpoint still compares elapsed time via fp_wake_deadline_expired, so the budget holds even without the timer).
- `void fp_wake_feed(void);` — calls `esp_task_wdt_reset()` only when fp_wake_guard_start subscribed the task (track it in a static bool: ESP-IDF logs an error for every reset from an unsubscribed task, and the panel driver calls this before the guard exists in unit bring-up or early boot). Safe to call from the panel driver during a blit: it never ends the wake.
- `void fp_wake_checkpoint(void);` — feeds, then if the flag is set or `fp_wake_deadline_expired(esp_timer_get_time(), start, CONFIG_SKYPANE_WAKE_BUDGET_S)` is true, logs `ESP_LOGW(TAG, "wake budget of %us exceeded", ...)` once and calls on_expired. Call only where going to sleep is safe (never while the panel is powered).
- `bool fp_wake_expired(void);`
- `uint32_t fp_wake_elapsed_ms(void);` — for the diagnostic timing line.
- `void fp_wake_light_sleep_s(uint32_t seconds);` — loops over `fp_wake_slice_s(remaining, FP_WAKE_LIGHT_SLEEP_SLICE_S)` with `#define FP_WAKE_LIGHT_SLEEP_SLICE_S 20`: for each slice `esp_sleep_enable_timer_wakeup(slice * 1000000ULL)`, `esp_light_sleep_start()` (on error fall back to `vTaskDelay` for that slice and log once), then `fp_wake_feed()` and `vTaskDelay(1)` so the idle tasks also run and reset their watchdog entries; afterwards disable the timer wakeup source again with `esp_sleep_disable_wakeup_source(ESP_SLEEP_WAKEUP_TIMER)` so the deep-sleep path re-arms it cleanly. Comment why slicing exists: whether the watchdog timer keeps counting through light sleep is not guaranteed, so no single sleep may approach the 60 s timeout.
In wake_guard.c add `_Static_assert(CONFIG_SKYPANE_WAKE_BUDGET_S > FP_WAKE_WORST_CASE_S(CONFIG_FP_MAX_GUARD_WAIT_S), "wake budget must exceed the worst legitimate wake");` and `_Static_assert(CONFIG_ESP_TASK_WDT_TIMEOUT_S > FP_WAKE_LIGHT_SLEEP_SLICE_S, ...)`. Include `sdkconfig.h`, `esp_timer.h`, `esp_task_wdt.h`, `esp_sleep.h`, `esp_log.h`, FreeRTOS headers. No plan IDs in comments (D-A3).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| hardware faults (SPI/GPIO, panel BUSY line, brownout) -> firmware control flow | Faults must become bounded failures, not loops |
| wall-clock budget -> battery | An unbounded wake is a flat battery |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-07-01 | Denial of Service | epd_init abort loop | mitigate | ESP_ERROR_CHECK removed; setup failure returns ESP_FAIL -> step=blit -> exponential backoff |
| T-34-07-02 | Denial of Service | hung wake | mitigate | Task watchdog (panic, 60 s) fed only at bounded points; wake budget timer + checkpoint; _Static_assert keeps the budget above the worst legitimate wake |
| T-34-07-03 | Denial of Service | watchdog false positive during long legitimate waits | mitigate | busy_wait and send_half feed; light sleep sliced to 20 s with feed + idle yield between slices |
| T-34-07-04 | Tampering | timer callback context | mitigate | Callback only sets a flag; sleep ordering stays in app_main's single exit |
| T-34-07-05 | Information Disclosure | battery telemetry | accept | Pack voltage is non-sensitive device telemetry already sent today |
</threat_model>
