<objective>
Cut the per-wake network cost: reuse one HTTP client (and connection) for every
request of a wake, and — best effort — resume the TLS session across deep sleep.
Also bound the download loop by the wake budget and log the connection facts the
hardware session needs to explain the ~28 s per-cycle overhead.

Purpose: FW-10 (keep-alive mandatory, cross-sleep session best effort with
fallback, per RESEARCH.md), FW-02 (download checkpoints), FW-14 (the single
client constructor now also owns reuse). Public API of api_client.h is unchanged
from plan 34-06; only internals move.
Output: reworked api_client.c internals, new tls_session.c/.h, tcp_transport in REQUIRES.
</objective>

- esp_http_client_config_t has `bool save_client_session` (under CONFIG_ESP_TLS_CLIENT_SESSION_TICKETS) and `struct esp_transport_item_t *transport` (under CONFIG_ESP_HTTP_CLIENT_ENABLE_CUSTOM_TRANSPORT). With a custom transport the client skips scheme-based transport selection. With save_client_session, after each connect the client calls esp_transport_ssl_session_ticket_operation(t, ESP_TRANSPORT_SESSION_TICKET_SAVE), and before a reconnect it calls ..._USE when a session was saved.
- components/tcp_transport/transport_ssl.c (v5.3.1) internal context, obtained with esp_transport_get_context_data(t):
    typedef struct transport_esp_tls { esp_tls_t *tls; esp_tls_cfg_t cfg; bool ssl_initialized; transport_ssl_conn_state_t conn_state; int sockfd; esp_tls_client_session_t *session_ticket; } transport_esp_tls_t;
  SESSION_TICKET_SAVE: esp_tls_free_client_session(ssl->session_ticket); ssl->session_ticket = esp_tls_get_client_session(ssl->tls);
  SESSION_TICKET_USE: requires ssl->session_ticket != NULL; sets ssl->cfg.client_session = ssl->session_ticket.
- esp_tls.h: typedef struct esp_tls_client_session { mbedtls_ssl_session saved_session; } esp_tls_client_session_t; esp_tls_free_client_session(esp_tls_client_session_t *).

- mbedtls: mbedtls_ssl_session_init/_free, mbedtls_ssl_session_save(const mbedtls_ssl_session*, unsigned char *buf, size_t len, size_t *olen), mbedtls_ssl_session_load(mbedtls_ssl_session*, const unsigned char *buf, size_t len).

Create `tls_session.h/.c` (SkyPane-original SPDX). Public API (always declared):
- `bool fp_tls_session_offer(esp_transport_handle_t ssl, const char *origin);` — before the first connect of a wake.
- `void fp_tls_session_save(esp_transport_handle_t ssl, const char *origin);` — after the first successful response.
- `void fp_tls_session_forget(void);`
- `bool fp_tls_session_offered(void);` and `uint32_t fp_tls_session_saved_len(void);` — for the fp_api diagnostic line.
Implementation guarded by `#if CONFIG_SKYPANE_TLS_SESSION_PERSIST && CONFIG_ESP_TLS_CLIENT_SESSION_TICKETS && (ESP_IDF_VERSION == ESP_IDF_VERSION_VAL(5, 3, 1))` (include esp_idf_version.h); otherwise every function is a no-op returning false/0 — the build then simply does a full handshake each wake. Header comment: why this reaches into the transport's private context (esp_http_client exposes no session export), why it is pinned to exactly v5.3.1 (the private struct layout is not a stable API), and that any failure falls back to a full handshake.

Guarded implementation:
- A local mirror struct of transport_esp_tls_t with the v5.3.1 field order (comment: copied from transport_ssl.c at v5.3.1; must be re-checked on any IDF upgrade — the version guard compiles this out otherwise).
- RTC storage: `RTC_DATA_ATTR static uint8_t s_blob[FP_TLS_SESSION_MAX]` with `#define FP_TLS_SESSION_MAX 3072`, `RTC_DATA_ATTR static uint16_t s_len`, `RTC_DATA_ATTR static char s_origin[FP_API_BASE_MAX]`.
- offer: if s_len > 0 and origin matches: `calloc` an esp_tls_client_session_t, `mbedtls_ssl_session_init(&s->saved_session)`, `mbedtls_ssl_session_load(...)`; on failure free and forget; on success free any existing `mirror->session_ticket` with esp_tls_free_client_session, set it to the new one, call `esp_transport_ssl_session_ticket_operation(ssl, ESP_TRANSPORT_SESSION_TICKET_USE)`; return true.
- save: read `mirror->session_ticket` (NULL -> nothing); `mbedtls_ssl_session_save(&t->saved_session, s_blob, sizeof s_blob, &olen)`; on MBEDTLS_ERR_SSL_BUFFER_TOO_SMALL log `ESP_LOGW(TAG, "TLS session needs %u bytes, have %u; not persisted", olen, FP_TLS_SESSION_MAX)` and forget; on success store s_len/origin and log `ESP_LOGI(TAG, "TLS session saved (%u bytes)", olen)`.
- forget: s_len = 0.
Wire into api_client.c: call fp_tls_session_offer right after creating s_tls (https only), fp_tls_session_save after the first request that returned any HTTP status on s_http, and fp_tls_session_forget when a connect fails on a wake that offered a session (so a stale ticket never blocks the next wake); feed the two getters into the Task 1 diagnostic line.
The hardware session (plan 34-11) decides whether resumption actually happens against Caddy by comparing first_connect_ms with tls_offered 0 vs 1; this task does not claim it works, it makes it measurable and safe.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device -> VPS TLS | Session tickets and resumed sessions must not weaken server authentication |
| shared HTTP handle -> image host | Headers set for the API must not reach another origin |
| RTC memory across deep sleep | Serialised session state persists between wakes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-09-01 | Information Disclosure | bearer token on image request | mitigate | All request headers deleted before each request; cross-origin download uses a separate client with no auth header |
| T-34-09-02 | Spoofing | resumed TLS session | mitigate | Session offered only for the same origin it was saved for; resumption is standard TLS 1.2 ticket resumption validated by the server; the full handshake still verifies the chain with the ISRG-only bundle |
| T-34-09-03 | Tampering | private struct mirror | mitigate | Compiled only for exactly ESP-IDF v5.3.1 and behind a Kconfig switch; any load/save error forgets the session and falls back |
| T-34-09-04 | Information Disclosure | session blob in RTC memory | accept | RTC memory is on-chip and cleared on power loss; an attacker with physical access already has the flash (D-A1 accepts no flash encryption) |
| T-34-09-05 | Denial of Service | slow download | mitigate | fp_wake_checkpoint per read ends the wake at the budget |
| T-34-09-06 | Denial of Service | stale connection | mitigate | Retry-once on a fresh connection only before any response status was read |
</threat_model>
