<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device -> VPS over the internet | TLS server authentication depends on the embedded trust store |
| developer build config -> shipped image | A dev-only option leaking into a production image weakens transport security or adds a crash trigger |
| upstream PEM source -> repository | Root certificates are supply-chain inputs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-04-01 | Spoofing | CA bundle | mitigate | Trust store reduced to ISRG Root X1/X2; fingerprints pinned in check_production_config.sh and cross-checked against a second source before commit |
| T-34-04-02 | Tampering | CONFIG_SKYPANE_ALLOW_HTTP | mitigate | Default n; only sdkconfig.dev.defaults sets it; static + built checks in CI fail if a production build has it on |
| T-34-04-03 | Elevation of Privilege | SKYPANE_FAULT_INJECT choice | mitigate | Default NONE; CI built check asserts CONFIG_SKYPANE_FAULT_INJECT_NONE=y and absence of the SKYPANE-FAULT-INJECT marker in skypane.bin |
| T-34-04-04 | Denial of Service | ISRG-only bundle vs a future Let's Encrypt root change | accept | Operational risk documented in sdkconfig.defaults and VENDOR.md (plan 34-10); fix is a firmware update |
| T-34-04-05 | Tampering | secret partition layout | mitigate | New partition only in the free gap; nvs/factory offsets asserted unchanged by the static check |
| T-34-04-SC | Tampering | package installs | accept | No npm/pip/cargo installs in this phase (RESEARCH.md Package Legitimacy Audit: n/a) |
</threat_model>
