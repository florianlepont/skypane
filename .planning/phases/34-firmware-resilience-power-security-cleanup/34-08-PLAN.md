<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chip reset cause -> radio use | Only a clean wake may poll |
| server replies -> step classification and sleep | Untrusted status codes decide token erasure and backoff |
| build configuration -> fault code | Dev-only triggers must not exist in production images |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-08-01 | Denial of Service | crash/brownout loop | mitigate | Abnormal reset -> fail_and_sleep("reset") before the radio starts; backoff counter in NVS survives power loss |
| T-34-08-02 | Denial of Service | hung or slow wake | mitigate | Wake budget checkpoints at every network boundary + task watchdog panic for true hangs |
| T-34-08-03 | Elevation of Privilege | fault_inject.c | mitigate | Whole body compiled out unless a non-NONE choice is selected; CI built check asserts no SKYPANE-FAULT-INJECT string in skypane.bin (plan 34-04) |
| T-34-08-04 | Denial of Service | hostile 401 forcing re-enrolment | mitigate | Re-enrolment only after the normal backoff sleep and only with the device's own secret; no hot loop |
| T-34-08-05 | Information Disclosure | diagnostic lines | mitigate | fp_boot and fp_diag lines contain only reset labels and durations — no tokens, secrets or URLs |
| T-34-08-06 | Tampering | static IP option | accept | Compile-time, developer-controlled, default off; no runtime input |
</threat_model>
