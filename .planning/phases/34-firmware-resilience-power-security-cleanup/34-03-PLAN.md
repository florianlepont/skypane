<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet -> byos /device/v1/setup | Anyone can POST a MAC (MACs are visible on the air) and a claimed secret |
| operator shell -> devices.json | Registry edits are privileged operations on the VPS |
| byos process -> state dir | Registry and token files at rest |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-03-01 | Spoofing | setup handler | mitigate | Enrolment requires the MAC's own secret whose SHA-256 is in devices.json; MAC alone -> 403, wrong secret -> 401 (tested) |
| T-34-03-02 | Information Disclosure | secret_matches | mitigate | hmac.compare_digest on SHA-256 hex digests; presented value shape-checked first |
| T-34-03-03 | Information Disclosure | devices.json at rest | mitigate | Only SHA-256 of a 256-bit random secret is stored; file written 0600 via os.open; test asserts plaintext never appears |
| T-34-03-04 | Denial of Service | revoke of a victim's token | mitigate | A wrong-secret setup leaves state untouched (tested) — the old shared-secret takeover path is closed |
| T-34-03-05 | Elevation of Privilege | load_registry | mitigate | Fail closed: missing/corrupt registry enrols nobody (tested) |
| T-34-03-06 | Denial of Service | setup brute force / request flood | accept | 2^256 secret space makes guessing infeasible; rate limiting and socket timeouts are Phase 36/37 scope (INT-06, SEC-06) |
| T-34-03-07 | Repudiation | setup refusals | mitigate | Each refusal prints `setup: <mac> refused (<reason>)` to the journal without the secret |
| T-34-03-08 | Denial of Service | migration ordering | mitigate | --secret accepted-and-ignored so a stale unit cannot crash-loop byos; README orders the steps |
</threat_model>
