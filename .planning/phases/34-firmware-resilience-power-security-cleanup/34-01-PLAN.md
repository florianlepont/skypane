<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server response -> device parser | JSON fields from the network (image_url, image_hash, sleep_s, led_enabled, device_token) are untrusted until validated |
| download bytes -> panel | Streamed image bytes are untrusted until size and SHA-256 match |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-01-01 | Denial of Service | fp_sleep_s_parse | mitigate | Upper bound FP_SLEEP_S_MAX = 86400; host test asserts 86401 and 4294967295 are rejected, so a hostile or buggy server cannot park the frame for years |
| T-34-01-02 | Tampering | fp_url_scheme_allowed / fp_url_valid | mitigate | https-only unless the caller passes allow_http=true (only a Kconfig-gated dev build will, plan 34-06); both modes asserted in test_validate.c |
| T-34-01-03 | Tampering | fp_download_verdict | mitigate | Exact-length + status + oversize checks precede the hash compare; NULL hashes fail closed as HASH_MISMATCH |
| T-34-01-04 | Tampering | fp_token_valid / fp_hex_lower_valid | mitigate | Exact 64-char lowercase-hex rule; uppercase and wrong length rejected (asserted) |
| T-34-01-05 | Elevation of Privilege | run_host_tests.sh discovery | accept | Runs only repository-controlled test sources with the system cc; no network or untrusted input |
</threat_model>
