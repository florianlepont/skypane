`firmware/provision.sh <serial-port> [--reset-device-state]` and `firmware/provision.sh --dry-run <mac>`.

Behaviour, in order:
1. Argument parsing with a `Usage:` message on stderr and exit 2 for anything unrecognised; the port is required outside dry-run and is never guessed (copy flash.sh's wording).
2. Tool checks: `docker`, `python3`, and (outside dry-run) `esptool`, each with an install hint on failure.
3. Parse `partitions.csv` with an inline `python3 -` heredoc (strip `#` comments, split on commas, trim) to get the `secret` row's offset and size (must be type `data`, subtype `nvs`) and the `nvs` row's offset and size; abort if the secret row is missing.
4. MAC: outside dry-run, run `esptool --chip esp32s3 --port "$PORT" --after no-reset read-mac` and extract the `MAC:` value, lowercase; in dry-run use the given argument. Validate against `^[0-9a-f]{2}(:[0-9a-f]{2}){5}$`; abort otherwise. Comment: the ESP32-S3 Wi-Fi station MAC equals the base MAC esptool reports, which is what the firmware sends in POST /device/v1/setup.
5. `umask 077`; `WORK=$(mktemp -d)`; `trap 'rm -rf "$WORK"' EXIT INT TERM`.
6. Secret: `python3 -c 'import secrets; print(secrets.token_hex(32))'` into a shell variable — never echoed, never written outside $WORK.
7. Write `$WORK/secret.csv` with lines `key,type,encoding,value`, `skypane,namespace,,`, `enrol_secret,data,string,<secret>` (namespace and key match nvs_schema.h, D-34-02).
8. Generate the image in the pinned container: `docker run --rm -v "$WORK:/work" -u "$(id -u):$(id -g)" -e HOME=/tmp espressif/idf:v5.3.1 sh -c 'python "$IDF_PATH/components/nvs_flash/nvs_partition_generator/nvs_partition_gen.py" generate /work/secret.csv /work/secret.bin <size>'`; check the output file size equals the partition size in bytes.
9. Outside dry-run: write only that region with `esptool --chip esp32s3 --port "$PORT" --after no-reset write-flash <secret-offset> "$WORK/secret.bin"`, read it back with `read-flash <offset> <size> "$WORK/readback.bin"` and `cmp`; abort on mismatch. Only if `--reset-device-state` was given, additionally run `esptool ... erase-region <nvs-offset> <nvs-size>` and print what that erased (bearer token, last image hash, backoff counter, boot counter, cached DHCP lease). Finally reset the board (`esptool --chip esp32s3 --port "$PORT" --after hard-reset read-mac` or equivalent chip-reset call).
   Comment the design choice in two lines: parttool.py needs serial access from inside the container, which this project avoids on macOS (see flash.sh); writing the single partition's byte range with host esptool, offset read from partitions.csv, is the same non-destructive operation.
10. Compute `HASH=$(printf '%s' "$SECRET" | python3 -c 'import hashlib,sys; print(hashlib.sha256(sys.stdin.read().encode("ascii")).hexdigest())')`, then `unset SECRET`.
11. Print: `Provisioned <mac>` (or `Dry run for <mac> (nothing written)`), `Registry line: <mac> <hash>`, and the two registration commands, verbatim: local stub `python3 stub-server/devices_cli.py --state-dir <state-dir> add --mac <mac> --secret-sha256 <hash> --replace` and VPS `ssh <ssh-target> "sudo -u skypane /opt/skypane/venv/bin/python3 /opt/skypane/stub-server/devices_cli.py --state-dir /opt/skypane/state add --mac <mac> --secret-sha256 <hash> --replace"`. Add a closing note: re-running this script generates a NEW secret, so the registry entry must be replaced (that is why `--replace` is in the commands).
The script never prints the secret, never writes it outside the temp dir, and never touches any partition other than `secret` unless `--reset-device-state` is given.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer laptop -> device flash | The secret crosses USB into the device's secret partition |
| provisioning output -> operator/VPS | Only MAC and SHA-256 leave the laptop |
| build profile -> shipped image | Dev options must not reach production images |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-05-01 | Information Disclosure | provision.sh secret handling | mitigate | Secret generated by Python `secrets`, kept in a shell variable and a 0700 temp dir removed by trap; never printed; only sha256 printed |
| T-34-05-02 | Information Disclosure | secret at rest in device flash | accept | D-A1: no flash/NVS encryption (irreversible eFuse burn); physical-access extraction yields one device's secret only, revocable by `devices_cli.py remove` |
| T-34-05-03 | Tampering | partition write range | mitigate | Offset/size parsed from partitions.csv, write limited to the secret partition, read-back cmp before reset; nvs erase only behind an explicit flag |
| T-34-05-04 | Elevation of Privilege | build profiles | mitigate | prod + fault refused with exit 2; dev uses a separate build dir; sdkconfig regenerated on every build; CI built check (plan 34-04) |
| T-34-05-05 | Spoofing | wrong device provisioned | mitigate | Port is required and never guessed; MAC read from the attached chip and printed with the registry line |
| T-34-05-06 | Repudiation | version reported by the device | mitigate | PROJECT_VER from git describe (with -dirty) so every image is traceable to a commit |
</threat_model>
