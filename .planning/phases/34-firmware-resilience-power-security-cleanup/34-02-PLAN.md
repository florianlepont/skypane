<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server sleep_s -> sleep timer | A validated server value becomes the device's next wake time |
| chip reset cause -> poll/backoff choice | Hardware-reported reset reason decides whether the wake may use the radio |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-02-01 | Denial of Service | fp_sleep_decide | mitigate | Zero server sleep is treated as a failure (backoff), so no path yields a zero-second wake loop; backoff counter saturates at 255 and sleep caps at 6 h (asserted) |
| T-34-02-02 | Denial of Service | fp_reset_is_abnormal | mitigate | Every non-deliberate reset (incl. brownout, glitch, lockup) is abnormal so a crash loop becomes exponential backoff, not a battery-draining hot loop |
| T-34-02-03 | Repudiation | fp_wake_reason_token | mitigate | 'power-on' reported only for a real power-on; abnormal resets report 'other' and plan 34-08 logs the precise reset label |
| T-34-02-04 | Tampering | FP_RST_* mirror | mitigate | Numeric mirror of the IDF enum is enforced by _Static_assert in the firmware build (plan 34-08) so enum drift fails compilation instead of misclassifying |
</threat_model>
