  <behavior>
    - Hovering a palette chip's `<label>` applies that chip's `data-preview-src` to the live preview.
    - Moving the pointer off it (to a non-chip area) returns the preview to the open row's own checked
      chip's src, falling back to the departures row's checked chip when the open row's selection is the
      leading "Same as departures" option, which carries no `data-preview-src`.
    - Keyboard-focusing a chip does the same as hovering it; blurring returns the preview the same way.
    - Hovering from one chip directly to a sibling chip previews the sibling — it does not flash back to
      the checked selection in between.
    - The preview NEVER becomes selection: no radio's `checked` is written, no change event is
      dispatched, no `click()` is called, no form value is written, and the preview's `src` is only ever
      written through `applyPreviewSrc()`.
    - A reload with nothing clicked shows the SAVED theme, not whatever chip was last hovered.
    - With the script blocked, hover does nothing and the preview shows the saved theme — no broken
      state, no blank box.
  </behavior>
  <action>
    Add ONE delegated pointer/focus listener pair on the card root, in the same place and the same style
    as the existing delegated `change` listener. Two listeners in, two out: `mouseover` + `focusin` to
    preview, `mouseout` + `focusout` to revert. Delegated on the card, never one pair per chip — a card
    can hold three 18-entry palettes and 108 listeners is the thing delegation exists to avoid.

    Resolve the hovered chip by walking from `evt.target` to the nearest ancestor carrying
    `data-preview-src`, and mirror the existing `change` listener's own guard shape rather than
    inventing a second resolution path. A `mouseover` that resolves to no chip is a no-op, not a revert
    — that is what makes chip-to-chip movement work without a flash, because the intervening
    `mouseout` and the new `mouseover` both fire and the revert must lose to the later preview.

    The revert target is `checkedChipSrc(openRow()) || checkedChipSrc(departuresRow())` — the same
    expression `refreshFromCurrentState()` already uses. Compute it fresh on every revert; do not cache
    it at load, because the checked selection changes under the script's feet whenever a visitor clicks.

    Use `mouseover`/`mouseout` rather than `mouseenter`/`mouseleave`: the latter do not bubble, so they
    cannot be delegated, and delegating is the constraint. Do not add `pointerenter`/`pointerleave`
    either, for the same reason.

    **No timer of any kind.** Not a debounce, not a settle delay, not a `requestAnimationFrame`. This
    file's standing rule bans every timer primitive by name and
    `companion/test_companion_app.py` enforces it. The crossfade already absorbs rapid changes by
    comparing against `pendingSrc`, which is exactly the problem a debounce would be reaching for.

    **No backtick anywhere, including comments.** **No second global.** **No new file.**

    Update the file's header comment: the "only DOM writes this file ever makes" sentence must be
    re-checked against this addition and the result stated, the way 28-05's own addition did. The new
