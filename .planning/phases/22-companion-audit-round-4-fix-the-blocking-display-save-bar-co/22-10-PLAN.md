<objective>
The Display page is 2 900 px tall on a desktop and 4 250 px on a phone, because
eighteen chips sit permanently expanded at 160x108 in the main grid while the same
list renders at ~104 px in the Arrivals and Rules rows — the same control, two
shapes, on one page. Around it: the runway grid breaks 2 + 1 on a phone, the time
inputs show "11:00 PM" beside a preset labelled "23:00", Connect calendar is the
only full-width primary button in the app, a hovered selected segment turns
unreadable, and the theme preview slices its caption mid-glyph. The Device page
adds an orphaned "Send a test" button floating between two cards and a
448-px-wide number field starting 154 px to the right of everything else.

Purpose: these are the measured geometry defects on the two settings pages, and
they share one file and one stylesheet — so they are one plan, ordered so the
chips (the largest single win) land first.
Output: a Display page that fits, controls that line up, and a preview that does
not look broken.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → the cross-DOM `form=` submission | a button outside a form submits it; the form's action is what authorises the write |
| server-rendered `data-current-label` → CSS `content` | a translated string crosses into a pseudo-element |
| rendered theme PNG → every consumer | the crop constant changes an image served to the chips, the live preview and any other reader |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-34 | Tampering | the Notifications test button's cross-DOM `form=` attachment | mitigate | the empty form keeps its own action and its existing server-side handler and validation; only the button's DOM position changes, and form ownership is decided by the browser from the `form=` attribute, not by proximity |
| T-22-35 | Information Disclosure | `data-current-label`'s value reaching a CSS `content` | mitigate | the value is a translated constant, interpolated through `escape_html()` at its attribute site like every other attribute on the page; it is never user input |
| T-22-36 | Denial of Service | a crop box that breaks pairwise distinctness | mitigate | the distinctness property is re-measured against the full registered theme set and recorded, and the 8:3 ratio is asserted, so two themes cannot silently render identical chips |
| T-22-37 | Tampering | the frame's own design system leaking into `style.css` | mitigate | Pitfall 6: every colour and font value in this plan comes from `style.css`'s own token set; no `server/plane/` constant or e-ink font crosses the boundary, which the file's own header comment states |
| T-22-SC | Tampering | npm/pip/cargo installs | n/a | this plan installs zero packages in any ecosystem |
</threat_model>
