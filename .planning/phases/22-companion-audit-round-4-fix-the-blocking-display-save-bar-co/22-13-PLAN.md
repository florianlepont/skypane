<objective>
The login card is the first thing anyone sees and the only page with no stylesheet
rule at all. A 225x44 input with an 8 px radius sits beside a 68x30 button with a
6 px radius, 7 px lower; on a phone the field keeps 225 of 278 px and the button
wraps glued underneath at a zero gap. The error is a bare paragraph with no error
class, no `aria-describedby` and no `aria-invalid`. There is no way to reveal the
password you typed, and the lockout message is a frozen sentence that never counts
down.

Purpose: this is the app's only pre-auth surface, and the one where a household
member is most likely to be stuck. Every fix here is a repair of a floor the rest
of the app already meets.
Output: a card whose two controls read as one object, an error a screen reader can
find, a password you can check, and a lockout that ends by itself.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated browser → login handler | the app's only pre-auth surface, reachable without a session |
| server lockout state → a client-side countdown | a security-relevant figure crosses into the DOM and into a script |
| password input → the show-password toggle | a secret becomes visible on screen at the user's request |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-46 | Elevation of Privilege | the client-side countdown re-enabling the form early | mitigate | the countdown is presentational only; `auth.py`'s `LoginThrottle` remains the sole authority and still rejects an attempt inside the window. No throttling constant is duplicated client-side, which the acceptance grep pins |
| T-22-47 | Information Disclosure | the show-password toggle revealing the secret on screen | accept | it is user-initiated, defaults to hidden, and reverts on any page load; this is the standard, expected control and its absence causes more failed logins than its presence causes shoulder-surfing |
| T-22-48 | Information Disclosure | the seeded remaining-seconds figure | accept | it reveals only how long the existing static sentence already states in words; no attempt count, no identity and no secret crosses with it |
| T-22-49 | Tampering | a new same-origin script on a pre-auth page | mitigate | `script-src 'self'` is unchanged, no inline script and no nonce is introduced, and the file is served from the same origin as every other script. Pinned by an acceptance grep |
| T-22-50 | Spoofing | the error message enumerating whether a password exists | accept | unchanged copy semantics: one message for a wrong password, with no account enumeration surface on this single-password app |
