# Phase 22 — UI Design Contract

> Visual and interaction contract for the companion's fourth audit round. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## How to read this document

**This is a correction phase against a mature, live design system. It invents no visual direction.**

`sketch-findings-skypane` (`.claude/skills/sketch-findings-skypane/SKILL.md` plus its six `references/*.md`) is the authority for every token, role and idiom in the companion app. This spec **cites** it and does not restate it. Where a value is already settled there — the accent hex, the spacing tokens, the serif boundary, the label voice, button geometry, the wash-strength register, the touch-target register — this document names the rule and moves on. Copying the token table here would create a second source of truth, which is exactly the drift `C1`–`C6` document.

What this document does specify:

| Section | Contains |
|---|---|
| §1 | Design-system citations and the three template tables, filled only where this phase changes something |
| §2 | Layout correction contracts — one per audit finding with a **measured acceptance target** from `22-AUDIT.md`'s Pixel measurements table |
| §3 | The three genuinely new surfaces: the bottom tab bar, the login card, the held-vs-late frame state |
| §4 | Design-system changes this phase forces, so `sketch-findings-skypane` is updated **in step** (D-08) rather than left contradicting the shipped code |
| §5 | Accessibility contracts the audit found broken |
| §6 | Explicitly out of scope |

**Every D1–D24 dynamism item is Phase 23 and is not specified here.** No motion beyond what a corrected control needs to not read as broken. No Home hero, no day timeline, no runway map, no quiet-hours dial, no theme carousel.

**Binding upstream inputs:** `22-CONTEXT.md` D-01..D-12 (all LOCKED), `22-AUDIT.md` (the specification), `22-RESEARCH.md` (mechanisms and pitfalls), `REQUIREMENTS.md` CFG-25..CFG-31.

### Spacing Scale

**Unchanged. Cited, not restated** — the seven `--space-*` tokens (4/8/16/24/32/48/64) and their placement rules live in `SKILL.md`'s Spacing paragraph, including the one-sibling-card-gap rule (`--space-lg` everywhere) and the 24px/16px card-padding split at the 960px breakpoint.

**Exceptions introduced by this phase — three, all off-scale for a stated physical reason:**

| Value | Where | Why it is not a token |
|---|---|---|
| `env(safe-area-inset-bottom, 0px)` | bottom tab bar, pinned save bar | A device-reported inset, not a design value |
| `56px` | bottom tab bar height | A hit-target dimension (20px icon + 4px gap + 11px label line + 2×8px padding ≈ 55px, rounded to 56), not a spacing rhythm |
| `8ch` / `min-width: 96px` | Device wake-interval number input (B17) | A content-fit width in character units — the correct unit for "sized for its content" |

No other off-scale literal may be introduced. `T16`'s existing off-scale literals (13/11/10px, radii 6/4/3px) are debt, not licence.

### Typography

**Unchanged scale. Cited, not restated** — four sizes (14/16/22/32px), two weights (400/600), three families, the three-rung heading ladder and the 12px uppercase label voice all live in `SKILL.md`'s Typography paragraph and `references/visual-direction-typography.md`.

This phase changes **four** things inside that scale, all as corrections:

| Change | From | To | Finding |
|---|---|---|---|
| Frame strip's next-update line | 22px (`--font-heading-size`, the Phase 21 `d9e0338` override) | 16px semibold — the Emphasis role, i.e. `.status-card__headline`'s own unoverridden base | C6 |
| `empty_state()` inside a tile | 22px serif `.text-heading` heading | compact variant: 16px sans semibold heading (Emphasis role) + 14px `.text-label` body | C1, X8 |
| Label-voice `<legend>` (`.frame-colours__panel-legend`) | serif, inherited from the `legend` selector | `--font-ui`, via a later higher-specificity rule | C1 |
| Time values (four treatments today) | 14px grey label / 16px bold mono / 14px mono / mono | one `.time-value` role — see §4 C5 | C5 |

**One new size joins the existing sub-scale exception tier** (alongside `.sparkline-axis-label` 10px and `.cell-secondary` 11–12px): the bottom tab bar's label at **11px**, `--font-ui`, regular (semibold when active). It is explicitly **not** the label voice — no uppercase, no `0.06em` tracking — because a nav destination is a destination, not a label. See §3.1.

**`legend` must stay in the serif selector.** It earned its place there as a bug fix (`SKILL.md` states this directly). C1's fix is an override on the one label-voice legend, using the same "non-serif exception, the other direction" mechanism `.page-section--nested > h2` already uses — never a removal from the shared selector list.

**No new colour literal, no new wash percentage, no new muted strength.** The register is `4.5% / 6% / 7% / 7.5% / 9% / 12% / 14% / 20% / 30% / 70%` (`references/control-density.md`). Every rule this phase adds draws from it. The audit's own "12–18% wash" suggestion for B7 is a suggestion; the register is the contract (see §2 B7).

**Any new use of a status colour as text or as a control border must be gated through `companion/contrast_check.py` before shipping** — `WCAG_AA_NORMAL_TEXT` (4.5) for text, `WCAG_AA_UI_COMPONENT` (3.0) for a border. The precedent is binding: 20-UI-SPEC.md specified `--color-status-warn` as the overdue headline's text colour, the gate measured 3.19:1 in light mode, and the choice was **dropped rather than the threshold weakened** (`.status-card__headline--warn` is `--color-text` today, with the warn carried by wording plus a leading dot). This phase follows that precedent exactly — see §3.3.

**Retired copy — these three wordings must not survive anywhere (D-04):** `Applies the next time the frame wakes up.` *(as a hard-coded strip caption)*, `Takes effect within about 5 minutes`, `Applies on the next scheduled poll, which may now be hours away`, plus the flash variant `Saved — will apply on the frame's next scheduled refresh`. The unknown-state sentence above reuses the first wording's **text** as the honest no-check-in fallback; it is no longer a per-control literal.

**The "within about 5 minutes" claim is suspect until substantiated** against `server/wake.py:114-115` and the firmware (D-04, and `22-AUDIT.md`'s own "Not verified" list). If it cannot be substantiated it is replaced by the computed estimate, **not restated**. If it is substantiated, it may appear only in the screen-already-off branch, and only as the computed estimate — never as a fixed literal.

**Three copy rules, all citations:**
1. **One caption per section** (`references/settings-page-patterns.md`) — six sections, six `<p class="text-label section-caption">`. A legend under a *control* (X6's swatch legend) is not the section caption and does not violate this; state that in the plan so a reviewer does not read it as a breach.
2. **Verdict and detail must always carry different information** (`status_row`'s D-21 rule). The verdict is the state name; the detail is evidence for it (when, how many, what value). X8's "double bold verdict" is a breach of this rule, not a new one.
3. **Plurals get singular forms** (D-06): `1 manual resolution`, `%d upcoming flight` / `%d upcoming flights`, `over the last %d days, %d events`. The battery caption stops naming `BATTERY_TREND_LIMIT` and states the real count.

## 2. Layout Correction Contracts

Each row is a contract with a **measured acceptance target** taken from `22-AUDIT.md`'s Pixel measurements table. "Measured today" is the audit's DOM measurement; "Target" is what the checker and the Playwright harness (D-02) verify.

### B13 — Frame strip cells

| | |
|---|---|
| **Measured today** | Cells `119 / 165 / 69` px tall, tops at `214 / 191 / 240`. Phone: third cell `42px`. `align-items: center`. |
| **Target** | All three cells report **equal `offsetHeight`** and **equal `getBoundingClientRect().top`** at 1280px. On a phone all three carry the same card chrome (the third is no longer a 42px bare line). |

**Contract.** `.frame-strip__cells { align-items: stretch; }` (was `center`). Every cell — both switches and the update cell — uses **one internal grid**: `display: grid; grid-template-rows: auto auto auto; row-gap: var(--space-sm);` with rows *(1)* label, *(2)* state + control, *(3)* caption. A cell with no content in a row renders an empty track, which is what makes the three cells' rows line up rather than each cell laying itself out independently (today the Screen cell puts its button on the label row and the Quiet-hours cell pushes it to its own row).

**Shared chrome = padding + hairline + radius + surface.** The `.quick-action--on/--off` left edge stays exclusive to the two switch cells: it is a *control-state* signal, not a cell style, and painting it on a non-interactive cell would claim a state the cell does not have.

**The next-update line is a cell of the same style**, not a floating headline. C6 rides here: delete the `.frame-strip__cell--update .status-card__headline { font-size: var(--font-heading-size) }` override so the line returns to `.status-card__headline`'s own 16px semibold Emphasis base, one step **below** the 22px serif section headings it currently competes with.

**C2 rides here.** The two switch buttons stop being accent-filled. Mechanism is prescribed, not free: a `.frame-strip__cell button` rule at **`(0,1,1)` — equal specificity to `button[type="submit"]` — placed after it in source order**, reusing the base quiet wash verbatim (4.5% rest / 7.5% hover background, 9% / 14% border). This is the identical mechanism `.logout-form button` and `.dirty-bar__cancel` already use, documented in `references/control-density.md`. **Do not raise specificity** (it starts beating class-scoped controls) and **do not invent a wash value**.

**T9 rides here.** `.stat-tile:hover { border-color: transparent }` becomes side-and-bottom only (`border-inline-color` + `border-block-end-color`), leaving `border-block-start` — the status/accent rail — intact. And the strip must not lift when a button inside it is hovered: the card `:hover` reveal is `:not(.frame-strip)`-scoped. The strip is a control area, not a browsable card.

### B9 — Runway grid on a phone

| | |
|---|---|
| **Measured today** | `150×150`, `150×150`, then a lone `308×217` — a 2 + 1 orphan, caused by `.runway-card { flex: 1 1 150px; min-width: 140px; }` against a ~342px content column at 390px. |
| **Target** | **Exactly one line, three equal cards.** All three widths equal within 1px, all three heights equal. `.runway-row` renders one flex line. |

**Contract.** Below 960px: `.runway-row { flex-wrap: nowrap; }` and `.runway-card { flex: 1 1 0; min-width: 0; }` → three equal columns. At 390px: `(342 − 2×8px gap) / 3 ≈ 108.6px` per card, `76px` of content inside the 16px padding — enough for a two-character runway number plus the airport diagram at `max-width: 100%; height: auto`.

**Never 2 + 1.** If measurement finds the number illegible at 320px, the fallback is `flex-direction: column` (a vertical radio list) below 360px — the audit's own second option — not a re-wrap.

**Touch target unchanged:** the cards stay ≥108×≥100px, so the hidden radios keep their **exempt-by-delegation** register entry (the wrapping `.runway-card` label still exceeds 44px in both axes). Confirm this explicitly in the plan, since the cards get narrower.

### B11 — Filter count + Clear on one line

| | |
|---|---|
| **Measured today** | At 390px, "Clear" drops alone onto its own line under the filter bar on Flights, Airlines **and** Health. This is a regression of Phase 18's **A-18** — name it as such. |
| **Target** | At 390px on all three pages, the count and Clear report **equal `getBoundingClientRect().top`**. The field occupies the line above. |

**Contract.** Wrap the pair in one `.filter-bar__meta { display: flex; align-items: center; gap: var(--space-sm); white-space: nowrap; margin-left: auto; }` so they wrap as a unit, never independently. `.filter-bar__count` already carries `white-space: nowrap`; the Clear control joins it inside the group. Both Clear controls stay converged on the existing `[data-filter-clear]` rule (06.6.4 D-08) — do not fork them.

### B10 — Nav state reminder, one line per state

| | |
|---|---|
| **Measured today** | `.nav-status` is `207×48` and wraps mid-phrase: "Screen on · Quiet hours" / "on" (FR: "Heures / calmes activées"). `style.css:1134-1147` is inline text with no `white-space`. |
| **Target** | **Zero mid-phrase breaks**: each `.nav-status__segment` reports `getClientRects().length === 1` in FR at both the 240px sidebar and 390px phone. Height ≤ 48px. |

**Contract.** Two segments, each `white-space: nowrap`, inside `display: flex; flex-wrap: wrap; gap: var(--space-xs)` — the line may break **between** segments, never inside one. FR's longest segment ("Heures calmes activées", ~22 chars at 14px ≈ 150px) fits the 240px sidebar's content width.

**The `aria-label` must stop lying (D-04).** `nav_status_html()` takes the active route. When `active == HOME_ROUTE` it renders a `<span class="nav-status text-label">` — **no `href`, no destination in the accessible name**, just the state ("Screen on · Quiet hours on"). Elsewhere it stays the existing `<a href="/">` with its destination-naming label. D-04's "stays only if it links somewhere useful" is satisfied by construction: on Home it is not a link at all, so it cannot claim a destination it already occupies.

### B17 — Device fields share one left edge

| | |
|---|---|
| **Measured today** | Wake-interval number input at `x=515, w=448` (inline label) vs the topic URL at `x=361, w=448`. |
| **Target** | Every Device control reports the **same `getBoundingClientRect().left`** (`361`). The number input's width ≤ **120px**. |

**Contract.** One field shape across the Device page: `<label>` on its own line above its control — the shape every other field already uses. The number input gets `width: 8ch; min-width: 96px;` with the unit rendered as a **sibling** `<span class="text-label">s</span>`, not a placeholder and not text inside the control. The global `input, select` 44px floor is untouched (`width` does not touch `min-height`), so the touch-target register's "kept" entry for `<input type="number">` (11-03-PLAN.md) still holds verbatim.

### B6 — Theme-preview crop

| | |
|---|---|
| **Measured today** | `403×180`; the render's caption is sliced mid-glyph ("AF1789 to New York" cut) at every chip size and in the live preview. `THEME_PREVIEW_CROP_BOX` (`theme_preview.py:101-110`). |
| **Target** | **No glyph partially rendered** at any of the three sizes (160px full chip, 104px compact chip, the large live preview). |

**Contract. Exclude the caption entirely** — crop to the panel's colour-bearing illustration band. Rationale: the chip's job is to show the theme's *colours* (its band plus its two real-palette swatch dots); a 160×108 chip cannot render legible caption text at any crop, and a sliced glyph reads as a rendering bug rather than a crop. This is a server-side constant change in `theme_preview.py` — **not** a CSS `object-fit` workaround, which would leave the served PNG still wrong for every other consumer.

**Pitfall 6 applies:** the crop box is computed against the frame's own render geometry, but no `server/plane/` constant, `PALETTE_RGB` value or vendored e-ink font may cross into `style.css` while fixing this.

### X8 — One Health tile anatomy

| | |
|---|---|
| **Measured today** | Three server cards, three anatomies. A double bold verdict. "Only one saw it" rendered in the same green as "Both agree". An empty state at 22px serif inside a tile whose own caption is 12px. Status tiles on a phone measure `112 / 112 / 131`. |
| **Target** | One anatomy across every Health tile. Phone status tiles **equal height** (or content-justified). The empty state's heading is 16px sans, not 22px serif. |

**Contract — four slots, fixed order, on every tile:**

```
label      →  label voice (12px uppercase semibold, 0.06em, 70% muted)
verdict    →  Emphasis role (16px semibold)  — the state name, exactly once
detail     →  70% muted                      — evidence: when / how many / what value
link       →  optional, .text-link
```

This is the `status_row` primitive's own label/verdict/detail contract applied to `.stat-tile`. The **verdict appears exactly once** (today's "double bold verdict" is the breach) and **the detail must carry different information from the verdict** — the D-21 rule, cited not restated.

**"Only one saw it" becomes neutral**: `.dot--off`, not `.dot--ok`. `.dot--off` is defined (Phase 21 D-03) as "a neutral, everyday state, never a problem" — this is its second consumer and exactly its stated meaning. **Do not add a fifth dot** and **do not introduce a third colour**. Colour is not alone here: the visible `.dot-label` text already differs ("Both agree" / "Only one saw it"), so the fix is the token only.

**Compact empty state (C1):** `empty_state(heading, body, compact=True)` renders the heading at the Emphasis role (16px sans semibold) and the body at `.text-label` (14px, 70% muted), instead of `.text-heading` (22px serif) + `.text-body` (16px). Net drop from 22px serif to 16px sans satisfies the audit's "14px empty state, body-sized not a serif heading" while **reusing the established bottom-rung tier** rather than inventing a 14px heading role. The non-compact variant is unchanged for its full-card callers.

**B2 rides here:** phone status tiles get `align-items: stretch` on `.home-status-grid` so 112/112/131 becomes one height.

### X5 — Flights row disclosure

| | |
|---|---|
| **Measured today** | 36–50 rows, no day separators, one 30px "More" text button per row, a 16px icon-only eye as the only route to the panel picture, a two-hop "View unresolved prefixes" link, phone cards missing airline name and thumbnail, "ORY → JFK Departing" with no separator, raw ISO beside a local clock time with no tz hint. |
| **Target** | Zero visible per-row text buttons. Day separators present. Phone cards carry airline name + thumbnail. One hop to name an airline. A **labelled** picture control replaces the 16px icon-only eye. |

**Contract.**

- **The toggle stays a real `<button>`.** A `<tr>` is not focusable and cannot carry `aria-expanded` — do not move the state onto the row element. The button becomes **icon-only**, reusing `.copy-btn`'s pattern verbatim: a 22×22 visual box, a `::before { inset: -11px }` synthesizing a real 44×44 hit area, a 14px chevron glyph.
  - **This does move `.row-toggle` in the touch-target register** — from the *traded-away* category (30px/36px base button geometry) to the *relocated* category (a 22px visual box with a synthesized 44×44 hit area). `references/control-density.md` currently **rejects** the icon-only pattern for this exact control, on the stated ground that "unlike `.copy-btn`, the row-toggle carries visible text". Removing the visible text dissolves that ground, so the change is defensible — but it is a **reversal of a recorded rejection** and must be marked SUPERSEDED in place with that reasoning (§4). `.row-toggle` has no CSS rule today (it is markup-only, `history_page.py:931`), so this creates a new rule block rather than editing one.

## 3. New Surfaces

Three things in this phase do not exist yet and need real specification.

### 3.1 The bottom tab bar (X9, LOCKED by D-10)

**D-10 is locked and non-discretionary.** The mechanism is a bottom tab bar. **Do not implement an overlay drawer** — `references/mobile-navigation.md` carries a locked *rejected* verdict on the absolute-positioned overlay, established by real-device testing during 06.6.1-06 (it could only overlay, never push, which is why the shipped dropdown is in-flow via `flex-basis: 100%`). If a plan finds bottom tabs unworkable, it must **say so and stop**, not fall back to the rejected pattern.

| | |
|---|---|
| **Measured today** | Opening the hamburger pushes the page ~**420px** down — a near-full-screen shove on a 390×844 viewport, with no overlay and no animation. |
| **Target** | Reaching any everyday destination costs **zero page shift**. The hamburger's remaining push is ≤ **220px**. |

**Tabs — five cells, in order:**

| Cell | Destination | Notes |
|---|---|---|
| Home | `/` | |
| Display | `/display` | |
| Flights | `/flights` | |
| Airlines | `/airlines` | |
| More | native `<details>` → Health (`/health`), Device (`/device`) | The Advanced group |

The four everyday tabs are exactly `NAV_GROUPS`' unlabelled everyday group; "More" is exactly its "Advanced" group. **Both renderings must keep consuming the one shared `_nav_links()` iteration** so the tab bar, the sidebar and the dropdown can never disagree on the tab set — this is the existing structural guarantee in `references/mobile-navigation.md` and the tab bar joins it as a third consumer rather than hand-listing routes.

**Geometry.**

- Visible **only** below 960px: `@media (max-width: 959.98px)` — the same fractional boundary the sub-960px button rule uses, avoiding a one-device-pixel gap. The desktop sidebar is untouched.
- `position: fixed; left: 0; right: 0; bottom: 0;`
- Height **56px** of tab row, plus `padding-bottom: env(safe-area-inset-bottom, 0px)`.
- Surface `--color-secondary` (the nav surface, matching `.mobile-nav`), a `1px solid var(--color-border)` **top** hairline, and `box-shadow: var(--shadow-card-hover)` at rest — a **floating-overlay exception** to the hairline-at-rest card contract, the same exception `.mobile-nav`, `.lightbox` and `.dirty-bar` already carry, for the same reason.
- **No border radius.** `--radius-card` (10px) is for floating elements that do not touch the viewport edge; this bar is edge-anchored, so square corners are correct. Getting this pairing backwards is the easiest mistake here (`SKILL.md` says so directly).
- Each cell: `flex: 1 1 0`. At 390px that is **78 × 56px** per cell.

**Content and type.**

Each tab is the tab's existing nav icon (20px, the `.icon` default, `stroke="currentColor"`) stacked above an **11px `--font-ui` regular** label, `gap: var(--space-xs)`. Sentence case. **Not the label voice** — no uppercase, no `0.06em` tracking; a nav destination is a destination, not a label. The 11px joins the existing sub-scale exception tier beside `.sparkline-axis-label` (10px) and `.cell-secondary` (11–12px); it is not a fifth content-type role. Icons here are consistent with the app's stated glyph rule — glyphs are a tile/control affordance, and nav links already carry them.

**Active state — reuse, do not reinvent.**

The active tab wears the app's **one** active-signal idiom verbatim: `color-mix(in srgb, var(--color-accent) 12%, transparent)` background + accent text + `--weight-semibold`. The pill is scoped to a wrapper around the icon+label stack (`inset: 4px 8px`, `border-radius: var(--radius-control)`), not full-bleed to the cell edge. The inactive hover is the register's **4.5%** text wash and must be `:not(.tab-bar__link--active)`-scoped — an unscoped hover at equal specificity, later in source, would erase the active tint the instant the pointer crossed it (`references/control-density.md` names this exact failure). The active tab also carries `aria-current="page"`.

**"More" — a native `<details>`, zero JavaScript.**

`<details class="tab-bar__more">` whose `<summary>` is styled identically to the four tab links, and whose panel opens **upward** (`position: absolute; bottom: 100%; right: 0;`) listing Health and Device at `.mobile-nav__link`'s own 44px / 16px geometry on `--color-secondary` with the same overlay shadow.

- **This absolute positioning does not reopen the rejected-overlay verdict.** That verdict is specifically about the *primary* nav's push-vs-overlay behaviour on a component that must be able to push content. This is a two-item secondary sheet anchored to an already-fixed bar. Record the distinction in `references/mobile-navigation.md` (§4) so a future reader does not read it as a reversal.

- Open state resets naturally on navigation (a page load), so no close-on-navigate logic is needed.

**Page clearance — the last card must not sit under the bar.**

Below 960px, `.page-content` gains:

```
padding-bottom: calc(var(--space-2xl) + 56px + env(safe-area-inset-bottom, 0px));
```

and, when `.dirty-ready` is present (T7), the save bar's own measured height is added on top.

**Stacking with the pinned save bar — they interact, so the order is stated.**

Display and Device both pin `.dirty-bar` on phones today at `bottom: calc(var(--space-md) + env(safe-area-inset-bottom, 0px)); z-index: 20` — i.e. **exactly where the tab bar now lands**. Two rules, in this order:

1. **Geometric separation first.** Below 960px the save bar's `bottom` becomes `calc(var(--space-md) + 56px + env(safe-area-inset-bottom, 0px))` so it floats **above** the tab bar. In the normal case the two never overlap at all.
2. **Stacking order, as belt-and-braces:** `.dirty-bar` `z-index: 30` (both breakpoints — this is also T7's desktop fix) **above** `.tab-bar` `z-index: 20`.

**The save bar wins if they ever do overlap, and the reason is stated:** the save bar is the active task, the tab bar is ambient chrome, and a blocked save is the P0 defect (B1/CFG-25) this entire phase exists to fix. A wrapped, taller save bar covering a tab is acceptable; a tab bar covering the Save button is not. This satisfies D-10's "must not cover the pinned save bar" literally.

**Acceptance (Playwright, D-02):** at 390×844 on Display with an unsaved edit, both bars are simultaneously visible, the Save button's bounding box does not intersect the tab bar's, and both are hit-testable at their centre points.

**Button geometry — a named, scoped exception, and a floor *gain*:**

```

  height: 44px;
  width: 100%;
  border-radius: var(--radius-control);   /* 8px, matching the field */
  font-size: var(--font-body-size);
}
```

This diverges from the base 30px / 36px register. Three justifications, all required in the plan:
1. It **restores** the WCAG 2.5.5 (AAA) 44px floor rather than trading it — a floor gain, so it joins the touch-target register's **kept / met-directly** category, not the traded-away list.
2. Matching the field's height and radius satisfies C4's new composition rule (§4) for a field-plus-action pair that reads as one object.
3. It is the app's only pre-auth surface and has no density argument to trade against — the same reasoning that restored `.mobile-nav__link`'s own 44px floor in quick task 260902-qkm.

**Error state — reuse `.field-error`, do not invent one.**

`.field-error` already exists (`style.css:362`, added 19-07-PLAN.md for A-25): `color: var(--color-status-error); margin: var(--space-xs) 0 0;`, always composed with `.text-label`. Its `margin-top` exists precisely to attach a message to the control above it.

```html
<label for="password">Password</label>
<input type="password" id="password" name="password"
       autocomplete="current-password" autofocus required
       aria-invalid="true" aria-describedby="login-error">
<p id="login-error" class="field-error text-label" role="alert">
  That password is not right. Check it and try again.
</p>
```

- The message moves **under the field**, not to the top of the card where it sits today.
- `aria-invalid="true"` and `aria-describedby` are present **only** when an error is rendered — never `aria-invalid="false"`.
- `role="alert"` is kept (it is the existing, correct behaviour).
- **One error voice on this card:** the lockout message uses the same `.field-error text-label` treatment. Only the copy differs.

### 3.3 "Held" vs "late" — the frame-state contract (X2 / D-03)

**This is the one contract where getting the colour wrong produces a nightly false alarm.** Today `next_wake_at_iso()` has zero quiet-hours awareness while `poll_loop.py:1019-1027` holds the device until morning, so every night the strip reads "Expected since 23:0x", the Frame tile escalates to warn then error, and the Health nav notification dot lights — for a device that is doing exactly what it was told.

**Three states. One vocabulary. One computed source (D-03).**

| State | Condition | Dot | Headline | Text colour |
|---|---|---|---|---|
| **Due** | `now < next_wake` **or** `now < next_wake + 2 × effective_interval` | `.dot--ok` | `Next update ≈ 17:54` | `--color-text` |
| **Held** | quiet hours active (or the screen is off) as evaluated **at `last_checkin_ts`** | **`.dot--off`** | `Next wake around 07:05 · quiet hours` | `--color-text` |
| **Late** | `now ≥ next_wake + 2 × effective_interval` | `.dot--warn` | `Expected since 17:54` | `--color-text` |

**Six binding rules:**

1. **The held state uses `.dot--off`, never `.dot--warn`.** `.dot--off` was added in Phase 21 (D-03) and is defined in the design system as *"a neutral, everyday state, never a problem"* — reusing a muted-grey `color-mix(in srgb, var(--color-text) 30%, transparent)` rather than a status colour. Applying it to a deliberately-sleeping frame is exactly its stated meaning. **Do not add a fifth dot and do not introduce a new colour for "held".**

2. **No status colour is used as text, in any of the three states.** `.status-card__headline--warn` is `--color-text` today because the 20-04 gate measured `--color-status-warn` as text on `--color-dominant` at **3.19:1** in light mode — below `WCAG_AA_NORMAL_TEXT` (4.5) — and the choice was dropped rather than the threshold weakened. The warn signal is carried by **the wording plus the leading dot**. That precedent is binding here: the Late state's distinctness comes from "Expected since" versus "Next update ≈", not from red or amber text.

3. **The grace window is invisible.** Between `next_wake` and `next_wake + 2 × interval` the signal stays in the **Due** state showing the **same** "Next update ≈ HH:MM" copy — there is no intermediate "slightly late" treatment, no colour shift, no third dot. One threshold, one flip. A user must never see a state that means "probably fine, but we're nervous".

4. **The held state cannot escalate.** Lateness is tested against the **held-aware** next wake, so a device inside an 8-hour quiet window is only Late at `07:05 + 2 × interval`. Elapsed time alone can never turn Held into Late.

5. **Disagreement is impossible by construction.** The Frame strip headline, Home's Frame status row, Health's Frame tile, the Health nav notification dot and every settings delay caption read **one** computed result (D-03). The `22-RESEARCH.md` Pattern 4 shape — a widened return carrying `(next_wake_iso, effective_interval_s, hold_reason)` — is the recommended mechanism precisely because it gives every consumer the same three facts without re-deriving any of them. The quiet-hours decision is evaluated **at `last_checkin_ts`**, not at render time, because that is the moment the device's own `sleep_s` was actually decided.

6. **The nightly regression test is the acceptance criterion.** With quiet hours 23:00–07:00, a last check-in at 22:58 and the clock at 02:00 Europe/Paris:
   - the strip renders the **Held** copy with `.dot--off`;
   - Home's Frame tile renders the **same** `HH:MM` and the same state;
   - the Health nav notification dot is **unlit**;
   - the rendered HTML contains **zero** occurrences of `.dot--warn`, `.dot--error`, `.stat-tile--warn`, `.status-card__headline--warn` or the string `Expected since` / `Attendu depuis`.

   `22-CONTEXT.md`'s `<specifics>` notes this night-time behaviour was **inferred from code, never observed live** — so pinning it with a unit test is part of the fix, not an extra.

**The delay sentence (D-04) is derived from the same result**, in the same three branches (see the Copywriting table). One computed sentence replaces all four of today's wordings.

**One control per setting (D-04):** the Frame strip owns Screen on/off and Quiet hours on/off; the settings form keeps only the quiet-hours **schedule** (enable-by-schedule semantics, start, end, presets). Pressing a strip switch with unsaved form edits must no longer fire the browser's "leave page?" dialog for a change the strip is itself about to apply.

> **Pitfall 1 (D-12.1) is a visual-contract hazard too, not only a data one.** Once the on/off checkboxes leave the form, `handle_post()`'s absent→`False` resolution would **switch the screen and quiet hours off on every settings save**. The user-visible symptom is the frame going dark after changing a theme. Both fields must resolve **absent → leave unchanged**, `screens.GROUP_DISPLAY` must leave **both** `everyday_groups` **and** `scope_groups()`'s hand-maintained `SCOPE_ALL` tuple (D-12.2), and a harness check must pin that saving an unrelated field alters neither flag.
