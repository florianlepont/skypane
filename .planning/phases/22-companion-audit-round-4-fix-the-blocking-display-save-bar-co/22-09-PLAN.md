<objective>
Make the Flights table readable. Thirty-six to fifty rows run together with no day
separators; every row carries its own 30 px "More" text button, so the scan path
is fifty buttons wide; the only route to the panel picture is a 16 px icon-only
eye with no name beside it; "View unresolved prefixes" leads to a list Health
itself calls read-only, so naming an airline takes two hops; the phone cards drop
the airline name and the thumbnail entirely; and "ORY → JFK Departing" runs
together with no separator. Alongside, the filter Clear drops onto its own line at
390 px — a regression of Phase 18's A-18.

Purpose: this is the everyday page a household member uses most after Home, and
every defect here is a scan-path defect: too many controls, too little grouping,
and the one control that matters hidden at 16 px.
Output: a table with day separators, one chevron per row, a labelled picture
control where the picture's siblings already live, and a one-line filter bar on a
phone.
</objective>

<decisions_covered>
D-07's X5 and B11 rows, UI-SPEC §2's X5 and B11 contracts in full, and the UI
checker's own follow-up notes: the day-separator format is the output of the
Paris-day formatter and not a licence to call `strftime` directly, and the row
toggle's accessible name must advertise the picture reachable inside. Sticky day
headers are D7, Phase 23 — the separators here are NOT sticky, and T4 removes the
app's one broken sticky claim rather than adding a second.
</decisions_covered>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored callsign / prefix → a generated link URL | the one-hop resolve link interpolates a value that came from ADS-B traffic |
| stored timestamp → day-separator label | a stored `ts` string is parsed to choose a group |
| delegated row click → the toggle button | a document-level click handler now acts on rows |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-30 | Tampering | the one-hop resolve link's query parameter | mitigate | the prefix is interpolated through `escape_html()` at its site and URL-quoted for the query string, the same treatment the existing two-hop link already applies; the resolve view validates the prefix on arrival, unchanged |
| T-22-31 | Denial of Service | an unparseable stored `ts` reaching the day grouping | mitigate | the grouping reuses `layout.parse_iso()` / `local_clock_text()`, both of which carry never-raise contracts; a row that cannot be dated falls into the existing ungrouped path rather than raising |
| T-22-32 | Tampering | the delegated row click acting on an interactive child | mitigate | the handler returns early for links, buttons, inputs, labels and summaries, so it can never swallow or redirect a real control's activation. Pinned by a browser assertion |
| T-22-33 | Information Disclosure | the raw ISO moving behind a copy control | accept | the value is unchanged and already public; only its placement moves, and the copy control is the existing audited one |
| T-22-SC | Tampering | npm/pip/cargo installs | n/a | this plan installs zero packages in any ecosystem |
</threat_model>
