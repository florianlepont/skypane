<objective>
Build the single next-wake truth. `server/wake.py`'s `next_wake_at_iso()` today
reproduces only half of what the device actually does: it applies the screen-off
sleep but has no quiet-hours awareness at all, while `poll_loop.py` holds the
device until morning. That is the sole root cause of X2's nightly false alarm —
every night the strip reads "Expected since 23:0x" for a frame doing exactly
what it was told. Extend the computation, add the view-free state resolution and
the one delay sentence every consumer will read, and pin the nightly regression.

Purpose: waves 3 and 4 rewire the strip, the tiles, Home and the settings
captions to one result. That result has to exist, be correct, and be tested
first — CFG-26's "disagreement is impossible by construction" is a property of
having one implementation, not of three careful ones.
Output: a quiet-hours-aware next wake, a `(next_wake_iso, effective_interval_s,
hold_reason)` result, three copy branches in EN and FR, and the quiet-hours-active
fixtures the phase's validation contract lists as a Wave 0 gap.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| on-disk device config → wake arithmetic | `quiet_hours_*` and `wake_interval_s` are operator-supplied values read on every render |
| device_health `last_checkin_ts` → parsing | a stored timestamp string, written by the poll path, parsed here |
| computed state → user-facing alarm | the state drives the Health nav notification dot |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-06 | Denial of Service | a malformed or hostile `last_checkin_ts` reaching `next_wake_at_iso()` | mitigate | the existing never-raise contract is preserved verbatim: `TypeError`/`ValueError` from `fromisoformat` return None, and `quiet_hours_status()` carries its own documented never-raise contract. Pinned by the unparseable-input assertion in Task 1 |
| T-22-07 | Tampering | a crafted `quiet_hours_enabled` value | accept | `quiet_hours_status()` already requires the value to be literally `True`; any other value resolves to (None, None), i.e. no hold. No new parsing is introduced |
| T-22-08 | Spoofing | a false "all is well" state hiding a genuinely dead frame | mitigate | the held state is bounded by the window's own end: lateness is measured against the held-aware next wake, so a frame that misses its 07:05 wake is late at 07:05 + 2 x interval. Pinned by an assertion that held becomes late after the window ends |
| T-22-SC | Tampering | npm/pip/cargo installs | n/a | this plan installs zero packages in any ecosystem |
