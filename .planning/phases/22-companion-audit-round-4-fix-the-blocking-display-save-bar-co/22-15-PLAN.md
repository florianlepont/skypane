<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → every state-changing POST | repeat submissions reach handlers that assume one call |
| a failing fetch → the refresh loop | an unreachable endpoint drives client-side retry behaviour |
| CSS specificity → the destructive action | the accent fill is the app's signal for the page's main action |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-55 | Tampering | duplicate POSTs from a double click on Save, a rule add or delete, or Disconnect | mitigate | one shared disable-on-submit guard covers every form; the server's own handlers are unchanged and remain authoritative, so a scripts-blocked client is no worse off than today |
| T-22-56 | Denial of Service | the retry loop hammering a failing endpoint | mitigate | exponential backoff with a stated ceiling plus an in-flight guard, so a failing server sees a decreasing rate rather than a constant one |
| T-22-57 | Spoofing | a destructive control wearing the primary accent | mitigate | T2 restores the grey secondary treatment by equal specificity plus source order, and the confirm dialog on Disconnect is unchanged |
| T-22-58 | Information Disclosure | the reconnecting pill exposing endpoint state | accept | it reveals only that the browser's own refresh request failed — information the user already has from a page that stopped updating |
| T-22-59 | Elevation of Privilege | a new same-origin script | mitigate | `script-src 'self'` unchanged, no inline script, no nonce, no vendored library; pinned by an acceptance grep |
| T-22-SC | Tampering | npm/pip/cargo installs | n/a | this plan installs zero packages in any ecosystem |
</threat_model>
