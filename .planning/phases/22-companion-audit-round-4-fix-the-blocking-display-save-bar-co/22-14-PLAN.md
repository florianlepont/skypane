<objective>
On a phone, opening the hamburger shoves the page about 420 px down — a near
full-screen push on a 390x844 viewport, with no overlay and no animation. Replace
the destination menu with a bottom tab bar and let the dropdown shrink to what it
is actually for. Alongside it, three nav defects the audit measured: the state
reminder wraps mid-phrase and claims on Home to be a link to Home; the dropdown's
close path can leave `hidden` and `aria-expanded` contradicting each other; and
two `max-height` values silently override one another.

Purpose: X9's mechanism is LOCKED to a bottom tab bar by D-10. The audit's own fix
column also offered "an overlay drawer with backdrop" — that was a mistake in the
audit: `references/mobile-navigation.md` carries a locked REJECTED verdict on the
absolute-positioned overlay, established by real-device testing during 06.6.1-06,
and the shipped dropdown is in-flow precisely because an overlay could only cover
content, never push it. Bottom tabs were chosen specifically so that verdict is
never reopened.
Output: five tabs, a dropdown that holds preferences instead of destinations, a
reminder that reads on one line and tells the truth, and a deterministic close.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| nav rendering → route reachability | a nav that hides a destination is presentation, never access control |
| fixed overlays → the save control | two fixed elements compete for the same corner of a phone viewport |
| dropdown state → assistive technology | `hidden` and `aria-expanded` must never contradict |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-51 | Denial of Service | the tab bar covering the Save button on a phone | mitigate | geometric separation first (the save bar's offset clears the tab bar's height), then an explicit stacking order favouring the save bar, then a browser assertion that the boxes do not intersect and both are hit-testable |
| T-22-52 | Elevation of Privilege | destinations moving between nav renderings | accept | nav visibility has always been presentation-only in this app; Health and Device remain session-gated on the server regardless of which rendering links to them |
| T-22-53 | Spoofing | the More summary or a tab claiming the wrong current page | mitigate | the active state derives from the same active-route argument all three renderings receive, and `aria-current` is asserted for both the tab case and the Advanced-page case |
| T-22-54 | Tampering | the dropdown's state desynchronising from its markup | mitigate | `aria-expanded` stays the single source of truth; the transition listener filters on its own target and property and the no-transition path sets the hidden attribute synchronously, both pinned by the browser check plan 22-01 established |
| T-22-SC | Tampering | npm/pip/cargo installs | n/a | this plan installs zero packages in any ecosystem |
