<objective>
Stop the companion telling the user the wrong time. The battery heading reads
"15:49 UTC (1m ago)" directly under a tile saying "17:49 (1m ago)", because
`_battery_reading_parts()` calls `strftime("%H:%M")` on an unconverted datetime
and appends a literal " UTC" — and that value then feeds every sparkline point's
tooltip, every aria-label, every `data-when` attribute and the hover swap in
`battery-trend.js`. The daily buckets have the same disease one level down: they
group by SQLite's `date()`, which is UTC-only, so a reading at 01:30 Paris time
lands on the previous day for half the year.

Purpose: CFG-28 says every visible time is Paris local time. That is one rule with
one implementation — `layout.local_clock_text()` — and this plan makes every
battery-side caller obey it, including the one that cannot be fixed in SQL at all.
Output: a Health page whose times agree with each other, day buckets that are
Paris days across a DST transition, and a corrected docstring so the next reader
does not copy the same mistake.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caddy access log → `device_health.ts` | `tail_caddy_battery_log()` stores whatever string the log entry carried; the column is TEXT NOT NULL and otherwise unvalidated |
| stored `ts` → Python bucketing | parsing moves from SQLite to Python, so the failure mode moves with it |
| server-rendered `data-when` → client swap | the browser now renders text it is given, with no client-side formatting |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-20 | Denial of Service | a hostile or malformed `ts` reaching the new Python bucketing | mitigate | each row's parse is guarded and a failure skips that row, reproducing exactly what `date(ts) IS NOT NULL` provided; pinned by an unparseable-row fixture |
| T-22-21 | Information Disclosure | `data-when` and `title` attributes carrying timestamps | accept | the values are already-public device timestamps rendered through `escape_html()` at their interpolation site, as every other attribute on this page is |
| T-22-22 | Tampering | client-side reformatting reintroducing a wrong time | mitigate | `battery-trend.js` is pinned by a source scan to contain no date parsing or formatting; the one formatter stays server-side |
| T-22-23 | Repudiation | day buckets silently wrong for half the year | mitigate | fixtures cover both DST transitions, not one; a SQL-side "fix" is explicitly forbidden and greppable |
| T-22-SC | Tampering | npm/pip/cargo installs | n/a | this plan installs zero packages in any ecosystem |
</threat_model>
