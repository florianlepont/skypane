<objective>
Close A-25 (D-07): stop throwing away everything a user typed when one field is
wrong, and report the problem under the control that caused it.

Purpose: today any validation failure redirects with one generic flash and an
empty form. Clearing a single quiet-hours time kills the whole save. That is the
highest-severity open Settings finding in the audit, and it makes the page
actively hostile to the second household member the redesign was for.
Output: `handle_post()` and `render()` widened (never rewritten) to carry an
`errors` dict and the submitted values, a 200-render failure branch in
`_handle_settings_post()` mirroring the login form's existing precedent, and a
`.field-error` style using the existing error token.
</objective>

THE COMPATIBILITY CONSTRAINT THAT SHAPES THIS WHOLE PLAN (19-RESEARCH.md
Pitfall 6, verified by grep): `config_page.handle_post(form, ctx)` is called from
75 places in `companion/test_config_page.py`, every one expecting a single STRING
return (the flash key). `config_page.render(ctx, scope=SCOPE_ALL)` is called from
46 places. Therefore:
  - add `errors=None` as a fully-defaulted LAST keyword parameter to handle_post
  - add `errors=None, submitted=None` as fully-defaulted LAST keyword parameters
    to render
  - NEVER change either return type. A diff that returns a tuple from
    handle_post is the signal this plan was abandoned.

The 200-on-failure precedent to mirror — `companion/app.py`:

          error="Incorrect password. Try again.", next_route=next_route))

Validation gates inside `handle_post()` — `companion/pages/config_page.py:1888-2182`.
Read its full docstring: four properties are documented as load-bearing
(checkbox absent-means-False vs radio absent-means-unchanged; quiet hours
persisting while disabled; ALL-OR-NOTHING rejection across all fields;
`wake_interval_s`'s explicit int conversion). None of them may change.
Failure returns of `FLASH_SAVE_FAILED` exist for: theme, calendar signal invalid,
calendar_theme_id, theme_arriving, tracked_runway, theme_arriving_enabled,
led_enabled, quiet_hours_enabled, wake_interval_s int(), display_enabled, and the
`except (ValueError, OSError)` around `save_device_config()`.

Which failures are REAL user errors (need a field message AND repopulation):
  `wake_interval_s`  — non-numeric or out of [60, 3600]
  `quiet_hours_start` / `quiet_hours_end` — empty or not HH:MM
  `calendar_url`     — over 2048 chars / contradictory / malformed
Which are hostile-request shapes (need a field message, no new copy):
  theme / theme_arriving / calendar_theme_id / tracked_runway membership,
  the three checkbox exact-value gates.
