## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query string -> render decisions | `?edit=1` is fully attacker-controllable and now decides what renders |

| lightbox forms -> `POST /illustrations/*`, `POST /airlines/manual-resolutions/*/delete` | the real authorisation boundary for artwork replace and manual-resolution delete |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-30 | Elevation of Privilege (mistaking a UI flag for a control) | `ctx["edit_mode"]` | mitigate | `edit_mode` is documented in `companion/pages/__init__.py` as presentation-only and is NEVER consulted by any POST handler. The POST routes those forms target (`ILLUSTRATION_IMAGE_ROUTE_PREFIX`, `MANUAL_DELETE_ROUTE_PREFIX`) keep their existing `require_session()` gates in `do_POST()`, so hiding the form changes what is offered, not what is permitted. Task 3's action states this explicitly so no future reader treats `?edit=1` as authorisation |
| T-19-31 | Tampering (query-flag injection) | the `?edit=` parameter | mitigate | resolved by an exact `== "1"` comparison, the same membership-test-before-use discipline `layout.ui_theme_from_cookie()` and `submitted_scope()` already apply; pinned by the `?edit=2`/`?edit=true`/`?edit=` checks |
| T-19-08 | Tampering (XSS) | `GAP_STRIP_HEADING`, `GAP_STRIP_BODY`, the reworded back link and stale body | mitigate | all four are module constants escaped at their single interpolation point; `gap_cards_html` and `overflow_html` are already-safe markup interpolated verbatim per this module's documented no-double-escape rule, and the values inside them already passed `escape_html()` in `_gap_card_html()` |
| T-19-32 | Denial of Service (accidental destructive action) | the delete form in the everyday lightbox | mitigate | D-22 removes it from the everyday view entirely, so a household member browsing artwork can no longer reach a manual-resolution delete by accident. This is a usability-shaped safety control, not an access control — stated as such so it is not over-claimed |
| T-19-SC | Tampering (supply chain) | package-manager installs | n/a | zero packages installed |
