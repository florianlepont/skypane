<objective>
Measured on the developer's screen recording: after dragging the end handle the
fields read `08:00` and `18:00`, both handles sit at 8 and 18 — and the arc still
draws 23:00→07:00 while the caption still reads `23:00 → 07:00 · 8 h`.

**Do not re-derive the cause; it is diagnosed.** `companion/static/value-controls.js`
models ONE value per wrapper, and `paint()`'s last act writes a per-handle CSS
custom property:

    wrapper.style.setProperty(FRACTION_PROPERTY, String((value - bounds.min) / span));

An arc and a span sentence are functions of **both** values. Nothing in the script
models the pair, so there is no element for them to be a function of. The arc is
server-rendered SVG — which is **correct**, and is what keeps the no-JS floor — and
is simply never repainted client-side.

This plan puts the pair into the model, keeps the server's arc authoritative for the
saved value, and closes the hole in the instrumentation that let three passing
checks ship a lying picture.
</objective>
