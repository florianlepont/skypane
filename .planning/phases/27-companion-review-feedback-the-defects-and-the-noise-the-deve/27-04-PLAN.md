<objective>
The developer's words: *"je veux aucun bouton ça sert à rien. Si tu veux une
confirmation visuelle, un 'sauvegarde…' et 'sauvegardé' suffit."*

This is correction 1, the developer's first priority, and the most dangerous change
in this phase against the locked no-JS floor. **27-03 already landed the floor as a
property of the construction** — the native submit is emitted unconditionally and
its save-to-disk proof is green. This plan can therefore remove the save bar without
the floor ever being made of the thing being removed.

**The auto-save model is not invented here; it already ships on this very page.**
`companion/static/quick-switch.js` is an auto-save end to end: press → optimistic
apply → `fetch` POST → **204 and nothing else confirms** → otherwise `rollBack()` +
`announceFailure()`. Its server half is already generic. Its failure vocabulary is
already translated. Correction 1 is therefore not "build auto-save" — it is **extend
the save model the page already has to the form that did not have it, and delete the
bar that existed because it did not.**

And the driver is not a new file. `dirty-state.js` already owns the delegated
`change`/`input` listeners on the settings form — the exact hook auto-save needs —
and already owns the region that announces save state. **The file being retired as a
bar becomes the file that drives the save.** No new file, no new route, no pin move.
</objective>
