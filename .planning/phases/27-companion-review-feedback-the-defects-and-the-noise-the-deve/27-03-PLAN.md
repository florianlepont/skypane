<objective>
The developer's words: *"je veux aucun bouton ça sert à rien."* A large accented
"Enregistrer les réglages" greets every fresh page load, and the reason is exactly
traceable: `style.css`'s rule is

    .dirty-ready.dirty-shown [data-static-save-fallback] { display: none; }

Two classes that the script must have *decided* to add. Until it decides, the
fallback is visible — so the no-JS fallback is what a scripted visitor sees first.

27-04 retires the save bar entirely and replaces it with auto-save. That is the most
dangerous change in this phase against D-09, the locked no-JS floor: **removing the
save button from the scripted path must not remove the only save path from the
unscripted one.**

So this plan goes first, and it does one thing: it makes the floor a property of the
**construction** rather than of a visibility rule, and proves it by saving to disk.
After this plan, the submit is emitted unconditionally on every render and is hidden
by the plain `.js` gate — the shape 06.6.4.1-01 originally landed, before the
narrowing. Then 27-04 can remove the bar knowing the floor underneath it is not
made of the thing being removed.
</objective>
