<objective>
Paginate Vols. The list renders 15 flights, then a real "Afficher plus" / "Show more" link that works with scripts blocked, using a server-side query-parameter re-render. The phone summary card's callsign/timestamp line becomes a stable two-column grid so it stops wrapping awkwardly at 390 px.

Purpose: the 2026-09-17 audit's P1 — the realistic 36-flight fixture produces a 6 710 px page on a phone, and "l'horodatage et l'indicatif se disputent aussi la même ligne dans certaines cartes, ce qui provoque des retours visuellement maladroits."

**Mechanism decision and its ground (CONTEXT.md leaves this to the planner; this is the recorded call).** A server-side `?limit=` query-parameter re-render, NOT a native `<details>` reveal. The deciding fact is `companion/static/freshness.js`'s own swap loop: it re-fetches `window.location.href`, the browser's CURRENT url including its query string, and replaces `ul.history-cards` and `.data-table-wrap` wholesale every 45 seconds. A query-parameter reveal therefore survives every refresh with zero script change, because the reveal state IS the URL. A `<details open>` reveal would be silently collapsed by the very next background swap — the reader would open "Show more", look away for 45 seconds, and find it closed with no error and no explanation, which reads as data loss and is worse than not shipping the feature. Keeping it open would need a new stateful-region mechanism in `freshness.js` that this file has no precedent for.

**The trade-off this buys, stated rather than hidden.** `list-filter.js` filters client-side over the rows currently in the DOM. With a limit in force, a search for a flight outside the loaded page returns "no matching flights" even though the row exists in the database. This is a real, disclosable product trade-off, not a bug — it is named in the filter's own empty-state copy by Task 1, and the filter's count reads the loaded subset honestly because `_filter_bar_html()` is already fed `len(formatted_rows)`.

Output: a Vols page whose first screen is the filter plus 15 flights, a no-JS reveal that survives the refresh loop, a stable phone summary grid, and a clamped, never-raising limit parser.
</objective>

| T-29-03-03 | Tampering | the Show-more anchor's href | low | mitigate | The href is built server-side from `layout.FLIGHTS_ROUTE`, the module's own param constant and an int computed as `min(shown + FLIGHTS_PAGE_SIZE, HISTORY_ROW_LIMIT)` — never from the raw query string, so a crafted value cannot be reflected into the link.
