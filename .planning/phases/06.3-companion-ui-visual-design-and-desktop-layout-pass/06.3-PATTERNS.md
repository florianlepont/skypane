## Pattern Assignments

### `companion/layout.py` — add `sidebar_nav()` (component, request-response)

**Analog:** `_nav_html()`, same file, lines 72-80

**Core pattern to copy** (lines 72-80):
```python
def _nav_html(active):
    links = []
    for route, label in NAV_TABS:
        slug = route.lstrip("/")
        css_class = "nav-tab nav-tab--active" if slug == active else "nav-tab"
        links.append(
            '<a class="%s" href="%s">%s</a>'
            % (css_class, escape_html(route), escape_html(label)))
    return "\n".join(links)
```
`sidebar_nav()` should follow the exact same loop shape, iterate the same `NAV_TABS` constant (line 25-31), and escape `route`/`label` the same way — only the wrapping element (`<aside>`/`<nav aria-label="Primary navigation">` vertical list vs. flat `<a>` row) and CSS class names differ. UI-SPEC's Component Patterns table requires `aria-label="Primary navigation"` on the `<nav>` and reuse of `NAV_TABS` — no duplicated route list. RESEARCH.md's Anti-Patterns section recommends extracting a shared `_nav_links(active)` helper returning `(css_class, route, label)` tuples so both `_nav_html()` and `sidebar_nav()` consume the same per-link logic — low-cost, recommended but not blocking.

**Escaping convention (every dynamic string always escaped):** every existing builder in this file (`_nav_html`, `_theme_form_html`, `status_dot`, `empty_state`, `data_table`) calls `escape_html()` on every interpolated value. `sidebar_nav()` and `stat_tile()` must do the same for `caption`/`label`.

### `companion/layout.py` — add `stat_tile()` (component, request-response)

**Analog:** `_section()` in `companion/pages/health_page.py`, lines 338-344

**Core pattern to copy** (lines 338-344):
```python
def _section(name, content_html):
    return (
        '<section class="page-section">'
        '<h2 class="text-heading">%s</h2>'
        "%s"
        "</section>"
    ) % (escape_html(name), content_html)
```
**Critical convention:** `content_html` is interpolated **unescaped** — it is always pre-built, already-escaped output from `layout.status_dot()`, `layout.data_table()`, or hand-built `<p>` strings. `stat_tile()` must replicate this exactly: escape `caption` (own parameter), never touch `content_html`. RESEARCH.md's Pattern 2 gives the target shape:
```python
_STAT_TILE_BORDER_CLASSES = {
    "ok": "stat-tile--ok",
    "warn": "stat-tile--warn",
    "error": "stat-tile--error",
}

def stat_tile(caption, content_html, status=None):
    css_class = "stat-tile " + _STAT_TILE_BORDER_CLASSES.get(status, "stat-tile--accent")
    return (
        '<div class="%s">'
        '<p class="text-label stat-tile__caption">%s</p>'
        "%s"
        "</div>"
    ) % (css_class, escape_html(caption), content_html)
```
**Anti-pattern warning (from RESEARCH.md):** re-escaping `content_html` would double-encode `status_dot()`'s intentionally-raw `<span>` markup, printing visible `&lt;span...&gt;` text — the exact bug CONTEXT.md's canonical refs flag as the risk to avoid. This mirrors the same reason `history_page.py` couldn't reuse `layout.data_table()` directly (see below).

### `companion/layout.py` — extend `page_shell()` (controller/shell, request-response)

**Analog:** same function, current implementation, lines 97-138 (the site to extend, not replace)

**Current structure to extend:**
```python
def page_shell(title, active, body, ui_theme="auto", flash=None, banner=None):
    ...
    return (
        "<!DOCTYPE html>\n"
        '<html lang="en" data-ui-theme="%s">\n'
        "<head>...</head>\n"
        "<body>\n"
        '<header class="site-header">\n'
        '<span class="site-title">%s</span>\n'
        '<nav class="nav-bar">%s</nav>\n'

        "%s\n%s\n%s\n"         # flash_html, banner_html, body
```

**Implementation approach (RESEARCH.md Pattern 1):** wrap the existing `<header>`+`<main>` pair in a new outer `<div class="dashboard-shell">`, add a second vertical nav block (`sidebar_nav()`) plus a second `_theme_form_html()` call. **Title/nav escaping (unchanged, still applies):** `escape_html(title)`, `escape_html(SITE_TITLE)` — same discipline for any new interpolation site in the extended function.

## Shared Patterns

### Escaping discipline (ASVS V5)
**Source:** `companion/layout.py`'s `escape_html()` (lines 43-55), used consistently by every existing builder in the file
**Apply to:** `sidebar_nav()` and `stat_tile()` — every dynamic string interpolated (captions, labels, route/label pairs) must go through `escape_html()`; `content_html` parameters (already-built markup) must NEVER be re-escaped.
```python
def escape_html(value):
    if value is None:
        return ""
    if not isinstance(value, str):
        value = str(value)
    return html.escape(value, quote=True)
```

### Token-value-only theming (light/dark via CSS custom properties)
**Source:** `companion/static/style.css` lines 23-88 (three-place `:root` / `@media (prefers-color-scheme: dark)` / `html[data-ui-theme="dark"]` pattern)
**Apply to:** every new color addition this phase makes (`--color-border`, revised Dominant/Secondary/Accent hex values) — always declared in all three places, never hardcoded inline in a component rule.

### `.data-table-wrap { overflow-x: auto }` horizontal-scroll fix
**Source:** `companion/static/style.css` lines 322-324, already applied to `.nav-bar` (line 158-163) and `layout.data_table()`'s output
**Apply to:** `history_page.py`'s `_history_table_html()` — this is the exact, already-proven pattern to replicate, not a new pattern to invent.

### `display: none` (never `visibility`/`opacity`) for breakpoint-hidden duplicate nav/theme-form copies
**Source:** RESEARCH.md Pitfall 2 — no existing CSS precedent in this codebase (this is a genuinely new pattern), but the *reason* is grounded in this file's existing, unconditional `:focus-visible` rule (lines 136-142) which must keep working correctly regardless of which nav copy is visible.
**Apply to:** `.dashboard-sidebar` / `.site-header .nav-bar` / `.site-header .theme-form` toggling in the new 960px `@media` block.

### `auto-fit`/`minmax` responsive grid idiom
**Source:** `.gallery-grid`, `companion/static/style.css` lines 363-367
**Apply to:** `.dashboard-grid` (Health, Airlines) — same idiom family, deliberately different function (`auto-fit` not `auto-fill`) and floor (240px not 160px) per UI-SPEC; not a literal copy.
