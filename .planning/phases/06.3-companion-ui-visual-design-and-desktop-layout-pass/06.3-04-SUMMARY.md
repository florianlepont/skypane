# Phase 06.3 Plan 04: Health and Airlines dashboard-grid reframe Summary

**Turned Health and Airlines from flat stacks of bare `<section>` blocks into status-coloured stat-tile dashboards — `health_page.render()` now emits one `.dashboard-grid` of four tiles under an "Overview" heading, `airlines_page.render()` emits one `.dashboard-grid` of two tiles under a "Coverage" heading, with every section builder's markup passed through `layout.stat_tile()` byte-for-byte unchanged.**

## Performance

- **Duration:** ~5 min
- **Tasks:** 2/2
- **Files modified:** 3

## Accomplishments
- `health_page.render()` replaced its four `_section()` calls with four `layout.stat_tile()` calls (Device check-in, ADS-B pipeline, Battery trend, Corroboration), wrapped in one `<div class="dashboard-grid">` under a new `<h2 class="text-heading">Overview</h2>` group heading; `_section()` deleted as dead code
- `airlines_page.render()` replaced its two `<section class="page-section">` wrappers with two `layout.stat_tile()` calls (Unresolved prefixes, Resolution statistics) under a new `<h2 class="text-heading">Coverage</h2>` group heading; the registry tile's border colour now tracks the existing `coverage_status(rows)` verdict, hoisted into `render()` rather than re-derived
- The anomaly banner and source-fault block stay full-width above the Health dashboard grid, not inside a tile
- Every section builder (`_device_section`, `_pipeline_section`, `_battery_section`, `_corroboration_section`, `_registry_section`, `_stats_section`) is untouched — only its call site changed
- `companion/test_status_pages.py` grew from 25 to 28 checks: two new Health checks (dashboard-grid shape; section-builder markup survives the reframe) and one new Airlines check (dashboard-grid shape with `stat-tile--warn` on a non-empty registry)

## Decisions Made
- Deleted `_section()` outright rather than leaving it as unreferenced dead code, since the plan explicitly required its removal and no test references it
- Reused `DEVICE_FRESHNESS_LABEL`/`PIPELINE_FRESHNESS_LABEL` module constants for both the tile captions and their existing status-dot labels, so the two can never drift apart — verified by a grep count of 6 (two definitions + four references)
- Passed `status=None` (not a status string) for the Airlines resolution-statistics tile, since a resolution rate around the low-50s is an expected, documented outcome, not a fault — `None` resolves to the accent-neutral top border per `06.3-UI-SPEC.md`'s Color section

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed an ambiguous test assertion that matched the wrong DOM element**
- **Found during:** Task 2 (Airlines dashboard-grid check)
- **Issue:** The new Airlines Section 2 check initially asserted `rendered.count(">Coverage<") != 1` to verify the "Coverage" group heading appears exactly once. This failed with `got 2`, because `_registry_section()` already calls `layout.status_dot(coverage_status(rows), "Coverage")` for its own status-dot label, which independently renders `<span class="dot-label">Coverage</span>` — also matching the loose `>Coverage<` substring pattern. The check as written could never distinguish the group `<h2>` heading from the pre-existing status-dot label.
- **Fix:** Tightened the assertion to the exact heading markup, `'<h2 class="text-heading">Coverage</h2>'`, which uniquely identifies the group heading and does not match the status-dot label.
- **Files modified:** `companion/test_status_pages.py`
- **Verification:** `companion/test_status_pages.py` exits 0 with 28/28 checks (was 27/28 with this check failing before the fix)
- **Committed in:** `a917a7c` (Task 2 commit)
