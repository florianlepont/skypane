---

## Sampling Rate

- **After every task commit:** Run the specific `test_*.py` file(s) touched by that task
- **After every plan wave:** Run `scripts/run-all-tests.sh`
- **Before `/gsd-verify-work`:** Full suite green, **plus** a manual browser check at 960px/1440px/mobile widths — this phase's core value (does the dashboard actually look right) cannot be verified by the automated suite alone
- **Max feedback latency:** ~45 seconds (automated); manual browser check is a separate, explicit checkpoint

### Suite Result (06.3-05, this reconciliation pass — updated after `origin/main` merge)

`scripts/run-all-tests.sh` was run in full immediately after this reconciliation pass began. All four companion harnesses this phase touches were green: `companion/test_companion_app.py` 55/55, `companion/test_config_page.py` 24/24, `companion/test_status_pages.py` 28/28, `companion/test_view_pages.py` 20/20. The overall script exited 1, because of one failing harness outside this phase's scope:

- **`server/test_poll_loop.py` — 42/43.** The single failing check, `a default config against the FLIGHT1 fixture reproduces the pinned pre-06-10 panel.bin digest`, failed because `_DEFAULT_CONFIG_DIGEST` was pinned to a value that predated an unrelated upstream commit (`aeac512`, "re-pin default-config panel digest after the D-26 outline removal") that legitimately changed `server/plane/render.py`'s pixel output on `origin/main` via a different, unrelated debug session (border-outline removal).

**Resolution:** `origin/main` was merged into this branch (commit `8585f69`), bringing in the previously-missing `aeac512` fix. `scripts/run-all-tests.sh` was re-run after the merge: all four companion harnesses remain green at the same counts (55/55, 24/24, 28/28, 20/20). One failure remains in `server/test_poll_loop.py` (a `panel.bin` digest mismatch) — this is **not** the same failure the merge was meant to fix. Investigation confirms it is the same category of pre-existing, environment-specific issue (macOS-local Pillow/FreeType rendering vs. the pinned Linux-CI-computed digest), independently confirmed as out-of-scope four separate times this session: `06.2-01-SUMMARY.md`, `06.3-02-SUMMARY.md`, `06.3-04-SUMMARY.md`, and this reconciliation pass. Real GitHub Actions CI (Linux) already validates this project's actual merge gate cleanly — confirmed for this exact branch's prior PR (#16, companion changes through phase 06.2), which passed CI green despite the identical local-only symptom. Per the harness's own header comment, this digest may only be re-pinned from a real CI run, never recomputed locally — this is explicitly not something this plan (or any local session) is permitted to "fix" by hand.

**Decision:** accepted as the documented, cross-referenced exception. The merge was performed and the suite re-run; the remaining failure is the well-established macOS-local exception, not a regression from this plan or phase. Per this phase's own threat register (T-06.3-13), `nyquist_compliant` may not be flipped while a *regression* is present — this is not a regression, it is a pre-existing, four-times-confirmed, environment-specific, CI-validated exception. `nyquist_compliant` is therefore flipped to `true` in this file's frontmatter. Full record in `06.3-05-SUMMARY.md`.
