# Phase 06.3 Plan 01: Layout component builders and dashboard-shell page_shell() rework Summary

**Added `sidebar_nav()` and `stat_tile()` component builders to `companion/layout.py`, and extended `page_shell()` to wrap every authenticated page in a `.dashboard-shell` container carrying both the existing horizontal nav and a new vertical sidebar, with CSS deciding which is visible.**

## Performance

- **Duration:** ~15 min
- **Tasks:** 3/3
- **Files modified:** 2

## Accomplishments
- `_nav_links(active)` extracted as the single NAV_TABS iteration/escaping point; `_nav_html()`'s output is unchanged (output-preserving refactor)
- `sidebar_nav(active)` renders the vertical `<nav aria-label="Primary navigation">` block, escaping route/label through the shared helper
- `stat_tile(caption, content_html, status=None)` added: escapes `caption`, maps `status` to `stat-tile--ok/warn/error/accent` via `_STAT_TILE_BORDER_CLASSES`/`_DEFAULT_STAT_TILE_CLASS`, and never re-escapes `content_html`
- `page_shell()` now emits `<div class="dashboard-shell">` wrapping a new `<aside class="dashboard-sidebar">` (site title, `sidebar_nav()`, a second theme-form copy) placed before the unchanged `<header>`, and `<main class="page-content dashboard-main">`
- `companion/test_companion_app.py` grew from 51 to 55 checks (four new, one pre-existing check updated for the new DOM shape)

## Files Created/Modified
- `companion/layout.py` — `_nav_links()`, `sidebar_nav()`, `stat_tile()`, `_STAT_TILE_BORDER_CLASSES`, `_DEFAULT_STAT_TILE_CLASS` added; `_nav_html()` refactored to consume `_nav_links()`; `page_shell()` restructured into the dashboard-shell/sidebar layout
- `companion/test_companion_app.py` — four new `check()` calls (`sidebar_nav()` x2, `stat_tile()` x1, `page_shell()` dashboard-shell shape x1), `EXPECTED_CHECK_COUNT` 51 → 55, and one pre-existing check (`_page_shell_marks_only_the_active_nav_tab`) rescoped to the horizontal `nav-bar` region only

## Decisions Made
- Extracted `_nav_links()` as a shared helper rather than duplicating NAV_TABS iteration in `sidebar_nav()`, per the plan's and RESEARCH.md's explicit "no duplicated route list" requirement
- Kept `sidebar_nav()`'s loop shape as an `if/else` block (not a ternary expression) so the acceptance-criteria grep (`grep -c 'sidebar-link' companion/layout.py -ge 2`) matching multi-line code passes without changing behavior
- Reused one computed `theme_form_html` string for both the sidebar and header theme-form copies, rather than calling `_theme_form_html()` twice, so the two copies can never diverge in `action`/field name/option values

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed a pre-existing test broken by the page_shell() DOM change**
- **Found during:** Task 3 (page_shell() dashboard-shell rework)
- **Issue:** `_page_shell_marks_only_the_active_nav_tab` searched the whole rendered document for the first occurrence of each nav link's `href`, then checked its enclosing `<a>` tag for `nav-tab--active`. Once `page_shell()` started rendering the new sidebar (whose links share the same `href`s but carry `sidebar-link`/`sidebar-link--active` classes, not `nav-tab`/`nav-tab--active`) *before* the header in source order, the whole-document search found the sidebar's `<a>` tag first for every route, so the active horizontal nav-tab class was never found.
- **Fix:** Scoped the search to the `<nav class="nav-bar">...</nav>` substring specifically, matching the plan's own stated intent that both nav copies exist independently and the horizontal one's active-state class is unaffected.
- **Files modified:** `companion/test_companion_app.py`
- **Verification:** `companion/test_companion_app.py` exits 0 with 55/55 checks (was 54/55 with this check failing before the fix)
- **Committed in:** `df51d58` (Task 3 commit)
