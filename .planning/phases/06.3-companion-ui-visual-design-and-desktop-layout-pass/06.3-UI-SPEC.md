# Phase 06.3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This contract **supersedes `06-UI-SPEC.md`'s Design System, Spacing, Typography, and Color sections** for the companion web app only (`companion/static/style.css`, `companion/layout.py`, `companion/pages/*.py`). It does not touch, and is entirely separate from, the physical frame's own design system (`03-UI-SPEC.md`/`07-01-PLAN.md` — Zilla Slab/PT Serif, dithered mood backgrounds, `PALETTE_RGB`). Per `06.3-CONTEXT.md` D-01, `06-CONTEXT.md`'s D-21 ("plain utility tool, deliberately less visual investment") is explicitly reversed for this phase — the companion app gets a full visual refresh (color/type/spacing) plus a genuine desktop dashboard layout (sidebar nav + multi-column stat tiles), not just a wider single column. D-22/D-23/D-24/D-25 from `06-CONTEXT.md` remain in force and are restated below where they constrain this contract.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no component registry, no shadcn. Confirmed again for this phase: no `components.json`/`tailwind.config.*`/`postcss.config.*`/`package.json` exist anywhere in the repo. This stays Python stdlib `http.server` + hand-rolled router rendering server-side HTML strings (`companion/pages/*.py`), styled by one hand-written stylesheet (`companion/static/style.css`). shadcn Initialization Gate: not applicable (no React/Next.js/Vite tech stack) — do not initialize shadcn for this phase. |
| Preset | not applicable |
| Component library | none — hand-rolled semantic HTML, extending the existing pattern set (`layout.page_shell()`, `layout.data_table()`, `layout.status_dot()`, `layout.empty_state()`, `layout.anomaly_banner()`, `layout.flash_banner()`). This phase **adds two new component builders** to that same module — `layout.sidebar_nav()`/dashboard-shell markup and a `stat_tile()` helper (see Component Patterns) — but does not introduce a templating library, client-side framework, or build step. |
| Icon library | none — unchanged from `06-UI-SPEC.md`. Status/health indicators keep the CSS-only `.dot` pattern; the sidebar nav uses text labels only, no icon glyphs (consistent with D-24's "no logo, no elaborate branding" even under the fuller visual refresh). |
| Font | System font stack only — unchanged from `06-UI-SPEC.md`: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif` for UI text, `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` for tabular/technical data. Zero web-font loading stays a hard constraint — "more visual personality" is delivered via color, spacing, card/border treatment, and layout structure, never via a new typeface (would require a `@font-face`/remote asset this stylesheet's own header comment explicitly forbids). |

## Spacing Scale

Declared values (must be multiples of 4) — same token names as `06-UI-SPEC.md`, with `3xl` now genuinely used (previously reserved/unused):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-gap/status-dot-to-label gaps, badge inline padding (unchanged) |
| sm | 8px | Form-field label-to-input gap, table cell vertical padding (unchanged) |
| md | 16px | Default element spacing, table cell horizontal padding, stat-tile internal padding |
| lg | 24px | Section padding, gap between stacked page sections, gap between stat tiles in the dashboard grid |
| xl | 32px | Gap between nav bar and page content (unchanged); gap between the sidebar and main content column on desktop |
| 2xl | 48px | Login page's centered-card top offset (unchanged); vertical gap between dashboard-grid groups (e.g. between "Device/Pipeline" tiles and "Battery/Corroboration" tiles on Health) |
| 3xl | 64px | **Newly active this phase.** Horizontal gutter centering the dashboard shell's max-width container (see Component Patterns → Dashboard shell) on viewports wider than the container cap, so content never stretches edge-to-edge on an ultra-wide monitor |

Exceptions (carried forward from `06-UI-SPEC.md`, still binding):
- **44px minimum tap target** on every interactive element (nav tabs, sidebar links, buttons, form inputs) — D-22.
- **1px hairline borders** — standard, not a spacing violation. This phase adds a visible `--color-border` hairline around stat-tile cards (see Color) as part of the personality refresh; still 1px, not a new spacing category.

## Typography

Exactly 4 sizes, 2 weights — unchanged token values from `06-UI-SPEC.md`; this phase **broadens usage**, not the scale itself.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (regular) | 1.4 |
| Body | 16px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 24px | 600 (semibold) | 1.2 |

Usage (revised):
- **Display (24/600):** The "SkyPane" site title (unchanged, D-24) **and, new this phase, a stat tile's headline value** (e.g. a large "12" flight count, a battery mV reading, a percentage) inside `.stat-tile__value`. Both uses share the same token — this is a usage extension, not a new size.
- **Heading (20/600):** Page titles and section sub-headers (unchanged) **and stat-tile group labels** (e.g. "Overview") when a dashboard grid is subdivided into named groups.
- **Body (16/400):** All prose, table cell content, form help text, button labels, stat-tile supporting detail line (e.g. "3m ago (14:02:11)"). Unchanged.
- **Label (14/400):** Table column headers, form field labels, timestamps, stat-tile caption line (e.g. "Device last checked in"), status-badge text. Unchanged.
- Monospace variant unchanged: same 14px/16px sizes, `ui-monospace` stack, weight 400 only, for callsigns/hex/prefixes/timestamps.
- **New typographic detail (not a new token):** the site title and sidebar section labels get `+0.02em` letter-spacing for a more considered, designed feel — a CSS `letter-spacing` value, not an additional font size or weight. Do not extend this beyond those two locations; it is a targeted accent, not a page-wide style.

## Color

Two full palettes required — CFG-09's dark/light toggle stays independent of the physical frame's own colors (unchanged constraint). This phase **revises the actual hex values** to add personality while keeping the same 60/30/10 role architecture `06-UI-SPEC.md` established, plus adds one new role (`Border`) needed for the card-based dashboard treatment.

### Light mode (default, follows `prefers-color-scheme` unless overridden by CFG-09)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAFBFD` | Page background (subtly tinted off-white, replacing the previous flat `#FFFFFF` — the single biggest lever for "more personality" without touching layout) |
| Secondary (30%) | `#EEF1F7` | Nav bar / sidebar background, table row alternation, form field backgrounds |
| Border (new, structural — not part of the 60/30/10 split) | `#E2E6EE` | Stat-tile card outlines, sidebar/content column divider, fieldset borders — replaces the previous bare reuse of Secondary as a border color now that cards need a visible edge against the new tinted Dominant background |
| Accent (10%) | `#3454D1` | Reserved for: primary action buttons (Save Settings, Trigger Poll Now, Sign In), the active nav-tab/sidebar-link indicator, text links, focused-input outline, stat-tile top-border accent when a tile's own status is neutral/informational (no ok/warn/error state applies) |
| Destructive | `#DC2626` | Reserved for: error-state banners/text, the "error" status dot/badge, form validation error text (unchanged) |

### Dark mode

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0D0F14` | Page background (deepened from `#12151B` for richer contrast against cards) |
| Secondary (30%) | `#1A1E27` | Nav bar / sidebar background, table row alternation, form field backgrounds |
| Border (new) | `#262B36` | Same reserved-for list as light mode's Border |
| Accent (10%) | `#6E93FF` | Same reserved-for list as light mode's accent (lightened for AA contrast against `#0D0F14`) |
| Destructive | `#F87171` | Same reserved-for list as light mode's destructive (unchanged) |

### Status colors (both modes, unchanged from `06-UI-SPEC.md`) — reused as stat-tile personality accents

Not part of the 60/30/10 split — small-area functional indicators, now doing double duty as each stat tile's top-border accent color so the dashboard grid reads with color-coded status at a glance instead of a flat, uniform card wall.

| Status | Light value | Dark value | Reserved for |
|--------|-------------|-----------|---------------|
| OK / healthy | `#16A34A` | `#4ADE80` | Health-page tiles in a healthy state, "on schedule" indicators, zero-unresolved-prefix summary — also the stat tile's top-border color when its own status is `"ok"` |
| Warning | `#D97706` | `#FBBF24` | Approaching-stale signals, a single uncorroborated detection, a minor battery dip — also that tile's top-border color |
| Error | same as Destructive (`#DC2626` / `#F87171`) | — | Stale/missed poll past threshold, disagreement streak, abnormal battery drop — also that tile's top-border color |

Accent reserved for (restated, explicit list — never "all interactive elements"): **primary buttons, active nav-tab/sidebar indicator, links, focused-input outline, and a stat tile's top-border only when no ok/warn/error status applies to that specific tile.** Everything else interactive (secondary buttons, disabled states) uses neutral gray, not accent blue. Border color is structural (card edges, dividers) — it is never used as an interactive-state signal, and never substitutes for Accent/status colors.

## Layout Contract (this phase's core addition)

### Desktop breakpoint
**960px** is the single new width breakpoint this phase adds (`companion/static/style.css` currently has exactly one breakpoint, the 480px mobile-nav-scroll fallback — this is the second). Below 960px, the page renders exactly as it does today: fluid single column, top horizontal `.nav-bar` (itself becoming a horizontal-scroll strip below 480px, unchanged). At 960px and above, the dashboard shell activates.

### Dashboard shell (≥960px only)
- A two-column CSS Grid: a fixed-width **sidebar** (declare **240px**) on the left, and a **flexible main content column** on the right, separated by a 1px `--color-border` divider.
- The sidebar **replaces** the horizontal `.nav-bar` at this width (answers `06.3-CONTEXT.md`'s open discretion question directly — supplement was considered and rejected: showing both a sidebar and a horizontal tab row at desktop width would duplicate navigation with no benefit and contradicts "not just a wider single column"). Below 960px, the existing top `.nav-bar` is untouched, including its own 480px sub-breakpoint.
- Sidebar contents, top to bottom: the "SkyPane" Display-size title (with the `+0.02em` letter-spacing accent noted in Typography), then the 5 nav links stacked vertically (same `NAV_TABS` list, same active-state Accent treatment, just vertical instead of horizontal), then the CFG-09 theme toggle at the bottom of the sidebar column.
- Main content column keeps its own internal `--space-lg` (24px) padding, capped at a **1440px max-width**, horizontally centered via `margin: 0 auto` with `--space-3xl` (64px) minimum side gutter once the viewport exceeds that cap — this is where `3xl` becomes genuinely used.

### Dashboard grid (stat tiles)
- A CSS Grid, `repeat(auto-fit, minmax(240px, 1fr))`, `gap: var(--space-lg)` — same `auto-fit`/`minmax` idiom the existing `.gallery-grid` already establishes as this codebase's working precedent for responsive grids (per `06.3-CONTEXT.md`'s Reusable Assets note), so this is a genuinely consistent extension, not a new pattern family.
- Applies specifically to: **Health page** (4 tiles: Device check-in, ADS-B pipeline, Battery trend, Corroboration — replacing the current flat `_section()` stack) and **Airlines page** (2 tiles: unresolved prefixes, resolution-rate breakdown).
- Does **not** apply to Config (a settings form, not a stat dashboard — desktop treatment there is a two-column fieldset layout: Theme and Runway fieldsets side by side, Trigger Poll Now full-width below), History (a single full-width table — data density matters more than tile framing), or Preview (keeps its existing `.gallery-grid`, optionally widened to more columns at this breakpoint via the same `auto-fill` rule already in place — no new grid needed there).

### Mobile/tablet floor (unchanged, D-22)
Below 960px: single fluid column, top `.nav-bar`, no sidebar, no dashboard grid — stat "tiles" degrade to the existing stacked `_section()` blocks (still get the new Border/card treatment for visual consistency, just stacked instead of gridded). Below 480px: `.nav-bar` becomes horizontally scrollable, unchanged. 44px tap targets preserved at every width.

## Component Patterns

Extends `06-UI-SPEC.md`'s existing set — everything there stays valid; this phase adds three new patterns and revises one existing pattern's visual treatment.

| Component | Pattern |
|-----------|---------|
| **Sidebar nav (new, ≥960px only)** | `<nav aria-label="Primary navigation">` inside a fixed 240px column, vertical list of the same 5 nav links, 44px min-height each (D-22 tap-target floor preserved even though desktop is mouse-primary — keeps one CSS rule instead of a breakpoint-conditional target size), Accent-colored left-border (not underline, since it's now vertical) on the active item. Implemented as one new builder in `companion/layout.py` (e.g. `sidebar_nav()`), reusing the existing `NAV_TABS` constant — no duplicated route list. |
| **Stat tile (new)** | A card: `--color-border` 1px outline, `--space-md` (16px) internal padding, `border-radius` kept minimal/sharp (0-4px — a utility-dashboard feel, not a soft consumer-app one), a 3px top border colored by that tile's own status (ok/warn/error/accent-neutral per Color section). Internal structure: Label-size caption line, Display-size value line (or the existing `status_dot()` + Body-size detail line where a tile shows a status rather than a number — e.g. Device check-in keeps its dot+timestamp pattern inside the new card frame, it does not need to become a bare number). |
| **Dashboard grid (new)** | See Layout Contract above — `repeat(auto-fit, minmax(240px,1fr))`, reuses `.gallery-grid`'s established idiom. |
| **Data table (revised — bug fix, not a new pattern)** | Unchanged visual spec from `06-UI-SPEC.md`. This phase's `06.3-CONTEXT.md` D-03 requires `history_page.py`'s `_history_table_html()` to gain the same `.data-table-wrap` horizontal-scroll wrapper Airlines/Health already have (currently missing — the reason History still crops on mobile). No new CSS rule needed; apply the existing `.data-table-wrap` div around the existing hand-rolled `<table>`, preserving the unescaped `status_dot()` embedding in the Corroboration column that was the original reason `layout.data_table()` couldn't be reused directly. |
| Status dot + label | Unchanged from `06-UI-SPEC.md`. |
| Anomaly banner | Unchanged from `06-UI-SPEC.md`; now sits above the dashboard grid on Health, full-width, spanning both grid columns' width (not inside a tile). |
| Form (Config page) | Revised for desktop only: Theme and Runway `<fieldset>`s render side by side in a 2-column grid at ≥960px (`grid-template-columns: 1fr 1fr; gap: var(--space-lg)`), stacked as before below that width. "Save Settings"/"Trigger Poll Now" buttons stay full-width-row, below the fieldset grid, at every width. |
| Confirmation message | Unchanged from `06-UI-SPEC.md`. |
| Trend/chart (Health page) | Unchanged mechanism (the existing dependency-free inline-SVG sparkline, `battery_sparkline_svg()`) — now rendered inside the Battery-trend stat tile's card frame instead of a bare section. |
| Button (disabled/cooldown state) | Unchanged from `06-UI-SPEC.md`. |
| Image preview (CFG-10) | Unchanged from `06-UI-SPEC.md`; on desktop, may sit inside a card frame matching the new stat-tile border treatment for visual consistency with the rest of the refreshed page, but this is cosmetic only — no functional change. |
| Gallery grid (CFG-11) | Unchanged grid mechanism (`.gallery-grid`); no changes required by this phase. |
