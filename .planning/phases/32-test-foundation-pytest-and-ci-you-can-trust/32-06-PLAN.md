<migration_rules>
Identical in every migration plan (32-03..32-10). "Harness" = one of the hand-rolled files; "baseline" = `.planning/phases/32-test-foundation-pytest-and-ci-you-can-trust/32-BASELINE/<key>.txt` captured by plan 32-02.

- MR-1 Translation: each old `check(label, fn)` becomes one pytest test function `test_<descriptive_snake_case>`, or one id of a `@pytest.mark.parametrize` when the old check was emitted from a loop. The old label is the test docstring verbatim (a parametrized or consolidated test lists its labels in the docstring or carries them in readable param ids). `return False, reason` becomes `assert <condition>, reason` (or `pytest.fail(reason)` where no single boolean exists); `return True, ""` disappears; exceptions propagate — never wrap a test body in try/except that turns an error into a pass.
- MR-2 Remove `check()`, the `results` list, every `EXPECTED_CHECK_COUNT`, `main()`, the "N/M checks pass" summary and the import-failure guard at the top of `main()` (pytest reports collection errors itself).
- MR-3 Legacy-runner bridge (removed by plan 32-13): keep the file's existing repo-root `sys.path` bootstrap and end the file with an `if __name__ == "__main__":` block that does `raise SystemExit(pytest.main([__file__, "-q", "-p", "no:cacheprovider"]))`, so `scripts/run_all_tests.py` (still CI's runner until plan 32-13) keeps running the file under coverage.
- MR-4 Independence: no test depends on another test's side effects or on execution order. Shared expensive setup → a `scope="module"` fixture built with `tmp_path_factory`. A genuinely sequential scenario (a later old check asserts on state an earlier one created) → one test function whose asserts cover those old checks (N old checks → 1 node id in the ledger). The module must pass with `-n 0` and with `-n 4`.
- MR-5 Filesystem: every path lives under `tmp_path` / `tmp_path_factory`; the migrated file contains no `tempfile.` call; a test run leaves no new untracked file in the repo.
- MR-6 Global state (module attributes, env vars, cwd, `socket.getaddrinfo`): patch with `monkeypatch`, never manual save/restore.
- MR-7 Network: no test opens a non-loopback socket or resolves a non-loopback name — the pytest-socket allow-hosts guard and the autouse DNS guard from plan 32-01 fail such a test. ADS-B/adsbdb HTTP goes through the `fake_providers` fixture (repo-root conftest.py) or through the file's own function-level stubs converted to `monkeypatch.setattr`. Never add `@pytest.mark.enable_socket`. A fallback to the "real" `socket.getaddrinfo` inside a test now reaches the DNS guard: that is intended.
- MR-8 Root safety: every check whose outcome depends on permission bits (`os.chmod`, read-only files or directories, unwritable paths) gets `@requires_non_root` (`from skypane_test_support import requires_non_root`), with every path under tmp_path. A baseline FAIL line caused only by euid 0 is ported this way (the check runs in CI, where the runner is non-root).
- MR-9 Subprocesses: env built with `skypane_test_support.child_env()` (guard active in the child), loopback ports only, fixture teardown terminate → wait(timeout=5) → kill → wait.
- MR-10 Comments: keep only comments that explain why a behaviour is checked; drop phase/plan/ticket history (D-A3); English only.
- MR-11 No production code change. If the guard exposes a real network access, stub it in the test. Anything surprising (a check that cannot be ported as-is) goes into the SUMMARY with the reason.
- MR-12 Ledger fragment `.planning/phases/32-test-foundation-pytest-and-ci-you-can-trust/32-ledger/<key>.md`, format exactly as described in `.planning/phases/32-test-foundation-pytest-and-ci-you-can-trust/32-MIGRATION-LEDGER.md`: `# Ledger: <harness>`, a `Baseline:` line, then one table row per PASS/FAIL line of the baseline, in baseline order. `deleted` only with a concrete reason (for example: the check only asserted that a module imports, which pytest collection now guarantees). Verify with `server/.venv/bin/python3 .planning/phases/32-test-foundation-pytest-and-ci-you-can-trust/32-ledger-check.py <harness>`.
- MR-13 Test names are unique in the module and read as behaviour ("test_empty_state_is_white_dominant"), not as numbers.
</migration_rules>
