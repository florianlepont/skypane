<planner_findings>
Verified by the planner against the installed pytest-socket 0.8.1 source (`pytest_socket/__init__.py`), correcting RESEARCH.md Pattern 3:
- In `--allow-hosts` mode pytest-socket only replaces `socket.socket.connect`. `socket.getaddrinfo` / `socket.gethostbyname` are replaced ONLY by `disable_socket()` (full-block mode). With `--disable-socket --allow-hosts=...` together, `pytest_runtest_setup` skips `disable_socket()` because hosts are set, so DNS is NOT guarded. This plan therefore adds its own DNS guard (`guarded_resolvers()`).
- Calling `disable_socket()` and then `socket_allow_hosts()` (RESEARCH's sitecustomize snippet) blocks socket CREATION entirely, so a child `ThreadingHTTPServer` could not even bind. The child hook must call `socket_allow_hosts(...)` ONLY, never `disable_socket()`.
- In allow-hosts mode an AF_UNIX `connect()` is blocked unless `--allow-unix-socket` is passed; CONTEXT.md requires Unix sockets to stay allowed.
- `socket_allow_hosts()` raises `SocketConnectBlockedError` (a RuntimeError subclass), which production code catching `requests.RequestException` does NOT swallow, so a guarded call fails loudly.
- `server/plane/detect.py:query_provider()` calls `requests.get(url, headers=..., timeout=...)`, then `raise_for_status()`, `.json()`, `data.get(spec["aircraft_key"])`. `server/plane/enrich.py:default_transport()` calls `requests.get(...)` and returns `(response.status_code, response.json() or None on ValueError)`. Both reference the shared `requests` module attribute at call time, so patching `requests.get` reaches both.
- Provider URL hosts today: `opendata.adsb.fi` (adsbfi, key "aircraft"), `api.adsb.lol` (adsblol, key "ac"), `api.airplanes.live` (airplaneslive, key "ac"), `api.adsbdb.com` (adsbdb). `detect.MIN_SECONDS_BETWEEN_CALLS` sleeps between provider calls.
- `server/` has no `__init__.py`; `companion/` and `server/plane/` do. No harness defines a module-level `test*` function or `Test*` class, so collecting unmigrated server harnesses imports them and yields 0 items.
- `companion/test_browser_ux_helpers.py` is a helper module imported by the browser harnesses, not a harness.
- The dev machine's `server/.venv` is Python 3.11; CI moves to 3.14 in plan 32-14. Do NOT recreate `server/.venv` in this plan (plan 32-02 runs harnesses from it in parallel).
</planner_findings>
