<planner_findings>
- Audit TST-06: the workflow-level group `ci-${{ github.ref }}` is held by a main-branch run whose `deploy` job waits for reviewer approval, so the next push's TESTS queue behind it; and the deploy group's `cancel-in-progress: true` can kill a half-done rsync. Fix: drop the workflow-level `concurrency:` block; give the `test` job its own job-level group `test-${{ github.ref }}` (cancel-in-progress only for pull_request, as today); deploy keeps `group: production-deploy` with `cancel-in-progress: false`.
- With cancel-in-progress false, GitHub keeps at most one running and one pending job per group and replaces an older PENDING job with a newer one; a running job is never cancelled. The previous `true` setting existed to stop a reviewer approving a stale queued deploy. To keep that protection without cancelling, add a step before `Deploy` that compares `${{ github.sha }}` with `git ls-remote origin refs/heads/main` (actions/checkout persists the token, contents: read suffices) and skips the Deploy step with a `::notice::` when the run is stale. CONTEXT.md: "a queued stale deploy may be superseded only if the mechanism never kills a running rsync" — this satisfies it.
- Pinned-SHA convention: every `uses:` is `owner/action@<full 40-char sha> # vX.Y.Z` (see existing checkout/setup-python lines). actions/cache is new: resolve the latest release tag and its commit SHA with `gh api repos/actions/cache/releases/latest --jq .tag_name` then `git ls-remote https://github.com/actions/cache refs/tags/<tag>` (dereference an annotated tag with `^{}`), and pin that.
- Playwright: `playwright install --with-deps --only-shell chromium` installs OS deps + the headless shell; it skips the download when the shell is already in the restored cache, while `--with-deps` still installs the apt packages every run (they are not in ~/.cache). The browser harnesses call `p.chromium.launch()` (headless default), which uses the headless shell. Cache key must use the INSTALLED playwright version, read with `server/.venv/bin/python -c "import importlib.metadata as m; print(m.version('playwright'))"` into a step output.
- Plan 32-12 made `server/requirements-dev.txt` a hash-locked superset of runtime + dev: install ONLY that file, with `--require-hashes`. `cache-dependency-path: server/requirements*.txt` stays valid.
- `firmware/tests/run_host_tests.sh` is POSIX sh, uses `${CC:-cc}`, exits non-zero on any failing suite, runs in ~0.35 s; ubuntu-latest ships gcc (RESEARCH Assumption A3).
- Comments: explain why only; drop the plan-number history in the header (D-A3), keep the substance (why one file, paths-ignore safety, timeouts, least privilege).
- YAML can be validated locally: system `python3` has PyYAML 6.0.1 (note PyYAML parses the key `on` as boolean True).
</planner_findings>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions → production VPS | The deploy job rsyncs code and restarts services |
| GitHub Actions → PyPI / Playwright CDN / actions marketplace | CI downloads packages, browsers and actions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-14-01 | Denial of Service | deploy cancelled mid-rsync leaving a half-synced VPS | mitigate | `cancel-in-progress: false` on the production-deploy group |
| T-32-14-02 | Tampering | reviewer approving a stale queued deploy | mitigate | Stale-commit guard (`git ls-remote origin refs/heads/main` vs `github.sha`) skips SSH/Deploy steps |
| T-32-14-03 | Tampering | CI dependency substitution | mitigate | `pip install --require-hashes -r server/requirements-dev.txt` |
| T-32-14-04 | Tampering | new third-party action (actions/cache) | mitigate | Pinned to a full commit SHA with a version comment, like every other action |
| T-32-14-05 | Tampering | poisoned Playwright browser cache | accept | Cache is scoped to this repository and keyed on the exact playwright version; browsers come from Playwright's own installer |
| T-32-14-06 | Elevation of Privilege | workflow token scope | mitigate | `permissions: contents: read` unchanged; ls-remote needs only read |
</threat_model>
