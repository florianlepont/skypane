<objective>
The roadmap entry for this phase names one blocker and asks for it to be settled at
planning: `device_health` records observed check-ins only, so a "honoured-wake
rate" needs historical expected intervals that are stored nowhere.

`24-RESEARCH.md` Risk 1 settles it in writing, and the finding is sharper than the
roadmap's framing. Three facts decide it:

1. `device_health` rows are **real per-wake check-ins** — `ingest_caddy_battery_log()`
   keeps one row per Caddy access-log entry for the device's display fetch, not
   merely per battery reading. So observed cadence is genuinely measurable.
2. The expected interval is **not merely unstored — it is not a constant.**
   `wake.effective_wake_interval_s()` switches to `DISPLAY_OFF_SLEEP_S` whenever
   the screen is off (a control the user flips from Home), and quiet hours hold the
   frame on top of that. There is no config change log: `device_config.json` is a
   current-state file whose **no-migration, no-rewrite** contract is pinned by three
   separate named checks in `server/test_config_history.py`.
3. **A missed log range is not a missed wake.** The ingest recovers a
   rotate-in-place (offset reset when the file shrinks) but cannot recover a
   rotation that moved the old file away between two ingests. The resulting hole in
   `device_health` is indistinguishable from a device that did not wake — and **no
   schema change fixes that**, which is what disqualifies the phrase "honoured-wake
   rate" even with a new column.

Verdict implemented here: **change the metric.** Plot observed check-in gaps judged
against the cadence in force, named honestly. Then, because it costs almost
nothing and permanently uncaps a future upgrade, start recording true interval
epochs in a **new table** — which this project's `CREATE TABLE IF NOT EXISTS`
bootstrap already supports with no migration mechanism whatsoever.

Output: two readers in `server/history_db.py` that plan 24-07 draws from, one
deduped write in `server/poll_loop.py`, and the checks that keep all three honest.
</objective>
