<objective>
The roadmap asked for a wake-punctuality grid and flagged that the data may not
support it. Plan 24-03 settled that: `device_health` rows are real check-ins, so
observed cadence is measurable — but the interval the device was *expected* to keep
is nowhere in history, is not even a constant (it switches when the screen is
turned off and is held by quiet hours), and a log range the ingest missed is
indistinguishable from a device that did not wake. No schema change recovers any of
that.

So this plan draws what is true: **a grid of observed check-in regularity**, each
cell coloured on-cadence / late / missing by the same threshold function the Frame
tile already uses, with a caption that states plainly what it judged against and
what it cannot know.

That honesty is the requirement, not a disclaimer bolted onto it. A grid captioned
"wake punctuality" would be a picture asserting something this deployment cannot
observe, and this project has a standing practice of writing the limit down beside
the number rather than letting the number over-claim.

Output: one grid emitter, one Health section, and a caption whose every clause is
asserted against the data it describes.
</objective>

Binding constraints:
- No interval arithmetic in this file. Read 24-03's reader and classifier; if
  something is missing from them, that is a finding for the SUMMARY and possibly a
  follow-up on 24-03 — not a local computation.
- The cadence passed to the classifier is `wake.effective_wake_interval_s()` of the
  CURRENT config, and the caption must say so. It must not silently assume a
  default when the config yields None: `device_staleness_thresholds()` degrades to
  its bare floors, and the caption must then say the grid is judged against those
  floors rather than against a configured cadence.
- Cell colours come from the existing status tokens via the ok/warn/error
  vocabulary this page already uses. Accent stays reserved.
- Cells need an accessible reading. Each cell carries a `<title>` naming its real
  observed gap as a LOCAL timestamp/duration (`layout.local_clock_text()`'s
  convention; every visible timestamp in this app is Europe/Paris and raw ISO
  survives only behind a copy control).
- If the grid uses SVG `<text>` for day or hour labels, the viewBox must contain
  the text's own bounding box — measured in a real browser, never computed.
  Preferring HTML `<span>` labels outside the SVG (the `.sparkline` wrapper's
  approach) is allowed and makes the problem disappear; if that is chosen, say so
  and the viewBox-containment check becomes trivially satisfied rather than skipped.
- The empty case is a real case: a fresh deployment has no gaps. Render an empty
  grid with a caption saying so, not a missing section.
- `style.css` at zero stray comment terminators.
