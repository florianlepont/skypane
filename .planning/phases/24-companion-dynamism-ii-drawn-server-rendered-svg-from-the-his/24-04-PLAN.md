<objective>
The battery reading is the one number this app shows on two pages, and today it is
text on both. D21 draws it.

The requirement that matters is not "a ring appears" — it is **one emitter, two
call sites**. The predictable failure is two functions that start identical and
drift: one gains a threshold marker, the other does not; one is fixed at 4 px
stroke, the other at 2; six months later they disagree about what 20% looks like.
`companion/battery.py` exists because that exact drift happened once with the
percentage itself, and 19-01 fixed it by making a shared module and forbidding the
copy. This plan does the same for the picture.

Output: one ring emitter in `companion/draw.py`, called at a large size on Health's
battery section and a small size in Home's battery tile, painted through theme
tokens, correct in both themes, and proven to be one function by mutating it and
watching both pages change.
</objective>

Binding constraints:
- ONE emitter. It takes a fraction (or a millivolt value and derives the fraction
  through `companion/battery.py` — decide and state which) and a size. It does NOT
  take a "variant" name: a variant parameter is how two drawings hide inside one
  function.
- The fraction and the printed percentage come from one call. If the emitter takes
  a fraction, the page computes it once and uses it for both. Assert it.
- The ring is decorative **because the percentage is already in text beside it on
  both pages**. So it is `aria-hidden`, and it must NOT also carry a `role="img"`
  and a label — that would make a screen reader announce the reading twice, the
  same reasoning the sparkline's axis labels already use. Verify the text really is
  present at both call sites before relying on this; if a call site has no text
  percentage, the emitter needs a label there and the SUMMARY must say so.
- No tick marks, no gradient implying measurement precision. The estimate is
  labelled `≈` and the drawing must not out-claim it.
- Accent stays reserved. A "healthy" ring is not an accent use; status colour comes
  from the existing status tokens, and the state the ring colours by is the one the
  tile already computes (`battery_state`), never a second judgement.
- Both arcs are stroked, so both declare `fill="none"` explicitly — 24-01's
  contract rule 4, the "deliberately unfilled" case.
- The `<svg>` carries an explicit size route. `layout.icon_html()`'s docstring
  records what happens otherwise: 300x150 and a blown layout.
- Home's battery tile must not grow: `stat_tile()`'s box is shared by three tiles
  and a taller battery tile would make the row ragged. Measure it.
- French strings for anything new go in `companion/i18n_fr/health.py` and
  `companion/i18n_fr/home.py` respectively — the two files are separate, so both
  can be edited here without a cross-page collision.
