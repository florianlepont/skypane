<objective>
The single most predictable defect in this phase is a drawing that is correct in
light mode and invisible in dark mode — an SVG shape that inherited no colour and
painted the SVG default black, or a class that resolves to nothing. 24-01's source
scans catch the two cheap versions of that. They cannot catch the expensive one:
markup that is structurally perfect and still paints wrong once the cascade,
`currentColor` and a theme token have had their say.

Only a real browser can answer that, and **this harness has never asked**. Every
check in `companion/test_browser_ux.py` runs in whatever theme the default
resolves to; `grep -c data-ui-theme companion/test_browser_ux.py` is zero today,
even though the app has had explicit `html[data-ui-theme="light"]` /
`html[data-ui-theme="dark"]` overrides since CFG-09.

Purpose: give the four drawing plans three shared helpers — switch theme, read a
real computed paint, and assert the page body does not scroll horizontally — so
that each of them asserts the same thing the same way, and so the assertion is a
measurement rather than a source inspection. 23-02 did exactly this job for Phase
23 and landed **zero net checks**; this plan holds to the same bar.

Output: three helpers, each proven against a deliberate failure, and an unchanged
`EXPECTED_CHECK_COUNT`.
</objective>

Binding constraints:
- **Zero net checks.** This plan adds helpers and proves them; it does not add a
  standing assertion about any page. If proving a helper requires a temporary
  check, delete it before the final commit and say so in the SUMMARY.
  `EXPECTED_CHECK_COUNT` must be unchanged when this plan finishes — and that is
  itself the acceptance criterion, re-derived by RUNNING.
- The theme helper sets the explicit attribute (`html[data-ui-theme]`), not the
  emulated OS preference. The explicit override is the mechanism the app's own
  theme picker uses and it takes precedence over `prefers-color-scheme`, so it is
  both the more faithful test and the deterministic one. Record that reasoning in
  the helper's comment, because the next reader's instinct will be
  `emulate_media`.
- The paint reader must read the **resolved** value the browser computed
  (`getComputedStyle` on the element, for `fill`/`stroke`/`color` as appropriate),
  never the attribute and never the class. A helper that reads the class back has
  measured nothing the source scan in 24-01 did not already measure.
- The overflow helper measures the **page body** (`document.body.scrollWidth` vs
  `clientWidth`, or `documentElement` — decide which and state why), because
  CFG-45's wording is "no horizontal scrollbar on the page body". A container that
  scrolls internally on purpose (a table wrap) is NOT a failure; the two existing
  overflow checks already encode that distinction and the helper must not
  contradict them.
- Do not weaken, retarget or delete any existing check. If a helper's introduction
  makes an existing check redundant, leave it and say so in the SUMMARY.
