## The UI-SPEC's mood recipe was measured and does not hold — this is its concrete replacement

`03-UI-SPEC.md`'s "Background generation recipe" specifies a light-to-base vertical gradient plus noise, quantized against the **full 6-colour palette**, and explicitly flags its parameters as "a starting point subject to the on-glass checkpoint, not asserted final." That recipe was executed during planning at real 1200x1600 scale against the D-13 interim triples. Measured index distributions:

| State | `LIGHT_TINT_MIX` | State hue | White | Yellow + Red | Verdict |
|---|---|---|---|---|---|
| departing (blue) | 0.35 | 37.8% Blue | 38.7% | 4.5% | marginal — 15.4% stray Green |
| departing (blue) | 0.20 | 40.4% Blue | 34.2% | 3.9% | marginal — 16.8% stray Green |
| arriving (green) | 0.35 | 16.1% Green | 24.9% | **23.4%** | **fails** — 17.4% Black, 18.2% Blue |
| arriving (green) | 0.20 | 17.6% Green | 18.6% | **24.9%** | **fails** — not green-dominant at all |

The arriving mood is not a green field; it is six-colour static. The cause is structural, not a tuning miss: the interim Green (96,128,80) is a dark desaturated olive with no near neighbour in a 6-entry palette whose entries are far apart, so error diffusion approximates it by mixing Black, Yellow, Blue and Green. Tuning `LIGHT_TINT_MIX` moves this in the wrong direction.

**Resolution, measured and adopted below: quantize the mood gradient against a two-entry sub-palette `[White, state_base_rgb]` rather than the full six, then remap the two local indices onto the canvas's real `IDX_WHITE` / `bg_idx`.** Measured result at `MOOD_LIGHT_TINT_MIX = 0.40`: departing 80.6% Blue / 19.4% White, arriving 80.6% Green / 19.4% White, **zero** Yellow, Red, Black or cross-hue pixels, ~44ms per background, byte-identical across repeated builds.

This is not a scope reduction and not a downgrade of D-17. It is still a Floyd-Steinberg-dithered, gently-graded, non-flat photographic-toned field in the state's hue — exactly what D-17 and D-14's `poster-blue.jpg` evidence describe ("a soft, gently-graded sky-blue field... a visible, subtle vignette/gradient"). What it additionally buys is that the `02-UI-SPEC.md` Color contract survives **completely unchanged outside the aircraft zone**: the panel still contains only `{bg_idx, IDX_WHITE}` everywhere except the illustration. That makes 03-03's spatially-scoped guard rail exactly the one `03-RESEARCH.md`'s Validation Architecture already specified, instead of a weaker statistical threshold.

**Deliberate consequence to be aware of:** this path needs a `.point()` index remap, because a two-entry target palette's local 0/1 numbering has no relationship to the canvas's real constants. `03-RESEARCH.md` Pitfall 3 warns against a remap — that warning is correct and still binding for the **illustration** path (03-03), which quantizes against `PALETTE_RGB` in canvas index order and must have no remap. The two paths differ, and `dither.py` must document why in-line so a later reader does not "fix" one into the other.
</planner_findings>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Render pipeline → packed 960,000-byte wire buffer | The only output boundary. Any illegal palette index reaching `pack_panel()` becomes an out-of-range nibble the device's controller was never commanded to accept. |
| Render pipeline → device wake/refresh budget | The panel's SHA-256 governs whether the device performs a ~31.5s full refresh. Render-side nondeterminism is an availability/battery concern, not just a cosmetic one. |

No new network, authentication, file-input or user-input surface is introduced by this plan — the background is generated in code with no external asset, which is precisely why `03-RESEARCH.md` Open Question #5's option (b) was chosen.
