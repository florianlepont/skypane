# Phase 03 — UI Design Contract (Revision 4 — as-shipped record)

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Revision 4 note (2026-08-26):** Revision 3 was written before Waves 3-4 executed and was superseded live, during execution, by decisions D-20 through D-27 recorded in `03-CONTEXT.md`'s addenda 2 and 3. Four things Revision 3 specified were built, previewed by the developer, and then deliberately removed or never built at all: **Zilla Slab typography** (rejected on a real rendered preview, replaced by PT Serif — D-20 — then further changed from Bold to Regular — D-27); the **Floyd-Steinberg dithered "mood" background** covering most of the canvas (`build_mood_background()` and its constants were implemented in Wave 2 and then removed from `server/plane/dither.py` entirely after the developer saw the speckled result — D-21); the **flat quiet-zone caption rectangles** that existed to protect text legibility over that dithered background (never needed once the background reverted to flat — no `draw_quiet_zone()` or `QUIET_ZONE_PAD` exists in the shipped code); and **state-based illustration mirroring** (dropped entirely after a real mirrored illustration looked "bizarre" — D-24 — every illustration now renders nose-left in both states). The replacement design — a real, detailed, full-color per-airline illustration for the current detection plus a second, smaller card for the immediately-preceding detection, both on a flat single-color background — landed across commits 7663cb2 (typography/palette), e52602e (illustration set extension), c20a8eb (two-flight compositing), and f8db99a (final geometry tuning). **This revision documents shipped behaviour rather than proposing new design** — its epistemic status differs from Revisions 1 through 3, which were all forward-looking proposals. Every number below is read live from `server/plane/render.py`; where this document and the code could ever disagree, the code wins.

**Scope note (unchanged framing from `02-UI-SPEC.md`, restated for this revision):** This is not a web/React UI. The "frontend" is a Python/Pillow raster-rendering pipeline on the server that produces a single 960,000-byte, 4-bit-per-pixel indexed-color panel image (`docs/PROTOCOL.md` §1), blitted directly to a 13.3" E Ink Spectra 6 panel by firmware with no rendering logic of its own. There is no browser, no DOM, no component tree, no user input this phase. The shadcn initialization gate does not apply.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — custom Pillow drawing primitives |
| Font family | **PT Serif** (SIL OFL 1.1, ParaType Ltd.) — see `server/assets/fonts/VENDOR.md`. **Regular (400) is the active weight for every active-state text role** (D-27); Bold (700) survives only on the empty-state heading. |
| Font weight history | Inter (Phase 2) → Zilla Slab SemiBold/Bold (D-15, rejected on preview, D-20) → PT Serif Bold (D-20) → **PT Serif Regular (D-27, shipped)**. |
| Background field | Flat single palette index per state (D-21) — no gradient, no dithering, no texture. |
| Aircraft illustrations | Real per-airline PNGs, full-color, Floyd-Steinberg dithered to the panel's 6-color legal palette. Not a flat silhouette. |
| Frame | A thin ivory (rendered as `IDX_WHITE` — the panel has no separate "ivory" ink) rectangle outline, `FRAME_STROKE_PX = 2` wide, inset `FRAME_INSET_FRAC = 0.025` (2.5%) of canvas width from every edge. This element has no Revision 1-3 equivalent. |

**Known open risk, carried forward not settled:** PT Serif Regular's strokes are visibly thinner than every previous font/weight choice this project made specifically to avoid an e-ink hairline-legibility risk (Zilla Slab was chosen as a slab serif "structurally cannot have thin hairlines"; then Bold; then, per D-27, Regular anyway, after the developer explicitly asked for a thinner look and was shown the caveat before confirming). `server/assets/fonts/VENDOR.md`'s "Known risk — Regular weight is active" section flags this as **confirmed only on-screen (preview PNGs), not yet verified on real Spectra 6 glass.** This is an open item for the Wave 4 on-glass checkpoint, not a settled design decision — see "Open items for on-glass verification" below.

## Canvas and Geometry

Canvas: 1200×1600, portrait, full-bleed.

| Constant | Value | Derived result |
|---|---|---|
| `FRAME_INSET_FRAC` | 0.025 (2.5% of `WIDTH`) | frame rectangle `(30, 30, 1170, 1570)` |
| `FRAME_STROKE_PX` | 2 | 2px stroke, drawn in the state's ink (`IDX_WHITE`) |
| `MARGIN` (= `SPACE_LG`) | 64 | `SAFE_BOX = (64, 64, 1136, 1536)` |

**Amendment (2026-08-28, quick task 260828-k5r):** the outline described in this table's `FRAME_INSET_FRAC`/`FRAME_STROKE_PX` rows, and drawn historically by `draw_frame()`, is no longer drawn on the active-state panel — removed at the developer's request after judging it visually unwanted on the physical Spectra 6 panel. `FRAME_INSET_FRAC` survives purely as layout geometry: it still derives the main illustration's `inner_width` (see "Layout and Composition" below) and still anchors the CFG-05 source-fault badge's bottom edge. `draw_frame()` itself is retained in `server/plane/render.py` but is no longer called from the render path. The prose below and elsewhere in this document that describes the frame as drawn is a point-in-time record of what shipped before this date and is left intact.

**The safe box is enforced strictly only for empty-state text (`_assert_in_safe_box()`).** Every active-state element — the frame, both illustrations, both text blocks, and the top labels — uses the looser `_assert_within_canvas()`, which only asserts the element does not fall off the 1200×1600 canvas entirely. Why: the frame's 30px inset deliberately sits *inside* the old 64px `SAFE_BOX` band, and at the top labels' small point sizes (18-20px), real PT Serif glyph metrics can carry a 1-2px negative left/right bearing that would fail a pixel-exact 64px boundary check despite the text visually sitting exactly at `MARGIN` as intended. **This has been confirmed only against on-screen preview PNGs and never against the real physical bezel** — an open item for Wave 4's on-glass checkpoint alongside the PT Serif Regular legibility question above.

## Layout and Composition

Revision 3's eleven-zone list (state label → gap → silhouette → gap → flight number → gap → route line → gap → airline line → empty space → bottom tag) does not describe the shipped panel at all. The shipped arrangement is a **five-element, current-plus-previous two-flight poster**, top to bottom:

1. **State label** — top-left, anchored at `(MARGIN, MARGIN)`, anchor `"la"`.
2. **Static tag** (`ORY · RWY 3`) — top-right, anchored at `(WIDTH - MARGIN, MARGIN)`, anchor `"ra"`.
3. **Main illustration** — the current detection's real per-airline PNG. Width = `MAIN_ILLUSTRATION_WIDTH_FRAC` (0.87) of the inner post-frame-inset canvas width (1200 × (1 − 2×0.025) = 1140 → **992px** rendered width), aspect-ratio preserved via `Image.LANCZOS` resize. **Centered on its opaque-pixel extent on both axes** (`IllustrationPlacement.content`), not on its source rectangle: horizontally on the canvas midpoint, and (quick task 260902-req) vertically so **its aircraft's visible mid-line** sits at `MAIN_ILLUSTRATION_CENTER_Y_FRAC` (**0.4006**) of canvas height.

   > **Corrected 2026-08-28, pass 2** (horizontal). Horizontal padding is asymmetric (left 3–32px, right 5–29px after resize), so centering the rectangle displaced the visible aircraft from the canvas centre by up to **7.5px**, varying per file.
   >
   > **Corrected 2026-09-02** (quick task 260902-req, the sixth position anchor pass 2 missed). `MAIN_ILLUSTRATION_TOP_FRAC` (0.30 → **y = 480**) applied a fraction of canvas height to the *source rectangle's* top edge, computed before the file was even loaded. Top transparent padding spans 6–124px across the 43 vendored files (spread 118px), so this put the aircraft's visible vertical centre anywhere from **y = 621.0** (`air-caraibes-atr72.png`) to **y = 741.5** (`generic-a330.png`) — a **120.5px drift** purely by which airline was flying, the developer's reported "inconsistent aircraft centering". `MAIN_ILLUSTRATION_CENTER_Y_FRAC` (0.4006) is the fraction at which `air-france.png` — this spec's own confirmed reference render (see item 4 below) — lands on the exact same row it did before (visible centre **y = 641.0** either way), so the approved on-glass look is preserved while the per-file drift is removed (post-fix spread 0.5px, measured across all 43 files). **Sizing is unaffected** — it still derives from `.rect`, unchanged; only position follows painted pixels, on both axes now.
4. **Main text block** — two centred lines starting `MAIN_TEXT_GAP_PX` (54px) below the main illustration's **opaque-pixel bottom edge** (`IllustrationPlacement.content`), *not* below its source rectangle. Line 1 at 44px, line 2 starts `MAIN_LINE_GAP_PX` (8px) below line 1's bottom.

   > **Corrected 2026-08-28** (debug session `illustration-crop-text-margin`). This item previously read: "starting at `main_illustration_bottom − MAIN_TEXT_OVERLAP_PX` (20px), a deliberate slight overlap: the vendored illustration files have no transparent bottom padding of their own (confirmed via `Image.getbbox()` during the live sketch pass)". **That claim was false, and the constant never overlapped anything.** Every vendored illustration carries a soft drop-shadow band (alpha 1..127) below the aircraft. `Image.getbbox()` counts those pixels as content; `draw_illustration()` hard-thresholds them away (`p > 127`) and never paints one. Measured across all 43 vendored files the two disagree by 5–261px, so the *visible* aircraft-to-text gap ranged from **17px to 154px** depending purely on which airline was flying — which is what the developer reported seeing on the physical panel. The two files on screen during the sketch pass (`air-france.png`, `vueling-airlines.png`) both happen to report a naive bottom padding of exactly **0**, which is how the claim came to be written down as verified. `MAIN_TEXT_GAP_PX` (54px) is that same confirmed render's *real* gap, so the approved look is preserved — the Air France reference render is byte-identical before and after the correction — while its per-file variance is removed.
5. **Previous illustration** — the flight detected immediately before the current one (`poll_loop.py`'s two-deep history). Width = `PREVIOUS_ILLUSTRATION_WIDTH_FRAC` (0.57) of the **main illustration's own rendered width (its rectangle, a constant 992px)** → 992 × 0.57 = **565px**. **Right-aligned to the main *aircraft's visible* right edge** (`main_placement.content[2]`), not the frame margin — the developer explicitly corrected an earlier attempt that aligned it to the frame instead. Vertically positioned so **its aircraft's visible mid-line** sits at `PREVIOUS_ILLUSTRATION_CENTER_Y_FRAC` (**0.7528**) of canvas height. Omitted entirely when no previous flight exists, or when its illustration cannot be selected (main illustration also missing).

   > **Corrected 2026-08-28** (pass 2). Both of this card's position anchors previously used source rectangles. Right-aligning rectangle-to-rectangle left the two *aircraft's* visible right edges up to **26px** apart (worst real pairing: `km-malta-airlines.png` main, 29px right padding, against `transavia-france.png` previous, 3px). Centering the rectangle vertically put the visible aircraft **5.5–28.5px too high, always high**, because the drop-shadow band makes bottom padding always exceed top padding; `PREVIOUS_ILLUSTRATION_CENTER_Y_FRAC` was re-derived 0.76 → **0.7528**, the value at which the sketch-era `vueling-airlines.png` card lands on the exact same row as before (`prev_top = 1118` either way), so the confirmed composition is preserved while the per-file drift is removed.
   >
   > **Sizing deliberately still uses the rectangle**, re-decided with horizontal centering explicitly in scope. `.rect`'s width is a constant 992px for every file, so this card's size is stable. Deriving it from the main illustration's *opaque* width (933–984px) would make the previous card's size depend on which airline is in the **main** slot — the same previous aircraft would render up to 5% larger or smaller depending on what flew before it. That is a new per-file coupling and strictly worse than the ~28px visible-width variation it would remove. **Sizing stays stable; only position follows the painted pixels.**
6. **Previous text block** — two right-aligned lines, right-aligned to the previous **aircraft's visible** right edge (`prev_placement.content[2]`), which item 5 has already placed on the main aircraft's visible right edge. So both aircraft and this text block share one visible vertical line. Corrected 2026-08-28 (pass 2) from the rectangle's right edge, which sat 3–17px right of the aircraft the text belongs to. Line 1 starts `PREVIOUS_TEXT_GAP_PX` (**47px**, corrected 2026-08-28 from 22px) below the previous illustration's **opaque-pixel bottom edge**, for the same reason as item 4 — at this card's 565px scale the rectangle sits 21–99px below the aircraft, which made the visible gap range 43–121px. 47px is the sketch-era `vueling-airlines.png` render's real gap (25px opaque padding + the old 22px). Line 2 starts `PREVIOUS_LINE_GAP_PX` (34px) below line 1's own **top**, not its bottom — the tighter confirmed stacking from the live mockup pass.

**Empty state** (unchanged in substance, still its own subsection): flat White background, no dithering, centred Bold 72px heading over manually word-wrapped Regular 40px body text, both asserted against the strict `SAFE_BOX`.

**Nose-left always, in both states (D-24).** `draw_illustration()` never mirrors — every illustration file is drawn exactly as vendored, nose-left, whether the state is departing or arriving. This is the single largest behavioural divergence from every prior revision, all of which specified mirroring (departing = nose-right, arriving = nose-left) as an explicit secondary state cue.

## Typography

Six active roles, all **PT Serif Regular (400)** (D-27), plus two empty-state roles:

| Role | Size | Weight | Font | `fit_text_size()` floor |
|---|---|---|---|---|
| State label | 20px | Regular | PT Serif | — |
| Top tag | 18px | Regular | PT Serif | — |
| Main line 1 (callsign + city) | 44px | Regular | PT Serif | 28px |
| Main line 2 (airline) | 22px | Regular | PT Serif | 16px |
| Previous line 1 (callsign + city) | 28px | Regular | PT Serif | 18px |
| Previous line 2 (airline) | 16px | Regular | PT Serif | **12px — the smallest text this panel has ever rendered** |
| Empty-state heading | 72px | **Bold** | PT Serif | — |
| Empty-state body | 40px | Regular | PT Serif | — |

`fit_text_size()` steps down in 2px decrements (`_FIT_STEP_PX`), never clipping, wrapping mid-word, or overflowing, floored at the values above.

**No role carries tracking or letter-spacing.** This supersedes Revision 3's tracked, uppercase Label role entirely — every text role reads as ordinary sentence-case prose. Bold (700) is the only weight left anywhere in the pipeline outside the empty-state heading; every other role, active or empty-state body, is Regular.

**Open item, not asserted resolved:** the previous card's line 2 shrinking to a 12px floor is smaller than anything this panel has ever put on real glass — flag this as an on-glass legibility question, not a closed one.

## Colour

### Empty state (unchanged)

| Role | Value | Usage |
|---|---|---|
| Dominant | White (`IDX_WHITE`, nibble `0x1`) | Full-bleed background, flat, no dithering |
| Secondary | Black (`IDX_BLACK`, nibble `0x0`) | Empty-state heading + body text only |

### Departing / Arriving states — flat single-color background (D-21, supersedes Revision 3's dithered mood gradient)

| State | Background index | RGB triple | Confidence |
|---|---|---|---|
| Departing | `IDX_BLUE` | **(110, 180, 225)** | **D-21, developer-confirmed** on a real rendered preview ("c'est parfait") |
| Arriving | `IDX_GREEN` | **(140, 195, 130)** | **D-21, developer-confirmed** on a real rendered preview |
| Yellow (illustration only) | `IDX_YELLOW` | (240, 224, 80) | D-13, still an **interim, uncalibrated** estimate |
| Red (illustration only) | `IDX_RED` | (160, 32, 32) | D-13, still an **interim, uncalibrated** estimate |

**Standing trap:** the panel-index order and the wire-nibble order diverge for Blue and Green specifically — index 4 (Blue) maps to nibble `0x5`, index 5 (Green) maps to nibble `0x6` (`server/panel_format.py`'s `INDEX_TO_NIBBLE`). Anyone reading the wire format directly must not assume index order equals nibble order.

**The palette contract is now a two-part legality-plus-dominance assertion (`_assert_legal_palette()`), not a spatial reservation.** It asserts (1) every index on the panel is one of the six legal Spectra 6 indices, and (2) the state's background index is the single most common index on the panel. **There is no remaining spatial reservation for Yellow or Red anywhere on the canvas** — a real airline livery may legitimately use all six legal indices anywhere within its own bounding box, or in principle anywhere else the code happens to paint, because the guard rail no longer distinguishes zones. This supersedes both Revision 2's whole-canvas "exactly `{bg_idx, IDX_WHITE}`" rule and Revision 3's spatially-scoped illustration-bbox exception — the shipped contract is simpler than either.

**D-11/D-12's illustration-zone livery permission still holds in substance:** Yellow may appear in a livery (no conflict with Phase 4's low-battery indicator, per the developer's own judgment); Red's original reservation (RER-03's disruption banner) is stale, since RER-03 was deferred to v2 and has no scheduled consumer in this roadmap.

## Rendering Rules

- **Flat integer-index fills** for all text and shapes — this satisfies the "no anti-aliasing" rule for free everywhere except the two illustration bounding boxes.
- **Standing prohibition on `ImageDraw.text(..., stroke_width=..., stroke_fill=...)`** — verified during Wave 2 to leak illegal palette indices (Yellow, Red) via anti-aliased edge blending, confirmed still honoured by the shipped renderer.
- **Illustration alpha hard-thresholded before paste** (`>127` → strictly binary): pasting through a soft mask blends palette index integers, not colours, and invents illegal indices — a mask value of 128 over Blue and White measurably produced Yellow during planning.
- **`Image.LANCZOS` resize** for both illustrations.
- **Floyd-Steinberg dithering confined to the two illustration bounding boxes only** (`dither.dither_to_full_panel_palette()`) — the background field is flat and never dithered.

## Open items for on-glass verification

The following must be answered, not assumed, at the Wave 4 checkpoint:

1. Is PT Serif Regular legible at every role — state label (20px), top tag (18px), main line 1 (44px, floor 28px), main line 2 (22px, floor 16px), previous line 1 (28px, floor 18px), and especially previous line 2 (16px, floor **12px**, the smallest text ever rendered on this panel)?
2. Do the frame and both illustrations, which deliberately sit inside the old 64px `SAFE_BOX` band, get obscured by the physical bezel?
3. Is the previous card's smallest text (12px floor) readable at normal desk-viewing distance?
4. Do the interim Yellow and Red `PALETTE_RGB` triples (D-13, still uncalibrated) need adjusting, while leaving the developer-confirmed Blue and Green (D-21) untouched?
5. Do the D-23 fuselage wordmarks (real airline lettering, waived from the no-text requirement) stay legible at both the main illustration's ~992px scale and the previous illustration's ~565px scale, or do they turn to speckle at the smaller size?
6. With mirroring gone (D-24) as the second state cue, is the background colour plus the state label text alone a clear enough departing/arriving distinction — or does losing the nose-direction cue leave the two states too easy to confuse at a glance?
