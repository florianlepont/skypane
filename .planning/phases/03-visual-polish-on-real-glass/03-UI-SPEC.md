# Phase 03 — UI Design Contract (Amendment — Revision 3)

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Revision 3 note (2026-08-26):** This is the second structural revision of this phase's contract, following the same revision-note convention `02-UI-SPEC.md` already established for its own internal Revision 1 → Revision 2 pivot. **What changed and why:** the first draft of this document (approved 6/6 by the checker earlier the same day) scoped Phase 3 narrowly — "the aircraft-illustration zone changes, everything else (background, typography, hierarchy) stays locked from `02-UI-SPEC.md` Revision 2." After that approval, the user directly compared the shipped Phase 2 design against real flightportrait.com product photography (`poster-blue.jpg`, `print-detail.jpg` — inspected directly this session, see Design System below) and asked for a materially wider realignment (`03-CONTEXT.md` D-14 through D-18): a serif typeface replacing Inter (D-15), flight number and destination/origin promoted to co-equal visual prominence instead of flight-number-alone-as-hero (D-16), the full-bleed saturated flat Blue/Green background replaced with a softer, photographic-toned, Floyd-Steinberg-dithered background (D-17), and a new mechanism for the departing/arriving state signal now that the background is no longer one flat legal color (D-18). **This document folds both scope expansions together** — the illustration-zone contract from the first draft (D-05 through D-13: per-airline dithered livery illustrations, the D-09 hand-off spec, the D-11/D-12 color-contract addendum, D-13's panel-RGB resolution) is retained essentially unchanged below; the newly-revised sections are Design System (font), Typography (hierarchy), Color (background treatment + state signal), and a new Layout & Composition section this document didn't previously need. **What stays locked, per the user's own explicit framing (`03-CONTEXT.md`/`03-RESEARCH.md`'s "Practical consequence" notes):** the 1200×1600 canvas dimensions, the overall top-to-bottom zone ORDER (state label → illustration → flight number → route line → airline line → bottom tag), the spacing token VALUES (8/16/32/64/96/128/192px), and the Copywriting Contract's actual text strings. Nothing in this document is newly decided here beyond the concrete design choices `03-RESEARCH.md` explicitly left to this UI-SPEC step (background generation recipe, exact hero-pair sizes, quiet-zone treatment) — everything else packages already-made `03-CONTEXT.md` decisions into the design-contract format the planner/executor/checker consume.

**Reference evidence inspected directly this session (D-14):** `poster-blue.jpg` — a framed poster showing 4 aircraft stacked vertically in full livery color on a **soft, gently-graded sky-blue field** (not a flat saturated fill — there's a visible, subtle vignette/gradient, lighter toward the upper portion), with small, tightly-set serif captions under each aircraft. `print-detail.jpg` — a close-up of the frame corner showing the "FLIGHTPORTRAIT" wordmark: uppercase, evenly/widely letter-spaced, slab-like serifs with no strong thick/thin stroke contrast (reads as typewriter-adjacent, not a high-contrast display serif). Both images remain saved at the session scratchpad path recorded in `03-CONTEXT.md` D-14 and were re-viewed this session to ground the decisions below.

**Scope note (unchanged framing from `02-UI-SPEC.md`, restated for this amendment):** This is not a web/React UI. The "frontend" is a Python/Pillow raster-rendering pipeline on the server that produces a single 960,000-byte, 4-bit-per-pixel indexed-color panel image (`docs/PROTOCOL.md` §1), blitted directly to a 13.3" E Ink Spectra 6 panel by firmware with no rendering logic of its own. There is no browser, no DOM, no component tree, no user input this phase. The shadcn initialization gate does not apply (confirmed again this session — still no `components.json`/`tailwind.config.*`/`package.json`, stack is still Python).

### Font vendoring (D-15)

Follow the exact same OFL-vendoring discipline `02-UI-SPEC.md` already established for Inter:

| Property | Value |
|---|---|
| Family | Zilla Slab |
| License | SIL OFL 1.1, Mozilla Foundation copyright — `[VERIFIED: 03-RESEARCH.md, cross-referenced against Font Squirrel, 1001 Fonts, Wikipedia]` |
| Source | Google Fonts distribution, release 1.501 |
| Weights to vendor | **SemiBold (600) and Bold (700) only** — do **not** vendor or reference the Regular (400) or Light (300) cuts anywhere in the render pipeline. This is a hard rule, not a style preference: Regular/Light cuts thin out stroke width in exactly the way this panel's e-ink hairline-legibility risk describes (`03-RESEARCH.md`'s explicit rejection of high-contrast/thin serifs applies equally to thin *cuts* of an otherwise-safe slab serif). |
| Files | `server/assets/fonts/ZillaSlab-SemiBold.ttf`, `server/assets/fonts/ZillaSlab-Bold.ttf` |
| Provenance | New `server/assets/fonts/VENDOR.md` entry: source URL, pinned release (1.501), retrieval date, license text pointer — same format as the existing Inter entry. **The actual TTF files have not been downloaded/hash-verified as of this UI-SPEC** — this is a planner/executor task, flagged `[ASSUMED]` correct until done (per `03-RESEARCH.md`'s Package Legitimacy Audit). |
| Inter status | `Inter-Regular.ttf`/`Inter-Bold.ttf` remain vendored in the repo (not deleted — same "retained for provenance, no longer primary" treatment already given to the retired CC0 silhouette in the prior draft) but are no longer referenced anywhere in `server/plane/render.py`'s active font constants. Note this supersession in the font `VENDOR.md`. |

**Why a slab serif, not a literal wordmark match attempt (binding rationale, not just a preference):** the exact typeface flightportrait uses could not be identified from any source checked (`03-RESEARCH.md` — no CSS/`@font-face` data found, the poster renderer is closed-source per `02-UI-SPEC.md`'s own prior investigation). Rather than pick a font that looks similar and hope its bold cut survives e-ink rendering, this contract picks a font **category** — slab serif — that structurally cannot have thin hairlines (a slab serif's serifs are as thick as the letter's main strokes by definition). A high-contrast display serif (e.g. Playfair Display) is explicitly rejected even in a Bold-only cut, because stroke-width contrast *within a single glyph* is that category's defining character and isn't eliminated by weight alone.

### Rendering rule (hardware-specific, binding — extends `02-UI-SPEC.md`'s rule, does not replace it)

`02-UI-SPEC.md`'s original rule — disable anti-aliasing / hard-threshold all shapes and glyphs, reserve Floyd-Steinberg dithering "for any future photographic content only" — is now exercised for **two** zones instead of one: the aircraft illustration (already true in the prior draft, D-05 through D-11) and, new this revision, the full-canvas background field (D-17). **Text itself is never dithered, in either revision.** Every text glyph on the panel is still drawn with `dither=Image.NONE`, hard-edged, exactly as `02-UI-SPEC.md` originally specified — what changes is what sits *underneath* the text: previously a single flat legal index, now a dithered multi-color field, which is why every text-bearing element needs the new "quiet-zone" flat-rectangle treatment specified in Layout & Composition below.

**Explicit ban, new this revision (D-17's own investigation):** `ImageDraw.text(..., stroke_width=N, stroke_fill=...)` must **never** be used anywhere in `server/plane/render.py`, for any font, in any state. Verified this session by direct local execution: it leaks illegal palette indices (Yellow, Red) into the canvas via anti-aliased stroke-edge blending — even against a flat single-color background, i.e. this isn't specific to the new dithered background. If a text element needs stronger contrast against its surroundings, use the flat quiet-zone rectangle pattern (Layout & Composition below), never a stroke outline.

### Airline name → filename normalization (deterministic, no live lookup)

```python
# server/plane/render.py (or a small new module) — mirrors enrich.py's
# normalise_callsign() discipline: deterministic, never raises, returns
# None for anything falsy. This is a PURE function of airline_name; it
# makes no network call.
import re
import unicodedata

def normalise_airline_key(airline_name):
    """'Air Algérie' -> 'air-algerie', 'CCM Airlines' -> 'ccm-airlines'."""
    if not airline_name:
        return None
    ascii_name = unicodedata.normalize("NFKD", airline_name).encode("ascii", "ignore").decode("ascii")
    slug = re.sub(r"[^a-z0-9]+", "-", ascii_name.lower()).strip("-")
    return slug or None
```

Illustration selection: `route.get("airline_name")` (already resolved by the existing `server/plane/enrich.py` `lookup_route()` call in `poll_loop.py`'s `run_once()` — no new enrichment call) → `normalise_airline_key()` → look up `server/assets/icons/illustrations/{key}.png`; if the file doesn't exist (unresolved airline, or enrichment returned no route at all — the "Route unavailable" state), fall back to `generic-fallback.png`.

### Coverage caveat — do not conflate "seen in ADS-B traffic" with "resolvable to an illustration"

Illustration selection depends transitively on `adsbdb`'s crowdsourced coverage (52.6% overall). `EJU` and `KMM` prefixes are **confirmed misses** — those flights always render the generic fallback regardless of illustration availability. Size the hand-off set around confirmed-hit carriers (table above), not around every callsign prefix seen in raw ADS-B samples.

### Quiet-zone text compositing (D-17's own new requirement — applies to every text-bearing element in the Departing/Arriving states)

Every zone above (1, 5, 7, 9, 11) sits on the new dithered mood background instead of a flat field. To keep every text-bearing pixel using only the two legal indices the Color contract requires (`{bg_idx, IDX_WHITE}`), each of those five zones gets a **flat quiet-zone rectangle** drawn in the state's dominant index (`IDX_BLUE` departing / `IDX_GREEN` arriving) directly onto the already-dithered canvas, sized to that zone's own measured text bounding box **plus `SPACE_XS` (8px) padding on all four sides**, drawn with hard/sharp corners (no rounding — same "no soft decorative edges" rule as the rest of this contract) — **before** the text itself is drawn on top in White.

```python
# Reuses existing bbox-measurement helpers (fit_text_size()/_tracked_text_bbox())
# already present in server/plane/render.py — no new measurement logic needed,
# only the extra rectangle + reordered draw call.
def _draw_quiet_zone_text(draw, bbox, text, font, bg_idx, tracking=0, pad=SPACE_XS):
    left, top, right, bottom = bbox
    draw.rectangle((left - pad, top - pad, right + pad, bottom + pad), fill=bg_idx)
    draw_tracked_text(draw, (left, top), text, font, IDX_WHITE, tracking=tracking)
```

**Compositing order for the Departing/Arriving states, replacing today's single `pf.new_canvas(bg_idx)` call:** (1) render the dithered mood background across the full 1200×1600 canvas; (2) composite the illustration (already dithered, no quiet zone); (3) draw each of the five text zones via the quiet-zone helper above, in top-to-bottom order. The Empty state is unaffected — it keeps `pf.new_canvas(IDX_WHITE)`'s single flat fill and plain `draw.text()`, no quiet zones needed since its background is already flat.

**Known open risk, flagged rather than asserted resolved (per this document's own instructions):** the quiet-zone rectangles are a verified-safe mechanism for palette legality (Pattern 5, `03-RESEARCH.md`), but their *visual* effect — five small flat-color "islands" sitting inside an otherwise busy dithered field — has not been seen on real glass as of this UI-SPEC. Whether they read as clean caption plates (the intent) or as visually awkward boxes depends on exact padding/corner treatment and how the mood background's local dither density looks immediately outside each box. This is explicitly a `checkpoint:human-verify` item (see "Checkpoints Required Before Phase Close" below), not a closed design question — the 8px padding value above is a starting point, not asserted final.

### Known open risk: two adjacent "busy" zones (illustration + background), flagged per this document's own instructions

Prior to this revision, the aircraft illustration was the panel's only dithered/multi-color element, sitting against a calm, flat, single-color field — a deliberate figure-ground contrast. Under D-17, the background itself is now also dithered and multi-tonal (even if visually calmer than the illustration, being a soft gradient rather than a full-color livery). **This is a genuine new visual-clash risk, not something this document can assert away:** the illustration may read as less distinct against a background that's no longer perfectly flat, weakening the figure-ground separation the prior "poster" composition relied on. There is no code-level mitigation proposed here beyond what's already specified (the illustration's own bounding box has 192px of breathing room above/below per the locked spacing scale, and the mood background is deliberately described as "soft"/lower-contrast than the illustration's full livery saturation) — **this must be judged on real glass** as part of the fresh legibility checkpoint below, and if it reads poorly, the most likely fix (increasing the mood background's lightness/desaturation relative to the illustration, not changing geometry) is left as an open follow-up, not pre-decided here.

## Typography

**Revised this session (D-15, D-16) — supersedes `02-UI-SPEC.md`'s Typography section and the prior draft's "unchanged" framing entirely.** Font family changes from Inter to Zilla Slab; the flight-number/destination hierarchy changes from a single 88px hero + smaller Body line to a co-equal hero pair; the airline-name role is demoted to a new, distinct Caption size. **Exactly 4 sizes, exactly 2 weights** (per this contract's own declaration requirement):

| Role | Size | Weight | Line Height | Tracking |
|------|------|--------|-------------|----------|
| Label | 36px | Bold (700) | 1.2 | 6px (widened from Phase 2's 4px, per D-15's "wide letter-spacing" instruction) |
| Caption | 40px | SemiBold (600) | 1.3 | 0 |
| Destination/Origin (hero — secondary) | 64px | SemiBold (600) | 1.15 | 0 |
| Flight Number (hero — primary) | 72px | Bold (700) | 1.1 | 0 |

Role usage:

- **Label** (uppercase, tracked): state label text (`DEPARTING`/`ARRIVING`); the "TO"/"FROM" route-line prefix; the bottom static tag (`ORY · RWY 3`). Font: Zilla Slab Bold.
- **Caption**: the airline line (e.g. "Air France"), including its "Route unavailable" fallback copy. Font: Zilla Slab SemiBold. Clearly the smallest and lightest of the four roles — the deliberate "subordinate" tier D-16 asks for.
- **Destination/Origin (hero-secondary)**: the route line's destination/origin city name. Font: Zilla Slab SemiBold.
- **Flight Number (hero-primary)**: the flight number caption only. Font: Zilla Slab Bold.

**Why this resolves D-16 concretely, not vaguely:** the prior design had an 88px/700-weight flight number against a 56px/400-weight route city — a 32px size gap and a full weight-class gap, making the flight number the unambiguous single hero. This revision closes the size gap to 8px (72px vs 64px, one spacing-token's worth of visual difference) and keeps both in the "heavy" weight range (SemiBold/Bold, never Regular) — close enough in visual mass that neither dominates the way flight-number-alone did, while flight number remains the marginally heavier of the two via weight (Bold vs SemiBold), per `03-RESEARCH.md`'s own suggested resolution. The airline name, previously sharing the Body role with the destination city (56px/400 for both), is now unambiguously smaller (40px) and visually distinct from both hero elements — matching the user's own words: *"le numéro de vol et la destination sont tout aussi importantes. Viennent ensuite le nom de la compagnie et les autres informations."*

**Dynamic shrink behavior (`fit_text_size()`, D-04's stress test target):** unchanged mechanism, now applies independently to whichever role's text risks overflowing the safe box — most commonly the Destination/Origin hero-secondary role (long city names) and the Caption role (long airline names), each shrinking from its own declared initial size down to the existing `MIN_CAPTION_FONT_SIZE = 28px` floor. The Flight Number hero-primary role is defensively wrapped in the same helper (ICAO-format callsigns are short and fixed-pattern, so this path is expected to rarely trigger, but the safe-box assertion must still hold for any input).

**Color per state (cross-reference only — full contract lives in Color below):** weight/size/line-height/tracking are identical across all display states; only the ink color and the presence of a quiet-zone backing rectangle change. All four roles render Black on the Empty state's flat White background (no quiet zone needed there), and White on the Departing/Arriving states' dithered mood backgrounds (each instance backed by its own quiet-zone rectangle, per Layout & Composition above).

**Legibility flag, extended from `02-UI-SPEC.md`'s original flag:** White text on a flat saturated field was verified "clearly legible" on real glass in Phase 2 (`02-05-SUMMARY.md`). That finding **does not transfer automatically** to Zilla Slab text over a dithered mood background, even with the quiet-zone mitigation — this is a fresh, distinct, required `checkpoint:human-verify` item (see below), not something this document treats as pre-verified.

### Background generation recipe (D-17/D-18, resolves `03-RESEARCH.md` Open Question #5 — code-generated, no external dependency)
