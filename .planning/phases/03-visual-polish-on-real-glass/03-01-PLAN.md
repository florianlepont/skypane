## Phase Goal

**As a** person glancing at the frame on my wall, **I want to** see a real, airline-specific aircraft rendered in a poster-quality composition that stays legible on actual e-ink glass, **so that** the frame reads as ambient art I want on the wall rather than a data dump.

This plan delivers the first user-visible slice of that goal: the panel's typography and information hierarchy are realigned with the flightportrait reference product (D-14/D-15/D-16), and the preview palette is moved onto real-panel-approximate ink values so every later dithering decision is made against the right colours.

<objective>
Vendor the Zilla Slab slab-serif family, replace Inter across the whole render pipeline, and restructure the caption hierarchy so flight number and destination/origin become a co-equal hero pair with the airline name demoted to a distinct subordinate Caption role. Apply D-13's interim panel-RGB values to `PALETTE_RGB` in the same pass, because every subsequent plan's dithering quality depends on those triples.

Purpose: D-15 and D-16 are locked user decisions taken after directly comparing the shipped Phase 2 design against real flightportrait.com product photography. D-13's interim step is sequenced here (not later) because 03-02's mood background and 03-03's livery quantization both quantize against `PALETTE_RGB`.
Output: two vendored OFL TTFs with provenance, four typographic role constants in `render.py`, an Inter-free active render path, and updated `PALETTE_RGB` triples.
</objective>

## Empirically verified during planning — read before implementing

Three claims in `03-RESEARCH.md` / `03-UI-SPEC.md` were tested directly against this repo's Pillow 12.3.0 and `server/panel_format.py` during planning. Two are corrections; all three are load-bearing.

**F-01 — `Image.getcolors()` returns `(count, index)` pairs, not `(index, count)`.** `03-RESEARCH.md`'s Validation Architecture snippet (`set(idx for idx, _ in colors)`) has the tuple order reversed. Correct idiom: `sorted({value for _count, value in canvas.getcolors()})`. This affects 03-02 and 03-03 more than this plan, but is recorded once here.

**F-02 — the full-6-colour mood-background recipe in `03-UI-SPEC.md` does not satisfy its own Color contract, and is replaced in 03-02.** Measured directly at 1200x1600 with the D-13 interim triples: the arriving/green mood produced only 16-19% Green with 18-25% Yellow+Red — visual mud, not a green-dominant field. Resolution is specified in 03-02.

**F-03 — a non-binary alpha mask blends palette INDICES and invents illegal colours.** Pasting a P-mode image into a P-mode canvas through an `"L"` mask whose value is 128 produced index 2 (Yellow) from a source of index 1 (White) over index 4 (Blue). This directly contradicts `03-RESEARCH.md` Pattern 2's instruction not to hard-threshold the illustration's alpha mask. 03-03 hard-thresholds it.
</planner_findings>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Google Fonts / GitHub raw → repo working tree | A third-party binary font asset enters the repo and is subsequently parsed by Pillow inside the production render process. This is the only new boundary in this plan. |
| Vendored font asset → `ImageFont.truetype()` in the poll-cycle render path | A committed binary is parsed on every render; a corrupt file surfaces as a raised exception mid-cycle rather than at review time. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01-01 | Tampering | Font download from `google/fonts` | high | mitigate | Download exclusively from an immutable commit SHA resolved via the GitHub commits API, never from a branch ref; record that SHA plus a per-file sha256 in `server/assets/fonts/VENDOR.md`. A branch ref is a mutable pointer an upstream compromise or force-push could repoint; a pinned SHA plus digest makes any later substitution detectable by re-running the digest. Gated by the acceptance criterion requiring a 40-hex SHA and per-file `sha256` lines in `VENDOR.md`. |

The asset is developer-vendored and committed once — it is never fetched at runtime and never accepted from network input, so the residual exposure is a regression in a reviewed commit, which `poll_loop.py`'s existing "a failed cycle leaves the previously served panel intact" contract already absorbs. |
| T-03-01-03 | Spoofing | A typosquatted or mislicensed font family masquerading as Zilla Slab | medium | mitigate | The family name reported by the loaded font object must equal `Zilla Slab`, and the vendored `ZillaSlab-OFL.txt` must contain the SIL OFL 1.1 header — both are acceptance criteria. `03-RESEARCH.md` independently cross-referenced the licence against three sources.
