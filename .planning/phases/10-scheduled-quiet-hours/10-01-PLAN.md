Add `from datetime import datetime, timedelta, timezone` and `from zoneinfo import
ZoneInfo` to `server/device_config.py`'s import block, and the module constant
`QUIET_HOURS_TZ = ZoneInfo("Europe/Paris")`. `zoneinfo` is stdlib since Python 3.9 and
adds nothing to `server/requirements.txt` — that file must stay at Pillow + requests.
The timezone is deliberately hardcoded, not a per-installation setting (10-RESEARCH.md
Assumption A3: this device has exactly one fixed physical location).

Add `seconds_until_quiet_hours_end(now_utc, start_hm, end_hm)`. Copy 10-PATTERNS.md's
reference body — `local_now = now_utc.astimezone(QUIET_HOURS_TZ)`, the two
`int(x) for x in ...split(":")` unpackings, the two `local_now.replace(hour=..., minute=...,
second=0, microsecond=0)` anchors, the `(start_h, start_m) <= (end_h, end_m)` same-day
branch and the wrap-midnight `else` branch with its `end_today + timedelta(days=1)` —
with exactly TWO mandatory deviations, both of which must be called out in the
function's own docstring or an adjacent comment so a future reader does not "restore"
the reference version:

  (a) The final return subtracts in UTC, not in local time. Return
  `max(0, int((end_dt.astimezone(timezone.utc) - now_utc).total_seconds()))`, NOT
  `(end_dt - local_now)`. This is a correctness fix, verified numerically during
  planning: `end_dt` and `local_now` share the same `tzinfo` object, and Python's
  documented rule for subtracting two aware datetimes with the same `tzinfo` is to
  ignore the zone and subtract the wall-clock numerals — so the reference body returns
  the naive numeral difference, which is wrong by exactly one hour across a Europe/Paris
  DST transition. 10-RESEARCH.md's Pattern 2 claim that "subtracting two zoneinfo-aware
  datetime objects always computes the true elapsed duration" holds only for operands in
  different zones; converting `end_dt` to UTC first restores that property.

  (b) The parameter contract is documented as: `now_utc` MUST be a timezone-aware
  datetime; `start_hm`/`end_hm` MUST already have passed `_HHMM_RE`. This function is
  the arithmetic core only — it does no validation of its own, because plan 10-03
  duplicates it byte-for-byte across the vendor boundary and every byte it carries has
  to be reproducible there.

Return `None` when `now_utc` falls outside the window, including the `start_hm == end_hm`
case (which the same-day branch's `start_today <= local_now < end_today` test already
rejects for every instant — a zero-width window is never active; state that explicitly in
the docstring so it is not later "fixed" into an always-active window).

Document 10-RESEARCH.md Pitfall 2 as an accepted caveat in the docstring rather than
engineering around it: a window boundary configured inside the 02:00-03:00 transition
hour on the last Sunday of March or October resolves via PEP 495's default `fold=0`
semantics and can be up to an hour off for that one instant; no `fold=1` override is
added, because D-01's "never shorter than the base sleep" rule bounds the worst case to
one extra or one missing wake, twice a year, only for a boundary configured inside that
specific hour.

Add `quiet_hours_status(config, now_epoch)` — the convenience wrapper `server/poll_loop.py`
calls in plan 10-04, and deliberately NOT part of what plan 10-03 duplicates. It takes
`config`, a `load_device_config()` return dict, and `now_epoch`, epoch seconds as a float
(so `poll_loop.py` can pass its existing `now_s()` seam straight through and the poll-loop
harness's fake clock drives it for free). Returns a `(seconds_remaining, end_hm)` tuple,
or `(None, None)` when: `config` is not a dict, `config.get("quiet_hours_enabled")` is not
literally `True`, or `seconds_until_quiet_hours_end()` returns `None`. Re-normalise both
time strings through `normalise_quiet_hours_time()` before use, so a caller passing a
hand-built dict cannot slip an unvalidated string into the arithmetic. Build the aware
instant with `datetime.fromtimestamp(float(now_epoch), timezone.utc)`. Wrap the whole
body in a `try` that catches `(TypeError, ValueError, OverflowError, OSError)` and
returns `(None, None)` — this module's never-raise contract has to hold for a hostile
`now_epoch` too, and `poll_loop.py` calls this before it has rendered anything.
