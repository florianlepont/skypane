### `companion/layout.py` (new shared helpers: `relative_age_text()`, `absolute_and_relative()`)

**Analog:** `companion/pages/health_page.py`'s existing `_parse_iso()` / `_age_seconds()` / `_relative_age_text()` (lines 155-187), and this same file's own `status_dot()` (lines 151-161) as the "single escaped component builder, one obvious place to add a helper" precedent.

**Source to promote verbatim (health_page.py, lines 155-187):**
```python
def _parse_iso(ts):
    if not isinstance(ts, str):
        return None
    try:
        return datetime.fromisoformat(ts)
    except ValueError:
        return None


def _age_seconds(ts, now_ts):
    parsed = _parse_iso(ts)
    now_parsed = _parse_iso(now_ts)
    if parsed is None or now_parsed is None:
        return None
    return (now_parsed - parsed).total_seconds()


def _relative_age_text(age_seconds):
    age_seconds = max(0, int(age_seconds))
    if age_seconds < 60:
        return "%ds ago" % age_seconds
    if age_seconds < 3600:
        return "%dm ago" % (age_seconds // 60)
    if age_seconds < 86400:
        return "%dh ago" % (age_seconds // 3600)
    return "%dd ago" % (age_seconds // 86400)
```

**Target format to replicate (health_page.py lines 350-356, `_device_section()`):**
```python
ts = (device_health or {}).get("ts")
age = _age_seconds(ts, now)
detail = (
    "no reading yet" if ts is None
    else "%s (%s)" % (escape_html(ts), escape_html(_relative_age_text(age)))
)
```

**Placement rationale:** `companion/pages/__init__.py` forbids one page module importing another (`history_page.py`'s own docstring, lines 40-46, already documents this exact constraint — it duplicates `HEALTH_UNAVAILABLE_TEXT` for this reason). `companion/layout.py` is already imported by all four page modules (`from companion.layout import escape_html` / `import companion.layout as layout`), so it is the correct promotion target, not a new module.

**Import style already established** (layout.py header, lines 1-19): stdlib-only (`import html`), single-purpose helpers, each with a docstring stating its escaping/safety contract. New helpers should follow this same docstring convention (state whether the return value is pre-escaped or plain text — `_relative_age_text()`/`absolute_and_relative()` should return **plain text**, matching `status_dot()`'s label parameter convention where the caller/helper itself calls `escape_html()` on it, not on already-markup output).

**Signature note:** Keep `_battery_section(trend_rows)` a single-argument call — do not thread `now` through it as a new parameter (would break a sibling 06.5 plan's pinned grep assertion `_battery_section(trend_rows)`). ## Shared Patterns

### Single-escaping-choke-point discipline
**Source:** `companion/layout.py` module docstring (lines 1-15) and `escape_html()` (lines 43-55).
**Apply to:** All four page modules — every new/changed string must flow through `escape_html()` (or a `layout.*` builder that already calls it) before reaching HTML. `layout.absolute_and_relative()` returns plain (unescaped) text, matching `_relative_age_text()`'s existing plain-text contract — callers keep calling `escape_html()` on the result exactly as `_device_section()` already does.

### `_safe_query()` / `_DB_UNAVAILABLE` sentinel
**Source:** `companion/pages/health_page.py` lines 136-152, mirrored in `companion/pages/history_page.py` lines 65-74.
**Apply to:** No change needed by this phase — both files already guard database access this way; new timestamp formatting happens after the guard, not inside it.

### JS safety conventions (sink-safety, no network calls)
**Source:** `.planning/phases/06.5-.../06.5-01-PLAN.md` Task 1 (battery-trend.js constraints), reused as a design precedent for `config_page.py`'s inline script.
**Apply to:** `config_page.py`'s new `<script>` block only — `json.dumps()` for every Python value crossing into JS, `textContent`/`removeAttribute` only, no `innerHTML`/`document.write`/`eval`/`fetch`/`XMLHttpRequest`.

### Test harness convention: `EXPECTED_CHECK_COUNT`
**Source:** `companion/test_config_page.py` (line 49, currently 15), `companion/test_status_pages.py` (line 55, currently 25), `companion/test_view_pages.py` (line 60, currently 19) — each file's `return 0 if (passed == total and total == EXPECTED_CHECK_COUNT) else 1` pattern.
**Apply to:** Every new `check(...)` call added to any of these three files must be paired with incrementing that file's `EXPECTED_CHECK_COUNT` by the same amount, in the same commit (per RESEARCH.md Pitfall 3). Existing precedent: `test_config_page.py` lines 275-293 already exercise `poll_trigger_section(0)` (enabled branch) and `poll_trigger_section(17)` (disabled branch, remaining-seconds copy) — new checks for the `<script>` block's presence/DOM-ids and a sink-safety grep should extend this same file, same style.
