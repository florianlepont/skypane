# Phase 13 — UI Design Contract

> Visual and interaction contract for the two-step "resolve an unidentified flight" flow (Airlines' new resolve form + manual-resolutions management list, Health's re-worded read-only note + per-row deep link). Generated by gsd-ui-researcher (autonomous mode), verified by gsd-ui-checker.

This phase adds companion-web-only UI. No shadcn/component-registry ecosystem exists or applies here — `companion/` is a stdlib-only Python HTTP service serving hand-written, build-step-free HTML against `companion/static/style.css`. The shadcn gate is not applicable and was skipped for that reason, not bypassed.

Every token, class, and pattern referenced below is read from `.claude/skills/sketch-findings-skypane/SKILL.md` and its `references/` files, plus a direct read of `companion/pages/airlines_page.py`, `companion/pages/health_page.py`, and `companion/layout.py` at execution time (2026-09-05). This phase introduces the smallest number of new visual patterns that make D-01–D-14 legible, reusing every existing component vocabulary item it can.

No new `<form>`, no new `<button>` — D-10 is explicit and this contract does not reopen it. Two edits only, both presentation:

### 1. `_READ_ONLY_NOTE` (module constant, currently at line 352) — reworded

**Current:** "This list is read-only by design — resolving a prefix is a manual step done elsewhere, following the existing coverage-gap runbook."

**New:** "This list is read-only here — each row's Resolve link opens the Airlines page to name that prefix's airline (and add artwork, if it needs one)."

Rendered exactly as today: `<p class="text-body section-caption">{escaped}</p>`, no class change.

### 2. Per-row deep link — both representations

**Desktop table (`_registry_table_html()` / `_registry_row_html()`):** append a sixth column.

- `_REGISTRY_HEADERS` gains a sixth entry: `"Resolve"` (appended at the end — indices 0–4 used by existing card-label lookups are unaffected by an append).
- New sixth `<td>` per row: `<td><a href="/airlines?resolve={escaped-prefix}" aria-label="Resolve prefix {escaped-prefix}">Resolve</a></td>` — a plain `<a>`, never a `<button>` or a form. The `aria-label` is load-bearing: a screen-reader user tabbing a link list otherwise hears "Resolve" repeated once per row with no way to distinguish them.

**Mobile card (`_registry_cards_html()`):** append a new block after the existing secondary line, before the `<details>` disclosure — visible at rest, not hidden behind "More details" (this is the row's one actionable affordance, it must not require a tap-to-reveal first):

```html
<div class="data-card__action">
  <a href="/airlines?resolve={escaped-prefix}" aria-label="Resolve prefix {escaped-prefix}">Resolve this prefix</a>
</div>
```

`.data-card__action` is a new, minimal selector: `margin-top: var(--space-xs);` — no new colour, no new size, the link inherits the page's default link styling.

Link label differs deliberately between the two representations ("Resolve" on desktop, where the row's own Prefix cell already supplies context; "Resolve this prefix" on mobile, where the card is read as a standalone unit) — both carry the identical `href` and the identical `aria-label`.

### 3. `_SOURCE_ROWS` gains a fifth tuple (D-02) — copy only, no visual change

Renders through the existing `_stats_table_html()`/`_stats_cards_html()` machinery unchanged — no new class, no new colour, matches every other row's treatment exactly.

## Accessibility & JS-Free Degradation Notes

- **Zero JavaScript.** `<datalist>` is the only new interactive primitive and is fully native — no script required for suggestions, submission, or validation beyond the browser's own HTML5 `required`/`maxlength` constraint validation (server-side re-validation is mandatory regardless, per this codebase's existing "never trust the hidden field" discipline — see `13-RESEARCH.md` Pattern 3).
- **Every new state-changing control is a real `<form>`/`<button type="submit">`, every new navigational control is a real `<a>`.** No `<button>`-as-link or `<a>`-as-submit fakery, matching the project's closed rule.
- **`aria-label` on every "Resolve"/"Resolve this prefix" link** — required precisely because the visible link text is intentionally short and repeats once per table row (see Page Composition — Health above).
- **Autofocus on the Step A name field** — a deliberate, scoped use: the operator has just navigated here specifically to fill this one field, and no other page in this app currently uses `autofocus`, so this is a new but narrowly-justified pattern, not a precedent for using it elsewhere.
- **No colour-only signal.** The Superseded marker carries text ("Superseded"), not just colour or an icon — consistent with this app's Label-voice convention, which is always text, never colour-alone.
- **Every interpolated value passes through `companion.layout.escape_html()` exactly once**, at the point of interpolation — the airline name, the prefix, the callsign, and the `<datalist>` option values all carry operator- or ADS-B-sourced content and must go through this single choke point, no exceptions (V5 Input Validation / stored-XSS mitigation named in `13-RESEARCH.md`'s Security Domain section).

## Autonomous Decisions Log

Per `--auto` mode's instruction to record every call this agent made in place of asking. None of these touch a locked decision (D-01–D-14); all are genuinely open UI-detail choices `13-CONTEXT.md`/`13-RESEARCH.md` left to planning/UI-SPEC.

1. **Resolve-section placement and visual weight (Research Open Question 2).** Placed at the *top* of the Airlines page, above the filter bar and gallery, as a plain unhighlighted `.page-section` card (no accent border, no status modifier). Rationale: it only ever appears when the operator arrived with intent to act on it (via a deep link), so its position alone is the emphasis it needs; adding a coloured/accented treatment would mean extending the project's closed accent-reservation list for a one-off, task-scoped element.
2. **Management-list placement.** Placed at the *bottom* of the page, mirroring the `06.6.4.1-04` precedent of demoting the old diagnostics content into full-width stacked cards below the main content — this list is reference/cleanup material, not the page's primary purpose (the gallery is).
3. **No filter bar on the management list.** D-07 itself frames this list as "the smallest surface that makes D-06 mean something" — a filter control is discoverability chrome for a list expected to hold a handful of entries, not the 27-entry gallery or the potentially-many-entries Health registry both filter bars already serve.
4. **Delete has no confirmation dialog.** See the Copywriting Contract's Destructive-confirmation row for the full rationale (D-08's recoverability plus this codebase's zero-precedent-for-`confirm()` posture). If a future developer disagrees, the correct fix is a second confirmation *page* (GET before POST, JS-free) rather than a JS `confirm()` — this app has no client-side confirmation mechanism to reach for.
5. **Superseded marker uses the existing muted Label voice, not a warn/error colour.** A superseded entry is an expected, harmless outcome of the static table catching up — not a fault requiring the operator's urgent attention — so it does not warrant `--color-status-warn`/`--color-status-error`, both of which are reserved for genuine problem states elsewhere in the app (source faults, anomalies). Reusing the existing 70%-muted label voice (already used for the "Current" quiet marker on Settings' theme/runway pickers) keeps this app's semantic-colour vocabulary from growing for a state that isn't actually bad.
6. **Flash messages carry no interpolated dynamic content (name/prefix).** This project's existing `FLASH_MESSAGES` dict is a fixed key→static-string mapping (confirmed by reading every existing `FLASH_*` constant — none embeds a runtime value). Rather than inventing the first interpolated flash in this codebase, dynamic specifics (the airline name, the prefix) are shown in ordinary escaped page body text — the resolve section's own Step B heading ("Add an illustration for {name}") — which the page already re-renders fresh from server-side state per D-12's own "never from the query string" discipline.
7. **Step B offers an explicit "Skip" escape hatch.** Not required by any locked decision, but D-03's own logic ("no upload is asked for when the named airline already has artwork") implies uploads are optional by design; a dead-end two-step flow with no way to back out except abandoning the browser tab would contradict that spirit. The skip link costs nothing (Step A's work is already durably saved) and prevents the flow from reading as a forced two-step wizard.
8. **Resolve context block reuses `.data-card__details dl`'s exact declarations** rather than introducing a new definition-list visual pattern, by adding `.resolve-context` to that existing selector group. This is the single closest existing precedent (Health's own registry already renders first-seen/last-seen/example-callsign as a `dt`/`dd` pair inside a disclosure) and needs no new CSS values, only a wider selector.
