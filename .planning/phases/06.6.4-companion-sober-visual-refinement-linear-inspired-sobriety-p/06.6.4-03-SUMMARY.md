# Phase 06.6.4 Plan 03: Banner sobriety — flat surface, 3px edge, status dot Summary

**Replaced the banner system's 10% colour-wash background with a neutral card surface, hairline border, 3px coloured edge and a small status dot across all three severities, and reconciled Health's combined card-and-banner selector so it keeps its stacked block layout instead of inheriting the new flex row — plus a live WCAG AA guard for body text on the surface every banner and card now shares.**

## Accomplishments

- D-04: base `.banner` rule rebuilt as a flex row on `--color-dominant`, with a 1px hairline border and a 3px `border-left` edge (declared after the shorthand so it cannot be clobbered), the `color-mix` wash removed outright; a new `.banner::before` 6x6px status dot added as a presentational pseudo-element since the banner builders (`companion/layout.py`'s `flash_banner()`/`anomaly_banner()`) emit no dot element in markup
- All three severity modifiers (`.banner--anomaly`, `.banner--warn`, `.banner--flash`) reduced to `border-left-color` plus a sibling `::before` rule for the matching dot colour — each keeps exactly the colour it had before, only the wash-vs-dot mechanism changed
- D-04a: `.page-section.banner--anomaly` (Health's source-fault block, the only consumer) reconciled — edge narrowed 4px to 3px to match the new width, background moved from the wash to `--color-dominant`, and two new opt-outs (`display: block` plus a `.page-section.banner--anomaly::before { display: none }` rule) stop the block from inheriting the base banner's flex row and dot
- `companion/test_contrast_check.py` gained two `live_pairs` entries pinning body text (`#17191F` light / `#F1F3F6` dark) on the card surface (`#FFFFFF` light / `#151922` dark) to WCAG AA — `EXPECTED_CHECK_COUNT` 31 -> 33

## Decisions Made

- The flex-inheritance finding on the combined selector — documented as "the new finding, not something CONTEXT.md could have anticipated" in the plan's own Task 2 action block — was confirmed exactly as described during execution: `.page-section.banner--anomaly` is one specific selector combination sharing the cascade with the base `.banner` flex row, so both the `display: flex` and the `::before` dot reach it by inheritance without an explicit opt-out. Fixed with `display: block` (turns the flex row back off) and a scoped `.page-section.banner--anomaly::before { display: none }` rule (suppresses the inherited dot). Both are documented in the rewritten comment as scoped exceptions preserving D-04a's "container treatment only, never banner content" boundary — the source-fault block's own heading/paragraph content in `health_page.py` was never touched.
- `EXPECTED_CHECK_COUNT` before/after: real on-disk baseline was 31 (confirmed by reading the file before editing, not trusting the plan's own literal value), after adding two entries the true value is 33 — matches exactly (the plan explicitly warned against trusting any number written into it at planning time).
