<decisions>
## Implementation Decisions

### Buttons
- **D-01 — text buttons shrink from 44px to 30px, a deliberate WCAG 2.5.5 AAA touch-target trade-off the developer explicitly accepted after being shown it three times.** New values: `height: 30px` (was `min-height: 44px`), `padding: 0 12px` (was `0 var(--space-md)` / 16px), `font-size: 13px` (was `var(--font-body-size)` / 16px), add `font-weight: var(--weight-semibold)` (buttons currently carry no explicit weight), add `letter-spacing: -0.01em`, `border-radius: 6px` (was `var(--radius-control)` / 8px). This drops below the 44px floor `06.6.2` added for WCAG 2.5.5 (Level AAA); WCAG 2.5.8 (Level AA, the less strict criterion) only requires 24px, so 30px stays AA-compliant — the AAA floor is what's being consciously given up. `companion/test_contrast_check.py`/any touch-target-floor test asserting 44px on `button` needs updating to reflect this new intentional value, not silently left failing.
- **D-01a — primary button (`button[type="submit"]`) gets a subtual inset highlight instead of a flat fill:** `box-shadow: inset 0 1px 0 rgba(255,255,255,.14), 0 1px 2px rgba(18,21,27,.14)`; hover swaps to `inset 0 1px 0 rgba(255,255,255,.16), 0 2px 5px rgba(18,21,27,.18)` alongside the existing `--color-accent-hover` background swap. Dark-mode: same shadow values (they're neutral-black-based, not accent-tinted, so no per-theme override needed beyond what already exists).
- **D-01b — secondary/quiet buttons (base `button`, `.logout-form button`, `.dirty-bar__cancel`) move from "transparent + always-visible 1px border" to "near-invisible at rest, revealed on hover":** `background: rgba(23,25,31,.045)` light / equivalent low-opacity white wash in dark (use `rgba(255,255,255,.06)` as the dark-mode analogue — not previously specified live, planner's call to verify against real dark-mode contrast), `border: 1px solid rgba(23,25,31,.09)` light, hover → `background: rgba(23,25,31,.075); border-color: rgba(23,25,31,.14)`. Active/pressed state on both primary and secondary: `transform: translateY(1px)`.
- **D-01c — button-height token change ripples:** anywhere `44px` is hardcoded or referenced as the button height (comments, tests, `.dirty-bar` layout math, `.filter-bar` alignment) needs auditing — grep for `44px`/`min-height: 44px` across `companion/static/style.css` and update comments that assert "never reduce below 44px" for the specific `button`/`input`/`select` rules this phase touches, while leaving that guarantee genuinely intact for anything this phase does NOT touch (e.g. native `input`/`select` height is unchanged by this phase unless D-08 below says otherwise for the filter input specifically).

### Icon-only buttons
- **D-02 — `.copy-btn` (and any other icon-only action button) becomes visually 28×28px while keeping a real 44×44 hit area, via an invisible `::before` pseudo-element — no accessibility trade-off, unlike D-01.** New rule: `.copy-btn` (or a renamed/generalized icon-button class, planner's call) — `width: 28px; height: 28px; padding: 0; position: relative; border-radius: 6px; background: transparent;` plus `.copy-btn::before { content: ""; position: absolute; inset: -8px; }` (28px + 8px×2 = 44px effective hit area, centered). Hover: `background: rgba(23,25,31,.07)` light-mode equivalent (dark-mode analogue needed). This pattern generalizes to any other icon-only button this phase finds.

### Cards & surfaces
- **D-03 — shadow-at-rest (06.6.1's D-02 "visible relief" choice) is replaced by a hairline border at rest; the shadow now only appears on hover/interaction.** Applies to `.stat-tile`, `.page-section`, `.battery-trend-section`, `.runway-card`, and any other card currently styled `border: 1px solid transparent; box-shadow: var(--shadow-card);`. New rule shape: `border: 1px solid var(--color-border); box-shadow: none;` at rest, `:hover, :focus-within { border-color: transparent; box-shadow: var(--shadow-card-hover); }`. Border-radius on cards tightens from `var(--radius-card)` (10px) to 8px. `.stat-tile`'s existing `border-top: 3px solid var(--color-accent|status-*)` colour-coded top edge is UNCHANGED by this — it's a different property (`border-top`) from the general `border` this decision touches, and both coexist exactly as `.stat-tile`'s own existing comment already documents for the pre-06.6.1 hairline/shadow interaction.
- **D-03a — `.runway-card--selected`'s existing 2px accent border is unaffected** — it already overrides the general border with a real, always-visible signal; D-03 only changes the *unselected* card's resting treatment.

### Banners
- **D-04 — the 10% colour-wash background is replaced by a near-neutral surface + hairline border + a slimmer coloured edge + a small status dot, so colour becomes a punctual signal instead of a background wash.** New `.banner` shape: `padding: var(--space-sm) var(--space-md); border: 1px solid var(--color-border); border-left: 3px solid var(--color-accent);` (was 4px), `background: var(--color-dominant);` (was the `color-mix(...)` wash — remove that), `display: flex; align-items: center; gap: 8px;`, plus a `::before` 6×6px `border-radius: 50%` dot coloured the same as the left edge. Apply the same edge-colour swap to `.banner--anomaly` (`--color-status-error`), `.banner--warn` (`--color-status-warn`), `.banner--flash` (`--color-accent`) — each keeps its existing colour, only the wash/dot mechanism changes.
- **D-04a — container-only, not content:** this does NOT touch Health's banner content (the redundant detail-text list debate is out-of-scope, see above) — purely the container's visual treatment.

### Navigation
- **D-05 — `.sidebar-link` (and the equivalent mobile nav link rule) tightens from 44px/16px to 32px/14px, and the active-state signal drops from two cues to one.** New values: `height: 32px` (was `min-height: 44px`), `font-size: 14px` (was `var(--font-body-size)`/16px). `.sidebar-link--active` currently signals via BOTH a 2px accent left-border AND a 12%-accent-tint pill background — this decision drops the left-border, keeping only the tinted-pill background as the single active signal (`border-left` removed or set to `transparent` permanently). Add a quiet hover state for inactive links that doesn't exist today: `background: rgba(23,25,31,.045)` on hover (dark-mode analogue needed).
- **D-05a — OPEN QUESTION for the planner, not resolved live: nav-link font-weight.** The reference artifact used `font-weight: 500` for nav links, but this session separately closed the type system to exactly 2 weights (`--weight-regular` 400 / `--weight-semibold` 600) with a formalized "Emphasis" role (D-09 below) reusing existing sizes+weights rather than inventing new ones. A third weight token (500/"medium") for nav specifically would reopen that closure. Planner must pick one: (a) add `--weight-medium: 500` as a deliberate, documented third token used *only* for nav links, or (b) use existing `--weight-regular` (inactive links) / `--weight-semibold` (active link only) instead, dropping the artifact's exact 500-weight look. No live developer input exists on this specific fork — flag it back to the developer at plan-review time rather than guessing silently either way.

### Theme picker (segmented control)
- **D-06 — `.theme-form .theme-option` (currently 3 independent 44px bordered boxes, active = accent border+text unfilled) becomes one shared segmented-pill control.** New structure: a wrapping `.theme-form` container gets `border: 1px solid var(--color-border); border-radius: 8px; padding: 2px; gap: 2px;` (the individual button borders are removed); each `.theme-option` becomes borderless, `height: 28px; padding: 0 12px; font-size: 13px; border-radius: 6px; background: transparent; color: var(--color-text-muted-or-soft)` (this project has no existing "muted text" token — check for one or use `color-mix(in srgb, var(--color-text) 60%, transparent)` planner's call); `.theme-option--active` gets `background: color-mix(in srgb, var(--color-accent) 12%, transparent); color: var(--color-accent); font-weight: var(--weight-semibold);`. Same visual language as `.sidebar-link--active`'s new single-signal tinted-pill treatment (D-05) — reuse, don't reinvent.
- **D-06a — this is a markup change, not CSS-only:** the three `<button type="submit">` elements need a shared wrapping container that doesn't exist in today's `.theme-form` markup (currently a bare flex row with no shared visual boundary) — touches `companion/layout.py` (or wherever `.theme-form` is rendered) as well as `style.css`.

### Data table
- **D-07 — `.data-table` drops zebra striping (`tr.row-alt`) in favour of a hover-only row highlight, and the header moves from a solid-colour block to a quiet uppercase label.** New `th` rule: remove `background: var(--color-secondary)`, add `font-size: 11px; font-weight: var(--weight-semibold); letter-spacing: 0.06em; text-transform: uppercase; color: var(--color-text-muted-or-soft); padding: 0 var(--space-md) 10px; border-bottom: 1px solid var(--color-border);` (was `padding: var(--space-sm) var(--space-md)` on a filled background). `.data-table-wrap th`'s sticky positioning is UNCHANGED — still sticky, just restyled. Remove `.data-table tr.row-alt { background: var(--color-secondary); }` entirely (or leave the rule but stop applying the class — planner's call on the cleaner path given `history_page.py`/`airlines_page.py` currently compute `row_class = "row-alt" if index % 2 else "row"` server-side). Add `.data-table tbody tr:hover { background: color-mix(in srgb, var(--color-text) 4%, transparent); }` (or the project's existing convention for a subtle hover tint — check `.stat-tile:hover`/`.runway-card` patterns for the established idiom rather than inventing a new one). `td` padding increases from `var(--space-sm) var(--space-md)` (8px/16px) to `13px var(--space-md)` for more vertical air. `tbody tr:last-child td` loses its `border-bottom` (clean bottom edge, matching the reference artifact).
- **D-07a — NOT in scope:** adding new pill/dot treatments to specific column content (e.g. a neutral "State" pill, a `.dot`-based Corroboration column) was demonstrated in the reference artifact as an *example* of what the real `.dot`/`.dot-label` component can do inside a table row, not a mandate to add new columns or change History/Airlines' actual column set. Leave column content as-is; this phase only restyles the table shell (header/rows/borders/hover).

### Filter bar
- **D-08 — `.filter-bar__field input` tightens from 44px to 32px and loses its filled background; `data-filter-clear` softens from a bordered button to a quiet text link.** New input rule (scoped to `.filter-bar__field input`, not the global `input` rule — do not change native `input`/`select` height globally, only inside the filter bar): `height: 32px; padding: 0 10px 0 26px; font-size: 13px; background: transparent; border: 1px solid var(--color-border);` (was the global filled-secondary 44px style), with `:focus { border-color: var(--color-accent); }`. `.filter-bar__count` shrinks to 12px, muted colour. The Clear control: History's is currently `<button type="button" data-filter-clear>Clear</button>`; Airlines' is already `<a href="#{id}" data-filter-clear>Clear</a>` per an existing D-16 constraint ("read-only page has zero buttons"). **Planner must reconcile:** either restyle History's `<button>` to *look* like a quiet underlined text link (`background: none; border: none; text-decoration: underline; text-underline-offset: 2px; color: var(--color-text-muted-or-soft); font-size: 12px;` — a visual-only change, element stays a `<button>`) — the safer option since it doesn't touch History's existing accessibility semantics — or restyle both `<button>` and `<a>` variants to converge on identical CSS via a shared class. Do not change History's Clear from `<button>` to `<a>` without checking whether that breaks `list-filter.js`'s existing `click` listener wiring or any test asserting `<button>` specifically.

### Typography — Emphasis role (formalizes existing gap this session found)
- **D-09 — retire `--font-display-size` (24px) from `.stat-tile__value` and `.runway-card__number`; both move to the "Emphasis" role: existing Body size (16px) + `--weight-semibold`.** This isn't a new token — `.data-table th` already uses exactly this combination (Label 14px + semibold) as a precedent for "a size that already exists, made bold for emphasis." The rule change: `.stat-tile__value` and `.runway-card__number` drop `font-size: var(--font-display-size)` in favour of `font-size: var(--font-body-size)` (both keep `font-weight: var(--weight-semibold)`, already present). Check whether `--font-display-size` is still referenced anywhere else in `style.css` after this change — if not, it can stay defined (harmless, still a real token other future work might want) or be removed; not a hard requirement either way, planner's call.

### Explicit non-goals (confirm, do not silently change)
- **D-10 — typeface and accent colour are NOT part of this phase.** The developer was asked directly whether to also push toward Linear's actual typeface/colour language (Inter, near-monochrome) and never asked for that — the validated direction keeps `--font-serif` (Georgia stack) for headings and `--color-accent` (`#B13F16` light / `#FF8A5C` dark) exactly as `heading-color-consistency` (commit `01235a6`) left them. "Sober/Linear-inspired" in this phase means structural restraint (hairline over permanent shadow, flat banners, tighter density/sizing, single-signal active states) — not a rebrand.
- **D-11 — do not re-touch `--color-status-error`, `--color-status-warn`, `--color-status-ok`, `--color-accent`, or the serif/`legend` heading rule** — all already correct as of commit `01235a6`. This phase consumes those tokens, it does not revisit the values.
