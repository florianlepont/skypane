# Phase 06.6.4 Plan 05: Table Shell + Filter Bar Sobriety Summary

**Table headers went from filled color blocks to quiet uppercase labels (static and sticky alike), zebra striping was replaced by a hover-only row tint, and History's Clear button and Airlines' Clear link converge on one `[data-filter-clear]` CSS rule with zero markup changes to either page.**

## Performance

- **Duration:** ~20 min
- **Completed:** 2026-09-01T00:49:19+02:00
- **Tasks:** 3/3 completed
- **Files modified:** 2 (`companion/static/style.css`, `companion/test_view_pages.py`)

## Accomplishments

- D-07/D-07a: `.data-table th` lost its `background: var(--color-secondary)` fill and became an 11px, letter-spaced, uppercase, 70%-muted-text label row with a bottom hairline. `.data-table-wrap th` (the sticky rule) was edited in the same task — position/top/z-index untouched, but its `background` moved from the elevated secondary surface to `var(--color-canvas)`, so the header stays quiet even once a long table (History) is scrolled. `.data-table td` padding grew to `13px var(--space-md)`; a new `.data-table tbody tr:last-child td { border-bottom: none }` gives every table a clean bottom edge; a new `.data-table tbody tr:hover` rule adds a 4% text-tint row cue; the `.data-table tr.row-alt` zebra-stripe rule was deleted outright, with a comment explaining that the three server-side sites still computing that class name are deliberately left in place as inert markup.
- D-08: `.filter-bar__field input` is now a 32px, 13px-font, transparent field with a 1px border and a `:focus` accent edge, scoped so it never touches the global `input, select` rule's 44px floor used everywhere else in the app — `min-height: 0` is the load-bearing declaration that actually clears that floor. `.filter-bar__field .icon` shrunk to 14px so the glyph stops overlapping the input's own left padding. `.filter-bar__count` shrunk to 12px and picked up the same 70% muted-text strength used elsewhere. A single `.filter-bar [data-filter-clear]` rule (plus `:hover`) resolves D-08's Clear-control fork: History's `<button type="button" data-filter-clear>` and Airlines' `<a href="#..." data-filter-clear>` now render pixel-identically as a quiet underlined text link, with zero edits to either page module.
- Task 3 added a drift guard to `companion/test_view_pages.py` pinning the three-way contract Task 2's zero-Python-change resolution depends on: History's rendered output still carries `data-filter-clear`, `style.css` styles it via the attribute selector, and no competing class-keyed Clear-control rule exists. `EXPECTED_CHECK_COUNT` moved from its real on-disk baseline of 41 to 42.

## Decisions Made

- Sticky header background token: `--color-canvas`, chosen because History (the only table long enough for the sticky state to actually engage) renders directly on the page background rather than inside a card. RESEARCH.md flagged this as the one value in the phase never live-validated — if the in-card tables (Airlines, Health) read as a visibly mismatched strip against their white card surface once scrolled, the primary card surface token is the documented one-declaration fallback. This is an explicit item for the phase's closing verification checklist, not resolved in this plan.
- Left the alternating-row (`row-alt`) class computation in place at all three server-side sites (`companion/layout.py`'s `data_table()`, `history_page.py`, `airlines_page.py`) rather than removing it. The class becomes inert markup with no visual or functional effect; removing it would have required three Python edits and three harness updates for zero user-visible gain, contradicting this plan's stated minimal-blast-radius goal.
- Resolved D-08's Clear-control fork via the existing `[data-filter-clear]` attribute selector rather than introducing a new shared CSS class (the option CONTEXT.md/RESEARCH.md both assumed would be needed). The attribute selector reaches identical CSS output with zero Python edits, zero markup change, and zero risk of reopening Airlines' D-16 no-button-no-form constraint — the decisive point, since a shared class would have required adding it to two page modules.
