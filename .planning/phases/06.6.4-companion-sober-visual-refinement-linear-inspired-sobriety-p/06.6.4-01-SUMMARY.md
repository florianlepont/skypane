# Phase 06.6.4 Plan 01: Card hairline-at-rest + Emphasis type role Summary

**Reversed 06.6.1's shadow-at-rest card treatment to a hairline-border-at-rest/shadow-on-hover contract across all six card components, and retired the 24px display-size type role in favour of Body-size-plus-semibold (Emphasis) on its two consumers.**

## Performance

- **Duration:** 25 min
- **Started:** 2026-09-01T00:15:00+02:00 (approx.)
- **Completed:** 2026-09-01T00:22:05+02:00
- **Tasks:** 2/2 completed
- **Files modified:** 1 (`companion/static/style.css`)

## Accomplishments

- Retired `--font-display-size` (24px) entirely — deleted the token declaration and moved both of its consumers (`.runway-card__number`, `.stat-tile__value`) onto the Emphasis role (`var(--font-body-size)` + `var(--weight-semibold)`), restoring the typography scale's own claimed four sizes.
- Gave all six card components (`.runway-card`, `.history-card`, `.stat-tile`, `.battery-trend-section`, `.page-section`, `.login-card`) a hairline `var(--color-border)` edge at rest, `box-shadow: none`, and `var(--radius-control)` corners, with the shadow now revealed only on hover/focus-within.
- Scoped `.runway-card`'s hover rule with `:not(.runway-card--selected)` so a selected runway card's 2px accent border structurally cannot be cleared by hovering it (D-03a).
- Removed both now-redundant dark-mode card-edge override blocks; the `html[data-ui-theme="dark"]` variant would otherwise have outranked a bare `:hover` rule and pinned the border back on during hover for explicit-dark-mode users only.
- Rewrote every comment the change falsified: the file's own header ("Border is structural only..."), `.stat-tile`'s D-02 "do not restore the border" instruction, `.page-section`'s border/shadow-pairing explanation, `.runway-card`/`.history-card`/`.login-card`'s "reserves the width the dark-mode override colours in" sentences, and `.battery-trend-section`'s "two deliberate omissions" comment (now one, since the shadow-reveal omission it used to describe no longer applies).

## Files Created/Modified

## Decisions Made

- **`.login-card` inclusion:** Deliberately included as a full sixth member of the card set, not an oversight — it shares 100% of the resting-relief pattern with the other five, and the pre-auth login page would otherwise have been the one surface in the app still carrying 06.6.1's shadow-at-rest treatment after this plan.
- **Token retirement over deprecation:** `--font-display-size` was deleted outright (not merely stopped being referenced) because the `:root` scale block's own comment asserts exactly four sizes, and deleting the token is what makes that claim literally true again — matching the file's own established precedent (e.g. the `.runway-option` rule removal note) of deleting superseded declarations rather than leaving unreferenced bloat.
- **Dark-mode override removal, not specificity rework:** Both dark-mode card-edge override blocks were removed entirely rather than reworked to lower specificity, because leaving either in place — especially the `html[data-ui-theme="dark"]` attribute-selector variant, which outranks a bare `.stat-tile:hover` — would have silently pinned the resting border back on during hover for any user who explicitly picked dark mode via the theme picker, while `prefers-color-scheme` dark users saw the correct hover behavior. That per-theme divergence is exactly the class of bug this file's own comments exist to prevent.
