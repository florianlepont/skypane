## Nav-link font-weight — implemented as option (b), pending developer confirmation

CONTEXT.md flags this as the one genuinely unresolved fork in the phase and instructs the planner to pick one, document the rationale, and surface it for confirmation rather than deciding silently. This plan implements **option (b): reuse the existing two weights** — inactive links inherit `--weight-regular`, the active link declares `--weight-semibold`. No third weight token is introduced.

**Why (b):**
1. The same session that produced these decisions deliberately closed the type system to exactly two weights, and D-09 (plan 01) formalized the Emphasis role specifically as "an existing size made bold" rather than a new token. Adding a 500 weight for one component reopens that closure a week after it was made.
2. D-06's own already-locked value for the active theme segment is `font-weight: var(--weight-semibold)`, and D-06 explicitly instructs the theme picker to reuse the active nav link's visual language. Option (b) makes the two genuinely identical; option (a) would leave nav at 500 and the theme picker at 600 for the same "active" concept.
3. The reference artifact's uniform 500 on all nav links is a texture choice, not an active-state signal. Option (b) trades that texture for a stronger active/inactive weight contrast, which serves D-05's own single-signal goal.

**If the developer prefers option (a)** the change is a one-line addition of a `--weight-medium: 500` token in `:root` plus a `font-weight: var(--weight-medium)` declaration on both link rules — trivially reversible, and an explicit item on this phase's closing verification checklist. Do not implement (a) unless the developer asks for it.
</open_decision>
