  <behavior>
    - `load_device_config()` on a state dir with no config file returns a dict whose `calendar_theme_id` is `None`.
    - `load_device_config()` on a config file written before this key existed returns `calendar_theme_id` as `None` and every other key unchanged from its stored value.
    - `load_device_config()` on a config file whose `calendar_theme_id` is a non-member string, an int, a bool, a dict or `null` returns `None` for that key — never a theme id, never `DEFAULT_THEME_ID`, never an exception.

    - `save_device_config(state_dir, calendar_theme_id=<registered id>)` persists the id and carries every other field forward.
    - `save_device_config(state_dir, calendar_theme_id=<non-member>)` raises `ValueError` naming both the rejected value and the registry, and leaves a pre-existing file byte-identical.
    - `save_device_config(state_dir, theme=<id>)` with no `calendar_theme_id` argument leaves an already-saved `calendar_theme_id` untouched.

  <action>
Four edits to `server/device_config.py`, all additive. Do not change any existing key's contract, do not reorder the `new_config` dict, and do not touch `CLEAR_THEME_ARRIVING`.

**1. A read-path normaliser.** Add `normalise_calendar_theme_id(value)` immediately after `normalise_theme_arriving()`. Same body shape: return `value` when it is a string present in `THEMES`, otherwise `None`. Its docstring must state the contract in this module's own vocabulary — it degrades to `None`, never to `DEFAULT_THEME_ID`, and `None` here means *the operator has not chosen a theme for calendar matches, so a calendar match resolves to nothing and the manual rules run next*. Make the reasoning explicit, because it is the one thing a reviewer will want to challenge: degrading to the default would turn every calendar match into a repaint in the theme the panel was already using, which looks exactly like a broken feature and is indistinguishable from the frame simply not having matched — the honest inert state is "no calendar theme chosen".

**2. Wire it into the read path.** Add `"calendar_theme_id": normalise_calendar_theme_id(data.get("calendar_theme_id"))` to `load_device_config()`'s return dict, positioned directly after the existing `theme_arriving` entry so the two theme-override keys stay adjacent. Extend that function's docstring where it enumerates the keys and where it names the keys whose valid value set includes `None`: `calendar_theme_id` becomes the third such key, alongside `wake_interval_s` and `theme_arriving`.

**3. A write-path gate and a new keyword.** Add `calendar_theme_id=None` as the last keyword parameter of `save_device_config()`. In the validation block, beside the existing `theme_arriving` check, add a guard that raises `ValueError` when the argument is not `None` and not a member of `THEMES`, with a message naming both the rejected value and `THEME_IDS`, in the same wording style as the neighbouring raises. Place it before anything is written, so the all-or-nothing contract holds unchanged.

**4. Carry-forward in the write.** Add `"calendar_theme_id": calendar_theme_id if calendar_theme_id is not None else current["calendar_theme_id"]` to `new_config`, directly after `theme_arriving`. Extend `save_device_config()`'s docstring with a short paragraph recording the deliberate divergence: `theme_arriving` needed `CLEAR_THEME_ARRIVING` because its UI is a checkbox plus a grid and the checkbox is the only signal that distinguishes set from clear; the Calendar section (`16-UI-SPEC.md` § Section Anatomy) has no checkbox and a `required` always-rendered `<select>`, so there is no clear path to model, and this key keeps `None`'s single existing meaning of "not supplied, carry forward" — the same resolution `wake_interval_s` already has and for the same reason.
  </action>
