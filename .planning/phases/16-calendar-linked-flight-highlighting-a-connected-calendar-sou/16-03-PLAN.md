<objective>
Give `server/plane/calendar_rules.py` its storage tier: the environment-variable accessors for the calendar URL, the `{state_dir}/calendar_rules.json` registry file contract, D-03's rolling-window filter, and the throttle gate the 30-second poll oneshot needs because it has no in-process memory to hold a timer in.

Purpose: this is where **D-01** and **D-03** are actually implemented. D-01 says a calendar match never touches Phase 15's rule store, and the only way to prove that is a separate file with its own loader, written by its own writer. D-03 says the window is rewritten whole on every fetch, which is what makes expiry a property of the write rather than a cleanup job — and what bounds how much of a named person's schedule sits on the VPS at any moment. The throttle exists because `deploy/skypane-poll.timer` fires a fresh `Type=oneshot` process every 30 seconds, so "next fetch due" has to be durable on disk exactly the way `poll_state.json`'s `last_advance_at` already is.

Plan 16-04 adds the fetch that drives this tier; plan 16-05's Settings status line reads `last_synced_at` from it; plan 16-06's matcher reads its entries. Nothing here performs network I/O.

Output: one extended server module, one extended harness.
