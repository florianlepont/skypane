<objective>
Wire the calendar source into `server/poll_loop.py`: one throttled refresh per cycle, one match computed from settled inputs at the flight-detected render, that match persisted alongside the flight it describes, and both flight-displaying `build_canvas()` call sites resolving through it.

Purpose: this is the plan that makes the feature real, and it is also the plan that must not break Phase 15's hardest-won property. `T-15-10` and D-13 require the same flight redrawn on a later battery-icon or source-fault repaint to get the identical effective theme id — and a calendar match is the first input to the resolver that is a function of the clock, so recomputing it in the held branch would let a repaint hours later silently change the panel's colour. The resolution is the one this file already uses for the route: the held branch reuses what the flight-detected branch persisted. That makes the invariant hold by construction rather than by the two branches happening to agree.

Output: one modified controller, one extended harness. This is the phase's last code plan; `/gsd-secure-phase 16` follows.
</objective>
