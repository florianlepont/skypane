**`_reference_time(entry, render_state)`.** The moment a match is measured against: the entry's `start_at` for a departure (the aircraft leaves near off-blocks) and its `end_at` for an arrival (it lands near on-blocks). Returns `None` for any other state.

**`match_calendar_theme(registry, route, render_state, device_cfg, now)`.** Pure, never raises, returns a theme id or `None`. Its parameter list deliberately excludes both the flight dict and `route_source` — say so in the docstring and give the reason for each. The flight dict is excluded because nothing in D-04's key comes from it; the airline comes from the enriched route and the direction from the render state, and an unused parameter would invite a future change to start matching on the raw callsign, which measured finding 2 rules out. `route_source` is excluded because it is not meaningful at `poll_loop.py`'s second call site — the held/repaint branch reports `held` — so a source-string test would silently disable the feature on every repaint, while the field-presence test below is exactly equivalent and works identically at both sites.

Sequence:

1. Resolve the operator's chosen theme first: read `device_cfg["calendar_theme_id"]`, require a string that is a member of `device_config.THEMES`, and return `None` immediately otherwise. Doing this first means an unconfigured or tampered theme costs no comparison work at all, and it is the module's own share of T-16-TAMPER.
2. Require `render_state` to be one of the two confirmed flight states.
3. Require `route` to be a dict carrying all three of `origin_iata`, `destination_iata` and `callsign_iata` as non-empty strings, with both airport codes passing `_AIRPORT_IATA_RE`. Comment this as the encoding of CORRECTION 1's narrowing: these three fields exist only on a `fresh_hit` or a `cache_hit`, so this test is exactly the `route_source` restriction, expressed in a form that is still true at the held call site.
4. Derive the detected airline through `_airline_iata_from_route()` and the detected far end through `_far_end_iata()`; return `None` if either is missing.
5. Walk the registry's entries, skipping any that is not a dict or whose fields fail the same allowlists the loader applies. Keep an entry as a candidate when its `airline_iata` equals the detected airline, its own far end for this direction equals the detected far end, and the absolute difference between `now` and its reference time is at most `CALENDAR_MATCH_TOLERANCE_S`.
6. Return the theme when at least one candidate survives, choosing the candidate with the smallest absolute time difference. Break an exact tie deterministically — by the earlier reference time, then by the entry's own field ordering — so the result never depends on iteration order. State in the docstring why a single winner matters even though every candidate yields the same theme id today: it keeps the function honest about the physical fact that a flight is one aircraft, and it is what a future per-entry theme would need. Record the tolerance as this phase's resolution of a Claude's-Discretion point, with its reasoning: ninety minutes is generous enough to absorb an ordinary delay and far tighter than the roughly eight hours separating the measured twice-daily same-route rotations, so a same-route collision is never ambiguously close.

Guard the whole body so a malformed registry, route, config or clock returns `None` rather than raising — this function runs inside the poll cycle and must never become a new way for a render to fail.
