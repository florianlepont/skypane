<objective>
The Frame strip's two switches are forms with a submit button that navigates: press
it, the page reloads, the state is different. It works, it is honest, and it feels
like 2004. D2 asks for real `role="switch"` controls that flip under the finger and
reconcile with the server afterwards.

Purpose: the interesting part of D2 is not the fetch. It is that this app has three
contracts that all bear on one small control, and each one has already caused a
real defect. `/quick/*` answers a 303 with a flash, and `fetch` follows redirects
silently by default. `led_enabled` resolves an absent checkbox to False, so moving
it out of the settings form without changing that would switch the LED off on every
unrelated save — the regression D-12.1 records and 22-05 already fixed twice. And
X1 exists because one setting with two controls is a defect, so "add a switch" is
only correct if something else goes away.
Output: three switches that tell the truth, a form underneath each that still works
with scripts blocked, and one written finding where the fourth switch would have
required a decision nobody has taken.
</objective>

<decisions_covered>
D2, narrowed to three of its four switches on stated grounds. Its "JSON/204"
clause is honoured as 204 (there is nothing to send); its "toast instead of a
permanent banner" clause is built; its "300 ms spinner" clause is implemented as a
pending state with no fixed delay, because a deliberate 300 ms wait on a local
request makes a fast action feel slow and the pending marker is what the refresh
loop actually needs. The fourth switch is a FINDING, not a silent omission — see
Task 3. D-04/X1 (one control per setting) and D-12.1 (absent-checkbox semantics)
are locked and are honoured exactly.
</decisions_covered>

<no_js_floor>
This is the plan where the floor is most at risk, and Phase 22 already shipped the
failure once: a control that rendered with scripts blocked and silently did
nothing, caught only by the browser harness.

The floor here is structural, not additive. Each switch IS the `<form>` that
already ships today — `layout.frame_strip_html()` renders a real form per switch
with a `state` field and a `return_to` hidden field that `_handle_quick_toggle()`
validates against `{HOME_ROUTE, DISPLAY_ROUTE}`. The script does not create a
control; it intercepts the submit of a control that already works. Remove the
script and the button posts the form, the server saves, the 303 lands back on the
page it came from with its flash, exactly as today.

`role="switch"` and `aria-checked` are rendered by the SERVER from the saved
value, so the accessible state is correct on a scripts-blocked page too — the role
is not a promise the script keeps, it is a description of what the button does
either way.

The LED switch inherits the identical shape: a real form, its own `/quick/led`
route, the same `return_to` whitelist. Its no-JS path is a form post, and the
acceptance criteria prove it by submitting with scripts blocked at 360 px and
asserting the value persisted.

The toast is the one script-only surface, and it is additive: with no script there
is no fetch, so there is no failure that only a toast could report — the failure
path is the server's own flash, unchanged.
</no_js_floor>

Binding constraints:
- Content negotiation, not a new route shape. `/quick/*` answers exactly what it
  answers today for a form post. A fetch identifies itself with a request header
  (the same `X-Requested-With` convention `freshness.js` already sends) and gets a
  204 with no body. Do not change the redirect, the flash keys or the whitelist.
- `redirect: "manual"` on the client regardless, so a session that expired between
  page load and press cannot be read as success — the exact reasoning
  `freshness.js:525-533` already records.
- Rollback on `!response.ok` AND on a network error. A `.then()` with no `.catch()`
  is the warning sign `23-RESEARCH.md`'s Pitfall 5 names by shape.
- The failure message is the existing generic one. No server internal, no status
  code, no URL in user-facing text (V7).
- ES5 subset, no banned sinks, `textContent` only. `catch` is written in bracket
  form, the way the research's own example shows, because it is reserved in ES3.
- The pending marker goes on the region plan 23-06's swap skips, and is removed in
  BOTH terminal branches — never only the happy one.
