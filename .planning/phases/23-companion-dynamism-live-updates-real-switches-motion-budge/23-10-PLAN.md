<no_js_floor>
Three of the four clauses are pure CSS on server-rendered markup and are therefore
present, unchanged, with scripts blocked: the selection transition animates a
state the server also renders (`--selected` is the no-`:has()` and no-JS
fallback), the dialog entrance applies to native `<dialog>`s, and the skeletons
are a background treatment on an element the server already sizes.

The crossfade is the one script-adjacent clause, and it is an enhancement over
`theme-preview.js`, which is itself an enhancement: with no script the Frame
colours card renders its four panels always-visible and fully `<fieldset>`-wrapped
(Phase 21's stated floor), the theme chips are real radios inside a form, and
selecting one and pressing Save changes the theme. No preview swap happens, so
there is nothing to crossfade — and nothing renders that would do nothing.

The skeletons need one explicit guarantee, and it is the reason they are in this
plan rather than dropped: a skeleton that does not reserve the final size IS a
layout shift, which is worse than no skeleton. With scripts blocked the reserved
box and the image behave identically, because both are CSS and markup.
</no_js_floor>

  and is the warning sign `23-RESEARCH.md`'s Pitfall 6 names by shape.

  comment says so. If a transition appears to need a specificity change, it does
  not — state the property and the base rule instead.
