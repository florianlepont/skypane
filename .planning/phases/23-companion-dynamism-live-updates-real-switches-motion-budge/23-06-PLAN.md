<objective>
`freshness.js` is a good loop: a 45-second cadence, an exponential retry ladder to
a ten-minute ceiling, an in-flight guard, a visibility gate that makes a
background tab free, and a targeted swap that leaves untouched every region that
did not change or that holds the user's focus. It runs on exactly one page.

Home and the Frame strip are the two surfaces where a stale value costs the most —
the strip is where the frame's state is claimed, and Home is the page someone
leaves open. D1 says "reuse `freshness.js` on `/` and `/display`" and stops
there. What it does not say is how a script that swaps five hard-coded selectors
learns a second and third page's regions, what happens when a swap lands on a
half-edited settings form, or what happens when it lands between an optimistic
switch flip and the server's confirmation.

Purpose: answer those three, once, in a shape the next page can reuse for free.
Output: one registry, one page key, three skip rules, a picture that fades when
the picture actually changed, and a countdown that formats without deciding.
</objective>

| Boundary | Description |
|----------|-------------|
| browser → its own authenticated page, refetched | the loop fetches the page it is on, with credentials, every 45 seconds |
| fetched markup → the live DOM | server markup is parsed inert and grafted into a document the user is interacting with |
| an expired session → a refresh | a 303 to the login page must never be mistaken for fresh data |

|-----------|----------|-----------|-------------|-----------------|
| T-23-18 | Spoofing | an expired session's redirect rendered as live content | mitigate | unchanged from 22-15: `redirect: "manual"` makes the 303 an opaque, non-ok response that takes the retry branch and swaps nothing; now inherited by two more pages rather than reimplemented |
| T-23-19 | Tampering | a new DOM sink on two more pages | mitigate | the swap mechanism is unchanged — `DOMParser` + `importNode` + `replaceChild`, the one sanctioned path; no markup-writing sink is introduced and the ban list is pinned per file |
| T-23-20 | Denial of Service | three pages polling instead of one | mitigate | the same 45s cadence, the same visibility gate (zero requests from a hidden tab, proven by request counting), the same decreasing-rate retry ladder, plus a new stand-down while a form is dirty — strictly fewer requests per page than the ladder alone |

| T-23-22 | Information Disclosure | Display's form values refetched every 45 seconds | accept | the fetch is same-origin, same-session, and returns the page the user is already looking at; it is `no-store` and never persisted |
