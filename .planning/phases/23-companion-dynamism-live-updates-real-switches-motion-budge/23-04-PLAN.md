<objective>
Cross-document view transitions are the reason a build-free multi-page app can now
feel like a single-page one: one at-rule, three name declarations, zero JavaScript.
Chrome and Edge have had them since 126, Safari and iOS since 18.2 — both of the
design system's two reference devices, the Android at 360 px and the iPhone at
390 px. Firefox has not implemented them and gets today's behaviour exactly.

Purpose: this is the cheapest item in the whole phase and the only one that
improves the scripts-blocked experience as well as the scripted one. It carries
exactly one trap, and it is invisible: the global reduced-motion override matches
`*, *::before, *::after`, which matches ELEMENTS — and `::view-transition-old()`,
`::view-transition-new()`, `::view-transition-group()` and the `::view-transition`
root are a separate pseudo-element tree the universal selector never reaches.
Shipping this without its own opt-out gives reduced-motion users full-page
cross-fades on every navigation.
Output: one media-wrapped at-rule, three names that cannot collide, and two checks
that would have caught both mistakes.
</objective>

<decisions_covered>
D10 in full. The reduced-motion wrapper is D3's clause and is implemented here,
where the at-rule is, because `23-RESEARCH.md` establishes that D3 is a
PREREQUISITE of D10 rather than its peer and that the correct shape is a
conditional group rule around the at-rule — not an `animation: none` override on
the pseudo-elements, which would run the transition with a zeroed duration
instead of preventing it being set up at all. Plan 23-01 recorded the gap in the
stylesheet and wrote the guard that expects this plan to move the no-preference
count from zero to one.
</decisions_covered>

<no_js_floor>
This plan is the phase's one enhancement that is fully present with scripts
blocked. `@view-transition { navigation: auto }` is parsed and honoured by the
CSS engine and the navigation machinery; no script participates at any point. A
scripts-blocked Chromium gets the cross-fade; a scripts-blocked Firefox gets
today's instant navigation; neither gets a control that renders and does nothing,
because this plan renders no control at all. There is nothing to degrade and
nothing to fall back to.
</no_js_floor>

  The at-rule, exactly as verified to parse and be retained in the CSSOM in
  Chromium 151 this session (CSS View Transitions 2 §8.3.1 permits nesting an
  at-rule inside a conditional group rule):

      @media (prefers-reduced-motion: no-preference) {
        @view-transition { navigation: auto; }
      }

  And the three participants:

      .dashboard-sidebar    { view-transition-name: skypane-sidebar; }
      .page-title           { view-transition-name: skypane-title; }
      .preview-frame__image { view-transition-name: skypane-picture; }

Binding constraints:
- Names must be unique per document. `.dashboard-sidebar`, `.page-title` and
  `.preview-frame__image` each render at most once; a shared nav class does not.
  This is a HIGH-confidence structural fact with a MEDIUM-confidence consequence
  (the spec-level collision behaviour), which is exactly why it gets an assertion
  rather than a comment.
- Same-origin only, by spec. Nothing in this app navigates cross-origin from a
  page carrying the at-rule, so no additional gate is needed — but say so in the
  stylesheet comment rather than leaving it as an unstated assumption.
- Do NOT reach for `document.startViewTransition`. The same-document API is a
  different feature with a different support matrix and needs a script; the whole
  value of D10 is that it needs none.
- Do NOT add an `animation: none` override on the pseudo-elements as a second
  belt. The media wrapper prevents setup; an override that also existed would be
  the dead-code-not-a-safety-net pattern `references/accessibility-contrast.md:90`
  records, on a feature where it is also strictly weaker.
