<objective>
D14 asks for "one script updating every `<time data-relative>` each second".
`grep -rn '<time' companion/` returns nothing: this app has never rendered a
`<time>` element. Every relative age it shows — "3m ago", "il y a 3 min" — is
plain text baked into a span or a table cell at render time by
`layout.relative_age_text()`, and it is frozen from the moment the page loads
until something replaces the whole region.

Purpose: before anything can tick, there has to be something to tick. This plan
builds the element convention and the one server-side function that produces it,
and it does it in Python so the ladder keeps exactly one definition site. Pitfall
4 in `23-RESEARCH.md` is this codebase's most repeated failure — two next-wake
figures, two battery estimates, four surfaces that never got converted to Paris
time — and a client-side date formatter would be the fifth instance.
Output: a `<time datetime data-relative>` element with server-rendered text and
server-rendered French, a future form for the countdown plan 23-06 needs, and an
explicit written inventory of which visible ages become live and which do not.
</objective>

Binding constraints:
- The element is `<time datetime="<ISO>" data-relative>...</time>`. `datetime`
  carries the machine-readable instant (the same value `data-loaded-at` carries
  for the refresh loop); `data-relative` is the hook plan 23-05 queries. Nothing
  else goes in the element: no class that carries meaning, no state word.
- The visible text is produced by the SAME call the site makes today. If the
  rendered string changes for any input, the conversion is wrong — this plan is a
  wrapping, not a rewording. Pin it: for a representative set of ages the new
  function's inner text must equal `relative_age_text()`'s output exactly, in both
  languages.
- The FUTURE form ("in 4 min") is new copy and needs its own catalogue entry. It
  lives beside the past form in `companion/i18n_fr/health.py` and is produced by a
  new function in `layout.py` that shares the ladder's own thresholds — same
  module, same bucket boundaries, no second set of constants.
- The future form is FORMATTING, never a verdict. It says how long until a
  server-computed instant; it never says "late", "held", "due" or anything about
  the device's state. Those words stay server-rendered, and plan 23-06 wires the
  countdown beside them without touching them.
- `.time-value` is the time-value role (C5, Phase 22): sans, tabular numerals.
  A `<time>` element is semantic, not presentational — it does not replace
  `.time-value`, it can carry it. Monospace stays reserved for identifiers.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server-rendered timestamp → the DOM | an ISO instant now appears in an attribute a script will read |
| a raw-markup-producing function → its callers | a caller that escapes it again renders literal markup; one that forgets to escape an input opens an injection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-07 | Tampering | the new `<time>` element's `datetime` attribute | mitigate | the instant is server-computed and passed through `escape_html()` at the interpolation site, the same discipline every raw-markup producer in `layout.py` already carries; no value reaching it comes from a request parameter |
| T-23-08 | Information Disclosure | a machine-readable instant exposed in markup | accept | the same instant is already visible as text on the page and already present in `data-loaded-at`; it names no user and no secret |
| T-23-09 | Tampering | double-escaping or missed escaping at a converted call site | mitigate | the docstring states the raw-markup contract in the same words `concise_timestamp_html()` uses, and the harness asserts rendered output equality rather than substring presence, so a literal `&lt;time` would fail |
| T-23-SC | Tampering | npm/pip/cargo installs | n/a | this plan installs zero packages in any ecosystem |
</threat_model>
