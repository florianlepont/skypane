# Phase 06.4: Runway picker - show runway number and airport map - Context

**Gathered:** 2026-08-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Upgrade the companion web interface's runway picker (currently a plain text radio list — no runway numbers shown prominently, no visual/map representation at all) to show the runway number/heading clearly and a real airport diagram/satellite excerpt with the tracked runway highlighted, one image per runway. This phase is UI-only — it does not touch `server/plane/detect.py`'s actual runway-tracking logic (CFG-12, already shipped in Phase 6).

</domain>

<decisions>
## Implementation Decisions

### Map style and sourcing
- **D-01:** The "map" is a **real airport diagram or satellite excerpt** (not an abstract schematic), with the currently-tracked runway highlighted on it — chosen over a code-generated abstract diagram for accuracy.
- **D-02 (external dependency — blocking):** **The user will supply the image(s)**, not Claude. This phase cannot ship its visual centerpiece until that asset exists. The plan must not attempt to source, generate, or fetch a satellite/chart image itself.
- **D-03 (derived — how the phase stays executable without the asset in hand yet):** Ship with a **graceful fallback**: if a given runway's image file is absent at request time, render the (upgraded, number-prominent) text-only picker for that entry instead of a broken image. This means the phase's code can be planned, built, and verified now — the user can drop in image files afterward with zero further code changes. The plan should define a clear, predictable asset contract (e.g. one static image file per runway ID, named consistently) so "drop the file in and it works" is literally true.

### Claude's Discretion
- Exact file-naming convention and location for the runway images (should live alongside `companion/static/style.css`, i.e. `companion/static/`, following the existing static-asset serving pattern).
- Exact visual treatment for "highlighted" (outline, color overlay, arrow/label) on the runway image.
- Exact layout of the number/heading text relative to the image (before/after/overlaid).

</decisions>
