## Accomplishments
- `companion/app.py` gained a registry-bounded, never-raising `runway_images_available()` (mirrors `gallery_entries()`), wired into `page_context()` as `ctx["runway_images"]`
- `companion/pages/config_page.py`'s `runway_fieldset()` now renders each option's number/heading in `--font-display-size` type inside `.runway-option`, and conditionally emits an `<img>` — driven entirely by `ctx["runway_images"]`, never by filesystem access from this module
- A new session-gated, membership-validated `/runway-image/{id}.png` route in `companion/app.py`: validates the requested id against `device_config.RUNWAY_IDS` before any path is built (validate-then-join), returns an identical 404 for unknown ids and missing files, serves PNG bytes with a 300s cache
- `companion/static/RUNWAY-IMAGES.md` documents the D-03 drop-in asset contract (exact filenames, PNG-only, highlight-baked-into-the-file requirement, sizing guidance, deploy/auth notes)
- `companion/static/style.css` gained `.runway-option`/`.runway-option__number`/`.runway-option__image` rules, reusing only existing tokens (with a `--color-border` fallback so the rule is valid whether or not phase 06.3 has landed)
- The full phase ships and verifies with **zero image files** in `companion/static/` — the D-02/D-03 graceful-fallback state
