<objective>
CMP-09, part 1 of 4: introduce stable message IDs and migrate the shared (non-page) modules.
Rendered output stays byte-identical in both languages.

Mechanism (Claude's discretion on the ID scheme, recorded here):
- `class Message(str)` — its string value is the English text; `.msg_id` is the stable ID.
- `i18n.msg(msg_id, english)` returns a Message and records REGISTRY[msg_id] = english; a second
  declaration of the same ID with a different English raises ValueError (same English is idempotent).
- IDs are `<area>.<slug>` where <area> is the i18n_fr module holding the French today and
  <slug> is derived ONCE, at migration, from the English text by one deterministic rule shared
  by plans 40-12/13/14 (so two plans converting the two halves of one entry agree on its ID
  without coordinating): lowercase; every run of characters outside [a-z0-9] becomes "_";
  strip leading/trailing "_"; truncate to 48 characters at a "_" boundary; a "%s"/"%d"
  placeholder contributes nothing beyond the "_" separator; on a collision within one area
  append "_2", "_3" in the catalogue's current source order. Examples: "Home" -> "nav.home",
  "just now" -> "health.just_now", "%s ago" -> "health.ago". Once assigned, an ID never
  changes when the English is reworded — that is the point. Put the rule in
  test-support/i18n_ids.py as `slug_for(english)` (migration tooling, not production code),
  with a unit test in test-support/test_i18n_ids.py covering the three examples and a collision.
- Each i18n_fr module exports `MESSAGES = {msg_id: french}` instead of `CATALOG = {english: french}`.
- t()/t_lang(): English -> str(text). French, for a Message -> BY_ID[text.msg_id] if present,
  else the legacy English-keyed CATALOG entry for str(text) if its catalogue is not migrated yet,
  else str(text). French, for a plain str -> legacy CATALOG, else an English->French view derived
  from REGISTRY+BY_ID (so a plain-str call site whose string is now a registered Message still
  translates), else the str. These two fallbacks let the source half and the catalogue half of
  one entry migrate in different plans without a render changing; plan 40-15 removes both
  (plain str -> TypeError; a Message with no BY_ID entry fails the completeness test).
Recommended technique: write a one-off codemod in the session scratchpad (never committed) that
maps each English key of the three migrated catalogue modules to its ID and rewrites both the
catalogue and the constants that feed i18n.t/t_lang; review its diff by hand.
Coordination (Phase 39 runs in parallel and owns server/, stub-server/ and new shared modules):
before starting, run `git fetch origin && git log --oneline HEAD..origin/main`; if it lists
commits, merge origin/main first, keeping both sides' intent on conflict (Phase 39 may switch
companion imports to shared state_store / battery / quiet-hours modules). If the merge changes
any rendered page (test_render_baseline.py fails right after the merge), stop and report rather
than regenerating the baseline.
</objective>
