Ship the client half of D-02 — the static asset and the pre-auth route that serve it — one wave ahead of the markup that references it, so the page never emits a `<script src>` pointing at a 404.

This plan creates `companion/static/battery-trend.js`, the first JavaScript file this project has ever shipped. That is a deliberate, bounded decision, resolved here and not left open: **06.5-CONTEXT.md's flagged tension (no-JS vs. scoped-JS) resolves to scoped-JS.** A CSS-only `tabindex` + `:focus` approach was investigated (06.5-RESEARCH.md, Pitfall 1) and rejected as the *primary* mechanism because tap-triggered `:focus` on a non-native-control element (an SVG `<circle>` is neither a link nor a form control) is not reliable on iOS Safari — and D-02 explicitly requires tap on mobile, against `06-CONTEXT.md` D-22's mobile-responsiveness bar. Betting the phase's whole user-facing requirement on that gap is not acceptable. CSS `:hover` and the native SVG `<title>` tooltip are still implemented, as a free JS-independent desktop layer, not as a replacement.

Purpose: without a served script the interaction cannot exist at all, and without shipping it first the intermediate wave-1 state of the tree would render a broken asset reference.
Output: one new static file, four new CSS rules, one new pre-auth route mirroring `/static/style.css` byte-for-byte in structure, and one new automated check proving the route answers without a session.
