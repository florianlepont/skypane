# Phase 06.5 Plan 01: Battery-trend chart client asset and pre-auth route Summary

**Shipped the project's first JavaScript file (`battery-trend.js`) plus a pre-auth `/static/battery-trend.js` route mirroring `/static/style.css`, and four new CSS rules for the chart's tap/hover targets — one wave ahead of the markup that will reference them.**

## Performance

- **Duration:** ~25 min

## Accomplishments
- `companion/static/battery-trend.js`: a dependency-free, ES5-safe, IIFE-wrapped vanilla-JS file that reveals a chart point's exact mV reading and timestamp through `textContent` on click, mouseenter, focus, and Enter/Space — never through an HTML-writing sink, `eval`, or a network call. Returns early and harmlessly on every page without a `battery-readout` element, since it ships one wave ahead of the markup (plan 06.5-02) that will provide one.
- `companion/app.py`: `SCRIPT_ROUTE` + `_BATTERY_TREND_JS_PATH` constants and `Handler._serve_battery_trend_script()`, structurally identical to the existing `_serve_stylesheet()`, dispatched pre-auth in `do_GET()`. Serves `text/javascript` (RFC 9239) with a 300-second cache window, 404-ing cleanly on a missing/unreadable file.
- `companion/static/style.css`: `.sparkline-dot` (cosmetic, `pointer-events: none`), `.sparkline-hit` (transparent, enlarged tap target), `.sparkline-hit:hover`/`.sparkline-hit--active` (neutral-text hover/active fill, deliberately off the reserved accent colour), `.sparkline-hit:focus-visible` (accent focus ring), and `.battery-readout` (fixed-height reserved line so the first reveal never shifts the page).
- `companion/test_companion_app.py`: one new check proving `GET /static/battery-trend.js` answers 200 without a session cookie, with a `text/javascript` content type, a non-empty body, and `Cache-Control: max-age=300`. `EXPECTED_CHECK_COUNT` bumped 55 → 56.
