<objective>
Swap what the two existing accessors read, delete the environment variable outright, thread the throttle-bypass parameter through, and rewrite the ~52 test fixtures that used to configure this feature by mutating the process environment.

Purpose: after this plan the file plan 17-01 built is the only source of the calendar URL. Keeping the variable as a precedence-ordered override was considered and rejected — it buys a deployment the option of a secret that never touches disk, at the cost of two sources to test, a precedence rule to explain in the interface, and a state in which the field refuses what is typed into it. No data migration is needed because the variable was never set on the VPS, but the plan must not assume that silently: the template line comes out, and the Settings copy that interpolated the variable's name is rewritten rather than re-pointed.

This is the plan where the tree is briefly red. The accessor signature change and the constant's deletion break the four harnesses that depend on them, and the fixture rewrite is what makes them green again. The three tasks are therefore one atomic change and cannot be reordered or split across plans.

Output: two rewritten accessors, one deleted constant, one new function parameter, one rewritten copy string, one deploy template line removed, and four harnesses reconciled.
</objective>

**`server/plane/calendar_rules.py`.** Delete the `CALENDAR_URL_ENV_VAR` constant and its comment block. Rewrite both accessors to take `state_dir` as their first and only parameter.

`configured_calendar_url(state_dir)`: call `_calendar_secret_mode_is_safe(calendar_secret_path(state_dir))` first and return `None` unless it is `True` — the `is not True` shape, so both the absent case (`None`) and the drifted case (`False`) refuse without a second branch. Only then open the file, read it inside a `try` catching `OSError`, and return the stripped content or `None` when it is empty. The strip is not cosmetic: a value read back from a file, especially one a human may later hand-edit, picks up a trailing newline in a way an environment variable did not, and an unstripped URL fails the fetch in a way that looks like a bad feed.

`calendar_is_configured(state_dir)`: `return configured_calendar_url(state_dir) is not None`. The explicit identity comparison rather than a truthiness test on the return keeps the genuine-`bool` contract that D-08 depends on.

Rewrite both docstrings. The existing ones make claims that are now false and one that was already false: the claim that the value is "never returned to `companion/`" is true of `companion/`'s own module code and false of the companion's *process*, because `POST /poll-now` calls the poll cycle in-process and that cycle refreshes the calendar, which reads the URL. Say so plainly. The honest property is not a process boundary — none exists, all three systemd units run as the same user and load the same environment file — it is that no rendering, logging or flashing path touches the value. State that, and state that the companion now legitimately both writes and reads it.

Keep the fail-open register: an absent calendar is a designed, legitimate empty state in which the feature is simply off, not an authentication failure. Note in the docstring that a drifted-permission file resolves to the same `False`, and that the reason the operator is nonetheless told something different is a second, narrowly-scoped predicate — never a richer return type here.

In `refresh_calendar_registry()`, make three edits: add `min_interval_s=None` as the last parameter; pass `state_dir` to the internal `configured_calendar_url()` call; and pass `min_interval_s` through to the internal `calendar_fetch_is_due()` call. Relocate both internal call sites by grep rather than by any line number cited in the phase documents — the file has shifted since those were written. Extend the docstring's second no-network guarantee to say that `None` preserves the standard interval and is what the poll loop passes by omission, and that the only caller expected to pass anything else is the Settings save, which needs the throttle bypassed because connecting a calendar shortly after an unrelated sync must not silently do nothing for up to half an hour.
