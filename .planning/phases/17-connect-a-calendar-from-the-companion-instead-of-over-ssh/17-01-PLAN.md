<objective>
Build the secret file: a writer that creates it owner-only at creation time, a guard that refuses it when its permissions have drifted, and the erase-on-every-change behaviour that makes "disconnected" mean what the word promises. Nothing is wired to it yet — this plan is additive, and the existing accessors, the poll loop and the Settings page are untouched.

Purpose: this is the one place in the phase where copying the house pattern produces a security regression rather than correctness. Every state write in this repo goes through the same tmp-write-then-atomic-rename idiom and **not one of them sets a file mode** — they inherit the process umask, `0644` in practice. `deploy/provision.sh:76-77` adds `caddy` to the `skypane` group and sets setgid on the state directory, so a `0644` file there is readable by the internet-facing reverse proxy's own account. The environment file the URL lives in today is owner-only and escapes this entirely, which makes it the one genuine security regression available in this phase. The divergence has to be visible in the shipped code, not inferred from a plan document, and the suite has to contain a check that fails when the guard is removed — not merely one that passes when the writer is right.

Output: three new module-level names, two new functions, one new private helper, and a set of permission-bit checks in the existing harness.
</objective>
