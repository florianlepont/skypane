# Phase 06.6.2 Plan 06: Health Severity Derivation + Role-Aware Banners Summary

**A real `ok`/`warn`/`error` severity, derived once from Health's four existing D-14 signals with a documented precedence table (error always wins, warning-only states never escalate to red), now drives the sidebar nav dot, the mobile-nav dot, and the anomaly banner from one value — closing UXA-14's exact reproduced bug (a lone corroboration disagreement showing the same red "Something needs attention" chrome as a genuine device outage) — alongside `flash_banner()`/`anomaly_banner()` carrying the ARIA role (`status` vs `alert`) that matches their real severity instead of one role for every outcome (UXA-07).**

## Accomplishments

- `companion/pages/health_page.py` gained `overall_severity(device_state, pipeline_state, battery_state, disagreement_warn)` (a pure precedence function: any `"error"` wins; else any `"warn"`/`disagreement_warn` makes it `"warn"`; else `"ok"` — with the docstring explicitly excluding `_source_fault_block()`'s own signal from the precedence, a deliberate scope boundary) and `health_severity(state_dir, now=None)` (the `ctx["health_severity"]` source of truth, fail-closed to `"ok"`, routing through the exact same section builders `render()` uses so the nav dot and the banner can never disagree). `anomaly_active()` became a two-line thin wrapper (`health_severity(...) != "ok"`), its public signature unchanged. `ANOMALY_BANNER_TEXT` dropped only its leading `"⚠ "` glyph; the new `_anomaly_banner_text(severity)` prepends `"⚠ Warning: "` or `"⚠ Error: "`. `render()` now derives `severity` via `overall_severity()` and calls `layout.anomaly_banner(_anomaly_banner_text(severity), severity)`.
- `companion/layout.py`'s `_health_alert_markup(severity)` now takes the severity string and looks up the dot class via the existing `_STATUS_DOT_CLASSES` dict (reused, not duplicated) instead of a hardcoded `dot--error`. `sidebar_nav()`, `_mobile_nav_html()`, and `page_shell()` widened `health_alert`'s default from `False` to `None` and its gate from truthy-boolean to membership in `("warn", "error")`. `flash_banner(message, role="status")` validates `role` against a `{"status", "alert"}` whitelist (safe fallback to `"status"`) and emits `role="%s"`. `anomaly_banner(message, severity="error")` chooses `banner--anomaly`/`role="alert"` for `"error"` (preserving every existing no-keyword call site's prior meaning) or the new `banner--warn`/`role="status"` otherwise.
- `companion/static/style.css` gained `.banner--warn { border-left-color: var(--color-status-warn); }` immediately after `.banner--anomaly`.
- `companion/app.py` gained `FLASH_ROLES` (every `FLASH_KEY_*` mapped to `"status"` or `"alert"` — save-failed/poll-failed are `"alert"`, everything else `"status"`). `page_context()` replaced `"health_anomaly_active"` (boolean) with `"health_severity"` (from `health_page.health_severity()`) and added `"flash_role"` (from `FLASH_ROLES`). All six call sites that previously read `health_alert=ctx["health_anomaly_active"]` (the five do_GET page-route blocks plus `_render_tab()`) now read `ctx["health_severity"]`; all six `flash_banner(ctx["flash"])` call sites now pass `role=ctx["flash_role"]`.
- `companion/pages/__init__.py`'s ctx-contract docstring documents `health_severity` (renamed from the old boolean key, described in prose without repeating its literal old name) and the new `flash_role` entry.
- `companion/test_companion_app.py`'s pre-existing `_health_nav_notification_dot()` check was updated to the new severity contract (`health_alert=True/False` → `"error"`/`None`), and a new check (`_health_nav_notification_dot_warn_severity`) pins `health_alert="warn"` rendering `dot--warn` with zero `dot--error` anywhere in the document. `EXPECTED_CHECK_COUNT` 72→73.

## Decisions Made

- `ANOMALY_BANNER_TEXT` drops only its leading `"⚠ "` glyph, not its full text — this is what keeps every existing `health_page.ANOMALY_BANNER_TEXT in rendered` / `.count(...)` check in `test_status_pages.py` passing with zero edits to that file, confirmed by the plan's own verification step 3 (`git diff companion/test_status_pages.py` is empty).
- `collect_anomalies()` was left fully intact as the readable, greppable anomaly-list definition (`test_status_pages.py` still calls it directly) — only its use as `render()`'s presence-gate was replaced by `overall_severity()`, avoiding a second, cheaper reimplementation of the same rules.
