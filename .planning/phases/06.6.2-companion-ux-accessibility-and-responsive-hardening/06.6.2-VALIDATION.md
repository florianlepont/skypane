## Sampling Rate

- **After every task commit:** Run the specific `test_*.py` file(s) touched by that task
- **After every plan wave:** Run `scripts/run-all-tests.sh`
- **Before `/gsd-verify-work`:** Full suite green, plus a real browser/device check (keyboard walkthrough, screen-reader spot-check, viewport matrix, both themes) per `06.6.1-UX-AUDIT.md`'s own "Verification matrix" section — this phase's core value (does keyboard/screen-reader/narrow-viewport behavior actually work) cannot be verified by the markup-level automated suite alone, same limitation 06.3-05/06.6.1-06 already documented for this codebase
- **Max feedback latency:** ~45 seconds (automated); manual browser/device check is a separate, explicit checkpoint, expected as this phase's own closing Wave 4 per the audit's suggested implementation sequence

## Manual-Only Verifications

| Behavior | Requirement | Why Manual | Test Instructions |
|----------|-------------|------------|-------------------|
| Closed-menu accessibility-tree exposure (UXA-02) | D-06 (from 06.6.1) hardening | This harness asserts markup strings; it cannot observe the browser accessibility tree or actual Tab focus order | With the mobile menu closed, inspect the accessibility tree (DevTools or a real screen reader) — confirm none of the 5 nav links or 3 theme buttons appear; Tab from the hamburger toggle must land on the first focusable element in main content, not inside the clipped panel |
| Battery chart roving-tabindex keyboard model (UXA-11/D-13) | D-13 | Keyboard focus movement and Left/Right/Home/End behavior on an SVG chart cannot be asserted from markup alone | Tab to the chart (must be exactly one stop), then use Left/Right/Home/End and confirm the readout line updates and focus stays on the chart, never spilling into per-point Tab stops |
| WCAG AA contrast across both themes (UXA-04/D-14) | D-04, D-14 | Requires measuring actual rendered computed colors, not just the token values in source | Verify every normal-text/background pair used in Light, Dark, and Auto-resolved themes reaches ≥4.5:1 (research found a small pure-Python contrast-ratio script reproduces the audit's own published numbers — run it against the final shipped token values, not just the draft exploration palette) |
| Real viewport/theme/data-state matrix (all 18 findings) | Full phase | This codebase has no browser-automation test infrastructure (06.3-RESEARCH.md Pitfall 3, still true) | Walk the audit's own "Verification matrix" section (viewports 320-1920px, both themes × system-auto, the listed data states) in a real browser/device before closing this phase, mirroring 06.3-05/06.6.1-06's precedent |
| Production authenticated read-only walkthrough | Phase closing checkpoint | Requires the real deployed VPS and the developer's own credentials | Per the audit's own Wave 4: after automated + local checks pass, the developer authenticates in the production browser and walks all five pages read-only; any save/poll/logout action that changes real state is its own explicit checkpoint |
