## Issues Encountered

- **Safari + `Secure` session cookie over plain HTTP:** the developer's first login attempt (in Safari) against the local `http://localhost:8091` test instance appeared to silently fail ("je rentre le mot de passe, il n'est pas refusé, mais il ne se passe rien"). Root-caused: `companion/auth.py::session_set_cookie_header()` sets the session cookie with an unconditional `Secure` flag (`d9bd8fd`, Phase 6's original auth implementation — "Secure is unconditional because Caddy always terminates TLS" in production). Chrome grants `localhost` an exception allowing `Secure` cookies over plain HTTP; the developer's Safari session did not, so the server-side login succeeded (confirmed via direct `curl`, 303 redirect with a valid `Set-Cookie`) but the browser silently dropped the cookie, causing an invisible redirect-back-to-login loop. **Not a regression from this phase** — this exact behavior predates 06.6.2 entirely and is correct for the real production deployment (which is always behind Caddy's TLS termination). Resolved by switching to Chrome for local testing; no code change warranted or made.
- **Sidebar sticky false alarm:** see Accomplishments #2 — fully resolved as a wrong-URL testing mistake, not a defect.
