## Fixed Issues

### CR-01: Skip-to-content link target is not focusable, so it does not actually skip keyboard focus past the nav

**Files modified:** `companion/layout.py`, `companion/test_companion_app.py`
**Commit:** b202407
**Applied fix:** Added `tabindex="-1"` to `page_shell()`'s `<main id="main-content">` element so activating the skip link actually moves keyboard focus past the nav, per WCAG SCR28/G1. Updated the existing `_page_shell_renders_dashboard_shell_with_sidebar_and_dropdown_theme` assertion (which had asserted the old, non-focusable markup) and added a dedicated regression check, `_page_shell_skip_link_target_is_focusable`, asserting both the skip link's href and the target's `tabindex="-1"`. Verified against the full `test_companion_app.py` harness (80/80 checks pass, run under `server/.venv`, which has `requests` installed).

### WR-01: `nav-dropdown.js`'s open-transition callback can silently re-open the menu after a fast close

**Files modified:** `companion/static/nav-dropdown.js`
**Commit:** 6ab7159
**Applied fix:** Guarded the `requestAnimationFrame` callback in `setOpen(true)`'s non-reduced-motion branch with an `isOpen()` re-check before adding `OPEN_CLASS`, so a fast `setOpen(true)` → `setOpen(false)` sequence no longer lets the stale scheduled frame re-open a panel that has already been told to close. Kept the file ES5-safe (re-wrote an initial comment draft that accidentally contained the literal substring `let ` and tripped the file's own `nav-dropdown.js stays ES5-safe` regression check; the final wording avoids it). Verified: `node -c` syntax check plus the full `test_companion_app.py` suite, including the ES5-safety and DOM-contract checks, all pass.

### WR-02: Every response is missing baseline hardening headers

**Files modified:** `companion/app.py`
**Commit:** f5e8d23
**Applied fix:** Added a `_send_hardening_headers()` helper on `Handler` that sets `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, and `Referrer-Policy: same-origin`, and called it from both `send_html()` and `send_bytes()` (the only two response-emitting code paths in the file) before `end_headers()`. No existing tests asserted on response headers, so no test updates were needed; verified via syntax check and re-read of the modified block (the live-server `Harness`-based tests in `test_companion_app.py`, run under `server/.venv`, all continued to pass against the two modified methods).

### WR-03: Unauthenticated `POST /login` can block a worker thread indefinitely on a slow/lying request body

**Files modified:** `companion/app.py`
**Commit:** fa0a978
**Applied fix:** Added `import socket`, a `REQUEST_SOCKET_TIMEOUT_S = 30` constant, and a `Handler.timeout = REQUEST_SOCKET_TIMEOUT_S` class attribute (honoured by `socketserver.StreamRequestHandler`, which calls `self.connection.settimeout(self.timeout)`). Wrapped `read_form()`'s `rfile.read()` calls in `try/except socket.timeout`, degrading to an empty form on timeout — the same fallback already used for an oversized/undecodable body — rather than propagating and blocking the worker thread. Verified via syntax check and the full `test_companion_app.py` suite (80/80 pass under `server/.venv`).

### WR-04: Health severity is computed twice per Health page load from independent, non-atomic DB reads

**Files modified:** `companion/app.py`, `companion/pages/health_page.py`
**Commit:** 38f63d2
**Applied fix:** Introduced `health_page.compute_health_state(state_dir, now)`, which runs `_read_health_inputs()` and the four section builders exactly once and returns a dict carrying every value both the nav-dot severity and the full page render need (html fragments, per-signal states, `disagreement_warn`, and `severity`). Added `health_page.safe_health_state()` as the fail-closed wrapper (returns `None` on any unanticipated exception, mirroring the broad `except Exception` contract `health_severity()` previously implemented inline). `health_severity()` now delegates to `safe_health_state()`, preserving its existing "ok"-on-failure, never-raising signature for all existing callers (`anomaly_active()`, `test_status_pages.py`). `companion/app.py`'s `page_context()` now calls `safe_health_state()` exactly once per request and threads the result into `ctx["health_state"]` alongside the existing `ctx["health_severity"]`. `health_page.render()` reuses `ctx["health_state"]` when present, falling back to a fresh `compute_health_state()` call when it is absent (preserving standalone behavior for tests that build `ctx` directly without going through `page_context()`, e.g. `test_status_pages.py`'s `_ctx()` helper). Verified against the full `test_status_pages.py` (49/49), `test_companion_app.py` (80/80), `test_config_page.py` (39/39), `test_contrast_check.py` (16/16), and `test_view_pages.py` (30/30) suites, run under `server/.venv` (the interpreter with `requests` installed) — all pass with no changes needed to existing assertions.
