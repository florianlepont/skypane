# Phase 06.6.2 Plan 03: Structural High-Severity Hardening (UXA-01, UXA-02/UXA-12) Summary

**Guaranteed document-level overflow containment for populated History (body overflow-x: hidden plus defense-in-depth max-width clamps) and a `.js`-marker-class + native `hidden`-attribute state machine that makes the closed mobile nav genuinely absent from the accessibility tree/tab order while staying fully visible with no JavaScript at all.**

## Accomplishments

- `companion/static/style.css`'s `body` rule gained a guaranteed `overflow-x: hidden;` — the document itself can never scroll horizontally regardless of any descendant's layout quirk — plus two belt-and-braces clamps: `.dashboard-main`'s `max-width: 1440px` became `max-width: min(1440px, 100%)` with an added `width: 100%`, and `.data-table-wrap` gained `max-width: 100%` alongside its existing `overflow-x: auto`, closing UXA-01's measured 287px document-level overflow at 1440x900 with populated History.
- `companion/static/nav-dropdown.js` now adds a `.js` marker class to `<html>` as its very first statement (unconditional, even on pages with no dropdown), so `style.css`'s new `.js .mobile-nav`/`.js .mobile-nav--open` rules — the relocated clipping half of the panel's old base rule — only ever apply once client-side script has proven it is running. Without the `.js` class present at all, the base `.mobile-nav` rule renders the panel in its natural, unclipped, fully visible document flow (UXA-12's floor).
- `setOpen()` was rewritten so the native `hidden` attribute is the genuine accessibility-tree/tab-order boundary: opening clears `hidden` before animating in (a hidden element has no box to transition from, applied synchronously under `prefers-reduced-motion` or via `requestAnimationFrame` otherwise); closing removes the open class immediately and applies `hidden` only after the collapse transition completes (via a one-shot `transitionend` listener, or synchronously under reduced motion) — closing UXA-02's finding that a closed-but-still-focusable panel could be tabbed/read into without ever being seen.
- `companion/test_companion_app.py`'s `_dropdown_survives_with_javascript_disabled()` was rewritten in place per the plan's Pitfall 2 guidance: it now asserts the server-rendered panel carries no `hidden` attribute *and* the server-rendered `<html>` tag carries no `.js` marker class (the SSR-default-is-unclipped floor), rather than its old, now-incorrect assertion that no `hidden` attribute ever appears under any condition. A new check pins `nav-dropdown.js`'s `.js`-before-lookup string-index ordering and the `hidden`/`transitionend`/`matchMedia`/`prefers-reduced-motion` state machine, matched against `style.css`'s `.js`-scoped rules. `EXPECTED_CHECK_COUNT` 70 → 71.
