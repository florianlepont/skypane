<objective>
Close UXA-15: manual poll gets a real server-side mutual-exclusion guard around its check-run-mark sequence (never two overlapping poll cycles, an honest "already running" response for the loser) plus a client-side "Polling…" disabled-button affordance that is cosmetic only — the server lock is what actually prevents double-execution.

Purpose: `POST /poll-now` today checks cooldown, runs the full ADS-B poll cycle, and only then records that it ran — two requests arriving before the first finishes can both observe zero cooldown and both enter `run_once()`, hammering the free ADS-B aggregator APIs this project depends on and racing to write the same state.
Output: a process-global `threading.Lock` guarding `_handle_poll_now()`, a new honest "already running" flash outcome, and a small progressive-enhancement script disabling the trigger button on submit.
</objective>
