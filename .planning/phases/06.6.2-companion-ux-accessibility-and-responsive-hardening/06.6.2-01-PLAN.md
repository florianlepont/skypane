  <action>
Create `companion/contrast_check.py` as a new stdlib-only module (no imports at all — pure arithmetic). Implement exactly three functions plus two named threshold constants, matching this project's existing docstring density convention (see `companion/auth.py` for the house style):

- `_linearize_channel(value_0_255)`: converts one 0-255 sRGB channel to its linear-light value per the WCAG 2.x formula (`c = value/255`; if `c <= 0.03928` return `c/12.92`; else return `((c+0.055)/1.055) ** 2.4`).
- `relative_luminance(hex_color)`: strips a leading `#` if present, splits into R/G/B byte pairs, and returns `0.2126*R + 0.7152*G + 0.0722*B` where each channel has gone through `_linearize_channel`.
- `contrast_ratio(hex_a, hex_b)`: computes both luminances, orders them lighter-first, and returns `(L1 + 0.05) / (L2 + 0.05)`.
- `WCAG_AA_NORMAL_TEXT = 4.5`, `WCAG_AA_LARGE_TEXT = 3.0`, `WCAG_AA_UI_COMPONENT = 3.0` — named floors so callers never hard-code a bare `4.5`.

The module docstring must state: this is the WCAG 2.1 SC 1.4.3 relative-luminance/contrast-ratio algorithm reproduced from the published spec text, verified in `06.6.2-RESEARCH.md` to reproduce the audit's own numbers exactly; no external tool, no network call, no third-party library, matching this project's zero-external-dependency discipline. Do not accept a leading `#` requirement strictly — `relative_luminance()` must accept both `"E8622C"` and `"#E8622C"` (use `.lstrip("#")`).
  </action>
