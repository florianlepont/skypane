# Phase 06.6.2 Plan 05: Sidebar Control-Rail Treatment + Footer Sign-Out + POST /logout Summary

**Sidebar nav gains per-label icons, an aria-current-driven tinted-pill active state, and a sticky position; a new sidebar/mobile-nav footer region groups the theme picker with the app's first-ever visible Sign out control, submitting to `/logout` now moved from GET to POST; a skip-to-content link and local data-URI favicon close UXA-10's remaining completeness gaps.**

- **Started:** 2026-08-31T~08:20Z (approx, first task commit)
- **Completed:** 2026-08-31T~08:40Z (last task commit)

- **Files modified:** 4

## Accomplishments

- `companion/layout.py` gained five new `icon-nav-*` sprite symbols and `NAV_ICON_IDS` (slug -> icon-id), growing `ICON_IDS` from 5 to 10 members; `sidebar_nav()` now prefixes every link with its icon and adds `aria-current="page"` to the active link only.
- New `layout._logout_form_html()` (the shared `POST /logout` Sign out control) is now grouped with the theme picker inside a new `.sidebar-footer` wrapper (desktop, `page_shell()`) and `.mobile-nav__footer` wrapper (mobile, `_mobile_nav_html()`) — the first visible logout control anywhere in this app's UI.
- New `layout.SKIP_LINK_TARGET_ID`/skip-link markup renders as the literal first element inside `<body>` (before `ICON_DEFS_HTML`), and `<main>` now carries `id="main-content"`. New `layout.FAVICON_LINK_HTML` serves a local `#B13F16`-accent data-URI favicon with zero external file or route, interpolated into `page_shell()`'s `<head>` so 06.6.2-07's future `login_shell()` can reuse the exact same constant.
- `companion/static/style.css`: `.sidebar-link--active` now carries a `color-mix(in srgb, var(--color-accent) 12%, transparent)` tinted background and `var(--radius-control)` corners, with the left border reduced 3px -> 2px (kept, not removed, as a secondary cue). New `.sidebar-footer` (>=960px) and `.mobile-nav__footer` (<960px) rules supersede the old theme-form-only bottom-pinning/spacing rules on both renderers. `.logout-form button` overrides the accent-filled `button[type="submit"]` rule via **source-order** placement after it (both share equal `(0,1,1)` specificity — see Decisions). `.dashboard-sidebar` (>=960px) gained `position: sticky; top: 0`. New `.skip-link`/`.skip-link:focus` rules render the link off-screen until keyboard focus reveals it.
- `companion/app.py`: `/logout`'s branch moved from `do_GET` to `do_POST` (placed after `THEME_ROUTE`, no `require_session()` gate, matching the route's pre-move behavior and `THEME_ROUTE`'s own precedent) — a `GET /logout` now falls through to the 404 handler, closing T-06.6.2-09 (a stray prefetch/crawler/`<img src="/logout">`-shaped link could previously end an active session).
- `companion/test_companion_app.py`: renamed the existing logout-cookie check to `POST /logout`, added a new `GET /logout` now-404s check, and fixed three pre-existing regression checks that had baked in the old "exactly five" icon-set cap and the old id-less `<main>` tag shape — both superseded by this plan's own Task 1 changes, not regressions.

## Decisions Made

- Kept the 3px->2px left border on `.sidebar-link--active` as a secondary cue rather than deleting it, exactly as the plan specified — the audit's complaint was relying on the line *alone*, not the line's existence.
- `.logout-form button` and `button[type="submit"]` are both `(0,1,1)`-specificity selectors (one class + one element vs. one element + one attribute) — genuinely equal, not the higher-specificity relationship `.theme-form .theme-option`'s `(0,2,0)` precedent has. Verified this by first placing the override rule *before* `button[type="submit"]` in source order and confirming (by re-reading the cascade, not by rendering) it would lose; moved it to appear *after* `button[type="submit"]:hover` instead, which is what actually wins at equal specificity.
- Corrected `test_companion_app.py`'s three pre-existing checks that hard-coded the old five-icon whitelist cap and the old `<main class="page-content dashboard-main">` (no `id`) shape — both are this plan's own intentional Task 1 changes (D-17's icon-per-label requirement, UXA-10's skip-link target), not accidental regressions the checks should have kept guarding against.
