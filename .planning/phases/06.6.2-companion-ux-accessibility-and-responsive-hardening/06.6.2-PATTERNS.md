### `companion/static/style.css` — `.mobile-nav` rule (UXA-02/UXA-12, paired with the JS change above)

**Current pattern:**

```css
.mobile-nav {
  flex-basis: 100%;

  border-bottom-left-radius: var(--radius-card);
```

**Required change:** the `max-height: 0; overflow: hidden;` clipping rule (and its `transition`) must move under an `html.js` (or `.js`) ancestor selector — i.e. `.js .mobile-nav { max-height: 0; overflow: hidden; transition: ...; }` and `.js .mobile-nav--open { max-height: 420px; }` — so a no-JS browser (no `.js` class ever added to `<html>`) sees `.mobile-nav` in its natural, unclipped, fully-visible flow. **Also relevant — `.nav-notification` (lines 348-359)** is the precedent for "small CSS-only addition that composes with an existing class rather than inventing a fourth status colour" — same discipline applies to D-06's `accent-color: var(--color-accent)` addition to native radio/checkbox controls (Theme swatch, Runway cards' underlying input if still present, LED checkbox): add `accent-color: var(--color-accent);` to the existing selector(s) that already style those inputs, do not create new selectors.

### `companion/static/battery-trend.js` + `companion/pages/health_page.py::battery_sparkline_svg()` (UXA-11/D-13, roving tabindex)

**Analog:** itself — extend in place; markup-side analog is the file's own per-point loop.

**SSR baseline (health_page.py, around line 318, `<circle ... tabindex="0" ...>`):** every hit-target `<circle>` currently gets `tabindex="0"` unconditionally. This must become conditional — only the **last** (chronologically newest) point gets `tabindex="0"`; every other point gets `tabindex="-1"` (still focusable via JS, removed from the natural Tab order). `SPARKLINE_HIT_CLASS = "sparkline-hit"` (health_page.py line 159) is the class every point already carries — no new class needed for this change.

**Client-side (battery-trend.js):** the existing per-point closure loop (lines 78-105, already read in full) wires `click`/`mouseenter`/`focus`/`keydown` (Enter/Space only) listeners per point via `(function (point) { ... })(points[i])`. Add Left/Right/Home/End handling *inside the existing keydown listener* (do not add a second listener) that:
1. Computes a `targetIndex` from the pressed key relative to the closure's own `i` — note `points` here is a `NodeList` from `document.querySelectorAll(".sparkline-hit")`, chronological oldest→newest, matching `reveal()`'s existing DOM-order assumption.
2. No-wraps at the boundaries (silent no-op if out of range) — Claude's Discretion, documented in RESEARCH.md.
3. Moves the `tabindex` pair (`"-1"` on the old point, `"0"` on the new one) and calls `points[targetIndex].focus()`, which triggers the existing `focus` listener's `reveal()` call — no new reveal logic needed.
4. Uses `getAttribute()`/`setAttribute()`, never `dataset` (the file's own documented reason at lines 43-46: `dataset` on `SVGElement` has a narrower support floor than `getAttribute`).

**No new escaping surface** — same as the file's own header comment (lines 12-21): this only reads/writes `tabindex` attribute values and calls `.focus()`, no HTML-writing sink.

### `companion/app.py::_handle_poll_now()` (UXA-15, non-blocking lock)

**Analog:** `LOGIN_THROTTLE = auth.LoginThrottle()` (app.py line 131) — the existing "process-global singleton guard object, instantiated once at module scope" shape.

**Current handler (lines 643-659, already read in full):**
```python
def _handle_poll_now(self):
    state_dir = self.args.state_dir
    remaining = poll_cooldown_remaining(state_dir)
    if remaining > 0:
        return self.redirect(
            "%s?flash=%s" % (CONFIG_ROUTE, quote(FLASH_KEY_POLL_COOLDOWN)))
    try:
        poll_loop.run_once(state_dir=state_dir, geofence=self.args.geofence)
    except Exception:
        return self.redirect(
            "%s?flash=%s" % (CONFIG_ROUTE, quote(FLASH_KEY_POLL_FAILED)))
    mark_poll_triggered(state_dir)
    return self.redirect(
        "%s?flash=%s" % (CONFIG_ROUTE, quote(FLASH_KEY_POLL_TRIGGERED)))
```

**Required change:** wrap the entire body in a module-level `_POLL_LOCK = threading.Lock()` (declared near `LOGIN_THROTTLE`, line ~131) acquired with `blocking=False` at the very top; on acquire failure, redirect immediately with a new `FLASH_KEY_POLL_ALREADY_RUNNING` (added to `config_page.py`'s `FLASH_*` constants, rebound in `app.py` exactly like the existing four `FLASH_KEY_*` rebindings at lines 100-104, and added to `FLASH_MESSAGES` at lines 111-118). Release the lock in a `finally:` block. See RESEARCH.md Pattern 3 for the exact code (already verified against this file's current shape).

**Client-side cosmetic affordance (optional, non-blocking):** follows `config_page.py::_poll_cooldown_script()`/`_js_literal()`'s exact convention (see below) — a small inline `<script>` in `poll_trigger_section()` disabling the submit button on the form's `submit` event. ## Shared Patterns

### Escaping discipline
**Source:** `companion/layout.py::escape_html()` (lines 218-230)
**Apply to:** every new dynamic value in every file above — filter query echo, dirty-state bar copy, card labels, disclosure summaries. Single choke point; no page module reaches into stdlib `html` directly (layout.py's own docstring, lines 1-15).

### ES5-safe vanilla JS convention
**Source:** `companion/static/nav-dropdown.js` (full file, lines 1-93) and `companion/static/battery-trend.js` (full file, lines 1-110)
**Apply to:** every new/modified client script (`nav-dropdown.js` extension, `battery-trend.js` extension, new `table-filter.js`, config dirty-state bar's embedded script). No `let`/`const`/arrow functions/template literals; IIFE wrapper; early-return if target DOM elements are absent; no network calls, timers, or persistent state; attributes/classNames/hidden-toggling only — never an HTML-writing sink (so no escaping function is needed in any of these files, matching both existing files' documented rationale).

### Python→JS boundary escaping
**Source:** `companion/pages/config_page.py::_js_literal()` (lines 197-212)
**Apply to:** the dirty-state bar's embedded script and any other Python-value-into-`<script>` interpolation this phase adds — never `%`/f-string interpolation into a `<script>` body.

### Exact-membership allowlist for any redirect target
**Source:** `companion/app.py::_referring_tab()` (lines 504-511)
**Apply to:** UXA-03's `next` param validation (new `_validated_next_route()`) — never `startswith`/prefix/URL-parse a client-influenced redirect target.

### Process-global singleton guard object
**Source:** `companion/app.py::LOGIN_THROTTLE = auth.LoginThrottle()` (line 131)
**Apply to:** UXA-15's `_POLL_LOCK = threading.Lock()` — same "module-level, instantiated once" shape.

### Asymmetric read/write validation
**Source:** `companion/pages/config_page.py::handle_post()` docstring (lines 356-386) — read path forgives via `normalise_*()`, write path rejects the whole submission.
**Apply to:** any new POST handler this phase touches (none of D-01–D-23 add a new persistence endpoint besides the existing `/config`/`/config-led`/`/poll-now`/new `/logout`-as-POST) — D-03's dirty-state bar explicitly must NOT weaken this by adding a parallel JS-only save path (Pitfall 4).

### `_safe_query()` sentinel discipline
**Source:** `companion/pages/history_page.py` (lines 99-104) and `companion/pages/airlines_page.py` (lines 72-81) — near-identical helpers, `_DB_UNAVAILABLE = object()` sentinel distinguishing "query raised" from "legitimately empty".
**Apply to:** any new query path D-20's filtering touches — filter the result of `_safe_query()`'s success branch only, never bypass the sentinel check.
