<decisions>
## Implementation Decisions

**How these were captured:** the developer was offered a normal multi-area discussion and explicitly declined it — "rien, je veux que tu corriges l'ensemble des points de l'audit en suivant les recommandations ou tes propres décisions" (nothing to discuss, apply the audit's recommendations or your own judgment for everything). Every decision below therefore has an explicit rationale so the developer can override anything at plan/execute time without another discussion round. Findings that already carry a single clear "Recommended direction" in the audit (UXA-01's desktop-containment half, 02, 03, 04, 07, 09, 10, 12, 14, 15, 16) are NOT re-decided here — research/planning should follow the audit's own Detailed Findings sections directly for those.

### Language & terminology
- **D-01:** English-only interface. `<html lang="en">` and all copy stay English; no translation catalog is introduced. Rationale: the entire codebase, docs, and every shipped string are already English; the audit itself notes French-language collaboration on this project is not evidence the *product* must be French, and warns that partial/mixed-language chrome is worse than a consistent single language. Lowest-scope choice; revisit explicitly if the developer wants French later (own future decision, not silently mixed in).

### Shared control styling (from UXA-08 — the accent-color-token half; the heading-dedup half moved to 06.6.3)
- **D-06 (accent-color token half):** Establish `accent-color: var(--color-accent)` as the standard token applied to every native radio/checkbox control site-wide, after confirming contrast still holds, so they stop rendering browser-default blue against the terracotta system. This is a one-time global rule this phase ships; Phase 06.6.3's Runway cards, Theme swatch, and any other per-page controls consume it rather than re-deriving it.

### Auth & interactions
- **D-11:** `/logout` moves from **GET to POST**. Single-user tool, so the risk this closes is minor (a stray prefetch/crawler/link-scan GET-triggering a logout), but it's a small, correct fix consistent with "state-changing actions are POST," and the audit explicitly offered this as the follow-up phase's call to make.

### Visual foundation (folded back into scope 2026-08-31 — the developer explicitly overrode the audit's own recommendation to defer this)
- **D-14:** Color/surface system — adopt the audit's exploration palette (three distinct surface levels: canvas / primary card-and-control surface / secondary-elevated-nav surface, both themes) as the starting token set, but treat its exact hex values as a draft, not a lock: re-run the audit's own contrast measurements against whatever final values ship, since the audit explicitly labels its table "an exploration target, not a locked implementation contract." Dark mode gets real tonal elevation + a restrained border (not shadow-only, which the audit found doesn't read on an already-dark canvas).
- **D-15:** Typography hierarchy — add a distinct page-title role (~28-32px serif) above the existing 20px section-heading size, per the audit's suggested type scale; body/label/technical-metadata sizes follow the same table. Serif stays reserved for page/section titles and the wordmark (06.6.1 D-03's rule is unchanged) — card captions like "Device" stay sans-serif.
- **D-16:** Every authenticated page adopts one consistent page-header pattern: title, one-sentence purpose (only where the title alone isn't self-explanatory), freshness indicator on status/data views, at most one contextual action on the right. Replaces today's inconsistent "bare H1 on some pages, second heading immediately below on others." Implement as one shared, reusable component (e.g. `layout.page_header()`) — Phase 06.6.3's five pages all consume it.
- **D-17:** Sidebar refinement — active navigation renders as a low-contrast tinted pill/surface plus strong text (not only the current 3px vertical line), each nav label gets a small outline icon from the existing sprite, and the theme picker + logout (D-11) are grouped into a visually separated footer region at the bottom of the sidebar.
- **D-19:** Motion polish — 120-180ms color/border/shadow transitions on interactive state changes, the mobile menu's existing height/opacity transition keeps its reduced-motion path, save/refresh confirmations appear without layout jump. No bouncing, scale transforms, parallax, or animated gradients — the audit's anti-goals list stays a hard constraint even though the rest of the visual-direction section is now in scope.

### Operator efficiency accelerator (from UXA-18 — the shell-level half; per-page filtering moved to 06.6.3)
- **D-21:** The desktop sidebar becomes sticky, so navigation stays reachable on long pages (Health in particular, once Phase 06.6.3's per-page recomposition lands). Verify no nested-scrolling or 200%-zoom regression before shipping.

### Claude's Discretion
- Exact final hex values for D-14's palette, exact icon choices for D-17's nav-label icons — the audit gives a strong direction, not a pixel-locked spec; planning should propose concrete values and confirm visually (screenshots, both themes) before treating them as final, same discipline 06.6.1 already used.
- All findings the audit already gives a single "Recommended direction" for and that land in this phase (UXA-01's desktop-containment half, 02, 03, 04, 07, 09, 10, 12, 14, 15, 16) — implement per the audit's own text, no re-decision needed here.
- The shared foundation's exact public surface (`page_header()`'s signature, the severity function's name/return shape, the contrast checker's module path) — pick sensible, conventional names consistent with `companion/layout.py`'s existing style (`status_dot()`, `stat_tile()`); document them clearly in the plan and SUMMARY, since Phase 06.6.3 will need to reference them by their real names, not guesses.

## Existing Code Insights

### Reusable Assets
- `companion/layout.py::status_dot()`, `stat_tile()`, `icon_html()`/`ICON_DEFS_HTML` — the existing status/card/icon primitives every UXA finding's fix should compose with rather than duplicate.
- `companion/static/nav-dropdown.js` — the ES5-safe vanilla-JS pattern (`"use strict"` IIFE, no framework) this phase's new client-side bits (the mobile-nav closed-state fix) should follow.

### Established Patterns
- Every page module reads `ctx` computed once per request in `companion/app.py::page_context()` — cross-page signals (like 06.6.1's `health_anomaly_active`) are threaded this way, never via one page module importing another (`companion/pages/__init__.py` forbids it). D-11's logout change and the severity function likely follow this pattern.
- No-JS floor is a running project discipline (battery chart, poll-cooldown countdown, nav dropdown all ship a working no-JS fallback) — the mobile-nav fix (UXA-02/UXA-12) is specifically about a floor that currently fails this test.

### Integration Points
- `companion/app.py` — where D-11's `/logout` method change, UXA-03's login shell and deep-link return, and UXA-15's poll-concurrency lock land.
- `companion/static/style.css` — the single stylesheet every visual-consequence fix (D-06's accent-color token, D-14 through D-17/D-19/D-21, UXA-04's contrast tokens, UXA-01's desktop containment) lands in.
