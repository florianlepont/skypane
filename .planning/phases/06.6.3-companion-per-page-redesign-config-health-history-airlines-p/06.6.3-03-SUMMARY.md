## Accomplishments

- `led_fieldset()`/`led_section()`/`LED_HELPER_TEXT` renamed every user-facing "bring-up LED" string to "diagnostic LED" (D-02) — Python identifiers (`led_fieldset`, `LED_HELPER_TEXT`, `LED_CHECKBOX_VALUE`, `LED_ROUTE`) unchanged by name, a copy-only rename. `led_section()`'s duplicate `<h2>Bring-up LED</h2>` removed outright, leaving the fieldset's own `<legend>Diagnostic LED</legend>` as the section's sole accessible group name (D-06), matching its Theme/Runway siblings inside `.config-form`.
- `theme_fieldset(current_theme_id)` now branches on `len(device_config.THEME_IDS) == 1`: the single-theme branch (true today) renders a read-only `.theme-status` block with a two-chip `.theme-swatch` whose inline `background:#RRGGBB` values come from a new `_palette_hex(index)` helper — sliced directly from `server.panel_format.PALETTE_RGB`, never hardcoded — so a future re-tuning of the physical panel ink (07-01's own real-glass correction precedent) automatically updates the swatch too. The `len() > 1` branch keeps the original radio-group markup verbatim, unreachable today but exercised via a monkeypatched-registry test. `THEME_HELPER_TEXT` reworded from the internal "...once Phase 7 validates..." phrasing to "Additional themes will appear here once more are validated on real hardware." (UXA-05).
- `runway_fieldset(current_runway_id, images_available=())` rewritten to emit one `.runway-card` per `device_config.RUNWAY_IDS` entry: the entire `<label>` is the hit target/card, wrapping a visually-hidden (`.visually-hidden`, never `display:none`) native radio so keyboard/no-JS selection still works, an `icon-check` glyph (via `layout.icon_html()`) present on every card but shown only via the server-computed `runway-card--selected` modifier, and the existing conditional `<img>` wiring reused verbatim (`RUNWAY_IMAGE_ROUTE_PREFIX`/`RUNWAY_IMAGE_ALT_TEMPLATE`/`images_available`) — confirmed correct across 0/1/2/3 supplied images.
- `render()`'s Theme/Runway `<form>` gained `data-dirty-form` and a nested `.dirty-bar` (`hidden` by default, `data-dirty-bar`/`data-dirty-count`/`data-dirty-cancel`) sitting between the two fieldsets and the always-visible bottom `Save Settings` submit button — a genuine descendant of the same `<form>` (never a sibling/portal), so its own `<button type="submit">` submits natively with no `form=` attribute and no second endpoint. The bottom button is untouched — the unchanged no-JS fallback path.

## Decisions Made

- `runway_fieldset()` no longer wraps its cards in an outer `<fieldset>`/`<legend>` — matches the UI-SPEC's literal card markup (individual `<label class="runway-card">` elements, no wrapping group element) and the plan's own action text (cards + trailing `RUNWAY_HELPER_TEXT` paragraph only, no group heading specified). Each card's own visible number/heading label (e.g. "Runway 3 (07/25)") already carries the accessible name a screen-reader user needs per option; nothing in this plan's acceptance criteria requires a wrapping group name for the card set.
- `theme_fieldset()`'s read-only branch resolves `theme_id` as `current_theme_id if current_theme_id in device_config.THEMES else device_config.THEME_IDS[0]` rather than assuming `current_theme_id` is always the sole registry member — a defensive fallback (Rule 2) for correctness if a future caller ever passes a stale/unrecognised id, with no behavior change for any real call site today (the upstream `render()` value always comes from `normalise_theme_id()`-adjacent validated state).
- The global `input[...] { accent-color: var(--color-accent); }` rule 06.6.2-05 already shipped applies unchanged to the runway card's native radio inputs (D-06's own note to "confirm it applies correctly rather than re-deriving it") — no new accent-color rule was added, since the existing site-wide rule already covers every `<input type="radio">` regardless of its visual-hiding class.

**1. [Rule 1 - Bug] Corrected Task 2's own inline `<verify>` script's `class="runway-card` substring-count bug**

- **Issue:** The plan's own `<verify>` script asserts `out2.count('class="runway-card') == 3`, but `class="runway-card` is also a string prefix of `class="runway-card__number"`, `class="runway-card__check"`, and `class="runway-card__image"` — none of which exist in `runway_fieldset("3")`'s actual output (that call has `images_available=()`, so no `__image` spans render), yet `__number` and `__check` spans render on every one of the 3 cards, inflating the literal count to 9.
