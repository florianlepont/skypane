## Accomplishments
- `_confirmed_state_label(raw)`/`_runway_label(raw)` map `runway_events`' real raw values (`"departing"`/`"arriving"`, and `RUNWAY_IDS` members like `"3"`) to human presentation labels ("Departing"/"Arriving", "Runway 3 (07/25)"), with a title-cased/underscore-stripped fallback for anything else and never the literal word "None" for a falsy value — closes UXA-05 using the RESEARCH.md Pitfall 1-corrected real values, not the audit's incorrect `on_runway`/`approaching`/`departed` guesses.
- `_history_cards_html(formatted_rows, now)` builds the D-07 mobile compact-card representation (`ul.history-cards` → `li.history-card` per flight) from the exact same `formatted_rows` list `_history_table_html()` consumes — never a second independently-derived data pass. Each card's primary line (callsign + concise time) and secondary line (route + state) surface the four most-scanned fields; a native `<details>` disclosure reaches the remaining three (aircraft/airline, corroboration, runway) plus a duplicated Callsign row and Hex/Full-timestamp rows that also host the D-23 copy buttons.
- `render()` emits the mobile cards as a DOM sibling immediately before the desktop table — required by `06.6.3-02`'s `.history-cards ~ .data-table-wrap` sibling-combinator CSS toggle to correctly hide/show the right representation at each breakpoint. An empty History still renders only the unchanged `empty_state()` block, no empty `<ul>` alongside it.
- `layout.concise_timestamp_html(row["raw_ts"], now)` now drives both the desktop Timestamp `<td>` and the mobile primary-line time — byte-identical markup for the same row, verified directly at implementation time. `format_event_row()` gained a `raw_ts` key (the unformatted ISO string) alongside the pre-existing plain-text `ts` key, which no renderer uses for the visible timestamp any more.
- `_filter_bar_html(total)` renders D-20's filter bar (`data-filter-input`/`-count`/`-clear`/`-empty`, exactly one each), skipped entirely when there are zero rows. `_filter_text_attr(row)` computes the escaped, lowercased `"{callsign} {hex}"` pair once per row, applied identically to the desktop `<tr>` and the mobile `<li>` for `list-filter.js` to match against.
- `_copy_button_html(value, label)` + a new dedicated `_callsign_hex_cell()` give the desktop Callsign+Hex column 2 copy buttons (callsign, hex) — the general-purpose `_merged_cell()` (still used by Type+Airline) is untouched and carries zero copy buttons, confirmed by a regression check. The mobile details region carries all 3 (callsign, hex, full timestamp), each immediately followed by its `data-copy-feedback` sibling per `copy-button.js`'s exact contract.
- `companion/test_view_pages.py` grew 30→35 checks: 5 new (filter bar markers present-once, `data-filter-text` on both representations, desktop 2-copy-button + feedback-sibling shape, mobile 3-copy-button + feedback-sibling shape, presentation labels re-asserted against the full `render()` output) plus 2 pre-existing checks fixed in place for this plan's own intentional behaviour changes (not counted as new).

## Decisions Made
- `raw_ts` was introduced a task early (Task 1, not Task 2) — Task 1's own mobile-card acceptance criteria already required a findable full-ISO-timestamp substring in the details region, which needs the true raw value ahead of Task 2's formal introduction of the key. No behavioral gap: Task 2 still does the work its own action text describes (threading `raw_ts` + `now` into `concise_timestamp_html()` for both renderers' visible timestamp slot).
- All three mobile copy buttons (callsign, hex, full timestamp) live inside the `<details>` disclosure, including a new Callsign dt/dd pair that duplicates the already-visible primary-line callsign text. This was chosen over placing the callsign copy button on the primary line itself (as the UI-SPEC's illustrative markup shows) because Task 3's own acceptance criteria explicitly requires "the mobile detail region containing three copy buttons" — the task's acceptance criteria is authoritative over the UI-SPEC's illustrative sketch.
- The filter bar renders only when `formatted_rows` is non-empty, matching this codebase's existing "no chrome with no data" precedent (the table/card renderers already skip their own markup for zero rows) — not required by any single acceptance criterion, but consistent with the file's own established discipline.
