# Phase 06.6.3 — UI Design Contract

> Visual and interaction contract for the per-page recomposition of Config, Health, History, Airlines, and Preview. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase **evolves** the shipped companion design system (06.3 → 06.6.1 → 06.6.2), it does not replace it. Every token, component builder, and CSS class named below that already exists in `companion/layout.py` / `companion/static/style.css` is a **reuse**, not a re-derivation — do not redefine `--color-accent`, `--space-*`, `page_header()`, `stat_tile()`, `status_dot()`, `data_table()`, `empty_state()`, `flash_banner()`, `anomaly_banner()`, `icon_html()`/`ICON_DEFS_HTML`, `sidebar_nav()`, or the sidebar footer region. This document only specifies what is genuinely **new** for this phase's nine per-page decisions (D-02 through D-05, D-06's heading-dedup half, D-07 through D-10, D-12, D-13, D-18, D-20, D-22, D-23) plus this phase's owned audit findings (UXA-01's mobile half, UXA-05, UXA-06, UXA-08's Config half, UXA-11, UXA-13, UXA-16, UXA-17, UXA-18).

## Foundation Already Shipped (06.6.2) — consume, do not redeclare

Read `companion/layout.py` and `companion/static/style.css` directly before planning; do not guess these shapes. Confirmed live by `06.6.2-VERIFICATION.md` (17/17 must-haves):

- **Tokens**: `--space-{xs,sm,md,lg,xl,2xl,3xl}`, `--font-{label,body,heading,page-title,display}-size`, `--weight-{regular,semibold}`, `--font-{ui,mono,serif}`, `--radius-{card,control}`, three-level surface system `--color-{canvas,dominant,secondary,border}`, `--color-{accent,accent-hover,destructive,text,status-ok,status-warn,status-error}`, `--shadow-card{,-hover}`. All defined for light (default), `prefers-color-scheme: dark`, and the explicit `html[data-ui-theme="light"|"dark"]` overrides.
- **`layout.page_header(title, purpose=None, freshness_html=None, action_html=None)`** — literal signature contract. This phase's D-12 freshness signal and Config's dirty-state action both plug into this function's existing `freshness_html`/`action_html` parameters — do not build a second, parallel header element.
- **Sidebar**: `sidebar_nav(active, health_alert=None)`, tinted-pill active state, per-link icons via `NAV_ICON_IDS`, sticky at ≥960px, footer region (`sidebar_footer`) grouping the theme picker + `Sign out`.
- **Severity**: `health_page.overall_severity()` / `health_severity()` / `compute_health_state()` / `safe_health_state()` — `"ok"`/`"warn"`/`"error"`, threaded once per request into `ctx["health_state"]`/`ctx["health_severity"]`. This phase's Health recomposition reuses this precomputed state; it must not re-derive severity a second time.
- **`companion/contrast_check.py`** — pure-stdlib WCAG contrast checker. Any new color pairing this phase introduces (filter input focus ring, disclosure summary marker, copy-button success text, freshness banner) must be checked against it before shipping, same discipline 06.6.2 used for its own token rework.
- **Breakpoint**: exactly one, `@media (min-width: 960px)`. Below it: fluid single column, header hamburger + push-down dropdown. At/above it: `.dashboard-shell` sidebar grid. This phase introduces no second breakpoint.

## New Component Contracts

Every builder below follows the existing `companion/layout.py` discipline: escape captions/labels via `escape_html()`, accept already-safe markup verbatim (never re-escape it), whitelist-then-render for anything icon/class-name-shaped, never raise on malformed input.

### New icons (extend `ICON_IDS` from 10 → 14)

All four follow the sprite's existing visual language exactly: `viewBox="0 0 20 20"`, `fill="none"`, `stroke="currentColor"`, `stroke-width="1.5"`, `stroke-linecap="round"`, `stroke-linejoin="round"`, built from `<path>`/`<line>`/`<circle>`/`<rect>` primitives only — no detailed illustration, matching `icon-device`/`icon-pipeline`/etc.'s existing minimalism.

| Icon id | Concept | Used by |
|---|---|---|
| `icon-check` | A simple checkmark stroke | Selected Runway card (D-05), paired with the visually-hidden "Selected" text |
| `icon-copy` | Two overlapping rounded rectangles (the standard "copy" glyph shape) | Copy-to-clipboard buttons (D-23) |
| `icon-refresh` | A circular arrow (open circle with an arrowhead at one end) | The Refresh action on Health/Preview (D-12) |
| `icon-search` | A magnifying glass (circle + short diagonal line) | Inside the History/Airlines filter inputs (D-20), purely as a leading visual affordance — never load-bearing (the `<label>` carries the real accessible name) |

### Native disclosure (no new JS)

Use `<details>`/`<summary>` for **every** collapse/expand this phase needs — the Battery readings table (D-08), the History mobile per-card detail region (D-07), and no custom JS toggler for either. This is a deliberate choice over a JS-driven accordion: it is keyboard- and screen-reader-operable for free, degrades correctly with JavaScript disabled (the project's running no-JS-floor discipline), and needs zero new script file.

```html
<details class="readings-disclosure">
  <summary class="text-body">View 20 readings</summary>
  <!-- existing layout.data_table() output, or the mobile detail fields -->
</details>
```

CSS: style `summary` with `cursor: pointer`, `min-height: 44px`, `display: flex; align-items: center;` (44px hit target floor); style `summary::marker` (and the `::-webkit-details-marker` fallback) with `color: var(--color-accent)`. No custom chevron icon — the native marker is sufficient and needs no icon-sprite entry.

### New static JS files (ES5-safe IIFE, `"use strict"`, `defer`, mirrors `nav-dropdown.js`/`battery-trend.js`'s conventions exactly — no build step, no framework, no network call, no persistent state beyond the current page)

| File | Purpose | Guard (early-return if absent) |
|---|---|---|
| `companion/static/dirty-state.js` | D-03: watches `change`/`input` events on every `input`/`select` inside `form[data-dirty-form]`; shows/hides `[data-dirty-bar]`, updates its count text via the singular/plural copy above; `Cancel` calls `form.reset()` and re-hides the bar. Generic over the form's inputs (not hardcoded to Runway) so it needs no change if/when Theme becomes editable again (D-04's own auto-revert note). | `document.querySelector('form[data-dirty-form]')` absent |
| `companion/static/list-filter.js` | D-20: one generic client-side filter, reused by History and Airlines. Reads `[data-filter-input]`, lowercases the query, matches against each row/card's `data-filter-text` attribute (pre-lowercased by the server, never re-derived from escaped cell HTML), toggles a `hidden` attribute per non-matching row, updates `[data-filter-count]` text and shows/hides `[data-filter-empty]`. `Clear` resets the input and re-shows every row. | `document.querySelector('[data-filter-input]')` absent |
| `companion/static/copy-button.js` | D-23: click handler on every `[data-copy-value]` button; `navigator.clipboard.writeText()` with a hidden-`<textarea>` + `document.execCommand('copy')` fallback for browsers without the Clipboard API; swaps the button's accessible label to "Copied" for ~2s via `textContent`/`setTimeout`, then reverts. No HTML-writing sink. | `document.querySelectorAll('[data-copy-value]').length === 0` |
| `companion/static/freshness.js` | D-12/UXA-13: reads `data-loaded-at` (an ISO timestamp `page_header()`'s `freshness_html` slot renders) on page load; if `Date.now() - loadedAt > STALE_VIEW_THRESHOLD_MS` (default 10 minutes, documented as a named constant, not a magic number), reveals `[data-stale-banner]` (`role="status"`, already server-rendered but `hidden` by default). No polling, no `setInterval`, no network call — a single one-shot check plus, at most, one deferred re-check scheduled for exactly the threshold boundary (`setTimeout`, not `setInterval`), so a tab left open past the threshold still reveals the banner without a page reload. | `document.querySelector('[data-loaded-at]')` absent |

`battery-trend.js` is **extended in place** (not a new file) to add D-13's roving-tabindex arrow-key model — it already owns every point element and the readout line; adding a second file for the same points would duplicate state. See Interaction Contract below for the exact keyboard behavior.

### `layout.concise_timestamp_html(ts, now_ts, fallback="no reading yet")` (new, `companion/layout.py`)

Implements D-09: returns already-safe HTML — `<span class="mono" title="{escaped full ISO}">{HH:MM} UTC ({relative})</span>` — with the full raw ISO string demoted to the `title` attribute and the visible text reduced to a concise `HH:MM UTC` clock time plus the existing `relative_age_text()` suffix, keeping the absolute-first ordering convention `absolute_and_relative()` already established (do not reverse to relative-first). `absolute_and_relative()` itself is **not deleted** — it may still be the right choice anywhere a plain-text (non-HTML) value is genuinely needed — but every one of this phase's five pages' visible timestamp renderings (Health's Device/Pipeline/Battery rows, History's Timestamp column, Preview's caption) switches to `concise_timestamp_html()`.

**Integration note for planning:** `layout.data_table()` escapes every cell value it is given, so it cannot host this function's pre-built `<span title>` markup without double-encoding it (the same trap `stat_tile()`'s and `_merged_cell()`'s docstrings already document). The Battery readings table (`health_page.py::_battery_section()`) currently uses `layout.data_table()` for its Timestamp column — this phase must either hand-roll that one table (mirroring `history_page.py::_history_table_html()`'s existing precedent for exactly this reason) or extend `data_table()` with an opt-in "this column is pre-escaped markup" parameter. Pick one approach and document it in the plan; do not silently double-escape.

## Page-by-Page Design Contract

Every page keeps its existing `layout.page_header(...)` call as the first element — do not add a second, competing heading.

### Config (D-02, D-03, D-04, D-05, D-06's heading-dedup half, UXA-08's Config half)

**Composition, top to bottom:**

1. `page_header("Config")` — unchanged.
2. `<form class="config-form" data-dirty-form method="post" action="/config">` — two-column at ≥960px (unchanged grid), one column mobile:
   - **Theme** column: when `len(THEME_IDS) == 1` (true today), render the new **read-only theme status** block instead of `theme_fieldset()`'s radio group. When `len(THEME_IDS) > 1`, `theme_fieldset()` (unchanged radio-group markup) renders automatically — this is a `len()` check, not a hardcoded assumption, so no code changes are needed when a second theme ships.
   - **Runway** column: `runway_fieldset()`'s radios re-rendered as **selectable cards** (D-05) — see markup below.
   - A `[data-dirty-bar]` region (hidden by default, `hidden` attribute) sits directly below the two columns, above the always-visible `Save Settings` submit button — **not replacing it**. The no-JS floor is the existing bottom button; the dirty-state bar is a JS-only enhancement layered on top, per D-03's explicit "preserve a server-rendered always-available submit path."
   - Existing bottom button stays: `<button type="submit">Save Settings</button>` (Title Case, unchanged — this is the no-JS fallback path, distinct from the dirty-bar's own sentence-case `Save settings`).
3. `poll_trigger_section()` — unchanged, still its own sibling `<section>`.
4. LED `<section class="page-section">` — heading de-duplication (D-06): **drop the `<h2>Bring-up LED</h2>`**, keep the `<fieldset><legend>Diagnostic LED</legend>` (D-02's renamed copy) as the section's sole accessible group name. This aligns LED's own naming pattern with its Theme/Runway siblings inside `.config-form`, which already have no independent `<h2>` — only a `<legend>`. Do not keep both.

**Read-only Theme status markup (D-04):**

```html
<div class="theme-status">
  <p class="text-label">Theme</p>
  <div class="theme-status__row">
    <span class="theme-swatch" aria-hidden="true">
      <span class="theme-swatch__chip" style="background:{departing_hex}"></span>
      <span class="theme-swatch__chip" style="background:{arriving_hex}"></span>
    </span>
    <span class="text-body">{theme_label} · current</span>
  </div>
  <p class="text-label">Additional themes will appear here once more are validated on real hardware.</p>
</div>
```

`{departing_hex}`/`{arriving_hex}` are computed server-side from `server.panel_format.PALETTE_RGB[THEMES[theme_id]["departing_index"]]`/`["arriving_index"]` (today: Blue `#2D5F9B`, Green `#326941` — the real, on-glass-calibrated panel colors, not an invented web-only palette) — never hardcode these two hex strings in Python; derive them from `PALETTE_RGB` so a future Phase-7-style re-tuning of the panel ink automatically updates this swatch too. `.theme-swatch__chip` is a small (≈16×16px) rounded square/circle, sibling pair, no border needed beyond the existing card surface's own contrast.

**Runway selectable card markup (D-05), one per `RUNWAY_IDS` entry:**

```html
<label class="runway-card runway-card--selected">
  <input type="radio" name="tracked_runway" value="3" checked class="sr-only">
  <span class="runway-card__number">Runway 3 (07/25)</span>
  <img class="runway-card__image" src="/runway-image/3.png" alt="Airport diagram for Runway 3 (07/25)">
  <span class="runway-card__check">{icon-check}<span class="sr-only">Selected</span></span>
</label>
```

- The entire `<label>` is the hit target/card (not just the native radio) — `.runway-card` gets the full `.stat-tile`-style card treatment (`background: var(--color-dominant); border-radius: var(--radius-card); box-shadow: var(--shadow-card);`), a visible `2px solid var(--color-accent)` border only on `.runway-card--selected` (computed server-side from `checked`, not purely a `:has()` CSS trick — this project's target browser floor should not assume `:has()` support; render the modifier class directly), plus the `icon-check` glyph (visually shown only when selected).
- The native radio input becomes visually hidden (`.sr-only`, the existing visually-hidden-until-focused technique `.skip-link`/`.sr-only` utilities already establish) but stays in the DOM and keyboard-operable — clicking/tapping anywhere on the `<label>` still toggles it natively, no JS required for the selection itself (only the dirty-state bar's *feedback* is JS-enhanced, the actual radio selection is pure HTML/CSS).
- Renders correctly with 0, 1, 2, or 3 runway image files present (per `RUNWAY-IMAGES.md`'s existing "partial sets are fully supported" contract) — `runway-card__image` is simply omitted, not shown broken, exactly like today's `runway_fieldset()`.
- Reuses `RUNWAY_IMAGE_ROUTE_PREFIX`/`RUNWAY_IMAGE_ALT_TEMPLATE`/`images_available` wiring verbatim — this is a markup restructure of `runway_fieldset()`, not a new data path.

**Dirty-state bar markup:**

```html
<div class="dirty-bar" data-dirty-bar hidden role="status">
  <span data-dirty-count>1 unsaved change</span>
  <button type="submit" class="dirty-bar__save">Save settings</button>
  <button type="button" class="dirty-bar__cancel" data-dirty-cancel>Cancel</button>
</div>
```

## Interaction & Accessibility Contract

- **Every new control meets the existing 44×44px minimum** (dirty-bar buttons, runway card's effective hit area, filter input, copy buttons, disclosure summaries, Refresh link). This is not new policy — it is the audit's own "Strengths to preserve" list, restated here so no new control regresses it.
- **Roving tabindex adds exactly one stop** to the page's Tab order for the battery chart (D-13/UXA-11's explicit acceptance criterion) — verified by counting `tabindex="0"` occurrences inside the sparkline SVG (must be exactly one, not zero and not many).
- **All disclosures are native `<details>`/`<summary>`** — keyboard-operable (`Enter`/`Space` on the focused summary) and screen-reader-operable with zero custom ARIA, for free, matching the audit's own recommended direction for UXA-02/UXA-12's sibling problem.
- **Filters are additive, not load-bearing.** With JavaScript disabled or `list-filter.js` failing to load, the filter input renders but does nothing — the full unfiltered table/card list underneath remains completely intact and usable. This is a deliberate, acceptable "enhancement, not requirement" per D-20's own scope (client-side only, over already-rendered rows) — do not degrade the underlying data view if the script is absent.
- **Copy-to-clipboard degrades to nothing if unsupported**, never to a broken button: `copy-button.js`'s early-return guard (no `[data-copy-value]` elements) means the button renders as an inert, unstyled-but-harmless element if the script never runs; consider also adding `aria-disabled="true"` removal only after confirming `navigator.clipboard` (or the `execCommand` fallback) actually exists, so a genuinely unsupported browser doesn't show a button that silently does nothing on click without feedback — flag this exact fallback-detection behavior for the plan to implement, not left ambiguous.
- **Freshness banners never fabricate a new severity.** `freshness.js` only ever toggles the visibility of a banner the server already rendered (`hidden` by default) — it must never recompute Health's `ok`/`warn`/`error` verdict client-side (UXA-13's explicit "do not let client code independently recompute authoritative health severity" constraint).
- **`role="status"` (polite), never `role="alert"`,** for: the dirty-state bar's appearance, the stale-view banner, and the copy-to-clipboard success text — none of these are failures, all should announce without interrupting, consistent with 06.6.2's existing `flash_banner(role=...)`/`anomaly_banner(severity=...)` severity-to-role discipline this phase must not weaken.
- **No new destructive-styled control anywhere in this phase.**
