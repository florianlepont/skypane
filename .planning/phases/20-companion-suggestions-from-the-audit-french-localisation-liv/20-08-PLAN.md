<objective>
Build the live theme preview's whole server and browser mechanism: a `?live=1`
render keyed on the last real runway event, and the small script that swaps the
preview image when a chip is selected.

Purpose: S-03 asked for a preview of the *current* flight, not of a fiction.
The cache is the hard part — the existing scheme was deliberately designed around
a scene that never changes, and a live variant that reuses its filename would
serve the first live render forever.

`companion/static/theme-preview.js` wired through all six touch points, and its
three standard static-script checks. The markup that consumes it lands in 20-11.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → GET /theme-preview/{id}.png?live=1 | a client-controlled theme id and query flag reach a render-and-cache path that writes files |
| SQLite runway_events → rendered raster | third-party API strings (callsign, airline, route) are drawn into an image for the first time |
| static script → DOM | the script writes one attribute under a CSP that forbids inline scripts |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-14 | Tampering (path traversal) | the cache filename now carrying an event discriminator | mitigate | the theme id is membership-tested against `device_config.THEMES` before any path is built, in both the route and `cache_path()`; only an `int()`-coerced event id reaches the filename, and any coercion failure falls back to the literal `"sample"`; pinned by a hostile-id check |
| T-20-28 | Denial of Service (cache growth) | one cached render per (theme, event) pair | accept | the cache directory grows by at most one file per theme per newly-previewed flight, in a directory the project already prunes/rebuilds by signature; the grid is unaffected because it keeps the fixed-scene filename. Recorded rather than mitigated; revisit if the directory ever becomes large |
| T-20-29 | Information Disclosure | live flight data reaching a preview image | accept | the data is the operator's own frame content, already shown on Home and Flights to the same session-gated audience; the route sits behind the same session gate as every other image route |
| T-20-15 | Tampering (CSP) | the new browser script | mitigate | served from its own route through the six-touch-point contract; no inline `<script>`, no `on*` attribute, no `innerHTML`; pinned by the banned-token check and the "no inline script" shell check |
| T-20-SC | Tampering (supply chain) | package-manager installs | n/a | zero packages installed; the script is hand-written like every sibling |
</threat_model>
