## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-13 | Elevation of Privilege / SSRF-by-proxy | `POST /settings/notifications/test` | mitigate | session-gated like every sibling POST; the topic URL is read from the stored config and never from the request body, so the button can never be used to make the server fetch an arbitrary URL; `send_notification()`'s own `_url_is_safe()` gate still applies; pinned by a check that a submitted `topic_url` field is ignored |
| T-20-12 | Information Disclosure | the stored topic URL | mitigate | write-only rendering — no `value` attribute, no masked fragment, only a Configured/Not configured status row; pinned by a check that no substring of a seeded URL appears anywhere in the rendered page |
| T-20-03 | Tampering (XSS) | `data-*` attribute values now carrying translated text, and the live-preview caption's callsign | mitigate | every attribute value crosses `escape_html()`; the scripts assign through `textContent`-style writes only, never `innerHTML`; pinned by the banned-token checks |
| T-20-15 | Tampering (CSP) | the live preview and the notifications group | mitigate | no inline `<script>`, no `on*` attribute; the swap is `theme-preview.js`'s job through its own route |
| T-20-14 | Tampering (path) | the `?live=1` src built per chip | mitigate | built from `THEME_PREVIEW_ROUTE_PREFIX` plus a theme id that is a literal key of `device_config.THEMES`; the route re-tests membership before constructing any path |
| T-20-SC | Tampering (supply chain) | package-manager installs | n/a | zero packages installed |
</threat_model>
