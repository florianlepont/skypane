# Phase 20 — UI Design Contract

> Visual and interaction contract for: bilingual FR/EN, Display regrouped (Look / What it watches / When it is on), Home redesigned (hero row + recent flights), a live theme preview, push notifications, simple mode, and the Airlines "Change pictures" button. Generated by `gsd-ui-researcher`, verified by `gsd-ui-checker`. Authoritative source of decisions: `20-CONTEXT.md` (D-01..D-36). This spec does not re-litigate any locked decision — it specifies the *shape* those decisions take in markup, copy, CSS and structure, and resolves everything `20-CONTEXT.md` left to "Claude's Discretion." Non-interactive run: every open question below is resolved with a stated default and a one-line rationale, not left for the user.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-written, build-step-free, stdlib-only Python HTTP app |
| Preset | not applicable |
| Component library | none — `companion/static/style.css` is the sole authority for every token and component class |
| Icon library | this app's own inline `<svg>` symbol sheet (`layout.ICON_DEFS_HTML` / `layout.icon_html()`). Reused verbatim: `icon-power`, `icon-moon`, `icon-refresh`, `icon-check`, `icon-nav-*`. **No new icon is needed by this phase** — the language/mode switches reuse the theme-picker's text-only segmented idiom (no icon), and every other new element is text, a swatch dot, or a thumbnail image. |
| Font | `--font-ui` for every new control and row; `--font-serif` only on the three new Display section `<h2>`s (Look / What it watches / When it is on) and the promoted `<h2>` on the Home status card region, per the existing serif-headings-only boundary — nothing here breaks it. |

No shadcn gate applies (no `components.json`, not a React/Next/Vite stack). Do not propose a component library, CSS framework, or build step at plan or execute time.

**Bilingual mechanism has no separate visual contract.** `companion/i18n.py`'s `t()` lookup (D-04) is a string-substitution layer under every render call already covered below — this spec does not repeat D-01..D-09's mechanism, only the copy each new element needs in both languages (see Copywriting Contract) and the two visual consequences: (1) `<html lang="fr">`/`<html lang="en">` is set by `page_shell()` per D-03 — no visual change, but the executor must confirm no CSS rule silently assumes `lang="en"`; (2) French strings run longer than their English source (e.g. "Callsign prefix" → "Préfixe d'indicatif d'appel"). Every new fixed-width element in this spec (segmented-control buttons, the compact theme chip, the rule-row kind badge, nav labels) is sized generously enough or wraps rather than truncates — flagged per-component below where it matters most (the language/mode nav-footer switches, the Flight-colours segmented control).

## Typography

Reused as-is — zero new sizes, zero new weights. Four sizes (14/16/22/32px) and two weights (400/600) remain exhaustive.

| Role | Size | Weight | Family | Where it appears in this phase |
|------|------|--------|--------|----------------------------------|

| Nested card title | 16px | semibold | sans (`--font-ui`) | Every existing group heading nested under a Display supersection (Theme, Flight colours, Calendar, Runway, Screen on/off, Quiet hours) — see §C for why this is a reuse, not a new tier |
| Emphasis | 16px | semibold | sans | Status-row verdict text, the "Next update ≈ HH:MM" headline (default/ok state), rule-row theme name |
| Body | 16px | regular | sans | Preview-frame flight caption line, calendar/notifications field values |
| Label voice | 12px, uppercase, 0.06em tracking | semibold | sans | Status-row's `label` slot, `.rule-row__kind` badge, quick-action label (unchanged), nav-group label (unchanged) |
| Section caption | 14px (`.text-label.section-caption`) | regular, 70%-muted | sans | Every new section/group caption below |
| Sub-scale (theme-chip name) | 13px → **12px on the compact variant** | semibold | sans | `.theme-chip--compact .theme-chip__name` — the compact chip's own established sub-scale exception, shrunk one step further and justified in §F |

**"Next update" headline, warn state.** When the wake time is already past ("Expected since 12:03"), the headline keeps the same 16px-semibold Emphasis role and adds `color: var(--color-status-warn)` directly on the text. This is a **genuinely new use of a status colour as text colour** (every existing status use is a dot, a 3px card-top border, or a `.quick-action` left-edge — never body text). Required before this ships: run `companion/contrast_check.py`'s `WCAG_AA_NORMAL_TEXT` (4.5:1) check for `--color-status-warn` (light `#D97706` / dark `#FBBF24`) against `--color-dominant` in both themes (the card surface this headline sits on). If either theme fails, fall back to plain `--color-text` for the headline and move the warn signal onto a small leading status-dot instead (`<span class="dot dot--warn"></span>` before the headline text) — the wording itself ("Expected since…" vs "Next update ≈…") already carries the state distinction in text, so colour is never the only signal either way and no rewrite is needed if the fallback triggers.

## Section Anatomy

### A. The `status-row` primitive (D-21) — new, shared

`layout.status_row(label, verdict, detail, state)`:

```html
<div class="status-row status-row--ok">
  <span class="dot dot--ok"></span>
  <span class="status-row__label text-label">FRAME</span>   <!-- omitted entirely when label="" -->
  <span class="status-row__verdict">Checking in normally</span>
  <span class="status-row__detail">Last check-in 2m ago</span>
</div>
```

- `label` is optional (empty string omits the `<span>` outright, not just its text) — Home's three rows always pass one (Frame/Battery/Flight data); Calendar's status row (D-14b) passes `""`, since the surrounding `<h2>Calendar</h2>` already names the subject and a repeated "CALENDAR" label would be redundant chrome.
- `.status-row__label` becomes the **seventh member** of the existing shared label-voice declaration set (`.stat-tile__caption`, `.data-table th`, `.data-card__label`, `.filter-bar__count`, `.banner__pill`, `.airline-card__chip`) — same 12px/semibold/uppercase/0.06em/70%-muted declaration, written as its own selector in that same shared block, not duplicated.
- `.status-row__verdict` is the Emphasis role (inherits Body 16px, adds `font-weight: var(--weight-semibold)`) — zero new declaration beyond that one line.
- `.status-row__detail` reuses `.widget-detail`'s exact declaration (`color: color-mix(in srgb, var(--color-text) 70%, transparent)`) at the inherited Body/14px-label size depending on context (Home's rows compose `.text-label` for detail per the existing `widget-detail` precedent; standalone use elsewhere may compose whichever text role its container already uses — this is a colour-only mixin, not a size mixin).

```css
.status-row {
  display: flex;
  align-items: baseline;
  flex-wrap: wrap;
  gap: var(--space-sm);
  padding: var(--space-xs) 0;
}
.status-row__label {
  flex: 0 0 auto;
  min-width: 96px;   /* aligns the three Home rows' verdicts into one visual column at >=960px */
}
@media (max-width: 959.98px) {
  .status-row__label { min-width: 0; }  /* let it wrap freely on phones rather than reserve dead space */
}
.status-row__verdict {
  font-weight: var(--weight-semibold);
}
.status-row__detail {
  color: color-mix(in srgb, var(--color-text) 70%, transparent);
}
```

The dot reuses `_STATUS_DOT_CLASSES` (`dot--ok`/`dot--warn`/`dot--error`) verbatim — no new colour, no new class.

**Fixing the duplicated-verdict bug (D-17).** The Frame row's `verdict` and `detail` must be two *different* pieces of information (state word vs. freshness/detail), never the same sentence twice — this was today's real defect (`FRAME_STATE_TEXT` rendered once as `verdict` and again inside `detail`). The new contract: `verdict` = `FRAME_STATE_TEXT[state]`; `detail` = a freshness clause built fresh (e.g. "Last check-in %s" from the existing `health["device_html"]` timestamp, stripped of any repeated state wording) — never a second copy of `FRAME_STATE_TEXT`.

### C. Display's three supersections (D-12) — reuse Health's exact pattern, do not invent a new tier

**Finding:** Health already solved "a heading that groups several sibling setting-cards, one level above their own `<h2>`s" — `health_page.py`'s private `_section_intro_html(section_id, heading, description)` plus the `.page-section--nested` modifier on each grouped card. Display's three sections (Look / What it watches / When it is on) are the *same* structural problem and must reuse the *same* two-part solution, not a new heading tier:

**Required structural decision, flagged for the planner (this is not cosmetic — it determines whether the page is valid HTML).** Today, `render()` wraps every group (`theme_fieldset()`, `display_group()`, `quiet_hours_group()`, etc.) inside one `<form id="settings-form">`. **Recommended resolution:** pull the Screen on/off and Quiet hours group wrappers (`<div class="theme-status">…</div>`, whole cards) out of `<form id="settings-form">` entirely — render them as siblings of the form, exactly like Calendar already is — and give their scheduled inputs (the `display_enabled` checkbox; the `quiet_hours_enabled` checkbox and the two `time` inputs) a `form="settings-form"` attribute each. This is not a new idiom: it is the exact cross-DOM submission technique this codebase already uses for the dirty-bar's Save/Cancel buttons and the screen-type `<select>` in `page_header()`'s action slot. Net effect: the quick-action's inner `<form>` and the checkbox/time-input's `form="settings-form"` attribute now sit at the same DOM level with no nesting conflict, and the group's own card markup, copy and dirty-bar tracking (`data-dirty-section`) are otherwise unchanged. Every other group (Theme, Flight colours, Calendar, Runway) is unaffected — this restructuring is scoped to exactly the two groups D-19 touches.

Reuses the existing `.page-header__screen`/`.text-label.section-caption` slot shape `_edit_artwork_link_html()` already used on Device — this is that exact function's markup, relocated to `airlines_page.py`'s own `render()` (at the top of the gallery, per D-36, not in the page header's action slot, since Airlines' page header has no equivalent action slot precedent to reuse — place it as the first element inside the gallery section, directly under the page's own `<h1>`/purpose block). Style as a **secondary button** (D-36's own word) — i.e., render it as `<a class="airlines-edit-toggle">` styled with the same quiet-button visual treatment the base `button` selector already gives (`color-mix` wash, 30px/36px height) rather than a plain text link, since D-36 explicitly calls it a button, not a link. Two options for achieving link-styled-as-button with zero new CSS:

- **Recommended:** render it as `<a href="..." class="airlines-edit-toggle">`, and add one small rule `.airlines-edit-toggle { display: inline-flex; align-items: center; height: 30px; padding: 0 12px; border-radius: 6px; background: color-mix(in srgb, var(--color-text) 4.5%, transparent); border: 1px solid color-mix(in srgb, var(--color-text) 9%, transparent); text-decoration: none; color: var(--color-text); font-weight: var(--weight-semibold); }` plus its own `:hover`/sub-960px rules mirroring the base `button` block verbatim (an `<a>` cannot share the `button` element selector, so this is a deliberate, minimal duplication of that one visual treatment onto an anchor — the same reason `.airlines-edit-toggle` needs to exist as its own class at all).
- Alternative: a same-page `<form method="get" action="/airlines"><button>Change pictures</button></form>` — works with zero new CSS (a real `<button>`) but a GET form for a pure navigation link is an unusual pattern this codebase does not otherwise use; not recommended.

This spec recommends the styled-anchor option. Hidden entirely in simple mode (D-30), matching "Edit artwork"'s own precedent.

## Accessibility Floors

- **Focus order.** Every new interactive element (status-row has none itself — it is read-only; the compact chip's native radio; the segmented-control buttons; the rule-suggestion chips; the notifications fields; the "Change pictures" anchor) is a native element or an already-established pattern (`.theme-form .theme-option`) — the existing global `:focus-visible` outline applies with zero new CSS. The instant-switch quick-action forms keep their existing tab order (button focus, matching Home's current shipped behaviour).
- **`aria-labelledby` on radiogroups.** The Flight-colours "Match by" segmented control and both new compact-chip grids (Calendar's theme picker, the add-form's theme picker) each carry `role="radiogroup"` + `aria-labelledby` pointing at a visually-hidden (or already-visible) label — matching D-12/A-30's established pattern exactly (`theme_fieldset()`'s own two grids already do this; these are the third and fourth/fifth consumers, not a new pattern).
- **Live-region behaviour for the switches' flashes.** No new mechanism needed: every quick-action / instant-switch / test-notification POST already redirects back to a page rendering `layout.flash_banner()`, which already carries `role="status"` (or `role="alert"` for a failure) — this is D-19's/D-26's entire "the operator is told what happened" requirement, satisfied by the existing mechanism with zero new code.
- **Contrast of the status dots against both themes.** Unchanged mechanism (`_STATUS_DOT_CLASSES`, already contrast-validated for its existing dot/border/left-edge uses) — the one **new** contrast question is the "Next update" headline's warn-coloured text, flagged and gated in the Typography section above; do not ship that specific treatment without running the check.
- **Segmented-control and compact-chip touch targets.** Both stay within already-accepted registers (`.theme-form .theme-option` at 28px, exempt from the 44px floor per the existing register; the compact chip's native radio is exempt-by-delegation to its 104px×64px wrapping label, matching the full-size chip's own precedent) — no new register entry required.
- **French string length never breaks layout.** Explicitly checked for the two tightest new spaces: the nav-footer segmented buttons (French "Complet" is longer than English "Full" — both fit comfortably within the existing `.theme-option`'s `padding: 0 12px` at 13px/14px, matching how "Auto"/"Light"/"Dark" vs. no-French-theme-picker-precedent-needed since that control's options are untranslated theme-mode identifiers) and the compact theme chip's name ellipsis (already covered in §G).
