<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| poll loop → operator-supplied topic URL | an unattended background process makes an outbound request every cycle a transition occurs |
| device_config.json / poll_state.json → poll loop | both are on-disk files a corrupt write or a hand edit could malform |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-05 | Tampering / Elevation of Privilege (SSRF) | the outbound POST from the poll loop | mitigate | delegated to `notify.send_notification()`'s first-line `calendar_rules._url_is_safe()` gate (20-02); this plan never constructs a request itself |
| T-20-17 | Denial of Service | a hung, slow or erroring topic endpoint stalling the poll cycle | mitigate | one attempt, five-second timeout inside the sender, plus a whole-body `except Exception` in each hook; pinned by a raising-sender check that must not propagate |
| T-20-22 | Repudiation / notification spam | a transition re-reported every cycle | mitigate | `poll_state["notifications"]` records what was last reported and is written even when the POST failed; pinned by the "second cycle sends nothing" checks |
| T-20-23 | Tampering | a malformed `notifications` group on disk | mitigate | read through `device_config.load_device_config()`, which normalises per field and degrades to defaults (20-02); the hooks additionally treat a falsy `topic_url` as "off" |
| T-20-SC | Tampering (supply chain) | package-manager installs | n/a | zero packages installed |
</threat_model>
