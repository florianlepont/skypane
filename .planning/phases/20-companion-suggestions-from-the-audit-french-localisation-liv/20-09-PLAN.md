<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → POST /settings/calendar/connect | a new state-changing route taking an operator-supplied feed URL |
| browser → POST /settings/rules/add and /settings/rules/{kind}/{key}/delete | unchanged routes now reached from Display |
| stored calendar URL → render | a secret-shaped value that must never come back out |
| third-party calendar feed → status detail | fetch failures must be reported as sentences, not as exception text |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-10 | Elevation of Privilege | `POST /settings/calendar/connect` | mitigate | registered behind the same `require_session()` guard every sibling POST carries; pinned by a no-session check |
| T-20-11 | Tampering (silent state loss) | connecting a calendar through the scoped settings handler | mitigate | the connect form posts to its own route, which never touches `handle_post()`'s scope/in-scope machinery; pinned by the seed-ON / connect / still-ON regression check |
