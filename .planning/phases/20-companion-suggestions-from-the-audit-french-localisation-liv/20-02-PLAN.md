<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server process → operator-supplied topic URL | the server itself POSTs, on a schedule, with no browser and no user watching |
| device_config.json → server | a hand-edited or corrupt config must degrade, never crash the poll loop |
| config history file → companion render | anything written here is read back and displayed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-05 | Tampering / Elevation of Privilege (SSRF) | `notify.send_notification()` | mitigate | `calendar_rules._url_is_safe()` is the function's first line, reused verbatim; four loopback/link-local/file-scheme cases pinned in `server/test_notify.py` with a call-counter proving the transport was never reached |
| T-20-06 | Information Disclosure | notify failure logging | mitigate | log `type(exc).__name__` and a fixed description only; `str(exc)`/`repr(exc)`/the URL never appear, mirroring `fetch_ics()`'s own rule |
| T-20-07 | Tampering | `save_device_config(notifications=...)` | mitigate | `normalise_notifications()` degrades on read; a malformed write raises `ValueError` naming the field, pinned by four checks |
| T-20-12 | Information Disclosure | the topic URL in config history | mitigate | history records `set`/`cleared`, never the URL; pinned by a substring check |
| T-20-17 | Denial of Service | a hung or slow topic endpoint | mitigate | one attempt, `timeout=5`, every exception swallowed to `False`; the poll cycle can never block on it (consumed by 20-05) |
| T-20-SC | Tampering (supply chain) | package-manager installs | n/a | zero packages installed; stdlib `urllib.request` only, per 20-RESEARCH.md's Don't-Hand-Roll table |
</threat_model>
