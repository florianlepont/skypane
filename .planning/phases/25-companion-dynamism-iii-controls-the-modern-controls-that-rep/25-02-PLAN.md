<objective>
Five controls are about to be built, and each needs the same four proofs: it works
with scripts blocked, it works from the keyboard alone, its hit areas survive
360 px, and it is legible in both themes.

Written five times by hand, that is five chances to transcribe a sequence wrongly.
`_no_js_page()`'s own docstring already says this out loud — it exists because
three checks had spelled the scripts-blocked sequence out by hand, and *"a
scripts-blocked proof that quietly ran with scripts enabled would pass while
proving nothing"*. That docstring names "five more controls" that each need one.
They are D16, D17, D18, D5 and D19.

This plan writes those helpers once. It adds **zero net checks** — it converts
nothing and asserts nothing new. Its whole output is the sequences the next five
plans call.

The most important of the four is the first, and it is not obvious: **the no-JS
proof for a control is not "it renders". It is "operate it, submit the form,
reload, and the value persisted."** A control can render perfectly with scripts
blocked and save nothing at all — Phase 22 found exactly that, and this phase can
ship it five times over.
</objective>

CFG-52's instrumentation half. The regression floor itself is asserted by each
control plan using these helpers; this plan proves only that the helpers work,
using the app's EXISTING controls as their subjects. No new control exists yet.
</decisions_covered>
