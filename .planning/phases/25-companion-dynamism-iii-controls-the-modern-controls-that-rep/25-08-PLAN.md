<objective>
Five controls shipped. This plan makes sure the next phase inherits what they
taught rather than rediscovering it, and that the developer gets one list rather
than eight scattered notes.

Three jobs:

1. **The design system, updated in step.** `.claude/CLAUDE.md` names the
   `sketch-findings-skypane` skill as this app's design authority, and Phase 22
   established the discipline: the skill is updated by the phase that changed the
   thing, every supersession marked **in place** with its reason, nothing deleted.
   This phase added the app's first continuous-value controls, its first documented
   use of the `.js` gate as a *pattern* rather than one nav rule, and at least two
   new touch-target register entries. None of that is in the skill yet.
2. **The coverage ledger.** Five D-items, each with clauses. Several clauses were
   deliberately not built — D19 lost three, D5's "dialog" became a `<details>`, and
   D18's battery gauge ships a narrower claim than the audit wrote. Each needs to
   be recorded as *decided*, with its ground, so a future audit does not re-propose
   it as an unexamined idea. That is exactly what happened with the overlay drawer,
   twice.
3. **The developer's list.** This phase was planned with no CONTEXT.md and the
   developer unavailable. Eight decisions were taken provisionally. Now that the
   code exists, each one's reversal cost has changed, and the list should say so.

This plan writes no application code and changes no behaviour.
</objective>
