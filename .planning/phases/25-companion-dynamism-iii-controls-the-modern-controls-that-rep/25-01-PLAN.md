<objective>
Five controls are about to be built. Left to themselves, each would pay the same
three taxes separately, invent its own answer to "what happens with scripts
blocked", and add its own script — 23-RESEARCH.md predicted six to eight new files
against a shell that carries fourteen.

This plan builds none of the five. It builds the seam they share and the machine
that judges them:

- **One** new static script, with its route, its shell registration, its ES5 guard
  and the deferred-script pin moved once and only once.
- The `.js`-gated CSS vocabulary that makes "an affordance that cannot work
  without script does not render without script" a property of the stylesheet
  rather than a promise in five plans.
- The battery-life arithmetic D18's gauge needs, in the one module that already
  owns the battery estimate — extended, never duplicated.
- **The executable no-JS control contract**: a guard that fails when a control's
  value is held anywhere but a server-rendered native input.

Output: the next five plans can each add a control and a check, and none of them
touches `app.py`, `layout.py` or the script pin again.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser script → a settings form input | a script writes a value the user will then save to device config |
| a new static route → the unauthenticated internet | one more file served by the companion |
| stored battery history → a displayed lifetime claim | arithmetic over stored rows becomes a sentence a user acts on |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01-A | Tampering | a script writing an out-of-range value into `wake_interval_s`, bypassing the field's own `min`/`max` | mitigate | the script clamps to bounds READ FROM `device_config`, the native input keeps its `min`/`max` constraint validation, and `save_device_config()`'s server-side re-check is unchanged and remains the real control |
| T-25-01-B | Information Disclosure | a new static route served before authentication | accept | it matches the sixteen existing static-asset routes exactly; the file contains no user data and no secret. The check asserts its behaviour equals an existing static route's rather than assuming |
| T-25-01-C | Spoofing | a control that changes state by GET | n/a | this script writes into a form input and submits nothing itself; every state change stays the existing POST with `SameSite=Strict` |
| T-25-01-D | Repudiation | a lifetime figure the data cannot support, acted on by the user | mitigate | the estimate returns a named "not enough history" state and the absolute figure is emitted only when observed history supports it |
| T-25-01-SC | Tampering | npm/pip/cargo installs | n/a | this plan installs zero packages in any ecosystem; the phase adds no runtime dependency and no vendored library |
</threat_model>
