  <behavior>
    - Perfect cadence (every 900 s plus 14 s) over 2 days: gaps median about 914, coverage and max-gap gates PASS against expected 900.
    - A 3-hour hole in the middle: max-gap gate FAIL, count of gaps above 3 x expected is 1.
    - `--from`/`--to` (UTC ISO) select a window; rows outside are ignored; an empty or one-row window is refused (exit 2).
    - Gaps that start inside the quiet window (Paris 23:30-06:00 by default, `--no-quiet-hours` to disable) are reported separately and excluded from the gate verdict; the output says how many were set aside.
    - Output prints count, median, min, max gap, the share of gaps within expected to 1.5 x expected, the gate results with PASS/FAIL/SKIP and a final line `cadence verdict: PASS` or `FAIL`; exit 0 on PASS, 1 on FAIL, 2 when refused.
    - A parked-style window at expected 3600 on synthetic hourly rows passes; the same rows judged against expected 300 fail (the tool does not hide a wrong cadence).
    - No thresholds of its own: after loading the module as `lt`, set `lt.RUN_THRESHOLDS["max_gap_intervals"]` and `["min_coverage"]` to other values (monkeypatch) and the same synthetic rows flip verdict accordingly (a 2-interval gap passes at max_gap_intervals 3 and fails at 1); the gate names printed contain the patched numbers. This proves the gates read RUN_THRESHOLDS at call time.
    - `--skip-first-gaps N` (default 0): after quiet-hours gaps are set aside, the first N remaining gaps are set aside too and printed with their lengths (`first gap(s) set aside: ...`); rows: one 3600 s gap then 300 s gaps judged against expected 300 FAIL with N=0 and PASS with N=1, the printed set-aside gap is 3600; N larger than the number of gaps is refused (exit 2). Starting `--from` at a row with no earlier gap in the window gives the same PASS with N=0.
    - Quiet window default is explicit: `--quiet-start 23:30 --quiet-end 06:00` are the argparse defaults (the owner's production window), not device_policy's code default 23:00-07:00. A gap starting 23:10 Paris is judged, one starting 23:40 and one starting 05:50 are set aside, one starting 06:10 is judged. `--no-quiet-hours` judges every gap in the window and sets none aside (the output says `quiet hours: off, no gap set aside`); explicit `--quiet-start/--quiet-end` with `--no-quiet-hours` is refused (exit 2).
  </behavior>
  <action>
Write tests first in hardware/test_logtools_gaps.py (synthetic exports in tmp_path, CLI by subprocess, module loaded by path as in test_logtools_model.py). Then add `_add_checkin_gaps_parser(sub)`, `cmd_checkin_gaps(args)` and pure helpers (under 80 lines each) to hardware/logtools.py: args `rows` (file or stdin), `--expect-s` (required), `--from`, `--to`, quiet-window options as in sleep-trend, `--out` optional deterministic JSON. Reuse check_coverage and check_max_gap with thresholds read from RUN_THRESHOLDS at call time (judged against `--expect-s`) so the gates are the Phase 45 gates, not new ones; do not change any threshold and define no threshold constant in the new code. Gap bookkeeping: take consecutive polls in the window, form gaps (seconds between consecutive polls); a gap belongs to the quiet window when its START poll's Paris local time (QUIET_HOURS_TZ) is inside [quiet-start, quiet-end) and is set aside (counted, listed, not judged); then drop the first `--skip-first-gaps` remaining gaps; the rest are the judged gaps. Build the `stats` dict that check_coverage and check_max_gap read from the judged gaps with the same definitions compute_battery_stats uses: `observed` = number of judged gaps, `nominal` = (sum of judged gap seconds) / expect_s, `coverage` = observed / nominal (so it equals expect_s over the mean judged gap), `max_gap` = (largest judged gap seconds) / expect_s in intervals, `span_days` = sum of judged gap seconds / 86400. Refuse (exit 2) when fewer than 2 judged gaps remain. The verdict is PASS only when both gates PASS; SKIP never counts as PASS. Because quiet-hours gaps are removed, coverage and max_gap describe the judged gaps only, and the output says so. Keep comments free of plan and phase IDs.
