  <action>
Add three pure functions (no I/O, no clock reads: `now` is a parameter) and one locked wrapper to `server/firmware_registry.py`:

`compute_offer(registry, device_entry, battery_low_active, base_url)`: the offer gate for OTA-01. The battery gate consumes the poll loop's existing battery-low alert flag only (per D-12, no new threshold). Quiet hours and display off are deliberately not parameters (per D-13). Counting unreconciled failure events inside the offer decision stops byos from serving a fourth attempt in the same request that carries the third failure report (per D-15). The floor check is defensive: the registry already refuses to schedule below it (per D-11).

`reconcile(registry, device_report, now)`: returns (new_registry, notifications) where notifications is a list of tuples ("installed", version, None) or ("failed", version, back_on). Deep-copy the input; never mutate it. Events whose schedule_id differs from the current schedule update last_outcome for "installed"/"rollback" but never touch attempts. Only a terminal failure notifies, per D-15 and D-08.

`apply_reconcile(state_dir, now)`: the one locked I/O wrapper around reconcile, used by the poll loop (plan 10); it skips the write when reconciled_seq did not move.

`update_view(registry, device_report, now)`: state derivation: schedule "scheduled" and not acknowledged -> "scheduled" (timestamp scheduled_at); schedule "scheduled" and acknowledged -> "in_progress" (timestamp of the newest event for the schedule); schedule "failed" -> "failed" (failed_at); no schedule and last_outcome kind "installed" and its version equals the running version -> "installed" (last_outcome at); otherwise "available" (timestamp: newest release published_at, or None). The device entry used is the most recently reporting one (single-frame UI; the per-device map stays so multiple devices are not ruled out). History rows carry version, released_at, notes, installed_at list, bench, installable.

Tests first, then implementation. Parametrise the offer gate over every None condition and include one test proving quiet hours cannot influence the offer (the function signature has no such input and the test documents that by calling it with only the four inputs).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| byos device report -> registry | device-supplied tokens and versions enter server state through device_report.json |
| CI manifest/image -> registry | release metadata and bytes from the deploy import |
| companion operator -> registry | schedule/cancel requests |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-01 | Tampering | publish_release | mitigate | Recompute SHA-256 and size of the file bytes and refuse on mismatch; version/sha/size validated by anchored regexes; a version cannot be re-bound to a different sha |
| T-42-02 | Tampering | firmware_image_path | mitigate | Path built only from a SHA256_HEX_RE match; anything else returns None (no traversal) |
| T-42-03 | Tampering | registry.json concurrent writers | mitigate | Every read-modify-write under atomic_io.exclusive_lock and written with atomic_io.atomic_write (Phase 36 helpers, never re-implemented) |
| T-42-04 | Denial of Service | reconcile / load_device_report | mitigate | Tolerant loaders never raise; events processed once via reconciled_seq; notes and event lists capped |
| T-42-05 | Elevation of Privilege | downgrade below floor | mitigate | schedule_release refuses below floor_version; compute_offer re-checks the floor |
| T-42-06 | Tampering | downgrade within allowed range | accept | Voluntary downgrade is a feature (D-06); only the authenticated operator can schedule |
| T-42-07 | Repudiation | outcome history | accept | installed_at and last_outcome are kept in the registry, backed up nightly; single-operator system |
</threat_model>
