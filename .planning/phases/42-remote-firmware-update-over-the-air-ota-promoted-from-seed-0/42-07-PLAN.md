<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device -> byos | telemetry headers are attacker-influenced input (a stolen token, a buggy device) |
| internet -> /fw/ | unauthenticated path requests |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-28 | Tampering | X-Ota-Result / X-Fw-Version injection into state | mitigate | anchored regexes, 64-byte cap, recorded only after bearer auth, events capped at 50 |
| T-42-29 | Information Disclosure | path traversal via /fw/ | mitigate | strict regex on the raw path, registry membership check, firmware_image_path, regular-file check |
| T-42-30 | Denial of Service | large file serving | mitigate | MAX_IMAGE_BYTES cap and chunked streaming |
| T-42-31 | Spoofing | forged "installed" report | accept | requires the device bearer token; worst case marks a release installed in the UI; the running version shown is still the device's own X-Fw-Version |
| T-42-32 | Tampering | race between Cancel and a served offer | accept | offered event written before the response; a cancel landing in the same millisecond may still see the device install; outcome is still recorded and visible |
| T-42-33 | Information Disclosure | firmware image readable without auth | accept | signed, credential-free images (plan 06); same exposure as /img/ |
</threat_model>
