fp_ota_apply(offer, fail_out):
1. `esp_http_client_config_t` with url = offer->url, crt_bundle_attach = esp_crt_bundle_attach (same ISRG-only bundle), timeout_ms 30000, keep_alive_enable true; `esp_https_ota_config_t` with that http_config.
2. esp_https_ota_begin; failure -> FAIL_DOWNLOAD.
3. esp_https_ota_get_img_desc -> fp_ota_image_check(desc->project_name, desc->version, offer->version, CONFIG_SKYPANE_OTA_FLOOR_VERSION); WRONG_PROJECT or VERSION_MISMATCH -> FAIL_IMAGE, BELOW_FLOOR -> FAIL_FLOOR; abort and return.
4. Loop esp_https_ota_perform while it returns ESP_ERR_HTTPS_OTA_IN_PROGRESS, calling fp_wake_checkpoint() each iteration (feeds the watchdog; on budget expiry the wake ends through the single failure exit and the stored ota_try makes the next boot report the attempt as interrupted). Any other error -> FAIL_DOWNLOAD (abort).
5. Require esp_https_ota_is_complete_data_received and esp_https_ota_get_image_len_read == offer->size, else FAIL_SIZE (abort).
6. Read back offer->size bytes from esp_ota_get_next_update_partition(NULL) with esp_partition_read in 4 KiB chunks into an mbedtls SHA-256 context, render with fp_sha256_to_image_hash and compare with offer->sha256; mismatch -> FAIL_HASH (abort). This check runs before any boot switch (per D-09 the hash stays as the cheaper earlier gate).
7. esp_https_ota_finish: ESP_ERR_OTA_VALIDATE_FAILED -> FAIL_IMAGE (bad or missing signature, or corrupt image); any other non-OK -> FAIL_DOWNLOAD; ESP_OK means esp_ota_end verified the image (signature included) and the boot partition is switched. Treat only this single return as the commit point (Pitfall 3).
Log `ota step=<begin|desc|download|size|hash|finish> result=<ok|fail> err=<name>` lines (tag "ota"), never the URL.

fp_ota_boot_check(): read FP_NVS_OTA_TRY; running version; esp_ota_get_state_partition(esp_ota_get_running_partition()) == ESP_OTA_IMG_PENDING_VERIFY; esp_ota_get_last_invalid_partition() and its esp_ota_get_partition_description version (empty string if none); call fp_ota_boot_classify. TRIAL: record "trial;<version>" (kept until reported). ROLLED_BACK: record "rollback;<ota_try>" and erase ota_try. INTERRUPTED: record "fail-interrupted;<ota_try>" and erase ota_try. NONE with ota_try set: erase ota_try. Log `ota boot outcome=<none|trial|rollback|interrupted>`.

fp_ota_confirm_if_pending(): if the running partition is PENDING_VERIFY, call esp_ota_mark_app_valid_cancel_rollback(); on ESP_OK record "installed;<running>" and erase ota_try; log `ota confirmed version=<v>`. It never runs any other logic and is cheap (one otadata write), so it can sit immediately before deep sleep.

Result storage helpers use fp_ota_result_format and nvs_util; recording a new result overwrites any older unreported one (only the latest outcome matters for the server, which counts attempts from its own event log).
