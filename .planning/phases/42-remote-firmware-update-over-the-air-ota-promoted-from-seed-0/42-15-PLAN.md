<objective>
Carry signed releases from GitHub to the VPS firmware store through the existing reviewer-gated deploy: the CI deploy job downloads every `fw-v*` release's image and manifest, `deploy.sh` ships them with the code, and `activate.sh` imports them into `/opt/skypane/state/firmware/` as the service user before swapping releases.

Purpose: OTA-10's deploy half (D-17, D-18). Plan 11's release workflow dispatches CI on main, so a tag becomes an available release after one reviewer approval, and every ordinary deploy re-syncs idempotently.
Output: import CLI and tests, deploy/activate changes and tests, CI workflow changes, README.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-64 | Tampering | image altered between GitHub and the VPS | mitigate | publish_release recomputes SHA-256/size against the manifest; the device independently verifies the signature |
| T-42-65 | Elevation of Privilege | import running as root | mitigate | runuser -u skypane; tar extraction with --no-same-owner; symlinked images refused |
| T-42-66 | Elevation of Privilege | deploy without review | mitigate | same production environment gate and moved-on guard for workflow_dispatch runs |
| T-42-67 | Denial of Service | failed import breaks the running service | mitigate | import runs before the swap; failure keeps the previous release |
| T-42-69 | Denial of Service | firmware store lost with the VPS | mitigate | firmware/ added to the nightly backup allow-list; releases also remain on GitHub Releases |
| T-42-68 | Information Disclosure | GH token scope | mitigate | github.token with contents: read in the deploy job, passed via env: |
