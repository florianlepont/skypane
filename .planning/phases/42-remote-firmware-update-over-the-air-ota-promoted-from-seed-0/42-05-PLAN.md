    - `verify --chain <pem> --roots <dir>` exits 0 for a leaf+intermediate chain issued under a root present in the roots dir
    - exits 1 with a message containing "no path to a trusted root" when the chain was issued under a different root
    - exits 1 when the leaf is expired, when the chain file has no certificate, and when the roots dir has no .pem file
    - the message on failure names the chain's top issuer subject and the roots it tried, and never prints certificate bodies
    - tests generate their own throwaway roots, intermediates and leaves with the openssl CLI in tmp_path (no network, no committed private keys)
  </behavior>
  <action>
Create `scripts/check_cert_chain.py` (stdlib + the `openssl` CLI via subprocess with argument lists, never shell=True; English docstring; no plan IDs). Two subcommands:
- `fetch --host <name> --out <pem>`: runs `openssl s_client -connect <host>:443 -servername <host> -showcerts` with stdin closed and a 20 s timeout, extracts every PEM block into the output file; exits 1 if none. Host must match `^[A-Za-z0-9.-]{1,253}$`.
- `verify --chain <pem> --roots <dir>`: builds a CA file from every `*.pem` in roots, splits the chain into leaf and the rest, and runs `openssl verify -x509_strict -CAfile <roots bundle> -untrusted <rest> <leaf>`; exits 0 only on success. Do not pass `-partial_chain` (the path must end at one of the compiled roots, per D-19).
- `check --host <name> --roots <dir>`: fetch into a temp file then verify.
Write the tests first: a module-scoped fixture creates root A, root B, an intermediate under A, a leaf under that intermediate, another intermediate+leaf under B, and an expired leaf under A (use `openssl req -x509` and `openssl x509 -req` with `-days`/`-not_after` or a negative `-days` equivalent supported by the runner's openssl; skip only the expired case with a clear reason if the local openssl cannot backdate). Tests call the script through subprocess with `sys.executable`.
  </action>
