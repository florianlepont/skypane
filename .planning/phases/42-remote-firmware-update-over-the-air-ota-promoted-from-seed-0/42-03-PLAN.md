Output: config and build changes, an extended production-config check, `firmware/SIGNING.md`.
</objective>

Key research points (42-RESEARCH.md "Signed app verification", Open Question 1, Assumption A2/A3):
- CONFIG_SECURE_SIGNED_APPS_NO_SECURE_BOOT + CONFIG_SECURE_SIGNED_ON_UPDATE_NO_SECURE_BOOT: the new image is verified against the public key in the signature block of the currently running app; no eFuse is involved. The running app must itself be signed for any OTA to verify (the factory image flashed in the hardware session is a signed CI release).
- CONFIG_SECURE_BOOT_BUILD_SIGNED_BINARIES=n: the build emits an unsigned skypane.bin; CI signs it out of band with `espsecure.py sign_data --version 2`, so the private key never touches a build machine.
- ESP32-S3 Secure Boot V2 scheme is RSA-3072 (to be confirmed in the container, A3).
- CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE is a bootloader option: only a USB flash of the new bootloader makes it effective.
</context>
