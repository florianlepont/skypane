<task type="checkpoint:human-action" gate="blocking">
  <name>Task 1: Developer generates the key, stores the secret and makes the offline backup</name>
  <files>(none: human procedure)</files>
  <read_first>
    - firmware/SIGNING.md ("One-time key generation (human only)" and "Resolved configuration")
  </read_first>
  <action>
Present the procedure from firmware/SIGNING.md to the developer and wait. Claude does not run any of these commands and never asks for the private key's contents.
  </action>
  <what-built>firmware/SIGNING.md documents the procedure; the release workflow expects the FW_SIGNING_KEY secret in the firmware-signing environment and the public key at firmware/signing/skypane-signing-pubkey.pem.</what-built>
  <how-to-verify>
1. On the Mac, in the pinned container, generate the key: `espsecure.py generate_signing_key --version 2 --scheme rsa3072 skypane-signing-key.pem` (scheme exactly as SIGNING.md's resolved configuration says).
2. Extract the public key: `espsecure.py extract_public_key --version 2 --keyfile skypane-signing-key.pem skypane-signing-pubkey.pem`.
3. In GitHub Settings -> Environments, create `firmware-signing` with yourself as required reviewer and deployment branches limited to tags `fw-v*`.
4. `gh secret set FW_SIGNING_KEY --env firmware-signing < skypane-signing-key.pem`.
5. Make the encrypted offline backup (password manager attachment, or `age -p -o skypane-signing-key.pem.age skypane-signing-key.pem`), and confirm you can decrypt it once.
6. Delete the plaintext private key (`rm -P skypane-signing-key.pem`).
7. Create the `PRODUCTION_HOST` repository secret (the byos public host name) for the chain guard.
8. Paste the contents of `skypane-signing-pubkey.pem` (public key only, starts with `-----BEGIN PUBLIC KEY-----`) into the chat.
  </how-to-verify>
  <verify>
    <human-check>The developer confirms steps 1-7 and pastes only a PUBLIC KEY block</human-check>
  </verify>
  <acceptance_criteria>
    - Developer confirms the secret exists in the firmware-signing environment, the encrypted backup decrypts, the plaintext key is deleted, and PRODUCTION_HOST exists
    - The pasted text contains "BEGIN PUBLIC KEY" and does not contain "PRIVATE KEY"
  </acceptance_criteria>
  <resume-signal>Paste the public key block and type "key stored"</resume-signal>
  <done>The private key exists only in GitHub's secret store and the encrypted offline backup.</done>
</task>

Otherwise write the pasted block verbatim to `firmware/signing/skypane-signing-pubkey.pem` and check it with openssl.
  </action>
  <verify>
    <automated>openssl pkey -pubin -in firmware/signing/skypane-signing-pubkey.pem -noout -text | grep -q 'Public-Key: (3072 bit)' && ! grep -rqE 'BEGIN [A-Z ]*PRIVATE KEY' firmware/</automated>
  </verify>
  <acceptance_criteria>
    - `openssl pkey -pubin -in firmware/signing/skypane-signing-pubkey.pem -noout -text` reports a 3072-bit public key (or the key type SIGNING.md recorded)
    - `grep -rlE 'BEGIN [A-Z ]*PRIVATE KEY' firmware/` prints nothing
  </acceptance_criteria>
  <done>The public key is committed and verified; no private material is in the repository.</done>
</task>
