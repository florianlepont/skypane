H42-09 Tampered and wrongly signed images refused (two variants, both must be refused): (a) tampered: build with `SKYPANE_VERSION_LABEL=tampered`, sign it with the real offline key per SIGNING.md, then flip one byte in the middle of the signed file (`printf '\x55' | dd of=<file> bs=1 seek=65536 conv=notrunc`); (b) wrongly signed: build with `SKYPANE_VERSION_LABEL=wrongkey` and sign it with a throwaway key generated in the container for this test only (`espsecure.py generate_signing_key --version 2 --scheme rsa3072 throwaway.pem`, deleted afterwards), so the image is intact and only the signature check can refuse it. Import each with import-bench (its hash is computed from the file, so the SHA-256 gate passes), Install, confirm `ota step=finish result=fail` and that the device stays on fw-v1.0.1, and let each reach Failed after three attempts (Cancel is gone once the first offer was served, by design).
H42-10 Forced crash on a trial image rolls back: build `SKYPANE_PROFILE=dev SKYPANE_FAULT=panic SKYPANE_RELEASE_TAG=fw-v1.0.1 SKYPANE_VERSION_LABEL=crash ./firmware/build.sh`, sign locally, import-bench with `--version` set to exactly the version build.sh printed (the device requires the image descriptor version to equal the offered one), Install; the device switches, restarts, panics before its first poll, the bootloader rolls back; the following wake shows `ota boot outcome=rollback` on fw-v1.0.1, the companion shows the rollback warning banner. Also schedule one install while quiet hours or display off is active and confirm the UPDATING screen is still drawn (can be combined with H42-06 or this row; record which).
