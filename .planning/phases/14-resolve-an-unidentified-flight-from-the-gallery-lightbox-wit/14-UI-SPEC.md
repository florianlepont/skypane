# Phase 14 — UI Design Contract

> Visual and interaction contract for folding Phase 13's "resolve an unidentified flight" flow into the Airlines gallery's own dialog, with coverage gaps rendered as empty cards. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds companion-web-only UI. No shadcn/component-registry ecosystem exists or applies here — `companion/` is a stdlib-only Python HTTP service serving hand-written, build-step-free HTML against `companion/static/style.css`. The shadcn gate is not applicable and was skipped for that reason, matching `13-UI-SPEC.md`'s own precedent.

Every token, class and pattern below is read from `.claude/skills/sketch-findings-skypane/SKILL.md`, plus a direct read of `companion/pages/airlines_page.py`, `companion/pages/health_page.py`, `companion/static/panel-lookup.js`, `companion/static/list-filter.js` and `companion/static/style.css` at execution time (2026-09-06). This phase adds the smallest number of new classes/attributes that make D-01–D-14 legible, reusing every existing pattern it can — in particular `.resolve-context`, `.resolve-name-field` and `.resolve-upload-zone`/`.lightbox__replace-zone`, all three already generic (not lightbox-specific) and reusable byte-identical inside the dialog.

## Component Inventory

### One render function per form, called twice (Claude's Discretion #1 — binding, not optional)

The no-JS fallback (`_resolve_section_html()`, kept per D-12) and the dialog's static copy (`_lightbox_html()`, extended per D-03) must **share the exact same Python rendering functions** for every piece of form markup — never two independent copies. Concretely:

| Function | Called for the no-JS fallback with… | Called for the dialog with… |
|---|---|---|
| `_resolve_name_form_html(prefix_value, id_suffix)` | the real prefix, `id_suffix=""` (existing ids: `manual-airline-name`, `known-airlines` — **unchanged**, so no existing test/id reference breaks) | `prefix_value=""`, `id_suffix="-dialog"` (new ids: `manual-airline-name-dialog`, `known-airlines-dialog`) — JS fills the hidden prefix input's `.value` at click time |
| `_resolve_upload_form_html(action, id_suffix)` | the real `/illustration/{key}.png` action, `id_suffix=""` (existing id `manual-illustration-input` unchanged) | `action=""`, `id_suffix="-dialog"` (new id `manual-illustration-input-dialog`) — JS overwrites `action` via `setAttribute`, exactly like the existing replace form |
| `_resolve_context_html(row, id_suffix)` | the real sighting-context tuple, `id_suffix=""` | `row=None` (five empty `<dd>`s), `id_suffix="-dialog"` — **each `<dd>` additionally carries one of five new classes** (`resolve-context__prefix`, `-first-seen`, `-last-seen`, `-count`, `-callsign`) in *both* calls, so the dialog's copy has stable JS hooks and the two copies stay structurally identical |
| `_manual_delete_form_html(action)` | the real `/airlines/manual-resolutions/{prefix}/delete` action — rendered whenever a manual entry exists for the prefix being viewed (D-09 amendment, 2026-09-06 — see below) | `action=""`; JS overwrites it via `setAttribute`, exactly like the existing replace form |

**Why two ids, not one:** whenever `?resolve={prefix}` is present, the no-JS fallback section renders unconditionally (D-12) *and* the dialog is always present in the DOM — both on the page simultaneously. Reusing one literal id (`manual-airline-name`, `known-airlines`, `manual-illustration-input`) in both places would produce duplicate DOM ids, an invalid-HTML defect that breaks `<label for>` association and makes `<datalist>` resolution undefined. The `-dialog` suffix is the whole fix; it is not optional.

**`_manual_delete_form_html(action)` needs no `id_suffix` at all — unlike the two functions above.** Its output is `<form class="lightbox__delete"><p class="text-label section-caption">{MANUAL_DELETE_CAPTION}</p><button type="submit">{DELETE_BUTTON_TEXT}</button></form>`: no `<label for>`, no `<input id>`, no `<datalist>` — nothing that HTML requires to be document-unique. Two copies of this exact markup can coexist on the page (dialog + fallback) with zero collision risk, because neither copy names an id at all. This is *why* the delete form was cheap to duplicate once the developer ruled on it (see below): the resolve-name/resolve-upload forms needed the `-dialog` suffix precisely because they have id-bearing children; the delete form structurally cannot collide.

**D-09 amendment (2026-09-06) — delete renders in both places, not dialog-only.** `gsd-ui-checker` correctly caught that the first draft of this section — "the no-JS fallback never rendered delete, that capability is dropped" — contradicted D-12's own promise that nothing is lost relative to Phase 13: Phase 13's standalone table carried a delete control that worked with **no JavaScript at all**. Put to the developer, who ruled that the promise stays literal: `14-CONTEXT.md`'s D-09 amendment now requires `_manual_delete_form_html()` to render in the no-JS fallback section too, for every prefix that has a manual entry, exactly mirroring how the resolve-name/resolve-upload forms already work in both places. See Page Composition below for exactly which fallback branches gain it. Enumeration (seeing *that* a card is manually resolved or superseded at all) was never actually at risk without JS — the chip itself is plain server-rendered HTML on the card, no JS required — only the *delete action* needed a no-JS home, and this is that home.

## Interaction Contract

### Attribute vocabulary (every trigger carries a subset of these — `data-view-panel-resolve-prefix` is what decides whether `.airline-card__zoom`/the gap card is a real `<a href="/airlines?resolve={prefix}">` or a plain `<button type="button">`, see Page Composition's Trigger-tag generalisation)

| Attribute | Values | Meaning |
|---|---|---|
| `data-view-panel-src` (existing) | image URL, or `""` | Empty **only** for a raw gap (no manual entry at all yet) |
| `data-view-panel-caption` (existing) | text | Airline name for art/manual cards; the example callsign for a raw gap |
| `data-view-panel-heading` (new) | text or `""` | `RESOLVE_HEADING` for `mode=gap`, `STEP_B_HEADING_TEMPLATE % name` for `mode=needs-artwork`, `""` otherwise |
| `data-view-panel-mode` (new) | `art` \| `gap` \| `needs-artwork` | Governs image/heading/context/name-form/upload-zone/replace-form visibility — see table below |
| `data-view-panel-manual` (new) | `""` \| `active` \| `superseded` | **Orthogonal to mode.** Governs delete-form and manual-note visibility only |
| `data-view-panel-scope` (new) | text or `""` | The `RESOLVE_CAPTION_TEMPLATE` sentence; non-empty only for `mode=gap` |
| `data-view-panel-resolve-prefix` (new) | 3-letter prefix or `""` | Present on any trigger with an associated prefix (gap, needs-artwork, manual-active, manual-superseded); absent on a plain curated art card with no manual history. **This is also D-13's location-search match key.** |
| `data-view-panel-first-seen` / `-last-seen` / `-count` (new) | text or `""` | Sighting-context values; present only when live gap data still exists for this prefix (empty after CR-02's row-gone path) |
| `data-view-panel-replace-action` (existing) | URL or `""` | Used when `mode=art` |
| `data-view-panel-upload-action` (new) | URL or `""` | Used when `mode=needs-artwork`, or `manual=superseded` and the built-in airline still lacks artwork |
| `data-view-panel-delete-action` (new) | URL or `""` | Used when `manual` is `active` or `superseded` |
| `data-view-panel-manual-note` (new) | text or `""` | Non-empty only when `manual=superseded` |

**Correctness rule, not optional:** every one of these must be copied on **every** click/load-time open, using the existing `attr || ""` idiom (`captionText = trigger.getAttribute(...) || ""`) — never conditionally skipped. The dialog's DOM is reused across clicks; skipping a write when an attribute is absent would leak the *previous* click's content (e.g. a stale superseded note showing on the next, unrelated card). This generalises the file's own existing discipline; it is the single highest-risk correctness detail in this phase's script change.

### D-13/D-14 auto-open

On script init (not inside the click handler), read `location.search`'s `resolve` param. If present, run the identical "populate dialog from a trigger, then `showModal()`" function against `document.querySelector('[data-view-panel-resolve-prefix="' + value + '"]')` instead of `evt.target`. If no such element exists (prefix already fully resolved and capped out of the gap block, or genuinely stale), do nothing — the page's own server-rendered fallback section already tells the honest story, exactly as RESEARCH.md's Pattern 3 requires. This satisfies D-13 (auto-open from Health's Resolve link) and D-14 (auto-reopen on the upload step after Step A's redirect) with **one** mechanism, not two — the redirect's `?resolve={prefix}` is indistinguishable, at the script level, from a fresh deep link.

## Page Composition — Airlines (`companion/pages/airlines_page.py`)

**Primary visual anchor (Dimension 2, stated explicitly):** the top-left card of `.illustration-grid` is what the eye meets first on page load — the single highest-sighted gap card (D-05's sort) when at least one prefix clears the threshold, or the first curated airline card when none does. This is a deliberate reversal of Phase 13's own anchor (a page-top resolve-section heading, above the grid): the grid itself is now the first thing on the page with visual weight, matching D-04's own framing that "the visual force of the idea is seeing the holes among the art."

New top-to-bottom order (replaces the current `resolve_section + filter + gallery + lightbox + manual_section`):

```
page_header
+ filter_bar                          # unchanged shape, reworded label + broadened total (see below)
+ manual_summary_line                 # NEW — only when the manual-resolution registry has ≥1 entry
+ gap_overflow_line                   # NEW — only when the cap (12) hides ≥1 eligible prefix
+ gallery_grid                        # gap cards prepended, head-of-grid, then art cards (D-04/D-05)
+ lightbox                            # extended: heading, manual-note, resolve-context, resolve-name
                                       # form, resolve-upload-zone, delete form, all newly toggled
+ resolve_section (conditional)       # UNCHANGED function, kept per D-12 as the no-JS fallback
```

`resolve_section` moves from the *top* (Phase 13) to the *bottom* of the page's own render order — its content is now redundant with the dialog for a JS-enabled operator (the dialog auto-opens over it, D-13), so it no longer needs the prominent top slot Phase 13 gave it; a JS-disabled operator still reaches it via the same URL and normal in-page reading order.

**`_resolve_section_html()`'s expanded responsibility (D-09 amendment, 2026-09-06).** Whenever a manual entry exists for the prefix being viewed (`entry is not None`), the section additionally renders `_manual_delete_form_html(_manual_delete_action(prefix))` beneath whatever else that branch already shows — **in every branch that reaches an entry, never in Step A** (no entry yet, nothing to delete) and never in the stale/invalid branches (no entry, no live gap):

| Branch (existing) | Entry present? | Gains the delete form? |
|---|---|---|
| Stale/invalid prefix, no live gap and no manual entry | no | no |
| Step A — name not yet saved | no | no |
| Step B — name saved, no artwork yet | yes | **yes**, beneath the upload zone/skip link |
| Already resolved (name + artwork both present) | yes | **yes**, beneath the existing body text — this is the branch a fully-resolved manual/superseded prefix's own `?resolve=` link now lands on |

This is the same rule the dialog already encodes (`.lightbox__delete` shown whenever `manual` is `active` or `superseded`, i.e. whenever an entry exists) — one rule, two render sites, not two rules.

**Trigger-tag generalisation, required for the fallback path above to be reachable at all.** D-12 already makes a raw gap card's whole element a real `<a href="/airlines?resolve={prefix}">`. This phase generalises that same rule to **any** card carrying `data-view-panel-resolve-prefix` — i.e. `needs-artwork`, `manual-active` and `manual-superseded` cards too, not just raw gaps. Concretely: for those cards, the existing `.airline-card__zoom` element's tag changes from `<button type="button">` to `<a href="/airlines?resolve={prefix}">` (everything else about it — its classes, its `data-view-panel-*` attributes, the image it wraps — is unchanged). `panel-lookup.js`'s ancestor walk and `.airline-card__zoom`'s CSS are both class-based and tag-agnostic already, so this needs **zero** new CSS and only the same generic `preventDefault()` D-12 already specifies for any anchor trigger. Without JS, clicking such a card now navigates to `?resolve={prefix}` and lands on the fallback branch above — which is precisely what makes the no-JS delete form reachable by click, not just by manually typing the URL. A plain curated card with **no** associated prefix keeps its existing `<button>` — untouched, since D-09's amendment only concerns prefixes with a manual entry.

### Gap-card markup shape (D-01, D-02, D-12)


### Manual-resolution absorption (D-08, D-09, D-10, D-11)

**Grid injection (Claude's discretion — flagged for visibility, not a locked decision).** `illustrations.target_variants_by_airline()` is a fixed curated list, independent of manual resolutions. An *active* manual entry whose operator-chosen name is not among that curated set (the operator typed a genuinely new name instead of picking a datalist suggestion) would otherwise never get a card at all — silently defeating D-08's "the state reads in the grid without a click." This UI-SPEC's call: the grid's pairs become curated-pairs **∪** every active manual-resolution airline name not already present (each `shapes=[]`), appended after the curated set in prefix order, rendered through the *same* `_airline_card_html()`. This is additive, changes nothing for the common case (operator picks from the datalist, already curated), and needs no server change — `illustration_key_for_name()` already accepts and serves any validated novel key (Phase 13's own Step B upload path already proves this route works for a non-curated name). A superseded entry needs no injection: its `enrich.static_airline_name_for_prefix()` name is, by construction, a real built-in airline, already curated.

**Known limitation, not further special-cased:** if two different prefixes both resolve (actively or superseded) onto the *same* airline-name card, that one card can only carry one prefix's `data-view-panel-resolve-prefix`/delete-action pair (first-by-prefix-ascending wins) — a rare multi-prefix-per-airline edge case, acceptable for this phase.

**Chip + filter text.** Every card backed by a manual entry gets, appended to its existing chip list: `<span class="airline-card__chip">Resolved by hand</span>` (active) or `<span class="airline-card__chip">Superseded</span>` (superseded, reusing `SUPERSEDED_MARKER_TEXT` byte-identical). `data-filter-text` gains, appended: `" resolved by hand manual"` or `" superseded manual"` — the shared, invisible `"manual"` token is what the summary line's click targets (see below), independent of which of the two visible labels a card carries.

## Accessibility & JS-Free Degradation Notes

- **Gap card accessible name carries the callsign**, not just "Resolve" (see Copy Deck) — Health's existing per-row links keep their own shorter `aria-label` since the row's Prefix cell already supplies context there; the gallery's gap card is the *first* thing an operator meets, so its label is more self-contained.
- **The placeholder box is `aria-hidden="true"` and empty.** It is decorative reinforcement of a state the card's own visible, announced text (the callsign) already communicates in full — not a colour-only or shape-only signal a screen-reader user would miss.
- **The gap card's whole surface is a real `<a href>` and needs only `preventDefault()`** to become a JS-enhanced trigger (D-12) — no `tabindex`, no synthetic keyboard handling; a plain anchor is natively focusable and activatable by Enter.
- **Every attribute-driven dialog field must be reset on every open**, including to empty, per the Interaction Contract's correctness rule — this is an accessibility concern as much as a correctness one: a stale, wrongly-associated note or heading read aloud on the wrong card is a real screen-reader defect, not just a visual glitch.
- **Autofocus, per RESEARCH.md Pitfall 3:** `hidden` must be set on the non-matching forms *before* `showModal()` runs, in the same population function, never after — the browser's one-time autofocus placement is synchronous with `showModal()` and only ever looks inside the dialog's own subtree, so the no-JS fallback's own `autofocus` (outside the dialog) never competes with it.
- **No colour-only signal, unchanged from Phase 13:** the "Superseded"/"Resolved by hand" chips carry text, never colour or an icon alone.
