<objective>
Every claim this phase makes is about something a string comparison cannot see:
where focus went, what a screen reader was told, which routes a stranger can
open, and whether a keypress landed in a text field. Four plans need those
readings and none of them should invent its own way of taking them — that is how
a harness ends up with three ways to block scripts and two definitions of 360 px.

This plan adds the instruments and **zero net checks**, following 24-02 and 25-02
exactly. It asserts nothing about the palette, the first run or the share control;
it makes those assertions cheap enough that the plans owning them can afford to
make the expensive version.
</objective>

<decisions_covered>

judgement call: the unauthenticated-route enumerator (Task 3) is built in the
browser harness rather than in `test_companion_app.py` even though it is really an
HTTP-level question, because this file already runs a real server subprocess with
a real session and can therefore compare "with cookie" against "without cookie"
over the SAME running instance. A second definition of "the public route set" is
exactly the drift this phase is trying to avoid.
</decisions_covered>
