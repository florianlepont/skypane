<objective>
A command palette is the feature that quietly adds a script, a route, a second
navigation source of truth and a new POST surface — four things, one of which
(the second nav list) is the one that rots. Phase 25 has just shown that five
controls can cost one script; this plan spends this phase's entire script budget
in one place and makes the palette structurally incapable of the other three
mistakes.

It builds no search, no filtering and no shortcut. It builds:

- **One** new static script with its route, its mirror constant, its ES5 guard
  clause, its French catalogue entry, and the shell pin moved **once**.
- The **command index**, emitted by the one `_nav_groups()` iteration the sidebar
  and the bottom tab bar already share — so the palette is the fourth renderer of
  one list, not the first renderer of a second one.
- The `<dialog>` and the `.js`-gated trigger, reusing the shipped `showModal()`
  and `@starting-style` vocabulary rather than inventing a third.
- **The executable contract**: a check that fails when a destination comes from
  anywhere but the shared nav iteration, and a check that fails when the trigger
  renders without `.js`.

Output: 26-03 can add behaviour and 26-04 can add shortcuts, and neither touches
`app.py`, `i18n_fr/` or the script pin again.
</objective>

<decisions_covered>
CFG-53 in full. **The palette navigates; it does not act** — 26-RESEARCH.md §2.4,
Open decision 1, PROVISIONAL. The audit's "switch screen off" becomes a
destination ("Display → Screen"), not a POST. Grounds: Phase 25 has just built
the real controls, and a second way to mutate config would have to be kept in
agreement with the first, in an app with no CSRF token. The alternatives (hidden
mirror forms in the shell; page-scoped action commands) are priced in
26-RESEARCH.md and not built here.

**The trigger is visible at every width** — Open decision 2, PROVISIONAL. An
invisible P3 feature is a P3 feature nobody finds, and the trigger is what lets
26-03 open the palette at 360 px without synthesising a keystroke.
</decisions_covered>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated client → `/static/command-palette.js` | the asset is served pre-auth like all sixteen others; anything baked into it is public |
| authenticated browser → the rendered index | route/label strings pass from `NAV_TABS` through `_nav_links()`'s escaping into the DOM |
| keystroke/click → any state change | the boundary this plan deliberately does not cross |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-01-A | Information disclosure | `/static/command-palette.js` served pre-auth | mitigate | the file carries no session data and no state of any kind; the index lives in the authenticated HTML, never in the cached asset. Asserted by the public-route smoke check |
| T-26-01-B | Tampering / Spoofing | a palette command pointing at an attacker-chosen or non-existent destination | mitigate | destinations come only from `_nav_groups()`; the index is server-rendered and escaped by `_nav_links()`; Task 3's set-equality check fails on any addition |
| T-26-01-C | Elevation of privilege | a state change reachable from a keystroke with no CSRF token (`auth.py:263`, `SameSite=Strict` only) | mitigate | the palette navigates and never acts; Task 3 greps the script for every submission and fetch sink |
| T-26-01-SC | Tampering | dependency installs | accept | no package manager is involved — no bundler, no framework, no dependency; the file is hand-written ES5 |
</threat_model>
