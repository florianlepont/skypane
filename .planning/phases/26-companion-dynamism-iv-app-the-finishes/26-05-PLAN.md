<objective>
"Guided first run" is the item most likely to be built as three green ticks that
are always green. One of its four proposed items cannot fail, one describes a
concept this codebase does not have, and the tempting implementation of the whole
thing — a "seen it" flag in browser storage — would put a second source of truth
beside a server-authoritative app.

This plan builds the version that survives all three problems: three signals
derived live from state the app already holds, a card rendered from them, and a
disappearance that is a property of the data rather than a promise about a flag.
It adds no script, no storage, no state file and no schema.
</objective>

<decisions_covered>
CFG-56. **"Password set ✓" is replaced, not kept** — 26-RESEARCH.md §3.1, Open
decision 3, PROVISIONAL. Options recorded there: replace (taken), drop to a
three-item checklist, or keep as written (rejected — it fails the vacuity
question outright). The replacement compares the configured password against
`deploy/skypane.env.example`'s literal placeholder, in constant time, and renders
neither value.

**No dismissal control.** The card is a function of state, so "dismiss" has
nothing to write to. A dismissal would need exactly the persistence this plan
declines.
</decisions_covered>
