<objective>
This plan finishes D23 and then proves the thing the whole feature rests on.

The finishing is small: `g h/d/v/c` to jump, `/` to open the palette, Escape to
leave, and the two guards every shortcut implementation needs and half of them
forget — do not fire while someone is typing, and do not let a chord's first key
hang around forever.

The proving is the point. A palette is script-only, and this project's no-JS
floor is absolute. The only honest way to hold both is to make "everything the
palette reaches is reachable without it" an executable, exhaustive check — every
destination, every run. That check is this plan's real deliverable; the keystrokes
are the easy half.
</objective>

<decisions_covered>
CFG-55, and CFG-53's no-JS half. **There is no touch equivalent for a keyboard
shortcut and none is invented** — 26-RESEARCH.md §2.6. The bottom tab bar (22-14)
already is the touch answer for navigation, on every authenticated page below
960 px, and adding a second gesture-based jump mechanism would contradict the
standing refusal of the overlay drawer as well as duplicate the tab bar. The
palette itself IS reachable by touch, via 26-01's visible trigger.
</decisions_covered>

    Register ONE delegated `keydown` listener at document level, following
    `submit-guard.js`'s registration shape.

    Bind: `/` opens the palette. `g` begins a chord; a following `h`, `d`, `v` or
    `c` navigates to Home, Display, Flights (the "v" of the audit's list) and
    Airlines respectively — **resolving each destination by looking it up in the
    server-rendered index by slug**, never from a literal path in this file. A
    letter this file maps to a path it typed itself is the second destination
    list that 26-01 exists to prevent.

    Guard 1 — do not fire while typing. Return early when the event target is an
    `<input>`, `<textarea>`, `<select>`, any element whose `isContentEditable` is
    true, or when `ctrlKey`/`altKey`/`metaKey` is held (except the palette's own
    accelerator). Write the guard as a single named predicate with a docstring
    comment, not as an inline condition repeated per binding — a guard that exists
    at three of four call sites is the defect.

    Guard 2 — bound the chord. A named constant holds the window in milliseconds;
    state the value and the reason in a comment. When the window expires the
    pending `g` is discarded. The pending state is cleared on blur, on the
    palette opening, and on any non-matching key. This is the one timer the phase
    adds, and the header must say so.

    Then drive it, using 26-02's targeted keystroke helper: press `g` inside the
    Airlines filter input, inside the palette's own search input, and inside a
    `<textarea>` if one exists (otherwise record that no textarea exists in this
    app and say so). Each must leave the page unchanged and the palette closed.
    Press `g`, wait past the window, press `h` — nothing happens. Press `g` then
    `h` within the window — Home. Press `g` then `q` — nothing, and the pending
    state is cleared.
