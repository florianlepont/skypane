<objective>
"Share the picture of the day" sounds like a link. In this app a link is the one
thing it cannot be.

Every page is session-gated and every HTML response is `no-store` by a deliberate
Phase 18 decision. Authentication is one shared password. And since Phase 16 the
picture is not just a departure board: a calendar match repaints the panel, so the
picture's colour can say "a flight from my private calendar is leaving now". A
shareable URL would need a new unauthenticated route, a token store, an expiry
policy, a revocation path, and a test for each — and would put that signal behind
a forwardable link.

So this plan shares the bytes instead. A `download` anchor is the floor: no
script, every browser, resolves through the caller's own session. `navigator.share`
is the phone enhancement, built from the image already on the page. Nothing becomes
public, nothing expires, nothing needs revoking — and a check proves it.
</objective>

<decisions_covered>
CFG-58 in full, and 26-RESEARCH.md §4's privacy answer.
**Open decision 8, PROVISIONAL:** the File is built by canvas re-encode rather
than by `fetch`, to preserve `panel-lookup.js:14-17`'s pinned "never introduce a
network call, a timer, or any persistent state". The stated cost: the shared PNG
is visually identical but **not byte-identical** to the served file. Alternatives
priced in the research: amend the pin and use `fetch` (B), or a dedicated new
script (C, which would take the phase to two scripts). Neither is taken.

This is not in tension with 25-07's refusal of a client-side canvas for D19: that
refusal's ground is a second, differently-thresholded MEASUREMENT drifting from
`illustration_normalize.py`. This canvas measures nothing; it re-encodes bytes.
</decisions_covered>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated internet → any companion route | the boundary this plan asserts is unmoved |
| authenticated session → image bytes | the download resolves through the caller's own session, as `_serve_gallery_image()` already requires |
| browser → OS share sheet | bytes leave the app by the user's explicit action, to a destination the user chooses |
