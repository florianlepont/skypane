<objective>
Make the device protocol server safe and exact: content-addressed image download (INT-05),
request hardening (INT-06, the remaining sub-items), and unique-temp atomic writes for byos's
three state files (INT-02, byos copy).

Already fixed and not redone here (say so in SUMMARY): INT-06's "non-string `mac` crashes the
handler" was fixed by Phase 34 (FW-08, 34-03: `normalize_mac()` answers 422), and the enrolment
secret already uses `hmac.compare_digest` (`secret_matches`). What remains is `Content-Length`,
the socket timeout, the bearer check in `bearer_ok()` and non-dict log entries.

Room left for 37-11 (byos `--bind` and IP filtering): the server is still built by the one
expression `ThreadingHTTPServer(("0.0.0.0", args.port), Handler)` in `main()`, which 37-11
greps for and replaces with `(args.bind, args.port)`; this plan adds no outbound connection
(no `urllib`, `requests`, `http.client` or `socket.create_connection` in byos), so 37-11's
`IPAddressDeny=any` cannot break it; the new `--request-timeout` flag only sits in the argument
parser next to `--port`.

Vendor boundary: byos still never imports `server.*` (until Phase 39 ARC-05). Its
`_atomic_write` is a local copy; a behaviour-parity test (not a source-text guard) pins it to
`server.atomic_io.atomic_write`. Record the copy in SUMMARY as a Phase 39 ARC-05 input.

Firmware: no change. The firmware checks HTTP 200 + exactly 960 000 bytes + SHA-256 against
`image_hash` and treats a non-200 as a failed download retried on the next wake
(`firmware/main/api_client.c` `fp_download_verdict`, `firmware/main/state_machine.c`).
Output: hardened `stub-server/byos_server.py`, `stub-server/test_byos_hardening.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| frame/Internet -> byos (through Caddy) | any client can reach `/device/v1/*` and `/img/*`; only `/display` and `/log` need a bearer token |
| byos -> state/ | byos writes byos_state.json, devices.json, battery_state.json and img/ |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-11 | Denial of service | `read_body_json` Content-Length | mitigate | negative/non-integer 400, > 64 KiB 413, body never read in those cases, connection closed |
| T-36-12 | Denial of service | stalled client pins a thread | mitigate | `Handler.timeout` (15 s default) applied to the socket; test with 1 s |
| T-36-13 | Information disclosure (timing) | `bearer_ok` | mitigate | `hmac.compare_digest` over every stored token, no early exit |
| T-36-14 | Tampering / path traversal | `/img/` handler | mitigate | full-path regex `^/img/[0-9a-f]{64}\.bin$`, file name built only from the matched hex, anything else 404 |
| T-36-15 | Denial of service (disk) | `img/` growth | mitigate | pruned to 8 hash files on each publish; only `/display` (authenticated) publishes |
| T-36-16 | Information disclosure | devices.json mode | mitigate | `_atomic_write(mode=0o600)`: mode set on the temp before data, test checks 0600 |
| T-36-17 | Repudiation | malformed requests | accept | byos logs method and path only, as today; no body contents are logged beyond the existing frame-log lines |
</threat_model>
