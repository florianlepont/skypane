## Decisions Made
- Went beyond `03.1-PATTERNS.md`'s literally-quoted one-line extraction (`(winner.get("t") or "").strip().upper() or None`) in two ways, both required by the plan's own stated behavior, not scope creep: (1) an `isinstance()` guard before calling `.strip()`, since the naive one-liner would raise `AttributeError` on a truthy non-string `t` (e.g. an int, which is truthy and would skip the `or ""` fallback); (2) an alphanumeric-only shape regex (`_VALID_AIRCRAFT_TYPE_RE`) after strip/upper, since the plan's Task 2 malformed-value battery explicitly requires a path-separator string to yield `None`, which a bare type/emptiness check cannot satisfy.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Added ICAO-designator-shape validation beyond the naive strip/upper extraction**
- **Found during:** Task 2 (writing the malformed-type-value battery check)
- **Issue:** The plan's own Task 2 action text requires a path-separator string (e.g. `"../../etc/passwd"`) to yield `aircraft_type is None`. `03.1-PATTERNS.md`'s literal suggested extraction line only checks truthiness/emptiness after `.strip().upper()`, which would pass a path-separator string through as a normalized-but-non-empty string (e.g. `"../../ETC/PASSWD"`), failing that requirement and leaving a raw-shaped untrusted string one step closer to a future filesystem lookup (T-03.1-02-01, ASVS V5).
- **Fix:** Added `_VALID_AIRCRAFT_TYPE_RE = re.compile(r"^[A-Z0-9]+$")`; the stripped/uppercased candidate must match this shape or the result is `None`. Real ICAO type designators (B738, A20N, AT76, E145) are always short alphanumeric strings, so this doesn't reject any legitimate value while closing the path-separator gap.
- **Files modified:** `server/plane/detect.py`
- **Verification:** `server/test_plane_detection.py`'s malformed-battery check (including the path-separator case) passes; all 5 of Task 1's original acceptance-criteria one-liners (valid `b738`, int `t`, missing `t`) re-verified unchanged after the addition.
- **Committed in:** `0ea839f` (Task 2 commit - the gap was discovered while implementing Task 2's own specified check, so it's committed alongside that check rather than requiring a Task 1 amendment)
