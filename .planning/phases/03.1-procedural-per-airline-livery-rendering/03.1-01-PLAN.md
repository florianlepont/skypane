## Planner decisions recorded for this phase

These close RESEARCH.md's Open Questions and Assumption A2 with documented rationale
rather than leaving them for the executor to guess. They are repeated in every plan that
implements them.

- **P-01 (RESEARCH Open Question 1 — CCM Airlines / Air Corsica):** the selection key and
  the filename `ccm-airlines.png` stay exactly as they are (Pitfall 1 — `adsbdb` still
  resolves the pre-rebrand string, confirmed live). Brand accuracy is closed instead by a
  presentation-only alias applied in `render.py` alone (plan 03.1-04, `P-01` again),
  never in `illustrations.py`. Rationale: D-04's real concern is what a human reads on the
  glass; the alias is one dict entry, never reaches a filesystem path, and leaves selection
  keyed on the data source's literal output so a future genuine `adsbdb` miss still surfaces.
- **P-02 (RESEARCH Open Question 2 — display-label wording):** Claude's Discretion per
  CONTEXT.md. Use the specific labels (neo and MAX variants called out by name) from
  RESEARCH.md Code-Level Finding #6. Rationale: D-03's own verified table distinguishes neo
  variants, the label is genuinely more informative, and it is cosmetic and reversible.
- **P-03 (RESEARCH Open Question 3 — easyJet):** generate `easyjet.png`. Rationale:
  RESEARCH.md's own recommendation; `EZY` (UK AOC) is a live-confirmed `adsbdb` hit, so the
  file is selectable in the real world. `EJU` (Austrian AOC) stays a documented, deliberate
  exclusion, unchanged from Phase 3.
- **P-04 (RESEARCH Assumption A2 / Pitfall 3 — primary vs secondary for mixed fleets):** the
  unsuffixed `{airline-slug}.png` is the numerically dominant type, and an already-vendored
  file is never regenerated purely to swap roles. Concretely: `transavia-france.png` stays
  B737 (secondary `transavia-france-a320.png`, with D-05's note that these roles will swap
  later this decade), `ccm-airlines.png` stays A320 (secondary `ccm-airlines-atr72.png`),
  `royal-air-maroc.png` is B737 (secondary `royal-air-maroc-embraer.png`),
  `air-caraibes.png` is A350 (secondary `air-caraibes-a330.png`).
- **P-05 (validator sequencing):** `required_filenames()` keeps meaning "files that must
  exist and validate right now"; the full D-03 plan lives in a new `target_filenames()`.
  Rationale: `server/test_illustrations.py` asserts every entry of `required_filenames()`
  exists and validates, and `scripts/run-all-tests.sh` runs in CI — expanding the required
  set to ~38 entries before the art exists would hold CI red for the whole hand-off. No
  target is dropped; `outstanding_filenames()` reports the remainder and `--strict-targets`
  fails on it.
- **P-06 (ATR42):** ATR42 ICAO codes map to the `atr72` shape bucket, per D-03's explicit
  "only 7 distinct base shapes" table which has no separate ATR42 entry.
