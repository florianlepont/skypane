<conventions>
- Planning correction to the research: test_render.py DOES rebind render-namespace functions by assignment
  (`render._font = _spy_font` near lines 756/784, `render.draw_main_text_block = ...` and
  `render.draw_previous_text_block = ...` near 2513/2591). After a split, a rebinding on the package
  object is a silent no-op for code in a submodule, and the byte-identity test near 2513 would then pass
  vacuously. Rule: inside the package, every call to `_font`, `_role_font`, `draw_main_text_block` and
  `draw_previous_text_block` from another submodule goes through the defining module attribute
  (`text._font(...)`, `text.draw_main_text_block(...)`), and those test sites rebind on `render.text`.
  Each retargeted test adds a non-vacuity assertion (the spy recorded at least one call).
- Other patches hit shared objects (PIL classes via `render.ImageDraw`, `render.illustrations`,
  `poll_loop.render.build_canvas` on the package) and keep working if `__init__` binds those names.
- `git mv server/plane/render.py server/plane/render/__init__.py` first, then carve submodules out, and
  delete nothing else. Keep `_font_cache` and `_illustration_cache` in exactly one module each.
- `build_canvas` dispatches to both layout and hold screens: it lives in `layout.py`; `hold_screens.py`
  must not import `layout`. Submodules never import the package `__init__`.
- No new module named after a stdlib module (research §7). `style.py`, `text.py`, `glyphs.py`, `layout.py`,
  `hold_screens.py`, `cli.py` are clear of that rule as package submodules imported by absolute name.
- `firmware/tools/gen_fault_screen.py` imports `server.plane.render._build_no_connection_canvas` and writes the
  literal provenance text `server/plane/render.py _build_no_connection_canvas(flat=True)` into
  `firmware/main/fault_screen_mask.h`, which `server/test_fault_screen_mask.py` compares byte-for-byte. Leave that
  provenance string and the header untouched in this plan.
