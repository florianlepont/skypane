Then read whether the key existed, call `colour_rules.delete_rule()`, and redirect to the Settings route with the deleted flash key on success or the delete-failed key when the entry existed but the delete reported failure. Deleting an already-absent key is success, not an error, matching the existing idempotent precedent.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-01 | Tampering | the add route and the delete route's path segments | high | mitigate | Every request-supplied value is normalised through `colour_rules.normalise_rule_kind()` / `normalise_rule_value()` before it is used — at write, on the delete route's lookup, and again before the `rule=` value is interpolated into the replaced flash message. An unrecognised kind or a malformed value on the delete route is a 404, never a lookup against a request string. The registry module re-applies the same allowlist on every read as the second line (plan 14-01). Proved by Task 3's rejection and 404 checks. |
| T-14-05 | Tampering | the add route's `rule_theme_id` | high | mitigate | Membership validation happens inside `colour_rules.add_rule()` against `device_config.THEMES` before anything is written, and the route maps the resulting rejection to the generic save-failed flash. A crafted theme id therefore cannot become a stored rule and cannot reach `render.build_canvas()`. Proved by Task 3's crafted-theme check, which asserts nothing is written. |
| T-14-13 | Cross-site request forgery | the two new state-changing POST routes | medium | transfer | No new mechanism: both routes fall under the existing site-wide `require_session()` gate in `do_POST()` and the session cookie's `SameSite=Strict` flag, which is this app's documented, uniformly-applied CSRF control. | T-14-14 | Information disclosure / injection | the `rule=` query parameter echoed into a flash message | medium | mitigate | Validate-then-display: the value is re-normalised through its kind's allowlist before interpolation and falls back to the generic added message when it fails, so only uppercase alphanumerics can ever reach the string; `escape_html()` on render is the second line. Nothing displayed comes from the request unvalidated. |
| T-14-04 | Denial of Service | registry growth via the add route | medium | mitigate | The cap is enforced in `colour_rules.add_rule()` (plan 14-01) and the route surfaces it as the registry-full flash rather than failing silently. | T-14-02 | Tampering / Repudiation | concurrent add and delete requests | medium | transfer | Fully mitigated in `server/plane/colour_rules.py` (plan 14-01, T-14-02): one module-level lock wrapping the whole load-check-mutate-write sequence and pid/thread-scoped temp filenames.
