# Phase 06.6.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This contract **supersedes `06.3-UI-SPEC.md`'s Design System, Typography, and Color sections**, and **extends its Spacing/Layout/Component sections**, for the companion web app only (`companion/`). It is the second visual-design pass on this codebase (06.3 was the first) — a genuine evolution, not a from-scratch redesign: every token this phase changes is named against its existing 06.3 value so the delta is auditable. It does not touch, and stays entirely separate from, the physical frame's own design system (`03-UI-SPEC.md`/`07-01-PLAN.md`). Source of every decision below: `06.6.1-CONTEXT.md` (D-01 through D-06, locked) and the `sketch-findings-skypane` skill (three sketch sessions, winners: 001-B, 002-C, 003-B), reconciled against the real, currently-shipped tokens in `companion/static/style.css` and `companion/layout.py`.

## Typography

Exactly 4 sizes, 2 weights — same token *values* as `06.3-UI-SPEC.md` (14/16/20/24px, weights 400/600); this phase changes which **font-family and weight** the Heading role uses, and reassigns the site title from Display to Heading. No new size is introduced (the sketch prototypes used one-off 15px/18px/19px values in a few spots — reconciled below onto the existing 4-value scale so the declared contract stays exactly 4 sizes).

| Role | Size | Weight | Font Family | Line Height |
|------|------|--------|-------------|-------------|
| Label | 14px | 400 (regular) | sans (`--font-ui`) | 1.4 |
| Body | 16px | 400 (regular) | sans (`--font-ui`) | 1.5 |
| Heading | 20px | **400 (regular)** — was 600 (semibold) in 06.3 | **serif (`--font-serif`)** — was sans in 06.3 | 1.2 |
| Display | 24px | 600 (semibold) | sans (`--font-ui`) | 1.2 |

Usage (revised):

- **Heading (20/400/serif) — the core typographic change this phase makes:** applies to every `<h1>`/`<h2>`/`<h3>`/`.text-heading` element (page titles, section sub-headers, empty-state headings) **and, new this phase, the site title** (`.site-title`, both the header copy and the sidebar copy `.sidebar-title`) — reassigned down from Display (24px) to Heading (20px) and onto the new serif family. This directly answers D-01 ("redesign its typography/spacing to feel more crafted, not just default bold sans-serif") without adding a logo asset. Letter-spacing on `.site-title`/`.sidebar-title` stays `+0.02em` (unchanged from 06.3). Add `letter-spacing: -0.01em` on the general heading selectors (`h1, h2, h3, .text-heading`) per the sketch's CSS pattern — serif faces read tighter at this weight.
- **Display (24/600/sans) — narrows in scope this phase:** `.stat-tile__value` (large numbers/mV readings) only. No longer used by the site title (moved to Heading, above).
- **Body (16/400/sans):** unchanged — all prose, table cell content, form help text, button labels, stat-tile supporting detail line.
- **Label (14/400/sans):** unchanged token, but **one new usage this phase:** `.stat-tile__caption` switches from small-caps uppercase (`text-transform: uppercase; letter-spacing: 0.04em`) to normal-case, with `font-family: var(--font-serif)` layered on top of the existing 14px/400 Label size — this reconciles the sketch's one-off 15px caption value down onto the declared 14px Label token while preserving the "warmer, less form-field-label" feel the sketch validated. **Stat-tile captions are therefore the one Label-role text that is serif, not sans** — a deliberate, narrow exception, not a precedent to extend elsewhere.
- Monospace variant unchanged: same 14px/16px sizes, `ui-monospace` stack, weight 400 only.

**What stays sans-serif (explicit, per D-03 — do not extend serif beyond the list above):** all body text, table cells (History, Battery trend, Airlines), form inputs/labels, nav links (sidebar links AND the new mobile dropdown's nav links — the raw sketch prototype in `002-mobile-hamburger-nav.html` styled dropdown nav-links in serif at 18px, but that detail was never part of `06.6.1-CONTEXT.md`'s locked decisions; D-03's "body text stays sans-serif" rule takes precedence, so dropdown/sidebar nav links stay Body-size (16px) sans-serif, not serif), the hamburger button's accessible label, monospace/data content, and the theme-picker buttons.

## Layout Contract

### Mobile navigation (< 960px) — **replaces the horizontal-scroll nav strip (D-06, core deliverable)**

Winning pattern: sketch 002, Variant C ("Header dropdown"). Full spec:

- **Trigger:** a hamburger icon button (`icon-hamburger`, 24×24 inline SVG, 3 horizontal lines), placed in the header where the horizontal nav-bar/theme-form used to sit, right-aligned. Minimum 44×44px tap target (D-22).
- **Open behavior:** tapping the hamburger expands a panel directly below the header, **pushing page content down** — no backdrop, no full-screen takeover, no `position: fixed`. Implemented via a `max-height` transition (`max-height: 0` → `max-height: 420px`, `overflow: hidden`, `transition: max-height .22s ease`), not `display`/`height:auto` (neither can transition). The dropdown is `position: absolute`, contained by the header's own `position: relative` — correct and sufficient for "pushes content down in normal flow" without a `position: fixed` stacking-context workaround.
- **Dropdown contents, top to bottom:** the 5 nav links (`NAV_TABS`, same order as today — Config/Health/Airlines/History/Preview), each a real `<a>` with 44px+ min-height, sans-serif Body-size text (see Typography — no serif here); **then** the existing theme-picker (Auto/Light/Dark 3-button row) below the nav links — this is where the theme picker relocates once it's no longer squeezed into the header row (the D-00 crush-bug's root cause; this phase removes the cramped header placement entirely rather than re-fixing the flex sizing again).
- **Close behavior:** tapping the hamburger again toggles closed (same button, same handler, reads current state). **Escape key also closes it** (a global `keydown` listener, scoped to only act while the dropdown is open).
- **Accessibility:** hamburger button carries `aria-expanded`, synced on every open/close transition (see Copywriting Contract for the fixed-label rationale).
- **Implementation:** requires real JS (the toggle also needs `aria-expanded` sync, which a CSS-only `:checkbox`/`:target` hack cannot do cleanly alongside Escape-to-close). **New file:** `companion/static/nav-dropdown.js`, following the exact conventions `companion/static/battery-trend.js` (Phase 06.5) already established for this project — `"use strict"` IIFE, ES5-safe (no `let`/`const`/arrow functions/template literals), no network calls, no timers, no persistent state, served via a new pre-auth static route mirroring the existing `/static/style.css` and `/static/battery-trend.js` routes. Early-returns if the hamburger button isn't present in the DOM (same defensive pattern `battery-trend.js` uses for pages without a chart).
- **Desktop sidebar nav (≥960px) is untouched by this change** — `sidebar_nav()`'s existing markup, the 960px dashboard-shell breakpoint, and the 240px sidebar column all stay exactly as 06.3 shipped them. The mobile dropdown is a **third** navigation rendering mode for the <960px range specifically (alongside the existing horizontal-nav-bar-now-removed and the sidebar), not a replacement for the sidebar.
- **Below 480px:** the previous horizontal-scroll sub-breakpoint rule for `.nav-bar` is now dead code (the horizontal nav-bar itself is gone below 960px) — remove it rather than leaving an orphaned, unreachable CSS rule.

### Health nav-tab notification indicator (new, all widths)

- A small error-colored dot (reuse `.dot--error`'s existing visual treatment, not a new color) appended after the "Health" text in **both** places the nav link renders: the desktop `sidebar_nav()` link and the mobile dropdown's "Health" link. Not shown in a third place — there is no third nav rendering.
- Driven by the same anomaly signal `health_page.py::collect_anomalies()` already computes — this needs a new cross-page `ctx` key (e.g. `ctx["health_anomaly_active"]`), threaded through `companion/app.py`'s `page_context()` the same way `ctx["runway_images"]` was added in Phase 06.4 (existing precedent for adding a new cross-page ctx signal without a page module importing another page module, which `companion/pages/__init__.py` forbids).
- Absent (no dot, no markup) when no anomaly is active — same "absence is the all-clear" precedent as the anomaly banner itself and CFG-05's source-fault badge.

### Battery-trend section — full-width (was a cramped grid tile)

- Moves **out of** the Health page's `.dashboard-grid` (Overview) entirely, into its own full-width `<section>` immediately below the Overview grid.
- Same card treatment as stat tiles (`--shadow-card`, `--radius-card`, serif `<h2>` heading "Battery trend") — visually consistent with the grid above it, just not grid-constrained to a `minmax(240px, 1fr)` column width.
- The existing `status_dot()` badge (Phase 06.5, D-01) and the interactive per-point hit targets/readout (D-02, `battery-trend.js`) are unchanged in mechanism — only the section's container and available width change.

### Health Overview stat-tile icons (new)

- Each of the 4 Overview tiles (Device check-in, ADS-B pipeline, Battery trend, Corroboration) gains a small inline SVG icon (`icon-device`/`icon-pipeline`/`icon-battery`/`icon-corroboration`, 20×20, from the shared `<defs>` block) in its header, accent-tinted (`color: var(--color-accent)`) when the tile's status is neutral, or tinted to that tile's own status color when ok/warn/error applies (same color source the tile's top-accent already uses — no new color logic, just a second element consuming the same status→color mapping).
- **Scoped to Health's 4 Overview tiles only.** Airlines' 2 tiles (Coverage group) do not get icons this phase — not part of the validated sketch scope; extending icons there is a future-phase decision, not this contract's.

### History table density — 9 columns → 7 (D-06/`data-density.md`, winner: sketch 003 Variant B "Inline compact")

- **Merge Callsign + Hex** into one column, one line: `{callsign} · {hex}` — callsign bold mono (`.cell-primary`), middle-dot separator (`.cell-inline-sep`), hex muted mono 12px (`.cell-secondary`).
- **Merge Aircraft type + Airline** into one column, same pattern: `{type} · {airline}`.
- **Row height stays identical to today** — this was the deciding factor over the rejected "stacked cells" variant (two-line cells inside one `<td>`, which grows row height and works against fast scanning). Do not stack; keep everything on one line per cell.
- **Column order after merge:** Timestamp, Callsign (merged), Type (merged), Route, State, Corroboration, Runway — same left-to-right order as today, two fewer columns.
- Both merged cells still go through `companion/layout.py::escape_html()` exactly like every other cell in `history_page.py::_history_table_html()` — no second escaping path.
- **Mobile fallback unchanged:** keep the existing `.data-table-wrap` horizontal-scroll wrapper for <960px — this phase's decision was explicitly to keep scroll-on-mobile rather than switch to a stacked-card responsive pattern, since 7 columns (down from 9) is already easier to manage on a phone.
- **Known interim-state caveat (verify at execution time):** this table's Timestamp column was sketched assuming Phase 06.6's shortened relative-timestamp format (`"3m ago"`) already shipped. As of this UI-SPEC's writing, **Phase 06.6 has not yet executed** (`ROADMAP.md`: 0/3 plans). If 06.6.1 executes first, the Timestamp column still holds the full ISO string (e.g. `2026-08-29T07:24:05+00:00`) and will take noticeably more horizontal width than the sketch showed. This is an **accepted interim state, not a blocker** — the 7-column merge still reduces total width regardless of Timestamp's exact format, and `.data-table-wrap`'s horizontal-scroll fallback remains in place at every width as a safety net. Re-verify the unscrolled fit on a real ~1280px-wide viewport once both phases have shipped; do not block this phase on 06.6's timestamp work.
- **Do not implement Variant C** ("max density", 6 columns, also merging State into Route) — explicitly out of this phase's locked scope; shown in the sketch only as a "how far could this go" reference.

### Anomaly banner — redundancy removed (D-04)

- Keeps its existing visual treatment (`banner--anomaly`, red left border) and its existing gating mechanism (`collect_anomalies()` returning a non-empty list).
- **Removes** the `<ul><li>` detail-item list that previously rendered below the banner heading — see Copywriting Contract for the accompanying heading-text revision (the old text referenced "the flagged item(s) below," which no longer exist).
- `collect_anomalies()` itself is unchanged (still computes the same list) — only `health_page.py::render()`'s markup-building step changes (stop building the `<ul>`, stop concatenating it onto `banner_html`).

### Desktop dashboard shell (≥960px) — unchanged from 06.3

No changes this phase. 240px sidebar, 1440px main-column max-width, `repeat(auto-fit, minmax(240px,1fr))` dashboard grid — all carried forward as-is. The new spacing (Spacing Scale table above) and new card treatment (shadow/radius) apply here too, since those are global token changes, not layout-structure changes.
