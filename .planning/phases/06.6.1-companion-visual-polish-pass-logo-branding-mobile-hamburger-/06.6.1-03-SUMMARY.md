## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Task 1's own inline verify script's literal `'<ul>' not in src` / `'<li' not in src` gate was tripped by my own explanatory comments naming the markup being removed**
- **Found during:** Task 1
- **Issue:** The mandatory comments explaining the `ANOMALY_BANNER_TEXT` copy change and `collect_anomalies()`'s docstring addition both used the literal substring `<ul>` to describe the removed markup, which the plan's own textual gate (`assert '<ul>' not in src`) cannot distinguish from real markup.
- **Fix:** Reworded both comments to describe the same removed element ("bulleted detail-list markup") without the literal `<ul>` substring.
- **Files modified:** `companion/pages/health_page.py`
- **Verification:** Task 1's inline Python parsing gate passes; `companion/test_status_pages.py` 38/38.
- **Committed in:** `708a1b0` (Task 1 commit)

**2. [Rule 1 - Bug] Task 3's plan-authored assumption that `anomaly_active()` returns `False` for a merely-empty (but writable) directory contradicts the codebase's own pre-existing, documented D-12 behaviour**
- **Found during:** Task 3, while implementing the "never raises on hostile inputs" check
- **Issue:** The plan's action text and its own inline `<verify>` script both assert `h.anomaly_active(empty) is False` for a temp directory that exists but has no data yet. Verified directly against the running code: a genuinely empty-but-writable `state_dir` makes `history_db.open_db()` succeed (it creates the schema), so `_device_section()`/`_pipeline_section()` correctly read "never seen" and map to `"warn"` per `staleness_status()`'s own pre-existing, documented D-12 rule (`age_seconds is None -> "warn"`) — untouched by this plan. `collect_anomalies()` treats any non-`"ok"` state as an anomaly, so `anomaly_active()` correctly returns `True` for this case, and `render()` itself already shows `ANOMALY_BANNER_TEXT` for a truly empty `state_dir` (confirmed by direct execution, predating and unrelated to this plan). Forcing `anomaly_active()` to lie and return `False` here would have broken the exact agreement property Task 3 exists to guarantee.
- **Fix:** Kept the `False` assertion only for the three inputs that make the database itself unopenable (non-existent path, corrupt `history.db`, a regular file in place of a directory) — where every section builder's `_DB_UNAVAILABLE` branch correctly returns `"ok"`. For the empty-but-writable-directory case, asserted instead that the call does not raise (returns a `bool`) and that its verdict agrees with `render()`'s own banner presence for that same fixture — preserving the check's real intent (never raises, never disagrees with the page) without asserting an incorrect specific value.
- **Files modified:** `companion/test_status_pages.py`
- **Verification:** Direct execution confirmed `anomaly_active()` returns `False` for the non-existent-path, corrupt-db, and file-not-directory cases, and `True` (agreeing with `render()`) for the empty-directory case; `companion/test_status_pages.py` 42/42.
- **Committed in:** `d555da0` (Task 3 commit)
