# Phase 06.6.1 Plan 04: Health icon sprite and nav-tab notification dot Summary

**Added a single five-symbol inline icon sprite (device/pipeline/corroboration/battery/hamburger) referenced everywhere via `<use>`, wired icons onto Health's three Overview tiles and its Battery trend heading, and surfaced an active anomaly as a small error-coloured dot on the Health sidebar link from every tab — driven by a new `ctx["health_anomaly_active"]` signal computed once per request in `companion/app.py`.**

## Accomplishments
- `layout.ICON_IDS` (exactly 5: device/pipeline/corroboration/battery/hamburger), `ICON_DEFS_HTML` (one inline `<svg class="icon-defs">` sprite, outline glyphs, `stroke="currentColor"`, no hex fills), `STAT_TILE_ICON_CLASS`, and `icon_html(icon_id, size=20, extra_class="")` — a whitelisted `<use>`-reference builder that renders `""` for any id not in `ICON_IDS`

## Decisions Made
- `icon-hamburger` is defined in this plan's sprite even though plan 06.6.1-05 is the one that consumes it — per the plan's own instruction, this keeps `ICON_DEFS_HTML` the single write site for every icon rather than a second definition site landing in plan 05.
- The battery-trend heading's icon deliberately carries no tint class, unlike the three Overview tile icons — the Battery section is a page section, not a status tile, so there's no status modifier for `.stat-tile__icon`'s tint rule to hang off; it correctly inherits the heading's own colour via `currentColor` instead.
- `HEALTH_ALERT_SUFFIX_TEXT` is appended via a separate visually-hidden `<span>`, never an `aria-label` override — an `aria-label` would replace the link's accessible name and lose the word "Health" for screen-reader users; the appended span adds to it instead, per 06.6.1-UI-SPEC.md's explicit accessibility rationale.
