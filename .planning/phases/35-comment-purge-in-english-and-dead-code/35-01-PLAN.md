  </behavior>
  <action>
Write the tests first, then the tool (RED, then GREEN).

Tool:
- stdlib only, one file, with subcommands:
  - `check [--paths P ...]`. With no paths it scans `git ls-files`, minus the exclusions and
    minus the paths in `scripts/comment-history-pending.txt`. With `--paths` it scans exactly
    those paths and ignores the pending list;
  - `ratio [--out TSV] [--before TSV --markdown] [paths]`;
  - `same-code --base REV [--allow P ...] [paths]`. By default it compares the files changed
    between REV and the working tree.
- Output: each hit as `path:line: pattern-name: text`; exit 1 on any hit or difference.
- Exclusions: `.planning/`, `.claude/`, `*.md`, `LICENSE`, `NOTICE`, `firmware/LICENSE`,
  `firmware/NOTICE`, data/binary files (images, fonts, json/jsonl, pem, log, ics,
  `server/fixtures/**`, `hardware/fixtures/**`, `hardware/logs/**`), `server/requirements*.txt`
  (generated) and the tool's own tests' literals (which are string literals anyway).
- String-aware extraction per language:
  - Python: `tokenize` COMMENT tokens plus docstring nodes via `ast`;
  - C/H: a hand tokenizer aware of string and char literals;
  - JS: string, template and regex-literal aware, using the heuristic in RESEARCH pitfall 4;
  - CSS: string and `url()` aware;
  - hash formats: `.sh`, `.service`, `.timer`, `Caddyfile`, `*.env.example`, `.yml`, `.yaml`,
    `.toml`, `CMakeLists.txt`, `Kconfig*` (including `help` text), `sdkconfig*`, `.gitignore`,
    `.in`, `partitions.csv`, where a `#` at the start of a token outside quotes starts a
    comment. `# CONFIG_X is not set` counts as code;
  - XML `<!-- -->` for `*.plist.template`.
- Patterns: the forms in the behavior block. Prefix IDs use an explicit allowlist:
  CFG TST FW INT CMP SEC DEVICE HYG EFF ARC RER PLANE DOC VIS MSG UXA UIR MR CP DP SEED UAT QT
  WR CR IN BL. Never use a generic `[A-Z]+-\d+`. Match a bare `NN-NN` only in plan context
  (followed by ` Task`, or preceded by `plan `/`Plan `). There is no inline suppression pragma.
- same-code rules:
  - Python: `ast.dump` equal after stripping docstrings. The module docstring is kept in the
    comparison when the module reads `__doc__`;
  - C/H: `cpp -fpreprocessed -P -w` output equal after whitespace normalisation, with a fallback
    to the internal tokenizer if cpp is missing;
  - JS/CSS: token streams equal without comments and whitespace;
  - hash formats: non-comment lines equal after stripping trailing comments;
  - every language: the pragma and SPDX/copyright multiset is equal.
- The tool's own comments and docstrings must pass `check` (no IDs).

Tests: parametrised per pattern × syntax, the negatives, one same-code test per language
(including the sdkconfig line, the pragma multiset and `__doc__`), and a `check` run over a
temporary git repository with a planted ID.
