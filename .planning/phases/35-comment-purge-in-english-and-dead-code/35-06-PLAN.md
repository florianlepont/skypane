<close_procedure>
This procedure is shared by every group-close plan. GROUP_PATHS is the group's pathspec
(here `server/`) and ALLOW is its explicit allow list.
1. Run `git fetch origin main`, then BASE = `git merge-base HEAD origin/main`.
   Run `CLI same-code --base "$BASE" [--allow …] $(git diff --name-only "$BASE" -- GROUP_PATHS)`.
   It must exit 0.
2. `CLI check --paths $(git ls-files GROUP_PATHS)` reports 0 hits.
3. Run `CLI ratio --before .planning/phases/35-comment-purge-in-english-and-dead-code/35-BASELINE/ratio-before.tsv --markdown $(git ls-files GROUP_PATHS)`.
   Append its output to `35-COMMENT-RATIO.md` under a heading for the group. Create the file
   with a one-paragraph header if it is absent. Add a group-total row, and list every file still
   above 35 % with the one-line justification taken from the plan SUMMARYs.
4. Delete every GROUP_PATHS line from `scripts/comment-history-pending.txt`. `CLI check` (no
   args) exits 0.
5. Run `./scripts/run-all-tests.sh` and `server/.venv/bin/ruff check .`. Run
   `find deploy -name '*.sh' -print0 | xargs -0 shellcheck` if shellcheck is installed;
   otherwise CI is the gate.
6. Merge `origin/main`. On STATE.md/ROADMAP.md conflicts, keep both sides. If the merge
   brought new history comments into GROUP_PATHS, purge them, then re-run steps 1-2 and 5.
7. Push and open a draft PR titled "Phase 35 group N: comment purge in <area>". The body gives
   the group totals before and after, the same-code evidence and the allow list, and ends with
   the session attribution lines.
</close_procedure>
