## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| companion HTTP POST -> `save_device_config()` | An untrusted submitted wake-interval value crosses into a persisted document |
| `device_config.json` on disk -> `load_device_config()` | A hand-edited or corrupted file crosses into every reader of the config, ultimately into `quiet_hours_sleep_s()`'s arithmetic and the device's deep-sleep duration |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01-01 | Tampering | `server/device_config.py` write path (`save_device_config()`) | high | mitigate | The new `wake_interval_s` guard runs before `current = load_device_config(...)` and before the file is ever opened: a non-int, a bool, or an out-of-`[60, 3600]` value raises `ValueError` and leaves any pre-existing file byte-identical (same T-06-01-01 all-or-nothing discipline as `theme`/`tracked_runway`). Task 2 acceptance criterion (4) proves byte-identity across every rejection |
| T-11-01-02 | Tampering | `server/device_config.py` read path (`normalise_wake_interval_s()` / `load_device_config()`) | high | mitigate | `normalise_wake_interval_s()` is never-raising and degrades every hostile on-disk shape to `None`, so a corrupted document can never propagate a bool, a string, or an absurd integer into a caller — and never into `quiet_hours_sleep_s()`'s arithmetic downstream (11-RESEARCH.md Security Domain, row 1; T-06-01-01 precedent reused) |
| T-11-01-03 | Tampering | The bounded-int type test itself | medium | mitigate | `isinstance(True, int)` is true in Python, so a bare int test would silently accept a boolean as a wake interval. Every bounded-int check in this module pairs `isinstance(value, int)` with `not isinstance(value, bool)`; Task 2 covers `True`/`False` explicitly on both the read and the write path |
| T-11-01-04 | Denial of Service | The device's own battery (DEVICE-05) via an extremely short interval | medium | mitigate | The 60s floor (D-02) is itself the mitigation, enforced identically on the read path (degrade to `None`) and the write path (raise `ValueError`); the Settings form that writes it already sits behind the companion app's existing session auth, unchanged by this phase |
| T-11-SC | Tampering | npm/pip/cargo installs | high | accept | This phase adds zero packages — every change is Python stdlib plus the existing first-party modules. No package-manager install task exists in any Phase 11 plan; `server/requirements.txt` is untouched, so a supply-chain entry point cannot be introduced without an out-of-plan edit |
</threat_model>
