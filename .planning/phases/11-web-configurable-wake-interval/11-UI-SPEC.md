# Phase 11 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

This phase touches only the companion web app's Settings page (`companion/pages/config_page.py`, `companion/static/style.css`). No e-ink panel surface is involved (unlike Phase 10). It adds exactly one new control: a fifth `.theme-status` group, `wake_interval_group()`, containing the **first plain `<input type="number">` anywhere in this codebase** — every prior field is a radio, checkbox, or Phase 10's `<input type="time">`. This document specifies that one new control's contract; every other visual property on the page (page chrome, nav, save-bar mechanics, colour tokens, type scale) is inherited unchanged from the existing design system documented in `sketch-findings-skypane` and is NOT re-litigated here.

## Interaction Contract

- **Control type:** `<input type="number" name="wake_interval_s" min="60" max="3600">` — HTML5 native stepper/spinner UI, no custom widget. This is a genuinely new control shape for this codebase (D-05); treat this contract as authoritative until a real-preview check confirms it, same discipline Phase 10 applied to its own first `<input type="time">`.
- **Bounds:** `min="60"` / `max="3600"` (D-02) rendered as native HTML5 attributes — client-side UX sugar only, never the security boundary. `server/device_config.py::save_device_config()` re-validates the identical bounds server-side and raises `ValueError` outside them (V5, asymmetric validation convention, matches every other bounded field on this page).
- **States to design for:**
  - **Filled (has an explicit saved value):** `value="{int}"` attribute present, no placeholder shown.
  - **Empty/unset (legitimate default state, not an error):** no `value` attribute, `placeholder="Uses server default"` shown in muted placeholder styling (native browser default — no custom placeholder colour override needed, matches `--font-body-size` in the browser's own muted placeholder tone).
  - **Invalid submission (client bypass, e.g. crafted request):** generic save-failed flash per Copywriting Contract above; the on-disk config value is left byte-identical (existing all-or-nothing rejection contract, matches every other field).
  - **Dirty (edited, unsaved):** picked up automatically by the page's existing dirty-tracking script and floating save bar — no group-specific dirty behavior to design; `wake_interval_group()`'s wrapping `.theme-status` div carries the same `DIRTY_SECTION_ATTR` every sibling group already carries.
- **Placement:** Fifth `.theme-status` group in the single-column Settings stack, in this order: Theme → Runway → Diagnostic LED → Quiet hours → **Wake interval** (new, last). No `<fieldset>`/`<legend>` wrapper (matches `led_group()`/`quiet_hours_group()`'s established "H2-headed group, no fieldset" pattern — a `<legend>` only has accessible-name semantics inside a `<fieldset>`, which these sibling groups deliberately don't use).
- **Markup shape** (mirrors `led_group()`'s structure, adapted for a numeric input instead of a checkbox):
  ```html
  <div class="theme-status" data-dirty-section="Wake interval">
    <h2 class="text-heading">Wake interval</h2>
    <p class="text-label section-caption">How often the frame wakes to poll for updates. Shorter means fresher info and more battery drain; longer means more battery life and staler info at a glance. Applies on the next scheduled poll.</p>
    <label>Wake interval (seconds)
      <input type="number" name="wake_interval_s" min="60" max="3600" placeholder="Uses server default" value="{current or omitted}">
    </label>
  </div>
  ```
- **Touch target:** No new CSS rule needed. The global `input, select { min-height: 44px; min-width: 44px; }` rule (companion/static/style.css line ~1242) already applies to every native input including `type="number"`, with no type-specific override required — identical precedent to Phase 10's `<input type="time">`, which the touch-target register already lists in its "kept" (44px floor) category. Record `<input type="number">` as a second entry in that same "kept" category, not a new exception.
- **Border/surface treatment:** No new rule. Inherits the same 1px `--color-border` edge, `--color-secondary` fill, and `--radius-control` (8px) every other text-like input already has.
- **Focus state:** No new rule. Inherits the existing `input:focus-visible` accent-outline treatment site-wide.
