<objective>
Deliver the configured wake interval to the device: add a best-effort
`read_wake_interval_s()` to `stub-server/byos_server.py` and make its value the base that
Phase 10's existing `quiet_hours_sleep_s()` extends, replacing the direct `self.args.sleep`
reference at the single `/device/v1/display` call site (D-01, D-03).

Purpose: this is the entire delivery mechanism. `sleep_s` is already a fully
server-controlled per-response field the firmware consumes as an opaque `uint32_t`
(confirmed again at `firmware/main/state_machine.c:51` and `firmware/main/app_main.c:172`),
so a saved config value reaches the device on its very next poll with no service restart,
no new protocol field, and zero firmware change.

Output: two independently-defined bound constants, one new never-raising read function,
one changed expression in the `/display` handler, updated local-modification provenance in
the module docstring and `stub-server/VENDOR.md`, and unit plus over-HTTP integration
coverage in `stub-server/test_poll_cycle.py`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `device_config.json` on disk -> `read_wake_interval_s()` | A hand-edited, bug-written or corrupted file crosses into the arithmetic that sets the device's deep-sleep duration |
| `stub-server/byos_server.py` -> device firmware (`GET /device/v1/display`) | The `sleep_s` field crosses the wire and is consumed by `enter_deep_sleep()` as an opaque `uint32_t` with no firmware-side interpretation |
