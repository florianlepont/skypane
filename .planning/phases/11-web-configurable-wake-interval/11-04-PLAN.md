<objective>
Implement D-07's locked pre-fill mechanism: `companion/app.py` reads `SKYPANE_SLEEP_S`
out of its own process environment and threads it into the page context as
`wake_interval_env_default`, so the Settings page's Wake interval field shows the real
deployed cadence on first load instead of an empty box — falling back honestly to the
placeholder whenever that value is absent, unreadable or outside the field's own bounds.

Purpose: 11-RESEARCH.md's Open Question 1 established that the companion process cannot
see `byos_server.py`'s `--sleep` argparse value, and recommended giving up on a pre-fill
entirely. The developer chose the better option, and the correction that followed made it
cheap: `deploy/skypane-companion.service` already declares the same
`EnvironmentFile=/opt/skypane/skypane.env` directive `skypane-byos.service` does, so
systemd already injects `SKYPANE_SLEEP_S` into this process exactly like it injects
`SKYPANE_COMPANION_PASSWORD`. This is a copy of an existing pattern, not new plumbing.

Output: one environment-variable constant, one never-raising reader, one new `ctx` key,
its entry in the documented page-context contract, coverage in
`companion/test_companion_app.py`, and a corrected `deploy/skypane.env.example` comment.
</objective>

Add `env_wake_interval_default()`, a module-level function placed near the other
module-level helpers. It calls `os.environ.get(SLEEP_ENV_VAR)` on every invocation — a
per-call read, never a value captured at import time, matching
`configured_password()`'s own per-call shape so a redeployed env file takes effect on the
next service restart with nothing cached in between. Convert the raw string with `int()`
inside a `try` that catches `(TypeError, ValueError)`, then return the result only when it
falls within the inclusive
`[device_config.WAKE_INTERVAL_MIN_S, device_config.WAKE_INTERVAL_MAX_S]` range; return
`None` in every other case, including an unset or empty variable. Never raises.

Document the one contract difference from `configured_password()` in the docstring, since
that is the function a reader will compare it against: `configured_password()` is
fail-closed and raises `AuthNotConfigured` when its variable is missing, because it guards
an auth boundary; this one is fail-open and returns `None`, because it is a UI pre-fill
convenience whose absence has a designed, legitimate empty state (the placeholder
`Uses server default`). Also document why the range check exists and is not merely
belt-and-braces: `deploy/skypane.env.example` ships `SKYPANE_SLEEP_S=30`, below the field's
own 60s floor, and rendering that as a `value` attribute on a `min="60"` numeric input
would fail HTML5 constraint validation and block submission of the entire Settings form —
not just this field. The honest, designed behaviour for a deployed value the form cannot
represent is the placeholder, not a number the user cannot save.

only consulted by `config_page.render()` when the stored value is `None`, i.e. before the
user has ever set one explicitly. Note in the same comment that once a user saves any
value, the stored one wins permanently — `save_device_config()` has no unset path, which
is deliberate (11-RESEARCH.md Open Question 2: an empty numeric input means "leave
unchanged", never "clear").

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Process environment (`SKYPANE_SLEEP_S`) -> `env_wake_interval_default()` | A deployment-controlled string crosses into a value interpolated into rendered HTML |
| `env_wake_interval_default()` -> `ctx` -> `config_page.render()` | The parsed value crosses into a native form control's `value` attribute |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-04-01 | Tampering | `env_wake_interval_default()` | medium | mitigate | The environment value is deployment-controlled, not user-controlled, but is still parsed defensively: `int()` inside a `try` catching `(TypeError, ValueError)`, then an inclusive `[60, 3600]` range test, returning `None` on any failure. Nothing but an int in that range can ever reach the rendered `value` attribute, and `wake_interval_group()` re-checks the same bounds independently before emitting it (defence in depth across the two plans) |
| T-11-04-02 | Denial of Service | The whole Settings form's submittability | medium | mitigate | An out-of-range environment value rendered as a `value` attribute on a `min="60" max="3600"` input fails native constraint validation and blocks submission of every field on the page. The range check here is the primary guard and Task 2 check (3)'s `"30"` case is its regression test, using the value `deploy/skypane.env.example` actually ships |
| T-11-04-03 | Information Disclosure | The environment read | low | mitigate | Only `SKYPANE_SLEEP_S` is read, never the whole environment, and the function returns an int or `None` — it never echoes a raw environment string into a page or an exception message, matching `configured_password()`'s explicit "never include the environment value in the raised exception" rule |
| T-11-04-04 | Elevation of Privilege | Route exposure | low | accept | The new key is built inside `page_context()`, which only authenticated page handlers call; the Settings page's existing session gate is unchanged by this phase and no new route is added |
| T-11-SC | Tampering | npm/pip/cargo installs | high | accept | This phase adds zero packages — the read uses `os.environ`, already imported by `companion/app.py`. No dotenv or other loader library is introduced, matching 02-RESEARCH.md's own Don't Hand-Roll ruling that systemd's `EnvironmentFile=` is the mechanism here |
</threat_model>
