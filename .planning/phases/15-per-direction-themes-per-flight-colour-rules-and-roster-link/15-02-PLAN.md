<objective>
Extend `server/device_config.py` with `theme_arriving` — the optional per-direction theme override (D-04) — including the one genuinely new mechanic this phase needs: an explicit clear path that `save_device_config()`'s current "`None` always means carry forward" contract cannot express.

Purpose: this is the phase's real design risk. `theme_arriving` is the second key (after `wake_interval_s`) whose valid value set includes `None`, but unlike `wake_interval_s` it **must** be clearable from the Settings form. Getting the two meanings of `None` confused here would produce a field that silently fails to clear — indistinguishable from a working feature until an operator tries to undo an override.

Output: one modified config module, one extended harness.

Independent of plan 15-01 by construction: `colour_rules.resolve_effective_theme_id()` reads `theme_arriving` with `.get()`, so neither plan blocks the other.
</objective>

  <action>
Three edits to `server/device_config.py`, all additive. Do not change any existing field's behaviour, signature default, or contract.

**1. The sentinel.** Add a module-level `CLEAR_THEME_ARRIVING = object()` near the other module-level constants. Comment it as the one thing in this module that widens what a `save_device_config()` argument can mean: `None` keeps meaning "caller didn't supply this parameter, carry the current on-disk value forward" — the meaning every other parameter has and keeps having — and this sentinel means "the caller explicitly wants this field cleared". Name `companion/pages/health_page.py`'s `_DB_UNAVAILABLE` as the existing in-codebase precedent for the idiom, and name the alternative that was considered and not taken (a second boolean `clear_theme_arriving=False` parameter, rejected because it would give one field an asymmetric extra parameter while every other field keeps identical arity — `15-RESEARCH.md` Assumption A1). State that `load_device_config()` never sees this sentinel: it exists only in the write path.

**2. The normaliser.** Add `normalise_theme_arriving(value)` immediately after `normalise_theme_id()`. It returns `value` when it is a string present in `THEMES`, else `None`. Never raises. Its docstring must state the divergence explicitly, in the same voice `normalise_wake_interval_s()`'s docstring already uses: unlike `normalise_theme_id()`, which degrades an unrecognised value to `DEFAULT_THEME_ID`, this degrades to `None` — and `None` here means "no override, i.e. same as `theme`" (D-04), not "degraded to the documented default". Note that this makes `theme_arriving` the second key in this module, after `wake_interval_s`, whose valid value set includes `None`.

**3. The load and save paths.**
- In `load_device_config()`'s returned dict literal, add `theme_arriving` computed through `normalise_theme_arriving()` on the parsed data's `theme_arriving` entry, read with `.get()` so a pre-existing file that has never carried the key resolves to `None` with no migration. It must sit in the returned dict unconditionally, beside `theme`, because the all-keys-always-present contract is what lets `colour_rules.resolve_effective_theme_id()` and `config_page.render()` index it directly.
- Add `theme_arriving=None` to `save_device_config()`'s signature, after `theme` and before `tracked_runway` so the two theme fields read together. Update the function's docstring to describe the field and to spell out its three-state argument contract: `None` carries forward, `CLEAR_THEME_ARRIVING` clears to `None`, and any other value must be a `THEMES` member.
- In the validation block, before anything is written, raise `ValueError` when `theme_arriving` is neither `None`, nor `CLEAR_THEME_ARRIVING`, nor a member of `THEMES`. Use an identity comparison against the sentinel, never an equality comparison. Match the message shape the sibling theme validation already uses, naming the offending value and the accepted set.
- In the write block, `theme_arriving`'s new value is: `None` when the argument is the sentinel; the argument itself when it is not `None`; otherwise the current on-disk value. Comment this three-branch expression as the one place in this module where a parameter has three meanings instead of two, and point at D-05 as the reason (an unchecked arrivals checkbox must genuinely clear the override, which is the opposite of the resolution `wake_interval_s` deliberately took).

Do not touch `theme`'s own handling, `normalise_theme_id()`, `theme_background_index()`, or any `theme_*` accessor — the base theme keeps its exact current meaning as the frame's theme for departures, the empty state, the hold screens and the Settings previews (D-04).
  </action>
