# Phase 02 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This is not a web/React UI. The "frontend" here is a Python/Pillow raster-rendering pipeline on the server that produces a single 960,000-byte, 4-bit-per-pixel indexed-color panel image (`docs/PROTOCOL.md` §1), which the device blits directly to a 13.3" E Ink Spectra 6 panel. There is no browser, no DOM, no component tree, and no user input during this phase (the physical button ships in Phase 4). The shadcn initialization gate therefore does not apply — confirmed by scanning the repo for `components.json`/`tailwind.config.*`/`package.json`: none exist, and the stack is Python (`stub-server/byos_server.py`), not React/Next/Vite. This contract instead specifies the fixed 6-color hardware palette, the type/spacing scale for a 1200×1600 @ ~150 PPI portrait panel viewed from a few feet on a wall or desk, and the exact copy for every state PLANE-01/02/03 can produce.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — not a component-based web project; server renders a raw raster buffer with Pillow |
| Preset | not applicable |
| Component library | none — custom Pillow drawing primitives (text blocks, filled rects, glyph masks) |
| Icon library | Lucide (MIT license), static SVG → rasterized at render time: `plane-takeoff` (departing) and `plane-landing` (arriving) only. No other icons this phase. |
| Font | Inter (SIL OFL 1.1), static TTF, Regular 400 + Bold 700. Vendor `Inter-Regular.ttf` and `Inter-Bold.ttf` into `server/assets/fonts/` with a VENDOR.md provenance note, following the vendoring discipline already established in `stub-server/VENDOR.md` |

**Rendering rule (hardware-specific, binding):** disable font anti-aliasing (or explicitly threshold glyph edges to pure black/white) before quantizing to the Spectra 6 palette. AA'd grayscale glyph edges dither into visible halftone noise on this panel; flat black-on-white text does not. Reserve Floyd-Steinberg dithering (Pillow's `Image.quantize(..., dither=Image.FLOYDSTEINBERG)`) for any future photographic content only — this phase's layout is flat text + solid fills and should be quantized with `dither=Image.NONE` against the exact 6 legal palette entries.

**Exact panel RGB reference values are unverified** — PROTOCOL.md §1 fixes only the nibble codes (`0x0` black, `0x1` white, `0x2` yellow, `0x3` red, `0x5` blue, `0x6` green), not their sRGB values. Confirm the true swatch RGB against the Waveshare `EPD_13in3e` reference driver or panel datasheet before implementation; do not guess hex values into the render code. Confidence: LOW until sourced.

## Spacing Scale

Panel is 1200×1600 px, ~150 PPI (13.3" diagonal, portrait), viewed from a few feet on a wall or desk — denser and physically larger than a typical web viewport, so the standard 8-point scale is scaled up ~2-3x to preserve legible physical spacing. Still strictly multiples of 4:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 8px | Icon-to-label gap inside the mode badge |
| sm | 16px | Badge internal padding |
| md | 32px | Gap between the route line and the airline line |
| lg | 64px | Panel content margin (all four edges) and section padding |
| xl | 96px | Gap between the hero flight number and the block below it |
| 2xl | 128px | Major vertical break between the mode badge zone and the hero zone |
| 3xl | 192px | Reserved for future use (e.g. a taller layout variant); not used in this phase's default composition |

Exceptions: the lg (64px) content margin is inviolable on all four edges regardless of content length — nothing may render under the physical bezel.

## Layout & Composition

*(Non-template addition: a raster full-bleed layout needs spatial zones the base template doesn't capture. Included because the planner/executor have no other spatial source of truth for this phase.)*

Canvas: 1200w × 1600h, portrait, full-bleed, hard-edged rectangles only (no rounded corners — curved edges dither poorly on Spectra 6). Content safe-box after the lg (64px) margin: 1072w × 1472h.

Top-to-bottom zones, in the safe-box:

1. **Mode badge** (top-anchored) — filled rectangle, ~120px tall, containing the takeoff/landing icon + label text (Label size, see Typography), background = Accent-Departing (blue) or Accent-Arriving (green) per D-03's inferred state, never both at once.
2. **2xl (128px) gap**
3. **Hero flight number** (e.g. `AF1380`) — Display size, bold, black, horizontally centered.
4. **xl (96px) gap**
5. **Route line** — a Label-size prefix ("TO" for departing / "FROM" for arriving) followed by Heading-size destination or origin city, black.
6. **md (32px) gap**
7. **Airline line** — Body size, regular weight, black (e.g. "Air France"). On enrichment failure, this line is replaced by the fallback copy in the Copywriting Contract below rather than left blank.
8. Remaining space is empty white — deliberate negative space, consistent with the "ambient piece" core value; this is not a dashboard and should not be filled with filler content.
9. **Bottom-anchored static tag** — Label size, black, e.g. `ORY · RWY 3`. Does not change per flight; reinforces place/context at a glance.

## Typography

Exactly 4 sizes / 2 weights, chosen for legibility on a dithered 6-color panel viewed from a few feet:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 36px | 700 (Bold) | 1.2 |
| Body | 56px | 400 (Regular) | 1.3 |
| Heading | 88px | 700 (Bold) | 1.2 |
| Display | 160px | 700 (Bold) | 1.1 |

Label text is set in uppercase with widened letter-spacing (Pillow: manual glyph-advance widening, no native tracking API) to stay legible at small size on dithered glass.

## Color

Fixed 6-color Spectra 6 hardware palette (`docs/PROTOCOL.md` §1) — the contract here is *which of the 6 legal colors is used for which role*, not a free hex choice.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | White (nibble `0x1`) | Background canvas |
| Secondary (30%) | Black (nibble `0x0`) | Hero flight number, route/airline text, dividers, default icon fill, bottom static tag |
| Accent (10%) — Departing | Blue (nibble `0x5`) | Mode badge fill + `plane-takeoff` icon, DEPARTING state only |
| Accent (10%) — Arriving | Green (nibble `0x6`) | Mode badge fill + `plane-landing` icon, ARRIVING state only (mutually exclusive with Departing — only one is ever on screen per D-03) |
| Destructive | not applicable | No destructive actions exist on a passive, buttonless display this phase |

Accent reserved for: the mode badge fill/icon only, nothing else. Body, hero, and static-tag text stay black regardless of departure/arrival state — color communicates *state*, not general decoration.

**Cross-phase reservation note:** Yellow (`0x2`) and Red (`0x3`) are intentionally unused in this phase's palette, held in reserve for Phase 3's disruption banner (RER-03) and Phase 4's low-battery indicator (DEVICE-04) so those later semantic colors don't collide with this phase's departure/arrival color-coding.

## Copywriting Contract

No clickable UI exists this phase (passive e-ink display, no buttons until Phase 4), so "Primary CTA" is reinterpreted as the single most important glanceable readout.

| Element | Copy |
|---------|------|
| Primary readout (mode badge label) | `DEPARTING` or `ARRIVING` — exact uppercase string, mutually exclusive, per D-03's inferred runway configuration |
| Empty state heading (no aircraft ever detected since server start / cache empty) | "Watching Runway 3" |
| Empty state body | "No aircraft detected yet — the display updates the moment one is." |
| Between-flights state | Not a distinct visual state — per D-04, the last detected flight stays on screen indefinitely; no separate "waiting" copy is ever shown once at least one flight has rendered |
| Error / partial-data state (D-02 enrichment lookup fails or returns no route for a real detected callsign) | Airline line falls back to: "Route unavailable" (Body size, regular, black) — the hero flight number and mode badge still render normally from ADS-B data alone; only the airline/route line degrades |
| Destructive confirmation | not applicable — no destructive actions exist on this passive display this phase |
