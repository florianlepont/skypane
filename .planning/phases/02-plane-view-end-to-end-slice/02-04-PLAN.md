## Phase Goal

**As a** person glancing at the frame on my wall, **I want to** see the plane that is using Orly runway 3 right now, **so that** the frame is a live, satisfying ambient window onto the airport next door rather than a static picture.

This plan advances that slice from "which plane, going which way" to "which plane, whose airline, to or from where" — completing the informational content of PLANE-01 and PLANE-02.

<objective>
Slice 4: resolve the airline name and the origin/destination city for the detected callsign, and render them as UI-SPEC's route line and airline line — with a fallback path that is built and tested from day one, because for this airport's traffic mix the fallback is the coin-flip case, not the edge case.

Purpose: PLANE-01 and PLANE-02 both name airline and destination/origin explicitly. Raw ADS-B carries neither; D-02 exists precisely to close that gap.
Output: `server/plane/enrich.py` with a persistent callsign-keyed cache and a graceful miss path, plus the two caption zones in `render.py`.
</objective>

<locked_decisions>

- **D-02** (locked, CONTEXT.md): raw ADS-B gives position, altitude, speed and callsign only — no airline name, no route. A supplementary free lookup keyed by callsign resolves airline plus origin and destination. The specific provider was left to research and is now fixed below.
- **D-P2-05** (research-resolved, provider selection under D-02): the provider is **adsbdb.com**, endpoint `https://api.adsbdb.com/v0/callsign/{callsign}`. Open source (`mrjackwills/adsbdb`), free, no API key, and — decisively — live-verified against all 38 distinct real callsigns from Phase 1's own Orly sample rather than against documentation. One call returns airline name, IATA/ICAO flight number, and both origin and destination with clean municipality names. hexdb.io was evaluated as a secondary fallback and **deliberately deferred**: it recovered 2 of 4 sampled adsbdb misses but missed the same Transavia France callsigns adsbdb missed, so it is complementary rather than a superset, and it would add latency and a second failure mode without changing user-visible behaviour in the case that actually matters.
- **02-UI-SPEC.md Copywriting Contract (locked, resolves 02-RESEARCH.md Open Question 3):** on an enrichment miss, **both** the route line (zone 7) and its preceding 32 px gap (zone 8) are omitted — not rendered empty, not rendered with a placeholder — and the airline line (zone 9) alone falls back to the exact string `Route unavailable`. There is no partial case: destination/origin city and airline name come from the same single lookup, so a miss always takes out both together. The silhouette, state label and flight number all still render normally from ADS-B data alone.
- **D-P2-02** (inherited from 02-01): `poll_loop.py` is a systemd oneshot with no memory between cycles, so the enrichment cache 02-RESEARCH.md describes as "in-process" is persisted in `server/state/poll_state.json` via the atomic tmp-write-then-`os.replace()` pattern.
</locked_decisions>

<expectation_note id="N-02-04-01">
**Enrichment misses are the common case here, not the exception.** Querying adsbdb for all 38 distinct real callsigns captured at this exact geofence returned a full route for only **20 of 38 (52.6 percent)**. Coverage is excellent for legacy and full-service carriers (Air France, Iberia, TAP, Air Algérie, CCM Airlines, Vueling all hit) and poor for low-cost carriers using per-tail rotating callsigns (Transavia France `TVF*` hit 2 of 20). This airport's traffic mix is dominated by exactly the carriers adsbdb covers least well.

Two consequences the executor must not lose:
1. The `Route unavailable` path is a first-class rendering state to be built and tested alongside the success path — not an afterthought, and not something to be validated only against a hand-picked Air France callsign.
2. A manual QA session that only ever shows an Air France or Iberia flight has not exercised this feature. 02-05's checkpoint carries an explicit item to observe the fallback caption on real glass.

02-RESEARCH.md assumption A3 notes the possibility that the `TVF` gap was a transient adsbdb data outage rather than a structural one. Either way the required engineering is identical; only the expected frequency changes.
</expectation_note>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adsbdb.com API → `enrich.py` | Untrusted third-party JSON from a free, unauthenticated, crowdsourced service crosses into the render pipeline. |
| `poll_state.json` cache → `enrich.py` | Cached lookup results read back from disk across process boundaries. |
| Detected callsign → outbound request URL | An aggregator-supplied string is interpolated into a URL this server fetches. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04-01 | Tampering | `enrich.lookup_route` parsing an adsbdb response | high | mitigate | Defensive `isinstance` walk at every nesting level (`response`, `flightroute`, `airline`, `origin`, `destination`); all five required fields must be non-empty strings or the whole result degrades to a miss (ASVS V5). Non-2xx, connection errors, JSON decode failures and structurally incomplete bodies all return `None` rather than raising. Asserted by the hostile-response cases in `test_enrich.py`. |
| T-02-04-02 | Tampering | Aggregator-supplied callsign interpolated into the adsbdb request URL | medium | mitigate | `normalise_callsign` strips and upper-cases; reject anything non-string or empty. Additionally constrain to an alphanumeric-only shape before interpolation so a hostile callsign field cannot inject path segments or query parameters into the outbound URL. Covered by a normalisation case in `test_enrich.py`. |
| T-02-04-03 | Denial of Service | adsbdb slow, down, or rate-limiting the server | medium | mitigate | Explicit `timeout` on every call; cache both hits and misses so a rotating low-cost callsign is queried at most once ever (02-RESEARCH.md's named anti-pattern, and assumption A2 flags the rate limit as undocumented); a lookup failure degrades to the `Route unavailable` state and never blocks or aborts the render cycle, so the previously served panel is always preserved. |
| T-02-04-04 | Denial of Service | Unbounded growth of the enrichment cache inside `poll_state.json` | medium | mitigate | Cache bounded to a few hundred entries with insertion-order eviction, so the state file cannot grow without limit on a long-running server and the atomic rewrite stays cheap. |
| T-02-04-05 | Information Disclosure | Enrichment logging | low | mitigate | Log only the callsign and whether the lookup was a cache hit, a fresh hit, or a miss — never the raw response body, never a bearer token or setup secret (ASVS V7, preserving `byos_server.py`'s existing discipline). Callsigns are public broadcast data, so logging them discloses nothing not already transmitted in the clear by the aircraft. |
