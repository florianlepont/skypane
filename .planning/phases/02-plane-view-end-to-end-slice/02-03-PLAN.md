<locked_decisions>

- **02-UI-SPEC.md Design System (locked design contract):** the silhouette asset is freesvg.org / OpenClipart **SVG ID 178507**, "Passenger aircraft silhouette clip art", Public Domain / CC0. It was chosen over OpenClipart SVG IDs 18321 and 37085 as the only CC0 candidate reading as a modern commercial jet in profile without per-airline livery detail. Do not substitute a different asset; if 178507 is unreachable at execution time, stop and report rather than silently picking another, because the choice was made against explicitly named alternatives.
- **02-UI-SPEC.md hardware constraint (locked):** the silhouette renders as a flat shape in exactly one legal palette colour — White in both active states. It is not a livery illustration and cannot be; the panel is a 6-colour e-ink display with dithering disabled. This is a deliberate, hardware-forced simplification of the flightportrait reference, not an oversight.
- **02-UI-SPEC.md Revision 2 finding (locked, informational):** flightportrait's poster renderer is explicitly closed source — their public `flightportrait/frame` repo contains only device firmware and the minimal reference server this project already vendored. This composition is an independent design reverse-engineered from public screenshots, not a copy. Record this in `server/assets/icons/VENDOR.md` so a future contributor does not go hunting for upstream rendering code that does not exist.
- **D-04** (locked, CONTEXT.md — inherited, constrains this plan's Empty state): between flights the last detected flight persists with no expiry and no waiting screen. The Empty state this plan must leave silhouette-free is therefore only ever seen before the *first* detection since the state file was created — never as a between-flights screen. Do not add a "waiting" silhouette, a placeholder shape, or a faded variant for the gap case; there is no gap case to render.
- **D-P2-03** (inherited from 02-01): palette RGB triples are render-internal only and never cross the wire, so the silhouette's White fill is specified by palette *index*, not by a colour value. Preview PNG colours remain labelled approximate.
- **02-RESEARCH.md Pattern 2 (verified, binding):** `Image.resize()` reintroduces anti-aliased grey edges — measured at 159 distinct grey levels after a LANCZOS resize during research. The mask must be hard-thresholded back to strictly binary with `Image.point` after every resize and before every paste, or the paste alpha-blends grey into off-palette intermediate colours.
</locked_decisions>

  <action>
Add the silhouette centrepiece to the active-state render path.

**Geometry.** Place the silhouette in UI-SPEC zone 3: horizontally centred in the 1072 px safe box, target width about 900 px with height following from the source aspect ratio (UI-SPEC anticipates roughly 220-260 px tall), positioned after the state-label band and its 128 px `SPACE_2XL` gap, with at least `SPACE_3XL` (192 px) of clear colour field between the silhouette's own bounding box and its neighbours above and below, and `SPACE_XL` (96 px) between the silhouette zone and the flight-number caption. Express these as named constants (`SILHOUETTE_TARGET_W`, `SILHOUETTE_ZONE_TOP`, and so on) rather than as inline arithmetic, so the geometry assertions in `test_render.py` can reference the same numbers the renderer uses.

**Compositing — the ordering is the whole task.** Follow 02-RESEARCH.md Pattern 2 exactly and in this order:
1. Open the vendored PNG and convert it to mode `L` so it is a pure luminance mask.
2. Resize to the target box. Any resampling filter reintroduces anti-aliased grey edge pixels; that is expected and is why step 3 exists.
3. Hard-threshold with `Image.point` back to strictly binary — every pixel becomes either 0 or 255 at a midpoint cut. Skipping this step is the single failure mode that breaks the exactly-two-palette-indices assertion, because `paste` treats intermediate mask values as alpha and blends off-palette colours into the canvas.
4. Mirror by state with `Image.transpose(Image.FLIP_LEFT_RIGHT)` only when the vendored source orientation differs from the required one: nose-right for `departing` (reads as climbing away), nose-left for `arriving` (reads as descending in). Read the recorded source orientation from `server/assets/icons/VENDOR.md`; do not guess, and do not hardcode a flip that silently becomes wrong if the asset is ever re-rasterized mirrored.
5. Build a solid fill image in `"P"` mode at canvas size filled with `STATE_INK[state]` (White in both active states), apply the same palette, and `paste` it onto the canvas through the thresholded mask.

Extract this as a reusable helper — the Lucide state glyphs in 02-02 need identical treatment, so factor a single `paste_mask(canvas, mask_path, box, fill_index, mirror=False)` used by both call sites rather than duplicating the sequence. If 02-02 already introduced `load_binary_mask`, extend it instead of adding a parallel path.

**Empty state.** Draw no silhouette and load no mask. UI-SPEC is explicit: there is no flight yet, so there is nothing to depict.

**Guard rails.** Assert at render time that the composited silhouette's bounding box lies inside the safe box, and that the canvas's palette-index count is still 2 for the active states. Failing loudly inside `render_panel` is better than shipping a subtly dithered panel to the glass, where the failure is only visible by eye.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

The SVG is never parsed at runtime — only the pre-rasterized PNG is loaded, which removes the entire XML-entity-expansion and external-reference class of risk that a runtime SVG parser would introduce (ASVS V5, and 02-RESEARCH.md's Don't Hand-Roll ruling). | T-02-03-02 | Denial of Service | Oversized or malformed image asset consumed by Pillow (decompression-bomb class) | low | accept | The asset is a fixed, repo-committed file reviewed at vendor time, not user-supplied or fetched at runtime, and its dimensions are asserted by this plan's acceptance criteria. | T-02-03-03 | Tampering | Un-thresholded resized mask blending off-palette colours into `panel.bin` | high | mitigate | Pattern 2's hard `Image.point` threshold after every resize and before every paste, factored into one shared helper with one call site so a future caller cannot skip it. Enforced at runtime by the render-time palette-index assertion and in CI by `test_render.py`'s exactly-two-palette-indices check for both active states. |
| T-02-03-04 | Tampering | Silhouette rendered outside the safe box, under the physical bezel | medium | mitigate | Named geometry constants plus a render-time bounding-box assertion against the 1072x1472 safe box, asserted independently in `test_render.py`.
