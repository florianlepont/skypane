# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This contract covers the **companion web page's own visual design** (D-21: a plain utility tool) — login, Config, Health, Airlines, History, and Preview/Gallery pages. It is entirely separate from the **physical frame's** own design system (Zilla Slab typography, dithered mood backgrounds, PALETTE_RGB) governed by `03-UI-SPEC.md`/`07-01-PLAN.md`. CFG-01's theme picker *exposes choices from* the frame's palette but the picker widget itself, and every other page in this phase, follows the contract below — a deliberately different, lower-investment visual register (D-21).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no component registry, no shadcn. This is not a React/Next.js/Vite project; `06-RESEARCH.md`'s standard-stack recommendation is Python stdlib `http.server` + a hand-rolled router rendering server-side HTML strings (mirroring `stub-server/byos_server.py`'s own shape). No `package.json`, no build step, no client-side framework exist anywhere in this repo today — confirmed via repo scan (no `components.json`/`tailwind.config.*`/`postcss.config.*`/`*.css` files). |
| Preset | not applicable |
| Component library | none — hand-rolled semantic HTML (`<table>`, `<form>`, `<nav>`, `<fieldset>`) styled by one shared, hand-written CSS file (`companion/static/style.css`), served as a static file by the companion service itself. No Jinja/templating library either (RESEARCH.md's primary recommendation is stdlib-only) — page-builder functions in `companion/pages/*.py` return HTML strings directly, with `html.escape()` applied at every dynamic-value interpolation site (RESEARCH.md Pitfall 2). |
| Icon library | none — adds a dependency (icon font/SVG sprite library) this project has never needed and D-21 explicitly doesn't call for. Status/health indicators use a small CSS-only "status dot" pattern (a `<span class="dot dot--ok/warn/error">` colored circle via `border-radius:50%`) plus a text label — never an emoji (inconsistent cross-platform rendering) and never an icon-font glyph. |
| Font | System font stack only — `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif` for all UI text; `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` for tabular/technical data (timestamps, hex codes, ICAO prefixes, callsigns). Zero web-font loading — this is a deliberate contrast with the physical frame's vendored Zilla Slab/PT Serif fonts (`server/assets/fonts/`), which exist for the device's own poster aesthetic and must never be pulled into this page (D-21: different visual register, and pulling a vendored font into a second, unrelated context would blur that boundary for no benefit — the system stack renders instantly, needs no `@font-face`, and matches "plain utility tool"). |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-gap/status-dot-to-label gaps, badge inline padding |
| sm | 8px | Form-field label-to-input gap, table cell vertical padding |
| md | 16px | Default element spacing, table cell horizontal padding, card padding |
| lg | 24px | Section padding, gap between a page's stacked sections |
| xl | 32px | Gap between the nav bar and page content |
| 2xl | 48px | Login page's centered-card top offset |
| 3xl | 64px | Not used at this scale — no page-level hero spacing needed for a utility tool |

Exceptions:
- **44px minimum tap target** on every interactive element (nav tabs, buttons, form inputs, table row actions if any) — required by D-22 (basic mobile responsiveness: "tappable controls"). This is a touch-target floor, not a spacing-scale token; it constrains `min-height`/`min-width` on buttons and nav links, not the gap between them.
- **1px hairline borders** (table row dividers, input borders, card borders) — standard, not a spacing-scale violation (borders aren't spacing).

## Typography

Exactly 4 sizes, 2 weights — per contract discipline.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (regular) | 1.4 |
| Body | 16px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 24px | 600 (semibold) | 1.2 |

Usage:
- **Display (24/600):** The "SkyPane" site title in the top nav bar only (D-24: simple title, no logo). Appears once per page, never repeated as a content heading.
- **Heading (20/600):** Page titles ("Config", "Health", "Airlines", "History", "Preview") and section sub-headers within a page (e.g. "Theme", "Runway", "Battery Trend").
- **Body (16/400):** All prose, table cell content, form labels' associated help text, button labels.
- **Label (14/400):** Table column headers, form field labels, timestamps, secondary/meta text (e.g. "Saved 3 minutes ago"), status-badge text.
- Monospace variant (same 14px/16px sizes, `ui-monospace` stack, weight 400 only) applies to: ICAO callsigns, aircraft hex codes, unresolved prefixes (CFG-04), raw timestamps — anywhere tabular alignment or unambiguous character reading matters.

## Color

Two full palettes required — CFG-09 mandates a page-level dark/light toggle, independent of the physical frame's own colors (D-09 note: never assume any frame panel color below is real-glass-validated; that constraint governs the frame's palette, not this page's, which is a separate design system entirely).

### Light mode (default, follows `prefers-color-scheme` unless overridden by the CFG-09 toggle)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background |
| Secondary (30%) | `#F1F3F6` | Nav bar background, table row alternation, card/panel backgrounds, form field backgrounds |
| Accent (10%) | `#2563EB` | Reserved for: primary action buttons (Save Settings, Trigger Poll Now, Sign In), the active nav-tab underline/indicator, text links, focused-input border outline |
| Destructive | `#DC2626` | Reserved for: error-state banners/text (login failure, save failure), the "error" status dot/badge (stale poll, uncorroborated ADS-B, battery anomaly — D-14), form validation error text |

### Dark mode

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#12151B` | Page background |
| Secondary (30%) | `#1C2028` | Nav bar background, table row alternation, card/panel backgrounds, form field backgrounds |
| Accent (10%) | `#5B8DEF` | Same reserved-for list as light mode's accent (lightened for AA contrast against `#12151B`) |
| Destructive | `#F87171` | Same reserved-for list as light mode's destructive (lightened for AA contrast) |

### Status colors (both modes) — a narrow, additional semantic set for CFG-03/CFG-14's anomaly flagging

Not part of the 60/30/10 layout split above — these are small-area functional indicators (status dots + badge backgrounds) confined to the Health, Airlines, and History pages, never used for layout/decoration.

| Status | Light value | Dark value | Reserved for |
|--------|-------------|-----------|---------------|
| OK / healthy | `#16A34A` | `#4ADE80` | "Corroborated" ADS-B status, "on schedule" last-poll indicator, resolved-prefix summary when zero unresolved entries exist |
| Warning | `#D97706` | `#FBBF24` | Approaching-stale poll time (not yet flagged as an outage), a single uncorroborated detection, a minor battery dip that isn't yet a hard anomaly |
| Error | same as Destructive above (`#DC2626` / `#F87171`) | — | Stale/missed poll past the anomaly threshold, `corroborated=False` streak, abnormal battery drop (D-14) — reuses Destructive rather than introducing a fifth color |

Accent reserved for (restated, explicit list — never "all interactive elements"): **primary buttons, active nav-tab indicator, links, focused-input outline.** Everything else interactive (secondary buttons, disabled states, table sort/filter controls if any) uses neutral gray, not accent blue.

## Component Patterns

A small, fixed set — enough to cover every page, nothing more (D-21: plain utility, not a design system to maintain):

| Component | Pattern |
|-----------|---------|
| Status dot + label | `<span class="dot dot--ok">` (12px circle, one of the 3 Status colors above) followed by a Label-size text description. Used on Health (poll/battery/corroboration), Airlines (coverage summary), History (per-row state). |
| Anomaly banner | Full-width Secondary-background block, Destructive or Warning left-border accent (4px), Body-size text, appears at the top of Health/Airlines when D-14's anomaly condition is true; absent entirely when nothing is flagged (no "all clear" banner needed — the absence of a banner *is* the all-clear signal, keeping the page uncluttered per D-21). |
| Form (Config page) | Plain `<form method="post">`, `<fieldset>` per setting group (Theme / Runway), native `<input type="radio">`/`<select>`, one "Save Settings" button at the bottom. No client-side JS validation beyond native HTML5 `required` attributes — server validates against the fixed `THEMES`/`RUNWAY_CONFIGS` key sets regardless (RESEARCH.md's V5 threat control). |
| Confirmation message | Appears inline above the form after a successful POST/redirect (not a JS toast/snackbar — a plain server-rendered banner, Accent-colored left border, shown once per page load then gone on next navigation). Carries D-07's exact copy. |
| Data table | Plain `<table>` with a Secondary-background header row (Label-size, weight 600 — the one place Heading-weight text appears at Label size, an intentional exception for table headers only), alternating Secondary/Dominant row backgrounds, 16px horizontal / 8px vertical cell padding. Used on Airlines (unresolved prefixes), History (flight log). Monospace font for any hex/callsign/prefix cell. |
| Trend/chart (Health page, CFG-03/D-12) | A plain, dependency-free rendering — either a simple `<table>` of recent readings (safe minimum) or a minimal inline-SVG sparkline generated server-side (no charting library — consistent with "zero new dependencies"). Exact choice left to planning; either satisfies D-12's "history/trend, not just current snapshot" requirement. |
| Button (disabled/cooldown state, CFG-07/D-17) | Native `<button disabled>` with reduced opacity (0.5) and a `cursor: not-allowed`, showing the cooldown countdown copy above. No JS timer required for MVP — a simple "try again shortly" static message on cooldown is acceptable; a live countdown is a nice-to-have, not a contract requirement. |
| Image preview (CFG-10) | A single `<img>` tag pointing at `/preview.png`, Body-size caption below stating when it was captured (reuses the monospace timestamp style). |
| Gallery grid (CFG-11) | CSS grid, `repeat(auto-fill, minmax(160px, 1fr))`, each cell a thumbnail `<img>` + monospace timestamp caption — collapses to fewer columns automatically on mobile widths (D-22), no JS/media-query breakpoints needed beyond the grid's own auto-fill behavior. |
