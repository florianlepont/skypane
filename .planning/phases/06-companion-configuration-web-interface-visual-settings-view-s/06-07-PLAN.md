    - A post whose runway is absent from the registry likewise writes nothing and returns the save-failure key.
    - A post with a theme but no runway field carries the existing runway forward unchanged.
    - A post whose theme value is a path-shaped or SQL-shaped string is rejected by the same membership test as any other non-member.
    - A save that raises an operating-system error returns the save-failure key rather than propagating.

  <action>
Implement `handle_post(form, ctx)`.

Read the two field values from the form dict. For each, apply an explicit membership test against `device_config.THEME_IDS` and `device_config.RUNWAY_IDS` **before** the value is used anywhere. Do not call `normalise_*` here: normalisation is the read-path's forgiving behaviour, whereas a *write* of an unrecognised value is a real client error and must be reported to the user rather than silently coerced into the default. That asymmetry is deliberate — say so in the docstring.

Reject the whole submission if either field is present and non-member: partial application would leave the user's two settings in a state neither the form nor the page reflects. An absent field means "unchanged" and carries the current value forward.

On a valid submission call `device_config.save_device_config()` inside a try that catches `ValueError` and `OSError` and returns the save-failure flash key. The corresponding user-visible copy is 06-UI-SPEC.md's save-failure sentence, which the router maps from the key — this function never returns a message string.

On success return the saved flash key. The router redirects back to the Config page, whose banner then renders D-07's confirmation copy verbatim: the sentence stating the change was saved and will apply on the frame's next scheduled refresh. That sentence is the whole mitigation for D-06's deferred-apply model — a user who checks the physical frame immediately and sees no change must be told why — so it is mandatory and must not be reworded.

Define the four flash-key constants at module level and have the router's allowlist reference them, so the key strings exist in exactly one place.

Add a docstring note recording D-06 and D-28: neither a theme change nor a runway change reaches the device early. The server applies both on its own next cycle, and the frame picks up the resulting image on its own next scheduled poll. No push mechanism is introduced, preserving the poll-only security model.
  </action>
