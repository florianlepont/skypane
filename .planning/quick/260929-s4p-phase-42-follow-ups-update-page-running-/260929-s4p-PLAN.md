- `update_view()` already carries `running_version` (the device's
  X-Fw-Version) and per-release `installed_at` (a list of ISO timestamps,
  appended only by an "installed" result in `reconcile()`). It is ~70
  lines; `scripts/check_function_size.py` caps `server/` functions at 80,
  so move the per-release loop into a helper.
- `_release_row()` returns a 5-tuple that both the desktop table and the
  mobile `.data-card` list render from. Notes are column 2, currently
  plain text escaped by `data_table()` (not in `raw_columns`).
- The global `summary` rule in `companion/static/style.css` (~line 2452)
  already gives 44 px min-height, accent colour and the rotating chevron.
  `.readings-disclosure` is the existing plain control-style disclosure.
- The shared render baseline seeds an empty firmware registry, and its
  `GET /static/style.css` entry records only status/location. The
  expected baseline diff for this task is zero.
- Every `poll fail step=ota` exit in `state_machine.c` comes after
  `draw_updating_screen()`, which always writes `FP_UPDATING_SCREEN_HASH`.
  So `already_shown` is false on those exits and `fail_and_sleep("ota")`
  reaches `maybe_draw_fault_screen("ota", next_backoff_n)`. Today the
  allow-list rejects `ota`.
- Wake budget is flag-only. The timer never interrupts a blit, and
  `maybe_draw_fault_screen()` never checkpoints. A fault-screen blit
  after an OTA attempt can therefore overrun the 360 s budget unless it
  is gated. `FP_WAKE_OTA_WORST_CASE_S(90)` is already 325 s.
