<objective>
Plan 05-01's Tasks 2 and 3 — the multi-day unattended battery discharge run that produces the DEVICE-05 mAh-per-cycle figure — were written in Phase 1, when the only server that existed was a stub run by hand on the developer's Mac. That premise made the Mac the device's only peer for up to 21 days, and the protocol was forced to absorb the consequences: a keep-awake wrapper around the capture pipeline, an Energy Saver override, a router-side address reservation, a LAN address re-checked daily, and a laptop that could not sleep, move, or be closed for three weeks.

That premise is now false. Phase 2 shipped `deploy/skypane-byos.service` on the OVH VPS, running **the same** `stub-server/byos_server.py` file — not a reimplementation — under systemd, always on, restarted automatically, with stdout captured by journald. It already logs the device's `X-Battery-Mv` on every poll through the same `log_telemetry()` print the local stub used. The observation channel the run needs already exists and already runs without the Mac.

The only thing standing between journald and the analysis that already works is a timestamp format. `check-battery` parses a leading `[ISO-8601]` bracket that `stamp` prepends; `journalctl -o short-iso` puts the timestamp first with no brackets, followed by a hostname and a syslog identifier. Bridging those two shapes is a few lines of string work — and once bridged, every gate, threshold, projection band and reconciliation in `check-battery` is reused **completely unchanged**.

This is a correction to the test methodology, not a reduction of it. Nothing about measurement validity moves. The thresholds stay at the values pre-registered before the pack was ever connected, the 21-day ceiling stays, the division stays, and the physical handling of a lithium cell being deliberately run to its floor stays exactly as written. What goes away is a constraint that was never about the measurement at all.

One correctness problem falls out of the move and must be fixed here rather than discovered on day nine: the production server's `SKYPANE_SLEEP_S` is 30, and the pre-registered protocol assumes 300. `check-battery` computes its nominal poll count as span divided by `--interval-s`, so analysing a 30-second run at 300 would report ten times too few nominal polls, inflate coverage past 1.0, understate every gap in intervals, and pass all four gates on a run it should have rejected. The interval therefore stops being a remembered constant and becomes a recorded input, set and read back from the VPS at the start of the run.

Purpose: remove the Mac-availability constraint from DEVICE-05 without moving a single threshold.
Output: a `from-journal` bridge proven against the existing battery fixtures, an amended and explicitly-annotated pre-registered protocol, and 05-01's two hardware tasks re-scoped to the server that is already running.
</objective>
