# Quick task 261115-l7p: the row menu of the last Fleet row is reachable

## Problem (owner screenshot, 2026-11-15, French, administrator)

On the console Fleet page, the "Autres cadres" list holds a retired frame ("Le Petit Cadre"). Its
row menu (the vertical-dots button, `ui_entity_list.row_menu_html`, used by
`companion/pages/fleet_page.py` around the `_ROW_MENU_ARIA` entry) opens downward and the popover is
clipped at the bottom by its container, so its options (for example Re-activate) cannot be reached.
The frame was the last row of the list.

## Task 1: failing browser test first

Add a browser test (see the helpers in `companion/test_browser_*.py` and `companion/conftest.py`) that
builds a Fleet page where the LAST row of "Other frames" has a menu with several options (a retired frame
with Re-activate), opens that row's menu, and asserts in the browser that every option is fully inside the
visible viewport area (not clipped by an ancestor with overflow) and is clickable (`elementFromPoint` hits
the option). Run it at desktop width and at phone width, in English and French. It must fail before the fix.
Chromium is available at `/opt/pw-browsers` (run with `-n0 --no-cov`).

## Task 2: the fix

Find why the popover is clipped (an ancestor with `overflow: hidden` or the card radius clipping, or a
fixed-height container). Prefer the smallest change that keeps the design system
(`.claude/skills/sketch-findings-skypane/SKILL.md`): let the menu escape the clip, or open upward when there
is no room below. Check the other users of the same row menu (the Fleet "Frames" list, Users, Locations,
any `ui_entity_list.row_menu_html` caller) so the fix is shared and nothing else regresses. Both languages,
phone width, light and dark themes. Do not change the live pages' markup beyond what the fix needs; update
`companion/testdata` goldens only if the served HTML changes on purpose, and say so.
