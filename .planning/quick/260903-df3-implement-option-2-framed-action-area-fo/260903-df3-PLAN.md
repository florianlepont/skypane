<objective>
Restyle the Airlines gallery's illustration-replace control from a bare inline divider row into **"Option 2 — Framed action area"**, the direction the developer picked from a live-rendered three-option comparison built out of this app's own CSS tokens.

The complaint being fixed: the native `<input type="file">` currently renders as the raw, locale-dependent OS widget with zero visual integration — a muted 13px label, an unstyled system control, and an accent button crammed onto one line under a hairline divider.

The fix, inside the *existing, unmodified* `<form class="lightbox__replace">`: a new bordered zone (dashed `--color-border` edge, `--radius-control` corners, a light tint of `--color-secondary`) whose stacked, centred contents read top-to-bottom as **upload glyph → bold label → requirements hint → file picker → Upload button**.

Purpose: make the one place in this app where a user hands over a file look like it belongs to this app, and tell them the PNG requirements *before* the upload is rejected rather than only after.
Output: a restyled zone in `companion/static/style.css`, one new sprite glyph in `companion/layout.py`, new nested markup plus two new copy/class constants in `companion/pages/airlines_page.py`, and updated (not merely extended) test coverage across three harnesses.

**Hard boundaries — this task changes none of the following:**
- **Zero JavaScript.** `companion/static/panel-lookup.js` gets no edit. The module docstrings in `airlines_page.py` repeatedly document this form as plain/native/JS-free; that stays literally true.
- **No backend/route change.** `companion/app.py`'s `_handle_illustration_replace()` is untouched.
- **The `<form>` element's own class and attributes are byte-identical.** `LIGHTBOX_REPLACE_FORM_CLASS`, `method="post"`, `enctype="multipart/form-data"`, `action=""` — all unchanged, because `panel-lookup.js` finds this form by that class and writes that attribute.
- **The `<input type="file">` stays a real, visible, native file input.** Not hidden, not wrapped in a JS-driven fake, not replaced. This is a CSS-only restyle of an element whose markup gains nothing but its existing attributes.
- **D-04 still applies:** no revert / reset / restore-original control. Out of scope, do not add one.
- **History is untouched** (`companion/pages/history_page.py` never renders this form at all).
