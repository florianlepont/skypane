## PR text

## Summary

Adds an off-by-default server-side experiment that separates how often the frame checks in from how often the flight image is replaced. While active, GET /device/v1/display returns `sleep_s = check_interval_s` (60 s) and the poll cycle changes the normal flight image at most once per the device's saved `wake_interval_s` (N); between changes the panel hash is the same, so the firmware's hash-skip leaves the panel alone. No firmware change. Self-expiring (hard maximum 72 h), minimum 60 s, ignored when the last battery reading is at or below 3700 mV or unknown. Display-off, battery-critical and quiet-hours overrides still win, and hold screens (battery empty, display off, quiet-hours entry and exit, setup screen) are never delayed.

## How to use

```
python3 -m server.check_interval set --check-interval-s 60 --hours 24
python3 -m server.check_interval set --state-dir server/state/devices/d_xxxxxxxx   # a fleet frame
python3 -m server.check_interval status
python3 -m server.check_interval clear
```

State is a sidecar `check_interval_experiment.json` in the device state directory (not a device_config.json key, which the companion rewrites from its thirteen-key registry). Documented in `server/README.md`.

## Behaviour when off

With no experiment file, an expired or invalid one, no saved `wake_interval_s`, a battery reading at or below 3700 mV, or an unknown reading: served keys and `sleep_s` are unchanged, `poll_state.json` has exactly the frozen key set (a stale `last_flight_redraw_at` is removed on the first inactive cycle), panel hash sequences equal a run with no file. `measured_fields_freeze.json` is untouched and its test is green.

## Ambiguities resolved

- A1. `wake_interval_s` unset: the experiment is inactive (the `--sleep`/SKYPANE_SLEEP_S fallback is not a redraw period the owner chose).
- A2. `check_interval_s >= wake_interval_s`: inactive; the CLI refuses to set it.
- A3. Overrides (display off, battery critical, quiet hours) only see the experiment as a replaced base value and keep their order and effect. `server.wake.effective_wake_interval_s()` (companion next-wake, device-tile staleness, the wake_epochs history row) still reports `wake_interval_s`, so the history row records N, not the real 60 s cadence.
- A4. Last battery reading: byos uses this request's `X-Battery-Mv`, else `battery_state.json`; the poll cycle uses `battery_state.json`. Unknown means ignored; exactly 3700 mV means ignored.
- A5. Spaced: bootstrap promotion, queue advance to a new aircraft, and the same-aircraft refreshed re-render. Immediate: every hold screen, hold-exit repaint, source-fault and battery-low badge repaints, the no-location screen, the empty screen. Only a flight-path panel change stamps the redraw clock.
- A6. While spacing blocks, new aircraft still enqueue and expire after 150 s; at the next due cycle the panel shows a fresh queued or newly detected aircraft, and if none is fresh the old flight stays until the next detection.
- A7. A clock stepped backwards counts as due, like `advance_is_due()`.
