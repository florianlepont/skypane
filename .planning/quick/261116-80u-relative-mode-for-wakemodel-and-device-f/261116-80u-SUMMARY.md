## PR text

### Summary

- `wakemodel.py fit` and `rates` accept `--seq-min/--seq-max/--since/--until` to keep one device's rows; dropped rows (outside the wake_seq range, null wake_seq, outside the time range) are counted in the output.
- New `wakemodel.py rates EXPORT --window NAME=START,END ...`: per window it prints usable hours, the voltage fall in mV/h with an approximate 95% range, check and redraw wakes per hour, unknown wakes and median voltage. With three or more well-posed windows it solves fall = s + C x checks/h + R x redraws/h (mV/h and mV per wake) and prints R/C and R over a reference window's fall; otherwise it refuses with exit 2, the reason and the data that would fix it.
- A restart (non-timer boot reason or firmware change) excludes 3 h from the window; the voltage band between windows (default 60 mV) is an option, shown in every output.
- Docs (`hardware/WAKE-ENERGY.md`), three synthetic fixtures, behaviour tests. No firmware, server or `logtools.py` change; `fit` output is unchanged.

### How to use

    python3 hardware/wakemodel.py fit EXPORT --capacity-mah N --seq-min 20000 --seq-max 30000

    python3 hardware/wakemodel.py rates EXPORT.jsonl --seq-min 20000 --seq-max 30000 \
        --window w1=2026-11-15T07:55Z,2026-11-17T07:55Z \
        --window w2=2026-11-17T08:00Z,2026-11-19T08:00Z

The owner confirmed two windows (check 60 s + redraw 5 min from 2026-11-15T07:55Z for 48 h; check 60 s + redraw 60 min from about 2026-11-17T08:00Z for 48 h). With two windows the tool prints both falls and their ratio with a 95% range, says C, R and the standing draw cannot be separated, and exits 2 by design. `--band-mv`, `--reset-hours`, `--min-usable-hours`, `--reference` are available.

### What it does not claim

- No mAh and no current measurement: relative voltage-slope comparisons on a rated, uncalibrated top-of-charge region of the curve. Every output says so.
- Ranges are approximate (slope errors propagated through unconstrained least squares; model error ignored).
- Windows that all use the same check interval (60 s here) make every wake a check or a redraw, so wakes per hour are constant: they cannot separate the standing draw, the check cost and the redraw cost, and the tool refuses that 3-window solve. Such a schedule supports each window's slope and the ratio between two windows. Separating them needs a window at another check interval (for example the 60 s experiment cleared, so the frame wakes every 5 minutes and redraws at every wake). That is a requirement, not an agreed schedule.
- The full-discharge percentage-curve study is deferred (backlog).
