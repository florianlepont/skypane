## The height is derived, never chosen (DP-2)

`gcd(900, 263) = 1` (263 is prime), so **no** smaller integer pixel pair can
reproduce the 900:263 ratio exactly — the brief's "preserve the EXACT ratio"
is arithmetically unreachable below 900x263. The rule that replaces it, and
that satisfies the brief's actual intent ("do not introduce a second,
slightly-off ratio by independently rounding both numbers"): **fix W, then
derive H from the one formula** `H = round(W * 263 / 900)`.

For W=450: `450 * 263 / 900 = 131.5`, which rounds to **132** under both
half-up and banker's rounding (132 is even), so the value is unambiguous. The
resulting 450/132 = 3.4091 sits 0.38% off the 3.4221 median. That deviation is
invisible: it only shifts how much transparent letterbox each file gets, and
because the normalization scales every crop to FIT INSIDE the box, it can never
clip an aircraft.

(Considered and rejected: 452x132, which tracks 3.4221 to within 0.06%. It buys
a sub-pixel gain at the cost of no longer being the audit's own stated "450px"
and no longer being an exact halving of the width. Not worth it.)

## RESOLVED DECISION — DP-1: the target is 450x132 (2026-09-04)

This plan originally opened with a blocking `checkpoint:decision`, because
planning surfaced one consequence the audit did not have in front of it. **The
developer resolved it before dispatch and chose option-a, 450x132 — the audit's
own recommended number.** The checkpoint is gone; every value below is final.
The reasoning is kept here because the executor will be rewriting the very
comments that argue the old numbers, and must not re-litigate this.

**What was decided against.** `companion/static/style.css` sets
`.lightbox { max-width: 480px }` for the generic dialog and
`.lightbox--wide { max-width: 900px }` for the Airlines click-to-enlarge dialog,
with a harness check pinning that 900 to `ILLUSTRATION_TARGET_WIDTH` so the
enlarged illustration is never upscaled past its own native width. Moving the
target to 450 therefore moves `.lightbox--wide` to `max-width: 450px` — which is
**narrower than the 480px generic dialog it exists to widen**.

Measured against the real rules (`.lightbox--wide .lightbox__image` uses
`width: auto`, so the image renders at its intrinsic width and never upscales to
fill a wider dialog):

- **On mobile (375px): zero change.** `.lightbox` is already capped by
  `width: calc(100% - var(--space-lg) * 2)`, roughly 327px, so the 900px
  max-width never binds today and the 450px one will not either. The enlarged
  image renders at the same size before and after.
- **On desktop: the enlarged view shrinks from about 852px to about 402px.**
  Against the 224px desktop card that is still a ~1.8x enlargement, down from
  today's ~3.8x. **This is the accepted cost of the decision, not a defect** —
  Task 2 Part B measures the real number and reports it, and must not "fix" it.

There was no third path: leaving the dialog at 900px would strand a 450px image
in a mostly-empty box (because `width: auto` refuses to upscale), forcing the
image to fill it would render a 2x-upscaled, visibly soft picture on the one
surface whose entire purpose is looking closely, and serving a second larger
size for the lightbox is exactly the multi-size mechanism this task is not
building (DP-3). The rejected alternative was 600x175, which would have kept
`.lightbox--wide` above the 480px base but delivered only half the byte saving
(1.95MB vs 1.20MB) and would have closed UIR-08 as "fixed differently" rather
than as written.

**Final values, all derived from W=450 — do not recompute, do not substitute:**

| Value | Setting |
|---|---|
| `ILLUSTRATION_TARGET_WIDTH` | `450` |
| `ILLUSTRATION_TARGET_HEIGHT` | `132` (= `round(450 * 263 / 900)` = `round(131.5)`) |
| `ILLUSTRATION_TARGET_SIZE` | `(450, 132)` |
| `.airline-card__image` | `aspect-ratio: 450 / 132` |
| `.lightbox--wide` | `max-width: 450px` |
| `<img>` width/height attributes | `450` / `132`, via the existing import — no edit |
| New byte-ceiling constant | `65536` (64KB); measured post-change max is 53.1KB |
| Expected gallery total | 1.20MB, down from 3.92MB (31% of baseline) |
