<objective>
Scope the Location map's status-bar lead back to iOS. In companion/static/place-map.js, leadUnderStatusBar() returns early when `typeof window.navigator.standalone === "undefined"`. That property exists only in Safari/WebKit on iOS: it is false in a tab and true in a Home Screen web app, and both keep the lead exactly as now. Every other phone browser (Android Chrome first) gets no lead, tail, scroll lock, settle-back or nudge, so its own toolbar-hiding scroll is left alone.

Purpose: commit 16159b85 dropped the old `!== false` gate entirely, so every phone browser took the scroll lock. The owner wants the lead on any iOS WebKit context and nowhere else.

Necessary consequence (flagged for the owner): the light-palette ink on the brand and the frame button is keyed on `.place-lead` in style-place.css. 16159b85 also removed the app bar's dark canvas fade. Without the ink, a non-iOS phone in the dark theme would draw light ink on the light tiles and fail contrast. To keep 16159b85's ink behaviour unchanged on every phone, Task 2 drops the `.place-lead` qualifier from those two selectors. The ink values do not change. The style-place.css hash in the render baseline moves.

Output: the gated function, the ink selectors decoupled from the lead, browser tests split into iPhone (lead) and other-browser (no lead) expectations, three other test files back to the no-lead layout plain Chromium now shows, the render baseline hash, and a one-paragraph UI-SPEC revision.
</objective>
