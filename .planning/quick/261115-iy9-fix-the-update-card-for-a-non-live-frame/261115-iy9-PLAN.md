# Quick task 261115-iy9: Update card reads the root state dir for a non-live frame

## Problem (observed in production, 2026-11-15)

The EE04 frame's Fleet page shows "Aucune version signalée" and "Aucune version publiée" although
`registry.seeed-ee04-7in3-spectra6.json` lists fw-v1.2.0 and fw-v1.2.1 (`firmware_cli list`
verified on the VPS). `companion/pages/update_page.py::_loaded_parts` loads the registry and the
device report from `ctx.state_dir`. For a non-live frame that is its own `devices/<id>` directory,
while byos and `firmware_cli` keep both in the root state dir (`ctx.root_state_dir`,
`companion/page_context.py`). For the live frame the two directories are the same, which hid it.

## Task 1: failing behaviour tests first

Files: `companion/test_update_page.py` (or a new `companion/test_update_page_non_live.py`).
Serve the Update card / embedded Fleet parts for a non-live second-type frame (hardware type
`seeed-ee04-7in3-spectra6`, the second type enabled for the test the way existing tests enable
gated types) whose registry and device report are written under the ROOT state dir and whose
own device dir is empty. Assert on the served HTML: the release versions appear and the reported
firmware version appears. Also a live-frame case: output byte for byte equal to the output before
the change (existing golden `companion/testdata/update_page_one_type_golden.json` must not change).
Run them: they must fail before the fix.

## Task 2: the fix

File: `companion/pages/update_page.py` (`_loaded_parts`, and any other place in this page module
that takes `ctx.state_dir` to load the registry or the device report or `relevant_types`).
Use `ctx.root_state_dir` for `firmware_registry.load_device_report`, `resolve_type_choice`,
`load_registry`. Keep `ctx.state_dir` for anything that is the frame's own (next-wake clock text).
Also check `companion/app.py` POST install/cancel handlers (around lines 1330-1410): they pass
`self.args.state_dir` (root) already; confirm they are consistent and change only what is wrong.
If `ctx.root_state_dir` can be None in some context (tests), fall back to `ctx.state_dir`.
Grep `companion/` for other readers of the registry or device report that use the per-device dir
(console_fleet_view, home, health) and report them; fix only the Update card paths.
