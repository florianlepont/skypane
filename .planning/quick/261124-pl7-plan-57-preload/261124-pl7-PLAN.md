# Plan 57: preload every tab's assets during the opening splash

Source: 261124-lda-loading-audit (AUDIT.md, fixes 1-5) and the owner's remark "pourquoi pas tout durant l'animation ?".

## Design

1. `companion/preload_assets.py` builds the list from the tables the pages already use
   (`page_styles`, the tab script table moved there from `app.py`, `console_users.PAGE_SCRIPTS`,
   `console_fleet_view.page_scripts`, `place_page`), role-aware: only destinations the rendered
   sidebar / tab bar links to (plus the Console's own entries when Fleet is linked).
   Every URL carries the `?v=` token (`static_files.asset_version`).
2. Style page pictures (large current look + the layout thumbnails) come from
   `layout_picker.first_view_preview_srcs`, the same calls the page markup makes.
3. The list rides on the splash overlay (`data-splash-preload`); `splash.js` fetches it with
   6 parallel requests (map library last) and the airline pictures the page shows at w=264 are
   also fetched at w=450.
4. Owner correction: the fetches are a progress group ("others", weight 0.4). The splash keeps
   its fixed ~1.8 s sequence when everything is in, holds on its last frame while files are
   missing and opens at 100%; safety cap 10 s (boot cap 10.2 s); FORCE_DONE removed.
5. Tests: companion/test_browser_splash_preload.py (list covers every reachable page's own
   files, role-aware, no network request for static/preview after the splash) and
   companion/test_browser_splash.py (fast end, slow-link hold, stalled request at the cap).
6. Measurements: scratchpad lda57/measure.py before/after.
