# Quick 261029-f10: fleet_migrate tolerates upper-case token keys

`fleet_migrate` now shape-checks `byos_state.json` token keys case-insensitively (`_TOKEN_KEY_RE`, `\A...\Z`) and imports a token only when its key is the canonical lowercase MAC and is in devices.json. Any other well-formed key is skipped and counted in the existing "skipped N token(s)" line, and the token is never printed or copied. Production state with a key such as `DE:AD:BE:EF:00:01` no longer aborts the migration with exit 2.

## Behaviour
- Upper-case or mixed-case key: exit 0 in dry-run and real run, skipped and counted.
- Lowercase and upper-case keys for the same registered MAC: lowercase wins. Upper-case alone: the device migrates without a token.
- Non-hex, dashed, short, or newline-suffixed keys, and malformed token values (any key case): still exit 2 with no fleet.db.
- devices.json validation is unchanged.
- Side effect: the old `$`-anchored check accepted a key with a trailing newline and skipped it. `\Z` now rejects it with exit 2, as the plan specified.
- After migration, byos returns 200 for the live token and 401 for the upper-case-key token.
