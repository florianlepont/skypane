<objective>
Stop `fleet_migrate` from aborting on production state whose `byos_state.json` has a token keyed by an upper-case MAC (`DE:AD:BE:EF:00:01`). Today `_read_tokens` validates token keys with the lowercase-only `_MAC_RE` and raises "byos_state.json holds a malformed MAC", so the deploy's migration step exits 2.

Purpose: byos `normalize_mac` lowercases every MAC it handles, and `issue_token` stores tokens under that lowercase form, so byos never writes an upper-case key. Any upper-case key is a leftover, like the orphan tokens 48-08 already skips. The migration has to tolerate it the same way: skip it, count it, never import it, never print it.
Output: a narrow fix in `server/fleet_migrate.py` and tests in `server/test_fleet_migrate.py` and `stub-server/test_fleet_auth.py`.
</objective>

<decisions>
- F10-D1: Token keys in byos_state.json are shape-checked case-insensitively: six colon-separated hex pairs, `\A...\Z` anchored. A key failing that check, or a non-str key, still raises LegacyStateError "byos_state.json holds a malformed MAC" (exit 2). A malformed token value (empty, non-str) still aborts too, whatever the key's case. This is the same order as today: key shape, then token shape, then the skip decision.
- F10-D2: A token is imported only when its key is canonical (equals `key.lower()`) AND is in devices.json. Every other well-formed key is skipped and counted in `skipped_tokens`.
- F10-D3 (collision rule): if an upper-case key's lowercase form is a registered MAC that also has a lowercase token, the lowercase token wins and the upper-case one is skipped. If a registered MAC has ONLY an upper-case key, that token is skipped too and the device migrates without a token. Reason: byos looks tokens up by the normalized lowercase MAC, so it could never have tied that key to the device. A real device in that state re-enrols through /setup with its own secret after the deploy. F10-D2 gives both cases without extra code: the decision depends only on the key's own canonical form, never on folding keys together.
- F10-D4: devices.json validation stays as it is: lowercase-only `_MAC_RE`, upper-case registry MACs still abort. The existing `test_malformed_registry_aborts` cases do not change.
- F10-D5: The report keeps the existing single line "skipped N token(s) for unregistered device(s)" with one shared count. An upper-case key is not a key in devices.json, so the wording still holds. No new line, no MAC and no token in the output.
- Accuracy note (not a code change): before migration, byos `bearer_ok` compares the bearer against every token value in byos_state.json whatever its key, so an upper-case-key token could authenticate on the legacy path. This is the same legacy-fallback exposure 48-08 accepted for orphans. After migration the fleet view has no such token, so it gets 401. The byos test asserts only the post-migration behaviour.
</decisions>
