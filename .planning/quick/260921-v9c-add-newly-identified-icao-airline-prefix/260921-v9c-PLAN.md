Do not invent a new format, a new tuple arity, or a new comment style.** Read both modules in full before editing either.

## The evidence class this batch introduces

Every existing row in `_ICAO_AIRLINE_PREFIXES` carries an evidence citation of one of four kinds: a real curled callsign that resolved (`HOP4001`, `AIA6412`), a real curled callsign that definitively missed (`KMM466`), an airline-endpoint probe (`VLG`, `TAP`), or a citation to a prior planning document. **None of the eleven rows in this batch has any of those.** Their evidence of record is the developer's own observation at Orly on 2026-09-21 — the same class as the KLJ row's 2026-09-02 confirmation ("no specific callsign or flight number was captured; the evidence of record is the developer's own in-session confirmation, not a fixture or curl transcript"), and materially weaker than a curl transcript.

Write every new comment to say that plainly. Introduce and use one new verdict token, `[DEVELOPER-OBSERVED]`, defined once in `illustrations.py`'s module docstring and once in HANDOFF.md as: *observed by the developer at Orly on 2026-09-21 from photographs/screenshots reviewed offline; no adsbdb transcript and no fixture exists for any prefix in this batch.* Do not reuse `[VERIFIED-CALLSIGN]`, `[VERIFIED-AIRLINE-ENDPOINT-ONLY]` or `[CITED: ...]` for any row here — each of those makes a claim this session cannot support.

**Do not run adsbdb probes to try to upgrade that evidence.** No transcript was captured when the flights were seen, a probe run today answers a different question (what adsbdb says about a code, not what a real observed flight returned), and the developer's decision governs the table values either way. The accepted consequence is recorded instead — see the RJA/SVA note in Task 2.

## Decisions this plan makes (cite these IDs in the code comments)

- **QT-v9c-D-01 — CAJ reuses the existing "Air Caraïbes" key.** Air Caraïbes Atlantique is the group's long-haul AOC: same brand, same livery, a different legal AOC. It maps to the parent brand's existing name, costs zero new artwork and adds zero `_ILLUSTRATION_TARGETS` entries — the identical brand-consolidation precedent as the shipped `WMT` -> "Wizz Air" and `EJU` -> "easyJet" rows, which the comment must name explicitly as the precedent.
- **QT-v9c-D-02 — DJT resolves La Compagnie, superseding Phase 3.1's `[UNRESOLVED]` verdict.** `.planning/phases/03.1-procedural-per-airline-livery-rendering/03.1-LIVE-RESOLUTION.md` (Step C, and the "Consequences for the target set" exclusion) parked this carrier because its Wikipedia-confirmed ICAO code resolves in adsbdb to a different, unrelated US operator, and no real La Compagnie callsign had ever been caught to learn what a genuine flight returns. The developer observed a real DJT-prefixed La Compagnie flight on 2026-09-21; that is the blocker the old verdict named, and it is now cleared. This is structurally the same supersession as Amelia's (`260827-kih`) — follow that bullet's prose shape in both VENDOR.md and HANDOFF.md.
- **QT-v9c-D-03 — TFV is a defensive alias, not a second ICAO code.** The observed callsign read `TFV60HA`; the official prefix already in the table is `TVF`. A letter transposition in the observed data is far more likely than a real second code. It maps to the same existing "Transavia France" value, adds no illustration target, and its comment must say it is a safety net whose premise is a probable misreading — so a future reader with real evidence can delete it rather than defend it.
- **QT-v9c-D-04 — CTM's delivered A330 artwork ships as the unsuffixed primary `french-air-force.png`.** The developer delivered this one file named `french-air-force-a330.png`, and COTAM's A330 MRTT Phénix really does broadcast type designators (A332/A339) that `classify_aircraft_type()` maps to the `a330` bucket, so a shape-suffixed target would fire on Tier 1. **It is still installed as the primary**, because this codebase has a structural requirement a shape-only target violates: `companion/pages/airlines_page.py` builds every gallery card's image URL from the primary key alone, and `companion/test_status_pages.py` asserts every rendered card URL is a member of `target_filenames()`. A shape-only "French Air Force" target would render a 404 image in the companion and fail that harness. Installed as the primary, Tier 2 (D-06, "brand identity wins over exact type precision") returns the identical file for a real COTAM A330 that Tier 1 would have returned, and additionally covers COTAM's other types instead of dropping them to the generic silhouette — strictly more coverage, one fewer file, zero duplicated bytes. Task 1 adds a machine check so this requirement is never discovered by accident again. **The deviation from the delivered filename is deliberate and must be recorded in VENDOR.md** (the row names the delivered filename and this rename), never silently applied.
- **QT-v9c-D-05 — FGN and IPF are included as state operators with their own artwork.** Both were initially scoped out as "not real airlines"; the developer reversed that on 2026-09-21. They are treated exactly like QAF/SRA/KAF: a prefix row, a target, delivered art. The comments must say what each operator actually is (Gendarmerie nationale's aviation branch; the Iraqi Prime Minister's Office aircraft, tail YI-ASF as observed) so the "this is not a commercial airline" fact is visible in-tree rather than lost.
- **QT-v9c-D-06 — DEF, QEM and `saudi-special-flight.png` are deliberately out of scope.** DEF was a privately-registered Cirrus SR22T (tail D-EFGM), not an operator. QEM was flagged by the developer as NOT Qatar Amiri Flight's official prefix — the aircraft actually observed (Airbus ACJ320, tail A7-MBK) belongs to Qatar Amiri Flight and is reachable through the `QAF` row in this batch, so hardcoding QEM would encode an unreliable guess for zero gain. A tenth delivered file, `saudi-special-flight.png`, has no confirmed operator behind it — its name says Saudi while the only candidate prefix discussed was for a Qatari aircraft, an unresolved mismatch — so it is neither copied nor referenced, and is deferred to a future session. Record all three exclusions in HANDOFF.md so a later reader does not "complete the job".
