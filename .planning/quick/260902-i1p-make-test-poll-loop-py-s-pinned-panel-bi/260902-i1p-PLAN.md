<objective>
Make the pinned `panel.bin` digest regression check in `server/test_poll_loop.py` platform-aware: a mismatch stays a hard FAIL on Linux (CI + the production VPS, the authoritative platform), and degrades to an informational `NOTE ` line plus a plain PASS on any other platform (macOS dev machines).

Purpose: every macOS developer's local `scripts/run-all-tests.sh` run currently shows a permanent, expected `42/43` red herring for a cross-platform Pillow/FreeType text-rasterization difference that this file's own comment block has already root-caused four separate times and confirmed is never a regression. Stop the noise without weakening CI's actual safety net.

Output: `server/test_poll_loop.py` only - a platform-gated comparison helper, a dedicated both-branch regression check, a `EXPECTED_CHECK_COUNT` bump 43 -> 44, and a new dated entry in the existing `_DEFAULT_CONFIG_DIGEST` provenance comment block.

Explicitly out of scope: `_DEFAULT_CONFIG_DIGEST`'s pinned value, any rendering code (`server/plane/render.py` and friends), `scripts/run-all-tests.sh`, and every other test file.
</objective>

Four edits to `server/test_poll_loop.py`, all in one commit.

(1) Add `import platform` to the stdlib import block at the top of the file, keeping the existing alphabetical order (it sits between `os` and `shutil`).

(2) Add a new module-level helper `_digest_verdict(digest, expected)` immediately after `_write_battery_state()` and immediately before `def main():`. It follows the same module-level-helper convention as `_snapshot()`/`_empty_snapshot()`/`_write_battery_state()`, and returns the same `(ok, reason)` two-tuple every `check()` function in this file returns.

Required behaviour, exactly:
  - If `digest == expected`: return `(True, "")` and print nothing, on every platform.
  - Otherwise build the mismatch detail string in the SAME shape the current inline comparison produces: `"panel.bin digest %s != pinned %s" % (digest, expected)`.
  - Otherwise, if `platform.system() == "Linux"`: return `(False, <that detail string>)` and print nothing. This is byte-equivalent to today's behaviour for CI and the production VPS - zero change there.
  - Otherwise (any non-Linux platform): print one informational line and return `(True, "")`. The printed line MUST start with the four characters `NOTE ` at column 0, so it lines up with the harness's own `PASS `/`FAIL ` prefixes, and MUST contain the mismatch detail string and the value `platform.system()` actually returned. It also names why this is expected - a Pillow/FreeType text-rasterization difference, with the pin being Linux/CI-authoritative, pointing the reader at `_DEFAULT_CONFIG_DIGEST`'s own comment history.

Two hard constraints on this helper:
  - `platform.system()` must be called through the module object at call time (i.e. `platform.system()` inside the helper body), NOT captured into a module-level constant at import time. Task 2's proof monkeypatches that attribute, and a hoisted constant would make the proof exercise a copy of the logic instead of the real branch.
  - Do not introduce a third result status. `check()` and its `results.append((name, ok))` accounting stay untouched; the softened path is a plain pass whose explanation travels out of band via `print()`.

Give the helper a docstring stating the Linux-authoritative/non-Linux-informational split and pointing at `_DEFAULT_CONFIG_DIGEST`'s comment history for the full reasoning.

(3) Rewire `_default_config_byte_identity()` (check 10, currently around line 1171): keep the temp dir, the `run_once()` call, the file read, the `hashlib.sha256(...).hexdigest()` line and the `finally: shutil.rmtree(...)` exactly as they are, and replace only the trailing `if digest != _DEFAULT_CONFIG_DIGEST: ... return True, ""` block with a single `return _digest_verdict(digest, _DEFAULT_CONFIG_DIGEST)`. (4) Append a new dated entry to the existing `_DEFAULT_CONFIG_DIGEST` provenance comment block (currently lines ~91-224), placed AFTER the "Sixth re-pin" paragraph and immediately before the `_DEFAULT_CONFIG_DIGEST = ...` assignment line.
