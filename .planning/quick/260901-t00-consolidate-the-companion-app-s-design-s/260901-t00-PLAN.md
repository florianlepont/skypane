**Output:** a rewritten `SKILL.md`, three new reference files, three corrected reference files, an updated `.claude/CLAUDE.md` pointer line, and two focused commits. Zero source-code changes.

**The one failure mode this plan exists to prevent.** A documentation-synthesis task fails by confidently restating a value that was true three phases ago. `companion/static/style.css` is unusually well-commented — nearly every non-obvious declaration cites its origin inline (`06.6.4 (D-01b)`, `quick task 260901-s5o`, `Direct follow-up to 260901-s5o`) — which makes it a genuine ground truth, but it also means a *sampled* read will hand you a superseded rule's own explanation of itself and read exactly like current fact. Read the whole file. Then Task 3 mechanically re-derives every literal the finished skill states and fails if any of them is not in the real sources.

**The SUPERSEDED convention** (introduced by this plan, enforced by Task 3). Historical values must appear in the skill — that is the entire point of documenting a reversal — but they must be distinguishable from current ones by machine, not just by prose. Rule: any line stating a value or mechanism that is no longer current must carry the literal uppercase token `SUPERSEDED` on that same markdown line. Task 3's cross-check treats `SUPERSEDED` as the only escape hatch for a literal it cannot find in the real sources.
