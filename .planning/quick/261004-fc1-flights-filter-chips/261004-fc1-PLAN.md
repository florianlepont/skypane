# 261004-fc1: Filter bar rebuilt as segmented chips plus an expanding search (owner sketch C)

## Objective

The plain filter area on Flights, Airlines and Health's unresolved-prefix list
becomes one shared component: a 16px / 48px search field with an inline clear,
and on Flights a segmented chip group whose segments carry live counts. The
search collapses to an icon beside the chips on phones.

## Data check (what the chips may filter on)

`runway_events.confirmed_state` is written only as `departing` or `arriving`
(`server/plane/runway_config.py`), and both occur: the phone card already
renders "Arriving" with the destination as the home end. So the sketch's
All / Departures / Arrivals are backed by real data and are kept. The other
columns were considered and rejected: the runway is the same for every row
(only the tracked runway), "resolved or unidentified" is already a per-row link
rather than a dimension worth a segment, and a "today" chip duplicates the day
headers. Airlines and Health carry no second dimension, so they get the plain
search pill only.
