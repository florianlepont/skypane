<objective>
Remove the ntfy push-notification feature completely. The owner no longer wants it. That means the server sender and its poll-cycle hooks, the `notifications` device-config group, the companion Notifications card with its "Send a test" route, and every test and doc that describes them. Two things stay: the firmware reconcile step and the calendar feed's SSRF-safe fetch path. State already on disk in production (a stored `notifications` group with a topic URL in device_config.json, and a `notifications` dedup sub-dict in poll_state.json) must keep loading cleanly, and the next save must drop it.

Purpose: Owner request. It also shrinks the attack surface: one fewer outbound request to an operator-chosen URL, and one fewer authenticated POST route.
Output: A companion, a server and tests with no push feature. Two new behaviour-test files prove the legacy state is tolerated and that no push ever goes out. The render baseline is regenerated, the docs are corrected, and every gate is green.

Task order is companion first, then server, then docs and gates. The swap from the suggested server-first split is on purpose. The companion imports `server.notify` and `device_config.DEFAULT_NOTIFICATIONS`, so removing the companion's use first keeps the whole suite green at every task commit.
</objective>
