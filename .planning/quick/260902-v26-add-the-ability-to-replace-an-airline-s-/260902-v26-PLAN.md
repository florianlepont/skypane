the companion web gallery AND the physical panel compositor (`server/plane/render.py`)
both resolve illustrations through — so an uploaded replacement stored outside the
git-tracked source tree wins over the vendored original, at every fallback tier,
for both consumers (D-01).

physical panel, not just the web preview". Nothing in plans 02/03 can deliver a
panel-side effect without this seam existing first.

Output: a new public resolver API in `illustrations.py`, a one-line wiring in
`poll_loop.run_once()`, and harness checks proving both the override precedence
and the zero-regression property.
</objective>

    - `generic_fallback_path()` keeps returning the vendored path unconditionally.

  <action>
Implement the D-02 override-storage layer as new public API in
`server/plane/illustrations.py`. Add near the existing constants block:

`ILLUSTRATION_OVERRIDE_DIRNAME` — the subdirectory name under a state dir where
uploaded replacements live. Use `illustration_overrides`. Document in its comment
that this name is a per-state-dir convention chosen because `deploy/deploy.sh`
rsyncs `server/` with `--delete` and excludes only `state`, so the vendored
`ILLUSTRATION_DIR` is the one place an upload must never be written (per D-02).

Add a module-level process default (name it `_override_state_dir`, initialised to
`None`) plus a public setter `set_override_state_dir(state_dir)`. Its docstring
must state precisely why it exists: `select_illustration()` is called from deep
inside `render._build_active_canvas()`, a call chain that deliberately carries no
filesystem-location awareness (`state_dir` appears nowhere in render.py), so the
alternative — threading a state_dir through `render.build_canvas()`,
`render.render_panel()`, `render._build_active_canvas()` and poll_loop's five
`build_canvas()` call sites — would push a deployment concern through three public
render signatures and would silently invalidate `server/test_render.py`'s existing
two-argument monkeypatch lambdas. The process default is set once per process by
the entrypoint that already parses `--state-dir`; the explicit `state_dir=`
parameter below stays the primary, directly testable contract. Setting it to
`None` restores the vendored-only behaviour.

Add three resolver functions, each pure-ish and never-raising, matching this
module's established discipline:

- `override_dir_for_state_dir(state_dir=None)` — resolve the effective state dir
  (the argument, else the process default), return `None` when there is none,
  otherwise join `ILLUSTRATION_OVERRIDE_DIRNAME` onto it. Do not create the
  directory; this module is read-only with respect to overrides.
- `override_path_for_key(key, state_dir=None)` — return `None` for a falsy key,
  for a key matching `_UNSAFE_KEY_RE`, or when there is no effective override
  dir; otherwise join `key + ".png"`. Re-use the SAME `_UNSAFE_KEY_RE` boundary
  check `illustration_path_for_key()` already applies. Its docstring must say
  this is the boundary itself, exactly like `illustration_path_for_key()`'s does,
  and must not rely on the caller having validated the key.
- `resolved_illustration_path(key, state_dir=None)` — the single seam: return the
  override path when it exists as a real file, else the vendored
  `illustration_path_for_key()` path when THAT exists as a real file, else `None`.

Change `select_illustration`'s signature to
`select_illustration(route, aircraft_type=None, state_dir=None)` and replace each
of its four tiers' `illustration_path_for_key(...)` + `os.path.isfile(...)` pair
with a single `resolved_illustration_path(..., state_dir)` call. Tier 4's key is
derived from `GENERIC_FALLBACK_FILENAME` by stripping the extension — do not
introduce a second hardcoded literal for it. Extend the existing four-tier
docstring with a short paragraph explaining that each tier now consults the
override location first and the vendored file second, and that tier PRECEDENCE is
unchanged: an override only ever replaces the source of the tier whose key it
matches.

Leave `illustration_path_for_key()`, `generic_fallback_path()`,
`validate_illustration_file()`, `target_filenames()` and every other existing

the vendored file — `render._load_illustration_safely()` uses it as a last-resort
candidate and `server/test_illustrations.py` asserts it points at the real
vendored file.

Zero-regression requirement: with `state_dir=None` and the process default unset,
every code path must produce the identical result it produces today. This is what
keeps the 52 existing checks green without editing them.
