Parser rules, all strict, all fail-closed to `None`:

- Parse `content_type` with `email.message.Message` (assign the raw header value,
  then use `get_content_type()` and `get_param("boundary")`). Note in the
  docstring that this is the non-deprecated stdlib replacement for `cgi.parse_header`

  `multipart/form-data`, and the boundary to be a non-empty `str` that encodes
  cleanly to ASCII and is at most 70 characters (the RFC 2046 ceiling).
- Build the delimiter as two hyphens followed by the ASCII-encoded boundary, and
  split the raw body on it. Require **exactly three** segments: a preamble, the
  one part, and an epilogue. Require the preamble to be empty after stripping
  whitespace, and the epilogue to begin with the two-hyphen closing suffix.
  Anything else — including a second part — returns `None`. Accepting exactly one
  part is deliberate: this route's form carries a single file input and nothing
  else, so the parser has no reason to implement general multipart semantics, and
  refusing to is the smallest provably-correct behaviour.
- Require the part segment to start with a CRLF; strip it, then split once on a
  doubled CRLF into a header block and a payload. A missing separator returns `None`.
- **Discard the header block entirely.** Do not parse it. Do not read the declared
  filename, the field name, or the declared media type. The docstring must state
  explicitly that the client's filename is ignored by construction — the

  `None` for an empty payload.

| Boundary | Description |
|----------|-------------|
| browser -> POST /illustration/{key}.png | An authenticated client submits arbitrary bytes with an arbitrary declared filename and media type. First untrusted file upload in this codebase. |
| uploaded bytes -> Pillow decoder | Image data reaches an image decoder, both at validation time and again at serve time. |
| URL key -> filesystem path | The path component chooses the destination filename. |
| stored override -> panel compositor | The stored file is later opened by `server/plane/render.py` on the device-facing render path. |
