<objective>
Give the companion Airlines gallery the same aircraft framing consistency the panel compositor gets, reusing the panel's own proven bbox logic.

`companion/pages/airlines_page.py` renders each of the 43 airlines as a plain `<img src="/illustration/{key}.png">` at `width: 100%; height: auto`, and `Handler._serve_illustration_image()` streams the vendored PNG's raw bytes. There is no centring or cropping logic anywhere on this path — so every card inherits its source file's own transparent padding verbatim. Measured on these exact files: horizontal padding is asymmetric per file, top padding spans a 118px range at panel scale, and the painted aircraft's aspect ratio ranges from 2.97:1 (`chalair-aviation.png`) to 5.00:1 (`amelia-embraer.png`). In a uniform CSS grid that reads as aircraft randomly sized and randomly offset within otherwise identical cards.

The fix normalizes server-side, at the route, using `server.plane.render`'s `_threshold_alpha()` / `_opaque_bbox()` — the same named `ILLUSTRATION_ALPHA_THRESHOLD` the panel paints with, imported rather than reimplemented, so the web gallery and the panel can never disagree about where an aircraft ends.

Purpose: the gallery is the reference view for "what art does this frame have"; inconsistent framing makes the vendored set look lower quality than it is.
Output: a shared normalization helper, a normalizing image route, and a stable-layout gallery card.

**Deliberate constraint: this plan does not edit `server/plane/render.py`.** It only imports from it. That is what guarantees zero change to panel.bin's pixels and therefore no `_DEFAULT_CONFIG_DIGEST` re-pin — unlike its sibling plan 01, which does move panel pixels and handles the re-pin explicitly.
</objective>

  <files>companion/illustration_normalize.py, companion/test_status_pages.py</files>
  <behavior>
    - normalized_png_bytes(path) returns PNG bytes whose painted content is tight-cropped to the opaque bbox, then padded symmetrically into one fixed output aspect ratio shared by every file.
    - Across all 43 vendored illustrations, every output has identical pixel dimensions.
    - Across all 43, the painted content's centre sits at the output's centre within 1px on both axes.
    - No output clips its aircraft: the painted bbox is fully inside the output on both axes for every file.
    - A file whose opaque bbox is None (nothing painted) falls back to the source image rather than raising.
    - The helper imports the threshold logic from server.plane.render; it does not define its own alpha threshold or its own bbox routine.
  </behavior>
  <action>
    Create `companion/illustration_normalize.py`.

    Import `server.plane.render as panel_render` and use `panel_render._opaque_bbox()` and `panel_render._threshold_alpha()` directly. Do NOT copy the threshold value, do not re-derive a bbox from `Image.getbbox()` or from the raw alpha channel, and do not add a second alpha constant anywhere in the companion tree. The originating debug session's transferable lesson is precisely that a measurement using a different predicate than the renderer is indistinguishable from a correct one until it drifts; importing is what makes drift impossible. Reading a private name across this boundary follows the existing precedent in `companion/pages/history_page.py`, and importing costs nothing in panel risk — whereas adding a public wrapper would mean editing render.py, which this plan deliberately avoids.

    Implement `normalized_png_bytes(path)`:
    - open as RGBA, compute the opaque bbox, crop to it (falling back to the whole image when the bbox is None)
    - scale the crop to fit inside a module-level target box, preserving aspect ratio, using the same LANCZOS resampling `_resize_illustration()` uses
    - paste it centred onto a fully transparent canvas of exactly the target dimensions
    - return PNG bytes via an in-memory buffer

    Choose the target box from the measured extremes rather than guessing: painted aspect ratios span 2.97:1 to 5.00:1 with a median of 3.43:1. A target near the widest ratio letterboxes the tall-ish files with dead space; a target near the median crops nothing but leaves the widest file smaller in frame. Pick one, name it as a module constant, and record the measured range and the reasoning in its comment so the next reader knows it was derived, not picked. Fit-inside (never crop-to-fill) is required — clipping a wingtip to fill a frame is a worse defect than the one being fixed.

    Add an `lru_cache`-backed accessor keyed on path plus the file's mtime, so the 43 files are normalized once per process but a replaced asset is still picked up. Keep the uncached `normalized_png_bytes()` separately testable.

    Add the behaviour checks above to `companion/test_status_pages.py` in that harness's existing style, iterating the real vendored files rather than synthetic fixtures — the same "real project assets, not test fixtures" discipline `server/test_render.py` documents. Include a check that no module in `companion/` defines its own alpha-threshold constant, so a future copy-paste is caught.
  </action>
