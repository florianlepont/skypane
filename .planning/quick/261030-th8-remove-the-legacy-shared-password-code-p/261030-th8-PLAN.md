<objective>
Remove the legacy shared-password code path from the SkyPane companion now that
SKYPANE_LEGACY_PASSWORD_LOGIN=0 has been live in production since 2026-10-30
and Auth0 sign-in works (54-LEGACY-ADMIN-REMOVAL.md steps 2, 3 and 4; step 5,
the schema/migration, is deliberately NOT done).

password throttle, no standing legacy principal).

regenerated render baseline, updated deploy docs, updated removal/handoff notes.

nothing may change what the live frame receives or how it authenticates; no
production deploy; Phase 50/51 areas (image format, per-device config) and
firmware untouched; no commit by the planner or this plan.

Rollout caveat (record verbatim in the SUMMARY): the production
/opt/skypane/skypane.env still holds SKYPANE_COMPANION_PASSWORD and
SKYPANE_LEGACY_PASSWORD_LOGIN=0. After this change both are unknown variables
and must be tolerated (ignored, never fatal) by the companion, activate.sh and
provision.sh. The Auth0 variables (SKYPANE_AUTH0_DOMAIN / _CLIENT_ID /
_CLIENT_SECRET, plus SKYPANE_COMPANION_PUBLIC_URL as already required) are
already set in production because Auth0 is live; a deploy of this code without
them would make the companion refuse to start.
