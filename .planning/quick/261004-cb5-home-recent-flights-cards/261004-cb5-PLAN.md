# 261004-cb5: Home "Recent flights" as slim boarding-pass tiles on phones

## Objective

Owner feedback: Home's recent flights deserve the Flights card treatment
(PR #177), but more compressed. Below 960 px, each recent flight becomes one
slim two-row tile in the Flights card language. The goal is at least 5
flights visible in the card on a 390x844 screen, against about 3 today.
The desktop list at >= 960 px is unchanged.

Also investigate the duplicate TVF49NS row the owner saw.

## Approach

- **Shared helpers instead of copies.** The Flights card's route line and
  artwork plate move into a small shared companion module that both pages
  import. Flights markup stays byte-identical, which the render baseline
  checks.
- **Phone tile markup.** A sibling `ul.recent-flight-tiles` sits before the
  unchanged desktop `ul.recent-flights`, with a CSS toggle at 960 px (the
  Flights pattern). Each tile has two rows:
  - Row 1: the callsign in mono and the muted airline (ellipsis) on the left,
    the clock and live age on the right.
  - Row 2: a wide artwork plate (about 30 px tall, or a dashed placeholder),
    then a compact ORY ┄✈┄ IBZ route with the direction label under the plane.
  - Hairline separators, no nested card chrome.
- **No new actions.** Home rows have no link today, so the tiles get none
  either.
- **Duplicate.** De-duplicate consecutive events in Home's list: same hex,
  callsign, route and direction, with timestamps under 60 s apart. Fetch a
  few extra rows so five distinct flights still show. Storage is untouched.
- **Swap registry.** The whole `section[aria-labelledby="home-flights"]` is
  already the swap target, so no registry change is needed.

## Tasks

1. Shared helper module plus Flights refactor (no markup change), and the Home
   tile markup with dedupe and any new FR strings.
2. CSS for the phone tile and the 960 px toggle.
3. Tests: retarget the Home recent-flights tests, then add new ones. The
   served-HTML tests cover tile structure, the variants, dedupe and the absence
   of style attributes. The browser tests check 390/360 overflow, at least 5
   tiles visible, and the 1280 desktop list unchanged. Regenerate the baseline
   after inspecting the diff.
4. Verify with screenshots before and after (scratchpad `shots-cb5/`), then
   run the full suite and the gates, and push.
