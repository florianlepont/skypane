## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server-rendered HTML | the prefix originates from the validated device id, then is written into attributes |
| hidden return_to fields | client may alter them before posting |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-33 | Tampering | XSS through the prefix in attributes | mitigate | prefix is built only from an id matching `\Ad_[0-9a-f]{8}\Z`; every emitter keeps `escape_html` on attribute values (tests render with the fixture ids) |
| T-51-34 | Tampering | open redirect via return_to | mitigate | return_to stays un-prefixed and whitelisted; handler-side membership test from the earlier plan |
| T-51-35 | Elevation of privilege | link or form that escapes the device scope (acts on live frame from a device page) | mitigate | prefix carried by one helper at every emitter; the crawl test in the final integration plan asserts completeness across all pages |
| T-51-SC | Tampering | package installs | accept | none installed |
</threat_model>
