## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fix commit or pull request -> public repository | a diff can reveal the weakness it fixes |
| session -> production deploy | owner-only |
| held-back file -> repository | one-way: nothing flows in until the fix is deployed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66-07-01 | I | high/critical fix visible in the public diff before deploy | mitigate | local unpushed branch and neutral commit message until the owner says push; owner pushes and deploys in one sitting |
| T-66-07-02 | I | pull request titles, bodies and test names | mitigate | neutral wording; test names describe the protected behaviour in general terms |
| T-66-07-03 | E | session approves or runs a deploy | mitigate | forbidden; deploy is the owner's manual step (checkpoint) |
| T-66-07-04 | T | fix breaks golden hashes, freeze test or live frame | mitigate | gates listed in Task 2 run before every commit; live-frame check by the owner after deploy |
| T-66-07-05 | D | fix collides with an open pull request | mitigate | open pull requests checked before editing any file; conflicts raised to the owner |
| T-66-07-06 | R | high item left without a decision | mitigate | phase cannot close: plan 08 refuses to finish while any high or critical item lacks "deployed" or a written acceptance |
</threat_model>
