<objective>
The production deploy fetches the typed assets of a release and imports them once the owner lifts the switch (criteria 2-3, deploy side).

Purpose: `ci.yml` requires `skypane-<tag>.bin` and `release.json` and downloads only those; `activate.sh` runs `import-dir` under `runuser` with a clean environment and never sources the env file, so a switch placed only in `skypane.env` would be invisible to the import step even after the lift.
Output: pure tested asset selection script, ci.yml download step using it, activate.sh forwarding.
`ci.yml` is deployed on merge, so the change must be behaviour-neutral for live-only releases. Do not touch firmware-release.yml.
</objective>
