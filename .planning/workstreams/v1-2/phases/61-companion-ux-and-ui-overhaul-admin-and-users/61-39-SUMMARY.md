# Phase 61 Plan 39: Personalisation navigation and Look picker Summary

Owner decision D29 (W10): Personalisation becomes a segmented, animated section navigation (Look, Special looks, Calendar, Screen) over one view per entry, and the Look view is the look picker (Departures/Arrivals tabs, live picture, colour dots, background and band segments, Reset, Save), as in mockups P1 and P1d.

- **Navigation (`companion/pages/personalisation_cards.py`, `style.css`, `theme-preview.js`):** the "On this page" list is replaced by `nav.personalisation-nav`, four plain links with a 20px icon and label (new `icon-palette`, `icon-calendar`; existing `icon-star`, `icon-nav-display`), 44px tall, current link `aria-current="page"`. At 360px the bar scrolls inside itself and the current link is scrolled into view. With a script a thumb starts under the link of the page just left (kept in `sessionStorage`) and slides to the current one (`transition` on the thumb); under `prefers-reduced-motion` it is placed at once. Without a script the current link carries the pill itself.
- **One view per address:** Look `/display` (unchanged), `/display/special-looks`, `/display/calendar`, `/display/screen`. All four are wrapped as the Display tab (same nav highlight, scripts, freshness token) with the same `OWNER_DEVICE` access, and appear in the device-scoped route set (`/devices/<id>/display/...`). `config_page.render(..., view=...)` renders one view; `view=None` renders all four (used by whole-page checks, never served). Each view's hidden `return_to` is its own address; `submitted_return_route` accepts the four; a rejected save redraws the view holding the refused field (`config_page.error_view`); the rule add/delete routes return to Special looks, the calendar connect/disconnect/sheet routes and the calendar-sheet links to Calendar; the Screen switch returns to its own view. Saving from a view submits only its fields (absent fields leave the stored value unchanged, as `handle_post` already did).
- **Look view (`settings/theme.py`, `theme-preview.js`):** `look_card_body_html` now renders Departures/Arrivals tabs (script-only), the two existing pictures as panels, and the look sheet in an inline form (`data-look-inline`: no dialog role, no scrim, no focus trap, Escape inert) inside a script-only wrapper, with Reset (restores the saved look of the active tab) and Save. The script keeps the sheet's three axes bound to the active tab's own target, so a choice checks the same theme radio, raises the save bar naming "Look" and posts through the unchanged form. With scripts the radio cards, the Arrivals "Change" table and "Customise look" are hidden; without one they are the Look view exactly as before.
- **Save button:** the picker's Save is `type="button"` and presses the save bar's own Save, so the settings form keeps exactly one submit control (an existing invariant).
- **Calendar bug found and fixed:** the Calendar view holds no departures look, so its "Same as departures" toggle could not resolve a theme. The calendar target now carries `data-look-follows-theme` (the saved departures theme) and `effectiveTheme` falls back to it.
- **Special looks dialog:** the add dialog opened to the left of its (now narrower) card and off the content; it now opens over its own card from 700px.
- **Strings:** `display.personalisation_sections` (replaces `display.on_this_page`), `look.save`, `look.departures_or_arrivals`, EN in code, FR in `companion/i18n_fr/`.
- **Tests (adapted in place, none weakened):** `test_browser_personalisation.py` rewritten for the new behaviour (44px and no overflow on all views in both languages and themes, phone scroll, picker save bar and persistence, tabs and Reset, plain-link navigation, sliding vs reduced motion, no-script floor), `test_personalisation_page.py`, `test_personalisation_special_looks.py`, `test_display_looks.py` (inline picker, hidden dialog on the other views, calendar follows-theme), `test_browser_display_looks.py`, `test_browser_personalisation_cards.py`, access matrix and route-set pins, redirect pins (`test_device_actions.py`, `test_calendar_sheet.py`, ...), `test_browser_ux_02/03/04.py`, `test_browser_calendar_*.py`, overhaul sweep/steps (new views added to the sweep). Icon count 50 to 52. `render_baseline.json` regenerated (new pages and routes added to the snapshot) and the `test_sign_in_surfaces.py` digests regenerated deliberately (the icon sprite is part of the shell).
- **Docs:** `61-UI-SPEC.md` section 11 (Batch 3 structure block, strings, R22).

## Deviations from Plan

- The Look view with a script hides the radio look cards and "Customise look" (the picker replaces them); no-script keeps them. This follows mockup P1, which shows neither.
- The ux_04 "palette floors" test now measures the no-script controls with scripts blocked (synchronous reads) and the picker controls with scripts, instead of one scripted page; the "card titles" test covers three card views (Look is the picker and has no card title).
