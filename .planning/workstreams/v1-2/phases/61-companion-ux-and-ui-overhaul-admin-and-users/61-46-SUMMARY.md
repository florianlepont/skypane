# Phase 61 Plan 46: Phone chrome Summary

Owner round 4 feedback W22, W23, W38, W39: a slim phone header, the space switch as the first tab-bar cell, and a compact, collapsible, marked-off frame strip.

- **Header (W39, W22):** the phone header is a logo-only bar (min-height 52px). The gear toggle, its panel and the Sign out form are gone from the shell (Sign out stays on the Account page and in the desktop sidebar footer). Removed with it: `_mobile_nav_html`, `NAV_TOGGLE_ID`, `MOBILE_NAV_ID`, `MOBILE_NAV_OPEN_CLASS`, `NAV_TOGGLE_LABEL`, the `nav.account_menu` strings (EN and FR, added in plan 61-37), the `icon-gear` sprite symbol (sprite is now 51 symbols), the `.site-nav-toggle`, `.mobile-nav*` (except `.mobile-nav__link`, still the More sheet row geometry) and `.space-strip` CSS.
- **Space switch (W38):** the big strip under the header and the More-sheet switch row are removed. For an administrator the tab bar's first cell is a plain GET link (`ui_nav._switch_cell_html`, same `_switch_target` destinations and aria texts as the desktop segments) showing the space you would switch TO (icon + "Console" or "My frame" / "Mon cadre"). It is a fixed 64px, 56px-high cell with an accent-outlined pill, accent text and a 1px divider after it. The desktop sidebar keeps its two-segment switch. There is no remembered-space cookie in the codebase; the existing mechanism is the two fixed GET links, which the cell reuses (works without script).
- **Tab bar fit:** a sixth equal cell does not fit "Compagnies" / "Utilisateurs" at 360px, so the **Console bar moved Audit log into More** (bar: switch, Fleet, Users, Airline editor, More; A6 is 2 taps again, documented in `61-STEP-COUNTS.md`). The personal bar keeps Home, History, Location, Style beside the switch (six cells, labels short enough at 360px, measured by the browser tests); More now holds Airline collection and Account only.
- **Frame strip (W23):** `ui_shell.strip_fold_html` wraps the strip in `details.frame-fold` (also used by the Console Fleet strip in `console_fleet_view.py`). On phone (<700px) it is a marked-off surface (secondary background, hairline border, inset shadow, soft gradient, tokens only, both themes) with a 44px summary row showing the active frame's name (or "System") and a chevron; tiles are 84px wide with only the picture and the name, status dot kept small, last-seen and owner note hidden. From 700px the summary is hidden and the strip looks as before. `nav-dropdown.js` (now: the `js` class plus strip memory) restores a collapse from `localStorage` (`skypane.frameStrip`, try/catch) on phones only and forces open on wider windows; without script the strip is open.

## Deviations from Plan

- The strip is always rendered open (script restores a stored collapse). The brief says "open by default only when there is more than one frame": the personal strip only renders for two or more frames anyway, and the Console Fleet strip stays open with one frame because it also holds the System and Add tiles.
- The shell script keeps its file name and `NAV_DROPDOWN_SCRIPT_SRC` constant (renaming would ripple through routes and pins) but now only sets the `js` class and remembers the strip state.
