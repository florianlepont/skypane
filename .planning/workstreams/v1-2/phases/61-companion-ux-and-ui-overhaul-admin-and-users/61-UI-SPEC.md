  grab handle, `max-height: 88vh`, bottom padding adds `env(safe-area-inset-bottom)`.
- Status dot is 12px (`.dot`) in lists and 14px (`.home-state__dot`) on Home, as today.

table (User with avatar initial and email, Role select, Frames, Last sign-in, Active switch, "..." menu);
below 70rem each user is a card with the same controls. The role select saves as soon as it changes
(`data-autosubmit`, a normal form submit; without script a small "Save role" button shows), the Active
switch posts disable or enable, and the "..." menu (native `<details class="row-menu">`, Escape closes) holds only the
rare actions that exist as routes (Unlink identity, shown for users who have signed in). The guards
stay: the signed-in administrator and the last active administrator show the guard sentence instead of
the select and a locked switch.

Console Airlines editor (D33, revision 3, mockup E3): one `<table class="airlines-table">` with one
`<tbody>` per airline. Columns: Airline (the name is a text field saved in place through the rename
route: with script on change, so Enter or leaving the field; without script a small Save button),
Prefixes (read-only text), Artwork (the thumbnail is the label of a file input that posts to the
illustration upload route on change; without script an Upload button), Views, Last seen (from the
frame's own stored sightings) and a "..." menu (native `<details class="row-menu">`, Escape closes) holding only "Reset to the original
name" (the rename reset, or the manual name's delete for an owner-named airline; shown when there is
something to reset) and "Enlarge the artwork" (the shared lightbox; a plain link to the picture without
script). A native `<details>` chevron at the start of the row expands one sub-row per aircraft type
seen (type code and model name, views): a type that has an artwork slot of its own in the curated
list (an aircraft variant) offers Replace to that type's upload address, every other type says "Uses
the airline's artwork"; curated variants never seen are listed too (0 views). Unidentified prefixes
are highlighted rows at the top with a "Name it" link into the existing resolve flow (dialog with
script, in-page section without); an owner-named airline still without artwork keeps the link into the
add-artwork step. From 70rem (1120px) it is a table; below, every airline is a card (the sub-rows
stay stacked inside it). Targets are 44px; the filter field keeps its place above the table. The old
airline sheet dialog (name, reset, type tabs) and the `?sheet=` in-page sheet are removed; `?sheet=<key>`
now only puts the focus in that row's name field after a refused name.

Layout widths: content column unchanged. Lists (fleet, my frames) are a single column,
`max-width: 56rem` inside the page card at >=960px. No horizontal scrolling anywhere at 360px
(page and every card: `scrollWidth <= clientWidth`).

## Typography

Four primary sizes and two weights, as shipped. The 12px tier (label voice: counts, pills) and the 13px tier (button sub-scale) are inherited from the shipped stylesheet, not extended (D10); this phase adds no size and no weight:

| Role | Size | Weight | Line Height | This phase |
|------|------|--------|-------------|------------|
| Body | 16px (`--font-body-size`) | 400 (`--weight-regular`) | 1.5 | form text, modal body, helper sentences |
| Label | 14px (`--font-label-size`) | 400 | 1.5 | list second lines (owner, role), helper text, tab labels |
| Heading | 22px (`--font-heading-size`), serif | 400 | 1.2 | modal title, section card titles |
| Display | 32px (`--font-page-title-size`), serif | 600 (`--weight-semibold`) | 1.2 | page title (`.page-title`) |

Rules specific to this phase:
- List row primary text (frame name, user email, my-frame name) is **16px sans semibold**
  (the existing "Emphasis" role: Body size plus `--weight-semibold`). Not serif, not 22px, not
  monospace. It wraps with `overflow-wrap: anywhere`; it is never truncated with an ellipsis and
  never breaks mid-word only because of a narrow column (the column is the full row minus dot and
  action).
- Emails are sans 16px or 14px, never monospace (fixes F4). Frame names are sans. Monospace is
  kept only for the pairing code input and device ids shown in the modals' secondary text.
- The existing 12px uppercase label voice (`.filter-bar__count`, `.banner__pill`) is used for the
  list count line and pills; nothing new at that tier.
- Buttons keep their shipped 13px/14px (14px below 960px) sub-scale.

## 2. Shared modal component

One component, `dialog.modal`, used by all thirteen dialogs below. Native `<dialog>`, no library.

Markup contract (per dialog, rendered in the page, not fetched):
```
<dialog class="modal" id="dlg-<kind>[-<id>]" aria-labelledby="dlg-...-title">
  <form method="post" action="<existing POST route>" ...> csrf field, fields
    <header class="modal__head"><h2 class="modal__title text-heading" id="...-title">…</h2>
      <a class="modal__close" href="<host page path>" data-modal-close aria-label="Close">×</a></header>
    <div class="modal__body">…</div>
    <div class="modal__actions">primary <button type="submit">, dismiss <a href="<host page path>" data-modal-close></div>
  </form>
</dialog>
```
Triggers: `<a href="#dlg-…" data-modal-open>` (a link, not a button, so the no-JS path works).

Behaviour (testable):
- **Open (JS):** `modal.js` calls `showModal()`; page behind is inert; scroll locked; focus trapped by
  the browser. **Initial focus:** first invalid field when re-rendered with an error, else the first
  form control (`autofocus`), and for confirm-only dialogs (retire, re-activate, leave) the *dismiss*
  control, so Enter never confirms a destructive action.
- **Close:** Esc (native `cancel`), the 44x44 close control, the dismiss control, or a backdrop click
  on dialogs without inputs. A backdrop click is ignored on dialogs that hold inputs. After a
  successful POST the server redirects to the page (toast shown); the dialog is gone.
- **Return focus:** to the element that opened it (stored by `modal.js`); when the page was reloaded
  by a POST, focus goes to the page's `h1` (`#main-content` target).
- **Errors:** a refused submission re-renders the page (status as today: 400/429) with that dialog
  carrying `open`; `modal.js` upgrades it with `close()` then `showModal()`; fields carry
  `aria-invalid` and `aria-describedby` to a `.field-error` (existing pattern). The typed pairing
  code / email is re-rendered escaped, as today.
- **No-JS fallback:** the same `<dialog>` is shown by CSS when targeted (`.modal:target`) or when
  server-rendered `open` without the `.is-modal` class `modal.js` adds: an in-page fixed card over
  a scrim made with `box-shadow: 0 0 0 100vmax var(--color-scrim)`, bottom-anchored below 700px. Dismiss/close are plain links to the host
  page path (clears the hash). The submit is the normal form POST. Without script nothing is lost:
  the row menus are `<details>`, the dialogs open from hash links.
- **Geometry:** >=700px: centred, `width: min(480px, calc(100% - 48px))`, padding `--space-lg`,
  radius `--radius-card`, `box-shadow: var(--shadow-pop)`. <700px: bottom sheet (full width,
  `max-height: 88vh`, `overflow-y: auto`, radius 18px 18px 0 0, grab handle, bottom padding includes the safe area).
- **Surface:** `--color-dominant`, `--color-text` set explicitly on the dialog (as `.lightbox` does),
  1px `--color-border`, backdrop `--color-scrim`. Identical rules for both themes via tokens.
- **Controls:** every input/select/button/link inside is >=44px high; fields are full width
  (`max-width: 100%`, no overflow at 360px); labels above fields (14px label); `.modal__actions`
  stacks on phone (primary on top, full width, dismiss below) and is a right-aligned row on desktop.
- **Motion:** entrance uses `--motion-fast` opacity/transform transition with `@starting-style`
  (the `.lightbox` mechanism); close is instant; no new `@keyframes`, no new duration.
- **Script:** `companion/static/modal.js`, first-party, listed in `SHELL_SCRIPT_ORDER` and
  `GLOBAL_PAGE_SCRIPTS`, served from `/static/` (CSP `script-src 'self'` unchanged). It also
  closes open `.row-menu` details on outside tap/Esc (revision 2: the `.frame-switcher` details are replaced by the frame sheet dialog).

### 9.3 Search by city or address (Nominatim, external, D19)

- A search field (`type="search"`, label "Search a city or address", 44px) with a "Search places" button. **Search runs
  on submit only** (Enter or the button): never on keystroke, no autocomplete, no suggestions while typing.
  This is the Nominatim usage policy's explicit ban.
- Request: `GET https://nominatim.openstreetmap.org/search?format=jsonv2&q=<text>&countrycodes=fr&limit=5&accept-language=<en|fr>`,
  `fetch` with `credentials: 'omit'`, `referrerPolicy: 'origin'` (identifies the app by its origin; the
  site's global `Referrer-Policy: same-origin` is not changed), no custom headers.
- **Rate limit:** at most 1 request per second per page (policy), implemented as one request in flight and
  a 1.5-second lock after each; the button is disabled during both; identical queries in the same page
  session are answered from memory; no retries, no timers, no requests on load, no reverse geocoding
  (the label comes from the result's `name` or first comma segment, or from the user).
- Minimum 3 characters; query capped at 120 characters; a result list of up to 5 rows (44px min, wraps), each row the
  place name 16px semibold and the rest 14px muted (the `display_name` without the country). Tapping a
  row moves the pin and the map (zoom 15 for a street-level result, 12 for a city), fills the label field if empty, and closes the list.
  No result: "No place found in France. Try another spelling, tap the map or pick an airport."
- **Failure** (network, 429, 5xx, CORS or blocker): "Search is not available right now. Tap the map, pick
  an airport or enter coordinates." The rest of the page keeps working.
- A caption under the field: "Search by OpenStreetMap Nominatim. What you type is sent to
  nominatim.openstreetmap.org." (privacy note, 14px muted). It is the only place the page sends typed
  text off the site.
- No-script: the search form is hidden (it needs script); the airport list form (9.3b) and the
  coordinates (9.8) are the no-script ways.

### 9.5 A frame's own position (D20), storage, live-frame safety

- **No saved-locations UI.** No Locations tab, page, picker, "Saved places" list or "Save as a place" action
  anywhere. The Display location picker and the old position-mode "choose a saved location" radio are gone. SUPERSEDED: revision 1 "Locations" Console tab and the merged card on Display.
- **Storage (expand-only, no schema change, no change to what the live frame reads):** the frame's
  position is the `locations` row referenced by `devices.location_id`, as today. The first map save on a
  frame **creates a private row for that frame** (name = the place label or "Frame position", latitude,
  longitude rounded to 4 decimals, timezone, `owner_user_id` = the frame's owner) through the existing
  `fleet_db.add_location` and links it with the existing `set_device_location_checked`; later saves **update that row in
  place** through `fleet_db.update_location`. **Copy on write:** if the frame's current row is used by more than one device
  (an old shared saved location), the save inserts a new private row instead of editing the shared one, so no other frame moves.
  A save that leaves the position unchanged writes nothing and does not touch the row.
- **Existing frames keep their position:** nothing is migrated or rewritten. A frame that already has a
  `location_id` opens the map on that row's coordinates; a frame without one opens on France with no pin and
  shows "No place chosen yet" (a position-mode frame in this state keeps its existing "SET A LOCATION" screen
  until the owner saves a place).
- **Runway mode unchanged:** the legacy Orly runway ids (`3`, `06-24`, `02-20`) and their frozen geofence are untouched. The page shows
  them as the matching catalogue airport and runway (LFPO, 07/25 for id `3`); saving without changing the choice keeps the stored
  value as it is (the form posts the legacy id back unless the owner picks something else).
- **What a save writes:** `save_place` posts `mode` (`runway` or `position`), `airport`, `runway`, `radius_km`, `latitude`,
  `longitude`, `place_label`, `timezone` and the csrf token to `/detection` (or `/devices/<id>/detection`). Server rules: the
  existing validators (catalogue airport and runway, `radius_km` 2-28 whole km, the coarse France box 41.30-51.15 N / -5.20-9.60 E
  for a free pin; a catalogue airport is accepted even outside it, for example overseas), `timezone` through `resolve_timezone`,
  the label trimmed, at most 60 characters, control characters refused. Runway mode stores the detection value and the position row
  (the airport coordinates unless the pin was moved); position mode stores the detection value and the position row.
  The detection position used by the poll loop for a frame that does not save is byte-identical to today (assertion R19).
- The old POST actions (`save_detection`, `save_location` with `location_id`) stay accepted for scripts and old tests; no UI posts them.
- Refused saves re-render the page (400, existing statuses) with the entered values escaped and field errors beside the fields (existing pattern).
- **Time zone** moves here from Display; Quiet hours (section 10) read it and say so. Default is Europe/Paris, listed first in the select; the select lists the IANA zones the server already accepts.

## Final design language (plan 61-60, owner decision D39)

The consistency and polish pass over the whole app. The rules every page now follows, in the stylesheet and held by `companion/test_browser_consistency.py`:

- **Page title.** One `h1` per page on `--font-page-title-size` (700, tight tracking). Nothing else on a page is that size.
- **Headings below the title** use one of three sizes: the section label above a group (13px, 600, secondary ink; `--font-caption-size`), the card title inside a free-content card (`--font-card-title-size`, 17px, 600) and the sub-page title (22px: a frame name on Fleet, the place name on Location). Sheet titles (special look, add look) use the card title size.
- **Surfaces.** One glass tier (`--glass-solid` fill, `--color-border`, `--shadow-glass`, card radius 22px) for a group, a free-content card (`.page-section`) and a table wrapper (`.data-table-wrap`, so the Flights desktop table matches Users, Airline editor and Audit). A glass surface never sits inside another (embedded content in a Fleet group is flattened). A card does not lift or change shadow on hover; only an action reacts.
- **Groups and rows.** Lists are a section label over one group of rows (at least 54px, hairline between rows). Fleet Access is rows: the purpose, the owner, each co-manager with its Remove action as a trailing control and the invite select (or typed e-mail) plus a primary Add as the last row. The Fleet System view is one labelled group per topic (flight data, data sources, identification, backups) with the unresolved-airline registry as its own group. The standalone Releases page lists versions as one group of expandable rows with the running count in the label. The airline sheet's facts are hairline rows on the sheet (the sheet is the glass, so no inner group). Special look rule rows keep their trailing Remove action (a rule opens nothing, so no chevron).
- **Controls.** Selects and text, number, search and time inputs are 44px tall with the 14px control radius. The Flights, Airline collection, Airline editor and Health search field is 44px with that radius too (the phone icon button is 44px square). Primary buttons are graphite (ivory in Dark), secondary buttons are glass, destructive text is the error colour.
- **Dialogs and sheets** are glass with the 28px top radius on a phone; the dialog container itself draws no focus ring (every control inside keeps its ring); the quiet-hours time fields shrink so a 12-hour clock reads in full on a 360px phone.
- **Background.** The sky runs from pale blue to a cool pale grey (`--sky-bottom` is `#EDF1F6`); no warm beige remains in Light.
- **Quality gates** (all in the consistency test): at most six blurred surfaces per page, every animation finite except the status dot pulse, no layout shift above 0.1 while a page settles (Home, Flights, Fleet, Users), reduced motion leaves no looping animation, a visible focus ring on every control type, and `aria-current` on the current navigation entry, `aria-haspopup`/`aria-expanded` on the menus.
