<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session/branch -> repository secrets | Any workflow on any same-repo branch can read repository secrets on Free (no environments) |
| dispatch input -> shell | `confirm_sha` and `ci_sha` are untrusted text |
| GitHub runner -> production VPS | SSH with the deploy key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-70-01 | Elevation | deploy workflow started by accident or from a stale/other ref | mitigate | main-ref step before the key is loaded, strict tip-of-main equality, 7-character confirmation, CI check for the exact SHA; behaviour-tested |
| T-70-02 | Tampering | `confirm_sha`/`ci_sha` injected into shell | mitigate | passed only through `env:`, validated against fixed hex regexes before use |
| T-70-03 | Information disclosure | deploy key readable by a malicious branch workflow | accept (here) | cannot be fixed on Free in this plan; reduced by the dedicated key in 70-02, recorded in the README as residual risk; server-side gate/signed ticket is an owner decision in 70-02 |
| T-70-04 | Repudiation | deploy with no record of who/what | accept | the workflow run log and `workflow_dispatch` actor are the record |
| T-70-SC | Tampering | package installs | accept | no package is installed by this plan |
</threat_model>
