<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI artifact -> Mac signer | unsigned bytes built by a GitHub runner are signed with the owner's key |
| Mac script -> GitHub Releases | publishes the image the frame will be offered |
| Mac script -> docker | the private key is mounted into a container |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-70-09 | Tampering | malicious or off-main build handed to the signer | mitigate | tag regex, tag commit ancestor of origin/main, run headSha equals the tag commit and headBranch equals the tag, exact SHA256SUMS file set; the owner also reads notes.md before the real run |
| T-70-10 | Information disclosure | signing key exposed | mitigate | key never in a workflow or secret (test asserts no FW_SIGNING_KEY), mounted read-only with `--network none`, mode check, never printed, test asserts no key bytes in output |
| T-70-11 | Spoofing | forged release replacing an existing tag | mitigate | refuse when the release exists; `--verify-tag` |
| T-70-12 | Tampering | unverified signature published | mitigate | verify against committed public key and `fw_release_manifest.py --check-only` before staging |
| T-70-13 | Elevation | workflow with write access publishing a release | mitigate | `contents: read` only, tests assert no `gh release create` / `gh workflow run` in workflows |
| T-70-SC | Tampering | package installs | accept | stdlib only; no package is installed by this plan |
</threat_model>
