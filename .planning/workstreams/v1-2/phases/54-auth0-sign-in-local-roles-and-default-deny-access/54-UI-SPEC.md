# Phase 54 — UI Design Contract

> Visual and interaction contract. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This phase adds NO tokens, NO colours, NO accent consumers, NO fonts, NO motion. Every value below is read from the live system (`companion/static/style.css`, `ui_components.py`, `ui_shell.py`, `ui_nav.py`, `login_page.py`) and the `sketch-findings-skypane` skill, treated as locked. If a sentence here seems to need a new value, that is a defect in the spec: reuse an existing one.

## Surface Contracts

### 1. Login page (`/login`, `login_shell`, `.login-card`, max 360px)

Order, top to bottom:
1. Logo mark 40px, `h1.page-title` "SkyPane", purpose sentence (`.text-body`). Purpose copy changes only when Auth0 is on; see Copywriting.
2. Primary action: a GET link `<a href="/login/start[?next=...]">Sign in</a>` styled as the primary button, 44px, full width. It is a link, never a form (a POST would hit `form-action 'self'` against the Auth0 redirect). `next` carries only a same-site relative path from the whitelist.
3. Legacy block, rendered ONLY when `SKYPANE_LEGACY_PASSWORD_LOGIN` is on:
   - Hairline divider (`--color-border`, structural use) with `--space-lg` above.
   - `<details>` disclosure, closed by default when Auth0 is configured; open by default (and no summary chrome needed, but keep the heading) when Auth0 is not configured. Summary text: "Use the shared password (legacy)" with a neutral `.banner__pill` "Legacy" before it. Disclosure marker is the existing accent `<summary>` marker.
   - Inside: existing `login_body` form unchanged (label, password input, show/hide reveal, `.field-error` message, lockout countdown, `next` hidden field), submit button in quiet-wash styling (see Color) with label "Sign in with password".
   - One-line `.text-label` helper: "Temporary access for the administrator. It will be removed once Auth0 sign-in is live." (EN) / FR below.
4. Flag off: the legacy block is not rendered at all; POST `/login` answers with the generic refusal (Surface 7 "sign-in unavailable" wording, status 403/404 per planner), not a password error.
5. Error from a failed redirect (Surface 7) renders as ONE `toast--docked` error toast (in flow, above the card's primary action) via the login page's `error` argument path, `role="alert"`, never as a raw query-string message. Wrong-password and lockout keep their existing in-form `.field-error` and countdown (login-card.js unchanged).
6. No-JS: everything works (link and `<details>` are native).
7. If the user is already signed in, GET `/login` redirects by role (`user` -> `/account`, admin -> `/`), as today.

### 2. "Not invited" refusal page

- Served by the callback for a verified-but-unknown identity (or `email_verified` false: same page, same words, so the page does not reveal which). Status 403. No session cookie, no account row.
- `login_shell` + `.login-card`: logo, `h1.page-title` "SkyPane", one `toast--docked` warning toast (title "No invitation found", detail = body below), then a `.text-link` "Back to sign in" -> `/login`.
- No "request access" form, no email echoed back, no identity details, no Auth0 error text (never reflect `error_description`).
- Does NOT offer Sign in again as a primary button (nothing to retry); the text link is enough.

### 3. Interstitial page (post-callback landing and sign-out)

- Bare 200 document per RESEARCH ("Interstitial landing"): `<meta http-equiv="refresh" content="0;url=...">` with the target escaped, no inline script, CSP-safe, `referrer no-referrer`. It is built as a `login_shell` card so a slow hop never flashes blank, but it must not depend on any script.
- Content: logo mark, one `.text-body` line ("Signing you in…" / "Signing you out…"), and a visible `.text-link` fallback ("Continue") to the same target for browsers that block meta refresh. Role `status`.
- No spinner and no new animation (motion budget). The meta refresh fires immediately; the page should be effectively invisible on a normal connection.
- Targets: callback -> `/account` for `user`, `/` (or whitelisted `next`) for admin/legacy-admin. Logout -> Auth0 `/v2/logout?...returnTo=...`, and the local session is already destroyed when this page renders. If the Auth0 hop fails, the user lands on the fixed `returnTo` (the login page) with the signed-out state; never an error.
- Title tags: "Signing in" / "Signing out". Cache-Control no-store.

### 4. Account page (`/account`, `page_shell`, active slug `account`)

Role `user` minimum (admins may open it too; harmless, and it is where "signed in as" lives). Structure:
- `layout.page_header("Account", purpose="Your SkyPane sign-in and preferences.")`.
- Card 1, "Identity" (`.page-section`, nested card title tier): a two-row key/value list using the existing `data-card` label/value pairing (12px label voice + 16px value): "Email" (the linked email), "Role" ("User" / "Administrator"). Value text only; no avatar, no Auth0 `sub` shown.
- Card 2, "Preferences": language and theme controls are the SAME `_lang_form_html` / `_theme_form_html` partials the shell already uses (POST `/ui-lang`, `/ui-theme`), rendered inline in the card so they are reachable at 360px without opening the gear panel. Return target after those POSTs is `/account` for a `user` (RESEARCH pitfall 6).
- Card 3, "Frames": `ui_components.empty_state(heading, body)` full-card form (not compact): heading "Your frames will appear here", body "Once an administrator pairs a frame to your account it will show up on this page." No illustration, no action button, no health, no owner-frame data. This card is the slot Phase 55 replaces.
- Sign out: the existing `.logout-form` quiet button, in the card list after "Preferences" and also in the shell footer/mobile panel as today. Label "Sign out". Not destructive: no confirm dialog.
- No dirty-bar / save bar: both preference controls are already immediate POST forms.
- Header toast: a `flash` toast may appear after theme/lang changes via the existing flash mechanism; nothing new.

### 5. Legacy-access flag (persistent, only when principal is legacy-admin)

Proposal (least invasive for the shared shell): one neutral `.banner__pill` reading "Legacy access" (title attribute: "Signed in with the shared password") placed immediately before the Sign out button in the shell's existing logout footer, for both the sidebar footer and the mobile preferences panel. Implementation shape: `_logout_form_html()` (`ui_nav.py`) gains an optional pill fragment resolved from the request-scoped principal (the same request-scoped mechanism as `prefs.set_request_prefs`), empty string otherwise. No new landmark, no new row, no layout shift, no new CSS (existing `.banner__pill`; planner may add a flex-gap on the footer using `--space-sm` only if the pill and button do not already lay out cleanly).
- Also shown (so the flag is not hidden behind a closed panel on phone): in the Account page "Identity" card, "Role" value reads "Administrator (legacy access)". The phone mobile panel is closed by default, so the footer pill is not visible at a glance there; whether that is acceptable is Open Question 1.
- The pill is neutral on purpose: it is a state reminder, not an alert, so no warn/error colour and no accent. It carries text, so it is not colour alone.
- Not shown for `admin` (Auth0) or `user` principals, and not on login/refusal/interstitial pages.
- Baseline impact: this changes the shared-shell markup for any render captured while signed in as legacy-admin. The render-baseline fixtures log in with the shared password, so `render_baseline.json` entries for every authenticated page will change and must be regenerated deliberately (one reviewed diff: only the added pill fragment, identical on every page). Open Question 2 covers the alternative of switching the baseline harness to an Auth0 `admin` principal so the baseline stays byte-identical.

### 6. Navigation for a `user` principal

- Sidebar (>=960px): wordmark, then ONE link "Account" (`/account`, active pill, standard accent wayfinding use), then the existing footer (language/theme forms, Sign out). No group headings (`NAV_GROUPS` not rendered), no Home/Health/Flights/Display/Device/Update links, no Health dot.
- Phone (<960px): the bottom tab bar is NOT rendered for a `user` (one destination is not navigation); the gear toggle and its panel (language, theme, Sign out) remain, as today. The Account content is the whole page.
- No link anywhere may target a route that returns 404 for the role: the shell takes the nav entries from the same route table that enforces the minimum role, so a link exists iff the route is reachable. Test: every `href` in a `user` page's shell either is `/account`, `/ui-*`/`/logout` form actions, or a static asset.
- Admin / legacy-admin / Auth0 `admin`: nav is unchanged from today.
- Brand wordmark in the sidebar/mobile header links to `/account` for a `user` (not `/`).
- 404 and 403 pages (`not_found_page`, `forbidden_page`): for a `user`, no Health dot (health_alert forced to `None`), the shell nav is the `user` nav above, and the "Back to Home" link becomes "Back to Account" -> `/account`. For an unauthenticated caller the shell is the existing no-context shell and the link goes to `/login` ("Back to sign in") rather than a Home that would redirect or 404. Admin keeps "Back to Home". A `user` requesting an admin-only route or another user's device gets the identical 404 body and status as a nonexistent URL.

### 7. Generic sign-in error states

All render on the login card (`login_shell`) with the login page's primary Sign in link still present beneath, so recovery is one tap. One `toast--docked` error toast (role `alert`) with a title + detail, glyph + visually hidden tone prefix per the toast contract. Wording is deliberately generic and never includes Auth0 error text, `state`, `code`, or any claim value. Status 400 for the first two, 503 for unavailable.

| Case | Toast title | Toast detail |
|------|-------------|--------------|
| State mismatch / missing pre-login cookie / replayed callback | "Sign-in could not be completed" | "Start again from this page. If it keeps happening, check that cookies are enabled." |
| Expired login (pre-login attempt older than its lifetime) | "Sign-in took too long" | "Start again from this page." |
| Auth0 unavailable / token call failed / invalid token | "Sign-in is not available right now" | "Try again in a few minutes." |
| Auth0 returned `error=access_denied` or similar | same as state mismatch (no distinguishing) | same |
| Legacy flag off, password POST | "Password sign-in is turned off" | "Use the Sign in button above." |
| Account disabled mid-session | session ends; login page, same toast as "expired" is NOT used; show the refusal page wording "No invitation found" | see Surface 2 |

## Interaction and Accessibility Requirements

- 360px: login card is `width:100%; max-width:360px` inside `.login-shell` padding of 24px, so the usable card is 312px at a 360px viewport; the Sign in link, the legacy form, the toast and the Account cards must not overflow horizontally (assert scrollWidth <= clientWidth at 360 and keep the existing 320px assertions passing).
- Touch targets: Sign in link, legacy submit, Continue/Back links as text-links need >=44px hit height where they are standalone (give the text link block display with 44px min-height inside the card); gear/tab controls unchanged.
- Focus: Sign in link is `autofocus` when the legacy form is collapsed or absent; otherwise the password input keeps `autofocus` only when the legacy block is open (Auth0 not configured). One autofocus per page.
- Toast semantics follow the toast contract: `role="alert"` for refusal-warning/error, glyph + hidden prefix, no auto-hide (docked, persistent), no dismiss.
- Refusal and error pages: `Cache-Control: no-store`, `<title>` set, `lang` from the request prefs.
- Both themes verified (light/dark) via the existing theme-switch browser harness; contrast comes from existing tokens, so no new contrast pairs.
- Reduced motion: nothing animates here.
- Behaviour-over-source tests: assert served HTML/CSS and browser results (link href, no `<form>` around Sign in, legacy block absent with flag off, no Health dot in `user` 404, no admin hrefs for `user`), not source text.

## Open Questions (owner decisions, not decided here)

1. Legacy flag visibility on phone: the footer pill lives in the closed gear panel under 960px. Is that enough, or should the pill also sit beside the wordmark in the mobile header (still one neutral `.banner__pill`, but a bigger shell change and a bigger baseline diff)? Default in this spec: footer pill + Account "Role" value.
2. Baseline strategy: regenerate `render_baseline.json` once for the added pill (this spec's default), or move the baseline fixtures to an Auth0 `admin` principal so legacy-only markup never enters the baseline? The second keeps baselines byte-identical but changes the fixture login path for every render test.
3. Primary link styling source: reuse `a.calendar-manage--primary` declarations scoped to `.login-card`, or introduce a neutral alias class for the same declarations? No new accent use either way; this is a naming/CSS-hygiene choice for the planner.
4. Legacy block default state: collapsed when Auth0 is configured (this spec) versus always open but visually quiet. Collapsed reduces misuse; always-open is one fewer tap for the admin during the transition.
5. Refusal status code: 403 (this spec) versus 200 to avoid any browser/proxy treating it as an error page; both leak nothing. Also whether "unverified email" should be worded identically to "unknown" (this spec says yes).
6. French wording of the legacy labels ("ancien accès") and the "administrateur" gendering for the owner's review.
7. Role display on Account for `admin`: show "Administrator" (this spec) or omit the role row for admins.
