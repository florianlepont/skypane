<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server -> browser markup | pages echo configuration state and user-visible identity |
| query string -> login page | `next` and error text could reflect attacker input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-54-03-01 | Tampering | reflected content in login/error pages | mitigate | all dynamic text through layout.escape_html; error kinds are a closed set mapped to fixed strings; Auth0 error_description is never reflected; `next` only from the whitelist |
| T-54-03-02 | Information disclosure | refusal page reveals which condition failed | mitigate | unknown, unverified and disabled render the same page and words; no email echoed |
| T-54-03-03 | Information disclosure | user shell leaks admin nav or fleet health | mitigate | user role renders one Account link, no Health dot, no tab bar; tested |
| T-54-03-04 | Tampering | Sign in implemented as a form POST hitting CSP form-action | mitigate | plain GET link; test asserts no form ancestor |
| T-54-03-05 | Spoofing | interstitial open redirect via target | mitigate | target is supplied by server code only (fixed paths, fixed Auth0 URL), escaped in attribute; plan 05 passes only constants/whitelisted values |
| T-54-03-SC | Tampering | package installs | accept | none |
</threat_model>
