<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| frame -> /device/v1/setup and /display | untrusted network input: MAC, provision secret, bearer token |
| byos -> fleet.db / legacy files | identity store consulted on every request; may be absent, corrupt or stale |
| operator CLI -> both stores | two stores must change together |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-48-19 | Spoofing | auth fail-open on corrupt fleet.db | mitigate | corrupt/absent/too-new fleet.db falls back to the legacy files only, never to allow-all; tests with garbage bytes and wrong token (401 still) |
| T-48-20 | Elevation of privilege | cross-source confusion (union of stores) | mitigate | exactly one identity source per call (fleet.db when migrated and readable, else legacy); revocation test proves immediate 401 |
| T-48-21 | Information disclosure | timing leak on token compare | mitigate | keep hmac.compare_digest across all candidates with no early exit; existing tests retained |
| T-48-22 | Tampering | token known to one store only after enrolment | mitigate | fleet.db written first inside a transaction; failure -> 503 and legacy untouched; success -> legacy mirrored; old-reader test |
| T-48-23 | Information disclosure | secrets in logs/status file | mitigate | logs and fleet_status.json carry the exception class name and state only; tests scan stdout and the status file for the seeded token and hash |
| T-48-24 | Denial of service | sqlite open on every request | accept | one tiny read-only query per request on a loopback single-frame service; failure degrades to legacy path rather than 5xx |
| T-48-25 | Tampering | in-window re-enrolment by the old release between migration and swap | accept | requires a physical frame re-provision inside a seconds-long window; the next fleet_migrate run reconciles legacy-wins on tokens |
| T-48-26 | Repudiation | shared "default" bucket attributing polls to the wrong device | mitigate | unmatched token resolves to None and records nothing (D-09); tests |
</threat_model>
