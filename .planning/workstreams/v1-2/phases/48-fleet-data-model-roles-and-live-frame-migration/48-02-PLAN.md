    `connect_readonly(state_dir) -> sqlite3.Connection` uses a `file:` URI with `mode=ro`, raises FleetDbAbsent when the file does not exist, sets foreign_keys and busy_timeout, does NOT migrate, and raises FleetDbTooNew when user_version exceeds SCHEMA_VERSION. `connect_memory()` opens `:memory:` with the same pragmas and runs `migrate_schema`. Provide `schema_version(conn) -> int`.

    `MIGRATIONS` is an ordered tuple of step callables taking a connection; version 1 creates the schema exactly as in 48-RESEARCH.md Pattern 1: users (id INTEGER PRIMARY KEY, email TEXT NOT NULL UNIQUE COLLATE NOCASE, role TEXT NOT NULL CHECK(role IN ('admin','user')), disabled INTEGER NOT NULL DEFAULT 0 CHECK(disabled IN (0,1)), iss TEXT, sub TEXT, created_at TEXT NOT NULL, UNIQUE(iss, sub)); locations (id, name, latitude with CHECK between -90 and 90, longitude with CHECK between -180 and 180, timezone, all NOT NULL); devices (id TEXT PRIMARY KEY opaque `d_` plus 8 hex, never the MAC; mac TEXT NOT NULL UNIQUE; secret_sha256 TEXT NOT NULL; token TEXT; hardware_type TEXT NOT NULL; owner_user_id INTEGER NOT NULL REFERENCES users(id); location_id INTEGER REFERENCES locations(id); name TEXT; state_path TEXT NOT NULL DEFAULT '.'; created_at TEXT NOT NULL); meta (key TEXT PRIMARY KEY, value TEXT NOT NULL). No ON DELETE CASCADE anywhere and no user-delete API: disabling a user must never orphan devices. `SCHEMA_VERSION = len(MIGRATIONS)`.

    `migrate_schema(conn, migrations=MIGRATIONS)`: read PRAGMA user_version; if greater than len(migrations) raise FleetDbTooNew; for each pending step run BEGIN IMMEDIATE, the step, `PRAGMA user_version = %d` built from an int literal, COMMIT, rolling back on any exception and re-raising. The version set is inside the same transaction as the DDL.

    `transaction(conn)` context manager as in the behavior block. `meta_get(conn, key) -> str | None` and `meta_set(conn, key, value)` using `?` placeholders.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI/migration/byos -> fleet_db | untrusted strings (email, MAC, names, hardware key, timezone) reach SQL and file paths |
| process -> fleet.db file | the file holds secret hashes and plaintext bearer tokens |
| fleet.db contents -> role decisions | role must come only from the local row |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-48-05 | Tampering | SQL built from CLI/body input | mitigate | `?` placeholders everywhere; the single string-built statement is an int-literal PRAGMA; test grep-free: parameterised helpers only |
| T-48-06 | Elevation of privilege | role derived from IdP claim or header | mitigate | `users.role` CHECK(admin,user); `get_user_role(conn, user_id)` is the only reader and takes no claim/header argument; signature test |
| T-48-07 | Information disclosure | tokens/secrets in fleet.db | mitigate | file created 0600 (WAL/SHM inherit); `list_devices` and status file never carry tokens or full hashes; mode test |
| T-48-08 | Tampering | orphaned or doubly owned devices | mitigate | `owner_user_id INTEGER NOT NULL REFERENCES users(id)`, `foreign_keys=ON` per connection, no cascade delete, no user-delete API; IntegrityError tests |
| T-48-09 | Denial of service | newer or corrupt schema opened by older code | mitigate | FleetDbTooNew refusal without writing; callers fall back (byos plan); atomic DDL test |
| T-48-10 | Repudiation | none of audit scope this phase | accept | audit trail for pairing/ownership changes is Phase 54-55 scope |
</threat_model>
