<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| skypane.env (root-owned) -> activate.sh | operator-supplied value flows into a root script and a child command line |
| activate.sh (root) -> skypane user processes | backup and migration run unprivileged via runuser |
| state dir -> archive -> off-box pull | fleet.db (hashes and plaintext tokens) leaves the live directory |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-48-27 | Tampering / injection | SKYPANE_BOOTSTRAP_ADMIN_EMAIL in activate.sh | mitigate | value read by the strict `_extract_env` (never sourced), validated against an anchored allow-list regex before any change, passed as a single quoted argv element; invalid-value test |
| T-48-28 | Elevation of privilege | migration running as root | mitigate | `runuser -u skypane` for backup and migration so fleet.db is owned by the service user with mode 0600 |
| T-48-29 | Denial of service | failed migration leaving a half-deployed release | mitigate | steps run before the swap; any non-zero exit aborts with the previous release current; transaction-atomic migration; failure tests |
| T-48-30 | Information disclosure | tokens in the backup archive | accept | byos_state.json already carries the same plaintext tokens in the archive; archives are 0027/off-box via the forced-command gate; revisit when tokens are hashed |
| T-48-31 | Tampering | torn copy of a live WAL database | mitigate | snapshot via sqlite3 online backup API with integrity_check on the copy; concurrent-writer test |
| T-48-32 | Repudiation | silent loss of fleet.db from backups | mitigate | corrupt database fails the backup loudly; restore test proves content |
| T-48-33 | Information disclosure | owner email printed in logs | accept | an administrator address is not secret; no token or hash is ever logged |
</threat_model>
