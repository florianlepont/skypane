<objective>
Close gap CR-01 from 48-VERIFICATION.md: `devices_cli remove` leaves the removed
device's bearer token in byos_state.json, and `fleet_migrate._read_tokens` then
aborts (exit 2) on that orphan token, which wedges every deploy because
activate.sh refuses to swap when the dry-run or real migration fails.

Purpose: the live-frame migration (SC1/SC2) must be re-runnable and must not be
blocked by a leftover token from an earlier device removal.
Output: a one-line token drop in `cmd_remove`, an orphan-skipping and counting
`_read_tokens`, and regression tests.

Legacy-fallback decision (explicit): `bearer_ok` and `effective_tokens` in
byos_server.py are NOT changed. Filtering legacy tokens by registry membership
would change legacy-mode auth for states whose devices.json is missing or
corrupt, which existing tests and the previous release rely on. The orphan
risk is closed at its sources instead: (1) `cmd_remove` stops creating new
orphans; (2) the migration never copies an orphan into fleet.db, so in fleet
mode (DB authoritative) an orphan token gets 401. The residual exposure is a
pre-existing orphan token in byos_state.json while byos runs in the legacy
fallback (fleet.db corrupt or too new); the owner clears it with
`devices_cli revoke-token`, which needs only the token entry. This residual is
accepted and recorded in the threat register.

Deferred (out of scope, non-blocking per the verifier): WR-01 through WR-07 of
48-REVIEW.md. The two human checks (real-state dry-run replay against a copy of
production state; companion Chromium browser tests) cannot run in the sandbox
and are recorded as the final checkpoint task; they do not gate the code tasks.
</objective>

| operator CLI to state dir | devices_cli edits devices.json and byos_state.json (credential store) |
| legacy files to fleet.db | fleet_migrate reads untrusted-shape JSON and writes tokens into the authoritative DB |
| device to byos | bearer token presented on /api/display is checked against the stored tokens |
