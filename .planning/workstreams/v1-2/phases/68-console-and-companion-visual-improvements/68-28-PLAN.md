|----------|-------------|
| administrator form to POST /users/invite | e-mail and role input |
| companion to Auth0 Management API | outbound credentialed call |
| response to administrator's browser | one-time invitation link |
| Auth0 account to SkyPane access | identity proof versus authorisation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-68-28-01 | Elevation | Auth0 account creation widening access | mitigate | local invite remains the only gate: `sign_in_user` unchanged and tested (Auth0 account without invite is refused); the Auth0 payload carries no role or metadata |
| T-68-28-02 | Information disclosure | invitation link storage and logging | mitigate | link shown once in a `no-store` POST response; not in database, audit, logs, flash, cookie or URL (Test 2 asserts each) |
| T-68-28-03 | Spoofing | Host header into the invitation message and result URL | mitigate | existing `_HOST_RE` validation of the application URL kept and tested with a hostile Host header |
| T-68-28-04 | Tampering | invite form input | mitigate | existing e-mail and role validation and CSRF and origin checks unchanged (`test_csrf`, `test_post_origin`); e-mail escaped in the page |
| T-68-28-05 | Denial of service | Auth0 failure or slowness | mitigate | client timeouts; failure leaves the local invite and a retry through the same route; no exception to the user |
| T-68-28-06 | Repudiation | invitation outcome | mitigate | audit row records who invited whom and the outcome (never the link) |
