Owner decision of 2026-11-21 (recorded here as ART-01 to ART-09; the overview and CONTEXT are not edited by this plan): uploaded artwork is FLEET-WIDE, like the airline names of plan 41. Today an upload lives in `<device state dir>/illustration_overrides/<key>.png` (the live frame at the state root, every other frame under `devices/<id>/`) while the Airlines editor lists one fleet-wide set of airlines, so a picture added on frame A does not show on frame B. One directory at the fleet root, an idempotent merge of every frame's images, nothing deleted.

**Base and order.** Depends on plan 41, which introduced `device_dirs.fleet_root_for(state_dir)`, `server/plane/fleet_registries.py` (with `frame_state_dirs(root)`), the fleet-root registries, the marker idea and the `server.fleet_migrate` hook; this plan reuses all of them. **Decisions made here (the owner can overturn on review):**

- ART-01 Storage: keep PNG files in one directory, `<fleet root>/illustration_overrides/<key>.png` (the existing name and layout, per-type files `<key>-<slug>.png` included). The live frame's directory IS that directory already (its state directory is the root), so only the other frames' files need merging in. No database: files are the contract the render path, the upload route, the cache busters and the backup already share.
- ART-02 One seam, no call-site edits: `illustrations.override_dir_for_state_dir(state_dir)` (around line 627) returns `os.path.join(device_dirs.fleet_root_for(state_dir), ILLUSTRATION_OVERRIDE_DIRNAME)` (still `None` for a falsy `state_dir`, still never creates the directory). Every consumer already goes through it or through `override_path_for_key`, `resolved_illustration_path` and `select_illustration`: the poll render path (`render/layout.py`, `landscape_card.py`, `render/giant/compose.py` pass the frame's `state_dir`), the editor pages (`airlines_page.py`, `airline_known_rows.py`, `airline_collection_page.py`, `home_recent_strip.py`, `history_page.py`, `resolve_dialog.py`), the upload and delete routes (`post_actions.py` around line 296 and 332, `airline_actions.py` line 74), the cache buster (`illustration_normalize.py` line 155), the picture route (`app.py` around line 906) and the rename carry. No caller changes; `server.plane.illustrations` importing the leaf `server.device_dirs` creates no import cycle (device_dirs imports only `atomic_io` and `panel_format`). The separate poll unit reads the same directory with no other change.
- ART-03 Per-device image directories: never read, written, renamed or deleted by this release (frozen copies, FLT-07 rollback logic of plan 41). They disappear with their frame (`device_dirs.wipe_device_dir`). The upload temp files (`.<key>.upload.*.tmp`) are created in the fleet directory by the unchanged upload route; the merge ignores any dot-file and `*.tmp`.
- ART-04 Migration: a new module `server/plane/fleet_artwork.py` with `plan_merge(root)` and `apply_merge(root, plan, now=None)`, hooked into `server/fleet_migrate.py` `migrate()` next to the registry merge of plan 41 (same deploy order: pre-migration backup, `--dry-run`, real run, all before the symlink swap; `deploy/activate.sh` needs no edit). No lazy migration on read: renders must never write, and the migration never runs at service start. A root marker `illustration_migration.json` records per source file (`<device id>/<file name>`) the SHA-256 merged, so an unchanged source is never merged again (an image the owner deleted fleet-wide is not resurrected from the frozen copy) and a source changed since (by the previous release during a rollback period) is merged once more.
- ART-05 Conflict rule per key (file name): when the fleet directory and one or more frame directories hold different bytes for the same file name, the file with the latest modification time (`st_mtime_ns`) wins; on a tie the fleet (root) file wins, then the lowest device id. The mtime is preserved on the copy (`os.utime` with the source's `st_atime_ns`/`st_mtime_ns` after the atomic write), so the order stays stable across runs and a later merge compares the same values. Identical bytes (same SHA-256) are not a conflict and are not copied. This is the same "latest decision wins" rule as plan 41's `created_at`, as the owner confirmed.
- ART-06 Losers are never lost: before a winning file replaces a root file, and for every losing frame file, the loser is copied (atomic write, mtime preserved) to `<fleet root>/illustration_conflicts/<device id or "live">/<file name>` (never overwriting an earlier archive of different bytes: a numeric suffix `.1`, `.2` before `.png` is used), one log line per conflict names key, winner, losers, mtimes and sizes, and the marker records the first 50. The per-device files stay anyway. The archive folder is a root directory and is added to the backup (ART-08). It is not read by any page or render.
- ART-07 Safety and caps preserved: a candidate file is merged only when all hold: a regular file (not a symlink, `os.lstat`), name matching `^[a-z0-9][a-z0-9-]*\.png$` whose key also passes `illustrations.override_path_for_key` (the `_UNSAFE_KEY_RE` path-separator and `..` guard), size at most `post_actions.MAX_ILLUSTRATION_UPLOAD_BYTES` (read the constant from `companion/upload_form`'s `MAX_UPLOAD_BYTES` through a duplicated module constant in `fleet_artwork.py` with a test that asserts both are equal, because `server/` must not import `companion/`), and `illustrations.validate_illustration_file(path)` returns no problem (PNG, dimensions, pixel cap: decompression-bomb safe, header-only). Anything else is skipped and logged by name and reason, never merged and never deleted. Fleet-wide caps: at most `MAX_MERGED_FILES = 1000` files and `MAX_MERGED_BYTES = 256 MiB` added to the fleet directory in one run (deterministic order: latest mtime first, then name), the rest logged as skipped with a count. A `devices/<id>` directory is used only through the `device_dirs.resolve_state_dir` rules (name shape, no symlink); a symlinked `illustration_overrides` directory is ignored and reported.
- ART-08 Backup: `deploy/backup/skypane_backup.py` `INCLUDE_DIRS` already lists `illustration_overrides` (root) and `DEVICE_INCLUDE_DIRS` lists it per device (verified on main, lines 48 and 96): both stay, because the per-device copies are the rollback source and the pre-migration backup taken by `activate.sh` just before the merge is the only archived copy of the data being merged. `INCLUDE_DIRS` gains `illustration_conflicts` and `INCLUDE_FILES` gains `illustration_migration.json` (an unlisted root entry is logged as drift). Tests prove all four are archived and none is reported as drift.
- ART-09 Rollback caveat (to write in `deploy/README.md` next to plan 41's caveat): the previous release reads per-device image directories, so after a rollback every non-live frame sees its own old pictures again and pictures added after the upgrade exist only in the root directory (visible to the previous release on the live frame only); a later roll-forward merges again only the per-device files whose hash changed in the meantime, by the same rule, which can bring back a picture deleted fleet-wide before the rollback: re-check the Airlines editor after a roll-forward that followed a rollback.
- ART-10 Deferred cleanup (NOT built here, no task): after the rollback window, a later release deletes the frozen per-device `illustration_overrides/` directories (and the per-device registry copies of plan 41, FLT-13), with the matching `DEVICE_INCLUDE_DIRS` entry and the README caveats (owner, 2026-11-21: yes, later). Record it as an item for plan 32 (final plan) and for STATE.md's deferred list; this plan does not edit either.
