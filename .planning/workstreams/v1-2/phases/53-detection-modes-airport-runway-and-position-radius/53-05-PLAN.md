Output: per-device resolver, spec-driven selection, spec-driven tag and heading, integration tests.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-20 | Elevation of gate | zone fetched for device A but selection gated against the shared Orly geofence (cross-device leakage of the wrong aircraft) | mitigate | detect_flight uses ctx.spec built from the same spec_for call family as the resolver; integration tests for isolation and pipeline equality |
| T-53-21 | Denial of service | one corrupt device config breaking the whole fleet cycle | mitigate | spec_for never raises on config content; resolver exceptions limited to OSError/ValueError/KeyError/TypeError which plan_zones already maps to unzoned |
| T-53-22 | Information disclosure | location of one user used for another user's device | mitigate | The location comes only from the device's own devices.location_id row; test with two devices and two locations |
| T-53-23 | Tampering | markup/control characters in tag text | mitigate | Tag text is built only from catalogue ICAO/IATA/designator and an integer radius; the location name is never rendered on the panel |
| T-53-24 | Tampering | live frame behaviour drift | mitigate | Pipeline equality tests (generic vs kill-switch), unchanged freeze test and goldens |
| T-53-SC | Tampering | package installs | accept | No package added |
