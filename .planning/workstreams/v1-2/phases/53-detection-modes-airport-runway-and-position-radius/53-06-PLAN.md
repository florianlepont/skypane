## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to /detection GET and POST | Untrusted q, airport, runway, mode, device prefix |
| principal to device | A signed-in user may reach only their own devices; admins any |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-25 | Elevation of privilege | device-scope or ownership bypass on /detection and /devices/<id>/detection | mitigate | OWNER_DEVICE route access evaluated before the handler; matrix rows for GET and POST in both forms; HTTP tests: other user's device and unknown or malformed ids return 404 and write nothing; handler acts only on the device bound by the dispatcher |
| T-53-26 | Tampering | cross-site POST changing a device's detection | mitigate | Existing Origin/Sec-Fetch-Site gate runs before routing for every POST; a test posts with a foreign Origin and expects the gate's refusal and no write |
| T-53-27 | Tampering | crafted airport/runway values selecting non-catalogue geometry | mitigate | Server re-validates through detection.validate_runway_selection (catalogue lookup, exact regex); the client never supplies thresholds |
| T-53-28 | Tampering | reflected XSS via q, airport or error echo | mitigate | q capped at 60 chars, control chars stripped, layout.escape_html on every echo; test with a script payload and quotes |
| T-53-29 | Tampering | search/pick state change through GET | mitigate | GET handlers are read-only; only POST writes (test: GET with every parameter combination leaves the config file bytes unchanged) |
| T-53-30 | Denial of service | very long or many query parameters | mitigate | q length cap, 20-row cap, linear scan of a 272-airport catalogue; request body cap already enforced by read_form |
| T-53-SC | Tampering | package installs | accept | No package added |
