Design (from research, verified against HEAD):
- Token = hex sha256 of the bytes `csrf-v1:` followed by the raw session cookie token (the database stores only `sha256(token)`, so a database leak does not yield tokens). Compare with `hmac.compare_digest`. The cookie is HttpOnly so page script cannot read it; the server embeds the derived token in forms.
- `Route.csrf: bool = False` MUST be a defaulted trailing field of the `Route` namedtuple, and `access_matrix_support.stub_routes` must keep working (plan 04 changed it to `route._replace(handler=...)`).
- `Handler.read_form()` reads `self.rfile` once. The dispatcher check needs the form: cache the parsed form on the handler, reset at the top of `_dispatch` next to `_principal_cache`, so handlers calling `read_form()` again get the same dict. Multipart upload routes (illustration replace) are not urlencoded and are NOT in scope (`csrf=False`).
- Order inside `_dispatch`: origin gate, match, `access.decide`, LOGIN or NOT_FOUND, `_apply_principal`, THEN the CSRF check, THEN the handler. A denied role must still see the generic 404.
- `auth.LoginThrottle` no longer exists (the legacy password sign-in was removed); nothing here depends on it.
- No new JavaScript. Any static script that posts to one of the six protected routes (Grep `companion/static/*.js` for the route strings) must send the token: submitting through the form's own FormData includes the hidden field automatically; verify and fix if a script builds its own body.
</context>
