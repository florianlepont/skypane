Route paths (constants in `companion/console_routes.py`): `FLEET_ROUTE="/fleet"`, `FLEET_REGISTER_ROUTE="/fleet/register"`, `FLEET_PAIR_ROUTE="/fleet/pair"`, `FRAME_ACTION_PREFIX="/fleet/frames/"` with suffixes `FRAME_RETIRE_SUFFIX="/retire"`, `FRAME_REACTIVATE_SUFFIX="/reactivate"`, `FRAME_REASSIGN_SUFFIX="/reassign"`; `USERS_ROUTE="/users"`, `USERS_INVITE_ROUTE="/users/invite"`, `USER_ACTION_PREFIX="/users/"` with suffixes `/role`, `/disable`, `/enable`, `/unlink`; `AUDIT_ROUTE="/audit"`; `LOCATIONS_ROUTE="/locations"`, `LOCATIONS_ADD_ROUTE="/locations/add"`, `LOCATION_ACTION_PREFIX="/locations/"` with suffixes `/edit`, `/delete`. Access: everything admin-only except the Locations routes (signed in, row-level ownership in the handler, plan 13).

Route modules (each exports `ROUTES = ()` as a skeleton here, replaced by the owning plan): `console_pairing` (plan 10: register and pair), `console_lifecycle` (plan 11: retire, reactivate, reassign, audit page), `console_users` (plan 12), `console_locations` (plan 13). Handlers are plain functions `handler(h, m)` taking the Handler, so no `Handler` base class edit is needed. New POST routes set `csrf=True` on the `Route`.

Matrix row seams: `test-support/matrix_rows_<name>.py` exports `ROWS` (dict keyed `(method, route template)` to a policy kind name from `companion/test_access_matrix.py`) and `SAMPLES` (route template to a sample middle). `test_access_matrix.py` merges all four into `ROUTE_POLICY` and `SAMPLE_MIDDLE` (this plan is the only one editing the merge; later plans only fill their own row module).

Throttle API (`companion/throttle.py`): `LockoutThrottle(limit, lockout_s, max_keys=4096, clock=time.time)`; `locked_for(key)` returns remaining seconds or 0; `record_failure(key)` returns True when this failure started a lockout; `record_success(key)` clears the key; `reset()`. In-memory and per process (a companion restart resets it; stated in the hand-off). The legacy `auth.LoginThrottle` no longer exists; do not look for it.

Audit helper API (`companion/audit.py`): `actor_for(handler)` returns `fleet_db.AuditActor(user_id, email, source_ip)` with the IP from `auth.client_ip(self.client_address[0], X-Forwarded-For header)`; `record_in(handler, conn, action, target_type, target_id, outcome, detail=None)` appends inside the caller's transaction; `record_standalone(handler, action, target_type, target_id, outcome, detail=None)` opens `fleet_db.connect(state_dir)` and its own `transaction` for failed or denied events recorded after a rollback. Neither accepts or stores secrets, codes or guesses.

Flash (`companion/console_flash.py`): after a POST the handler redirects (PRG) with a one-shot cookie `sp_flash` (HttpOnly, SameSite=Strict, Path=/, Max-Age 60, value a base64url JSON of a registered key plus string parameters, at most 1 KiB, cleared when read). `register_flash(key, tone, title_msg, detail_msg)` is called at import by the module that owns the key; rendering looks the key up in the registry (unknown keys render nothing), HTML-escapes every parameter, and uses `ui_components.toast_html` (success tone auto-hides, warning and error never do). Never carries a code, guess, secret or MAC secret.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser cookie `sp_flash` -> toast renderer | attacker-settable display state |
| request headers -> audit source IP | `X-Forwarded-For` is forgeable unless from the proxy |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55-09-01 | Tampering | forged flash cookie injecting text/markup | mitigate | registry lookup of fixed keys only, all parameters escaped, 1 KiB cap, no HTML in parameters; text-only impact on the setter's own browser |
| T-55-09-02 | Repudiation | forged audit source IP | mitigate | `auth.client_ip` trusts XFF only from a loopback peer (Caddy) |
| T-55-09-03 | Information disclosure | secrets/codes/guesses reaching audit or flash | mitigate | audit and flash APIs have no such parameters; tests pass forbidden strings and assert absence |
| T-55-09-04 | Denial of service | unbounded throttle table | mitigate | `max_keys` with eviction, tested |
| T-55-09-05 | Elevation of privilege | console route added without a policy row | mitigate | aggregator + matrix completeness test names it |
| T-55-09-06 | Information disclosure | admin nav visible to users | mitigate | links derive from the route table and role; Test 1 and plan 01 user nav tests |
| T-55-09-SC | Tampering | package installs | accept | none added |
