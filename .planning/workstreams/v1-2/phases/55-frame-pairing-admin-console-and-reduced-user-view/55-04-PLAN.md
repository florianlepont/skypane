<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL `/devices/<id>/...` -> ownership gate | the id is attacker-controlled |
| un-prefixed URL -> live frame | a user must never fall through to `devices[0]` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55-04-01 | Elevation of privilege / IDOR | foreign `/devices/<id>/` pages and images | mitigate | `Access(USER,"device")` with the device id as captured value; other user gets the unknown-path 404; matrix rows prove it |
| T-55-04-02 | Elevation of privilege | un-prefixed route reaching the live frame as a user | mitigate | `_effective_access` makes the un-prefixed form admin-only; user scope never includes the synthetic live fallback |
| T-55-04-03 | Information disclosure | selector/Account listing other owners' frames | mitigate | `load_devices_for` owner filter; Tests 2-3 |
| T-55-04-04 | Information disclosure | 404 body distinguishing foreign from unknown | mitigate | identical `_not_found_page`; test compares bodies (plan 06 adds the real-handler comparison) |
| T-55-04-05 | Tampering | open redirect through `_referring_tab` | mitigate | only `DEVICE_PREFIX_RE`-validated owned ids and the page whitelist are honoured |
| T-55-04-SC | Tampering | package installs | accept | none added |
</threat_model>
