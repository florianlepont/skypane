Files owned here only: the six listed. The route module `companion/console_pairing.py` currently holds `ROUTES = ()` (plan 09); replace it. Handlers are plain functions `handler(h, m)`. Use `h._console_page(...)`, `console_flash.queue_flash(...)`, `audit.record_standalone(...)`, `ui_components.csrf_field()`, `console_routes.section_subnav_html(...)`. The Fleet row-action forms post to the lifecycle routes defined by constants in `console_routes` (`FRAME_ACTION_PREFIX` plus `/retire`, `/reactivate`, `/reassign`); plan 11 implements those handlers, this plan only renders the forms and the confirm blocks (UI-SPEC inline `<details>` confirm pattern, no JavaScript, no dialog, no `confirm(`).
Throttle parameters (module-level in `console_pairing.py`): per session `LockoutThrottle(limit=5, lockout_s=300)` keyed by the first 16 hex of `sha256(raw session token)` (never the token); global `LockoutThrottle(limit=20, lockout_s=900)` with a constant key and NO `record_success` (a success must not reset the global counter). A locked caller gets 429 with the "Too many attempts" toast and no code evaluation at all.
UI contract: UI-SPEC sections 1 to 3 and the Copywriting table (EN and FR); status badges neutral; one accent primary per page ("Pair frame"); "Register frame" is a quiet secondary button; 44 px hit targets on the claim form; `.data-card` stack below 960 px. Never echo the guess in a URL, an audit-visible place, a toast or a `title` attribute: it is re-rendered only into the input's value on the immediate POST response, which is sent with `Cache-Control: no-store`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser -> `/fleet/pair` | the typed code is a guess until proven |
| admin browser -> `/fleet/register` | MAC and hash are untrusted text |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55-10-01 | Spoofing | pairing code guessing | mitigate | per-session (5 per 300 s) and global (20 per 900 s) lockouts before any evaluation; admin-only route; 30 min TTL; salted constant-time scan |
| T-55-10-02 | Tampering | claim replay or double claim | mitigate | single transaction in `fleet_ops`; concurrent HTTP race test |
| T-55-10-03 | Information disclosure | validity oracle (wrong vs expired vs used) | mitigate | identical body and status, uniform compare count (Test 3, plan 05) |
| T-55-10-04 | Information disclosure | guess or code in audit, URL, toast, cache | mitigate | Test 4; `no-store`; guess only in the immediate response input |
| T-55-10-05 | Tampering (CSRF) | forged pair/register POST | mitigate | `csrf=True` on both routes (plan 08 dispatcher) |
| T-55-10-06 | Elevation of privilege | non-admin pairing | mitigate | ADMIN_ONLY, 404 for users, matrix rows |
| T-55-10-07 | Information disclosure | raw secret entering the companion | mitigate | only the SHA-256 is accepted and validated; no secret parameter exists |
| T-55-10-SC | Tampering | package installs | accept | none added |
</threat_model>
