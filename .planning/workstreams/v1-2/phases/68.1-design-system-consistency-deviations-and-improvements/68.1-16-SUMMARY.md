# Phase 68.1 Plan 16: Lighter console dialogs (P04) Summary

Confirmation dialogs ask one question (the title) in one sentence; the rest sits behind `ui_modal.more_html`, a closed native `<details class="modal__more">` with a 44px summary ("More detail" / "Plus de details") and a chevron that turns without motion. No typed-name confirmation exists or was added.

## Inventory and what changed

| Dialog | Page | Before | Now (visible sentence / behind the disclosure) |
|---|---|---|---|
| Retire | Fleet | 2 sentences | "It stops updating and shows a retired screen." / "Its data is kept and you can re-activate it later." |
| Re-activate | Fleet | 2 sentences | "Its settings and history are erased." / "It returns to pairing and shows a new code." |
| Reassign | Fleet | picker plus an effects list of two lines | one sentence (settings, history, gallery erased; or "Only the owner changes.") above the picker / the two effects list |
| Leave this frame | Account | 2 sentences | "You lose access to this frame and its settings." / "The owner or an administrator can add you again." |
| Remove this frame | Account | 3 sentences | "This frame leaves your account and its co-managers lose access." / "An administrator can assign it to someone again later; its history is kept." |
| Delete user | Users | 2 sentences | "<email> is removed from SkyPane for good." / "They lose access to their frames." |
| Manage access | Account, Fleet | typed address field, label, helper, full-width Add under it | the typed address shares a line with Add (as the administrator's picker already did); label stays for assistive technology |
| Add co-manager, role dialogs, rename | unchanged (title plus a field, or one sentence already) | | |

Unchanged on purpose: two actions, the safe button focused by default (Keep frame / Keep this user / Stay on this frame / Keep this frame / Keep retired), the destructive labels (Retire frame, Re-activate frame, Leave this frame, Remove this frame, Delete user) and the danger style, forms, fields, routes, CSRF, handlers, Escape and focus return. `test_retire_in_two_actions_with_focus_on_the_dismiss_control` passes unedited.

French Manage access at 360x800 (owner and two co-managers): fits within 85dvh with no inner scroll; no English word in the French dialog.

## Tests

`companion/test_browser_lighter_dialogs.py` (red first, then green per area): for 7 dialogs, EN and FR, Light and Dark at 360x800: no sentence break in the visible body, every disclosure closed with a summary of at least 44px, one disclosure per dialog, height at most 85% of the viewport, no sideways scroll, text contrast at least 4.5:1; the five destructive dialogs: exactly two actions, no text input (proves no typed confirmation), danger-styled named confirm button, default focus on the dismiss link; Escape closes and returns focus to the opener; French Manage access fit; no running animation under reduced motion (also after opening a disclosure).

Existing tests updated because a string or layout they assert changed: `test_browser_fleet_dialogs.py` (`_GAPS` now measures the question to the disclosure instead of to the submit button), `test_browser_delete_user_remove_frame.py` (Delete user text and the Account removal detail are read after opening the disclosure; wording "leaves your account"), `test_co_managers_page.py` ("You lose access to this frame"). Nothing about focus, flow or button count was weakened.

## Manifest and drift test

No token or documented value added or changed: `design_system_tokens.json` and the drift test are untouched (drift test run, green). New CSS uses existing tokens only.
