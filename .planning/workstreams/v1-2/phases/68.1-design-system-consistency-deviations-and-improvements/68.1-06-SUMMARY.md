# Phase 68.1 Plan 06: Executable design-system drift test Summary

A pytest-playwright test compares a token manifest, transcribed from the skill, with the values the browser computes on the served site (D-02).

## What the test pins

On Home and the admin Components page, signed in, against the shared read-only seeded server:

- 29 colour tokens per theme (canvas, card, secondary, border, text, accent and hover, on-accent, status inks, switch-off, rarity inks, yellow tile edge, map ground, sky stops, glass, bar, popover, toast) in explicit Light and Dark, and the Dark set again in Auto-dark (OS dark scheme, no `data-ui-theme`).
- Radii, the 4 to 64px spacing steps, type sizes, title tracking, tab-bar geometry, glass blur, the 17 motion durations, the two easings, `--rarity-tint` per theme, weights, opening opacity and glass saturation, in both themes.
- The page-title size per viewport (30px at 360, 44px at 1280).
- The 4.5:1 floor for nine stated pairs (text, secondary ink at 70%, accent, on-accent), measured on the composited canvas pixel of the live colours with `skypane_contrast_check.contrast_ratio`.
- At 360px: every visible `.btn`, tab-bar link and More summary is at least 44px tall, every `.btn--icon` has an accessible name, and the page does not scroll horizontally.
- Negative cases: a manifest with changed, undefined and unparsable values yields a mismatch naming each token; a pair below the floor is detected.

Values are compared in the browser's own serialisation (token and manifest value are both assigned to a probe element), so hex or rgb spelling cannot cause a mismatch, and an undefined token falls back to a sentinel that no manifest value can equal.

## Known limit (D-02)

The manifest is a hand-copied transcript of the skill. The test proves site = manifest; skill = manifest holds by review only.
