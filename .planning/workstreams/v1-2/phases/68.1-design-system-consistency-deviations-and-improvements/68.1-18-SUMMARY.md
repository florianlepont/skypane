# Phase 68.1 Plan 18: Copy confirmation, a check springs in (P14) Summary

When a copy succeeds, an ink check springs in beside the copied word (scale 0.4 to 1 and opacity, 180ms `--motion-fast`, `--motion-spring`) and the word rises 4px (180ms, `--ease-out`); under `prefers-reduced-motion: reduce` the check and the word appear at once and no animation runs.

## Inventory

- Elements carrying `data-copy-value`: one, the Copy button of the invitation link dialog on Users (`users_page._invitation_dialog`), handled by `copy-button.js`.
- The Account build line (`button.account-build[data-build-copy]`, handled by its own `account-build.js`) is the other copy button.
- The pairing code has no copy button in the code today; nothing to change there.
- Save confirmations that swap a label: none found (the save bar and `dirty-state.js` carry no "Saved" label swap), so only the two copy buttons change, as the plan allows.

## What changed

- `copy-button.js` and `account-build.js` insert an inline SVG check built with DOM methods (`createElementNS`, no HTML-writing sink), `aria-hidden`, drawn in `currentColor`, next to the copied word, and remove it when the 1500ms window ends. `account-build.js` also toggles `account-build--copied` on the button.
- `style.css`: the two keyframes `skypane-copy-tick` and `skypane-copy-rise` and their `animation` rules sit inside the existing `@media (prefers-reduced-motion: no-preference)` block, so no new media block exists and the pinned counts (3 reduce, 1 no-preference) stay true. Only durations from `var(--motion-fast)`, no bare literal, no new token.
- `style-admin.css`: static layout only (the check's box, the copy glyph giving way to the check while copied, the Account check in full ink with a 4px gap).
- No new string: the words are the existing "Copied" / "Copié" (`admin_users.copied`, `account.build_copied`), so no i18n entry. `companion/test_companion_app_04.py` needed no edit (its spender table pins other tokens; the motion-budget test passes unchanged).

## Tests

`companion/test_browser_copy_confirmation.py` (10 tests, red first: it timed out waiting for a check on all ten): on both surfaces at 360px, EN and FR, Light and Dark, clipboard granted: the check appears and is `aria-hidden`, exactly one running animation on the check and one on the word, each 180ms and limited to `opacity` and `transform` (read with `getAnimations()` / `getKeyframes()`); the word equals Copied / Copié and the live region announces it; the check's ink has at least 4.5:1 against the composited background behind it; the control stays at least 44px high and its height does not change; no page overflow; after the window the label is back and the check gone. Under reduced-motion emulation on both surfaces: the same check and word, and no running animation on the button or its children.

## Deviations from Plan

- The width of the Users button is not asserted equal between states: "Copy" and "Copied" are different words, so it changes by the word length (the height, the 44px floor and page overflow are asserted instead).
- The contrast of the `Copied` label text is not asserted or changed here (the plan leaves it to the status-colour work of plan 22); only the check and the control are measured.
