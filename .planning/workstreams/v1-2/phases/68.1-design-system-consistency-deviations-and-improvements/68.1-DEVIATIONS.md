## Decision vocabulary and rules

| Decision | Meaning | Rule applied |
|----------|---------|--------------|
| CORRECT-SYSTEM | The skill is edited to say what the site does | R1: default under D-01; the site breaks no hard rule |
| FIX-SITE | The site is changed, CSS or markup only, no visible pixel moves | R2: the site breaks a hard rule (44px target, accessible name, missing token in a theme block, owner-approved mockup contradicted, ...) and the fix is invisible (hit-area pseudo-element, `aria-label`) |
| MIGRATE-TOKEN | A literal is replaced by the token of identical computed value | R3: A4 TOKEN-EXISTS, rendered output unchanged |
| RECORD-REASON | The skill gets a "Known exceptions" entry, no code change | R4: A4 NO-TOKEN or JUSTIFIED; a new token would widen the scale and Plan 05 is behaviour-preserving |
| OWNER-QUESTION | Fixing would change a visible pixel; not decided silently, carried to the proposal input list (Plan 07) | R5: pixel-changing fix is not behaviour-preserving |

BLOCKED-ON-566: PR #566 (branch `phase-68-4-fleet-empty-state`, open, draft) changes `SKILL.md` (the "As of" line), `references/page-patterns.md` (the fleet list paragraph), `companion/static/style.css` (two `.fleet-split__main > .fleet-empty` selectors), `style-admin.css` (fleet rules), `console_fleet_view.py`, `pages/fleet_frames_list.py`, `i18n_fr/admin_fleet.py` and fleet tests. A row is BLOCKED-ON-566 when its edit lands on fleet content or on one of those hunks; a row whose edit is in the same file but in a disjoint section is marked "no (disjoint hunk)". Blocked rows wait until #566 is merged and the branch is rebased.

Risk column: low = invisible or documentation only; medium = page governed by the access rules (Account, Location, Fleet, Users, Editor) or a change whose golden hash (`companion/testdata/render_baseline.json`) must be checked.
