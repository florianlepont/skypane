# Phase 68.1 Plan 17: One filter style on Flights and Airlines (P02) Summary

P02 is a refactor, no visible change: Flights and Airlines now write their count line with one helper, `ui_filter.count_line_html(text, template="", attrs="")`, which emits the single `<p class="filter-count" data-filter-count role="status">` that was already the next sibling of the shared filter form on both pages.

## What changed

- `ui_filter.count_line_html` is new. `text` and `template` are escaped; `data-filter-count-template` is present only when a template is given; `attrs` is a trusted literal inserted verbatim (Flights passes ` data-flights-view`, which `list-filter.js` uses to swap the line after every answer; the docstring says never to pass user input).
- `airline_collection_page._count_html` and `history_page._matches_html` call it; texts, message ids and position are unchanged. Flights still builds the line inside `_synced_controls_html`, so the live swap is untouched. `list-filter.js` and `style-c-lists.css` needed no edit (`.filter-count` was already the only rule for this line; `.entity-count`, `.filter-bar__count` and `filter_bar_html` are untouched).
- `components_page.EXEMPT` lists the helper with a reason (the catalogue test requires every public helper to be catalogued or exempt). The catalogue sample is not changed, so `/components` renders as before.

## Render baseline

Regenerated with `test-support/companion_render_snapshot.py --write`. The diff is 4 lines: the four `/airlines` pages (en/fr, light/dark), where the attribute order of the count paragraph changed from `class role data-filter-count template` to `class data-filter-count role template` (the order Flights already used). The four `/flights` pages and every other page are byte-identical. No visible change.

## Tests

- `companion/test_ui_filter.py` (new, 4 tests): one status paragraph, template attribute only when given, text and template inert against `<`, `>`, `&` and a double quote, `attrs` verbatim.
- `companion/test_browser_filter_style.py` (new, 11 tests, seeded rows): Flights and Airlines, EN and FR, Light and Dark, 360 and 1280 px: same form child order, one `p.filter-count[data-filter-count][role=status]` as the form's next sibling, exactly one `[data-filter-count]` and no `.entity-count` / `.filter-bar__count` on either page, equal count font-size, colour and margin, equal chips background, search field at least 44px with an accessible name, no horizontal overflow; the count text follows the search live on both pages; Users keeps its `.entity-count` caption. The chips group differs by the pre-existing `js-gate` class on Airlines (its chips are script-driven), which the test normalises.
- Edited existing test: `companion/test_airline_collection_page.py` (the count regexp no longer fixes the old attribute order).

## Manifest and drift test

No token or documented value added or changed: `design_system_tokens.json` and the drift test are untouched (drift test run, green). No new string, so no i18n entry.

## Deviations from Plan

- [Rule 3] `components_page.EXEMPT` entry for the new public helper (catalogue guard).
- The helper's attribute order is the one Flights used, so the Airlines baseline pages changed (hash only, listed above); one page had to change because the two pages emitted different orders.
- The browser test is a characterisation of both pages and the count-gap between form and count is only bounded (at most 8px), not compared: the two pages differ by 1 to 2px there on main already (sticky bar rounding), unrelated to the helper.
