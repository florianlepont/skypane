# Phase 68.1 - Check B: page-by-page consistency (console and companion)

**Date:** 2026-11-25. **Base commit:** 9d01307 (branch `phase-68-1-design-system-consistency`). **Requirement:** DSY-01 (page-level half).

## How this was captured

- `capture_pages.py` (same folder) starts two seeded companion servers through `test-support/companion_app_server.py` and `provisioned_fleet.py` (one where user A owns the live frame, one where the administrator does), signs in with the test-support session helper (a local session row, no real credential), and visits every page in `en`/`fr` x `light`/`dark` x 360x800 / 1280x900 (8 cells per page).
- Browser: Python Playwright is not installed here and nothing was installed. The script drives the Node Playwright package already on the machine with the system Chrome (158). All cells ran locally: **no cell is "CI needed" for the capture itself.**
- Measured per cell: HTTP status, final URL, `lang`, document title, `h1`, horizontal scroll, interactive elements under 44px (checkbox and radio are measured on their label), controls without an accessible name, clipped or ellipsised text, the resolved `--color-*` values, nav shape and labels, and (every `<dialog>`, opened with `showModal()`) its box, whether it fits the viewport, inner scroll, small targets and clipped text. Screenshots (360 light EN, 360 dark FR) and the JSON live in the scratchpad, not in the repo.
- **Fleet pages** (Fleet list, frame page, Battery, Versions, retired, pending, System) and Users were captured from a worktree of `origin/phase-68-4-fleet-empty-state` because PR #566 is not merged. `gh api repos/florianlepont/skypane/pulls/566`: state `open`, draft `true`, merged `false`. The pages on the working branch and on the #566 branch gave the same results for every measured axis (no overflow, same targets, same labels), but **fleet rows must be re-checked after #566 merges**.
- Limits of the method, stated so nobody over-reads a MATCH: contrast ratios were not recomputed here (Check A covers token contrast); the light and dark `--color-*` sets were compared and 27 of 34 differ, the 7 equal ones are `image-backdrop`, `scrim`, `overlay-icon`, `overlay-text`, `control-wash`, `control-border-subtle`, `shadow-strong` (translucent or intentionally theme-independent values); the screenshots are full-page, so the fixed tab bar appears mid-image (a capture artefact, not a defect); the fixture frames never checked in and have no flights, so populated states (flight card, flights list rows, battery tile, airline cards) were not exercised. Those populated states are listed in B3 as "needs seeded data".
- Small-target scan result: **0 interactive elements under 44px on every captured page except the Components page** (7 "Back to the index" links 130x20 / 116x20 and one "Orly frame" sample link 24px tall, all samples of inline links) and the Quiet-hours dialog "Location" link (61x21 measured box; the skill says it has a 44px tap area, which would be a pseudo-element hit area this measurement does not see: marked to verify in Plan 05).
- No horizontal overflow on any of the 25 pages x 8 cells.

Row format: `B1-nn | what the skill says | what the served page does | axes where it differs | evidence | MATCH or DEVIATION`. Evidence names are the JSON page key plus the screenshot file stem (`page__360-light-en`).
