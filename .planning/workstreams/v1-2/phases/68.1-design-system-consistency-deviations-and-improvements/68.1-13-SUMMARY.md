# Phase 68.1 Plan 13: Table inside its rounded card (P03) Summary

The wide Users table and the Editor airline table now end at their card's rounded corners, with a tinted header row and no rule under the last row.

## What changed

- Tests first: `companion/test_browser_table_card.py`, 23 cases (Users and Editor, EN and FR, Light and Dark, 1280 px; open row menus on the first and last row; focus ring inside the card; Users phone cards at 360 px; reduced motion). Red first for the corners and the tint.
- Users (from 79.5rem): the table card has `overflow: hidden` at the card radius; header cells use `--color-secondary`; the last row has no bottom rule and keeps the rule's room (padding) so rows stay equally tall; corner cells carry the card radius.
- Clip and menus: `overflow: hidden` would cut the opened "..." panel of the last row. While a row menu is open (`:has(.row-menu[open])`) the clip is released; the corner cells keep the corners round meanwhile. The closed state clips again (asserted).
- Editor (from 70rem): header tinted, corner cells carry the radius. Deviation from the plan: no `overflow: hidden` here, because the table's caption sits above the table box (absolutely positioned) and the row menus reach past it; an overflow clip would cut both. Corners are asserted by hit-testing the card's four corners instead.
- Skill: `components.md` and the SKILL.md "as of" line.
- Baseline: only `companion_render_snapshot.py --write`; the differences are the stylesheet `?v=` hashes (verified by normalising them).

## Manifest and drift test

No token or documented value added or changed: `design_system_tokens.json` and the drift test are untouched (drift test run, green).
