# Phase 68.1: Design System Consistency, Deviations and Improvements - Context

**Gathered:** 2026-11-25
**Status:** Ready for planning

<domain>
## Phase Boundary

Check the design system against the deployed site (console and companion, English and French, phone and desktop, light and dark), list and settle every deviation, move bypassed tokens back onto tokens (or record why), then propose improvements and animations to the owner. Only owner-approved proposals are built.

Out of scope: new pages and features, the security audit (Phase 66), the code cleanup (Phase 67), any change to the e-ink frame screens (Phase 62).

</domain>

<decisions>
## Implementation Decisions

### Source of truth
- **D-01:** The site's own stylesheet and the companion components page are the source of truth. The `sketch-findings-skypane` skill and its references describe them. When the site is right and the skill differs, correct the skill.
- **D-02:** The drift check is made executable where possible: a browser test compares what the skill states (tokens, touch targets, contrast) with the served CSS, so later phases cannot drift silently. Tests assert served HTML/CSS/JS, never source text (companion/test_suite_guards.py).

### Animations
- **D-03:** Soft motion budget (owner's choice). Durations and properties are not capped, but every animation must be switched off by `prefers-reduced-motion`, keep contrast, and be judged on the deployed site on a phone. Each proposal states cost, accessibility and performance effects. A proposal that breaks a rule of the system says so openly and waits for the owner.

### Proposal checkpoint
- **D-04:** The proposal step is a real stop. Deliver the proposal document (mockups, reasons, cost, accessibility and performance effects, which ideas came from `frontend-design:frontend-design`), then wait for the owner's choice. No proposal code before that. Each approved proposal is its own small change with browser tests, English and French, phone width. Mockups before code.

### Claude's Discretion
- Format of the consistency check document, deviation numbering, and how the deviation fixes are split into plans.

</decisions>
