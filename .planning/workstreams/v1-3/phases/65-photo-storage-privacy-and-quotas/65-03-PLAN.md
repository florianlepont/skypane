    - remove_files(conn, root, refs) unlinks `<photos>/<device>/<id>.jpg` for each (device_id, photo_id) ref whose row no longer exists; a ref whose row still exists is left alone (protects against a rolled-back transaction); a missing file is not an error; a malformed ref is skipped; returns the number of files removed; removes an emptied device directory.

<task type="auto" tdd="true">
  <name>Task 2: Orphan sweep</name>
  <files>server/photo_purge.py, server/test_photo_sweep.py</files>
  <behavior>
    - (a) a `photos/<id>/` directory whose device id is not in devices is deleted entirely, with no grace period; a directory with an invalid name is deleted too (links removed, targets untouched).
    - (b) a final-named file with no row is deleted only when its mtime is older than the grace period (default 15 minutes, injectable `now` and `grace_seconds`); a young one survives.
    - (c) a `.up-*` temp file older than the grace period is deleted; a young one survives (an in-flight upload is never cut off).
    - (d) a row whose file is missing is deleted from the table (covers a restore of fleet.db without photos and a partial failure), after which listing shows no broken entry.
    - (e) symlinks anywhere in the tree are removed as links and never followed; a `photos` directory that is itself a symlink is refused (reported, nothing followed, nothing deleted behind it).
    - sweep(conn, root, now=None, grace_seconds=900) returns SweepCounts(orphan_dirs, orphan_files, stale_temps, missing_rows, links) as integers only; running it twice in a row second time returns zeros; with no photos directory it returns zeros and creates nothing.
    - Restore scenario: build a fleet with 3 photos, delete the photos tree to mimic a restore without photos, run sweep -> table empty, no exception, store.list_photos empty.
  </behavior>
  <action>
    Implement sweep in photo_purge.py as small private helpers, one per rule (a)-(e), each under the 80-line gate, so a failure in one rule does not stop the others. Output is counts only: nothing prints or logs a photo id, a file name or a path (the CLI in plan 05 prints these counts). When the sweep changes anything it does not write audit rows itself (audit stays at one count-only purge row per purge cause, written by the callers in plans 01 and 04).
