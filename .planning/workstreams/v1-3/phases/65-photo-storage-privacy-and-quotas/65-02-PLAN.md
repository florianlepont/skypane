## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| future route -> photo_store | untrusted device id and photo id text arrive here |
| uploader -> normalize_upload | hostile file bytes |
| photo_store -> filesystem | server writes private files in the state dir |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-65-09 | Information disclosure | admin or other user reading a photo | mitigate | capability type; no role parameter; one PhotoAccessDenied for every refusal; matrix test via inspect |
| T-65-10 | Tampering | path traversal / symlink in ids or planted links | mitigate | strict id regexes with \Z, ids from DB, islink refusal, O_NOFOLLOW read, tests with planted symlink |
| T-65-11 | Denial of service | storage exhaustion | mitigate | per-frame, server-wide and free-disk quotas inside BEGIN IMMEDIATE; BoundedSemaphore(2) around normalisation |
| T-65-12 | Tampering | quota race (check then insert) | mitigate | check and insert in one transaction; N-thread test |
| T-65-13 | Information disclosure | filename or path leaking via logs or errors | mitigate | add() takes bytes only; errors carry fixed codes; test asserts messages hold no path |
| T-65-14 | Information disclosure | file permissions readable by group | mitigate | explicit 0700 directories, 0600 files regardless of UMask |
</threat_model>
