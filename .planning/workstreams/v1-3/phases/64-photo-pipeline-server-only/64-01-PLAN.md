<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upload bytes -> normalize_upload | Fully untrusted content (and, later, untrusted filename/Content-Type, which this API refuses to accept) |
| normalize_upload -> storage (later work) | Only the re-encoded JPEG crosses; original bytes never leave the function |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-64-01 | D | decompression bomb | mitigate | MAX_PIXELS 50 MP checked from header before draft/load; DecompressionBombError mapped to too_many_pixels; no Pillow globals mutated; test with few-KB bomb PNG |
| T-64-02 | T/E | format confusion / polyglot | mitigate | `Image.open(formats=[JPEG,PNG,WEBP])` allowlist, content-only identification, full re-encode drops trailing payloads |
| T-64-03 | I | GPS/device metadata in stored copy | mitigate | save without exif/icc/comment; sentinel tests incl. GPS IFD |
| T-64-04 | T | path traversal via filename | mitigate | API has no filename parameter; test asserts signature |
| T-64-05 | D | truncated/corrupt file | mitigate | full load(); LOAD_TRUNCATED_IMAGES untouched; mapped to corrupt |
| T-64-06 | I | log/error leakage of user content | mitigate | exception message is the reason code only |
| T-64-07 | D | concurrent large decodes exhaust RAM | accept | pure function; the future upload route must bound concurrency (recorded in docs/PHOTO-RENDERING.md by the freeze plan) |
</threat_model>
