<task type="auto">
  <name>Task 1: Generate the contact sheets and measures outside the repository</name>
  <files>(none: scratch output only)</files>
  <action>
Shell variables do not persist between calls, so record the scratch path in a file. Create the scratch directory with `mktemp -d` (not under the repository), write its path to `${TMPDIR:-/tmp}/skypane-photo-trial-dir.txt`, and print it. Run `server/.venv/bin/python -m server.photo --synthetic --out "$(cat <that file>)"` in the same command so it uses the recorded path. Later steps (verify, checkpoint message) read the path back from that file. Capture the printed measures table (skin mean RGB and hue before and after, palette-index shares, fidelity) per tone and parameter set. Confirm the sheets cover tones I-VI, full-range and dull scenes, portrait 1200x1600 and landscape 800x480, fill and bands. Note any tone where hue drifted more than 6 degrees or the skin region dithers to a single flat index. Confirm with `git status --porcelain` that no image file appears. Record the scratch path and a short measures summary for the checkpoint message. Do not write any file in the repository in this task.
  </action>
  <verify>
    <automated>D="$(cat ${TMPDIR:-/tmp}/skypane-photo-trial-dir.txt)" && test -d "$D" && test -n "$(find "$D" -name '*.png' | head -1)" && test -z "$(git status --porcelain | grep -i '\.\(png\|jpg\|jpeg\|webp\)$')"</automated>
  </verify>
  <done>Contact sheets exist in the scratch directory, the measures summary is captured, and git shows no image files.</done>
</task>

<task type="checkpoint:human-verify" gate="blocking">
  <what-built>Procedural skin-tone grid rendered through the photo pipeline (crop, contrast and saturation boost, 6-colour dithering) for the portrait and landscape panels, with the provisional parameters (autocontrast cutoff 1.0 with tone preserved, stretch strength 0.8, saturation 1.2) and one-factor variations around them. Optionally, your own portraits rendered locally.</what-built>
  <how-to-verify>
1. Open the contact sheets in the scratch directory printed above (PNG, nominal palette colours; they are not colour-accurate to the e-ink panel).
2. For each of the six tones, compare the provisional column with the lower and higher saturation, strength and cutoff variants, in portrait and landscape, fill and bands. Decide what looks acceptable for a face.
3. Optional, recommended: try your own portraits (or public-domain portraits) kept OUTSIDE the repository: `server/.venv/bin/python -m server.photo --in /path/to/portrait.jpg --out /path/outside/the/repo --fit fill`. The tool refuses an output directory inside the repository. If a physical frame is at hand, say whether you looked at it.
4. Reply with: acceptable or not per tone group (light I-II, medium III-IV, dark V-VI); the parameter values you want frozen (cutoff, strength, saturation) or "keep provisional"; any limit you want written down (for example "dark skin shows green and red speckle, acceptable"); whether you used real portraits and/or the physical frame.
  </how-to-verify>
  <resume-signal>Type "approved" with the chosen values and your verdict, or describe what looks wrong and which variant to try next.</resume-signal>
</task>
